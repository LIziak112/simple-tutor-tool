## 六、二维码 + 局域网（缺口小，但链路已通大半）

核实过的现状：

- 仓库**没有任何二维码依赖**（全仓 grep 无 `qrcode` / `qr-code`），这是唯一真正要新增的东西
- 服务端 `apps/server/src/index.ts:75` `serve({ fetch, port })` 只传端口；底层 `@hono/node-server` 调 `server.listen(port, options?.hostname, cb)`，hostname 未传 → Node 默认监听全部网卡。**局域网本来就可达，不需要改 0.0.0.0**（我先前口头说的「只监听本机」是错的，以本条为准）
- dev 的 vite 已 `host: true`（`apps/web/vite.config.ts:166-173`，注释就是「暴露局域网地址，iPad 同一 Wi-Fi 可直接访问」），并带 `/api` 代理 → 手机打开 `http://<电脑局域网IP>:5173` 即可
- `PUBLIC_URL`（默认 `http://localhost:8787`）只影响**生成出来的链接**，不影响可达性；做二维码时要么按请求 Host 推导，要么新加 `LAN_URL` / 启动时枚举网卡

可直接复用的登录通道（关键发现）：

- `apps/server/src/routes/public.ts:153` `GET /s/:token`：学生专属链接，**带 token 即登录**（写 90 天会话 Cookie）
- 所以二维码不需要新做免登录机制：agent 生成 `http://<lan-ip>:<port>/s/<token>` 的二维码，手机扫码直接进学生端
- 安全口径沿用现有：token 即凭据，二维码等同把链接给出去，有效期与撤销走既有学生链接机制

实现最小集（建议）：

1. 加一个轻量二维码库，服务端出 SVG（命令行 agent 可直接 print / 落文件）
2. 新增一条 CLI 或接口：读取本机局域网 IPv4 + 当前端口 + 学生 token，输出二维码文本与 URL
3. 反代可选、非前置：`cloudflared tunnel --url` 免登录临时域名门槛最低，`tailscale funnel` 次之；不引入 nginx 配置
4. 移动端基础：`vite-plugin-pwa` 已在用，加桌面体验现成
