# 师生端以答对题数替代百分比分数

## 已确认范围与口径

- 修改我的记录、课程单元落地页（摘要及历次）、讲练落地页历次、课程目录状态徽章；未公布横幅「得分状态」改为「作答结果」。
- 学生练习结果页现有得分卡与题数统计保留；难度星级不改。
- 用户补充：教师端对应位置也纳入本次修改，包括作答记录卡、批改详情汇总、课程进度矩阵、学情完成矩阵和学生学情中的首次得分展示。真正的正确率/趋势指标与百分制得分区分处理，不能把「下节课重点」中已判题正确率冒充全卷答对数/总题数；不改与分数无关的统计。
- 展示「做对 X / N 题」，N 取本次作答冻结题数，未作答题仍计入分母；X 从当前权威逐题判定统计，不能从百分比分数反推。
- 待批和待自评沿用各自计数与标识；未公布只显示待公布，不泄露答对数。进行中不把未判题显示成已判错误。
- 用户明确：未做轮打断连续做对，但不增加错次。单纯打开后退出、未形成有效提交的草稿不新增统计轮次。

## 建议呈现（待本计划确认）

- 首次、最近、最佳三张摘要卡保留，各展示该次的答对数/冻结总题数；「最高得分」改为「最佳表现」。
- 最佳按答对数/总题数比例选取对应的一次作答，不以旧 score 排序，不把不同次作答的分子分母拼接；比例相同时优先最近一次。零题卷不参与最佳比较。
- 已公布的全待批/待自评记录仍展示已确认答对数与总题数，另列待批/待自评数，不把这些题算作错题。

## 实施文件与步骤

1. 契约先行：`packages/contract/src/student-records-api.ts`、`student-course-api.ts` 及相关契约测试。为记录、历次与首次/最近/最佳摘要补充计数数据，保留旧分数字段的兼容语义；旧响应缺少计数时明确回退，不伪造答对数。
2. 服务端先补测试，再实现：`apps/server/src/services/student-records.ts`、`student-course-service.ts`、`lesson-service.ts`，增加共用的按作答批量统计入口，复用既有公布、归属、提交和作废守卫。统计从冻结作答行派生，无数据库结构变更，不逐条读取导致 N+1。
3. 界面：`records-views.tsx`、`StudentCourseUnitPage.tsx`、`StudentLessonLandingPage.tsx`、`StudentCourseDetailPage.tsx`、`PendingReleaseBanner.tsx` 及对应测试；复用计数展示格式，保持学生结果页得分卡原样；教师端按下节同步修改。
4. 错题轮次边界：先在 `wrong-mastery.test.ts`、错题服务测试补「对→未做→对」用例；核对 `wrong-mastery.ts` 与 `wrong-questions.ts` 的轮次保留、攻克与错次统计，只修不满足已确认语义的路径。不得通过过滤未做轮把两次做对拼成连续做对。
5. 更新相关页面文档与约定，运行 `pnpm gen:spec`（含 schema 导出）并提交生成物；独立分支提交与 PR，保留本地已有 PR #10/#11 及紧凑排版改动。

## 测试与验收

- 混合对/错/未做/待批/待自评，教师改判与清除后的当前判定；历史不同冻结题数、全待批、零题与多次作答摘要。
- 未公布计数脱敏、学生隔离、课程可见性和作废守卫；新增学生载荷必须补泄露测试。
- 未做轮不入错次但打断连续做对；真实列表与首页攻克计数一致。
- 完整 diff 依次简化、正确性审查、安全审查；执行契约/服务/前端的定向单测、相关包类型检查、变更文件 lint、相关浏览器用例。避免主动跑本地全量；PR CI 按仓库配置执行。
- 本地实际浏览我的记录、目录、单元及讲练历次，核对结果页得分卡未变；PR 列出手动验证步骤。
- 教师端追加记录/批改/课程矩阵/学情矩阵回归，覆盖待批、教师改判、自评回落、多次历史冻结题数及教师隔离；确认教师展示与学生已公布结果同源，学生未公布保护仍独立生效。
