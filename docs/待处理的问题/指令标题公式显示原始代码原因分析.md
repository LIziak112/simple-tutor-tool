# 指令标题公式显示原始代码原因分析

> 记录日期：2026-10-09  
> 触发场景：在讲义中编写包含 LaTeX 行内公式的指令标题（如 `::::example{title="例 1：$0/0$ 型未定式泰勒展开确定待定常数"}`）时，例题卡片正文中的数学公式渲染完全正常，但卡片标题中的 `$0/0$` 却显示为未经渲染的原始文本 `例 1: $0/0$ 型未定式泰勒展开确定待定常数`。  
> 结论先行：**`remark-directive` 将指令的花括号属性 `{title="..."}` 解析为普通的字符串属性，流水线中的 `remark-math` 仅解析 Markdown 正文节点流，不会递归解析属性对象；同时前端指令组件（如 `ExampleDirective`、`StepDirective`、`Callout` 等）直接将 `title` 作为 React 纯文本节点（Text Node）输出，缺少行内 KaTeX 解析与渲染管线，导致 LaTeX 定界符 `$` 原样暴露。**

---

## 一、现象还原

在讲义编辑/导入页面（`/t/library?tab=lectures`）中编写如下讲义源码：

```markdown
## 六、典型例题精析

::::example{title="例 1：$0/0$ 型未定式泰勒展开确定待定常数"}
已知极限 $\lim_{x \to 0} \frac{\cos x - (1 + a x^2)}{b x^4} = 1$，求常数 $a$ 与 $b$ 的值。

:::solution
**解题思路**：分母为 $b x^4$，阶数为 4 阶。因此分子必须麦克劳林展开到 $x^4$ 阶，并令低阶项系数为 0。
:::
::::
```

### 渲染呈现对比
* **正文区域**：极限公式 $\lim_{x \to 0} \frac{\cos x - (1 + a x^2)}{b x^4} = 1$、阶数 $x^4$ 以及折叠项 `:::solution` 均正常渲染；
* **例题标题（卡片头部）**：显示为带有原始 `$` 定界符的文本：
  > $\sum$ **例 1: $0/0$ 型未定式泰勒展开确定待定常数**

`$0/0$` 没有被编译为数学公式排版，原始定界符直接暴露给用户。

## 二、底层原因剖析

### 1. 技术链路与解析边界

`RichMarkdown` 的渲染数据流经由 `remark` AST 解析、`rehype` 转换，最终交付给 React 自定义组件：

```
Markdown 源码
   │
   ▼
remarkParse
   │
   ├─► remarkDirective  ──► 将 ::::example{title="..."} 识别为 containerDirective
   │                         并将属性存入 node.attributes.title（普通纯文本 string）
   │
   ├─► remarkMath       ──► 仅扫描并转换正文段落流中的 $...$ (inlineMath) / $$...$$ (math)
   │                         ❌ 绝不扫描或转换 node.attributes 对象内部的属性值
   │
   ├─► remarkDirectiveHost ─► 将 containerDirective 转为 <directive-container>
   │                         将 attributes.title 透传至 DOM properties.title
   │
   ▼
React 组件层 (ExampleDirective)
   │
   └─► <figcaption>{title}</figcaption>  ❌ 直接作为 React 纯文本输出
```

### 2. 核心问题点分析

#### ① Remark AST 解析阶段：属性值不参与数学解析
* `remark-directive` 的 CommonMark 指令规范中，花括号内的键值对 `{key="val"}` 被存放在 AST 节点的 `attributes` 字典中。
* 流水线中的 `remark-math` 仅对正文 AST 节点（`text` 节点）中的数学语法进行切分与节点转换，它**不会遍历处理非子节点的属性字段**。
* 因此无论用户在 `title` 属性中写了什么，`attributes.title` 始终是未经处理的原生字符串。

#### ② 前端指令组件层：纯文本（Plain Text）输出
查看 [`apps/web/src/features/markdown/directives/Question.tsx`](../apps/web/src/features/markdown/directives/Question.tsx#L66-L80) 的源码实现：

```tsx
export function ExampleDirective({ attrs, children }: DirectiveProps) {
  const title = attrs.title?.trim() || "例题";
  return (
    <figure
      data-slot="example"
      className="my-4 rounded-xl border border-border bg-muted/30 p-4"
    >
      <figcaption className="mb-2 flex items-center gap-2 text-sm font-semibold">
        <Sigma aria-hidden className="size-4 text-primary" />
        {title} {/* 👈 根因：直接将 title 字符串作为 React Text Node 输出 */}
      </figcaption>
      <div className="text-sm leading-7">{children}</div>
    </figure>
  );
}
```

* React 遇到 `{title}` 字符串表达式时，直接调用浏览器的 `document.createTextNode` 创建原生文本节点。
* 该文本**完全没有经过 KaTeX 的编译，也没有经过 Markdown 的行内样式解析**。
* 因而任何包含在 `title` 里的行内语法（如 `$0/0$`、`**加粗**`、`*斜体*`、` `代码` `）都原样展示。

## 三、系统性共性缺陷（波及范围）

此问题不仅存在于 `example` 指令，全系统所有支持 `title` 或 `label` 属性的指令均存在相同缺陷：

| 指令名称 | 对应组件文件 | 当前渲染写法 | 缺陷表现 |
| :--- | :--- | :--- | :--- |
| **`example`** | `features/markdown/directives/Question.tsx` | `{title}` | 标题内公式 `$0/0$` 暴露原始代码 |
| **`step`** | `features/markdown/directives/Steps.tsx` | `{title && title.length > 0 ? title : ...}` | 步骤标题如 `title="计算 $f'(x)$"` 暴露公式 |
| **`fold`** | `features/markdown/directives/Steps.tsx`<br>`features/markdown/directives/LabeledFold.tsx` | `label={attrs.title}`<br>`<span>{label}</span>` | 折叠标题如 `title="证明 $\sin x < x$"` 暴露公式 |
| **`tip`** | `features/markdown/directives/Callout.tsx` | `<p>{title}</p>` | 提示框标题如 `title="当 $x \to 0$ 时"` 暴露公式 |
| **`warning`** | `features/markdown/directives/Callout.tsx` | `<p>{title}</p>` | 警告框标题如 `title="注意 $a \neq 0$"` 暴露公式 |
| **`box`** | `features/markdown/directives/Callout.tsx` | `<p>{title}</p>` | 版式盒标题如 `title="定理 $1$"` 暴露公式 |

在数学、物理、计算机等理科讲义中，在例题、步骤或提示标题中书写变量与数学表达式是普遍的高频需求。

## 四、额外潜在隐患：中文全角引号

在用户提供的截图中，左侧编辑器源码第 3 行显示为：
```markdown
::::example{title=“例 1: $0/0$ 型未定式泰勒展开确定待定常数”}
```
**隐患点**：引号疑似使用了中文全角双引号 `“` 和 `”`。
* 尽管在特定编辑器分词或宽松模式下属性可能被勉强截取，但在标准 `remark-directive` 属性规范中，属性值的定界符必须是英文半角双引号 `"`。
* 使用中文全角引号可能在 `pnpm tutor-lint` 校验、不同平台的解析器、或转义处理时引发意外截断或将引号作为标题内容的一部分。
* 编写规范中应明确要求属性一律使用半角字符。

## 五、解决方案规划

### 1. 临时规避方案（用户端）
在系统升级前，教师在编写讲义时可采用纯文本替代写法：
* 写法 A：去掉 `$` 符号，直接写字符：`title="例 1：0/0 型未定式泰勒展开确定待定常数"`；
* 写法 B：将公式移至例题正文第一行，`title` 仅保留概括性文字：`title="例 1：未定式泰勒展开确定待定常数"`。

### 2. 系统根本修复方案（研发端）

#### 方案设计：引入轻量级行内富文本/公式渲染组件 `<InlineRichText>`
在 `apps/web/src/features/markdown` 中实现一个专门针对单行属性文本（如 `title`、`label`）的行内渲染组件：

1. **实现机制**：
   * 可采用 `KaTeX` 的行内解析器（例如用正则切分普通文本与 `$...$` 公式段，公式段直接调用 `katex.renderToString` 或渲染为 KaTeX 容器）；
   * 或轻量级复用 `ReactMarkdown`（配置 `allowedElements: ['span', 'strong', 'em', 'code']`，启用 `remarkMath` + `rehypeKatex`，包裹元素设为 `Fragment` 或 `span`，禁止产生块级 `<p>`）；
2. **全局替换指令标题渲染**：
   * 在 `ExampleDirective`、`StepDirective`、`Callout`（tip/warning/box）、`LabeledFold` 中，统一将纯文本 `{title}` / `{label}` 替换为 `<InlineRichText text={title} />`；
3. **补充自动化回归测试**：
   * 在 `RichMarkdown.test.tsx` 中补充例题标题、步骤标题、折叠标题中包含 `$x^2$`、`$0/0$` 时的渲染断言；
   * 确保标题既支持纯文本，也支持行内 KaTeX 公式，且不产生多余的换行或块级容器。
