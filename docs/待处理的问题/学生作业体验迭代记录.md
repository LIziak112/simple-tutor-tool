## U01：画布错层修复

状态：实现与验证完成。

根因是 annotation-surface.mount 覆盖了调用方 absolute 定位，并额外设置宽度和 aspect-ratio，导致覆盖层成为底图下方的第二块文档内容。现在题面拥有布局，引擎只负责在宿主内铺满画布。仓库唯一生产调用方 AnnotationWorkspace 已提供 absolute inset-0 宿主，因此不需要增加另一套尺寸逻辑。

验证结果：

- `pnpm test apps/web/src/features/annotation/annotation-surface.test.ts`：13项通过。修改前新增定位测试失败，修复后通过。
- `pnpm e2e e2e/annotation.spec.ts --project=chromium`：3项通过，含真实底图生成、实际画布红色像素、两视口左右/上下锚定、交卷封存和教师回看。
- `pnpm typecheck`：所有workspace通过。
- `pnpm build`：server/web通过；现有大chunk及Vite配置警告仍在。
- 修改文件的Biome检查通过。

复用/简化检查：只移除引擎越权修改宿主布局的三条语句，不加重复布局抽象。
正确性审查：唯一生产调用方负责定位；canvas仍保持底图像素坐标、绝对定位、100%宽高；输入/撤销/同步/封存均未修改。补充E2E的坐标检查弥补此前只检查宽高的缺口。

手动验证：进入有标注的题目，展开圈画；在文字附近落笔，笔迹应覆盖底图而非出现在下方空白区；缩放宽度后仍在原底图位置；交卷后可只读回看。

## 第二轮：共享题面、答题工作区与填写完整度

状态：本轮基础实现、质量审查与验证完成；本轮不宣称U02—U04所有验收项均完成。

### 变更范围

- `QuestionSurface`统一题干、判断、单选、多选和填空的渲染。export模式空置所有作答值、禁止回调；目前仅完成共享组件，尚未替换旧底图生成器，题面与底图的几何一致性验证留在U02后续。

## 第三轮：U02新布局底图准入

执行分支：`codex/question-surface-base`。本轮完成共享题面底图生成器与布局契约，尚未将它接入学生标画入口；旧底图、CAS上传和封存协议保持原样。

### 实现与边界

- `AnnotationSurfaceLayout`由contract的严格Zod schema定义，记录公开questionRevisionId、CSS尺寸、固定2倍像素比、样式版本，以及公开内容/块几何/字体签名；不下发或散列服务端私密snapshotHash。
- `renderQuestionBaseImage`只从公开题干和选项重建export副本。等待字体、图片、异步图形与连续稳定布局，再比较原题/副本块边界，容差不超过1 CSS px；生成前后原题布局必须保持一致。
- 底图验证PNG头、实际像素尺寸、空白及文件大小。分数CSS宽度使用向上取整的像素尺寸，避免HTMLCanvasElement隐式截断造成裁边。失败不返回残缺底图，离屏React根与宿主必定清理。
- 判断题选中图标始终占据固定尺寸；正常与export副本各自使用独立radio组名，避免生成副本时取消原题选中状态。副本设为inert且没有作答回调，填空值与选中态为空。
- `/dev/question-base`只在开发环境注册，提供真实浏览器夹具；不进入生产导航或构建，不新增依赖、学生接口、数据库字段或判分逻辑。
- 当前拒绝超出4096像素边长的题面、坏公式、图片失败、横向溢出及展开折叠材料后与默认副本不一致的布局。后续U06须给这些状态提供兼容入口，不能据此直接放行原位覆盖。U05的本地PNG缓存、原子写入、服务器绑定及热缓存性能尚未实现。

### 质量闸门与验证

测试先行：新增布局契约、隐私标记/尺寸拒绝、radio组隔离与固定图标测试先失败，再实现。真实浏览器覆盖判断/单选/多选/四空/行内和块公式/本地图片/表格/长选项/函数图形，宽度304.25、720、856 CSS px，读取PNG实际像素验证非空与精确尺寸；生成后原有选择与私人填答不变。

复用/简化审查：复用QuestionSurface和已有字体嵌入、PNG校验、超时工具；不克隆作答DOM，不添加另一套Markdown渲染器，不把新布局版本塞入旧版底图。布局类型只从contract推导。

正确性审查：确认分数像素取整、选中图标几何、跨实例radio互斥、渲染异常/布局变化/图片失败清理及旧数据不被修改。展开材料目前明确拒绝，而非假装兼容。生产构建不含开发夹具。

安全审查：没有修改学生端载荷或新增API；生成器拒绝未脱敏空位及教师区块，export不接收本人的答案值；严格schema拒绝snapshotHash额外字段。原有学生载荷泄露测试与E2E泄露监视继续执行。

## 第四轮：阅读位置恢复

执行分支：`codex/attempt-reading-position`，承接U02提交`290692b`。补齐计划第3.4节的阅读恢复，不宣称U03/U04余项全部完成。

- `useReadingPosition`复用现有题卡ref集合，同时驱动当前题号和持久化，删除AttemptSession内重复的滚动观察逻辑。只保存questionId及相对sticky题头偏移，按部署origin、学生id、attemptId隔离，不存答案、个人填答或题目内容。
- 重新进入时等待字体、图片、题面异步资源以及连续300ms稳定几何；最多等待5秒，仅恢复一次。过期题号、存储不可用或资源超时不会阻断作答；不聚焦、不改变选中答案。当前版本对前序懒加载图片一直未就绪的情况放弃恢复，而不是猜测位置。
- 滚轮、触摸、指针按下或键盘先发生即取消待恢复，之后不会突然跳回旧位置；身份尚未绑定时的先行操作也会保留，迟到的绑定不能重新抢滚动。正常滚动以RAF更新当前题，200ms防抖写入；pagehide立即采集最新位置并写入，卸载取消待执行恢复及事件订阅。
- 等待只关注题面中的资源状态，草稿等待同步等旁路状态不阻止恢复。所有持久化错误只降低阅读恢复能力，不影响已有答案、草稿或标注同步。

测试先行：11项专项测试覆盖稳定后只恢复一次、4种用户操作取消、部署/学生/练习隔离、资源超时、过期题号、存储失败、旁路同步、关闭页面立即保存及迟到身份绑定。旁路状态、pagehide和迟到身份用例先失败再修复。

复用/简化审查：当前题导航与阅读保存共用一次滚动采样；本机阅读偏好不新增业务契约、服务器接口或平行草稿仓。正确性审查补查了防抖关闭窗口、卸载清理、资源等待范围和多层列表定位；浏览器测试使用article的直接父题卡，避免误测整节外层列表。

安全审查：未改变学生载荷、提示解锁或服务端判分；本机状态只有公开questionId和数字偏移。浏览器测试使用隔离测试作业，未操作用户原有作业。
