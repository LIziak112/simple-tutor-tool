# 标画题面与草稿按需分栏修复

日期：2026-10-15。用户已明确要求直接修复；分支 `codex/annotation-paper-space`。

## 根因与实施计划

题卡按布局偏好提前分配题干 55% 列位，没有检查草稿是否实际展开；放大模式又跨容器宽度变化保留，导致右侧无草稿时仍留空、打开分栏后出现非必要横向滚动。

1. `AttemptQuestionCard.tsx`：只有草稿实际展开才启用左右布局，收起时题干恢复整行；上下布局不分配右列。保持题面和草稿控制器身份。
2. `QuestionAnnotationOverlay.tsx`：可用宽度确实变化时先收笔，再清除旧的手动放大状态并重新适配；仅高度变化不取消放大或多余收笔。保留固定逻辑排版、矢量坐标和底图，不重生成已有底图。
3. 先修改组件与真实浏览器回归，确认旧实现失败，再改实现。覆盖自动／左右／上下、收起整行、分栏等比缩放、缩放前后像素和笔数不变、切换布局不重挂、既有放大状态重算。
4. 对完整差异依次做复用简化、正确性审查；运行相关单测、Chromium/WebKit 隔离回归、类型检查、构建与检查，更新 AGENTS 和架构约定，再按项目流程提交与本地集成。未安装同名工作流技能时按对应目标人工执行并如实记录。

用户本次要求替代此前“草稿收起后保留列位”的旧约定。保持外框宽度策略稳定，不为关闭的草稿分配内部列宽。

## 验证结果

先观察旧实现的两个失败：关闭草稿仍为 side；可用宽度改变后放大比例仍为 1。另补测关闭的草稿列不留占位间距，再改实现。没有修改接口、契约、持久笔迹或已有底图。

完整差异已依次按复用／简化、正确性目标人工审查：仅调整布局准入与已有 ResizeObserver，没有新增状态控制器、队列或依赖；缩放前先收笔，尺寸不变通知不会反复收笔或取消用户放大。相同笔迹的 backing 尺寸、像素散列、笔数均保持；草稿和题面子树保持挂载，失败保护沿用原路径。未触及学生载荷或答案数据，无需新增学生接口泄露测试。

## 手动验证

1. 草稿布局设为自动或左右，保持关闭，打开已有标画题：完整题面居中显示，无半栏预留和非必要滚动条。
2. 展开左右草稿：蓝框内题面与笔迹共同缩小适配左栏；收起后恢复整行。
3. 上下布局展开／收起，题面宽度不受影响。
4. 先放大题面再打开左右草稿，确认自动重新适配；仅高度变化不取消放大。
5. 连续开合、续写、撤销、刷新与导出，确认笔迹不变形、不丢失，保存失败仍保留编辑状态。
