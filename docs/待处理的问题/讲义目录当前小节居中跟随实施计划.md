# 讲义目录当前小节居中跟随实施计划

日期：2026-10-12。状态：用户已确认，实施及分支验收完成；目标分支 v2。

## 问题与根因

用户截图中当前小节位于目录底部，需要手动拖动目录滚动条才能看清上下文。
`apps/web/src/features/markdown/LectureOutline.tsx` 已根据 currentIndex 高亮并展开当前章节，但未调整目录滚动位置；页面桌面和移动目录各有独立的 overflow-y-auto 容器。因此正文的阅读位置与目录的可视位置脱节。

## 修改范围

1. `apps/web/src/features/markdown/LectureOutline.tsx`：给当前项与目录容器建立明确引用；当前小节变化、章节展开完成和目录尺寸变化后，按当前项中心与容器中心的差值调整目录 scrollTop，并限制到合法范围。频繁阅读跟随使用即时滚动，保留手动滚动能力；同一小节内不持续拉回。不调用会滚动正文祖先的 scrollIntoView，也不抢焦点。
2. `apps/web/src/pages/student/StudentLectureViewPage.tsx`：将桌面目录和移动弹窗各自的滚动容器引用传给目录。重新打开目录时定位当前项；首尾条目在滚动边界内尽量居中。
3. 相关组件/页面单测：先增加失败测试，覆盖当前项改变、边界限制、展开后定位、无当前项、手动滚动不被同一小节重渲染覆盖及不改变焦点。
4. `e2e/student-lecture-reading.spec.ts`：补充 Chromium/WebKit 中长目录随正文阅读自动居中、移动目录重开定位、正文位置不被目录跟随改变的断言。
5. 本文补充真实验证结果和手动验收步骤。

## 执行与验收

从最新 v2 创建独立分支与隔离工作目录，不切换当前其他任务的分支。依次执行 TDD、完整 diff 的 simplify 与 code-review、相关测试、类型检查、lint、构建及真实双浏览器 E2E；全部通过后按本会话授权合并 v2。

手动验收：在长讲义中连续向下阅读到后半部分，各当前小节在目录可滚动范围内接近中央；无需拖目录滚动条。展开/收起章节及重开目录后依然看得到当前项；手动浏览目录时，同一小节内不会自动拉回；正文滚动位置和键盘焦点保持正确。

本次只修目录的定位跟随，不修改 API、契约、DSL 解析或讲义内容；不新增依赖。

## 实施与质量闸门记录

分支：`codex/lecture-outline-center`，基于 v2 `28549ac`。桌面和手机使用各自容器引用，共用目录内的居中逻辑；当前项变化、展开状态变化及 ResizeObserver 尺寸变化后定位。通过 scrollTop 仅调整目录；首尾按合法范围限位，收起当前章时定位所属章。没有当前项或不可见尺寸时跳过。卸载断开观察器。

TDD 首轮：6 个测试中 4 失败、2 通过，失败证实目录只高亮而不滚动；实现后通过，追加尺寸变化/清理测试后 7 个组件测试通过。

按 simplify → code-review 顺序审查完整 diff：复用桌面/移动目录组件，不增加全局滚动监听或新的抽象；检查容器隔离、首尾边界、关闭目录/重新打开、隐藏子节、观察器释放、同一小节内手动滚动及即时跟随。没有未处理的确认发现。本会话没有可调用的 `/simplify` 或本地 diff 版 `/code-review`，本次执行人工等价审查，未宣称执行外部命令。修改不触及学生端载荷或答案数据。

真实浏览器首轮断言失败：收起整个侧栏会改变正文宽度，从而触发布局及浏览器滚动锚定，不能用来证明目录滚动隔离。改为展开其他目录章节（只改变目录高度），验证正文 scrollY 不变；不是修改产品代码去掩盖布局变化。
