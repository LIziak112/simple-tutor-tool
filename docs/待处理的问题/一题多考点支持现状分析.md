# 一题多考点支持现状分析

> 记录日期：2026-10-07
> 问题：按照规范（[dsl-kit/规范.md](../dsl-kit/规范.md)），我们的 demo 支持一个题目包含多个考点吗？
> 结论先行：**不支持。现行 DSL 语法一道题只能标注一个考点**；但数据契约与存储层已经为多考点预留，属于「语法未开放、数据层已就绪」的状态。

## 一、依据

1. **规范层面**：[dsl-kit/规范.md](../dsl-kit/规范.md)（生成源为 [docs/dsl/规范.md](../dsl/规范.md)）属性表明确写：

   ```
   | knowledge | string | 否 | — | 考点（单个字符串），用于学情统计；解析时归一为数组入库 |
   ```

   示例也是单值写法：`::::question{type=fill difficulty=2 knowledge="有理数加法"}`。

2. **注册表（契约）层面**：[packages/contract/src/directives.ts](../packages/contract/src/directives.ts) 中 question 指令的 schema 为：

   ```ts
   /** 考点（单个；解析时归一为数组入库，见 content.ts questionSchema.knowledge） */
   knowledge: z.string().min(1).optional(),
   ```

   即单个字符串，注释同样写明「单个」。

3. **解析器层面**：[packages/md-dsl/src/v2/question.ts](../packages/md-dsl/src/v2/question.ts) 做的是单值包数组：

   ```ts
   knowledge: attrs.knowledge !== undefined ? [attrs.knowledge] : [],
   ```

## 二、两个容易踩的坑（demo 编写时注意）

- 写 `knowledge="有理数加法,整式乘法"` **不会**得到两个考点，而是入库成一个名字叫「有理数加法，整式乘法」的考点——解析器不做任何分隔符拆分。
- 重复写两次 `knowledge="a" knowledge="b"` 同样没有多值效果——Markdown 指令属性是键值对，同名重复只保留一个值。

## 三、底层其实已经预留了多考点能力

| 层 | 现状 | 出处 |
| --- | --- | --- |
| 数据契约 | `knowledge: z.array(z.string().min(1)).default([])` 就是数组 | [packages/contract/src/content.ts](../packages/contract/src/content.ts) questionSchema |
| 存储 | 注释注明经 `knowledge_points` / `question_knowledge` 关联表存储（多对多） | content.ts knowledge 字段注释 |
| 学情统计 | 考点为公共数据，按名称全局匹配合并（多题共享同名考点会聚合为同一考点） | [docs/dsl/规范.md](../dsl/规范.md)「考点合并」说明 |

即「一题多考点」在数据模型与学情统计上都是通的，**卡点只在 DSL 语法只有一个字符串槽位**。

## 四、若将来要放开多考点，改动路径与风险

按 AGENTS.md 规则 11（已发布指令只增不改、新属性可选有默认、改动走注册表四步流程），有两条候选路径：

| 路径 | 做法 | 风险 |
| --- | --- | --- |
| A. 分隔符约定 | 解析器对 `knowledge` 值按约定分隔符（如 `,`）拆分 | **语义变更风险**：存量内容中名字本身含分隔符的考点（如「有理数加法，整式乘法」）会被拆散，需要迁移考量与 lint 提示；严格说这是对既有语义的修改，与「只增不改」有张力 |
| B. 新增可选属性/新语法 | 如新增可选属性承载第 2+ 考点，或约定容器体内列考点行的写法 | 完全只增不改、存量零影响；代价是写法略重，需同步 lint 规则 + `pnpm gen:spec` + samples 样例 |

无论选哪条，都需同步：注册表（directives.ts）→ 解析器归一逻辑 → lint 规则 → samples 样例与测试 → `gen:spec`（规范与 dsl-kit 分发包）。

## 五、给 demo 的当前建议

在多考点语法正式放开之前，demo 请**遵守规范只写单个 `knowledge`**；若一道题确实横跨多个考点，建议：

1. 选**最主要的考点**标注（学情统计按名称全局合并，多题同名考点会聚合）；
2. 其余考点可在题干或详解中以文字提及，或用 `:::tip` 标注「本题还涉及××考点」；
3. 确有批量多考点需求时，先按第四节路径立项讨论，勿在 demo 中用逗号分隔等临时写法（会产生脏考点数据）。
