# 讲义自动目录公式显示原始代码原因分析

> 记录日期：2026-10-07  
> 触发场景：讲义 H2/H3 标题中包含 LaTeX 行内公式（如 `### 1. $\varepsilon-N$ 严格定义`）时，正文中公式渲染正常，而左侧目录列中却显示为未经渲染的原始代码 `1. $\varepsilon-N$ 严格定义`。  
> 结论先行：**正文使用了完整的 Markdown + KaTeX 解析与渲染管线，而目录提取模块仅使用正则抓取了原始文本，且目录组件直接以 React 纯文本（Plain Text）输出，缺少 KaTeX 渲染支持，导致 LaTeX 定界符 `$` 及宏命令原样暴露。**

---

## 一、现象还原

用户在讲义 Markdown 中书写包含数学公式的标题：

```markdown
## 二、数列极限的定义与核心性质

### 1. $\varepsilon-N$ 严格定义
```

在前端讲义阅读页（`/s/lectures/:id`）的呈现状态为：
- **正文区域（右侧）**：正常渲染为排版优美的数学符号 $\varepsilon-N$；
- **目录列（左侧导航）**：条目直接展示为带 `$` 符号的原文字符串：`1. $\varepsilon-N$ 严格定义`。

*(注：全选网页复制时正文出现 `ε−Nε−N` 重复，属于 KaTeX 兼顾无障碍生成的 MathML 隐藏层与 HTML 视觉层被浏览器同时抓取所致，页面实际视觉展示为单个正常符号。)*

---

## 二、底层原因剖析

### 1. 正文与目录列的技术实现差异

正文与目录列采用了两套截然不同的渲染机制，导致了渲染能力的不对等：

| 维度 | 正文区域（右侧） | 目录列（左侧导航） |
| :--- | :--- | :--- |
| **数据源处理** | 原始 Markdown 完整内容 | 正则匹配提取的 `item.text` 纯字符串 |
| **解析管线** | `remark-parse` + `remark-math` + `rehype-katex` | 仅正则表达式 `ATX_HEADING_RE` 抓取行文本 |
| **渲染引擎** | `<RichMarkdown>` + KaTeX | 普通 React 文本节点 `{item.text}` |
| **公式支持能力** | ✅ 完整支持 LaTeX 行内与块级公式 | ❌ 仅支持纯字符串，不支持公式与富文本 |

---

### 2. 源码调用链路分析

#### ① 目录文本提取逻辑缺少公式编译与清洗
查看前端目录提取实现 [`apps/web/src/features/markdown/outline.ts`](../apps/web/src/features/markdown/outline.ts#L20-L66)：

```ts
const ATX_HEADING_RE = /^(#{2,3})[ \t]+(.+?)[ \t]*#*[ \t]*$/;

export function extractOutline(markdown: string): OutlineItem[] {
  // ...
  const heading = ATX_HEADING_RE.exec(rawLine);
  if (heading) {
    const text = (heading[2] ?? "").trim();
    // 此时捕获的 text 为原始字符串："1. $\\varepsilon-N$ 严格定义"
    items.push({
      depth: hashes.length === 2 ? 2 : 3,
      text,
      id: outlineId(text, occurrence),
    });
  }
}
```
`extractOutline` 仅通过简单正则切分行首的 `##` / `###`，截取到的 `text` 字段完整保留了 Markdown 原文中的 `$...$` 及其内部的 LaTeX 代码。

#### ② 目录视图组件直接作为纯文本渲染
查看前端讲义阅读页面实现 [`apps/web/src/pages/student/StudentLectureViewPage.tsx`](../apps/web/src/pages/student/StudentLectureViewPage.tsx#L46-L75)：

```tsx
function LectureOutline({ items, onNavigate }: { items: OutlineItem[]; ... }) {
  return (
    <nav aria-label="讲义目录" className="...">
      <ol className="flex flex-col">
        {items.map((item, index) => (
          <li key={item.id}>
            <button ...>
              {/* 直接作为 React 纯文本节点输出 */}
              <span className="truncate">{item.text}</span>
            </button>
          </li>
        ))}
      </ol>
    </nav>
  );
}
```
在 `LectureOutline` 内部，目录标题直接作为普通字符串 `{item.text}` 放入 `<span>` 中渲染，未挂载 KaTeX，亦未接入富文本解析管线。因此，定界符 `$` 及 `\varepsilon` 被浏览器当作普通文本字符直接呈现给用户。

---

## 三、应对与解决方案

### 1. 内容端优化建议（讲义编写端，立即生效）

讲义的 H2/H3 标题核心用于**目录检索与导航定位**，在前端尚未支持目录富文本/公式前，建议编写者：
- **在标题行中避免使用 `$...$` 公式**，使用通用的纯文本或 Unicode 希腊字母替代；
- **优化对比**：
  - 改造前：`### 1. $\varepsilon-N$ 严格定义`
  - 改造后：`### 1. ε-N 严格定义`
- **优势**：目录导航与正文两端均能美观清晰显示，正文段落内部仍可照常使用标准的 `$\varepsilon-N$`，不受任何影响。

---

### 2. 前端系统修复路径（供平台开发者参考）

若平台后续需要原生支持标题公式在目录中的渲染，有以下两条改进路径：

#### 路径 A：在目录组件中接入轻量行内公式渲染
- 在 `LectureOutline` 中，将 `<span className="truncate">{item.text}</span>` 替换为支持行内 KaTeX 的轻量渲染组件（或使用正则检测包含 `$` 时调用 `katex.renderToString`），使目录呈现真实的数学符号排版。

#### 路径 B：在提取目录时清洗公式标记（降级为平文字符）
- 在 `outline.ts` 中对捕获的 `text` 增加公式文本归一化函数，将常见的简单公式符号（如 `$\varepsilon$` 转为 `ε`，`$x$` 转为 `x`）并剥除 `$` 定界符，确保目录条目作为整洁的纯文本显示。
