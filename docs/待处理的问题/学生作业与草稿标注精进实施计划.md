# 学生作业与草稿标注精进实施计划

本文是可派给开发 Agent 的执行规格，承接 [粉笔实测定稿](./题干标画方案-粉笔实测定稿.md)。出现细节差异时以本文为准；不是再次推倒技术架构。修改前仍须遵守 AGENTS.md 的计划确认、TDD、质量闸门及合并流程。

## 1. 结论与范围

**重做作答界面和标画入口，复用可靠的底层能力；不要整块删除现有标注系统，也不要复制粉笔的私有代码。**

本期交付一条完整链路：进入作业 → 阅读/填写 → 原位标画 → 演算或正式手写 → 同稿全屏 → 保存恢复 → 导出题图 → 检查遗漏 → 交卷 → 原有教师回看可用。

范围包括两个入口共用的 `AttemptSession`：`/s/assignments/:id` 和 `/s/attempts/:attemptId`。不重做学生首页、课程目录、错题本、教师批改台，也不重写判分、上传队列、Markdown 渲染器。

暂不做：自由笔迹随文字任意重排、同时用同一指针选答案和画线、多套版式编辑、超长题自动分片、图形编辑器新功能、AI 批注、批量整卷导出。上述边界必须有可理解的回退，不能表现成坏画布或数据丢失。

## 3. 页面结构与尺寸：不得自由发挥

### 3.1 组件树及所有权

下列新名称是建议创建的文件，不代表仓库已有；全部位于 `apps/web/src/features/attempt/`，除另有路径说明。

```text
StudentLayout                     身份、会话绑定；提供显式页面框架模式
  AttemptSession                  数据、提交、各题编辑协调，保留原职责
    AttemptWorkspace              布局、顶栏/底栏高度、焦点返回、滚动定位
      AttemptHeader               返回、标题、保存状态、更多
      QuestionNavigator           桌面侧栏；窄屏复用内容于弹层
      AttemptQuestionCard[]       各题容器，稳定 questionId key
        QuestionHeader            题号、题型、状态、标画/纸面/更多入口
        QuestionSurface           公开题干、原生选项/填空、透明标画层
        AnswerArea                题外最终答案、正式手写
        AuxiliaryArea             演算草稿、提示（不在标画覆盖范围）
      AttemptBottomBar            答题卡、进度、交卷；标画时替换为绘制工具
      SubmitConfirmDialog         遗漏定位、真实保存问题、最终确认
```

`QuestionHeader`、`AnswerArea` 可以先保持题卡内函数，不要求机械拆成文件。`QuestionSurface` 必须是独立共享组件，因为正常显示与导出必须共用布局。不要创建包级通用“万能工作台”。

### 3.2 页面布局

| 区域 | 明确规格 |
| --- | --- |
| 断点 | 小屏 <768px；中屏 768–1199px；宽屏 ≥1200px。测试断点两侧，不依赖 UA |
| 工作区 | 居中 max-width:1120px；小屏水平 padding:12px，其他 24px；正文 min-width:0 |
| 宽屏网格 | `192px minmax(0, 880px)`，gap:24px；答题卡始终预留列宽，开草稿不改变列宽 |
| 中小屏 | 单正文列，不留侧栏占位；答题卡通过底栏打开。不是把桌面整体缩成一张图 |
| 页头 | sticky top:0，min-height:64px；返回 44×44，标题 min-width:0、最多两行，更多 44×44；标题 18px/26px。保存信息可第二行，禁止与标题重叠 |
| 页头内容 | 返回、练习名、保存状态、更多。来源/截止/总题数合成页头下的一行普通元数据，允许换行；不再套大圆角标题卡 |
| 题卡 | 本题是重复项目，可用边框卡；radius:8px，无大阴影。小屏 padding:16px，其他 20px；题卡间 gap:16px |
| 题头 | min-height:44px；左侧题号+题型+填写状态，右侧三个 44px 图标位，gap:4px。小屏状态放下一行，禁止压缩点击区；不重复圆形数字和“第 N 题” |
| 正文 | 16px/28px，letter-spacing:0；段落间 12px；公式按内容自然高度。所有表单输入文字至少 16px |
| 选项 | 整行点击，min-height:48px，padding:12px；选项间 8px。单选/多选保持原生语义；判断题两等宽列 |
| 底栏 | min-height:64px 加 safe-area-inset-bottom；单层固定，内部与工作区对齐。答题卡 ≥44px、进度可压缩、交卷 min-width:88px、height:44px |
| 留白 | ResizeObserver 测量实际顶/底栏高度写 CSS 自定义属性；页面末尾 padding-bottom=底栏高度+24px；题卡 scroll-margin-top=顶栏高度+12px，不只写死 pb-24 |
| 层级 | 文档 0、题面标画层 1、sticky 页头 20、底栏 30、菜单 40、全屏/模态 50 以上；检查现有弹层库的层级，不给题卡祖先加 transform/filter |

颜色沿用现有 `background/card/foreground/muted/border/primary/destructive` 语义 token；选中蓝、警告琥珀、错误红。填写完成不使用表示判对的绿色对勾。正文对比度 ≥4.5:1，控件/焦点边界 ≥3:1；不得用颜色作为唯一状态。

桌面结构：`[题号导航 192] [题头 → 题面 → 答案 → 可展开纸面]`。手机结构相同但无导航列。首版不做题面/草稿左右分屏，这是保证标画不漂移和减少交互分支的明确决定。

### 3.3 路由、滚动、窄屏

- `StudentLayout` 增加受控的 workspace 模式上下文，默认 standard；`AttemptWorkspace` 在挂载/卸载时申请/释放。只在进行中答题视图启用，结果页、错误态和其他学生页面恢复 standard。不得以包含字符串的 pathname 猜测，也不得卸载鉴权、note/annotation session provider。
- 页面只用文档主滚动条；桌面题号栏 sticky，超高时自身滚动。不要再把每个题卡装进固定高度滚动容器。
- 保存当前可见 questionId 和相对题头偏移，按学生/部署/attempt 隔离；资源尺寸稳定后恢复一次。用户开始滚动即取消待执行恢复，不能突然跳走。
- 窄屏答题卡为有标题、关闭按钮、焦点约束的弹层，max-height:70dvh，内部滚动；选题后关闭并聚焦题头，焦点不能回弹到底栏。
- 键盘打开时输入必须可见；必要时通过 visualViewport 更新底栏可用位置，不做 UA 分支。若选择隐藏非编辑底栏，失焦后恢复；标画退出按钮不能因此消失。iOS/Android 真机验收单列，模拟器不算全部通过。

## 4. 题卡与标画的精确交互

### 4.1 区域边界

`QuestionSurface` 只覆盖公开题干、图片/公式、选择题选项、题干内填空。题号工具、最终答案输入、提示、草稿和正式手写区都在外面。采用真实 DOM + absolute 透明画布，禁止把日常题面换成截图，禁止额外生成可见题面副本。

题头图标使用现有 lucide：Pencil 标画、NotebookPen 纸面、MoreHorizontal 更多（以实际导出名为准）；均有含题号的 aria-label 和 tooltip。更多含题目资料、显示/隐藏标画、导出题图；难度与全部考点放题目资料，默认不占正文行。提示保持现有受控解锁流程，不能预取未解锁内容。

### 4.2 编辑状态机

`AttemptSession` 协调唯一活动编辑目标：`null | { questionId, kind: 'annotation' | 'scratch' | 'answerInk' }`。各域文档仍归各自控制器；此状态只协调交互，不存文档。

| 事件 | 必须执行 |
| --- | --- |
| 点标画 | 结束上一目标在途笔段，等待其本地持久化；本地就绪后本题进入 draw，默认红色细笔。失败停留作答态并给重试 |
| draw | canvas 接收 pointer；题面内表单子树 inert，不能 Tab 偷改答案；工具位于 inert 子树外。保持可读题面无整体灰蒙层 |
| 点“作答”/Esc | 提交当前笔段并本地保存，退出 draw；透明层 pointer-events:none，笔迹继续显示，原生输入恢复。Esc 遵守弹窗/输入法优先级 |
| 点另一题/最终答案/打开草稿 | 收束当前绘制，不 preventDefault 吞掉目标首次正常操作；同页只能一个目标接收绘制 |
| pointercancel/失焦 | 结束已采集的有效笔段、释放 capture，不留下永远绘制中的状态 |
| 撤销/重做 | 只操作当前域；清空作为一次可撤销动作；切模式不清历史，不拦截输入框的 Ctrl+Z |
| 隐藏笔迹 | 只改显示偏好，不删笔迹；按钮状态/菜单明确反映隐藏中 |
| 网络失败 | 已完成本地保存的稿仍可编辑；明确“仅保存在本机”；本地写失败不冒称已保存 |

工具条在所有屏宽都复用底栏槽位：画笔、橡皮、撤销、重做、更多、作答。5 个 44px 图标 + 64px 作答 + 5×4px gap =304px，可容纳 320px 视口的 8px 两侧留白。颜色/粗细藏在更多，不再叠加第二条固定栏；活动题的题头标画按钮显示选中态和“标画中”可访问名称。

长题滚出题头后底栏仍能退出。鼠标滚轮不吞；普通手指 draw 模式画线，作答模式滚动。笔写/手指滚动可复用已有输入模式能力，但默认行为必须经真机验证，不能按 pointerdown 后修改 touch-action 来补救。

### 4.3 定位与布局一致性

- 宿主独占布局：`QuestionSurface` relative，画布 host absolute inset:0；引擎不得写 host.position、margin、aspect-ratio 去改变文档流。需要 aspect-ratio 的旧图片工作区由外层决定。
- 坐标转换统一入口：题面局部 CSS 坐标乘 `baseWidth / surfaceCssWidth`；笔粗同倍率，DPR 仅决定 canvas backing store，不重复乘入文档。输入、回放、导出共用几何函数。
- 当前 v1 笔迹保持像素坐标，不为原位显示强制换格式。字体/图片/公式全部就绪且布局稳定后才生成基底；在稳定前标画入口 loading，答案正常可填。
- 点击选项仅改变不占布局的选中样式；填空框固定尺寸，不随答案变长扩宽；长答案框内部滚动。提示在 surface 外展开；草稿展开不改变 surface 宽度。
- 保存的布局描述包括公开 revision、renderVersion、CSS 宽高、像素比例、字体/样式版本、内容块几何签名。签名只取学生可见信息，不暴露服务端 snapshotHash；仅宽高相同不等于布局相同。
- 重新换行或块位置变化时，禁止把旧圈百分比拉伸到新题面。自动退出 draw，保存原稿；正常题面继续答，显示“查看原标画”入口。专用视图展示原底图并可继续编辑/导出；回到匹配布局恢复原位覆盖。变形期间不接受新笔段。
- 首版延续 4096px 高度、8MB PNG 等既有限额；超限明确禁用本题标画并保留草稿、作答。不得静默裁图。多布局/分片另开任务。

## 5. 草稿和正式手写：统一操作，不混合数据

| 内容 | 存储/用途 | 入口与默认行为 |
| --- | --- | --- |
| 题面标画 | AnnotationDoc；阅读标记附件 | 题头标画；不计作答案 |
| 演算草稿 | NoteDoc scratch；沿用附件提交机制 | 非正式手写题的纸面图标；下置折叠区域 |
| 正式手写 | 原 InkDoc/答案上传控制器；保持现有评分输入规则 | 手写题的纸面图标名为“手写作答”；不再同时默认增加第二张草稿纸 |
| 最终答案 | StudentAnswer；沿用保存与提交 | 永远有明确标签，独立于手写工具，不隐藏在更多菜单 |

草稿区展开后：顶部 44px 工具行 + 纸面，纸面初始可视高度320px、小屏280px，延续原逻辑纸张尺寸及扩纸规则，超出视窗可滚动；外层不再套卡片。收起不清稿；有旧稿显示笔迹存在标识，但不要后台播种一到就强行撑开题卡打断阅读。改掉 `NoteLayer` 的自动展开策略：仅首次进入且没有恢复滚动目标时允许，或统一默认收起；本期选择统一默认收起，用户展开状态在当前 attempt 会话保存。

全屏采用 **同一个已挂载画布 host + CSS fixed 容器**，预留原位占位高度，不能条件渲染第二个 InkPad，也不能更换 React key/portal container 使引擎重建。全屏仅改变外壳尺寸；显示当前题号、可折叠题干（最多28dvh）、单工具条、完成。处理背景 inert、焦点约束、滚动锁和焦点返回；不只写 aria-modal。

新稿默认沿用 Atrament。已有 Excalidraw 稿继续交给其原引擎，只读缩略图+明确“继续编辑”进入原引擎全屏；不自动转换或覆盖。打开空稿全屏再关闭不创建异种空文档、不改变答案状态。高级画图入口本期不新增，原能力仅为历史兼容保留。

验收：页内画3笔→撤销1笔→全屏→重做→再画1笔→完成，应该4笔；再次撤销应3笔，原笔位置不变。连续进出10次不新增监听器/画布实例；保存/交卷仍使用同一个权威 doc 和 flush 控制器。

## 6. 保存、布局契约与导出

### 6.1 最小数据改动

- 先修改 `packages/contract/src/annotation.ts`，底图 layout 新字段对旧记录可缺省，缺省按 legacy renderVersion=1 处理；新渲染版本使用明确分支，不把全体 v1 校验放宽。
- v1 固定1440宽规则保留；新版本宽度按实际 CSS 宽×固定像素比2生成，并在4096边长、文件字节等上限内校验。服务端检查 PNG 实际尺寸与声明一致。不要让修改旧常量破坏历史下载和数据包。
- 每 attempt/question/phase 仍一份权威底图；ready 后永不替换。旧底图只能兼容编辑/查看，不能贴到新 DOM。新原位功能仅用于尚未创建底图的 scope。
- 数据库如需新增 layout JSON/版本字段，先契约再 drizzle schema，再 `pnpm db:generate`；同时更新备份/恢复和数据包消费者，旧包导入仍能打开原稿。

### 6.2 本地优先不能只是一句口号

新建本地记录必须原子保存：scope（部署/学生/attempt/question/phase）、公开 revision、layout、base PNG、vector doc、同步状态。沿用已有存储框架，不把 Blob 塞 localStorage。服务端 baseId 尚未取得时允许本地 scope 记录 pending，不伪造服务端 ID。

同步顺序：取回/创建服务器底图身份 → 对比 scope/revision/layout → 上传匹配底图并 ready → 上传 vector body → 处理现有 CAS。服务器已有不同底图时保留本地 pending 稿，显示冲突处理，不覆写 ready 底图，不自动把不同版式的笔迹拼接。登出/账号切换必须遵循现有会话隔离与防迟到回写。

只预热当前与相邻题，最多一个栅格化任务执行；不可在加载16/130题时并发生成整卷图片。未 ready 前可以作答。已本地 ready 的标画不等待网络即可进入；缺图片且离线时提供真实不可用状态。

顶部聚合状态由各域适配器提供，不重写各域队列：错误/冲突优先，其次仅本机，其次保存中，全部远端确认后才“已保存”。展开详情可以定位第几题的答案/手写/草稿/标画。不要每笔弹 toast，使用局部状态和节流的 aria-live。

保持当前交卷语义：正式手写 flush 失败阻断；草稿附件缺失按已有明确选择处理；标画 seal 在提交后按现有补偿机制执行。新本地 pending 标画必须加入交卷前未同步材料提示，不能提交成功后悄悄丢弃；“仅交答案”只能在用户明确选择后，且本地稿保留供导出。修改相应契约及测试后才能改变附件清单语义。

### 6.3 导出

进行中即可从题头更多导出“题面与标画”。首版只交付这一种范围，不加入可选本人答案/手写的复杂组合；现有交卷后复习图导出保留原功能。

输出流程：当前匹配且已缓存的 base PNG + 同版本矢量 → `annotation-composite.ts` 合成一次 Blob → 同一 Blob 预览/下载/复制。文件名使用作业名、题号，去掉非法字符；默认 PNG。复制失败保留预览和下载，不能把复制失败说成导出全失败。

底图用共享 `QuestionSurface` 的 export 模式：保留空位/选项尺寸，清空个人输入、选中态和焦点；不带工具栏、提示、答案、生成时间与装饰标题。资源未加载、跨域图无法栅格化、公式报错时逐项提示并可重试，不产出半张成功图。导出只依赖公开题面，不能为导出请求教师题目详情。

## 7. 进度、答题卡、交卷

新增纯函数 `getQuestionCompletion(question, answer, formalInkPresence)`，结果区分 `empty | partial | filled`，包含 filledSlots/expectedSlots（适用时）。formalInkPresence 由现有正式手写控制器提供有效笔迹存在性，不传整个引擎实例。不能修改旧 `isAnswered` 来意外改变记录统计/已有接口含义。待检查是独立布尔状态，不取代填写状态；本期仅本机持久化，按用户和 attempt 隔离，不承诺跨设备同步。

- 判断题：false 也是有效答案；单选选1项、多选至少1项即 filled，多选正确数量未知，不猜。
- 填空：复用 `RichMarkdown` 的同一 AST/remark 空位编号规则提取应填槽位，不用正则数 `[[`，不使用 answer 数组长度，也不读取标准答案。覆盖显式 blank 指令、嵌套内容、代码/数学文本；共享计数 helper 与渲染器做一致性测试。不必首版新增学生 API 字段。
- 手写题当前 `isAnswered` 只按非空 finalAnswer 计已答，本期保留这一完成口径：最终答案非空为 filled；只有正式笔迹为 partial，标记“已写过程，未填最终答案”；两者都无为 empty。空 Excalidraw 场景不算笔迹，只有草稿/标画不计填写。不要根据像素非白数量判作答，也不要据此修改服务端评分。
- 底栏“已填写 X/N”；partial 不计完整。题头与导航可见“已填1/4空”，不显示对错判断。
- 题号按钮44×44，宽屏3列；未开始空心、部分填写有短横/文本标签、已填写实心并提供可访问名称、待检查旗标。当前阅读题额外描边，不冒充当前选中答案。
- 提交弹窗列出未开始和部分填写题号；“去补全”关闭弹窗、滚到对应题并聚焦首个空位/答案控件。无遗漏才直接显示正常确认；仍允许按既有规则确认空题交卷。
- 点击交卷必须先结束活动笔段，本地保存并执行既有 flush/prepareSubmitEvidence；防双击，失败保留输入，错误能定位，取消弹窗不清状态。
