# 圈画与草稿交互修复计划

状态：用户已确认实施与合并到 v2；在独立工作树的 codex/annotation-scratch-fix 分支实施。验证结果见配套实施报告。

## 已定位问题

- `AttemptQuestionCard.tsx` 从单一 `editor.active` 推导草稿展开状态，切到 annotation 会收起草稿。
- 题卡的 `note-body-row` 写死 below；`NoteLayer.tsx` 在有编辑协调器时隐藏布局菜单，已有布局偏好无法生效。
- 标画 surface 默认 inputMode 为 auto，两个标画入口未传入草稿采用的笔写偏好。
- 标画激活态缺少范围边框。
- 清空菜单为 Portal 内容；题卡 pointer capture 的区域判断可能将菜单操作误判为离开标画。此项是待验证假设，必须先复现，再确定修复。

## 文件清单

- `apps/web/src/features/attempt/AttemptQuestionCard.tsx`：独立展开状态、输入区域切换、侧边布局与区域判断。
- `apps/web/src/features/attempt/AttemptEditorContext.tsx`：仅在确有必要时调整协调接口，保留收笔、落盘和失败保护。

- `apps/web/src/features/annotation/annotation-surface.ts`：按测试定位结果决定是否需要调整，优先复用现有输入状态机。
- 上述组件对应测试、`annotation-surface.test.ts`、`AttemptQuestionCard.layout-identity.test.tsx`、`note-layout.test.tsx`。
- `e2e/question-inline-annotation.spec.ts`、`annotation-paper-interaction.spec.ts`、`note-layer.spec.ts`：真实浏览器回归。
- `AGENTS.md`、`docs/页面功能清单.md`：同步交互约定与手动验证口径。

## 实现步骤

1. 确认后建立独立 `codex/` 分支；先补失败测试，复现互斥、布局菜单缺失、手指落墨和清空失效。
2. 分离纸面展开与标画模式：同题圈画与草稿可同时显示，由各自区域处理笔输入；切题仍先收笔并确认本机落盘，失败时保留原稿。正常关闭一个区域不关闭另一个。
3. 标画激活时给可标画题面加淡蓝色外框，不改变题面几何；明确范围包含题干与选项，排除草稿、答案输入和提示操作。
4. 标画复用笔写／手指滚动偏好，默认笔与鼠标可写，手指滚动；无笔设备通过明确的手指书写开关启用。两个标画入口保持一致。
5. 根据复现修复清空链路：菜单操作不提前退出编辑；清空立即移除笔迹、写入本机并同步，支持撤销；重开与刷新不恢复已清空正文。
6. 恢复自动／右侧／下方布局选择，复用 note-layout 偏好与宽度阈值；自动布局窄屏放下方，显式右侧生效。布局切换不丢稿、不重建控制器；既有标画底图不兼容新宽度时保留原图与原笔迹入口。
7. 对完整 diff 依次做简化与正确性审查，修复确认的问题。当前环境未找到 systematic-debugging、simplify、verification-before-completion 的 SKILL.md，执行其根因定位、完整 diff 审查和真实命令验证纪律；不声称已调用缺失技能。
8. 跑验证并记录真实输出，分步提交；全部通过后按本次用户指定范围仅合并 v2。

## 测试与验收

- 同题草稿展开后开启圈画，两者保持可见且已有笔迹不丢；可在两处连续书写，关闭行为独立。
- 草稿操作与标画菜单不会误触发退出；快速切换、落盘失败、迟到准备回执保持安全。
- 清空、撤销、重做、重开、刷新覆盖活画布和保活预览；检查本机与同步后的正文。
- 两个标画入口默认手指不落墨，笔／鼠标可写；显式手指书写可用。
- 左右／上下／自动布局、窄屏与旋转；切换布局不丢控制器、笔迹或撤销历史；旧底图兼容性判断保持正确。
- 普通作业与讲练复用路径、已提交题锁定、正式手写、现存 samples 渲染回归。
- 运行相关单元测试与 Chromium/WebKit E2E（隔离数据库与 8899/5199），以及 `pnpm test`、`pnpm lint`、`pnpm typecheck`、`pnpm build`，贴实际结果。
- 真机手动验证 Pencil 起笔、手掌接触、手指滚动、同题圈画与草稿切换、横竖屏及清空后刷新。浏览器模拟不能替代真机手感验收。

本计划不新增依赖，预计不修改 API、内容契约或数据库结构；若排查发现需要改动这些范围，先补充计划。
