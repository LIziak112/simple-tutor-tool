# 属性解析的归一层级与静态渲染通道待办

> 记录日期：2026-10-09（T7.2 四角度质量审查遗留，超出该任务范围未当场处理）
> 来源：T7.2「宿主消费 Zod 属性解析」的复用/简化/效率/层级审查；当场已修复项见 docs/审查报告/T7.2-实施报告.md。

## 一、字符串空白归一（trim）留在组件层，schema 通道只校验不归一

类型/枚举/数字解析已收敛进注册表 schema（T7.2），但 `.trim()` 散在 6 个组件约 13 处（Callout/Columns/Question/Media/Steps 的 title/src/alt/width 等）。「必填缺失→整体降级」与「纯空白→占位/缺省」这条策略边界由 trim 住在哪一层隐式决定。

**建议**：评估在 `directiveAttrs` 底座或逐 schema 对字符串属性统一 `.trim()`（zod transform，非收紧校验——纯空白书写值当前也过 min(1)，trim 后语义为归一而非拒绝，需按 AGENTS 第 11 条做兼容评估并跑样例门禁 + gen:spec 产物）。成文一条「缺省显示文案归哪层」的准则：数据语义缺省（step 空串、difficulty 2）进 schema；UI 文案缺省（提示/注意/例题）留组件——当前 tip/warning/example 与 fold 已是两种口径并存。

## 二、static-markdown.tsx 仍是第二条手抄属性解析通道

`apps/web/src/features/markdown/static-markdown.tsx`（T6R.19/20 静态材料管线）与 RichMarkdown 共用同一 remark/rehype 管线，但保留独立的 `attrOf` 手读属性 + `STATIC_CONTAINER_LABELS` 硬编码 12 个指令名。T7.2 收敛后这里成了仅存的手抄解析面：image 属性语义演进时两通道会静默分叉。

**建议**：把「按注册表 schema 解析 attrs」提炼为可复用原语供 StaticDirectiveLeaf 消费；或在下一个动 static-markdown 的任务里让其复用 directives/index.tsx 的绑定机制。

## 三、两类降级共用「未支持指令」文案，缺失败类别维度

「未注册指令」与「已注册但属性非法」（如 difficulty=abc）都渲染「未支持指令：question」——老师得到的提示指向错误的修法（以为指令不支持，真因是属性值）。

**建议**：UnknownDirective 增可选 reason/variant（如「属性非法」），不分叉降级机制地保留区分；属产品文案决策，动它需同步改 RichMarkdown.test 与 typed-attrs.test 的期望文案。

## 四、渲染期 safeParse 的重复解析（量级小，方向性记录）

react-markdown@10 默认零 memoization，宿主组件随每次 RichMarkdown 渲染整树重跑——同一节点的静态 attrs 每次渲染都重跑一次 safeParse（讲义页约 200 节点 ≈ 桌面 0.1–0.6ms/渲染、iPad 毫秒级，相对周边 remark+KaTeX 全量重解析为个位数百分比，StrictMode dev ×2）。

不建议直接把校验挪进 remark-directive-host 解析期（挂在 hast properties 会与 rehype-sanitize 白名单机制冲突，且偏离方案 §4.1 确认的「查表后传参前」设计）。**真正的杠杆是 RichMarkdown 的 source 级 memo/解析结果缓存**（上游每次渲染全量 parse+katex 才是大头）；若未来做，safeParse 的重复随之一并归零。

**T7.3 评估结论（2026-10-09）**：最简可行形态是用 `useMemo([source])` 锁住 `<ReactMarkdown>` 元素身份——元素级 bail-out 跳过整棵 markdown 子树重渲染（parse+katex+safeParse 全免），而 context 消费者（BlankDirective 读 fill、折叠组件读 telemetry）不受 bailout 影响，仍随 Provider 值更新重渲染，正是想要的形态。属行为敏感的性能改动（components/plugins 闭包身份、StrictMode 语义都需验证），须带测量独立落地，不宜骑在重构任务上；本待办保持打开，作为该独立任务的起点。
