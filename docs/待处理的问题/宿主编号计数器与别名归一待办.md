# 宿主编号计数器与别名归一的错层待办

> 记录日期：2026-10-09（T7.2 交付物；方案 §2.2 镜像三 2026-10-08 口径的落档）
> 来源：Phase7 清单 T7.2 条目「本任务不改 remark 宿主编号计数器，在 docs/待处理的问题/ 留待办，新增别名涉及编号时再处理」。

## 现状

`apps/web/src/features/markdown/remark/remark-directive-host.ts` 的 `annotate()` 用**裸 `node.name`** 特判维护编号计数器：

- `question`（题号，进入新题清 hint/blank 计数）、`hint`（题内提示序号）、`step`（steps 内步序）、`blank`（题内空序）四个语义计数；
- `dindex`（文档全局块级指令序号，directive_interact 遥测定位用）。

而**别名 → 主名的归一发生在 L3 查表层**（`directives/index.tsx` 经 `getDirective(name).name`），晚于 L2 的编号生成。

## 潜伏问题（当前无实际影响）

评审报告 R06（步骤总数不一致）、R09（别名漏计）源于此：

1. 当前 17 个指令**均未声明 `aliases`**，裸名 == 主名，计数正确——R09 属潜伏问题而非现行 bug；
2. 将来任何指令启用别名（AGENTS 第 11 条改名兼容机制）时，旧名写法的节点会：
   - 不参与对应语义计数（如 `:::旧step` 不进 step 计数，index=0）；
   - 仍照常消耗 `dindex`（dindex 只按块级节点数计，不受名字影响，定位语义保留）。

## 处理口径（触发条件与做法）

- **Phase 7 不动镜像三**（2026-10-08 已定）；T7.2/T7.3 均不触碰。
- **触发点**：第一个真实启用 `aliases` 的指令且该指令（或其计数同类）参与语义编号时处理。
- **建议做法**：把归一提前到 `annotate()` 之前——遍历时先经 `getDirective(node.name)?.name` 归一再参与特判与计数（`getDirective` 来自 @tutor/contract，remark 插件内可用，无分层问题）；或计数特判按主名匹配。同步补一条「别名写法编号与主名一致」的回归测试（现有 outline-consistency/样例门禁可承载）。
