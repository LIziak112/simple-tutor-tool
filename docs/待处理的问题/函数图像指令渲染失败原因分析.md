# `::graph` 函数图像指令渲染失败原因分析

> 记录日期：2026-10-07  
> 触发场景：在讲义或题目中编写 `::graph{fn="atan(x)" range="-5,5"}` 时，页面展示 `函数图像渲染失败，请检查 fn 表达式书写。`  
> 结论先行：**表达式本身书写完全正确。失败的根本原因是 Web 前端打包产物中动态加载 `function-plot` 时存在 CommonJS 默认导出互操作（Interop）缺陷，导致运行时抛出 `TypeError: is not a function`；组件又将该运行时异常笼统归因并展示了误导性的错误提示。**

---

## 一、现象还原

在讲义或题目 Markdown 中插入如下符合 DSL 规范的指令：

```markdown
::graph{fn="atan(x)" range="-5,5"}
```

页面出现异常态：
1. 图像区域无法正常展示坐标系与曲线；
2. 界面展示红色错误警告：`函数图像渲染失败，请检查 fn 表达式书写。`，下方带有「重新加载」按钮；
3. 用户容易误判为数学函数名拼写有误（如怀疑应写成 `arctan(x)` 或缺少特定前缀）。

---

## 二、底层原因剖析

### 1. 根本原因：打包器（Vite / Rolldown）对 CJS 动态导入的 `default` 双重包裹导致 `TypeError`

查看前端指令渲染源码 [`apps/web/src/features/markdown/directives/Media.tsx`](../apps/web/src/features/markdown/directives/Media.tsx#L88-L105)：

```tsx
import("function-plot")
  .then((functionPlot) => {
    if (disposed || !hostRef.current) return;
    try {
      const options: FunctionPlotOptions = {
        target: hostRef.current,
        width: hostRef.current.clientWidth || 480,
        height: 260,
        data: [{ fn, graphType: "polyline" }],
      };
      const xAxis = parseGraphRange(range);
      if (xAxis) options.xAxis = xAxis;
      functionPlot.default(options); // <--- 问题发生在此处
      if (!disposed) setState("ready");
    } catch {
      if (!disposed) setState("error");
    }
  })
```

- **第三方库结构**：`function-plot`（v1.25.4）是一个 CommonJS 格式的第三方库，其主入口 `dist/index.js` 的导出结构为：
  ```javascript
  exports.default = functionPlot;
  exports.__esModule = true;
  ```
- **生产构建产物行为**：打包器在将 `import("function-plot")` 拆分为独立异步 chunk 时，注入了 CommonJS Interop 互操作辅助函数：
  ```javascript
  // apps/web/dist/assets/RichMarkdown-*.js
  import(`./dist-*.js`).then(t => e(t.default, 1)).then(e => {
    // ...
    e.default(a); // <--- 运行时报错
  })
  ```
- **运行时对象结构失配**：
  在生产环境浏览器执行时：
  - `typeof functionPlot.default === "object"`（它拿到的是包含 `{ default: [Function: functionPlot], Chart: ..., ... }` 的命名空间对象，并非可执行函数）；
  - 真正的可执行函数实际上被嵌套在了 `functionPlot.default.default` 中；
- **抛出异常**：
  当执行 `functionPlot.default(options)` 时，浏览器直接抛出原生运行时异常：
  ```text
  TypeError: functionPlot.default is not a function
  （生产构建混淆后为：TypeError: e.default is not a function）
  ```
- **影响范围**：该缺陷不仅影响 `atan(x)`，在当前生产构建产物下，**任何函数表达式（包括最简单的 `fn="x^2"`、`fn="sin(x)/x"`）都会因为该调用崩溃而无法渲染**。

---

### 2. 次要原因：异常捕获文案泛化产生严重误导

在 `Media.tsx` 中：

```tsx
} catch {
  if (!disposed) setState("error");
}
```

当 `try` 块捕获到任何异常时（包括由代码自身运行时调用抛出的 `TypeError`），统一将组件状态置为 `"error"`，并在页面上固定渲染提示文本：

```tsx
<p className="text-destructive">
  函数图像渲染失败，请检查 fn 表达式书写。
</p>
```

此设计将「前端代码调用异常」与「用户输入表达式语法错误」混为一谈，使用户误以为是自己的函数名拼写有误。

---

### 3. 关于数学表达式 `atan(x)` 本身的合规性验证

经对底层 `function-plot` 及其内置计算引擎 `built-in-math-eval`（基于 JavaScript 原生 `Math` 对象的封装）的实测验证：
1. 求值器支持的三角函数严格继承自 `Math` 对象，因此**正规反正切函数名为 `atan(x)`**（对应 `Math.atan`）；
2. 若用户尝试书写为高等数学惯用的 **`arctan(x)`**，底层的 `math-codegen` 求值器反而会报 `SyntaxError: symbol "arctan" is undefined`；
3. **结论**：用户书写的 `fn="atan(x)" range="-5,5"` 无论在 DSL 规范还是在底层数学引擎语法上都是**完全合规且正确**的。

---

## 三、修复建议与方案参考

> 注：当前分析任务严格遵循要求，未对业务源码作任何改动，此处仅提供技术建议供后续修复参考。

### 1. 前端 Interop 健壮性适配（推荐）
在 `apps/web/src/features/markdown/directives/Media.tsx` 中，对动态导入进来的 `functionPlot` 增加防御性解构：

```tsx
const fnPlot =
  typeof (functionPlot as any).default === "function"
    ? (functionPlot as any).default
    : typeof (functionPlot as any).default?.default === "function"
      ? (functionPlot as any).default.default
      : (functionPlot as any);
```

此种写法可无缝兼容各种环境：
- Vite Dev Server（esbuild 预构建环境）；
- 生产构建（Rolldown / Rollup 打包 chunk）；
- Node / JSDOM 测试环境。

*注：同理建议检查 [`apps/web/src/features/export/question-materials.ts`](../apps/web/src/features/export/question-materials.ts#L47) 中是否也存在相同的潜在调用风险。*

### 2. 异常日志与错误提示精细化
在 `GraphDirective` 的 `catch` 块中加入 `console.error`，便于调试排查：
```tsx
} catch (err) {
  console.error("[GraphDirective] render failed:", err);
  if (!disposed) setState("error");
}
```
并在 UI 上可根据具体错误类型（`SyntaxError` 还是 `TypeError`）显示更贴合的提示文案，避免误导内容编写者。
