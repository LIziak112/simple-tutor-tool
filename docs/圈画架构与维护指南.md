# 圈画架构与维护指南

本指南对应 2026-11-05 整题缩放实现。行为约束见 [手写与同步](约定/手写与同步.md)、[学生作答与讲练](约定/学生作答与讲练.md)，批准范围见[整题缩放计划](superpowers/plans/2026-11-05-圈画统一整题缩放实施计划.md)。阶段报告各自的未覆盖项仍需整合验收，不能据本文宣称全部旧稿兼容。

## 显示与保存

同题只有一个真实 QuestionSurface，题面、原生答案控件和兄弟墨层在原逻辑框内整体等比缩放；退出圈画仍显示笔迹并可直接作答。PNG 保留为存证与历史证据导出资产，不作为题卡主视图，不按图片坐标重造输入框，没有「进入作答／返回原稿」。

- AnnotationDoc.version=1 继续使用原 PNG 像素域，缩放不改 points、笔宽或原基准。材料使用独立的 1000 归一坐标。
- 来源、正文、权限与几何分别核验。身份、坐标域、公开结构不符仍拒绝；可量化块边界差异在 10px 内放行，10.001px 拒绝，始终与原基准比较。
- 先可靠保存本机资产，再保存正文与待传身份；保留 CAS、mutationId、pending、retained、冲突、擦除墓碑、封存及账号迟到隔离。读取失败不能当无稿。
- 字体、图片解码、稳定帧等待有超时与取消，lazy 图片也须加载核验。PNG 尚未解码不能决定真实题面是否可显示，续画仍须满足可靠资产与身份约束。
- 材料盘点、标画正文、草稿头和草稿正文读取每请求含完整响应体最多 30 秒；超时进入原失败／重试流程，不初始化空稿或放行提交。

## 协议与兼容

| 类别 | 处理 |
| --- | --- |
| v1，无 layout | 缺位置证据时明确报错保稿，保留历史证据导出，不能当普通 v2 或称为已恢复。 |
| v2，有 compatibility | 原逻辑框、旧样式和公开证据恢复真实组件，按 10px 核验；旧 matching/ordering 尝试原方向模板，命中原证据后再核验实际 DOM。 |
| v2/v3，仅哈希 | 原签名须精确命中；哈希不能反推位置误差。补证据仅走显式授权续画流程，不被动写回。 |
| v3，有 controls | 恢复真实组件，controls 仅为历史只读字段，不再按 x/y 重建控件。 |
| v4 | 新稿使用 whole-question-v1，必须有公开 compatibility，不含 controls。 |
| 未知协议或坏数据 | 报错保留原资产、正文与待传稿，禁止造空稿、自动重冻或同尺寸替换身份。 |

v3/v4 PUT 分别声明能力 3/4。旧标签页与新页共享 IDB，发布仍走原 PWA 收笔、落盘、多窗口更新保护，不强刷、不让不认识 v4 的旧客户端写同库。

## 扩展和排障

可圈画正文保持稳定，答案操作不能搬走原文。公开 fold/steps 在 v4 固定完整展示，v2/v3 固定原默认状态；不展开题内答案、提示、详解。旧稿公开展开状态无法复现则保稿。新增题型复用 answering 调度，不在 Overlay 增加第二套按题型更新答案逻辑。

「正在恢复标画」先查材料盘点、严格本机读取、云端正文和会话代际；不要清缓存。几何阻断查原 layout、旧模板、字体图片及块边界；失败不代表可以覆盖原资产。

按[工程验证说明](约定/工程验证说明.md)选测。历史夹具必须包含原模板与原响应式样式，不能用新稿改版本号代替。验收须同时检查真实 DOM、直接作答、续画、原 PNG/layout/points 和同步状态；真实 Safari 合成事件不等于 Pencil 手感，未执行的离线、冲突、封存、更新项目如实保留。
