# 圈画架构与维护指南

这是一份题卡圈画的快速导航。行为与安全规则以 [手写与同步](约定/手写与同步.md)、[学生作答与讲练](约定/学生作答与讲练.md)、[技术架构与实施方案](技术架构与实施方案.md)和 [页面功能清单](页面功能清单.md)为准；本文只说明当前代码如何接线，以及扩展时先检查什么。题型作答的长期设计另见 [统一作答适配层方案](题目模型与练习适配/统一作答适配层方案.md)。

## 当前闭环与不变量

题卡以一次保存的**公开题面 PNG + 同一像素域的矢量笔迹**为原稿。目标设备显示这张图，不重新排版 HTML 来决定旧笔迹是否可恢复。答案状态仍由原有作答通道管理；PNG 不包含学生输入、答案、解析或教师私注。

| 项目 | 必须保持 |
| --- | --- |
| 身份 | `attemptId + questionId + phase` 隔离本机记录；冻结题 `questionRevisionId`、服务端独有的 `snapshotHash`、`baseRenderVersion` 绑定底图。服务端 `ready` 后 PNG、layout、底图身份不再改写。 |
| 坐标 | `AnnotationDoc.version=1` 的点与笔宽使用 PNG **像素**域，`baseWidth/baseHeight` 必须等于实际 PNG 尺寸。layout 的 `cssWidth/cssHeight` 是保存时的显示框，`pixelRatio=2`；槽位框使用该 CSS 框坐标。缩放、分栏与旋转只改变整组显示映射。PNG 和墨层须显式使用同一保存 CSS 宽高，包括非整数高度。 |
| 可读与可写 | 同一个 [resolver](../apps/web/src/features/annotation/frozen-surface-resolver.ts) 核验协议、底图来源和身份、正文尺寸、PNG 解码后真实尺寸、封存和上层只读事实。图片与正文错配时禁止叠画；控件缺失或题型未适配时仍可读有效原稿和旧墨，作答走唯一兼容视图。 |
| 保存 | 先可靠保存本机 PNG 资产，再保存正文/待传身份；空预备不产生云端底图或同步活动，首笔才排队。读取失败、未知协议、坏字节不能解释成无稿。保留 `mutationId` 幂等、CAS、冲突、`retained`、封存及账号切换防迟到回写。 |
| 上限 | 当前生产仅支持**单张题卡** PNG；像素单边最多 4096，比例 2 时保存 CSS 单边最多 2048。超限显式拒绝圈画，不绕开预算建超高画布。 |

### 版本怎么看

| 底图布局 | 当前行为 |
| --- | --- |
| v1：无 surface layout | 原稿弹窗只读，已封存的 v1 也可查看；不推断旧控件位置，不生成新稿覆盖。 |
| v2：`renderVersion=2` | 保存的 PNG 与旧笔迹成为题卡主视图；可续画，不因另一设备的字体或换行不同而拒绝。既有 PNG、layout、正文、ready 身份不迁移。答案在单独的唯一作答视图操作。 |
| v3：`renderVersion=3` | 同一固定原稿，另有保存时捕获的 `controls`。目前**仅完整静态 fill 文本槽位**有生产适配器：真实输入框覆盖原稿槽位，复用唯一答案状态。缺槽位或校验不合格则回退到唯一作答视图。 |
| 未知版本或损坏数据 | 严格读取报错并保留原记录、待传稿和资产；不按空稿重冻、上传或把异底图同尺寸笔迹叠上去。 |

这里的 v1/v2/v3 指底图布局协议；矢量正文的 `AnnotationDoc.version` 目前仍是 1。v3 服务端 PUT 要求显式能力标识；缺失时拒写并保留本机待传稿。已有旧 JS 与新页同机共用 IDB 键的混写风险仍需发布时的 PWA 安全更新处理，不能只靠版本字段消除。

## 打开、首笔与恢复

1. 答题页先读取 attempt 详情，成功后才挂 `AttemptSession`；课程练习和作业入口共用 `useAttemptDetail`。首次详情读取的每轮请求（包括完整响应体）有 30 秒期限，超时不自动重试；失败或离线暂停给重试，不能创建空答卷。后台暂时失败保留原题卡和画布位置，权限撤销仍终止编辑。详情生命周期见 [练习详情刷新恢复报告](审查报告/练习详情刷新恢复-20261105.md)。
2. [题卡宿主](../apps/web/src/features/annotation/QuestionAnnotationOverlay.tsx) 在作答卡和订正工作台共用。先严格恢复本机与云端状态；已有 v2/v3 通过 resolver 和图片解码门控直接显示原稿。显式开笔与被动显示走同一就绪判定，封存、切题或迟到权限变化不能重新激活画笔。
3. 新稿从公开 `QuestionSurface` 的稳定导出副本捕获 PNG、布局与可用槽位几何，复核导出前后布局；不能从目标设备 DOM 重测旧槽位。保存底图资产和空正文成功、图片解码与尺寸就绪后才允许首笔。空预备只在本机，首笔/有历史绑定或墓碑后才进入既有同步队列；已 `ready` 或曾画后擦空的原稿不因当前零笔而重冻。
4. 每笔收笔先写本机，再由原有队列同步底图与正文。打开失败、落盘失败、图片损坏和云端冲突分别给保稿出口；切题/切视图先收笔并确认本机落盘。45 秒预览若遇同底图新正文，丢弃旧预览。云端封存撞在途笔时，将已采样点本机保留为 `pending + retained`，普通封存后写入仍拒绝。

## 扩展一种题型或样式前

1. 先划定哪些内容能成为**不变的可圈画表面**，哪些答案控件会移动、删除或重排。未建立稳定绑定的动态区继续用唯一作答视图；不要把整道可变 DOM 截成图后假设笔迹会跟随对象。
2. 如需原稿内交互，在公开题目模型中确定稳定槽位键、数量与答案映射。把**捕获 + 恢复**一起登记在 `frozenAdapterOf`，并核对冻结题 revision；通用圈画管线只调用登记入口，不按题型写第二套 switch。运行时 `scopeId` 和测试用 `data-testid` 不可作持久业务键。
3. 控件框必须来自生成同一 PNG 的导出副本，保存于 versioned layout；恢复时验证键集合与几何，不在目标设备补测坐标。只渲染一套真实输入、焦点与保存通道，覆盖键盘、IME、只读/笔态及缩小时的 1:1 可达入口。纯展示修样式也要复核原稿框与笔迹坐标，既有 ready 底图不得自动重生成。
4. 若改契约，先 Zod，再实现、生成 Schema/规范和版本拒旧测试；检查普通学生公开投影，不能把答案/解析/教师私注烧进底图。补单测与 Chromium↔WebKit 浏览器证据，覆盖原稿/points 身份不变、同 PNG 新 doc、冲突/封存、缩放及唯一答案状态。正式选测口径见 [工程验证说明](约定/工程验证说明.md)。

**材料是独立后续工程**：当前 `materialInks/materialInkBases` 只在本机草稿，使用 1000 归一坐标、活排版/冻结框，没有题卡 PNG 和服务端 reader/writer。共享材料需要 attempt + 冻结材料版本身份、同一逻辑坐标空间分片、按需有界画布，以及跨片一笔、擦除、撤销的统一控制；不能将每片当独立题卡笔记。开发页分片原型只证明局部可行性，详见 [原型验证](审查报告/冻结圈画表面原型验证-20261105.md)，不代表材料跨设备功能已实现。

## 排障和验证入口

| 现象 | 先看什么 |
| --- | --- |
| 刷新停在「正在打开练习…」 | `useAttemptDetail` 的 `isPending/fetchStatus`、是否 offline/paused，详情 GET 的发出、服务端完成、响应头和 body 读完时点；此时圈画层尚未挂载。历史 15 秒自然失败的实际传输触发点尚未确证，见 [刷新报告](审查报告/练习详情刷新恢复-20261105.md)。 |
| 有 PNG 却无笔迹或不能开笔 | resolver 的来源底图身份、`AnnotationDoc` 尺寸、图片 `naturalWidth/Height`、封存与只读事实；不能只比较宽高或当前 HTML。看 [基础框架报告](审查报告/圈画冻结原稿基础框架-20261105.md)。 |
| 空稿、同步失败、换端出现不同原稿 | 先严格读 IDB 原记录和资产指纹，再查 `pending/mutationId`、`conflict/retained`、服务端 base `ready` 与 CAS 回执；不要删数据、将读失败当空稿或重冻 ready 原稿。 |
| 输入框偏位或出现两套答案 | 检查 `controls` 来自同次导出、layout CSS 框与图片/墨层等比映射、fill 适配器键集合；缩小后检查 1:1 入口与唯一答案状态。 |
