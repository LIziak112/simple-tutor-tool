# 学生作答与讲练

## MCP 逐题作答与教师修正

- 整卷与讲练逐题提交同时携带冻结题目版本和当前页面所见的答案版本。服务端在同一写事务核对版本、原稿声明并封存。答案版本冲突只返回本人云端稿，页面保留本机草稿，供学生核对后重新提交。旧页面缺答案版本时仅可提交从未保存过答案的空题。整卷收尾沿用已单题提交的判定与原稿。

- `query_student_attempts` 与 `query_student_responses` 支持练习开始时间筛选。逐题查询默认隐藏进行中卷的未提交题，显式传 `includeUnsubmitted` 可查到这些题与 `answerRevision`。
- 教师只可修正本人学生未作废草稿卷中的未提交题，须带最新答案版本与修正原因。快照修正保留题号、题型、材料引用及冻结判分策略，有草稿答案、已看提示或书写材料时保留原快照。答案修正不提交、不判分，也不计入学生改答次数。修正、答案版本递增与内部审计同事务落库。
- 学生 MCP 逐题提交要求学生确认，复用普通练习的版本、判分和证据封存规则。可同时提交本次答案，失败时保留已有草稿。相同请求重试使用同一提交标识，MCP 只回执提交成功。

本文件承接根 AGENTS.md 的专题约定；涉及本专题的任务必须在制定方案和修改前阅读。全局开发规则见 [AGENTS.md](../../AGENTS.md)。更新专题行为时同步维护本文件，不再向根文件追加实施细节。

## 作答表现展示约定（2026-10-25）

- 单元落地页的首次、最近与最佳表现使用一份语义化定义列表；手机单列、宽屏三列，保留服务端整轮计数和公布门，不在下方重复整段计数。已做次数和待批提示继续显示。学生首页以问候语作为唯一页面h1；课程进度直接显示当前值，不做宽度动画。
- 单元页有进行中作答时，提供「继续作答」与「清空并重新作答」。重开确认指定当前未交卷记录，服务端同一事务作废该卷并开一份空白新卷。旧卷从历次记录和进度中移除，原数据保留但学生读写均拒绝。已交卷记录保留。请求中不能关闭确认，失败保留具体错误。旧确认不能作废后来创建的卷。
- 作业、课程练习、讲练和错题重练的新卷最多 500 道实际冻结题。布置和换单元时按每份作业的有效题数检查，分开布置逐份计算。开卷重新检查当前题集，重开超限时原作答仍可继续。此上限只限制新卷，已有超限卷仍可打开。
- 501 题及以上的历史卷仍能交卷。确认后，页面按每批最多 500 题读取草稿头，再分批暂存题目版本、答案版本与原稿声明。相同批次可重试，暂存 15 分钟后失效。所有批次齐全后，服务端在同一事务重新核对全卷并判分、封存。取消、过期或版本冲突时保留草稿，学生可重新确认。
- 单元页可预选单选题提交方式，作答中通过「更多 → 做题方式」调整。默认点「提交」，选中即提交仅在工作流允许逐题提交时对单选题生效。本设备按作答保存偏好，恢复作答时不会自动提交之前已选的答案。
- 待公布摘要保留外层提交状态、倒计时、作答凭证与公布说明，移除九个只读内层的重复框线/背景/阴影；普通字体保留等宽数字，锁定状态用Lucide图标及完整文字。公布权限与学生载荷不因此改变。

- 题目考点（2026-11-06）：DSL 的 `knowledge="考点一|考点二"` 按管道符拆分、去首尾空白、去空项并按首次出现去重，未写为空数组，显式全空或纯分隔符报错；考点无主辅之分。学生卡片展示全部考点，错题筛选匹配任一考点、统计逐考点计数；错题归组沿用返回数组首项，回读按名称排序，不能把书写顺序当主考点。存量原文通过重导或 `reparse` 更新关联，历史作答快照不改写。

- 作答与讲练的版本更新（2026-11-04）：等待中的新版本须提供明确更新入口和稍后处理选择，不自动中断答题。保存并更新沿既有答案、正式手写、草稿与标画管线追平，恢复未完成或存在保存/同步异常时留在原页并说明原因；材料圈画的在途笔画须独立收笔保存，不能只等待题面标画或已入队稿件。更新不自动提交任何题目；细节与账号隔离、更新末轮复核规则见[手写与同步](手写与同步.md)。

- 列表作答与进行中的作业在底栏合并「答题卡」与填写数，所有窗口共用一个入口。题号网格在弹层内独立滚动，筛选与弹层边界不随结果数量移动。筛选为「全部／未填写／部分作答／已填写／待检查／不会」，按原题号排序，关闭后保留本卷筛选。交卷从页面底栏发起，交卷确认的遗漏题号仍可跳转。
- 列表答题卡的未填写、部分作答和已填写互斥。已有部分答案或本题圈画、草稿、正式手写保留笔迹，但仍未填完整时归为部分作答。只有已核对的答案及材料状态可用于区分未填写与部分作答；打开空稿、擦空笔迹、共享材料圈画均不计入。个人标记独立，可叠加。已填写用实蓝，部分作答只用浅蓝，当前题用描边。弹层关闭回到底栏入口，点题号沿已有收笔与跳题链聚焦目标题。
- 单题专注模式在所有窗口从底栏的当前题号打开与列表共用的答题卡面板。「下一道未答」固定在题号列表下方。切换宽窄屏或作答模式时保留本卷筛选，当前题在筛选范围内时滚入可见区域。开合保留题面阅读位置，关闭回到底栏入口，跳题后聚焦目标题。

- 开放题使用一个多行文本框，标题需要时写入正文首行。历史 `title` 与 `body` 合并显示，读取不回写；首次编辑才转为统一正文，完整保留旧稿文字，结果页仍兼容历史标题。
- 题组标题与说明均经 Markdown/KaTeX 管线呈现。题干中的材料结构引用在显示投影中移除，保留源文、材料关联和冻结快照；代码、公式与转义文本不误删，学生答案脱敏继续执行。
- 配对题的选项池必须完整换行展示并支持公式，下拉框以编号对应清洗后的选项正文（共享保守清洗单源，货币 `$`/字面下划线/全角空格不改写），辅助技术保留选项完整名称；选择不增删题面内容或改变题面高度，材料槽位编号、不可重复约束与保存格式保持原口径。
- 我的记录的进行中条目，在「继续作答」左侧显示「已做 X / N 题」，0 题也显示；实际填答、非空正式手写或已逐题提交计入，草稿纸和圈画不计入。进度只公开数字，不含判定或答案；历史未冻结卷只读兼容取题，不因浏览记录创建或冻结答案。

- 学生记录、单元/讲练落地页历次、课程目录，以及教师作答记录、批改汇总、课程进度和学情中的百分制得分改为「做对 X / N 题」；学生练习结果页原得分卡及真实正确率指标保留。计数从同一次冻结作答读取，未做仍进分母；待批与待自评分别展示，未公布结果不下发答对计数。首次/最近/最佳各保留对应整轮计数，最佳按答对比例、同率取最近，零题不参与。旧分数字段保留兼容，客户端不得反推题数。
- 未做轮保留在轮次史中，打断连续做对，不增加自动判错次数；不能过滤未做轮拼接连续做对，首页和错题本攻克口径一致。

## 结果回看 UI 约定

- 待公布结果携带本次服务端裁决时间，客户端用收到响应时的单调时钟推进倒计时。到期后重取结果，答案和判定仍按服务端公布状态展示；旧响应缺少有效样本时显示截止时间及手动刷新。

- 已交作业和练习的结果页与作答页共用底栏和答题卡弹层。所有窗口都从底栏打开，按当前公布权限显示回看范围和题号状态。打开答题卡时，若当前题在所选范围内，题号区自动滚到当前题。关闭后焦点回到入口，选题后焦点进入目标题。

- 结果回看的选择题只显示一组选项。原位题面在参考答案公布后标记正确项和本人选择，未公布时只中性显示本人选择。选项标记不改变题面几何，保留原稿圈画的位置。
- 错题本紧凑行使用共享解析与清洗管线的 `InlineMarkdown` 单行宿主：保留公式的 KaTeX/MathML 语义，块级元素收为行内，图片/表格/函数图像显示占位，链接和任务框不进入展开按钮；填空仅显示空框，不继承外层作答态。浏览器回归按真实数学减号「−」匹配公式名称，不依赖已删除的纯文本辅助摘要。
- 学生结果与教师批改的题卡进入可见区域后自动读取原标画；读取成功后由真实题面框架等比展示原题与笔迹，失败提供保稿重试。只读呈现不改写封存证据。
- 结果页材料区（题组共享材料与题级材料）以只读呈现本机材料圈画笔迹（交卷清稿保留 materialInks）；笔迹仍存作答设备本机，不跨设备同步、不进入服务端投影。
- 每题收起状态使用单行操作栏：查看详解、草稿、订正（直达动作）、本题历史、更多；窄屏横向滚动，展开材料使用题卡完整内容宽度。题干标注恒在题面原位直接呈现，不提供独立「本次原稿/题干标注」组；草稿组承载草稿原稿（非手写）/手写原稿（手写题）、题干标注回看与合成图导出（compact 关闭态零请求——学生侧导出出口）与 D8 找回区块，组内容首次展开才挂载（折叠零请求），非手写草稿原稿挂载即展开（一次点击直达）。
- 原稿与订正控制器持续挂载；切换操作分组或从待公布变为公布时，不丢编辑状态。
- 订正直达（2026-10 重构）：「订正」点击后懒取证据头——无未封存行则自动创建空白行（copyFromOriginal=false，不复制原稿），直接进入全屏订正工作台；不经二选一弹窗、不让用户命名。命名规律恒为「轮次（roundLabel）· 第 N 次订正」（N=已封存数+进行中这份）；已封存份数在按钮计数徽标（· N）与 aria（已订正 N 次）可见，历史订正查看走「本题历史」。
- 订正工作台按最初做题呈现（2026-10-27 实测反馈定稿）：单独题面用公开投影中性渲染（题干+选项，不带对错判定、本人答案与参考答案标记），题卡圈画与作答共用唯一真实 QuestionSurface 和原逻辑框，题面与笔迹整体等比缩放；「圈画」进入画笔态，「完成」收笔后直接作答，没有图片主视图、图片控件恢复或作答切换。v2/v3 保留原资产和核心布局，以原公开证据核验真实组件，10px 内正常放行；v1 缺位置证据明确保稿。已封存的上一份圈画原位只读展示（再点按钮提示已定格——圈画封存无新行机制）。草稿纸直接挂答题页同款 NoteLayer（phase=correction 参数化）——同一套手感、触底自动加高、全屏参考题面、布局偏好（左右分栏/上下排列）、收起保活与四维同步状态（图片维度关闭：订正查看走本地确定性渲染；不接答题页编辑协调器、不拉 scratch head——不触发其播种/补图副作用）。工作台布局与答题页同源（note-layout 常量）：1120px 宽行，题面 55%/草稿 45%，窄屏自动上下排；草稿纸全屏期间 Esc/遮罩不关工作台。「保存订正」是一层检查点：反思两输入（我卡在哪里/我的错因）→ 追平后按 baseRevision 封存草稿 → 本题有圈画正文则随同一并封存订正标注（attempt 级 seal；无圈画返回 0 不封存——含「画过又全擦除」的 0 笔态；conflict/denied/retained/pending 未清或本地读取失败均抛中文错误、同步异常先于无内容判定）。圈画封存失败不回滚草稿检查点：留窗提示**具体原因**并可**就地重试**（重试只补圈画，不再封存草稿），圈画保留可编辑；X/Esc 等价「知道了」收口。保存进行中 Esc/遮罩不关工作台。圈画封存后转只读（再修改无新行机制），后续订正仍可用草稿纸重做。
- 本题历史必须保留来源结果页、回看范围与当前题目，并在加载、错误、空记录状态提供返回入口；只接受学生作答结果路径（`/s/attempts/:id`、`/s/assignments/:id`），直接访问时回退我的记录。
- 本题历史每轮携带该轮开卷冻结的来源材料/组投影（QM-15）：恒读 attempt_context_snapshots、零 live 回退——库改稿/软删不换历史内容；单条坏快照跳过该条不打挂整页。同材料不同历史版本并存时（wrong 双版本卷）分别保留、逐版标注，消费方键必须含 (id, sourceVersion) 不按 materialId 覆盖；组块每 id 一段取最高冻结版。错题重练复制依赖闭包但不携带兄弟题答案（组快照仅成员 id 与引用），新卷自有 response ID 与保存版本基线；订正沿用原证据阶段，自评改选不改写交卷原稿，不用改答案替代订正。

## 学生对照自评 UI 约定（QM 支线，2026-10-24）

- 已提交且参考答案按四态 gate 公布后，reference_self 行在结果视图、题级反馈与讲练题卡默认出现对照答案、解析与「对了／错了／暂不判断」动作；不自动替学生选，未自评时「暂不判断」禁用（无可清除对象）。
- 完成状态三态经 `verdictBadgeDisplayOf` 单一出处：reference_self 教师未判行显示「已完成、待自评／自评正确／自评错误」（结果卡左边框随自评 verdict 变色），其余行沿既有 finalCorrect 徽章路径零变化；manual_only 行提示「暂无参考答案」，不假装可自动判断；教师已判时自评动作整块不渲染，显示走批改块（教师优先，不可被客户端覆盖）。
- 投影与 CAS：结果单题携带 `selfReview`（record + revision，undecided 清除后 record=null 但 revision 单独下发）与 `gradingPolicy`，公布前整键 null 投影；UI 只消费投影，本地采纳的成功回执/409 `_current` 仅在 revision 更大时生效，refetch 落地即回归服务端事实。同一意图重试复用同一 mutationId；成功后失效 attempt 前缀与讲练/记录/错题/教师聚合缓存。
- 对照格式：填空逐空对照（既有）；response 对照面附字数行（`countResponseWords` 契约单源 + wordMin/wordMax 建议，未作答不显示）；matching/ordering 逐项对照已随 QM-13 由登记表转正（ResultAnswerComparison 通用宿主，`answerKind in answerKindViews` I16 集合口径），不再走通用文本占位。
- 自评不阻塞回看、原稿、订正与记录入口；做完题即可回看或离开。
- 教师错题与 MCP 查询按有效判定筛选，依次取教师批改、当前学生自评、自动判定。教师清除批改后恢复当前自评，学生撤回自评后退出当前自评筛选。教师学习记录和复盘包同时区分有效判定与教师权威判定。学生学习记录只在该题已公布时显示本人自评。

## 题目模型与练习适配（QM，2026-10）

- 材料/组/引用是题目之上的教师域实体（迁移 0044 五表 + `attempt_context_snapshots`）：DSL 稳定 id 是教师域全局主键，同教师同 id 重导按「同 ID 更新/移动」覆盖（多语料连导须拆教师域）；开卷同事务冻结依赖闭包，学生侧一切消费（作答/结果/历史/错题/导出/AI 上下文）恒读冻结快照、零 live 回退，缺依赖 fail closed 不以活库顶替旧卷内容。
- 开卷同事务写入 `attempt_context_freezes`，空集合也记录完成。上下文接口以 `freezeState` 区分已冻结和来源未知的旧卷。有冻结证据的卷再次重练仅使用已保存的题组和材料，保留引用材料的全部冻结版本。无标记且无快照的旧卷回看为空，主动组建新重练卷时允许在教师域内冻结当前可取得的依赖。
- 新冻结卷由共享来源契约及迁移 0062 校验归属和工作流组合，历史卷保留旧值。草稿和逐题提交按冻结题型校验答案结构。公布查询与服务端共用截止裁决，旧时区偏移对外转换为 UTC，缺失和损坏的公布事实保持受限。整卷交卷、讲练提交和草稿写入在事务内校验回执。
- 学生作答文本序列化单源 `serializeStudentAnswerOfRow`（待批队列/CSV×2/学情包/单题包/错题本五出口共用，批量出口按 attemptId 记忆化）；matching「第 N 空＝选项正文」用 matchingSlots 携带的材料槽位 ordinal，不得用题内下标重排。

## 键盘快捷键体系（2026-10-28）

- 设备形态分三档呈现：桌面/笔记本（pointer: fine）完整快捷键与自定义；纯触控 iPad 与手机**零快捷键 UI**（「更多」菜单无「快捷键」项、设置页无快捷键开关与「自定义键位」分区），全部功能走屏上按钮——快捷键只是键盘设备的加速器，触屏零功能损失；iPad + 外接键盘（pointer: coarse）懒探测：window 捕获监听**首个合格 keydown**（目标非文本编辑区、非 IME 合成、key 非 Unidentified；软键盘输入恒落编辑区被排除）后切换为键盘设备，同一次按键先探测后派发，首键即生效。探测为会话内存态：不落盘、每标签独立、单向不回退。已知接受的误报：Android 个别软键盘向 body 发真实键值、iPad 仅外接触控板（无键盘）被 pointer: fine 直判——都可能提前亮出快捷键 UI（按键不可用、无功能损失，刷新即消/单向不变）。
- 命令注册表（`apps/web/src/features/keyboard/command-registry.ts`）是键位与中文含义的单源，帮助面板、设置页与作答页派发都从它渲染。可定制命令：`practice.submit-or-next`（Enter）、`practice.prev-question`（←）、`practice.next-question`（→）、`practice.open-help`（?）；固定命令：`practice.select-option`（1–9，判断 1 对 2 错）与 `practice.escape`（仅帮助展示，不参与派发）。**固定命令先匹配**：改键撞 1–9 抢不走选项数字；冲突检测（含撞固定键）在保存前拒绝。可定制命令的默认键位均含 Shift 变体（Enter/Shift+Enter、←→/Shift+←→）——沿用升级前 `event.key` 匹配不看 Shift 的行为，避免中文输入法切换后 Shift 未松开时按键静默失效；录制侧 Shift+Space 恒归一为 Space（IME 切换组合不做独立键位，契约文法拒绝 `Shift+Space` 与空白类单字符）。
- 键位自定义存本设备 localStorage（契约 `studentKeyboardBindingsSchema` strict v1，键 `ownclass:keyboard-bindings:[origin,"student",id]`，仿 practice-pref 先例）：坏值/未来 version 整体回默认不迁移；键位属个人使用偏好不进服务端——默认键位全设备一致、自定义不跨设备同步。KeySpec 文法禁 Ctrl/Alt/Cmd 组合（让位系统语义）、空格恒 Space、字符键自带 Shift（"?" 不写作 "Shift+/"）；每命令 1–2 键（2 键前向兼容，录制 UI 只写单键整替）。
- 作答页守门链顺序与语义不变（M3-D3 §9.2）：偏好总开关关闭全静默（含 ?）；文本编辑区/按钮 Enter/弹层打开/busy/书写中/纸面展开/答案冲突逐层让位；←→ 的「焦点在工作区容器自身」守卫挂在命令上，不随键位变化。Esc 的局部语义（退圈画/收纸面/关 AI 面板/退全屏/退选题）不在注册表派发，维持各局部处理器。
- 讲练页（StudentLessonPage）不走 AttemptSession，v1 未接入快捷键；注册表 scope 与 `practice.` 命名空间为 `lesson.*` 预留。出现第二个派发点（lesson.*）时，先把 `isTextEditingEvent` 等判定从 features/attempt/practice-keyboard 迁入 features/keyboard 解依赖环，再把设备门控下沉进共享守门链。草稿纸开关（守卫链在纸面展开时整体短路，键盘无法「关」纸面，且三类纸面语义歧义）与 AI 求助面板开关（接线需动 dock 状态机与焦点语义）为 v2 候选，未纳入。

- 位置即 markdown：题目在讲义中的位置不建锚点表——题块原位保留、开围栏注入最终题目 id（注入也写进该题 sourceMd，往返稳定）；改题块内容必须走重导/reparse 或题库单题编辑，不得在讲义编辑里改后放任双源漂移（编辑抽屉对题块只渲染只读占位卡）。题库单题编辑（`updateQuestion`）对嵌入题在同一事务内回写讲义正文题块（响应 `lessonSynced`），题库与正文不再漂移；正文缺该题块时 422 `LESSON_QUESTION_BLOCK_MISSING` 整体回滚，引导整页重导修正。

- 开卷幂等：`lesson/start` 是 create-or-return，**绝不因已完成而开新卷**（刷新已完成页不消耗 attemptNo）；「再做一次」只能走显式 `restart`。
- 单题提交语义：当题释放对错/参考答案/详解（恒题级粒度，attempt 级 answerRelease 不适用）；已提交行**行级锁定**（禁改答案与笔迹）；最后一题提交在事务内自动收尾；整卷收尾对已提交行不重判。
- 整卷和逐题收尾、教师待批队列和改判共用逐行冻结策略。已提交且快照可用的行中，旧策略和非自评策略在缺少最终判定时进入教师待批；参考自评行独立计待自评。整卷收尾且没有教师待批时，以教师权威判定计算整卷最终分数，学生自评只更新有效判定展示。作废卷不可批改。启动校正仅重算冻结快照完整且判分来源一致的已收尾卷。
- 学生端进入讲练页的题卡三态（作答/已提交/待批）与进度、孤儿题页尾分组、记录「讲练」徽章口径见 docs/页面功能清单.md §3.9。

## 限时测试（2026-11-09，个人学习迭代模块 2）

- **通用、学习者自选**：课程单元练习、首次作业开卷与作业重做均可选时长（常用档 15–180 分钟或自定义整数 1–600）。自定义时长无效时须修正或关闭限时才能建卷。建卷请求使用 `timeLimitMinutes`（`attemptStartOptionsRequestSchema`），服务端在 `attempts` 保存 `time_limit_sec` 与 `deadline_at`。继续作答沿用原卷时限，错题重练与讲练不限时。
- **DSL 推荐**：frontmatter `practice.timeLimitMinutes` 是单元推荐时长（随导入存入 `units.practice_defaults_json`、随导出写回），落地页据此默认开启并预选，学习者可改可关。
- **服务端时钟**：`deadlineAt = startedAt + 时长` 持久化。前端在收到草稿详情时用 `serverNow` 锚定浏览器单调时钟，缓存重挂载继续使用原锚点。题卡订阅截止和宽限阶段，倒计时单独刷新。阶段判定由契约纯函数 `attemptTimingPhaseOf` 统一。
- **到时后确认交卷**：`grace`（到时后 10 分钟，`ATTEMPT_TIME_UP_GRACE_SEC`）内题卡只读，已落盘的答案和正式手写仍可补传，新逐题提交被拒绝。宽限结束进入 `locked`，新答案和正式手写写入返回 409 `ATTEMPT_TIME_UP`。整卷交卷以服务端收到请求时的阶段为准，锁定后须由学生明确确认并发送 `confirmedSavedAnswers: true`，按服务端已存作答判分，未同步的本机稿仍保留。锁定草稿仍可重放已成功保存答案、正式手写和逐题提交的回执。结果页按交卷时刻显示是否超时。
- 单源：`packages/contract/src/attempt-timing.ts`（契约）、`apps/server/src/services/attempt-timing.ts`（时钟与写闸门）、`apps/web/src/features/attempt/attempt-clock.ts` + `AttemptTimer.tsx` + `TimeLimitPicker.tsx`（前端）。

### 题内活动用时（2026-11-09，模块 2 补刀，口径 v1）

- 学生点击交卷仅触发作答事件补传。整卷交卷和逐题自动收尾成功时，服务端在写入卷状态的同一事务记录交卷事件。统计以服务端受理时刻为界，浏览器旧版交卷意图不截断作答时间。受理之后收到的补传事件保留原始记录。

- **与考试时钟分开显示，不新建实体**：结果页在限时行下方另起一行「题内活动合计 X · 只看过 Y · 未归属 Z（最多 N 端同开）（口径 v1）」，题卡标题行末挂一枚「活动用时 X / 看过 Y（无作答动作）/ 看到过，无作答记录 / 无可用记录」；全部由服务端按 `events` 时间轴读时现算（`attemptActivityProjection`），不加表不加列，投影为 `AttemptResultData.activity`（`attemptActivitySchema`，无事件卷不带键 → 前端标「无可用记录」）。
- **归题口径**：`question_focus`→`question_blur`/下一题聚焦或最后一个可用浏览器事件为一段聚焦；段内出现题级动作（`QUESTION_ACTIVITY_ACTION_TYPES`：answer_change / ink_stroke_batch / ink_edit_batch / hint_open / question_submit / directive_interact）才记 `activeSec`，只看不动记 `observedSec`；`page_hidden`→`page_visible`、`idle_start`→`idle_end` 之间不计（段内有动作即视为结束空闲）；没聚焦就有动作时以动作本身开一段并归题；全卷用服务端接收时刻与 `attempts.submitted_at` 比较截止，各端迟到的补发保留原始事件但不进入已交卷统计。旧客户端的交卷意图不参与区间回放。新交卷以确认记录的数据库写入次序识别同毫秒迟到事件。`question_view` 只置 `viewed`。服务端直记的 `question_submit` / `hint_open`（服务器时钟、无 `viewId`）归入最近聚焦该题的会话，只把那次聚焦追认为有动作、不另开一段、不与客户端时钟的事件混排。
- **多端 / 多标签页与补发**：事件批请求体可选 `viewId`（作答页每次加载一个随机串，队列层生成，服务端折进每行 `payload`），按它分会话各自回放再扫描线合并——同一时刻多个会话聚焦**同一题**只算一次（任一端有动作即 active），聚焦**不同题**的重叠时段记卷级 `unattributedSec`、不归任何题；重复补发按 `type|clientTs|questionId|viewId` 去重；旧客户端无 `viewId` 的事件归一个默认会话。离线积压随积压当时的 `viewId` 一起存（IndexedDB 条目 `{events, viewId}`），补发按来源会话分批携带各自的 `viewId`，不冒用当前页会话；「N 端同开」显示 `concurrentSessionsMax`（同时在前台的会话数峰值），`sessions` 仍是参与计算的会话总数。
- **旧统计保留原口径**：教师侧 `responses.activeSec` / `attempts.activeSec`（`active-time.ts`，交卷时落库、不分动作与只看）不变；新旧数字标口径后再比较。单源：`packages/contract/src/attempt-activity.ts`、`apps/server/src/services/question-activity.ts`、`apps/web/src/features/attempt/QuestionActivity.tsx`。

## 通用量表判卷（2026-11-09，个人学习迭代模块 3）

- **不新建实体**：量表是题目的一部分——开放题（solve / apply / find-error / response 等主观题型）在 `::::question` 内写 `:::rubric` 子指令，每行一项「- 项名：评什么」，1–8 项、统一 1–4 档（`rubricSchema`，id 固定 `r1…rN`）；客观题写量表报 `RUBRIC_ON_OBJECTIVE_QUESTION`。随导入进 `sourceMd`，建卷冻结时与 word-min/max 同走「sourceMd 为单一来源」重抽进快照（`questionOfRow`），作答视图公开下发（`questionPublicSchema.rubric`，评价项不含参考内容）。`:::rubric` 不受 `NEW_CONTENT_ENABLED` 门控（`UNGATED_DIRECTIVES`）。
- **三份记录分立**：`responses` 三列 JSON `rubric_self_json` / `rubric_agent_json` / `rubric_final_json`（迁移 0056），结果视图投影为 `rubricReview {rubric, self, agent, final, pendingAgentTaskId}`（只在交卷并公布后；未公布形态与答案 / 判定同在 `restrictedResultQuestionOf` 置 null）。学生侧 `PUT /attempts/:id/questions/:questionId/rubric/self`（自评：逐项档位 + 一句依据 + 整体一句）与 `…/rubric/final`（裁定：`self` 保留我的 / `agent` 采纳 Agent / `custom` 自行改写）；未公布 / 无量表 403 `RUBRIC_NOT_AVAILABLE`，缺项 / 未知项 400 `RUBRIC_RATINGS_INVALID`。

## 使用数据采集口径（2026-10-28）

- 学习事件待传批次按部署、学生、试卷或讲义隔离，先落盘再发送。服务器确认所有事件标识后清理该批；后台 beacon 仅尝试投递。回执接口在旧服务端不可用时保留积压，账号切换只补传对应账号。升级前没有可信账号标记的旧键保留原地，避免误归属；旧客户端仍可直接使用旧接口。

- events 时间轴在 23 种既有事件外新增两种 attempt 域事件（使用数据补缺，2026-10-28）：`note_sync`——本 attempt 草稿/订正草稿纸一次成功同步报一条（phase=scratch/correction/supplement + revision + 笔画数计数，不含笔迹本体；首次观察到某键只记基线，打开旧页 head 回读不算同步）；`editor_toggle`——标画/草稿/正式手写三类编辑器激活与退出各报一条（开合成对；整页纸面进出仍以 ink_fullscreen 为准，不双报）。语义只增不改，旧客户端零影响。
- 复现做题状态的过程数据口径：作答值与改动（answer_change）、提示（hint_open）、手写（ink_stroke_batch/ink_edit_batch/ink_fullscreen）、草稿链（note_sync）、编辑器开合（editor_toggle）、逐题提交（question_submit）、环境（page/net/idle）全在 events 时间轴；notes/noteVersions/annotations/ink 各表仍是内容权威，事件只做时间轴，不承载内容。
- 练习与讲义事件按原顺序切批，每批至多 200 条且完整 `{"events":[...]}` 请求体至多 32 KiB（UTF-8，含外壳与分隔符）。单条超限事件独占一批，发送失败仍按原规则保留待重试。

## 普通课程练习的单题过程回放

- 过程记录为试点能力。服务端以 QUESTION_PROCESS_ENABLED=1 启用入口，学生在练习「更多 → 做题过程记录」明确开启当前作答。教师在所属学生的卷详情按题打开回放。
- 题干圈画、草稿、作答值和提示呈现共用一条单题时间轴。选择、配对和排序使用冻结题目身份。文本按已确认的编辑值记录，保留输入法提交和失焦结果。教师回放只用公开冻结题面与学生当时的作答，提示只显示事件和序号。
- 回放按采集段及段内顺序呈现。段间顺序缺乏可靠证据时分别展示，缺失的过程、未确认结束的尾段、缺失或错配的圈画底图分别给出提示。正式手写答案继续走既有保稿和回看链路。
- 圈画原图缺失、解码失败或尺寸不符时显示冻结公开题面和当时作答，提示底图问题。只在底图身份与实际尺寸均匹配时叠加圈画。
- 试点记录从开启起保留 30 天。学生可从练习或结果页删除本次过程，清除过程批次并阻止迟到补传。现有作答与封存证据依各自规则保存。历史整库备份依部署备份策略过期。
