## 1. 讲练是什么

- 讲练是一篇 `kind: lesson` 的讲义：讲义段落和可作答的题目按原位交错，一篇文档就是「一件事」。
- 和配套练习（`practice` / `mixed` 讲义 + 独立单元）的区别：讲练的题属于**嵌入单元**，不单独布置，不出现在资源库单元列表和课程目录计数里。
- 学生每做一次讲练产生一份讲练卷：`attempts.sourceType = "lesson"`，与作业、课程练习、错题重练并列，是四种作答来源之一。

本文用到的几个词：

| 词 | 意思 |
| --- | --- |
| 一次讲练（讲练卷） | 学生对一篇讲练的一次作答，一行 `attempts` |
| 做法 | 这一次怎么做：**先讲后练**（讲义和题目交错显示，现在的样子）或**先做后看**（先只显示题目，讲义收起） |
| 看答案的方式 | **逐题看**（每道题点「显示答案」当场看）或**做完统一看**（做题时不显示答案，结束后一起看） |
| 未做 | 这一次结束时，这道题没有提交过。沿用系统现有的未做口径：进分母，不算错，不进错题本 |
| 不会 | 没作答就点了「显示答案」。系统自动给这道题标「不会」 |
| 作废 | 进行中的卷被「重新开始」顶掉。整份不计入历次、统计和错题本 |

## 3. 数据地基【现状】

- **嵌入单元**：判定统一走 `apps/server/src/services/lesson-embedded.ts`（`units.lectureId` 指向 `kind='lesson'` 的讲义，含软删）。资源库、课程目录、各类计数、学情矩阵都排除嵌入单元。开卷、重开、落地页取嵌入单元走 `canonicalEmbeddedUnitOf`（与讲义题槽交集最大的那个单元，平局取最近更新）。
- **位置即 markdown**：题块就写在讲义正文的原位，开围栏里注入题目 id，没有另外的锚点表。讲义段落本身没有稳定的 id。
- **防泄露根基**：讲义的 markdown 原文对学生端恒不下发。学生拿到的只有服务端 `splitLessonBlocks` 切出来的讲义段和题目槽，加上冻结题的公开投影。
- **冻结范围**：题目、材料和题组在开卷时冻结（`createLessonAttempt`）。**讲义正文不冻结**，`buildLessonStartData` 每次用当前的 `lecture.markdown` 现切（`lesson-service.ts`）。讲义表没有版本号、修订号或内容指纹，也没有历史版本表。
- **做题方式三列不能用**：`attempts` 上给练习用的 `practice_workflow_version / feedback_mode / workflow_revision`，迁移 0063 的触发器规定讲练卷必须是空 / 空 / 0。讲练要记做法和看答案的方式，得另找地方存（见修改计划 §4.1）。

## 4. 一次讲练从开始到结束

```
                 开始练习（幂等：有进行中的就回到它）
   还没做过 ───────────────────────────────────▶ 进行中
                                                  │ 逐题点「显示答案」：这道题当场出结果并锁定
                                                  │
                    ┌─────────────────────────────┼──────────────────────────────┐
                    │ 最后一题也看了答案           │ 结束本次讲练【已定，未实现】   │ 重新开始
                    ▼ （自动收尾）                 ▼ （没提交的题按未做）          ▼
                  已完成 ◀────────────────────── 已完成                        作废（不留记录）
                    │ 再做一次                                                    │
                    ▼                                                            ▼
                  新的一次（第 n+1 次，从空白开始）◀──────────────────────────────┘
```

### 4.1 现在【现状】

- **入口**：落地页 `/s/lectures/:id/lesson`（`StudentLessonLandingPage`）按状态给三种按钮：从没做过是「开始练习」；有进行中的是「继续作答」和「重新开始」；做完了是「再做一次」。下面列历次记录。
- **开卷**：`POST /api/student/lectures/:id/lesson/start` 先返回进行中的卷，没有就返回最新一份已完成的卷，都没有才新建（`startLessonAttempt`）。刷新不会误开新卷。开卷要过讲义可见性校验（`requireVisibleStudentLecture`）。零题的讲练是纯阅读。
- **逐题**：题卡上的按钮叫「显示答案」，底层是服务端单题提交（`submitLessonQuestion`）：这道题当场给出对错、参考答案和解析，随后锁定，不能再改答案和笔迹。不能自动判的题不直接给对错：参考自评的题出现自评入口，其余等老师批改。
- **空着点「显示答案」算「不会」**：没有文字作答、也没有正式手写时点「显示答案」，系统自动给这道题标「不会」并记为已答（`finalizeLessonQuestion`）。这道题什么时候进错题本见 §9.1 的表。
- **收尾只有一条路**：最后一道题点了「显示答案」，同一事务里自动收尾（`autoFinishPerQuestionAttempt`）。讲练页当初按「老师讲解用的材料」设计，特意没放「完成练习」和进度计数（`StudentLessonPage.tsx`、`use-lesson-attempt.ts` 的头注释）。所以跳过了题、或者中途离开的卷，会一直是「进行中」。
- **服务端其实能整卷收尾，只是口径不同**：`POST /api/student/attempts/:id/submit` 对讲练卷可用（`finalizeWholeAttempt`）。它保留已经看过答案的题，其余的题**连同写下的草稿一起判分**。讲练页没有调用它的入口。但进行中的讲练卷如果从「我的记录」打开，进的是通用作答页（只有题目列表，没有讲义，没有「显示答案」），那里有「交卷」，走的就是这条路（读代码得出，没有实测）。这和 K2 不一致，要收口。
- **重开**：「重新开始」作废进行中的卷再开新卷；「再做一次」在已完成之后直接开新卷。两者都走 `POST …/lesson/restart`，带原卷 id 和操作标识，重复请求返回同一份新卷，过期的请求 409 `LESSON_RESTART_STALE`。新卷从空白开始，不带上一次的草稿。
- **不适用**：讲练不限时；讲练页不走通用作答会话，没有接键盘快捷键。

### 4.2 结束本次讲练【已定，未实现】

- 讲练作答页加「结束本次讲练」。这是 K2 的前提：K2 说的是主动结束时怎么算，现在页面上没有主动结束的入口。结束前二次确认，写明还有几道题没做。
- 至少看过一道题的答案才能结束。一道都没看过的卷留不下任何记录，想重来用「重新开始」。【建议】，待确认 Q7
- 没提交的题怎么算，看这一次的「看答案的方式」。由服务端按卷上记的方式决定，不由页面传参数：

| 看答案的方式 | 结束时 | 依据 |
| --- | --- | --- |
| 逐题看 | 点过「显示答案」的题保持原样。其余的题一律按未做，不判分 | K2 |
| 做完统一看 | 结束就是交卷：填了答案的题照常判分，没填的按未做 | 【建议】，待确认 Q3。这种方式下没有单题提交，「写了没提交」无从说起 |

- 逐题看时，没提交的题上已经写的东西这样处理【建议】，待确认 Q6：填的答案清空，这道题和别的未做题一样显示为空；正式手写、草稿纸、圈画不删，回看时还看得到，但不计分。
- 「未做」沿用系统里已有的口径：进分母、不计错、不进错题本（§8、§9）。
- 结束后这一次不能再继续作答，所有题的参考答案和解析都能看。
- 不做「长时间没动就自动结束」（K3）。中途离开的卷保持进行中，可以回来继续。
- 「重新开始」保留现在的含义（作废，不留记录）。有了「结束本次讲练」之后，学生想留下这一次已经做的题，就先结束再重做。
- 未做的主观题要不要进「待自评」和老师的「待批改」：待确认 Q2。现有规则不看这道题有没有作答，只要没有判定就进队列。
- 进行中的讲练卷已经看不到讲义（被移出课程、讲义被隐藏或删除）时，不能再继续作答，只能结束这一次。【建议】。现在这种卷可以在通用作答页接着做并交卷（读代码得出，没有实测）。

## 5. 做法与看答案的方式【已定，未实现】

### 5.1 开卷时选

学生在落地页开始一次新的讲练时选做法（K4、K6）：

| 做法 | 页面的样子 | 看答案的方式 |
| --- | --- | --- |
| 先讲后练（现在的讲练） | 讲义和题目交错显示 | 逐题看 |
| 先做后看 | 只显示题目，讲义先收起 | 学生选：逐题看，或做完统一看（K5） |

- 「再做一次」「重新开始」开的也是新的一次，同样可以选。
- 默认选中先讲后练；选了先做后看时，看答案的方式默认做完统一看。两者都记住学生上次的选择。【建议】

### 5.2 中途切换

K6 定的是「参考练习，可以中途切换」。练习现在的规则是：布局（列表 / 单题）随时能换；反馈节奏（每题提交后查看 / 交卷后查看）只在第一次提交之前能改，提交过任何一题就固定（`updateAttemptWorkflow`，【现状】）。讲练照这个对应：

| 能切换的 | 对应练习的 | 规则 |
| --- | --- | --- |
| 讲义显示 / 收起 | 布局 | 随时可以切。先做后看做到一半想翻讲义，点「显示讲义」；展开之后就是普通讲练的样子 |
| 逐题看 / 做完统一看 | 反馈节奏 | 这一次里第一次看答案之前可以改，看过任何一题的答案之后就固定 |

- 两个开关互不牵连：展开讲义不会改变看答案的方式。【建议】
- 先讲后练开的卷，在还没看过任何答案之前，也可以改成做完统一看。【建议】，待确认 Q4
- 做法和看答案的方式记在卷上（服务端），换设备、刷新之后保持不变。【建议】

### 5.3 做完之后落在哪【建议】

不管看答案的方式是哪一种，只看做完那一刻讲义是显示着还是收起着：

| 做完那一刻 | 看到的 |
| --- | --- |
| 讲义显示着（先讲后练，或先做后看中途已展开） | 留在讲练页，原地变成回看的「讲练」视图。和现在一样，不打断正在看的解析 |
| 讲义收起着（先做后看） | 进结果页的「题目」视图，可以切到「讲练」视图。这就是 K6 说的「做完后可以切换为普通讲练形式」 |

之后从任何入口再打开这一次，都按 §7.2 默认显示「题目」视图。

### 5.4 先做后看的一个限制

讲义收起时，题目如果要用到前面讲义里的图、表或例子，学生看不到，得自己点「显示讲义」。讲义段和题目之间现在没有显式的关联（§3「位置即 markdown」），系统判断不出哪道题依赖哪一段。彻底解决要等讲练 DSL，见 §11。

## 6. 作答页【现状】

- 路由 `/s/lectures/:id/lesson/run`（`StudentLessonPage`）：讲义段和题卡交错，目录在顶部工具栏。
- 题卡两种状态：作答态（题干、作答控件、分步提示、「显示答案」）和结果态（对错、参考答案、解析在原地展开）。
- 草稿纸、正式手写、题面圈画复用普通题卡；看过答案的题只读。
- 阅读位置按卷记在本机（localStorage，键以 `lesson-reading:` 开头），换设备不跟随。讲练页不上报讲义阅读事件：「当前读到哪一节」只用来驱动目录高亮，普通讲义阅读页才把它记成事件。
- 不在当前讲义题槽里的冻结题，排在页尾「本次练习其余题目」。

## 7. 回看

### 7.1 现在【现状】

| 从哪里进 | 看到什么 |
| --- | --- |
| 讲练页（最新一次已完成时） | 完成视图 `LessonCompletedView`：讲义段和只读题卡交错，有「查看结果」、整卷复盘入口、「再做一次」。**只有最新一次有这个视图** |
| 讲练页的「查看结果」、落地页历次记录里已完成的那几行 | 结果页 `/s/attempts/:id`：只有题目，没有讲义 |
| 我的记录 | 已完成的进结果页；进行中的进通用作答页（同 §4.1，没有讲义） |
| 错题本、本题历史里的某一轮 | 结果页 |

结论：除了最新一次的完成视图，所有回看路径都看不到讲义。第 1 次、第 2 次这些旧的轮次没有带讲义的回看。想再看讲义只能「再做一次」。这就是 #34139 的问题。

### 7.2 「题目」和「讲练」两个视图【已定，未实现】

## 8. 做题记录

### 8.1 现在【现状】

- 讲练卷进「我的记录」（`GET /api/student/records`），来源徽章「讲练」，可以按来源筛选。讲练卷不会失去访问权：进行中的照常列出，可以继续做（`student-records.ts`）。
- 进行中的卷显示「已做 x / n 题」（`recordAnswerProgress`）：已经看过答案、有正式手写、或者填了答案的题都算已做。
- 已完成的卷显示「做对 x / n 题」，未做的题在分母里（`result-counts.ts`）。落地页的历次记录还会列出待批、待自评的题数。
- 落地页的首次、最近、最佳表现也用「做对 x / n」。最佳按答对比例比，同比例取最近一次，零题的卷不参与（`resultCountsSummary`）。作废的卷不计入。
- 本题历史（`/s/notebook/:questionId`）跨四种来源聚合。进行中讲练卷里已经看过答案的题也算一轮（`note-service.ts`）；契约注释 `student-notebook-api.ts` 写的是进行中的卷不进轮次，与实现不符，以实现为准。
- 因为没有主动结束，一份跳过了题的讲练卷在记录里永远是「进行中」。

### 8.2 改完之后的变化

- 主动结束的卷成为「已完成」，显示「做对 x / n 题」，没做的题在分母里（§4.2）。这一次也会参与首次、最近、最佳表现的比较。
- 每条讲练记录点进去默认是「题目」视图，可以切到「讲练」视图（§7.2）；进行中的回到讲练作答页。
- 因为老师重新导入讲义而结束的卷，在历次里注明原因（§10.3）。

## 9. 错题本

### 9.1 现在【现状】

- 错题本不按来源过滤（`wrong-questions.ts`）。一道题的一轮作答要进轮次史，条件是：卷已结束或者这道题已单题提交，并且已有判定，并且答案已公布。讲练的题点过「显示答案」就算已提交、已公布（`review-access.ts`），所以**卷还在进行中，判错的题也已经进错题本**。
- 入本条件（`enteredWrongBook`）：任一轮「已答且判错」，或者标过「不会」。未做而只被自动判错的不算（`countsAsWrong`）；老师批错、学生自评「错」这类人工判定不受「未做」影响，照样算错。
- 讲练里几种情况的去向：

| 情况 | 进错题本吗 |
| --- | --- |
| 作答后点「显示答案」，判错 | 进 |
| 没作答就点「显示答案」，能自动判的题 | 进（自动标「不会」）。标过「不会」的题，之后做对了也留在错题本里 |
| 作答后点「显示答案」，判对 | 不进；如果这道题以前错过，这一轮计为做对的一轮 |
| 不能自动判的题，还没有老师批改或自评 | 暂不进。错题本只收已有判定的轮次，标过「不会」的也要等有了判定 |
| 没点「显示答案」，卷还在进行中 | 不进，也不构成一轮 |
| 作废的卷里的题 | 不进；之前因为这份卷进去的轮次一并消失 |

- 讲练的错题可以「重练全部 / 重练本组 / 选题重练」，重练卷的来源是错题重练。订正、本题历史和普通题同一套。
- 错题按题目所属单元分组（`originUnitTitle`），讲练的题归在嵌入单元名下；嵌入单元的标题和讲练页的标题是否一致，没有核对。每一轮的来源标题形如「标题 · 第 n 次」（`roundSourceTitle`）。
- 错题卡和轮次只链到结果页 `/s/attempts/:id`，回不到讲义里对应的位置。

### 9.2 改完之后的变化

- 主动结束时没提交的题按未做（K2），按现有口径不进错题本。它和「没作答就点显示答案」的区别在于：后者学生看了答案，算「不会」；前者学生没碰这道题。
- 讲练来源的那一轮加「回到讲义」：已结束的卷打开「讲练」视图并定位到这道题，进行中的卷回到讲练作答页并定位到这道题。学生能看到题目前面的讲义。【建议】，产品方没有提过，可以不做。

## 10. 老师改了讲义之后

### 10.1 现在【现状】

- 讲义正文有三条路会变：重新导入（同名命中，或用 `replaceLectureId` 指定替换）、老师端整页编辑（`updateLecture`）、题库里改单道题后回写讲义里的题块（`updateQuestion`）。都在 `content-service.ts`。
- 还有不经过讲义正文的改动：材料和题组可以在题库里单独改（`qm-edit-service.ts`），软删一道题也不动讲义正文。
- 这些路都不碰学生的卷：不作废、不提示、不打标记。
- 题目、材料、题组是冻结的，所以学生卷里的题不变。讲义不冻结，所以进行中和已完成的卷再打开时，看到的都是新讲义配旧题目；新讲义里已经没有的题掉到页尾「本次练习其余题目」。
- 重新导入时嵌入单元由本次导入接管，细则见《学生作答与讲练.md》「嵌入单元生命周期」。

### 10.2 冻结讲义【已定，未实现】

- 开卷时把这一次要显示的讲义段冻结下来，这一次从头到尾、以及以后回看，用的都是这一版（K7）。
- 冻结的是 `splitLessonBlocks` 切出来的讲义段和题目槽，不是 markdown 原文。原文里有答案，不能进学生读得到的任何表。【建议】
- 冻结功能上线之前的卷没有冻结的讲义：已完成的旧卷回看时仍然现切当前讲义，讲义在开卷之后改过的话提示「讲义可能已更新，和当时不完全一致」；进行中的旧卷在下一次打开时补冻结。【建议】

### 10.3 重新导入后，进行中的卷重新开始【已定，未实现】

- 学生打开一份进行中的卷时，如果老师在开卷之后重新导入过这篇讲练、内容有变化，告诉学生「老师更新了这份讲练」，让他重新开始（K8）。
- 导入的时候不去批量改学生的卷，学生下次打开时再判断。【建议】
- 整页编辑、题库改单题不是重新导入，不触发重新开始：进行中的卷继续用冻结的那一版，和普通练习「老师改题库不影响进行中的卷」一致。【建议】，待确认 Q5
- 旧卷怎么收【建议】，待确认 Q8：

| 旧卷的情况 | 处理 |
| --- | --- |
| 逐题看，至少有一道题看过答案 | 结束这一次并保留记录，其余的题按未做，历次里注明「讲义更新后结束」 |
| 逐题看，一道都没看过答案 | 作废，和现在的「重新开始」一样 |
| 做完统一看 | 作废。这种卷在结束之前没有任何一道题出过结果 |

- 已完成的卷不受影响，回看用冻结的那一版。

## 11. 保留：一组习题在前、讲义在后（等讲练 DSL）

- K6 里提到的另一种形态「一组习题在前、讲义在后」，产品方定为保留、这一轮不实施，先设计讲练 DSL（K9）。
- 做不了的原因：现在讲义段和题目之间只有先后位置，没有「这几道题对应这一段讲义」的关联（§3）。要把一组题排到对应的讲义前面，得先能说清楚哪些题和哪一段是一组。
- 设计时可以考虑的两个方向（讨论中提出，都没定）：题块上加一个指向讲义段的属性；或者新增一个把题组和讲义段包在一起的容器。两者都要遵守 DSL 的兼容规则：已发布的指令只增不改，新属性可选且有默认值。
- 这份 DSL 设计同时能解决 §5.4 的限制，也是 §9.2「回到讲义」定位到段落（而不只是定位到题目）的前提。
- 修改计划不为它排步骤，也不预留字段。

## 12. 这个专题不做的

- 长时间没动自动结束（K3）。
- 学习数据对比（按做法比较正确率和用时）：讲练页现在不采讲义阅读事件，没有数据可比。
- 老师端新界面：老师端看到的讲练卷多了「未做」的题和主动结束的卷，口径和普通练习交卷后一致。
