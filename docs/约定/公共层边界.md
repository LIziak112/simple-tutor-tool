# 门户公共层边界

`apps/web/src/features` 是领域与可复用组件层。门户路由和具体角色 HTTP 实现放在外层宿主，通过 runtime 的窄接口注入；领域类型可以表达学生、教师和账号能力，但不能导入门户实现或凭路径前缀猜认证主体。

`node scripts/portal-boundaries.mjs` 检查全部 features 生产代码，不只检查本次改动，也没有可增长的历史豁免基线。`--json` 输出文件、行号、规则和完整依赖链，退出状态仍在违规时为非零。扫描不到任何生产文件也是失败。

- `PORTAL_ROUTE`：拒绝 `/s`、`/t`、`/p`、`/a` 的字符串、模板片段、静态字符串拼接和正则白名单。注释、`/sqrt` 等非门户路径不作为违规。
- `LAYER_IMPORT`：拒绝静态 import、import type、重导出、字面量动态 import 或 require 指向 pages、portals、App；解析相对路径与 `@/` 别名，并沿本地 barrel 继续检查。非字面量动态 import 以 `DYNAMIC_IMPORT` 拒绝，不能计算路径绕过边界。
- `ROLE_CLIENT`：拒绝具体角色客户端，包括 `lib/api`、`lib/api-*`、`lib/*-api`，以及任意名字但包含具体角色端路径的中间模块；也拒绝直接 `api.api.student/teacher/public/admin` 或等价括号访问。类型引用不能借具体客户端模块绕过。
- `ROLE_ENDPOINT`：拒绝领域层中的具体角色 API/媒体路径，包括动态角色的 `/api/` 模板头。角色媒体访问应由宿主按主体租约提供；中性 Blob/图片读取不因一个通用 fetch 调用本身被误判为角色 API。

`lib/api-response` 中的纯错误与解包辅助、契约类型和不包含具体端实现的通用平台工具不受角色客户端禁令影响。既有角色 Cookie、账号 epoch、草稿、随笔 outbox 和中止信号的生命周期仍由宿主和领域租约维持；此脚本不是认证或响应防泄露机制的替代品。

守门使用自包含词法扫描和静态依赖图，不执行被检源码、不增加依赖。它识别常规 TS/TSX 中的注释、字符串、模板和正则；不承诺证明任意运行时字符串运算、反射或动态加载的行为。新增语法/编码变体应先增加反例，不能靠改写字面量绕过边界。完整 TS 类型检查仍由原有流水线负责。

门禁已经接入 `pnpm lint`、`lint:changed`、`lint:architecture`、pre-commit 与 CI 的 scope 治理阶段；说明文档改动不会跳过完整架构检查。scope 阶段仅使用 Node 即可运行，不需要为了守门安装前端依赖。Chromium/WebKit 独立必需矩阵、原测试范围、超时和失败聚合保持不变。

回归入口：`node --test scripts/portal-boundaries.spec.mjs`；同时保留 ci-scope、governance-invariants、file-size-guard 的决策测试。测试文件只按 `.test`、`.spec` 后缀精确排除；`/test/` 子目录中的普通模块与名字包含 `test-data` 的生产文件仍接受检查。短路运算符（`&&`、`||`、`??`）后的正则同样检查，合法除法不作为门户正则。

## 运行时与职责

- `features/runtime/portal-runtime.tsx` 声明领域可见的宿主上下文。生产环境没有缺省端口；缺少 `PortalRuntimeProvider` 会直接报错。React 入口通过 `usePortalClients()`、`usePortalRoutes()` 使用端口，普通函数通过显式 `ApiServices` 参数调用，类型引用只依赖契约和 `runtime/ports`。
- `portals/PortalHost.tsx` 在既有 `student/me`、`teacher/me` 查询上确认主体，创建该主体的不可重绑客户端；个人门户订阅两侧同一缓存，任一侧主体变化都撤销旧租约，班级门户仍保留独立会话。`subject-scope.ts` 将调用者的 AbortSignal 与主体信号合并，响应头与正文消费都再次检查主体，JSON、Blob、原始流和副本均覆盖不响应取消的传输；取消信号使用手动桥接兼容既有浏览器，XHR 也在租约关闭时取消。StrictMode 的 effect 重放通过持有计数处理。
- `portals/clients` 按资源职责实现 HTTP、媒体地址、可靠事件投递与笔记头合批。依赖闭包只能返回创建时同一组服务，不存在全局可变的“当前端口”。旧 `lib/*-api` 只供外层兼容及既有测试接缝，领域层无法引用。
- `features/runtime/service-leases.ts` 按会话对象绑定不可重绑客户端。持久键解析只负责找到业务坐标；上传调度必须同时捕获已绑定的会话对象，不能把解析得到的新对象当作租约。异步队列保留原账号 epoch、幂等键和服务器回执规则。
- 随笔补传以绑定对象识别账号代际，A→B→A 也不能接入旧续体。附件每个条目记住入队客户端，界面只显示本租约的条目，重试继续使用原租约。租约关闭后，已确认同一主体重新进入时可显式接回原文件和原 uploadId；旧进度与回执按捕获的租约丢弃，另一主体不能接回。遥测保留投递 eventIds、ownerId、viewId、持久前缀、确认删除与 beacon 降级规则。
- `features/answering` 拥有题面框架、最终答案输入、编辑上下文、答案展示与填写完整度；`features/persistence` 拥有本机草稿、同步、手写上传与材料恢复。笔记和标注可复用这些能力，不能反向引用 `features/attempt` 的作答编排。`L1_BACK_DEPENDENCY` 规则连同传递引用一起 enforce。

## 个人门户

个人业务页在 `/p/learn/*` 与 `/p/manage/*`，由 `portals/personal/PersonalLayout.tsx` 提供独立壳，不嵌入 `TeacherLayout`。页面复用已有学习与内容引擎，学习壳复用 `useLearnerBindings`，管理壳保留设置未保存导航保护。个人能力仍来自原能力表，班级学生、作业与教师 AI 连接入口不会进入个人导航。

进入或切换视角时，`usePersonalPair` 调用既有双会话检查端口，核验当前角色主体；结果只属于客户端租约，另一个租约即使账号 ID 相同也重新核验。身份仍只写既有两侧查询缓存。Cookie 不配对时回个人登录，不能通过替换另一侧主体恢复页面。

外层兼容映射将个人账号的旧 `/s/*`、`/t/*` 深链接迁到对应个人路径，保留查询与 hash；登录 returnTo 先执行原站内校验再迁移。班级门户的原路径和认证语义保留。个人管理记录可访问自己的学习档案，独立入口对其他学生坐标拒绝展示。

## 验证入口与迁移

架构反例运行 `node --test scripts/portal-boundaries.spec.mjs`；主体与视角重点回归包括 `subject-scope.test.ts`、`service-leases.test.ts`、`use-personal-pair.test.tsx`、随笔 outbox 和草稿/标注同步用例。`e2e/personal-account.spec.ts` 覆盖真实双 Cookie 注册、独立导航、课程与视角切换、个人 MCP 和退出。

统一 schema 保留已冻结主线迁移至 0073，未发布随笔结构由 drizzle 正式生成到 `0074_pale_sebastian_shaw.sql`，包含 memo_shares、parent_memo_seq、agent_request_digest。原结算、用时与复盘 trigger 不移动、不手改；随笔逐条分享保护继续由已审运行时授权与幂等逻辑提供，不虚构额外 SQL trigger。最终冻结的生产旧快照迁移演练由集成负责人单独记录。

## 个人门户兼容与离开保护

旧班级入口中的个人账号由L3 `legacy-personal-location` 统一映射：旧资源库与学生档案别名映到现有管理路由，合法的嵌套 `returnTo`、`aiFrom`、`from` 学习来源先转译，再由领域白名单校验。个人管理顶栏和正文共享设置离开保护，切视角与退出也先确认未保存设置；连接AI复用个人指路卡，不请求教师token。普通学习页保留同一助教队列与角标，工作区仍使用引擎内入口。

压缩正文读取在输入EOF后仍受owner与caller组合信号保护，解压结束及返回前再次检查，不将原取消原因包装成网络或文件损坏错误。链接兑换以token/重试为入口边界捕获操作与owner信号；自身成功提交身份不会重复兑换，外部撤销仍会阻止旧入口清理或写入新主体缓存。

身份缓存变化不能等React提交后才撤销旧端口。宿主在effect中订阅既有me查询，主体或个人配对ID变化时同步关闭旧lease；A→B→A即使被批成一次渲染，也重建新A lease。同ID正常me刷新保留普通lease。认证入口另捕获同一QueryCache的同步写代次，外部同ID成功写入也会使在途认证失效；clear/remove、各绑定与me提交前均检查，只有本次单个原子me提交成功才可完成导航。

登录后的三项预取通过runtime的`prefetchStudentAfterAuth`能力执行。L3明确建立刚提交学生的新短lease，沿同一缓存订阅撤权，完成后释放；不会让旧client转发到新主体。测试宿主仍复用同一预取清单及能力表，保留班级作业/课程/讲义三项、个人课程/讲义两项。

旧入口来源转译逐层校验origin和pathname，合法嵌套查询的编码斜杠不算路径编码；最多8层、每层32KiB。旧`/s`与`/s/`明确转到个人学习首页，查询与hash保留；登录safeReturnTo原边界不放宽。

该预取能力由所有学生身份成功应用路径复用，包括专属链接、密码、个人注册/登录及教师入口的个人双身份登录。短lease的personal选择依据已提交学生的accountKind，不能依据当前入口仍为`/t/login`而跳过peer观察；teacher peer发生A→B→A也永久撤销原短lease。notes/annotation绑定effect依赖clients，ABA重建后生成新持久会话对象并推进原同步epoch，旧对象的WeakMap服务租约保持旧端口；同A本地draft仍按原origin/studentId键安全复用，网络保存回调依赖新clients，不更改存储键或借新端口补旧请求。
