# 开发排障经验

供 Codex 等工具按问题查阅；执行职责见 [代理协作与执行](代理协作与执行.md)，测试范围与 CI 取证见 [工程验证说明](工程验证说明.md)。以下为历次项目记忆提炼的排障顺序，历史问题不等于当前版本仍有缺陷。

## 共享工作区与进程

- 开工和提交前检查 `git status --short --branch`、当前分支与基点 SHA。另一会话可切分支、提交、格式化或改文件，不能假定工作区一直归自己。
- 先复用适合当前任务的独立工作区；共享 checkout 有其他活动会话或脏改动时，使用独立 worktree。新 worktree 放仓库外，避免嵌套文件被 `lint:changed` 和选测扫描。Codex 有托管 worktree 工具时用该工具创建/归档。
- 暂存明确文件路径，不用 `git add -A` 或整个目录；不要替其他会话 stash、reset、清缓存或删未跟踪文件。已混入共享改动时先求文件交集，保留双方证据后只迁移本任务改动，不用整目录还原。
- 服务或端口冲突先用 `Get-NetTCPConnection` 和 `Get-CimInstance Win32_Process` 核对 PID、命令行与归属。只停止本任务进程；不要 `Stop-Process -Name node` 清全机 Node。
- 单测/E2E 计时前检查共租负载；安静窗口背靠背比较相同命令、workers、数据和配置。CPU 饱和时的超时不能直接归为产品回归，也不能仅凭重跑绿就归为环境问题。

## Windows 启停与命令结果

- 后端起不来先区分“启动后秒崩”和“挂起”，查服务日志、监听端口、实际 `PORT`、`DATA_DIR` 和进程命令行。预览工具曾注入 `PORT` 导致后端撞前端端口，不能仅看启动模板。
- Windows 下某些 watch 进程会受管道 stdin 影响；确认普通终端与工具启动的输入模式差异，必要时用无 watch 的定点命令或空输入复现，不反复重装依赖。
- 退出外层 shell 不保证 Node 子进程退出；停止后确认本任务端口已释放。后台辅助进程使用隐藏窗口，除非确需用户操作。
- 截断输出时保留真实退出码；PowerShell 中命令后立即保存 `$LASTEXITCODE`，再读日志尾部，最后 `exit $code`。不能用“输出全过”替代退出码。
- 中文脚本优先写 UTF-8 文件再执行，避免多层 shell/heredoc 转义；`.bat/.cmd` 含中文时检查 CRLF 行结尾。日志、密码或结构化 PR 正文用文件/结构化参数传递，不拼接成 shell 代码。
- 格式化只针对本任务文件，不用全仓 `pnpm format` 或 `biome --write --unsafe` 顺手修改无关代码。

## 数据库启动失败

拉新版本后出现“表已存在”或缺列，先只读核对数据库迁移账本、迁移 journal 与实际表结构，并确认连接的是哪个 `DATA_DIR`。历史上迁移重编号或被重生成导致过账本错位；不要删教学库重来，也不要把旧记忆中的手工补账脚本当通用修复。

结构变更继续经 `pnpm db:generate` 生成；线上修复遵循 [部署文档](../部署.md) 的备份和升级流程，在授权范围内处理，不手改线上库或既有迁移掩盖问题。

## 生成产物与合并树

- `pnpm gen:spec` 后有 `dsl-kit/tutor-lint.mjs` 差异时，先判断真实源变更还是工具链漂移，不直接丢弃产物。记录完整 `git status`，不能用前几行输出判断无漂移。
- 如需对照父提交，在独立临时 checkout/worktree 使用对应源码、锁文件和工具链重生成，对比哈希及语义；不在活动工作区回退源文件。基线可复现而当前变化来自源代码时提交真实产物；基线自身也不可复现则排查依赖/工具链差异，不把不明漂移提交或忽略。
- PR CI 可能测试 base 与 head 的合并树。分支本身可复现不代表合并树可复现；记录 head/base/merge SHA，按当前基点重新生成，不在旧分支盲目重复生成。合并生成文件后从最终源码重生成，不把任一侧产物视为最终答案。

## 自部署浏览器环境

`http://IP` 与 `http://localhost` 的安全上下文不同，不能用 localhost 成功证明 HTTP 自部署可用。新增浏览器 API 先查既有封装：UUID、剪贴板、内容哈希分别见 `apps/web/src/lib/uuid.ts`、`copy.ts`、`content-hash.ts`；能力缺失时测试实际降级路径，不裸调用仅安全上下文 API。

跨设备、系统缩放、Pencil 手感和旧 Service Worker 更新必须验实际环境；模拟 WebKit 不等于真实 iPad Safari。部署后确认浏览器实际加载的版本，再判断修复是否生效。
