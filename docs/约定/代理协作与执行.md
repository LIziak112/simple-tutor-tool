# 代理协作与执行

适用于 Codex、Claude Code 等工具执行本仓库任务。全局规则见 [AGENTS.md](../../AGENTS.md)，验证范围见 [工程验证说明](工程验证说明.md)。本文件承接既有项目记忆中的拆单、降本和交接经验，不依赖某一工具的私有记忆目录。

## 开工与授权

1. 检查当前分支、基点和未提交改动，确认是否有其他会话使用此工作区；按 [开发排障经验](开发排障经验.md#共享工作区与进程)隔离冲突。
2. 只读本任务需要的专题与相关小节。先用 `rg` 定位，避免通读全部文档、源码或历史报告；架构与产品约定不能因节省上下文而省略。
3. 多步任务列出文件、步骤、测试点和边界，按 AGENTS.md 获得确认；用户已经明确授权的方案连续执行，不逐单重复询问。普通可逆实现选择在既定范围内处理；会改变产品行为、数据或交付范围的重大决策再对齐。
4. 默认交付目标为 `v2`。创建 PR、合并、推送与发布遵循本次授权，不能从历史记忆中的某次授权推导本次授权；`main` 发布需用户明确要求。

## 单人执行与编排职责

小改动可由一个代理完成实现、自审和定向验证，不为形式拆出多名代理。用户指定编排时，职责如下；本次用户明确要求主代理亲自评审或指定工人模型时，优先遵从，并保留其余成本纪律。

| 角色 | 负责 | 交付 |
| --- | --- | --- |
| 编排者 | 拆单、确认依赖和权限、选择执行者、裁定风险与下一步 | 状态、结论与必要决策；不持续通读工人源码/日志，不亲自重跑已有有效验证 |
| 实现者 | 有界实现、TDD、修复循环中的定向自检、小步提交 | 提交、测试摘要、遗留与交接文件 |
| 独立验收者 | 完整 diff 的简化与正确性审查；触及学生载荷/答案数据再做安全审查；核验真实测试证据 | 发现、裁决建议与证据；不默认重跑实现者已验证的同一范围 |
| 收尾执行者 | 获准的文档更新、PR 正文、合并与推送 | 操作结果、最终 SHA、工作树状态；可与小修复合为一个有界任务 |

验收者使用与实现不同的干净会话，不能把实现者的自评当独立审查。没有子代理能力时如实说明，按用户已授权的单人方式完成等效检查；若用户要求独立验收且无法满足，则保留该缺口，不虚称已独立验收。不得为此擅自接入外部模型或服务。

## 拆单与派单

- 默认“一层或一项可独立验收的行为、一单、一代理”。契约、服务、前端、E2E 分阶段推进；紧耦合的小变更可同单，但不得将整个跨层改造、后续故障、文档与 PR 整合全部交给一个持续续接的工人。
- 首读文件通常不超过 8 个，只列直接相关路径与章节；按实际调用关系补读，不把数量限制变成漏查理由。完整需求保留在文件中，派单摘要给出关键约束与行号。
- 一个修改工作区同一时刻只有一个写入者。依赖未稳定的下游不得盲目并行；互不依赖的只读审查可在工具容量内并行。E2E 与性能测量错峰，不与其他重测试抢资源。
- 用户指定模型/推理档时严格执行；未指定时按复杂度和风险选择可用档位。复杂设计、保稿、判分、泄露等风险任务投入足够推理，状态查询、文档及机械收尾不默认用最高档。不能降低检查标准来省额度。

派单至少写清以下内容：

```text
目标与完成条件：
工作区、分支、基点 SHA；是否有其他写入者：
先读文件/小节；当前已确认的结论：
本单修改范围；本单不做：
依赖、测试点与验证档位；已有有效结果及日志路径：
允许的提交/推送/合并操作：
到完成条件即收口；范围扩大或出现新根因时先汇报再拆单。
最终回复通常不超过 5 行：状态、提交、测试/退出码、遗留、报告路径。
```

## 上下文、报告与等待

- 每个可验收阶段完成后提交、写交接并自然结束；下一阶段按方案和交接启新代理，不把同一工人连续用于所有层、所有返工及收尾。
- 阶段明显膨胀、需要反复压缩或频繁重读时，在最近干净检查点收口；记录当前完成和未完成的微块。不得强行终止半截编辑。旧记忆中的固定 token 阈值、GLM 看门狗和 `/compact` 指令不直接套用其他运行时。
- 完整证据写入 [审查报告目录](../审查报告/)；临时日志写工作区外临时目录，报告引用路径，避免被未跟踪文件扫描卷进选测。实现计划遵循 [文档地图](../README.md)；同一状态只维护一个入口，不重复粘贴长报告。
- 编排者接收摘要后按需读相关证据一次；不为“我也验过”重新读全量 diff、重跑全套测试或把完整日志回填到对话。
- 优先等完成通知或有界工具等待。长 CI 可用 `gh run watch <run-id> --exit-status` 等待终态；工具已返回运行会话后继续等待该会话，不另起命令反复查同一状态。需要定期沟通时只说明新增证据、阻塞或决策，不反复播报无变化状态。

交接文件至少保留：目标及不做范围、基点/分支/最新提交、改动文件、已确认根因、测试命令/范围/退出码/日志、失败和未决项、下一步、允许的外部操作。不得写入凭证、学生数据或整份原始请求。

## 审查与验证去重

1. 质量闸门仍依次覆盖简化、正确性，以及适用时的安全；复用/层级/效率等相同角度只检查一次，发现合并为同一根因，不叠多套内容相同的审查。
2. 常规改动一轮覆盖相关调用链即可；多角候选、投票和补漏仅用于风险与复杂度确实需要的改动，不做每任务固定“审查电池”。
3. 测试结果绑定所测代码、基线和范围。换代理、改报告、提交或等待 CI 不使已有结果失效；新增实现、测试、依赖或失败证据影响到该范围时才补跑，详见 [验证结果复用](工程验证说明.md#验证结果复用与失败处理)。
4. 失败先读具体用例、退出码与 trace，定点复现；不得靠不停重跑直到全绿或放宽断言完成验收。未确认原因的重试通过必须保留为未决/抖动记录。
