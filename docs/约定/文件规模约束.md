# 文件规模约束

AGENTS.md §五「文件规模与拆分」的细则。阈值、计入范围与豁免的单一事实源是 `scripts/file-size-policy.mjs`，本文解释为什么这样定、怎么拆、例外怎么走、三层守门怎么启用。

## 为什么是「软线 + 硬线 + 基线」，而不是一个数字

- 行数是代理指标，不等于质量。它真正拦住的是「AI 一把梭出巨型文件」这种最坏情况：文件小，agent 能整文件读进上下文、搜索替换式编辑出错少、多人 / 多 agent 并行改同一仓库时冲突面小、评审一次看得完。本仓的反例是 2200 行的 `AttemptSession.tsx`，重构时手动替换出一堆语法错误。
- 单一硬数字会逼出「凑数」：按行数而不是按职责拆（`xxx-part2.ts`）、删空行和注释、一行塞多句、加一层无意义转发——可读性反而变差。所以规则写成「超了就按职责拆并在 PR 里说明」，而不是「不许超」。
- 250 太紧：React 页面组件、路由表、Zod schema、生成代码很容易过线；1000 又太松，只拦得住病态情况。两档一起用：400 行软警告、1000 行硬失败。
- 缺陷密度随文件大小呈 U 形（Hatton 1997）：太碎和太大都差，中等最低。所以也不要把文件碎成几十个 30 行小文件。
- 仓库里已有 34 个非测试源码文件超过 1000 行（最大的 `attempt-service.ts` 4299 行）。它们登记为历史基线，规则是**只降不升**：不要求立刻拆完，但不允许继续长。

## 规则

| 档位 | 阈值 | 触发时 | 生效位置 |
| --- | --- | --- | --- |
| 软线 | 代码文件 > 400 行 | 提醒：继续加代码前先提拆分方案 | 编辑钩子写入后；pre-commit 与 CI 对本次改动文件提示（CI 写进 check 注解） |
| 硬线 | 代码文件 > 1000 行 | 阻塞：写入前拒绝 / 拒绝提交 / CI 红 | 编辑钩子写入前；pre-commit；CI 全仓 |
| 历史基线 | `scripts/file-size-baseline.json` 登记的文件 | 行数不得超过登记值；降到 ≤ 1000 后须移除条目 | pre-commit；CI 全仓；编辑钩子写入后提醒 / 阻塞 |

写入前的钩子只拦硬线、不拦基线增长：重构中间态常会先长后缩（先加导入、再删旧块），当场拒绝会把 agent 卡死。基线增长在写入后立即提醒（Claude Code / Codex 以 `decision: block` 把理由喂回模型），提交与 CI 时拦截。

## 计入范围与豁免

计入：`.ts .tsx .js .jsx .mjs .cjs .mts .cts`。文档、JSON、SQL、CSS 不计——它们的体量不代表职责混杂（CSS 与 SQL 迁移本就按文件组织）。

豁免（见 `EXEMPT_PATTERNS`）：

- 测试与规格：`*.test.*`、`*.spec.*`、`e2e/`、`test-support/`、任意 `test/ tests/ __tests__/ fixtures/ __fixtures__/ __mocks__/ __snapshots__/` 目录
- 类型声明 `*.d.ts`；数据库迁移 `apps/server/src/db/migrations/`
- 生成产物：`generated/` 目录、`*.gen.*` / `*.generated.*`、文件前 5 行带 `@generated` / `AUTO-GENERATED` / `自动生成` 标记
- 技能镜像 `.codex/skills/`、`.zcode/skills/`（源头 `.claude/skills/` 受检，镜像不重复计）
- `docs/ plans/ reports/ samples/ dsl-kit/`

新增豁免要同时改 `scripts/file-size-policy.mjs` 与 `scripts/file-size-guard.spec.mjs` 的样本，并在 PR 说明为什么这类文件的行数不代表职责。测试文件豁免不等于鼓励巨型测试：3000 行的测试同样该按被测行为拆，只是不由本闸门管。

## 怎么拆：按职责，不按行数

- **一起变化的放一起**：先问「这个文件里哪些部分总是一起改」，按变化原因切，而不是按行号切。
- 页面组件 → 容器（数据与状态）+ 展示子组件 + 自定义 hooks；`AttemptSession.tsx` 这类工作区按「作答区 / 工具栏 / 同步 / 快捷键」切。
- service → 按用例或聚合切（查询 / 写入 / 导出各一份），共享的私有工具函数放同目录 `*-shared.ts`。
- contract 的 Zod schema → 按领域切成多个模块，由 `index.ts` 重新导出，保持外部导入路径不变。
- 禁止：`-part2` 切片、删注释与空行、一行多句、只做转发的中间层、几十个 30 行小文件。
- 拆分的 PR 说明写清：拆成了哪些文件、按什么职责切、对外导入是否变化。

## 例外与基线怎么走

- 基线文件：`scripts/file-size-baseline.json`，`{ "仓库根相对路径": 行数 }`，按路径排序。生成 / 核对：`node scripts/file-size-guard.mjs baseline`（加 `--write` 写入），命令会列出新增 / 调高 / 调低 / 移除。
- **只降不升**。调低与移除随手改；新增或调高必须在 PR 写明理由并由评审确认——CI 看不出「为什么长」，这一步只能靠人。
- 重命名历史文件：改基线里的路径。删除：移除条目（CI 会报「条目已不存在」）。
- 降到 1000 行以下：移除条目，文件回到常规闸门（CI 会报「请从基线移除」）。
- 想临时绕过 pre-commit：`git commit --no-verify`。CI 的同一闸门仍会拦，所以绕过只对「先推上去再修」有意义。

## 三层守门怎么启用

| 层 | 文件 | 启用方式 | 行为 |
| --- | --- | --- | --- |
| Cursor | `.cursor/hooks.json` | 打开仓库即加载（Hooks 设置面板可见） | `preToolUse` 越硬线 `permission: deny`；`postToolUse` 以 `additional_context` 提醒 |
| Claude Code | `.claude/settings.json` | 项目设置；改动后 Claude Code 会要求在 `/hooks` 里确认 | `PreToolUse` 越硬线 `permissionDecision: deny`；`PostToolUse` 软线 `additionalContext`、基线增长 `decision: block` |
| Codex | `.codex/hooks.json` | 首次需 `/hooks` 审核并信任（Codex ≥ 0.124） | 匹配 `apply_patch`：按补丁的 + / − 行数预测结果；输出同 Claude Code |
| pre-commit | `.githooks/pre-commit` | `pnpm install` 时由 `prepare` → `scripts/setup-git-hooks.mjs` 把 `core.hooksPath` 指到 `.githooks`；手动 `pnpm hooks:install` | `check --staged`：只看暂存区内容 |
| CI | `.github/workflows/ci.yml` scope 作业 | 每个 PR 都跑，不装依赖 | `check --base $CI_BASE`：全仓硬线 + 基线，改动文件的软线写进注解 |

本地全仓自查：`pnpm lint:file-size`；只查几个文件：`node scripts/file-size-guard.mjs check <路径…>`。

三种编辑钩子都共用 `scripts/file-size-guard.mjs hook <cursor|claude|codex>`，输入无法识别一律放行（fail open）——钩子负责当场提醒与拦截，兜底是 pre-commit 与 CI。agent 通过 shell（`sed`、重定向）改文件不经过编辑钩子，同样由后两层兜住。

`setup-git-hooks.mjs` 在非 git 检出（Docker 构建、源码包）或找不到 git 时直接跳过；已自行设置了别的 `core.hooksPath` 时不覆盖并提示手动命令。Dockerfile 两个安装阶段需要先 `COPY` 这个脚本，否则 `pnpm install` 会因找不到 prepare 脚本而失败。

## 排障

- 钩子没反应：Cursor 看 Hooks 输出通道；Claude Code 跑 `/hooks` 看是否待确认；Codex 跑 `/hooks` 信任。三者都要求 `node`（≥ 24）在 PATH 上。
- 误报生成文件：加 `@generated` 头部标记，或登记到 `EXEMPT_PATTERNS`。
- 基线报「条目已不存在」：文件被重命名或删除，按上节处理。
- Windows：Codex 钩子用 `commandWindows`（相对仓库根，需在仓库根启动 Codex）；Claude Code 需 Git Bash；pre-commit 由 Git for Windows 自带的 sh 执行。
