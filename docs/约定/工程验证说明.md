# 工程验证说明

测试选测、结果复用与 CI 排障的现行入口。命令以根 [package.json](../../package.json)、[共享选测规则](../../scripts/affected-lib.mjs)、[E2E 选测](../../scripts/e2e-affected.mjs) 与 [CI 配置](../../.github/workflows/ci.yml) 为准；代理职责见 [代理协作与执行](代理协作与执行.md)。历史清单、验收记录或技能中的全量命令不能覆盖此处口径。

**云部署不重复开发验证（2026-11-06）**：本文件的选测与质量闸门用于开发、修复与合并。已合并到 `v2` 的版本上线直接复用合并前验证，不重跑单测、E2E、lint、typecheck、代码审查，不重新触发或等待 CI，也不因本次只改部署说明而重跑它们。生产构建只用于生成待上传产物；传输完整性、数据备份、依赖/迁移兼容与上线健康检查属于部署操作。执行入口与回退约定见 [部署文档 §0.1](../部署.md#01-现有云服务器的日常部署)。

## 按阶段选择验证范围

**本机与普通 PR 按范围选测，高风险兜底及定时/手动运行全量。** 不为“更放心”、交接、写报告或最终总结再加跑全量；不把底层 Vitest/Playwright 命令当绕过分层入口的办法。

| 阶段 | 执行方式 | 边界 |
| --- | --- | --- |
| 定位 / TDD 红绿循环 | 从仓库根定点运行受影响测试文件/用例，补最小复现 | Bug 先根因，解析器/判分必须先失败测试；不每次小修都跑全套 |
| 开发 / 修复检查点 | `pnpm test:quick`、`pnpm typecheck:affected`、`pnpm lint:changed` | 测试基线 HEAD，后两项 origin/main；阶段内合并检查，不每次读文件后重跑 |
| 实现收口 / 验证单 | `pnpm test:affected`、`pnpm e2e:affected` | 单测 origin/main；E2E 默认 v2、仅 Chromium、恒含冒烟；已有有效结果不重复 |
| PR CI | 说明文档跳过应用 job；代码保留 lint/类型/生成/构建，单测与双浏览器 E2E 按 PR 基点选测 | 高风险兜底全量；最终 CI 结果汇总为固定检查，本机不复制一套 |
| 纯文档 / 说明性注释 | 链接、镜像、命令口径、格式与 `git diff --check` | 说明不影响运行行为；不为文档运行应用单测、E2E 或构建 |

`test:quick` 看 HEAD 到工作树：提交后可能选不到刚提交的改动，零用例不能证明该提交已验证。保留提交前结果，收口用 `test:affected`。`typecheck:affected` 仅检查改动包及反向依赖包，不等同于根 `typecheck` 中的 E2E 类型检查；改 E2E TS 时补 `pnpm exec tsc -p e2e/tsconfig.json`。

## 自动升级与基线

选测会把已提交、已暂存、未暂存与未跟踪文件纳入决策，删除文件也参与兜底。共享脏工作区可能卷入别人的改动，先隔离，不删掉别人的文件骗过选测。

- `scripts/affected-lib.mjs`：锁文件、Vitest/Playwright/TS/Biome 配置、迁移、数据库 schema、contract、samples、test-support、测试 setup、E2E helpers/global-setup、scripts 等触发兜底。单测此时自动全量，必须执行其决策，不能手选几项替代。
- E2E 另对 `packages/`、服务端数据层/装配入口、未登记的 `e2e/` 路径和映射外 `apps/` 源码兜底。此处“全量”仍仅 Chromium，不自动加 WebKit；标签规则见 [选测实验记录](../e2e功能面选测与preview对照.md)。
- 怀疑范围太广时先打印决策，记录命中路径、基线与理由。`origin/main` 长期落后可能让 `test:affected` 命中此前的契约变更；这与“代理擅自全量”不同，不得为省时私改基线或兜底规则。
- E2E 默认的本地 `v2` 也可能落后。先核对 `git rev-parse v2 origin/v2` 与 PR 目标；获取最新远端引用后，若确认只是本地基线陈旧，可显式 `pnpm e2e:affected origin/v2`，记录两个 SHA 和选择理由，不强制移动别的工作区持有的 v2。这是校正目标分支引用，不能借此忽略本分支真实的契约/迁移变更。
- `pnpm e2e:affected HEAD` 仅核验最近工作树增量，须记录范围；不能替代分支相对 v2 的收口验证。失败复现可用明确 spec/`--grep`，但不能伪称完整选测通过。

PowerShell 只打印选择、不运行测试：

```powershell
$env:AFFECTED_DRY_RUN = '1'
try {
  pnpm test:quick
  pnpm test:affected
  pnpm e2e:affected
} finally {
  Remove-Item Env:AFFECTED_DRY_RUN
}
```

dry-run 不记为测试通过；实际验证前确认该变量已清除。

## 验证结果复用与失败处理

结果至少记录：所测提交或工作树版本、基线、文件/标签/浏览器范围、命令、退出码、通过/失败/跳过及日志路径。退出码非零或有 Unhandled Errors 时，即使 Tests 全过也不能记为通过。

同一代码和环境的有效证据由实现者、验收者、编排者共享；换代理、提交同一文件树、改说明文档、等待 CI 都不使结果自动失效。后续实现/测试/依赖/配置改变该范围，或出现新失败与未决风险时才重验。提交后文件树须与被测版本一致，不能拿早期成功覆盖后续实现改动。

CI 失败先取用例、注解、日志和 trace；记录 head/base/merge SHA，定点复现，再按根因补测。不能循环重跑到绿或先放宽超时、位置容差、断言。原因未确证但重试过的项保留首轮失败和不确定性，不一概归为“环境抖动”。

允许扩大本机范围的情形：选测脚本自动升级、用户明确要求，或具体故障/环境差异确实无法定点复现。后者先说明为什么定点不足、需覆盖什么、何时停止；不要直接执行完整双浏览器再重复构建。新失败只重跑必要 job/用例，不因报告更新重开整套 CI。

## E2E、负载与设备

- 本机 E2E 使用独立临时数据库及 8899/5199 端口，不复用用户 5173/8787 服务或教学 DATA_DIR。与其他 E2E、构建和重单测错峰；先核对端口及进程归属，只停止本任务进程。
- E2E 选测恒含 `@smoke`；不用 Playwright `--only-changed` 替代仓库映射，它认不到应用源码，叠 `--grep` 还可能滤掉冒烟。
- USB 连接真实 iPad Safari 的本机工具见 [iPad 真机调试](../iPad真机调试.md)。模拟设备不能替代 Pencil 手感、原生缩放或真实 Safari 验收。
- `vite preview` 历史对照未通过：部分 spec 依赖 `/src/*` 动态 import 与 `/dev/*` 调试页，不能仅因理论更快就切换。`E2E_WEB_PREVIEW` 默认关闭，详见 [实验记录](../e2e功能面选测与preview对照.md)。

## CI 与确定性排障

CI 在 PR 按范围运行；push 仅 main 触发并全量。新推送取消同 PR 未完成的旧任务，不边等边追加无必要提交；检查最终 SHA 的结果。夜跑固定默认分支 main，不能证明未发布的 v2 正确；指定分支使用对应 PR 或获准的手动 workflow。

- 时间窗口测试显式注入/固定 `now` 并匹配夹具日期，不让固定种子随日历过期；不扩大 `days` 或改成全时段掩盖窗口缺陷。负向断言也确保数据确实在窗口内，避免空集假通过。
- 本机与 CI 的时区、locale 不同。业务要求北京时间时显式 Asia/Shanghai；中文排序使用既有中文 locale 口径，ID/ISO 时间排序不盲目替换。时间问题用确定时间定点复现，不为此重跑全仓。
- 内容泄露哨兵不要意外匹配墙钟时间戳；保留答案/私注保护，明确字段后断言，不能放宽 `assertNoLeak` 掩盖真实泄露。
- 异步函数 mock 必须返回符合契约的 Promise；裸 `vi.fn()` 返回 undefined 曾导致 `.catch` 抛错、断言全过但未处理异常使退出码失败。
- 删除 fixture 前用 `rg` 全仓查引用，不只查 E2E；单测可能通过 fs 读取同一夹具。
- 先读 GitHub check 注解中的失败摘录；需完整日志/trace 时用现有 GitHub 工具或已登录 `gh`，不打印凭证。合并树和产物问题见 [开发排障经验](开发排障经验.md#生成产物与合并树)。

## 生成与内容校验

契约变更执行 `pnpm schema:export`；注册表、lint 规则、契约、linter/CLI 变更执行 `pnpm gen:spec`（含 schema 导出），提交真实生成产物。这些不是重复应用构建，不能用“本机不全量”省略。CI 要求生成后 diff 为空；仅改普通执行文档不触发生成。

DSL 内容用 `pnpm tutor-lint <文件或目录>`；重抽取前 `pnpm reparse --dry-run`，实际 `reparse` 复用正确 DATA_DIR、保留题目 ID。生成规范与分发包 `dsl-kit/` 不手改。

## 历史性能结论（不作为当前耗时承诺）

2026-10-25：`createTestDb` 模板克隆将单次建库从 42.9ms 降为 0.9ms；当时 5,775 用例从 318–335s 降至约 266s。模板字节不能写脏，旧结构/截断迁移测试保留 `createDb+migrate` 原语。

已否决：`vmThreads` 缺 Web 全局且曾破坏路径/changed 选择；`threads + isolate:false` 导致跨文件全局串扰；当时 `maxWorkers=8` 虽全绿但时长近翻倍。无工具链变化或新证据时不重跑全量实验。jsdom 每文件创建约占当时 tracked time 的 33%，为已接受余量。

负载敏感测试曾按文件/describe 设置 15–30s 超时，结果过渡等待为 10s；这是历史调优，不是新失败一律放宽超时的依据。基准遵循 [共享负载经验](开发排障经验.md#共享工作区与进程)。

## PR 范围判定（2026-11-05）

工作流先运行无依赖的 `node --test scripts/ci-scope.spec.mjs` 和范围判定，不安装应用依赖。说明文档白名单包括根说明、约定/计划/审查报告及技能说明；未知路径、DSL 样例和可能被 fs 读取的夹具不自动豁免，混合代码改动不会跳过。

PR 检出 GitHub 合并树、获取完整历史，以事件中的 base SHA 比较，覆盖整条 PR。单测复用 changed/import 图和共享兜底，E2E 复用 decideE2e 的功能标签/spec 清单、冒烟与兜底，同时运行 Chromium/WebKit。契约、迁移、脚本、工作流、根配置等升级全量。应用改动保留 lint、类型、生成一致性与构建检查。

`main` 推送、schedule 和 workflow_dispatch 强制全量。固定「CI 结果」job 在范围判定失败、应运行的应用 job 失败/取消/意外跳过时失败；纯说明文档的应用 job 正常跳过后成功。不用工作流级 paths-ignore，避免未来必需检查永远 pending。分支保护若已配置旧 job 名，管理员需改为此固定检查；本次不自动变更仓库权限或保护设置。

本次修改 CI/选测基础设施，PR 本身应触发全量兜底验收一次，不把纯文档豁免套到配置修改。脚本决策测试用 Node 原生测试入口，不依赖 Vitest，scope job 每次都会执行。


## CI 双浏览器任务

Chromium 与 WebKit 通过矩阵分别执行同一份范围决策，各自保留原用例超时、45 分钟套件上限及 55 分钟 job 上限。一个浏览器失败不取消另一个，失败报告按浏览器区分；固定「CI 结果」仍要求整个 e2e 矩阵成功。脚本不传 CI_E2E_PROJECT 时保持原双浏览器命令；只接受 chromium 或 webkit，空值和未知项目直接失败，不静默减少覆盖。
