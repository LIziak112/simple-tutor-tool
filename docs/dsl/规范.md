## 一、文档结构（frontmatter）

每个文档以 YAML frontmatter 开头（首行 `---` 围栏）：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| kind | 是 | `practice` 练习 / `lecture` 讲义 / `mixed` 混合 |
| unit | 否 | 练习单元标题（practice/mixed）；缺省取文件名（去扩展名）；其 slug 参与题目缺省 id「单元slug-序号」 |
| title | 否 | 讲义显示名与导入键（仅单讲义文件生效）；缺省取第一个 H1；多讲义文件逐篇按各自 H1，声明的 title 被忽略并告警 |
| lecture | 否 | 配套讲义的名字（声明本练习挂到哪篇讲义，导入时按讲义名在同文件夹匹配） |
| topic | 否 | 主题/知识点描述 |
| dsl | 否 | DSL 版本号，缺省 2；旧版本文档永远按旧规则解析 |

- `practice`：正文由若干 `::::question` 顶层题目容器组成，解析为一个练习单元；
- `lecture`：正文按 `# 第X讲 …`（一级标题）切分为多篇讲义，讲名作标题，H2/H3 进目录；
  第一个 H1 之前不要写正文（若写了会并入第一篇讲义并给出 CONTENT_BEFORE_FIRST_HEADING 警告，内容不丢失）；讲义内不出现 question；
- `mixed`：讲义段落与题目交替出现，导入时拆成讲义 + 练习单元并建立关联。

### 命名与身份规则

题目 / 单元 / 讲义的统一身份规则：**文档里声明的名字 = 身份；没声明 = 缺省派生；身份决定再次导入时更新还是新建**；其余情况导入时自动生成，无需关心。

| 实体 | 身份（导入键）来源 | 缺省派生 | 再次导入 |
| --- | --- | --- | --- |
| 题目 | 容器 `id` 属性 | `单元名-序号` | 同 id → 更新（version+1） |
| 单元 | frontmatter `unit:` | 文件名去扩展名 | 同名 → 合并题目 |
| 讲义 | frontmatter `title:`（可选） | 第一个 H1 | 同文件夹同名 → 覆盖正文 |

匹配与合并范围：

| 实体 | 匹配范围 | 行为 |
| --- | --- | --- |
| 题目 | 各教师自己的资源库内（按 id） | 同 id 更新；文件中缺失的已有题保留 |
| 单元 | 各教师自己的资源库内（按 unit 名） | 同名合并，保留原文件夹 |
| 讲义 | 同文件夹（按讲义名） | 同名覆盖正文 |

考点（`knowledge` 属性）为公共数据，按名称全局匹配合并。

`lecture` 是**配套讲义指针**：按讲义名在同文件夹匹配，匹配不到时导入预览给出 warning（LECTURE_LINK_UNRESOLVED），不会静默不关联。

## 二、题目语法

### 题型（question 的 type 属性，七种）

| type | 判分方式 |
| --- | --- |
| judge 判断 | 题干写 `[[正确]]` 或 `[[错误]]`，按标记判分（一题一个标记） |
| choice 单选 | 题干用 GFM 任务列表写选项（`- [ ]` / `- [x]`），正确项标 `[x]`，单选恰一个 |
| multi 多选 | 同 choice 写法，允许并要求至少一个 `[x]` |
| fill 填空 | 题干里 `[[答案]]` 即一个空；等价答案 `[[0.5|1/2]]`；空与答案按出现顺序对齐。答案需公式展示时写 `$…$`（如 `[[$-\frac{3}{4}$|-3/4]]`，判分不受影响，见下方要点） |
| solve 计算 | 手写题（学生写过程），可选 `:::answer` 给最终答案用于自动判分 |
| apply 应用 | 手写题（应用题），同 solve |
| find-error 找错 | 手写题（找错题），同 solve |

### 题目容器写法要点

- `::::question{type=… difficulty=… knowledge=…}` 包住一道题；题目 id 用 `{#p4-q7}` 指定，
  缺省为「单元slug-序号」；编辑内容时保持 id 不变，学情统计才能跨版本延续；
- 题干正文直接写在容器内；`:::hint` 可多个（学生逐个点开）；手写题可选 `:::answer`；
  `:::solution` 详解在学生交卷后才下发；
- `$…$` / `$$…$$` 数学环境与代码块内的 `[[…]]` 不识别为填空标记；
- **不要把填空空格嵌进公式**：若某空需要落在算式中间（如逐步约分过程），把公式在该处断成
  两段 `$…$`、`[[…]]` 夹在两段之间，断点两侧用**普通括号** `(` `)`，不要用 `\left(`/`\right)`——
  `\left` 与 `\right` 必须在同一条公式内配对，跨段不配对会触发 MATH_LEFT_RIGHT_UNBALANCED，
  KaTeX 将无法渲染（页面把 LaTeX 源码原样显示）；
- 填空答案需公式展示时把该答案写成 `$…$`（如 `[[$-\frac{3}{4}$|-3/4]]`）：判分归一化
  会自动剥去 `$` 并做数值等价（`$\frac{3}{4}$` 与 `3/4`、`0.75` 互通），不影响判分；
  交卷后结果页的参考答案按公式渲染。不带 `$` 的裸 LaTeX（如 `\frac{3}{4}`）只按原样显示；
- choice/multi 的选项字母按顺序自动编为 A/B/C/D，不需要手写字母。

## 三、指令语法（固定三种写法，永远不新增写法）

| 写法 | 形式 | 适用场景 |
| --- | --- | --- |
| 容器指令 | `:::名称{属性}` … `:::` | 包住一段内容 |
| 块指令 | `::名称[文字]{属性}` | 独立一行的组件 |
| 行内指令 | `:名称[文字]{属性}` | 句子中间的标记 |

- 属性统一 `{#id .样式类 键=值 键="带空格的值"}`；指令名均为小写；
- 容器嵌套时外层多一个冒号（如 `::::question` 内放 `:::hint`），且必须写结束围栏，
  否则之后的内容会被吞进容器；
- 填空/判断的 `[[答案]]` 是行内语法糖，不是指令，不要写成 `:blank[…]`。

## 四、指令清单（17 个，按注册顺序）

### question

- 写法：容器指令：`:::question{属性}` … `:::`（嵌套时外层多一个冒号，如 `::::question`）
- 可用于：文档顶层；since 2.0；别名：无

一道题，练习/混合文档的顶层容器。内部依次为：题干正文（填空标记 [[…]]、判断 [[正确]]/[[错误]]、选择题任务列表 - [x] 都直接写在题干里）、可选的 :::hint（可多个）、手写题可选 :::answer、可选 :::solution。id 可用 {#p4-q7} 指定，缺省为「单元slug-序号」；编辑内容时保持 id 不变，学情统计才能跨版本延续。type 必填，difficulty 缺省 2。

示例：

```markdown
::::question{type=fill difficulty=2 knowledge="有理数加法"}
计算：$(-3)+7=$ [[4]]。

:::hint
同号相加取相同符号；异号相加取绝对值较大的符号。
:::

:::solution
$(-3)+7=4$。
:::
::::
```

属性：

| 属性 | 类型 | 必填 | 缺省 | 说明 |
| --- | --- | --- | --- | --- |
| type | judge / choice / multi / fill / solve / apply / find-error | 是 | — | 题型，必填。七种取值：judge 判断 / choice 单选 / multi 多选 / fill 填空 / solve 计算 / apply 应用 / find-error 找错；写其他值会在 lint 报错 |
| difficulty | number | 否 | 2 | 难度 1–5 的整数，缺省 2；可写字符串数字（如 difficulty=3），解析时自动转换 |
| knowledge | string | 否 | — | 考点（单个字符串），用于学情统计；解析时归一为数组入库 |

通用属性：任何指令都可用 `{#锚点id}` 与 `{.样式类}`（写入 id / class，多个样式类以空格相连）。

### hint

- 写法：容器指令：`:::hint{属性}` … `:::`（嵌套时外层多一个冒号，如 `::::hint`）
- 可用于：题目内 / 讲义正文；since 2.0；别名：无

提示。题目内可有多个，学生端逐个点开、每次点开都记录事件（教师可见提示使用情况）；也用于讲义正文补充说明。提示内容不下发到题面，学生主动获取。

示例：

```markdown
:::hint
同号相加取相同符号；异号相加取绝对值较大的符号。
:::
```

属性：除通用 `{#锚点id}`、`{.样式类}` 外无额外属性。

### answer

- 写法：容器指令：`:::answer{属性}` … `:::`（嵌套时外层多一个冒号，如 `::::answer`）
- 可用于：题目内；since 2.0；别名：无

手写题（solve/apply/find-error）的「最终答案」，写在对应 question 内，服务端用它自动判分。属于教师侧机密，学生端交卷前不下发；过程与评分说明另用 :::solution。

示例：

```markdown
:::answer
-3
:::
```

属性：除通用 `{#锚点id}`、`{.样式类}` 外无额外属性。

### solution

- 写法：容器指令：`:::solution{属性}` … `:::`（嵌套时外层多一个冒号，如 `::::solution`）
- 可用于：题目内 / 讲义正文；since 2.0；别名：无

详解/讲解。题目内：交卷后才下发给学生；讲义内：常与 :::example 搭配写例题解析，默认折叠、展开/收起均上报事件。

示例：

```markdown
:::solution
$(-3)+7=4$；$(-2)+(-5)=-7$。
:::
```

属性：除通用 `{#锚点id}`、`{.样式类}` 外无额外属性。

### blank

- 写法：语法糖：直接写 `[[答案]]`（行内文字，不是指令写法）
- 可用于：题目内；since 2.0；别名：无

填空/判断的作答空位（语法糖，不是指令，不要写成 :blank[…]）：题干里写 [[4]] 即一个空；等价答案用 | 分隔，如 [[0.5|1/2]]；判断题固定写 [[正确]] 或 [[错误]]。空数由标记自动统计，答案与空按出现顺序对齐。标记内含参考答案，属教师侧内容，学生端下发前会被替换为输入框。

示例：

```markdown
计算：$(-3)+7=$ [[4]]；$(-2)+(-5)=$ [[-7]]。
```

属性：除通用 `{#锚点id}`、`{.样式类}` 外无额外属性。

### example

- 写法：容器指令：`:::example{属性}` … `:::`（嵌套时外层多一个冒号，如 `::::example`）
- 可用于：讲义正文；since 2.0；别名：无

讲义例题块：题面 + 解析，解析常以 :::solution 写在本块内（默认折叠，展开/收起均上报事件）。嵌套时外层要多一个冒号（::::example）。仅用于讲义/混合文档的讲义段落。

示例：

```markdown
::::example{title="例 1"}
计算 $(-3)+7$。

:::solution
$(-3)+7=4$。
:::
::::
```

属性：

| 属性 | 类型 | 必填 | 缺省 | 说明 |
| --- | --- | --- | --- | --- |
| title | string | 否 | — | 例题标题，可选；缺省前端显示「例题」 |

通用属性：任何指令都可用 `{#锚点id}` 与 `{.样式类}`（写入 id / class，多个样式类以空格相连）。

### steps

- 写法：容器指令：`:::steps{属性}` … `:::`（嵌套时外层多一个冒号，如 `::::steps`）
- 可用于：讲义正文；since 2.0；别名：无

逐步揭晓：把推导/解题过程拆成若干 :::step，学生逐步展开，每展开一步上报一次事件，教师能看到推进到哪里。仅讲义正文可用。

示例：

```markdown
::::steps
:::step{title="第 1 步：去括号"}
先处理乘方，再算乘除。
:::
:::step{title="第 2 步：合并"}
$-4+1=-3$。
:::
::::
```

属性：除通用 `{#锚点id}`、`{.样式类}` 外无额外属性。

| 属性 | 类型 | 必填 | 缺省 | 说明 |
| --- | --- | --- | --- | --- |
| src | string | 是 | — | 图片路径，必填：写导入时上传到服务端 blobs 的文件路径（如 "blobs/fig-1.png"），不支持外链 URL |
| width | string | 否 | — | 显示宽度（如 "60%"、"320px"），缺省自适应 |

通用属性：任何指令都可用 `{#锚点id}` 与 `{.样式类}`（写入 id / class，多个样式类以空格相连）。

### graph

- 写法：块指令（独立一行）：`::graph[文字]{属性}`
- 可用于：讲义正文 / 题目内；since 2.0；别名：无

函数图像，前端用 function-plot 按需加载渲染。fn 为函数表达式（如 x^2、sin(x)），range 为 x 轴范围（如 -3,3），缺省自动选取。

示例：

```markdown
::graph{fn="x^2" range="-3,3"}
```

属性：

| 属性 | 类型 | 必填 | 缺省 | 说明 |
| --- | --- | --- | --- | --- |
| fn | string | 是 | — | 函数表达式，必填，如 "x^2"、"sin(x)" |
| range | string | 否 | — | x 轴范围（如 "-3,3"），缺省自动选取 |

通用属性：任何指令都可用 `{#锚点id}` 与 `{.样式类}`（写入 id / class，多个样式类以空格相连）。
## 五、兼容规则（写给 AI，必须遵守）

1. **只增不改**：已发布指令的名字和含义永不改变；属性只能新增，且新增属性必须可选、带缺省值；
2. **改名用别名**：老指令改名后旧写法经别名继续有效——写内容时优先用清单中的主名；
3. **未知指令优雅降级**：渲染时按普通文字显示、不报错；因此**不要发明清单之外的指令或新语法**，
   需要的能力清单里没有就不用；
4. **版本声明**：frontmatter `dsl: 2`（缺省即 2），解析器按版本选择规则。
