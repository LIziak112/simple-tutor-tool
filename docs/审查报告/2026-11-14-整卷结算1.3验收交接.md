## 最终行为

- 契约与 JSON Schema 以两个严格分支表达：final 的成员数可为 0，partial 必须正数，但本期无 partial API/UI。
- `responses` 定义完整移出主 schema，保持旧出口；主 schema 2623→2445 行，基线下降。计时父提交已抽自动收尾，本包直接复用。
- 0067 仅新建结算表、追加可空列和索引；0068 用 drizzle custom 生成的新迁移承载同卷引用/不可改归属/不可改结算事实等触发器。没有重建 responses，也未改已有迁移或快照。
- 整卷及两种自动收尾都在原写事务内写唯一 final，实际收纳全部未结算 responses，含坏快照占位；判分、展示和答案公布范围保持原语义。全部逐题提交后虽剩余未提交题为 0，final 仍收纳全部未结算题。
- 结算只合计封存行的用时，区分 NULL 与 0；旧非空时间不重算。后续教师批改、自评和量表不改成员/结算用时。旧协议行提交时刻仍保持原语义。
- 普通逐题改为 immediate 事务：两进程实测原 deferred 事务会产生 SQLITE_BUSY，末两题可能未收尾。改动仅取写锁时机；格式器缩进造成较大 diff，`git diff -w` 可核对其实际行为差异。
- 一次性历史回填只补完成卷的结算和归属，原交卷时刻保留；坏/缺失时刻使回填失败而非用上线时间冒充。作废 draft 不补 final，旧完成卷与正常父删除/重做兼容。
- 随笔来源构造改从授权后的 response 取真实 `settlementSeq`，客户端伪造序号忽略。已存上下文不重写；同 clientId 的旧请求重放仍返回原 null 快照。MCP 经同一 memo-service，未新增工具。
