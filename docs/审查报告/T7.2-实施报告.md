## 二、实现要点

- **渲染器表**（directives/index.tsx）：`withTypedAttrs<TSchema>(definition, component)` 把组件与其指令 schema 绑定为 `DirectiveRenderer`。泛型在注册行具体化——safeParse 输出类型与组件 attrs 类型由同一 schema 推导，无 any、无强制断言；组件声明错 attrs 类型时编译即报错。`directiveComponents` 保留表名与显式维护（方案 §六.6 不变量措辞），值变为渲染器绑定。
- **降级协议**：渲染器解析失败返回 `null`（类型文档明文「null 是本层唯一失败信号，合法空输出请用空 fragment」）；宿主 `render?.(props) ?? degrade()` 单点构造 UnknownDirective——未注册与属性非法共用一条路径，正文保留、不抛错。宿主语义属性 `directive/dclass/index/dindex` 仍不进入 strict schema。
- **组件迁移**：types.ts 拆 `DirectiveBaseProps` + `DirectiveProps<TAttrs>`；不读 attrs 的六个组件（hint/answer/solution/steps/columns/blank）用 BaseProps；Question 删 `parseDifficulty` 与 `?? "题目"` 兜底（Record<QuestionType,string> 穷尽）；Mark 颜色表键类型从契约推导（穷尽四色，删兜底查找）；Step/Fold 删死可选链。trim 呈现层归一保留（schema 收紧 trimmed-min 属破坏兼容，见待办一）。
- **TDD**：typed-attrs.test.tsx 先行，difficulty=abc / color=purple / 缺 fn / 缺 src / hint 串用 color 五例确认红（旧行为渲染占位或忽略）后实现转绿；缺省值用例（难度 2、第 1 步、yellow）锁迁移前后语义不变。

## 三、有意的行为变化（渲染层校验语义，与 lint 同口径）

1. 值非法/越界（difficulty=abc、=7、=0）、必填缺失（image 缺 src、graph 缺 fn）、strict 拒绝跨指令串用键（hint{color=red}）、`{title}` 空写法（解析为空串，min(1) 拒绝）：旧=静默按缺省/占位渲染，新=整体降级 UnknownDirective（正文保留）。已各有用例锁定。

3. 未知指令路径、样式类 directiveClass 通道、别名查表层归一、编号计数器：零变化。
