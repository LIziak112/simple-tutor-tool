# PWA 安全更新实施与验收

## 问题与行为

服务器发布答题卡滚动修复后，iPad 仍在运行旧版应用。真机检查确认：旧 Service Worker 控制页面，新 worker 已安装但停留在 waiting，普通重新加载没有完成版本切换。保存确认后激活待用版本，题号列表恢复独立滚动，用户已确认该滚动问题复测正常。

本次改动补齐后续版本的更新流程：发现就绪版本时提供非模态提示；用户选择「保存并更新」后，先冻结新增输入、收笔并等待真实落盘与同步检查，再向 worker 请求激活，最后重载。任何失败均保留当前页面与稿件，恢复交互并显示原因。其它页面意外触发接管也不直接刷新。

## 保稿范围与限制

- 覆盖普通作答、讲练、正式手写、草稿、题面和材料圈画、订正。
- 复用现有保存链路，不能仅根据保存函数返回或「全部已保存」文案放行；检查本机写入、读取错误、待传、冲突、拒绝与会话代次。
- 常驻末轮检查不依赖当前路由，保护学生编辑器卸载后、切到教师页面或退出后仍在内存中的稿件。旧账号只检查本机落盘，不以新账号上传旧稿；已落盘的旧账号待传稿继续保留。
- worker 枚举同作用域窗口，只有请求更新的页面是唯一窗口时允许激活。其它页面、旧版页面与挂起页面都要求先保存并关闭，不把无响应当作已保存。
- 不自动提交、交卷、封存、裁决或清理学生数据；已有脏表单和其它编辑弹窗保守阻止更新。
- 注册使用 `updateViaCache: "none"`，固定更新控制脚本采用 `no-cache`；回前台和恢复联网时节流检查，不周期轮询。
- 首次发布本保护逻辑时，仍运行旧应用的页面没有新门禁：需要先保存，再完整关闭同站页面并重新打开。不能对旧页面强行激活来替代保稿。

## 实施与审查

采用测试先行，由业务保稿与 PWA 协调两个子任务实现，主对话统一审查；另由只读审查子任务检查更新协议。仓库列出的专用工作流技能当前不可用，采用等效的根因调查、失败测试、简化审查、正确性审查、安全检查及真实命令验证。

实际修复了以下审查发现：

1. 材料圈画的在途最后一笔未纳入普通保存等待；新增组件回归先失败后通过。
2. 部分底层保存会记录失败状态但不抛出；更新必须复核真实存储状态。
3. 学生路由卸载后仍可能有后台落盘；将末轮检查移到整页常驻组件，补跨路由及退出回归。
4. 保存阶段的超时曾覆盖后续激活阶段；补「保存 25 秒、激活 6 秒」回归，并在保存完成后解除该阶段计时。
5. 未受控的首次访问页面可能拿到等待更新；关闭其它页面后新 worker 自然激活，未受控页不会收到 `controllerchange`。已改为跟踪已发现更新 worker 的状态，用户明确选择更新且保稿成功后可以重载；首次无旧版本的安装仍不自动刷新。
6. 长作业 E2E 把全页失焦监听数量写死为 1，新增合法的常驻保稿监听后误判标画未就绪。改为检查打开标画相对既有监听增加 1，保留关闭后恢复、重复开合及唯一输入画布的断言。

## 手动验收方法

1. 在 HTTPS 测试环境使用包含本保护逻辑的版本，输入答案并书写草稿、正式手写、题面或材料圈画；发布下一版本，确认提示不抢焦点，点「稍后」能继续操作。
2. 在保存尚未完成、存在同步冲突、权限变化或本机保存失败时点更新：不得重载、清稿或提交，错误应明确并可重试。故障注入只在隔离测试环境执行。
3. 同时打开第二个同站页面，更新应要求先保存并关闭其它页面；关闭后重试，应能切换版本。
4. 对成功保存的答案及各类笔迹完成更新重载，重新核对正文与最后一笔。需要真实 iPad/Pencil 验收，浏览器模拟不能替代。
5. 切到教师页面后检查学生后台保存未完成的情况；教师自身仍有未保存设置或编辑弹窗时同样不得更新。

本次实现与测试不包含生产部署。新流程首次上线后的真实 iPad/Pencil 验收仍待进行。
