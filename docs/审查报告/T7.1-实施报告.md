## 1. 实现与范围

- 导出既有 `directiveComponents`，一致性测试要求主名集合与组件自有键集合完全相等，反向 fixture 检测漏项和多余项。
- 宿主先查询注册表，别名归一后检查 `Object.hasOwn`；两处均命中才渲染组件，否则走既有 UnknownDirective，保留正文与原始名称。修复 constructor 崩溃、toString 正文丢失和 __proto__ 被当作组件的问题。
- `deriveDirectiveHostAttrs` 接收契约 `RegisteredDirective[]` 的只读清单，从 ZodObject 的公开 shape 提取键，与 directive/dclass/index/dindex 合并去重；三种指令宿主使用同一推导结果。
- 不改指令注册定义、计数器、契约、服务端题干投影、判分、Context、依赖或数据库。白名单只应用于指令宿主，id/class、KaTeX、协议与全局清洗规则保持原有处理。
- 同步阶段方案与清单；新增实施计划和本报告。历史归档改为名称引用，避免提交未跟踪的研究文档。

共享目录在实施中被另一个会话切回 v2 并提交学情提示词改动。为避免相互影响，本任务迁移到 Codex 独立工作目录，7 个本任务文件复制后做 SHA256 校验，再清理共享目录内本任务的临时副本；未动其他文件。新目录离线安装同一锁文件的依赖，未改变技术栈或 lockfile。

### 简化与复用审查

- 保留显式组件表和既有 UnknownDirective，直接增加注册表/自有键条件，不引入第二层注册框架、异常捕获补丁或通用分派器。
- 属性推导为一个纯函数，复用契约类型与 Zod 公开 API，不读取私有 `_def`、不手抄属性列表。
- 集合正反 fixture 复用同一断言；别名 mock 用后恢复，未污染模块级注册表。
- 不扩大到 T7.2 类型迁移或 T7.9 自动发现。没有需要额外抽象或删除的重复实现。

### 正确性与清洗边界审查

- 两种单条件失配均有三个宿主回归：映射有但未注册，以及已注册但没有组件自有键。未知名称保留富文本正文，别名使用主名组件并保留属性。
- 当前注册定义均为 ZodObject，一致性测试显式检查该前提；未来 schema 形态改变应同步调整推导，不预造复杂解包逻辑。
- 推导值只赋给三个自定义宿主；普通 DOM 全局属性、KaTeX 白名单、危险协议、id/class 的上游过滤均未修改。
- 审查发现原有 XSS 用例缺少对指令图片协议及 id/class 通道的直接断言，已补 4 条回归：javascript/vbscript/data 图片 src 被剥除；class 仍控制 box 变体，id 仍不透传。定向 199 用例通过。
- 不涉及学生端 API 载荷、答案字段或判分实现，无新增答案安全路径；本任务完成清洗边界审查与既有投影回归，不把它称为额外 `/security-review` 命令执行。

没有确认后搁置的发现。

## 6. PR 描述与手动复验

PR 描述可用：未知指令 constructor/toString 过去可能令渲染崩溃或丢失正文；宿主现在要求注册表与组件自有键均命中，未知名称保留正文降级。指令清洗属性从注册表自动推导，并以双向映射与属性变更 fixture 防止漂移。验证结果见本报告 §4。

手动验证方法（不作为本任务必需人工门槛）：

1. 教师进入资源库的 Markdown 预览，打开现有含公式、图片、tip/box、fold/steps 的讲义，检查展示与揭晓仍正常。
2. 在教师编辑预览中输入 `:::constructor` 换行正文换行 `:::`、`::toString[块正文]` 和 `句中 :toString[行内正文]`，应保留正文并显示“未支持指令”提示。
3. 输入 `::image{src="javascript:alert(1)"}`，应提示图片路径缺失；输入 `:::box{#toc-id .warning}` 容器正文，应保持警告盒样式且不生成该锚点。
