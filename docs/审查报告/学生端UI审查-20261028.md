## 总体评价

**学生端 UI 整体质量高于同类自部署工具的平均水准**，核心结论是「结构和无障碍底子非常好，缺口集中在触屏细节与少量对比度问题」：

- ✅ 三态（加载骨架/空态+下一步动作/错误+重试）在所有列表页齐全；
- ✅ 触控目标基本达标：导航、选项、工具按钮普遍 `min-h-11`；选择题用 `sr-only input + label 整行命中` 的正确模式（无死区、键盘可用）；
- ✅ 焦点可见性（`focus-visible:ring-3`）几乎全覆盖，`outline-none` 均带替代焦点；无 `transition-all`、无 `autoFocus` 滥用、无 `onPaste` 拦截、无 `div onClick`；
- ✅ URL 即状态（作业/记录/错题本筛选分页全部可深链、可回退）；`aria-live` 反馈广泛；中文文案直白可执行；
- ✅ iPad 横屏的作答页（题单/题卡双栏）与讲练页（讲义/题卡双栏）布局优秀；五视口**零横向溢出**；
- ✅ overscroll 有系统性处理（`overscroll-contain` + `use-dynamic-overscroll`），固定底栏全部带 `env(safe-area-inset-bottom)`。

需要修的问题按优先级列在下面。P1 两项建议尽快修，P2 是触屏主力场景（iPad/手机）的明显短板，P3 为打磨项。

## 问题清单

### P1 — 建议立即修

#### 1. 首页问候横幅渐变右端文字对比度不达标（全端）

- 位置：[StudentHomePage.tsx:91](../../apps/web/src/pages/student/StudentHomePage.tsx:91)（`bg-gradient-to-r from-primary to-sky-500` + `text-white/90` 的概要句）
- 现象：概要句为 14px 常规字重白字（90% 不透明度），横跨整条渐变。左端 `oklch(0.55 0.2 260)` 对比度约 4.3:1（临界），右端 `oklch(0.685 0.169 237)`（≈ sky-500）对比度仅约 **2.8:1**，远低于 WCAG AA 要求的 4.5:1。右端文字正落在浅色渐变段上。
- 影响：视障学生、强光下 iPad 使用时读不清「今天有 X 份作业待完成」这句核心引导。
- 修复策略（任选其一，推荐 a）：
  - a. 渐变右端加深：`to-sky-600`（或 `oklch(0.55 0.18 240)` 一档），保证两端对白字对比度 ≥4.5:1；
  - b. 概要句升为 16px semibold 并全白（仍需右端 ≥3:1 才算大字达标，不如 a 稳）；
  - c. 右半段叠一层黑色渐变遮罩。
  - 修完用浏览器取色器/对比度工具核两端数值。
- 参考截图：[学生端UI审查-20261028/phone-home.png](学生端UI审查-20261028/phone-home.png)

#### 2. Sheet 抽屉关闭按钮 32×32，低于 44px 触控标准（iPad/手机）

- 位置：[sheet.tsx:62](../../apps/web/src/components/ui/sheet.tsx:62)（`size-8`）；对照 [dialog.tsx:73](../../apps/web/src/components/ui/dialog.tsx:73) 已是 `size-11`（44px），两组件不一致。
- 受害面：学生端 AI「求助记录」面板（[AiQueueButton.tsx:96](../../apps/web/src/features/student-ai/AiQueueButton.tsx:96)）、AI 伴学栏（AiCompanionRail）、以及各处抽屉。手机上 X 按钮热区 32px，手指易点空。
- 修复策略：`size-8` → `size-11`，与 dialog 对齐；一次改动全端受益。
- 参考截图：[学生端UI审查-20261028/phone-ai-panel.png](学生端UI审查-20261028/phone-ai-panel.png)

### P2 — 触屏主力场景的明显短板

#### 3. 全局缺 `touch-action: manipulation` 与 `-webkit-tap-highlight-color`（iPad/手机）

- 位置：[index.css](../../apps/web/src/index.css)（全局样式层）
- 现象：学生端主要在 iPad Safari 使用。当前未声明这两项：
  - 快速连点（如选择题选项、上一题/下一题）时 iOS 仍可能触发**双击缩放**；
  - Android/部分 WebView 点按出现**灰色高亮块**。
- 修复策略：在 `index.css` 加：
  ```css
  button, a, label, input, select, summary, [role="button"] {
    touch-action: manipulation;
    -webkit-tap-highlight-color: transparent;
  }
  ```
  手写画布区域（`touch-action: none` 由 InkSurface 自行管理）不受影响；改完在 iPad 真机连点验证不缩放。

#### 4. 设置页「快捷按钮」编辑器复选框命中区 <44px（手机）

- 位置：[StudentQuickButtonsSection.tsx:255-268](../../apps/web/src/features/student-ai/StudentQuickButtonsSection.tsx:255)（「启用」）、[311-352](../../apps/web/src/features/student-ai/StudentQuickButtonsSection.tsx:311)（「圈画/草稿/正式手写」三个并排项）
- 现象：label 行仅随文本行高（约 20px）撑开，复选框本身 16×16；实测手机端命中区高度约 20px，连续勾选「附圈画/附草稿/附正式手写」时极易误触相邻项。
- 修复策略：给这些 label 加 `min-h-11 items-center`（外层 `flex-wrap` 行距同步微调），让整行成为 44px 热区；不影响视觉密度太多。
- 参考截图：[学生端UI审查-20261028/phone-settings.png](学生端UI审查-20261028/phone-settings.png)

#### 5. 手写手感页工具按钮宽 36px（手机）

- 位置：[InkFeelPage.tsx:596-609](../../apps/web/src/pages/InkFeelPage.tsx:596)（试写区工具排「笔」按钮 `className="h-11"` 无 `min-w-11`，实测 36×44；同排「整笔橡皮/撤销/重做/清空试写」文字较长不触发。注：InkPad/NoteToolbar 的工具排已带 `min-w-11`，无此问题）
- 修复策略：该按钮加 `min-w-11`。

#### 6. 进入作答/结果页时手写文档 404×2 的控制台噪音（2026-10-28 复核：非产品缺陷）

- 复核结论：双请求是 **React StrictMode 在 dev 下双执行挂载 effect** 所致（`main.tsx` 开启 StrictMode；`HandwrittenControls.tsx:233` 恢复 effect 双跑）；生产构建只发一次。404 本身是 api.ts 注释明确的「该题尚无笔迹」约定信号（返回 null，从空白开始），不属于错误。**无需修复**；若要消除 dev 噪音，可日后把该读取并入 React Query 缓存（同 key 去重），属可选优化。
- 原「连续请求两次疑似冗余重试」的推测不成立，特此更正。

### P3 — 打磨项（按需排期）

#### 7. 页面级底部安全区兜底缺失（iPhone）

固定底栏（作答底栏、订正工作台、标注工具栏等）都已带 `env(safe-area-inset-bottom)` ✅，但普通列表页（首页/作业/错题本）的主内容底部没有兜底，`viewport-fit=cover` 下 iPhone 滚到底时最后一张卡会贴到 home indicator。
修复：[StudentLayout.tsx:199-207](../../apps/web/src/pages/student/StudentLayout.tsx:199) 的 `<main>` 加 `pb-[env(safe-area-inset-bottom)]`。

#### 8. 缺 `<meta name="theme-color">`

[index.html](../../apps/web/index.html) 未声明，手机浏览器地址栏/PWA 颜色跟随系统而非品牌色。加 light 主色（学生端靛蓝 `oklch(0.55 0.2 260)` 对应的 hex）即可。

#### 9. 未声明 `color-scheme`，学生端存在大量 `dark:` 死代码

学生端与教师端当前均为纯浅色主题（`.student-theme` 换色板），但组件里散布 `dark:` 变体（学生端永不生效）。建议：
- `html` 或主题类上声明 `color-scheme: light`，锁定 UA 控件（滚动条、表单）为浅色渲染，防止系统深色模式下错乱；
- 决策记录：要么后续真做暗色主题（保留 dark: 变体并补 color-scheme: dark light），要么明确不做（学生端清理死变体）。当前非 bug，属一致性债。

#### 10. 登录表单细节（电脑/手机）

[StudentLoginPage.tsx:69-95](../../apps/web/src/pages/student/StudentLoginPage.tsx:69)：
- 两个输入框补 `name`（`loginName` / `password`），提升密码管理器与自动填充归组；
- 登录名输入加 `spellCheck={false}`（中文姓名会被拼写检查标红）；
- 可选：登录页作为「单一主输入」场景可加 `autoFocus`（桌面收益、手机免焦点弹键盘，可只在不触屏时启用）。

#### 11. 无「跳到主内容」跳过链

键盘/读屏用户需先穿过顶栏（7 个站点）才能到内容。顶栏站点少、影响小，列为低优先：`StudentLayout` 的 `<main id="student-main">` + 视觉隐藏的跳过链接。

#### 12. 数字展示未统一 `tabular-nums`

进度/分页/统计数字混排时非等宽（如 [StudentAssignmentsPage.tsx:237-238](../../apps/web/src/pages/student/StudentAssignmentsPage.tsx:237)「第 X / Y 页」、结果页统计卡）。作答底栏已用（[AttemptBottomBar.tsx:117](../../apps/web/src/features/attempt/AttemptBottomBar.tsx:117) ✅），把其余计数处对齐即可。

#### 13. ~~手机端结果页 5 格统计卡偏挤~~（2026-10-28 复核：误报，撤销）

复核代码与实测：统计卡本就是 `grid-cols-2 sm:grid-cols-5`（[AttemptResultView.tsx:671](../../apps/web/src/features/attempt/AttemptResultView.tsx:671)），手机端 390px 实际为 2 列换行（2+2+1），且 `[&_dd]:tabular-nums` 已有。初次审查误读了整页长截图，特此更正，无需修改。

#### 14. 错题本筛选行手机端密度

「最近 30 天」「错 2 次及以上」两个数字筛选在 390px 并排各约 170px，可用但偏挤；`type="number"` 已保证数字键盘 ✅。可选优化：手机端两筛选拆两行，或合并为一个「筛选」折叠面板。

#### 15.（可选）`type="number"` → `type="text" + inputMode="numeric"`

数字框滚轮误改值、无法显示「清除」语义是 number 输入的通病；错题本筛选值域 1–3650/1–99 已有解析校验，改 text + inputMode 更稳。低优先。
