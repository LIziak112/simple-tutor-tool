## 三A、T7.8 推送后 CI 红与 bundle 不可再生成的追查（本任务内处置）

**现象**：v2@340d13a（T7.8 合并推送）CI 失败于「单元测试」步骤（lint/typecheck 过、e2e job 全绿、gen:spec 与 build 步骤被跳过）；142a112 复推同位置再红——确定性失败。

**取证（五轮 CI 注解取证，job 日志需管理员权限而匿名页不可读，故在诊断分支给 ci.yml 加「失败摘录写 check 注解」步骤，注解可经公开 API 匿名读取）**：第一轮抓到 ENOENT 等 stderr 噪声；第三轮确认**日志中零 FAIL 行且 `Test Files 298 passed (298)`——全部断言通过**；第五轮（剥 ANSI 后抓 Unhandled Errors 块）拿到堆栈：

```
⎯⎯ Uncaught Exception ⎯⎯⎯
TypeError: Cannot read properties of undefined (reading 'catch')
 ❯ onExportPack apps/web/src/pages/teacher/LibraryPage.tsx:704:37
 ❯ exportPack apps/web/src/pages/teacher/LibraryPage.tsx:178:35
```

**根因**：`LibraryPage.test.tsx` 的 `downloadTeachingPack: vi.fn()` 裸 mock首次点击「导出教学包」按钮时返回 undefined，生产路径 `downloadTeachingPack(...).catch(...)`（T7.8 新增）对 undefined 读 catch 抛 TypeError，经 React 事件系统异步重抛成 jsdom 未捕获异常；vitest 对「Unhandled Error」判**退出码 1**——断言全过仍红。本地（快机）时序吞掉从未复现：默认序多轮、TZ=UTC+en_US、`--sequence.shuffle`（其 19 例失败均为文件内有序用例被打乱的伪失败）、全新检出+全新安装（298/3807 全绿）、standalone 冒烟对提交版 bundle 直跑 2/2 过——全部无法复现即因异常投递时机依赖调度。**修复**（task/ci-unhandled-fix）：`downloadTeachingPack` / `downloadExportMd`（同款地雷）mock 改 `vi.fn(async () => {})` 守住「下载类 mock 必须返回 Promise」契约；ci.yml 的注解摘录步骤一并入库（此后单测红可免登录定位）。

**bundle 不可再生成（同轮发现的独立问题）**：`pnpm gen:spec` 在 340d13a 树上稳定产出与提交版仅差压缩标识符命名的 bundle（881769 → 881753 字节，字符串集两两配对全为单字母换名，行为等价）；同机对 597980c 树的再生成却与提交版**逐字节一致**（fresh worktree 实测）——即 T7.8 提交进仓库的 tutor-lint.mjs 是一个不可再生成的时点产物（疑似生成与当轮并发格式化/源态竞态），CI 的 gen:spec diff 步骤若跑到亦会拦截。**处置**：已在 T7.10 提交中以可再生成形态重新提交（提交后本地 gen:spec 复跑 diff 为空；597980c 先例证明本机与 CI 的 esbuild 产物同源）。

**CI 复验结论**：（待 task/ci-unhandled-fix 分支 CI 出结果后回填）
