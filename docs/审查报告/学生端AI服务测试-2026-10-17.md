## 已确认问题

1. **P2：AI E2E 缺少跨文件隔离。** playwright.config.ts 开启 fullyParallel；各 AI spec 仅在本 describe 内串行，共享 e2e/fake-ai-provider.ts 的全局捕获列表、FIFO 剧本和 reset。按项目允许的 --workers=2 执行 26 例时，16 passed、3 failed、7 did not run。失败的“禁用期间零出站”“无 AI 开栏零出站”断言捕获到了其他测试的“课程练习求助”“隔离场景求助”。这能证明测试串扰，不能据此判定产品越权。建议按测试隔离供应商会话/剧本/捕获，或将共享服务套件全局串行。
2. **P2：上下文链接文案滞后。** apps/web/src/features/student-ai/AiConnectionManager.tsx:611、788 仍显示“功能建设中，可先保存偏好/配置”，而实际已有链接生成、公开读取与对应 E2E，误导学生判断可用性。说明注释第63行也滞后。
3. **P2：质量闸门未全绿。** pnpm lint 退出码 1，因 .codex/worktrees/v2-clean-20261016/biome.json 被识别为嵌套 root 配置。定向 biome check 亦退出码 1：AiConnectionManager.tsx 与 AiConnectionManager.test.tsx 格式检查失败。未执行自动修复，以保留本轮审查范围。
4. **P3：验收文档头部状态过时。** docs/学生端AI伴学/验收记录.md 第3行称“其余批次未开始、尚无功能代码”，与同文件 B01–B20 已验收记录冲突。

## 能力及适用范围

- 页内 AI 已有完整服务链，首发使用 OpenAI 兼容 chat/completions、非流式响应；不能把协议兼容等同于所有供应商和模型可用。
- MCP 已有真实协议客户端测试，涵盖两题领取回写、题目回复对应、Token 重置后旧客户端拒绝；真实第三方客户端配置和公网连接仍须单独验证。
- 上下文链接已有只读受控出口与过期/撤销/策略重校验；外部 AI 能否抓取正文和图片受网络及客户端能力影响。
- guided_only 是提示词尺度约束，仍按需求附参考答案解析，不是答案保密模式。需要作答期不接触答案应使用 post_submit_only。
- 私网/环回 AI API 地址按既定 SSRF 防护被拒绝；本地模型或内网网关不是当前版本已支持的接入场景。
- API Key 密文、Token 哈希、防枚举、策略实时重校验、普通学生接口防泄露和回复 XSS 防护均有专项测试。本轮通过不构成全面安全认证。

## 性能采样

命令（apps/server 下）：node node_modules/tsx/dist/cli.mjs scripts/student-ai-bench.ts；退出码 0。
环境：Windows 11 / i5-12500H / 15.6GB / Node v24.19.0，内存数据库。
300 次答案保存：无 AI 时 p95=0.45ms，3 个 AI 出站挂起时 p95=0.39ms；未观察到 AI 在途导致保存阻塞。
120KB 题面+120KB 解析+10 条历史+2 份材料引用，装配载荷 496KB，50 次单次装配 p95=1.31ms。
60 个积压任务在瞬时假回信下 145ms 排空，仅用于观察服务端调度量级，不代表真实模型吞吐或生产数据库表现。
浏览器侧开关 AI 栏及保存延迟另由两浏览器性能 E2E 验证；性能用例是采样，不能代替长期压测。

## 结论

核心平台链路可行，自动化覆盖较充分；本轮未发现可确认的核心业务阻断缺陷。串行 Chromium/WebKit 26/26 全过，专项两轮均过、类型检查和构建通过。但测试并行隔离、界面文案、lint 与文档状态仍有明确问题，真实模型、第三方客户端及真机验收尚未闭环，不能称为“已完善、真实接入已验收”。

建议先修复文案与质量闸门、隔离 E2E 全局假服务，再在隔离部署完成真实供应商与客户端、iPad 真机验收。当前账号的实际使用应先让外部 MCP 客户端成功领取并写回已有测试任务；如希望网页内直接回复，需另行配置页内 AI 接口。
