## 1. 产品背景与真实需求

**产品**:simple-tutor-tool v2——一对一辅导老师的**自部署** AI 原生讲练工具。pnpm monorepo:前端 React 19 + Vite + Tailwind v4 + shadcn/ui;服务端 Hono + better-sqlite3;`packages/contract`(Zod 契约,前后端单一事实来源);内容用自研 Markdown+DSL 管线(题干含 `$...$` LaTeX,经 KaTeX 渲染)。

**用户**:老师(桌面浏览器)、学生(**iPad Safari + Apple Pencil 为主力**,少量安卓平板)。自部署小服务器(单教师~数十学生量级),无 CDN、无云依赖。

**真实需求**(用户原话整理,编号 R1–R6):

- **R1 草稿演算**:每道题(主要是数学的选择/填空题)可展开一块手写区打草稿;笔迹持久保存;回看做题记录(复盘)时能看到当时的演算过程,"看到自己哪里做错了、哪里做对了"。
- **R2 布局**:开启草稿时"题目在左边、笔记在右边"(横屏 iPad);竖屏时在题目下方;书写区可自动扩展或拖拽调高。
- **R3 输入共存**:笔迹功能与手指触摸不冲突——笔写字、手指滚动页面、手掌搭屏不误触;与选择题选项点击不冲突。
- **R4 关联与导出**:草稿存储必须与题目强关联;能把「题干 + 学生作答 + 解析 + 草稿」发给 AI 评析——场景 A 学生/老师单题即时发给任意大模型;场景 B 老师把一整套错题导出给 AI 逐题分析;也能导出为图片(题目+草稿一张图)。
- **R5 定位**:草稿**不是孤立的便利功能,而是"喂 AI 的学习证据链"**——给 AI 更多信息帮助学生、帮老师了解学生。
- **R6 题干标画**(最新提出,优先级较低):学生直接在题干文字上划重点/圈注,复盘可见;不要求导出;按题/按人可选开启。

**非需求**:草稿判分、草稿回放、草稿进作答上传链路、整卷一张长草稿纸、学生端 AI 直连(另期)、讲义页面标画。

## 2. 现有系统关键事实(附代码摘录)

### 2.1 手写引擎(已有,生产验证)

自研适配层 `InkSurface`,两个引擎实现:atrament(页内答题区)+ Excalidraw(全屏作答,懒加载)。**新功能只做 atrament 页内形态的复用**。

```ts
// apps/web/src/features/ink/engine/surface.ts(节选)
export interface InkSurface {
  mount(el: HTMLElement, initial?: InkDoc): void;
  getDoc(): InkDoc;
  load(data: InkDoc): void;
  exportPng(): Promise<Blob>;   // 白底 PNG
  undo(): void; redo(): void; clear(): void;
  onChange(cb: (doc: InkDoc, reason: InkChangeReason) => void): () => void;
  destroy(): void;
}
export interface ToolAwareSurface extends InkSurface {
  setTool(tool: InkToolConfig): void;   // pen(黑/蓝/红×3档)|highlighter|eraser|scroll
  canUndo(): boolean; canRedo(): boolean;
}
```

```ts
// packages/contract/src/ink.ts(节选)——矢量文档格式
// InkStroke = { tool:"pen"|"highlighter", color, weight, points:{x,y,p(0-1压力),t(本笔内相对ms)}[] }
// InkDoc<"atrament"> = { engine:"atrament", version:1,
//                        data:{ width:1000, strokes:InkStroke[] },  // 坐标归一化:画布宽=1000,旋转/换设备无损重绘
//                        updatedAt }
export const INK_MAX_UPLOAD_BYTES = 2 * 1024 * 1024;  // gzip 后矢量+PNG 合计
```

iPad 输入层语义(atrament 适配器已实现,真机验证过):Pointer Events;`getCoalescedEvents()` 高频采样;`touchstart` 仅 `touchType==='stylus'` 才 preventDefault(**笔写字、手指照常原生滚动**);见过笔后进入 pen-only(手指永不落墨,防手掌);Apple Pencil 悬停预览圈;整笔橡皮;自动加高(最后一笔距底 72px → 高度 +240px);DPR 上限 2。`InkPad.tsx` 是 React 外壳:工具栏命令式转发引擎,UI 归 React。

### 2.2 作答笔迹存储先例(草稿直接镜像此模式)

```
-- apps/server/src/db/schema.ts: ink 表(既有,作答笔迹)
id uuid pk · attemptId · questionId
strokesPath  -- DATA_DIR/blobs/ink/<attemptId>/<安全名>.json.gz(先 .tmp 后 rename 原子替换)
pngPath      -- 同名 .png
width/height/strokeCount/updatedAt
UNIQUE(attemptId, questionId)  -- 同题再传幂等覆盖、id 稳定
```

上传:multipart `strokes`(gzip,`CompressionStream`)+ `snapshot`(png);服务端 content-length 预检(2MB+64KB 提前 413)+ 解压 32MB 上限(防 gzip 炸弹);路径穿越校验。前端状态机 `use-ink-upload.ts`:**停笔 2s 防抖 PUT + 每次上传现导 PNG + flush(引擎移交/退出全屏时)**。

### 2.3 防丢与同步现状(注意:作答草稿与笔迹的本地仓会被清)

`apps/web/src/features/attempt/draft-store.ts`:IndexedDB(idb-keyval)`tutor-drafts` 仓,`draft:<attemptId>` 一条记录含 `{answers, inks: Record<qid, InkDoc>, ...}`;300ms 防抖落盘;**交卷成功后 `clearDraft` 删除整条记录**(作答语义);另有 10s 增量同步服务端循环 + visibilitychange。

### 2.4 答题页结构

页面随 document 滚动(无内滚容器);多题 = `<ol>` 内一列题卡 `<article>`(圆角卡片,内含题号徽章/题干/选项/作答控件)。**单选/多选/判断的选项 = `<label>` 包 `<input type="radio|checkbox" class="sr-only">` + 富文本内容**;填空题空位是题干内联 `<input>`。题干渲染走统一 DSL 管线(`RichMarkdown`),可含交互指令(折叠 fold、ECharts 图等)。

### 2.5 回看与题目快照

交卷时每题冻结 `responses.questionSnapshotJson`(题干/答案/解析全文,题目后续编辑不影响历史);结果页手写作答回显 = PNG 直出 `<img>`(懒加载)。**questions 表主键是复合 `(teacherId, id)`,id 为内容声明的 text,跨教师可重号**——一切题目查询必须域内复合。行为数据(activeSec/changeCount/hintsUsed)只在教师端契约与 AI 数据包,学生端结果契约不含。

### 2.6 AI 导出设施(Phase 4 已建成,草稿要扩展它)

「LearningPack」模块化定向导出(教师用):五步向导(/t/export)选范围(学生/课程/作业/时间)→ 内容模块勾选 → 任务目标(决定 prompt.md 模板,**四个模板**:诊断薄弱点/备讲解建议/生成变式练习/阶段总结)→ 隐私(默认化名,映射文件不进 pack)→ 预览 → archiver zip(≤50MB)。内容模块含:题目三层(题干/参考答案/解析,取自快照)、逐题答案与判定评语、作答汇总、**手写过程 PNG(默认关)**、每题派生指标(用时/提示/改答)。同一打包服务被 MCP 工具 `get_student_learning_pack` 复用(AI 客户端直连)。已知实现事实:模块/模板为**逐字段硬编码风格**(非注册表),MCP 侧白名单/默认集/goal 枚举在 `mcp/server.ts` 手写——扩展需同步改多处。

## 3. 硬性约束与目标环境事实(方案必须在这些红线内)

**工程红线**(节选自 AGENTS.md):

1. 契约优先:数据结构先改 packages/contract 的 Zod schema 再实现,禁止前后端各写一份类型;
2. TS strict,禁 any/@ts-ignore;
3. 学生端 API 永不返回未公布题目的答案/详解/提示,新接口必须加泄露测试(assertNoLeak);
4. 不新增技术栈清单外依赖(新增须 PR 说明理由与替代方案——本方案唯一预定新依赖 html-to-image 已附论证);
5. 不用 CDN,前端资源全随构建打包;
6. UI 文案中文;DB 变更只走 drizzle-kit 迁移;
7. 自部署资源约束:不做服务端无头浏览器(Puppeteer)类方案。

**目标环境事实**(已调研核实,2026-10):

- iPad Safari **不支持 `pointerrawupdate`**(截至 Safari 27/TP),也**不支持 Ink API(DelegatedInkTrailPresenter)与 canvas `desynchronized`**(均 Chromium-only)。Safari 18.2+ 支持 `getCoalescedEvents()`/`getPredictedEvents()` 与笔倾斜角。即:iPad 上低延迟手段 = 合并采样全采样 + 预测段 + 湿干双层画布,已全部在引擎内;
- 笔尖触屏期间 iPadOS 整体抑制手指事件(tldraw 团队实测结论)——手掌防误触有 OS 层兜底;
- iOS Safari canvas 总像素上限 ~16.7M;剪贴板 ClipboardItem 图片支持可用。

## 4. 方案演进史(为什么长这样——欢迎挑战这条线)

1. **v1 覆盖层方案(被否)**:笔迹直接叠在整张题卡上。否决理由:①指针与选项冲突(需事件放行改造);②题干重排导致笔迹错位(文字重排非线性,y 仿射缩放修不回);③z-index/overflow 裁切。→ 用户转向:
2. **v2 独立草稿区(用户拍板)**:草稿是独立 DOM 块(右侧/下方),三个难题同时消失,复用 InkPad;
3. **v3 AI 评析定位(用户补充)**:草稿的价值是喂 AI——导出从"图片"升级为"评析包"(文本为主+笔迹为图),并扩展现有 LearningPack 而非另建管线;
4. **v4 布局偏好(用户补充)**:右侧/下方/自动三态,注册表+设备级 localStorage 偏好,配置与代码分离;
5. **待定:题干标画提案(附录 B)**——v1 的复活尝试,范围缩到题干块+快照兜底。

## 6. 已识别风险与红线(我们已知的坑,评审时可补充)

1. IDB 必须独立仓(交卷 clearDraft 会清作答草稿仓);key 含 studentId 防共用设备串写;
2. `responses.inkId` 是从未写入的死列,不得复用语义;
3. 2MB 口径照抄 ink-service(content-length 预检+解压上限),勿另写一套;
4. 学生端评析组合三段门控(答案/判定/解析):服务端未公布已置 null,前端**字段缺省即整段不渲染**,不得从其他途径拼出;
5. 结果页题卡已有 `overflow-hidden`:草稿块走正常文档流;
6. LearningPack/MCP 扩展是逐字段硬编码多处修改(非注册表),漏改即不一致;
7. html-to-image:iPad Safari 的 foreignObject/字体内联/canvas 内联需真机验证(兜底已备);
8. 布局常量 1024 单点定义;
9. 引擎将来升级(perfect-freehand 等)与本功能正交(InkSurface 隔离)。

## 9. 附录 B:题干标画提案(未定稿,重点征集意见)

**需求**(R6):学生用笔直接在题干上划重点/圈注;复盘时能看到;不要求导出;按题可选开启;用户原始直觉是"标了之后锁定题目布局,保证笔迹不漂"。

**对齐难题的诚实分析**:

| 变化源 | 锁得住吗 |
| --- | --- |
| 草稿布局切换 side↔below(改题干列宽) | ✅ 按题锁定即可 |
| 草稿区加高/拖把手 | ✅ 两种布局下都不影响题干重排 |
| iPad 横竖屏旋转(auto 布局随旋转翻转) | ❌ 锁不住 |
| 跨设备/复盘(字体度量差异) | ❌ 锁不住 |
| 题干内 fold 指令展开状态 | ❌ 锁不住 |

根本原因:文字重排非线性——宽度变化后断行整体重排,y 仿射缩放只能近似。**锁 UI 管不住环境变量,所以锁是必要不充分条件。**

**提案(实时层 + 冻结快照兜底)**:

1. **书写时(实时层)**:题干块上叠覆盖层画矢量(归一化宽 1000);一旦该题有标注,布局按题锁定(lockedLayout 存入笔记文档);指针放行题干内交互元素(填空 `<input>`、fold/graph 指令,`closest('input, [contenteditable], [data-note-passthrough], …')` 命中即不落墨);
2. **上传时(保真层)**:防抖上传时顺手用 html-to-image 把「题干 DOM+标注层」一次成像存快照 PNG(复用 T6.9 能力;表加一列 stemPngPath;noteDoc 加可选 `stem: { ink, lockedLayout, widthPx, heightPx }`);
3. **呈现规则(一条)**:**当前环境与锁定布局匹配 → 渲染实时层(可继续编辑);不匹配(旋转过/换了设备/教师端)→ 显示冻结快照图**。复盘看到的永远是"当时划在哪",横竖屏、跨设备不漂;
4. 开关:草稿工具条的「标注/草稿」层切换(荧光笔为标画主力);教师级开关后议;排期依赖 T6.9,拟列 T6.11(P2 末,择机)。

**被否的更轻替代**:点"标注"先把题干冻成图片、在图上画(零对齐零穿透问题)——但体验像截图标注工具,不像在题目上划重点;既然快照层已兜住对齐风险,不再值得。

**请评审者重点回答**:提案的可靠性、匹配判定规则(什么算"环境匹配")的严谨化、以及有没有我们没有想到的第三条路(例如题干标画的 DOM 锚定方案、或直接用文本选择+高亮的混合模式)。
