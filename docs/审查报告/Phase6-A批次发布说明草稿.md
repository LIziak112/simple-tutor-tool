## 本批交付（可声明）

- **题目草稿（草稿纸）**：非手写题题卡内置草稿纸，笔迹本机持久化 + 服务端增量同步
  （CAS 并发保护、冲突给用户裁决、断网补传）；纸高自动加高、手指书写切换、布局自适应。
- **交卷冻结原稿**：交卷确认时追平最终矢量并固定版本引用；此后重练、改卷、清空都不
  改本次原稿；缺稿交卷必须用户明确确认。
- **双角色原稿查看**：学生结果页与教师详情页同视角只读查看本次原稿（轮次标注），
  缺图可一键重建分析图；教师连看不堆积画布。
- **单题完整导出（AI 复习包）**：学生结果页 / 教师详情页逐题下载 zip（复习提示 +
  pack.json + 题目投影 + 原稿分析图）；学生包剥除答案、解析与定位 id；教师域包照常
  携带参考答案；材料不完整时明确标注缺失，不声称完整。
- **学习闭环基础设施**：草稿头整卷批量拉取（一次请求）、错题本/重练与原稿联动、
  题目版本快照一一配对（v2 证据装配）、备份恢复可完整还原原稿证据链。

## 回滚与备份步骤（发布/回滚操作手册）

1. **发布前备份**：教师端「设置 → 备份与恢复 → 下载完整备份」得全量 zip（db 快照 +
   blobs/ + shared/ + secret.key）；建议同时停服拷贝整个 `data/` 目录一份。
2. **升级**：按既有部署流程替换构建产物后重启服务（Docker：新镜像 up -d；systemd：
   替换产物 + restart）。迁移随启动自动执行（幂等，0021–0025 已验证可从旧库重放）。
3. **验证**：`GET /api/health` 200；登录教师；学生端开一卷写草稿→交卷→查看原稿。
4. **回滚**：`docker compose stop app`（或 systemctl stop）→ 用第 1 步备份覆盖
   `data/`（保持属主 1000:1000）→ 启动。或应用内「从备份恢复」上传第 1 步 zip +
   登录密码（恢复前自动再拍一次快照作回滚保险；恢复后需重新登录）。
5. **回滚后注意**：回滚会把数据库与 blobs 一起回到备份时点——备份之后新产生的
   草稿/作答会消失（属备份语义，非缺陷）；如需保留，先做一次当下备份再回滚。
