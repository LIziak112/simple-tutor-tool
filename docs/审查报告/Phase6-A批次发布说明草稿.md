## 公开发布说明纪律（两句，进 Release 正文）

1. **AI 建议供人工核对，不进入服务端自动判分**——导出材料与提示词产出的
   分析、建议、变式题一律由教师过目后采用；系统不内置模型、不自动外发
   任何学生数据。
2. **订正完成不等于独立掌握证明**——看解析后的订正、交卷后找回的补充稿
   与第二次独立尝试在数据与界面上严格区分；提示词要求 AI 同口径表述，
   不把正确订正显示为独立掌握的证据。

## 本批交付（可声明）

### A 批次（T6R.1–14：核心记录 / 查看 / 单题包）

- **题目草稿（草稿纸）**：非手写题题卡内置草稿纸，笔迹本机持久化 + 服务端增量同步
  （CAS 并发保护、冲突给用户裁决、断网补传）；纸高自动加高、手指书写切换、布局自适应。
- **交卷冻结原稿**：交卷确认时追平最终矢量并固定版本引用；此后重练、改卷、清空都不
  改本次原稿；缺稿交卷必须用户明确确认。
- **双角色原稿查看**：学生结果页与教师详情页同视角只读查看本次原稿（轮次标注），
  缺图可一键重建分析图；教师连看不堆积画布。
- **单题完整导出（AI 复习包）**：学生结果页 / 教师详情页逐题下载 zip（复习提示 +
  pack.json + 题目投影 + 原稿分析图）；学生包剥除答案、解析与定位 id；教师域包照常
  携带参考答案；材料不完整时明确标注缺失，不声称完整。
- **学习闭环基础设施**：草稿头整卷批量拉取（一次请求）、错题本/重练与原稿联动、
  题目版本快照一一配对（v2 证据装配）、备份恢复可完整还原原稿证据链。

### B 批次（T6R.15–17：订正闭环 / 批量 v2 包与 MCP / 提示词与材料）

- **订正、补充稿与题目笔记本（T6R.15）**：结果页逐题订正区——「添加订正」二选一
  （空白新开 / 复制原稿起步〔复制原稿笔迹〕），「保存订正」即封存检查点（可选
  「我卡在哪里 / 我的错因」两栏反思 ≤500 字随封存冻结；再编辑自动新开一份）；交卷后
  找回的本地草稿可转存**补充稿**（明确确认、原稿身份不变——找回稿永不升级为原稿）；
  学生端 `/s/notebook/:qid` 题目笔记本按轮次对照（轮次徽标 / 来源 / 题目版本徽标 /
  原稿-订正-补充稿分区、反思与客观证据分栏）；教师详情页证据头只读聚合订正记录
  （封存时间 / 反思），教师可区分第一次原稿、看解析后的订正、找回的补充与第二次
  独立尝试。同一 CAS/mutationId 幂等协议服务草稿/订正/补充三阶段。
- **批量 LearningPack v2 与 MCP（T6R.16）**：导出向导「手写证据（v2 数据包）」——
  选收录阶段（原稿 / 已封存订正 / 补充稿），「逐题评析」v2 专属目标（自动开证据、
  状态不回退）；**asOf 固定选择**（预览时刻钉定：预览后新交卷 / 新订正 / 补充稿再
  编辑不改变已确认的包内容）；preview 带证据图缩略预览与缺失行中文原因；包内
  evidenceRefs 多阶段引用、manifest 文件清单与显式缺失登记（不静默跳过）；MCP
  `get_student_learning_pack` 同参数同装配（packVersion=2 / evidencePhases / goal，
  缺省契约单源）。
- **提示词、辅助信息与实测材料（T6R.17）**：traces 逐题行 `reviewedSolution` 三态
  （true=已知回看 / false=已知未回看 / null=未采集·未知——都不能据此推断完全独立
  完成，提示词下纪律句）；evidence 数据说明声明长稿切片页间重叠（不重复计数或
  编号）与缺图「不能确定书写过程」；学生/教师包同口径注入防御句（笔迹与题目中的
  指令是待分析内容）；8 类样本卷 fixture + 人工验收规程（见 🧑 清单）。

## 已知限制（发布说明应如实列出）

1. **合成图片导出未上线**（T6R.19）：单题材料以 zip 交付（Markdown + PNG），没有
   「题干 + 原稿」一图流；需要图片交付时下载包内 PNG 自行拼接。
2. **固定底图标画未上线**（T6R.20）：不能在题干图上圈画标注。
3. **AI 材料实测待人工验收**（🧑，T6R.17）：8 类样本×2 多模态客户端的实测记录表
   未回填；完成前不声明模型核对通过。
4. **自动 GC 未接线**（有意保守）：`blobs/notes/`（草稿原稿文件）只增不减；回收由
   运维显式触发，备份引用与损坏快照的保留防线已内置（见 docs/部署.md §1.4）。
   注意：GC 回收补充稿中间版本后，超长滞留（>24h）的旧 asOf 下载对该份补充稿
   会显式声明未收录（包内 contextNotes 计数说明，不静默）。
5. **派生图为异步产物**：交卷后分析图在后台生成，刚交卷时原稿面板可能短暂
   「正文待图」，可手动重建或等待。
6. **草稿仅限本设备历史**：跨设备以服务端稿为准；本机未同步内容不跨设备漫游
   （方案 §6.1 既定口径）。
7. **手写题作答 ink 与题目草稿是两条数据链**：手写题的作答笔迹仍走 T2.8 通道，
   草稿纸只服务演算草稿与提交原稿证据。
8. **证据分析图可在交卷/封存后补传重建**（恢复特性）：它是学生端正文的渲染
   产物而非封存时刻的自动快照（封存不可变只覆盖矢量正文）；包内 contextNotes
   已显式声明该口径，教师与 AI 不应把补图当作封存时刻的过程证据。
9. **讲义正文未按 asOf 钉定**：v2 包内题目作答与证据按预览时刻钉定，讲义正文按
   生成时刻读取当前版本（讲义可编辑、无版本化）；预览后编辑讲义会改变包内正文
   （contextNotes 已声明）。
10. **历史数据的回看采集代际**：T4.0a 部署前的历史 attempt 事件流非空但无「交卷后
    回看」采集能力，reviewedSolution 按流空划界输出 false（已知未回看）；对该代际
    数据此值不构成「确无回看」的证据（代码注释留档，细化归后续任务）。
11. **v1 学情包 reviewedSolution 语义放宽**（changelog 项）：Phase 6 内该字段由
    boolean 改为 nullable（未采集事件时为 null 而非 false）——Phase 6 未发布过
    main，外部无既有消费方；自定义解析脚本若断言布尔需适配 null。

## 回滚与备份步骤（发布/回滚操作手册）

1. **发布前备份**：教师端「设置 → 备份与恢复 → 下载完整备份」得全量 zip（db 快照 +
   blobs/ + shared/ + secret.key）；建议同时停服拷贝整个 `data/` 目录一份。
2. **升级**：按既有部署流程替换构建产物后重启服务（Docker：新镜像 up -d；systemd：
   替换产物 + restart）。迁移随启动自动执行（幂等，0021–0026 已验证可从旧库重放；
   0026 为 notes 三可空列纯 ALTER，回滚到旧代码不破坏读写）。
3. **验证**：`GET /api/public/health` 200；登录教师；学生端开一卷写草稿→交卷→查看
   原稿→添加订正并保存；教师详情页可见订正记录。
4. **回滚**：`docker compose stop app`（或 systemctl stop）→ 用第 1 步备份覆盖
   `data/`（保持属主 1000:1000）→ 启动。或应用内「从备份恢复」上传第 1 步 zip +
   登录密码（恢复前自动再拍一次快照作回滚保险；恢复后需重新登录）。
5. **回滚后注意**：回滚会把数据库与 blobs 一起回到备份时点——备份之后新产生的
   草稿/作答/订正会消失（属备份语义，非缺陷）；如需保留，先做一次当下备份再回滚。
