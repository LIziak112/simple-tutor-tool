## 二、实现要点

- **真实调用点核实后实施**：填空 Provider 在题卡外层（AttemptQuestionCard 包住 RichMarkdown），遥测 Provider 在 RichMarkdown 内层——与清单警示一致，未按「都在 RichMarkdown 内」实施。
- **单一 Context**：`directives/session-context.tsx` 新建 `DirectiveSessionContext`，fill（原 BlankAnswersContext）/telemetry（原 DirectiveTelemetryContext）为两个子命名空间；无 Provider 缺省 `{fill: null, telemetry: null}`（模块级常量）——填空显示下划线空框、遥测调用方空值保护即静默 no-op，折叠/逐步揭晓照常可操作。
- **嵌套语义**：`DirectiveSessionProvider` 用 `useContext` 读外层，`fill !== undefined ? fill : outer.fill`（telemetry 同理）——继承外层、仅覆盖显式提供的字段；**显式传 null 视为覆盖**，保持 RichMarkdown 内层对遥测的既有遮蔽语义。生产嵌套（题卡 fill 外层 → RichMarkdown telemetry 内层）由组合测试直接复现。
- **兼容适配（旧导入路径保留）**：`BlankAnswersContext.tsx` 成为适配层（`BlankAnswersState` 别名 re-export + Provider 委托 `fill=state`）；`expand-context.ts` 成为 shim（类型与 `useDirectiveTelemetry` 自 session-context re-export，`useDirectiveExpand` T2.10 别名保留）。**零改动文件即兼容承诺实证**：AttemptQuestionCard、Steps、StudentLectureViewPage、telemetry.test.tsx 全部原样通过。
- **裸 Context 导出移除**（`blankAnswersContext`、`DirectiveTelemetryContext`）：两者唯一消费方（Inline.tsx / RichMarkdown.tsx）已迁新 hook/Provider；清单明文「不能把值形状不同的 Context 直接 re-export 为同一个对象」，移除后外部误用会在编译期暴露而非静默错形。全仓 grep 确认无残留引用（.claude/worktrees 历史副本除外，不参与构建）。
- **不预造红线遵守**：未新增 reportEvidence、提示请求、步骤答案、手写上传接口；事件字段 `{name, index, action, step?}` 原样；判分/投影/学生端载荷零改动。
- **shim 同源锁定**：测试探针经旧导入路径取 `useDirectiveTelemetry` 与 canonical 导入比对同一引用（`===` 断言），证明 re-export 不是平行副本。
