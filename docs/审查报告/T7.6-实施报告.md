## 实现要点

- **契约（capability.ts）**：`capabilitiesManifestSchema`（strict：formatVersion=1、directives min 1、questionTypes **复用穷尽 Record schema**）；条目 `directiveCapabilityEntrySchema`（name/kind/attrs/capability——capability 可 null=未声明，方案 §4.4 全量收录）；`capabilityAttrSchema`（与规范.md 属性表同列：type/required/default?/description，default 为原始值）。`directiveKindSchema` 自 directives.ts 迁入（清单条目需要 kind 而 directives.ts 已依赖 capability.ts，避免反向依赖），directives.ts re-export 旧路径不变。
- **生成（md-dsl）**：`attrRowData` 数据层抽出——规范.md 表格与 capabilities.json **共用同一 zod 内省**（两处不漂移）；`renderCapabilitiesManifest` 全量指令（capability ?? null）+ 契约题型表嵌入，2 空格 JSON + 尾换行（content.json 先例）。gen-spec.ts 并入统一 outputs 循环（docs/dsl/schema/capabilities.json）+ kitCopies（dsl-kit/capabilities.json，清单口径 kit 根路径）。
- **分发（server）**：契约 specFileNames 五文件；spec-files.ts 物理映射（mtime 缓存复用，缺文件沿用 SPEC_UNAVAILABLE）；copy-spec.mjs 完整性守卫；**MCP 第 14 工具 `describe_capabilities`**（readOnly，复用 readSpecFile 原文返回——与 HTTP 同一数据源与缓存，逐字节一致有测试锁定）。工具 description 与规范.md §七均写明 snapshot=既有采集形式、partial 仅词表保留未实现。
- **只读边界**：生成侧只 import @tutor/contract（注册表 + 题型表），不导入服务端 grading 函数；清单内容为公开规范件元数据，无答案数据。
