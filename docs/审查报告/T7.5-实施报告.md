## 实现要点

- **packages/grading/src/validator-registry.ts（新建）**：`GradeValidator = (question: Question, answer?: StudentAnswer) => boolean | null`（清单口径：接受 Question 与可缺省 StudentAnswer，现有契约类型）；机制 `registerValidator`（重复 validatorId 抛错）/`getValidator`/`listValidatorIds`；`assertValidatorCoverage` 完备性检查（契约题型表引用的 validatorId 缺实现即 throw，属开发错误）。
- **七个内置校验器自 grade.ts 整体迁入，判分算法一行未动**；三手写题型共享 `gradeHandwritten`（不复制算法）；原 grade 的 `unansweredCorrect` 未作答分派吸收进各校验器（judge/choice/multi 未作答 → false〔D1〕、fill/手写 → null），grade 不再单独分派。内置登记在模块加载期完成（与 contract/directives.ts 注册表同款模式），函数与登记同文件自包含，避免 grade↔registry 循环导入。
- **grade.ts 重写为三行路由**：①题目无标准答案（answers 缺省）→ null，优先级最高保持不变；②题型表 `validation.shape !== "exact"`（rubric/unverifiable）→ null 恒人工（fill = rubric，与 2026-10-02「fill 全人工」决策等价）；③按 validatorId 查注册表执行既有校验器，查不到兜底 null——正常路径无异常，兜底语义 = 落教师待批，不换判分。
- **apps/server/src/index.ts**：installCrashHandlers 之后调 `assertValidatorCoverage()`——注册遗漏即启动失败（实测 Node ESM 顶层抛错确实路由到 uncaughtException → stderr 横幅 + exit 1）。测试不导入 index.ts，grading 测试期承担同一检查。
- **不做**（清单边界）：reason 载荷、部分得分、自动步骤判分、题目级策略、学生校验 API。

## 范围决策（可推翻）

- fill 校验器照常登记（清单明文七内置登记项）但经 grade 不可达（rubric 先行短路 null）——两路同 null；其「死桩」层级权衡与根治方向（契约侧 discriminated union：exact 才必填 validatorId）已落 [题型表validatorId无条件必填与死桩登记待办](../待处理的问题/题型表validatorId无条件必填与死桩登记待办.md)。
- 内置登记用字面 validatorId（非 bindings 取值）：可 grep、可读；与契约漂移由测试集合相等断言拦截。
- 机制 API（registerValidator 等）不进包桶导出（防应用代码运行时篡改注册表的面），测试直连文件路径导入；桶仅增 `assertValidatorCoverage`。
