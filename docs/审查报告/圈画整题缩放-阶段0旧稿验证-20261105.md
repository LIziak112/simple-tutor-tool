1. 已实际复现：实测填空稿的规范化字体一致，两端都是 26 个文本行框，四边最大偏差为 **2 个逻辑 CSS px**；生产 `compatibleSurfaceEvidence` 返回 `false`。按批准标准期望 `true` 的定向测试真实退出 **1**，不是静态推断。永久夹具只含原始测量几何和字体，不含作答值、笔迹、账号或业务身份。

### v1 和缺证据旧稿具体缺什么

v1 `base-image.ts` 输出是固定 720 CSS px、像素比 2、四边 36px padding 的静态导出页，前面还有题号标题、红线说明、生成时间、边框和间距。它不是 v2 的题卡 DOM。仅有 1440px 宽和总高，不能确定正文起点、段落/选项位置、字体回退、旧静态 DSL 输出及控件映射。

要恢复为真实题面，至少需要：冻结公开题面及版本归属、对应的旧静态模板与资源版本、原页面字号/行高/边距/页眉几何、可对照的正文区域证据，以及正文与旧笔迹像素域的精确映射。生成时间文本及历史字体会影响页眉与正文位置，不能自行补一个当前时间再声称一致。现有代码和本次证据未提供通用的历史 DOM 区域恢复器；因此 **v1 真实题面恢复仍未解决**。保留资产用于校对/导出不是 PNG 主视图兜底，不能把它写成正常同框兼容已完成。

缺 compatibility 的 v2 可在源设备、对应旧样式和同公开题面下重新测量，原内容/块几何/字体候选签名都命中后，才使用 `verifiedLegacySurfaceCompatibility` 返回的真实证据。服务端允许补充证据一次，原核心布局身份不变；被动显示不得借机补写。目标设备若无法命中且源证据不可得，需保稿并明确提示先在原设备核验；不能仅调大阈值。该函数在当前基线只有定义，没有生产调用，下一阶段需明确接线。

## 已确认的两层阻断根因

### 图片恢复与真实几何是不同门禁

`frozen-surface-resolver.ts` 先核对 schema、PNG 类型/大小、底图绑定和文档像素域，再对 URL/Blob 引用、解码完成与尺寸做检查。`canReadInk` 仅在状态 ready 时成立，`canWrite` 还受只读/封存限制。这里没有当前真实 DOM，也没有当前题/账号参数；不能靠移除最后一段解码检查就获得完整兼容与身份校验。

`QuestionAnnotationOverlay.tsx` 消费上述 source，创建 Blob URL 或用云端下载地址，保存图片解码状态，并由 ready 决定墨层可见。`prepareQuestionAnnotationBase` 对云端 ready 也会先下载 PNG 再落本机。网络/解码故障由此能阻止已保存的真实题面同框恢复，和排版是否超过 10px 无关。

### 原兼容函数存在独立的严格条件

`annotation-layout-compatibility.ts` 对每个块和每个 Range 文本片段的 x/y/width/height 分量按 0.75px 比较，要求片段数量相同、块 tag 顺序相同及字体规范化数组完全相同。它没有按 left/top/right/bottom 最大偏差判定，也没有使用区域身份完成语义匹配。实际字体相同的 2px 夹具因此失败。

`questionSurfaceMatchesLayout` 还会先拒绝逻辑宽高差 >1px；无 compatibility 时要求旧内容签名、去 node 的块几何签名和某个字体候选签名精确命中。旧哈希不能提供差值，也不能倒推出历史坐标。当前该函数的生产调用只在新稿预备接管处，不能据其存在声称当前 PNG 恢复流程已核验真实 DOM。
