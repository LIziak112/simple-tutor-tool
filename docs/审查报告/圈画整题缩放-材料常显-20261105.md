## 根因与修改

`MaterialAnnotationOverlay` 原先仅在圈画或 reviewMode 时应用固定宽框；普通阅读态恢复自然回流，并按旧 ±1px 匹配结果隐藏墨层。列宽旋钮改变了正文排版，导致必须另点「按圈画时排版查看」。

现改为只要存在 `materialInkBase`，同一个真实阅读框就在阅读和圈画期间保持保存的 `cssWidth`。分栏缩窄仅改变父框占位与整体 transform 比例；正文、输入层和绘制宿主继续常驻，既有笔迹不随退出圈画隐藏。非圈画态输入层 `pointer-events:none`；阅读链接、图片和正文仍可交互。保留必要的「放大材料 / 适应宽度」，删除 reviewMode、两种排版查看按钮和自动退出回看效应。

材料继续按 `INK_LOGICAL_WIDTH=1000` 归一化，不转换到题卡像素域；基准仍是首笔落笔时的 CSS 宽高。首笔前资源就绪、首笔收笔捕获、空稿清基准、跨版本 inkKey、稿件身份、session epoch、账号隔离、PWA 本机落盘保护和引擎工具链保持原管线。

固定框 ResizeObserver 使用未缩放 `contentRect` 同时核验宽高；最大尺寸差异 ≤10px 放行，10.001px 阻断新增输入并给出具体原因，原稿与原基准保留。实际资源尺寸变化先按既有状态机提交在途真实采样，后续 move 不再归入该笔，不自动重冻；恢复到允许尺寸后沿既有规则恢复输入。

旧稿有笔迹但完全缺少基准时，旧实现会以当前排版自动收养，无法证明历史位置。现在明确提示缺少原排版基准，保留原稿、不叠显到未经核验的正文、不允许续画，不凭当前尺寸补造历史基准。正常无笔迹新材料的首笔捕获不受影响。

## 限制、后续 API 与手工验收

1. 材料仍只有本机 `materialInks/materialInkBases`，没有材料服务端 reader/writer 或新增 API，不暗示已经跨设备同步。后续接入 API 时须保留 attempt + 冻结 sourceVersion、账号、CAS/保稿等独立身份；本单没有实现或设计新同步协议。
2. 旧材料基准仅有 CSS 宽高，不能证明内部逐字、字体或同尺寸内容未变化；早期缺 `cssHeight` 的稿更无法核验历史高度。这一证据缺口没有被放宽 10px 修复，也没有自动补写历史证据。完全无基准旧稿明确保稿停写。
3. 单测使用 DOM/ResizeObserver 与绘制 mock 验证结构和回放输入，不等于真实 Safari 字形位置、长材料性能或 Pencil 手感已验收。未运行 E2E、真机、全量测试或构建；按本单授权只做定向验证，最终专题文档与生产 API/真机矩阵由父流程收口。
4. 后续手工步骤：以现有真实学生作答 API 加载带共享材料的冻结卷，在同设备首笔建立基准；退出圈画后拖分栏、旋转、缩到窄列并点材料内链接/图片，确认正文只缩放且笔迹常显；放大 1:1 再适应宽度，确认原控件和滚动仍可用；用测试材料晚到图片造成 >10px 高度变化，确认已收笔并提示停写、原稿未重冻；离线重开及交卷结果页检查本机材料回看。同材料双 sourceVersion 应分别验证，不能搬 JSON 冒充跨设备同步。
