2. **Important：双定位重放接受不一致的题号。** 首轮 `student-mcp-submit.ts:93` 仅在首写回调校验 `questionNo`，原摘要不包含这个冗余定位字段。触发：q1/no1 成功后，同输入只把 no 改成 2；显式同键或省键均可命中原提交。实际影响：返回成功确认与本次定位不一致。最终 `student-mcp-submit.ts:121` 在 v2 事实回执前也核对冻结序号；原探针现返回 `QUESTION_LOCATOR_MISMATCH`。**已修复。**
3. **Important：首轮事件来源参数落在错误函数。** 首轮 `event-service.ts` 的 `recordQuestionSubmitEvent` 引用未定义 `origin`，参数误加在 `recordConfirmedSubmit`。触发：有效单题提交记事件。实际影响：运行失败并导致事务回滚/类型错误。最终 `event-service.ts:227` 正确声明第六参数，默认 web，MCP 传入服务端连接来源；已读修正补丁并以真实提交探针验证。**已修复。**

## 阶段结论与关键核对

- **简化：通过。** 普通提交与 lesson 提交按实际职责拆开；旧路径保留兼容导出。摘要函数正文与 HEAD 原实现逐字相同，仅增加导出和移动文件。MCP 不再无谓生成含答案的旧反馈结果。没有新增依赖、复制判分算法或第二套冻结排序。
- **正确性：通过。** 旧请求仍必须带显式键且成功只返回 `{success:true}`；显式 v2 才允许省键/题号，版本与证据仍必填，顶层未知字段仍拒绝。HTTP 仍使用原 strict 请求契约和反馈 wrapper，没有开放 MCP 新参数。
- 重放裁决位于当前 AI 首写回调之前；回调运行于原 `immediate` 写事务，随后仍执行原工作流、题目版本、答案版本和证据 CAS。服务端注入来源；客户端来源字段不被新输入契约接受。
- UUID 从原规范摘要派生，不读取最新草稿或证据头，不包含响应版本/设备。显式键不同内容仍比对完整摘要，发生派生 UUID 碰撞也会由完整摘要冲突裁决阻止覆盖；不同归属的 attempt/题目仍由原定位和鉴权隔离。
- v2 提交后重读真实行，末题 `settlementSeq` 取实际 final 归属，不使用提交前 RETURNING 行猜测；重放读取当前进度，允许后来整卷完成使早先提交行的 seq/进度更新。
- **学生出口安全：通过。** 成功回执逐字段构造并由 strict schema 校验，只含题目身份、提交时间、键、结算序号、进度与下一未提交题。没有展开反馈对象，没有答案/解析/判定/教师私注/邻题作答。本人、作废、课程可见门沿原提交前导保留；题号定位同时绑定本人 attempt 与冻结行引用，首写继续校验整个冻结成员集合。

旧行为的准确边界：旧格式 MCP 的首次提交现在会受当前 AI 门限制，这是计划明确增加的安全收紧，并非“旧行为全部原样”。内存专项探针证实 AI 禁用时旧 MCP 首写 `AI_POLICY_DISABLED` 且零写入；相同条件下 HTTP 原提交仍成功；随后相同旧请求重放仍仅得到成功壳。
