## 行为与范围

Windows x64 单文件 exe、独立 Node 脚本、远程 `check_ai_reply` 与提交校验共用核心。领取任务先给规范、清单入口和本地检查步骤；确定格式错误阻止新的 MCP 回信写入并保留租约。旧成功回执幂等、迟到事实、超长截断语义保留。历史及页内回复在显示时隔离坏公式和可疑中文边界，保留原文与安全预算；AI 参考答案复用单源格式化。

本次夹具依据 issue 已披露的回信片段脱敏构造，未读取生产学生数据或完整生产回信。检查只验证格式/可渲染性，不审核数学结论。无数据库迁移，无新增模型调用；KaTeX 是项目既有依赖，补到共享包显式声明。

## 手动验收

1. 从领取任务得到的 manifestUrl 取清单，按 SHA-256 验证 Windows x64 exe，运行 `ownclass-ai-check.exe reply.md --json`。
2. 使用缺起始美元符号的公式，确认本地/远程检查指出位置；修正后重查，提交相同正文。
3. 直接提交坏命令公式，确认返回诊断且任务仍 claimed；同租约修正提交成功。
4. 打开包含 issue 片段的旧回信，确认中文不成为伪公式、后续合法公式仍渲染；原文可分页查看。覆盖题下、侧边和弹窗。
5. 下载和部署时保持同一提交的 exe、cjs、manifest 与指纹配套；检查服务器最终清单包含 win32-x64。

未覆盖：真实第三方 AI 客户端是否自觉执行本地检查、生产完整回信重放、其他平台原生二进制。首版提供 Windows x64 exe，其余环境使用 Node 脚本或远程检查。
