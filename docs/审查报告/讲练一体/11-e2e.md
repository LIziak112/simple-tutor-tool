## fixture 与断言设计

- **五题六段**（choice 对路 + choice 错路 + judge + fill + judge 收尾题，六个 md 段交错）：
  任务要求的「完成练习（剩余未答题收尾）」需要留一题走整卷收尾路径——五题才能同时
  覆盖「四题单题提交（含 fill 即时进待批）」与「完成练习收尾剩余题」两条收尾路径
  （方案决策 5「两路殊途同归」的 e2e 层对照）。
- **唯一标记词**：8 个详解/提示标记词（对路题详解……填空题提示）+ 题块原文
  （`[[`、`- [x]`、`:::solution`、`:::hint`、`::::question`）做页面文本级防泄露断言
  （开卷未提交时 + 再做一次新卷时各跑一遍）；网络层沿用 helpers 的 attachLeakMonitor
  （键名级 + 交卷放行口径）双线把关。
- **DOM 序断言**：`[data-lesson-md]` 与 `[data-question-id]` 交替序列
  `md q md q md q md q md q md`——讲义段与题卡「按讲义顺序交错」的结构级证明，
  不依赖样式类。
- **复用既有 helper**：teacherApiLogin / createCourseViaApi / getStudentViaApi /
  addCourseMemberViaApi / attachLeakMonitor / expectResultCount / uniqueSuffix /
  TEACHER_LOGIN_NAME 等——零新造轮子；教师文档为自造 fixture（覆盖面大于完整样例：
  五题双 choice 对错路 + hint/solution 齐备）。

## 决策与偏差说明

1. **fixture 措辞规避 SECRET_EXCERPTS 碰撞（测试侧修正，非产品 bug）**：首版 md 段
   用了「只有符号不同的两个数互为相反数」——恰是 helpers 泄露监控硬编码的练习样例
   hint 片段，lesson/start 响应的 md 段（设计内全量下发的讲义正文）被误报「含教师侧
   原文」。改写为「符号相反、绝对值相同的两个数互为相反数」后双引擎转绿。教训：
   自造讲义正文须避开 helpers.ts 的 SECRET_EXCERPTS 六句。
2. **弹层按钮页面级定位**：Radix Dialog 默认 portal 到 body，「确认提交」「确认交卷」
   「开始新一轮」不能在题卡 locator 内取——全部页面级定位（一次试错发现，与 08 报告
   jsdom 弹层坑同族）。
3. **错题本分组标题 = 题目归属单元**：groupWrongQuestions「按练习」分组取
   originUnitTitle（题目归属的嵌入单元名），非讲义标题；卡片参考答案标签是
   「正确答案：」（与结果页/讲练题卡的「参考答案：」不同词表）。断言按实际口径修正。
4. **完成视图汇总行（批后）=「答对 3 · 答错 1 · 待批 0」**：契约
   attemptScoreSummary 的 correct/wrong 是**自动判定**计数（教师批对的 fill 不进
   correct），待批数走 pendingCount（finalCorrect 权威计数，批后归零）——教师判定
   反映在题卡 teacherMark 块（「老师批改：判对」+ 评语）而非汇总行。按契约口径断言；
   若编排者认为汇总行应计教师批对数，属独立产品变更（记录待裁决，未改产品代码）。
5. **结果页自动判分 75 = 3/4**：scoreAuto 分母排除不可自动判题（fill），与既有
   phase3 口径（1/2=50）一致；教师批后 scoreFinal=80 未单测（题卡判定已覆盖）。
6. **草稿恢复断言**：第 5 题判对草稿先 waitForRequest(PUT …/answers) 落服务端再
   reload（讲义页无 draft-status testid，请求级等待比轮询文案稳）；刷新后 radio
   toBeChecked + 三张已提交题卡徽章保持。
7. **进度断言**：每次单题提交后「已提交 n/5 题」逐级前进（0→4），收尾与新卷
   （0/5、第 2 次）全覆盖。
