## 第 4 步：数据库三列一索引（提交 8a8142d）

### schema.ts（只改 schema，迁移全经 drizzle-kit 生成）

- `lectures.kind: text("kind").$type<"lecture"|"lesson">().notNull().default("lecture")`——注释写明：导入按文档 frontmatter kind 写入（lesson 文档的讲义全部 lesson、其余 'lecture'；重导覆盖、编辑不改），lesson 讲义 markdown 原位保留题块、学生端经 splitLessonBlocks 安全投影。
- `attempts.lectureId: text("lecture_id")`（可空）——lesson 来源必填=讲练页讲义 id、其余来源恒 null；**无外键，参照 unitId 同款口径**（D10 后子表外键已拆、域一致性服务层保证），列注释明示。表头注释同步（删去「列由讲练一体后续任务加」的过渡语）。
- `responses.submittedAt: text("submitted_at")`（可空）——注释按计划口径：单题提交=该题提交时刻、整卷收尾对剩余行=交卷时刻、NULL=未提交；既有整卷作答链路（assignment/course/wrong）不写本列（对齐计划 :56「submittedAt 仅 lesson 单题提交会写」的待批谓词语义）。
- 索引 `attempts_student_lecture_idx(student_id, lecture_id)`——注释写明 start 幂等 create-or-return 与记录聚合走本索引，唯一性由服务层事务先查后插保证（attempts 表既有先例口径，不建 partial unique index）。
- schema 头注释追加讲练一体段（三列一索引一览）。

## 决策与偏差说明

1. **lesson 导出不带 `unit:` frontmatter**（按任务字面「只写 kind: lesson」）：再导入时单元名由 filename 兜底（UNIT_FROM_FALLBACK warning），题目因显式 id 稳定但**题库单元归属会随兜底单元变化**——这是既有重导语义（跨单元同 id 按更新、unitId 随之更新），测试内已注释说明，不在本单断言面。若后续要保单元归属，可在导出 frontmatter 补 unit 行（留给后续任务决策）。
2. **updateLecture 不从编辑后的题块刷新题库**：讲义编辑只存 markdown（原文是真相），题目内容改动走题库单题编辑/重导/reparse——与计划口径一致（讲练题块编辑属题库域），无静默同步。
3. 重导覆盖只按任务要求测 mixed→lesson 方向；反向（lesson→lecture 重导）由同一 `kind: lectureKind` update 写入路径覆盖，实现对称。
4. 首次全量跑曾出现 13 个与改动无关的偶发失败（seed-demo 等，Windows 并发负载）；已用基线（stash 后无改动全量跑 85 文件/1335 全绿）+ 最终树连续两次全量全绿排除关联。
