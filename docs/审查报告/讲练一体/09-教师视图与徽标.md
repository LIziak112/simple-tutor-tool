## 改动清单与决策理由

### 1. 契约与投影（930fb07，规则 1 契约先行）

- **四处 schema 增列**（08 报告已知边界 1 的裁决落地）：
  - `studentLectureSummarySchema`（学生讲义列表）增 `kind`——复用讲义行形态投影；
  - `studentCourseItemSchema`（学生课程目录条目）增 `docKind`——**命名决策**：条目
    自有 `kind` 是条目类型（section/lecture|unit），文档形态用 `docKind` 区分；
    分节/单元恒 null，superRefine 锁「docKind 非 null ⇔ 讲义条目」交叉不变式
    （与 attempt.ts 来源不变式同风格）；
  - `libraryLectureSummarySchema`（教师资源库列表）增 `kind`；
  - `lectureDetailSchema`（教师编辑详情）增 `kind`——学生详情已有 kind 不重复加。
- `studentLectureKindSchema` 更名 `lectureKindSchema` 并**前置到 content-api.ts 靠前
  处**：改名理由是学生/教师接口共用（名称去学生侧限定）；前置是修复新增的教师详情
  引用先于声明导致的模块初始化死区（ReferenceError，测试当场抓到）。该 schema 诞生于
  本分支第 2 步（未发布），更名无外部消费方。
- **服务端四处投影**逐一从 `lectures.kind` 读值填入：listStudentLectures（去重 +
  分组双视图）、getStudentCourseDetail（讲义条目；独立小查询镜像 unitIds 计数模式，
  不改共享的 listVisibleItems 形状；资源行缺失按默认 lecture 兜底不丢条目）、
  getLectureDetail、listLibraryLectures。
- `pnpm schema:export` 重跑：**零漂移**（导出集是 content/learning-pack/review-pack
  四份内容契约，API 响应 schema 不在其中——kind 值域已在第 2 步联动过）。git status
  干净即证据。
- 消费面夹具补列：web 四个测试文件（ExportWizard / StudentLecturesPage /
  StudentCourseDetailPage / LibraryPage 的既有夹具补 `kind`/`docKind`）。

### 2. 列表徽标与直达（4a4f120）

- **学生侧直达**：StudentLecturesPage 与 StudentCourseDetailPage 的 lesson 行链接直接
  指 `/s/lectures/:id/lesson?courseId=…`——08 报告的「阅读页重定向直达」升级为真
  直链（省一跳；重定向逻辑保留作兜底——书签/旧链接仍可经阅读页进入）。「讲练」徽标
  用 emerald 词表（与记录卡 SOURCE_BADGE_CLASS.lesson 同配色）。aria-label 区分
  「打开讲练/阅读讲义」；课程目录讲义行副标题补「可边学边练」提示。
- **教师侧仅徽标**：LibraryPage 讲义库行、AddFromLibrarySheet 讲义行显「讲练」徽标，
  点击仍进编辑/预览（ResourceRow 增可选 `docKind` 渲染标题行徽标，不占用
  「已在本课程」徽章槽位）。

### 3. 教师编辑与预览的讲练语境（b1fd01a）

- **本地 lint 按存储 kind**：LectureEditSheet 的 400ms debounce lint 由
  `wrapLectureMd(text)` 改 `wrapLectureMd(text, data.kind)`（md-dsl edit-context 已有
  kind 参数，第 3 步落地）——lesson 时题块不报 QUESTION_IN_LECTURE，与服务端
  updateLecture（第 5 步）同一包装口径，两端一致（任务 B.1 兑现；对照用例钉死
  lecture 塞题块本地仍报错禁存）。
- **RichMarkdown 题块占位卡**（任务 B.2，渲染管线惯例内的扩展点）：
  - 新增可选 prop `questionPlaceholder`（布尔）——**扩展点选 prop 注入而非注册表新
    指令**：question 是既有指令，占位卡是它的教师语境变体；`directiveComponents`
    映射保持与注册表 1:1（directive-registry-consistency 测试锁定的不变式不破），
    占位渲染器以独立常量挂在宿主选择逻辑上，attrs 同 schema safeParse（非法属性
    照样走 UnknownDirective 降级）。
  - 占位卡内容：题号 + 题型徽章 + 难度星 + 「内容请在题库编辑」+ `<details>` 折叠
    展示题块**原文**。原文取法：宿主从 hast 节点 position 偏移还原 `sourceRange`
    （DirectiveBaseProps 新增可选字段），占位卡从 context 携带的 source 切片——
    已用探针验证 position 偏移经 rehype-sanitize 后逐字保留（hast-util-sanitize
    会把 position 贴回节点）。选原文而非渲染子树的原因：**渲染管线会把
    [[参考答案]] 丢弃**（remark-blank 只留空框），教师查题需要看到答案原文。
  - **只读口径（防双源漂移，任务指定）**：占位卡无任何按钮/输入/编辑入口（测试
    断言 card 内无 button/input/textarea/select），题目内容编辑走题库——讲义里的
    题块是引用（导入时注入 id 对位），就地编辑会与题库形成双真相源。
  - **降级**：sourceRange 缺失（管线某环节丢 position 的防御路径）时渲染无折叠的
    「题目」占位框（题型徽章仍显示），不崩溃——即任务「默认无 handler 时优雅
    降级为『题目』占位框」的落点；缺省（无 prop）完全不进占位路径，题目编辑抽屉、
    学生页、samples 回归零变化（全量测试绿即对照）。
  - 学生端 md 永不含题块（lesson 安全投影，06 单），本组件仅教师路径触达。
- **消费方接线**：ContentEditSheet（LectureEditSheet 预览按 `kind === "lesson"` 启用；
  编辑器面板文案补「题块按讲练语境校验，内容请在题库编辑」）；SharedPreviewSheet 以
  frontmatter 轻量嗅探（首块 `---` 围栏内 kind 键去引号比对，与 server
  shared-service frontmatterOf 同风格，仅显示判定不做完整解析）对 lesson 文件启用；
  mixed/practice 文件照常渲染题面（预览的是文件本身，练习类文件教师要看题）。

## 已知边界（不在本单、记录给后续）

1. **共享目录列表的类型标注不含讲练**：`sharedFileKindSchema` 是
   lecture|practice 二值（D16 时代），lesson 文件在共享列表被归为「练习」
   （server extractSummaryInfo 只认 `kind: lecture`）；预览抽屉的占位卡不受影响
   （按 frontmatter 嗅探独立判定）。修正需扩该枚举 + 服务端归类，属独立契约变更。
2. **教师内容树与学生可见预览不带 kind**：contentTreeLectureSchema（GET
   /api/teacher/content）与 getStudentView（教师看学生视角的目录）未携带文档形态——
   任务清单只点名资源库列表/编辑详情，课程编辑页的讲义行暂无「讲练」徽标；需要时
   可按本单第 1 节同款三步补齐。
3. **占位卡折叠的原文区间依赖 hast position**：管线若引入会丢弃 position 的环节
   （如某些 rehype 插件重建节点），折叠静默退化为无原文占位框（不报错）——
   sourceRange 可选字段 + 降级路径即为此设计；directive-registry-consistency 与
   samples 回归继续守护管线不漂移。
4. **AttemptSession 对 lesson 草稿仍渲染整卷答题视图**（旧标签页直达
   /s/attempts/:id 的既有行为，08 报告已记录）：本单只对齐来源行文案与退出目标，
   不改会话形态（讲练页才是正门，入口已完成直链化）。
5. e2e（lesson.spec.ts 全链）在提交序列第 11 步，本单不跑（任务口径）。

## 手动验证建议（PR 描述用）

1. 教师导入 `kind: lesson` 文档：资源库讲义库与「从资源库添加」抽屉的该行显「讲练」
   徽标；点编辑进抽屉——正文含题块不报错可保存，右侧预览题块显示占位卡
   （题号/题型/难度 + 「内容请在题库编辑」），展开「查看题目原文」可见含 [[答案]]
   的原文；占位卡内无任何编辑控件。
2. 对照纯讲义：编辑抽屉塞入题块 → 本地 lint 标红 QUESTION_IN_LECTURE、保存禁用
   （与服务端 422 同口径）。
3. 共享页发布/查看讲练页文件：预览抽屉题块为占位卡；发布 mixed 文件预览仍是完整题面。
4. 学生端：讲义列表与课程目录的讲练行显「讲练」徽标，点击直达讲练页（URL 一跳到
   /s/lectures/:id/lesson?courseId=…）；纯讲义行为不变。
5. 教师批改队列：学生单题提交 fill 后队列卡显「讲练」徽章 + 「讲义标题 · 第 n 次」；
   /t/data 作答列表与详情页头同口径；「按作业」视图讲练卷独立成组「讲练 · 讲义标题」。
6. 学生完成讲练后从题卡「查看完整结果页」进入 /s/attempts/:id：来源行
   「讲练：讲义标题 · 第 n 次」，返回按钮「返回讲练页」回到讲练页（courseId 上下文
   随行）；导出 CSV（教师详情页）请求参数含 sourceType=lesson。
