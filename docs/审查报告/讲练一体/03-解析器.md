## 改动清单与决策理由

### 1. parse.ts —— kind 分派增 lesson（提交 0f53310）

- 分派改 switch（嵌套三元再套一层过深）；frontmatter 不可用仍兜底 practice（T1.3 行为不变）。
- `parseLessonDocument` 与 `parseMixedDocument` 同构：题目全收单单元、`applyLectureTitleOverride` 复用、零题记 warning `LESSON_WITHOUT_QUESTION`（「讲练页没有题目，建议改用 kind: lecture」，不阻断，讲义照常产出、无单元）、不产生 QUESTION_IN_LECTURE / MISSING_HEADING（后者本就只有 lecture 路径记）。
- **推断链复用落为代码共享**：从 mixed 抽出 `trackQuestionContainers`（单次遍历分流题块 + 跟踪最后一题所在讲）与 `inferUnitLectureTitle`（显式 frontmatter.lecture 优先 → 单讲义取 title 覆盖后终名 → H1 推断 → QUESTION_BEFORE_FIRST_HEADING 同码同文案）两个私有 helper，mixed/lesson 共用。mixed 行为字节级不变（快照与既有用例零改动全绿）。

### 2. lecture.ts —— splitLectures 增 mode:"keep"（提交 0f53310）

- `mode?: "strip" | "keep"` 缺省 strip，既有两个调用点（lecture/mixed）零变化；keep 模式题块行区间保留在讲义 markdown（切分时排除集为空），多讲义文件题块自然归属各自所在讲义段（行区间切分天然成立，测试钉住）。
- **开围栏注入**：对没有显式 id（`attributes.id` 空/缺，含 `{#id}` 简写归一）的题目容器，把最终题目 id（`单元id-序号`，与 extractQuestions 同规则）注入开围栏 `{...}` 内（无属性括号则补 `{id="…"}`）；**同一注入写进该题 sourceMd**（注入后重切行区间），题目编辑/reparse 往返 id 稳定（方案决策 8：只动存储形态不动原文语义，`imports.rawMd` 原稿不动）。行数不变，AST 行号全部保持有效。
- 与解析产出的对齐沿用 lint/questions.ts 的对位法（同容器切同一批原文行，单调游标）；被丢弃的题（type 非法，解析层已报 error 阻断导入）不注入。
- **引号策略（实测驱动）**：remark-directive 属性值**不支持 `\"` 转义、反斜杠按字面保留**（本机用 processor 实测：`id="a\"b"` 整个容器解析失败、`\\` 双写不还原）。因此手写 `quoteDirectiveValue`：值不含 `"` 用双引号包裹、含 `"` 不含 `'` 用单引号包裹、两种引号并存（或含换行）**跳过注入**（重解析仍按缺省规则复原 id，仅往返显式化降级，不破坏）。JSON.stringify 不用的原因：它会把 `\` 双写、把 `"` 转义成不可解析形态。
- 开围栏识别 `^(\s*:+question(\[标签\])?)(\{.*\})?(\s*)$`，形态意外防御性跳过（返回 undefined）。

### 3. split-lesson.ts（新）—— splitLessonBlocks（提交 ab6b320）

- `splitLessonBlocks(markdown, options?)`：输入无 frontmatter 的讲义正文（服务端存储形态），按顶层 question 容器切为 `LessonBlock[]`（md 段 + 题目槽）。**LessonBlock 类型直接 import 自 @tutor/contract**（md-dsl 本就依赖契约——parse.ts 导入 parsedDocumentSchema 等——遵循单一出处原则，未本地复制）。
- **签名决策**：计划字面是 `(markdown: string): LessonBlock[]`，但兜底 id「单元slug-序号」需要单元名、warning 需要出口，故加可选第二参 `{ unitId?, issues? }`——单参调用形态与计划完全兼容。无 id 题块按「单元id-序号」兜底对位（序号按**全部**题块计，与解析器缺省 id「被丢弃的题也占号」一致），warning `LESSON_QUESTION_WITHOUT_ID` 经可选 issues 旁路输出（服务端日志用，不进文档 lint）；unitId 缺省用 `FALLBACK_UNIT_ID`（"unit"，与解析器缺省单元 id 同源）。
- 空白 md 段跳过（契约 lessonBlockSchema md min(1)，空段是切段 bug 信号）；CRLF 归一 LF；含**闭环测试**：parseDocument 注入 → 讲义 markdown → 切段 → questionId 与题目 id 逐一对位（服务端安全投影的口径钉死）。

### 4. frontmatter.ts / lint/rules.ts / lint/directives.ts（提交 0f53310、ab6b320）

- frontmatter.ts：MISSING_KIND / INVALID_KIND 文案值域补 lesson（`practice | lecture | mixed | lesson`）。
- rules.ts：同名两码 description 补 lesson；QUESTION_BEFORE_FIRST_HEADING description 补 lesson（该码现由 mixed 与 lesson 同款产生）；登记 `LESSON_WITHOUT_QUESTION`（warning）；登记 `LESSON_QUESTION_WITHOUT_ID`（warning，splitLessonBlocks 专属，description 写明不出现在文档 lint）。
- **lint/directives.ts `initialChain` 补 lesson → `["document","lecture"]`（与 mixed 同链）**：计划文件清单未点名此处，但属必需——DocumentKind 契约已含 lesson，原实现的隐式兜底会落到 `["document"]`，导致讲练页讲义正文里的 `:::hint` 误报 HINT_OUTSIDE_QUESTION（error）、`:::fold` 等讲义限定指令误报 DIRECTIVE_NOT_ALLOWED_HERE。讲练页正文与 mixed 同为「讲义段落 + 题目」，同链才是正确语义；edit-context「lint 按 lesson 语境」的验收测试（题块不报错 + 讲义正文 hint 合法）即由它支撑。
