## 改动清单与决策理由

### 1. API 层（lib/api.ts，e02999a）

- `startLessonAttemptApi(lectureId, courseId?)`（POST /lectures/:id/lesson/start，query 形态与
  GET 讲义详情同款——06 单决策 3）、`restartLessonAttemptApi`（POST …/restart）、
  `submitLessonQuestionApi`（POST /attempts/:id/questions/:questionId/submit，json 以独立变量传入
  与既有 parseJsonBody 路由同款）。hc 客户端对三条路由端到端类型安全（web typecheck 即验证）。

### 2. use-lesson-attempt.ts：作答会话 hook（e02999a）

- **全量复用既有作答链路**（红线「参数化而非分叉」）：use-draft-sync（草稿防丢 + PUT answers +
  10s/切后台/断网恢复增量同步）、use-attempt-answers（防抖保存 + onAnswerCommitted →
  answer_change 事件）、use-attempt-events（question_view〔registerCard 视口观察〕/提示解锁
  directive_interact/聚焦兜底）、use-attempt-save-status（顶栏三态文案）、ink controller 注册表
  （手写题上传状态机经 HandwrittenControls 挂载）。页面把 draftSync 对象经 DraftSyncContext.Provider
  下发（与 AnswerView 同款，HandwrittenControls 状态联动）。
- **覆盖层**：released/summary/attempt 三个读侧字段以 start 数据为基线、单题提交响应覆盖
  （`{...data.released, ...overlay.released}` 合并读）；start 数据身份变化（refetch/重开卷）时
  整层重置——「刷新」拿教师批改结果的收敛路径永远以服务端值为权威。hintsOpened 同一重置模式
  （与 AnswerView 的 `useEffect(() => setHintsOpened(data.hintsOpened), [data])` 一致）。
- **submitQuestion 五步链**：该题 ink controller flush（手写题强制上传的单题化）→ syncNow +
  flushAnswers（判分读行内答案，提交前必须到服务端）→ prepareSubmitEvidence({questionIds:[qid]})
  （**单题化复用整卷同一实现**，天然获得 frozen/none/missing 分类与 CAS 载荷）→ 单题提交
  （questionRevisionId + evidence 单条声明，声明内 questionId 与路径一致）→ 响应叠进覆盖层。
- **错误码收敛**（任务指定口径）：QUESTION_REVISION_STALE / NOTE_EVIDENCE_MISMATCH →
  stale 文案「页面内容已过期，请刷新后重试」（弹层内展示、可重试）；QUESTION_ALREADY_SUBMITTED /
  ALREADY_SUBMITTED → 静默 `void refetch()` 并按 submitted 返回（不弹错，题卡/页面随新数据收敛）。
- **完成练习 finish**：注册表内 ink 全 flush（已提交题的 HandwrittenControls 已随题卡锁定卸载，
  注册表只剩未提交题——**evidence 范围天然 = 未提交题**，07 单「多声明已提交题 → 409」的客户端面）；
  revisions 回传全集（含已提交行，07 单「revisions 全集校验不变」）；finalizeSubmit 后走整卷
  submitAttemptApi；成功后 clearDraft + refetch（start 幂等取回已完成卷）。
- **最后一题自动收尾**：单题提交响应 attempt.status ≠ draft 时 void refetch()——refetch 落地前由
  页面的会话级分支（见 §3）用覆盖层兜底渲染完成视图，消除「提交完成但页面仍作答态」窗口。

### 3. StudentLessonPage.tsx + 路由 /s/lectures/:id/lesson（604b9dc）

- **数据流**：进入即 useQuery(startLessonAttemptApi)（幂等 create-or-return，刷新安全）；refetch 即
  「刷新」（待批题取教师批改）。三态齐全：isPending 骨架 / isError 错误面板（服务端中文 message +
  重试，重试 mock 后恢复）/ 零题讲练页（questions 空 → 纯阅读提示 + 不渲染「完成练习」——06 单
  零题开卷合法的 UI 落点）。
- **双视图**：attempt.status=draft → LessonAnswerView（key=attemptId，重开卷整会话重挂）；
  submitted/graded → LessonCompletedView。**会话级分支**：LessonAnswerView 在 hooks 之后若
  session.attempt.status ≠ draft（最后一题单题提交的自动收尾）直接渲染 LessonCompletedView
  （data 换成覆盖层合成值），refetch 落地后页面级分支接管、作答会话卸载（draft-sync 定时器/
  事件队列随之停止——避免完成后 10s 循环对着已收卷 PUT）。
- **blocks 渲染**：md 段 `<section data-lesson-md>` + RichMarkdown（lecture-body 样式），题槽按
  questionId 绑定冻结题渲染 LessonQuestionCard，**与 md 段按讲义顺序交替**；未冻结题槽（重导新增）
  渲染占位说明（本次练习按开卷内容进行）；孤儿冻结题页尾「本次练习其余题目」分组渲染（决策 2），
  含一句解释文案。**题号 = blocks 出现顺序，孤儿题排后**（契约「题号顺序 = blocks 中出现顺序」）。
- **目录**：全部 md 段拼接 `extractOutline(join("\n\n"))`（未降级——题干内标题经
  `[data-lesson-md] h2/h3` 选择器天然排除在目录采集与滚动定位之外，拼接目录与 DOM 标题序严格
  一致）；桌面 sticky 侧栏 / 窄屏弹层 + 工具栏按钮，复用 LectureOutline（currentIndex=null——
  讲练页不做分节聚焦埋点，任务口径只要求 attempt 事件族）。
- **顶部**：返回（courseId → 课程目录 / 缺省 → 讲义列表）+ 标题 + 「课程：x · 讲练 · 第 n 次」+
  进度「已提交 n/m 题」+ 草稿保存状态（aria-live；「本机保存失败」附手动重试——其余失败态由同步
  循环自动重试）+ 未全部提交「完成练习」/ 已完成「查看结果」（/s/attempts/:id）+「再做一次」
  （确认弹层「开始新一轮」——显式动作防误触，restart 409 由服务端守卫兜底）。
- **完成练习弹层**：复用整卷 SubmitConfirmDialog（未答数警示 + 草稿快览 + 缺稿明确选择分支 +
  busy 封堵关闭），阶段机与 AnswerView 的 NotePrepPhase 同构（无编辑器语境：提交链串行执行
  prepare→submit，无中止标志位——弹层 busy 期间不可关，取消只在非 busy 时发生，不存在半途关）。

## 决策与偏差说明

1. **结果页链接的收尾前隐藏**：进行中卷（attempt 仍 draft）不渲染「查看完整结果页」——该链接落到
  /s/attempts/:id 会进**整卷草稿答题视图**（AttemptSession 按 status 分支），与讲练页语境冲突且
  订正/笔记工具在 draft 态不可用（409 NOTE_NOT_SUBMITTED）。题卡上的「本题历史」（QuestionHistoryLink
  → /s/notebook/:qid）独立于 attempt 状态恒可用，进行中即渲染；收尾后两者都在。任务原文「入口链接
  到 /s/attempts/:attemptId」按此收窄为「收尾后链接」，避免死胡同动线。
2. **单题提交的证据恒携带**：草稿纸（scratch 笔记）未接（任务复用清单未含 NoteLayer/
   AttemptEditorContext），但手写题笔迹与最终答案在线；prepareSubmitEvidence 单题调用对无笔记题
   返回 `none` 声明——「缺省 = 旧客户端、有草稿 409」的坑在客户端先行规避（声明永远显式）。
3. **完成练习的 ink flush 语义**：不 flush「全部」controller 而 flush 注册表现存项——已提交题卡锁定
   时 HandwrittenControls 卸载、controller 注销，注册表天然只剩未提交题；与 evidence 范围一致。
4. **覆盖层而非写缓存**：单题提交响应不 setQueryData（会造成 data 身份变化触发 draftSync 重合并、
   hintsOpened 被陈旧缓存值覆盖等副作用），用组件态覆盖层 + data 身份变化重置，收敛语义更清晰。
5. **jsdom 测试坑（记录给后续）**：Radix Dialog 打开后 react-remove-scroll 注入含
   `overscroll-behavior` 的 `<style>`，jsdom 的 getComputedStyle 在该样式表上崩溃（`reading
   'length'`）——弹层开启期间对弹层**外**元素做 accessible-name 查询会炸；本次以文本查询规避
   （stale 用例内注释）。与既有提交（AttemptQuestionCard 用 getAllByRole 规避 name 匹配）同族。
6. **合并提交说明**：d60d4aa 误并入了 604b9dc 的 lectureId 透传小修（amend 目标错位）；两提交各自
   可构建、测试全绿，分组差异属外观性质，未重写历史。

## 已知边界（不在本单、记录给后续）

1. **列表「讲练」徽标未实现（契约缺口）**：`studentLectureSummarySchema`（讲义列表）与
   `studentCourseItemSchema`（课程目录条目）**均不携带文档 kind**（只有详情接口有 kind:
   "lecture" | "lesson"；课程条目的 kind 是条目类型 section/lecture|unit，非文档形态）——列表行
   无法数据驱动渲染「讲练」徽标，也不能直链 /lesson（需 kind 判定）。本单红线不动 server/contract；
   「点击直达」经讲义阅读页重定向达成（学生无感知）。
   **建议后续单**：契约 studentLectureSummarySchema 与 studentCourseItemSchema（lecture 条目）补
   `docKind`（或 kind 扩值）+ 服务端 listStudentLectures/getStudentCourse 补列，随后 StudentLecturesPage/
   StudentCourseDetailPage 行加徽标与 /lesson 直链（教师 LibraryPage/AddFromLibrarySheet 的
   libraryLectureSummarySchema 同缺口，第 9 步任务同受影响——编排者可一并裁决）。
2. **讲练页无圈画题干/草稿纸标注层**（AttemptEditorContext/AnnotationLayer/NoteLayer 未接——任务
   复用清单未列）：题干圈画与页内草稿在讲练页暂不可用；手写作答区与最终答案不受影响。需要时可按
   AnswerView 的 editor 接线模式补（AttemptQuestionCard 同款）。
3. **单题提交无 ink_stroke_batch/ink_edit_batch/ink_fullscreen 埋点**（任务只要求 question_view/
   answer_change/hint_open 三族）；手写题在讲练页作答时这三族事件暂缺，服务端统计照常宽松。
4. **md 段 RichMarkdown 未接 directive_interact 埋点**（讲练页无 lecture 事件队列——折叠开合/
   steps 揭晓在讲练段落里不上报）；如需可在讲练页建 lecture scope 队列补接。
5. e2e（lesson.spec.ts 全链）在提交序列第 11 步，本单不跑（任务口径）。

## 手动验证建议（PR 描述用）

1. 教师导入 `kind: lesson` 文档进课程 → 学生从讲义列表点该讲义 → 自动落到 /s/lectures/:id/lesson：
   讲义段与题卡交替、顶部「已提交 0/n 题」、右侧目录列出各 md 段标题。
2. 作答一道选择题 → 「提交本题」→ 确认 → 原地展开「答对/答错」+ 参考答案 + 详解；进度 +1；
   抓包单题提交请求体含 questionRevisionId 与 evidence 声明。
3. 提交一道 fill/无标准答案题 → 「待老师批改」+「刷新」；教师待批队列课中批 correct → 学生点刷新
   → teacherMark/finalCorrect 出现。
4. 提交最后一题 → 页面自动切完成视图（「再做一次」/「查看结果」+ 答对/答错/待批汇总）；
   「再做一次」→ 确认 → 新一轮从 0 开始。
5. 留一道题不交 → 「完成练习」→ 确认交卷 → 未交题按未答判分，页面切完成视图；
   「我的记录」出现该卷（讲练徽章），来源筛选「讲练」可筛出。
6. 教师重导讲练页（增删题）→ 学生开中的卷刷新：新题不在卷内（占位说明）、被移出 markdown 的题
   出现在「本次练习其余题目」。
