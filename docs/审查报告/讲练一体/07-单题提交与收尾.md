## 改动清单与决策理由

### 1. attempt-service 新 submitLessonQuestion（提交 9369a6e）

- **门口与守卫**：requireUsableAttempt（404 ATTEMPT_NOT_FOUND / 403 FORBIDDEN；lesson 无课程分态重校验——永不失权）→ 非 lesson 来源 404 `NOT_FOUND`（决策 1）→ 已离开 draft 409 `ALREADY_SUBMITTED` → 该题冻结行（严格口径 buildAttemptQuestionWhere：快照非空，缺失 404 QUESTION_NOT_FOUND）→ `questionRevisionId` 与行 id 精确比对（错版 409 QUESTION_REVISION_STALE，复用既有 revisionStale 工厂）→ 行内 submittedAt 非空 409 `QUESTION_ALREADY_SUBMITTED`。
- **判分**：草稿答案已在行内（answerOf，无 = 未作答提交），`grade(snapshot, answer)` 复用 @tutor/grading（红线：禁复制判分逻辑）写 autoCorrect 与 finalCorrect（不可自动判 → 两者 null 进待批）；draft 卷不可批注 ⇒ teacherMark 必空 ⇒ finalCorrect = autoCorrect（D3）。
- **单事务先查后写**：事务内复核 attempt 仍 lesson+draft、行仍未提交，再写行（autoCorrect/finalCorrect/submittedAt=nowIso，其余列不动）+ 证据行 + 自动收尾判定——并发双收尾（最后一题单题提交与整卷收尾同刻）后到者在复核处 409 幂等（better-sqlite3 同步事务天然串行，Review Focus 3）。
- **自动收尾（最后一题）**：事务内重读全部快照非空行，全部 submittedAt 非空 → finalScoreOf（有待批=submitted、全判完=graded）+ scoreAutoOf 写 status/submittedAt/scoreAuto/scoreFinal——**与整卷交卷同口径复用同一对计算函数**（scoreAutoOf 入参为此结构化为 `{autoCorrect}[]`，既有调用点零改动）；测试用「同一份卷全部单题提交 vs 整卷收尾」双学生对照钉死同值。
- **响应**（lessonQuestionSubmitData 三键）：question = resultQuestionOf + stemMd 经 studentStemMd（与 lesson-service released 同法——resultQuestionOf 导出处的「消费方必须自行投影」约定照做）；summary 现算；attempt 摘要（收尾后为新状态）。**其他未提交题的答案/详解/提示内容绝不出现**（测试三层断言：assertNoLeak（allow 当题 answers/answer/solutionMd）+ assertNoStemLeak + 未提交题详解/未解锁提示/`[[2]]` 字符串级）。
- **事件**：成功后直记 question_submit（recordQuestionSubmitEvent，payload 仅 questionId，与 attempt_start/hint_open 服务端直记同模式；拒绝路径不记，测试钉死事件计数与 payload 形态）。

### 2. submitAttempt 增 lesson 语义（提交 9369a6e）

- 判分循环拆两层：**allFrozen**（全部快照非空行——revisions 全集校验与得分汇总输入）与 **graded**（本次判分写入的行 = lesson 剔除已单题提交者）；已提交行入 keptRows 原样透传（autoCorrect 取行内值）。
- **已提交行不重判、零写入**：保 finalCorrect/teacherMark（教师课中批改优先参与 D2 重算）/submittedAt（原单题提交时刻，测试断言与交卷时刻不同值）；answerJson/activeSec/changeCount 也不补写（「不重判、保……」的字面执行，统计性补写留给后续需要时再议）。
- **未提交行**：既有交卷逻辑原样（未答按 D1 判 false）+ lesson 时多写行级 submittedAt=交卷时刻（schema 列注释口径「整卷收尾对剩余行 = 交卷时刻」；非 lesson 不写该列——`...(isLesson ? { submittedAt: nowIso } : {})`）。
- **revisions 全集校验不变**：validateSubmitRevisions 的输入从 graded 换成 allFrozen（含已提交行）——旧标签页整卷提交缺已提交题同样 409（测试钉死）。
- **evidence 范围 = graded（未提交行）**：buildSubmissionEvidence 的旧客户端草稿检测从「attempt 全部 scratch 笔记」**圈定为判分范围内**——已提交题证据已单题冻结不重做，其草稿不再阻塞旧客户端收尾（测试：仅已提交题有草稿时旧客户端收尾 200，未提交题有草稿时 409）；新客户端声明集合与未提交集合精确比对（多声明已提交题 → 409，与整卷「集合精确一致」口径同族）。非 lesson 时 graded ≡ allFrozen 且笔记只可能建在冻结题上——行为零变化（既有 attempt-submit-evidence 等测试全绿即对照）。
- 汇总口径：scoreAuto = scoreAutoOf(allFrozen)（已提交行用行内 autoCorrect）；finalCorrects 逐行取值（已提交行 = 行内 finalCorrect，否则 = autoCorrect）；结果视图预载 keptRows 原行 + graded 镜像，快照 Map 含全部行（免二次 parse）。

### 3. 证据单题化（提交 9369a6e）

- 抽出 **evidenceRowOfDeclaration**（单条声明验证核心：frozen 精确比对 head / none 与实际有稿矛盾 / missing 如实记录）——整卷 buildSubmissionEvidence 与新 buildSingleQuestionEvidence 共用同一实现（语义不复制）。
- buildSingleQuestionEvidence：缺省=旧客户端（该题有草稿 → 409、无草稿不落行=未采集）；声明携带时 questionId 必须与路径一致（否则 409 NOTE_EVIDENCE_MISMATCH——契约「须与路径一致，服务端校验」的落点）。测试覆盖 frozen 对/错、none 有稿、缺省有稿、路径不一致、无稿缺省、none、missing 全路径与 submissionEvidence 落库形态（(attempt, question) 唯一索引天然防重复冻结）。

## 决策与偏差说明

1. **非 lesson 来源 → 404 NOT_FOUND**（非 409）：任务口径「非 lesson 来源 409/404 按契约」——契约无专属分码，取 404「该入口对此资源不存在」的 D22 式口径（与 06 单「纯讲义不是讲练页 404」同款处理），消息「这份练习不是讲练练习，不能逐题提交」。
2. **状态检查先于题目检查**：已完成卷的单题提交按 409 ALREADY_SUBMITTED（attempt 级）拒绝，不再落到题目级 QUESTION_ALREADY_SUBMITTED——两码虽同 409 族，前端语义前者锁整卷、后者锁题卡，顺序即口径。
3. **自动收尾最小写入**：只写 status/submittedAt/scoreAuto/scoreFinal，**不写 attempt.activeSec 与行级 activeSec/changeCount**（任务枚举的字面执行；事件序列仍在、后续如需可补算）——与整卷收尾路径存在统计不对称，记入已知边界 2。
4. **整卷收尾对已提交行零写入**（含 activeSec/changeCount 统计列）：任务「不重判、保 finalCorrect/teacherMark/submittedAt」取最严读法——判定性数据与统计性数据都不回填，避免「收尾时刻重写历史」的任何歧义。
5. **evidence 新客户端多声明已提交题 → 409**：集合精确比对的既有口径延伸（不做「静默忽略多余项」——多余项即页面陈旧信号，可诊断拒绝优于静默）。
6. **markResponse 对 draft 卷不重算整卷**：这是任务字面之外的必要正确性处理——若沿用「批注即重算 D2」，课中批改一题会把仍有未提交行的 lesson 卷直接置 submitted（学生无法继续作答、未提交行被永久跳过）；收尾链路（自动收尾/整卷收尾）才驱动状态机，两者读同一批 finalCorrect 值，殊途同归。
7. **markResponse 响应 attemptStatus 对 lesson draft 卷映射 "submitted"**：契约枚举 `["submitted","graded"]` 已定稿不动；语义上「仍有未判定/未提交行」按 D2 即 submitted 态，收尾后终态由收尾链路写。若后续契约要加 draft 值属独立变更。
8. **行级锁定（56f3a60）是任务清单之外的补充**：实现「幂等拒绝」用例时发现——单题提交只锁提交动作，PUT /answers 与 PUT /ink 仍可改写已提交行（attempt 级 draft 守卫拦不住进行中卷），判定与答案会漂移。按 AGENTS 正确性纪律当场补上（守卫 + 2 用例），非镀金。
9. **sourceOf 的 unitTitle=讲义标题**：契约 02 注释写「unitId/unitTitle 为嵌入单元快照值」与任务「标题=讲义标题」在本单裁决为——unitId 保快照值（分组键/功能消费方），unitTitle 作展示串承载讲义标题（记录/教师列表/待批卡片/CSV 四消费方同源）；web 侧 lesson 分支展示（第 8/9 步）直接可用。

## 已知边界（不在本单、记录给后续）

1. **activeSec 统计不对称**：单题提交行不按事件重算每题用时；经自动收尾路径离开 draft 的卷 attempt.activeSec 为 null（经整卷收尾路径离开的卷照常计算）。教师端该类卷用时显示「—」。需要时可在收尾链路统一补算（事件都在）。
2. **analytics 的 qualifying 过滤未动**：`(assignment || attemptNo === 1)` 会把 lesson 首卷计入「首次作答」统计（与 course 首卷同构——都是该生该内容第一次完整作答，语义可辩护）；是否要在分析口径排除/单列 lesson 未在本单范围（任务只点名谓词与记录聚合），留编排者决策。
3. **lesson 详情/start 既有用例回归**：06 单的 released/summary 用例随 lessonLiveSummaryOf 重构跑绿（口径零变化）；`start` 进行中 summary 仍现算非 null（06 决策 2 维持）。
4. 单题提交后**笔记（scratch）与提示（hint）通道保持开放**：笔记证据已在提交事务冻结（frozen 行不再变），继续写草稿只影响 T6R.15 的 supplement 语境；已提交题的答案/详解已当题释放，解锁提示不再构成泄露面——两者无需锁定。

## 手动验证建议（PR 描述用）

1. 教师导入 `kind: lesson` 文档 → 学生开卷 → 逐题提交：客观题即时见对错+参考答案+详解，fill 显示「待老师批改」；抓包单题提交响应全局搜未提交题的 `:::solution`/`[[`/未解锁提示文本零命中。
2. 提交最后一题后 attempt 摘要变 submitted/graded 并带 scoreAuto；「完成练习」（POST /attempts/:id/submit）对已提交行判定与提交时刻不变（库内 responses.submittedAt 前后对比）。
3. 教师待批队列在学生提交 fill 后**立即**出现该题（卷仍进行中）→ 课中批 correct → 学生刷新讲练页见 teacherMark/finalCorrect、队列出队。
4. 学生「我的记录」出现讲练行（标题=讲义标题、徽标「讲练」〔web 第 8/9 步接入前显示单元标题样式〕）；把学生移出课程后该草稿仍可回看续作。
5. 已提交题在讲练页改答案/传笔迹 → 409（前端锁题卡；curl 直发同拦）。
