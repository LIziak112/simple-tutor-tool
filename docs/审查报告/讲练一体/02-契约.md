## 契约改动与决策理由

### 1. content.ts —— documentKindSchema 增 "lesson"（提交 9351070）

- 枚举 `["practice","lecture","mixed","lesson"]`，注释写明"题目容器合法且保留在讲义 markdown 原位（解析时注入最终题目 id）、导入建讲练页 + 练习单元"。md-dsl 侧解析支持属后续任务（本提交只动契约值域）。
- `pnpm schema:export` 重跑：docs/dsl/schema/content.json 的 frontmatter.kind 值域同步。md-dsl 未引用 documentKindSchema（自有 kind 处理），无跨包破坏。

### 2. attempt.ts —— 来源枚举 / 摘要不变式 / 新 schema / 错误码（提交 398920d）

- `attemptSourceSchema` 增 `"lesson"`。头注释写全 lesson 语义：记 lectureId + unitId（嵌入单元快照值）、assignmentId 恒 null、courseId 可空；**start 幂等 create-or-return 与 course 来源"再点开新卷"的行为差异**（方案决策 7）；lesson 永不失权；当题释放恒题级粒度（attempt 级 answerRelease 不适用，方案决策 3）。
- `attemptSummarySchema` 增 `lectureId: z.string().min(1).nullable()`。计划原文写 `z.string().nullable()`，实现取 `min(1)` 与同文件 unitId 同款处理——"必填"语义在字段层再拦一道空串，形态与计划一致（更严不失配）。superRefine 增两条：
  - lesson 分支：lectureId 必填、assignmentId 恒 null、unitId 恒非空、courseId 无约束（可空可非空）——逐字对齐计划不变式；
  - **反向锁定**（计划字面未列、按本文件既有"交叉不变式 schema 层锁定"风格补）：非 lesson 来源携带 lectureId 即拒绝。归属键只属于讲练开卷，防止 course/assignment/wrong 行携带无消费方的脏值。
- 新 schema 全部落 attempt.ts（作答域内聚：lessonStartData 与 attemptStartData 同族、lessonQuestionSubmit 与 attemptSubmit 同族；lessonBlockSchema 被 content-api.ts 复用，attempt.ts → content.ts 单向依赖无环），经 index.ts 全量导出（全站单一出处）：
  - `lessonBlockSchema`：discriminatedUnion("type")，md 段 `md: z.string().min(1)`（切段跳过空段，空串是切段 bug 信号）、question 段 `questionId: z.string().min(1)`；
  - `lessonStartDataSchema`：lecture{id,title,topic,courseId,courseName} + blocks + attempt + questions（attemptQuestionPublicSchema[] 平铺）+ drafts + hintsOpened + released（record<string, attemptResultQuestionSchema>）+ summary（nullable）+ enabledCapabilities。superRefine 锁两条状态-形态不变式：attempt.sourceType 必须 lesson；attempt 非 draft 时 summary 必须非空（完成后非空，草稿/完成共用一形态由 status 区分）；
  - `lessonQuestionSubmitRequestSchema`：questionRevisionId + evidence.optional() **直接复用 submitEvidenceDeclarationSchema**（含 questionId 与 frozen/none/missing CAS 语义，注释写明"questionId 须与路径一致，服务端校验"）；
  - `lessonQuestionSubmitDataSchema`：question/summary/attempt 三键（summary 恒非 null，进行中卷也现算部分汇总）；
  - 成功壳 lessonStartOkSchema / lessonQuestionSubmitOkSchema 与既有 apiOkExtend 模式一致。
- `attemptErrorCodeSchema` 增 `"QUESTION_ALREADY_SUBMITTED"`（插在 ALREADY_SUBMITTED 之后），注释写明 409 语义与分码理由（整卷重复交卷 vs 单题重复提交，前端据此锁题卡而非提示整卷已交）。
- 类型导出：LessonBlock / LessonStartData / LessonQuestionSubmitRequest / LessonQuestionSubmitData。

### 3. learning-event.ts —— question_submit 事件（提交 398920d）

- 枚举追加（"只增"：既有 22 项顺序零变化）+ `questionSubmitEventSchema {type, clientTs, questionId}`，加入 attemptEventSchema（attempt 域，讲练页逐题提交埋点；payload 仅 questionId——答案与判定在作答接口响应里，事件只做行为埋点，白名单无需扩）。lectureEventSchema 不收（测试锁定端点互斥）。
- 注释计数 22→23 更新三处（枚举头注释、attemptEventSchema 头注释、learningEventSchema 注释、index.ts 模块注释）。

### 4. content-api.ts —— 学生讲义详情 kind/blocks（提交 0ead1ff）

- 新 `studentLectureKindSchema = z.enum(["lecture","lesson"])`（lectures 行形态投影，与 frontmatter 的 documentKind 是两个概念，就近定义单一出处）。
- `studentLectureDetailSchema` 改 object+superRefine：
  - `kind` 必填；`markdown: z.string().min(1).nullable()`；`blocks: z.array(lessonBlockSchema).optional()`；companionUnits/enabledCapabilities 形态不变。
  - superRefine 锁四条：lesson → markdown 恒 null（题块原文含 [[答案]]/:::solution/:::hint，防泄露根基）；lesson → blocks 必须携带；lesson → companionUnits 恒空数组（嵌入单元隐藏、题目已在页内，防重复入口）；lecture → markdown 非 null 且不得携带 blocks（既有形态不变，向后兼容注释写明仅新增字段）。
- 教师端讲义接口零改动（计划只点名学生侧 533-552）。

### 5. 枚举联动面清点（student-records-api / teacher-attempt-api / learning-pack / student-notebook-api）

全库 grep `AttemptSource|attemptSourceSchema`：records/teacher/notebook/learning-pack 四处 sourceType 均**直接复用 attemptSourceSchema**，无独立枚举定义需要扩——只需注释同步（notebook 字段注释、teacherAttemptSourceSchema 头注释补 lesson 展示口径待后续任务对齐的说明）。learning-pack 的 sourceType 联动进 JSON Schema 产物（见提交 d1d3d2a）。

## 遗留与提醒

1. `lectureId` 用 `z.string().min(1).nullable()` 而非计划字面的 `z.string().nullable()`（理由见 §2；更严不失配）。
2. 非 lesson 来源 lectureId 恒 null 的反向锁定是计划字面之外的补充（风格与既有 wrong/course 交叉锁定一致）。
3. 学生讲义详情 `kind` 为必填新字段：服务端（student-course-service 已补 "lecture"）与任何手写该形态的旧载荷在下一任务接入 lesson 判定前，kind=lecture 形态零变化。
4. db schema 的 $type 收敛（AttemptSource/LearningEventType）与后续 db 迁移任务（lectures.kind/attempt.lecture_id 列）无冲突：$type 是 TS 元数据，不产生迁移。
