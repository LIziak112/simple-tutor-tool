## 改动清单与决策理由

### 1. 新 services/lesson-service.ts（提交 d1b3ebc）

- **startLessonAttempt(db, studentId, lectureId, courseId?)**：事务内查该 (studentId, sourceType='lesson', lectureId) 的 attempts——有 draft 返回它（幂等取回）；**有已完成（submitted/graded）返回最新那份，绝不重开**（方案决策 7：刷新已完成讲练页不消耗 attemptNo）；只在**零 attempt** 时建卷（attemptNo 恒 1）。事务先查后插（attempts_student_lecture_idx 走 (student_id, lecture_id)，sourceType 附加过滤）。
- **restartLessonAttempt(db, studentId, lectureId)**：仅最新 attempt 已离开 draft 可用；进行中 409 `ALREADY_SUBMITTED`（attempt 状态冲突的契约既有分码，message 写明「完成后才能再做一次」）；**无任何作答同样 409**（无可重做对象）；新卷 attemptNo = 最新 + 1、从空白开始。
- **建卷**：复用 `newDraftAttempt`（四来源唯一行字面量，本单扩展 lectureId 可选参）+ `freezeInputsOfAttempt` + `insertFrozenResponses`（两者由 attempt-service 私有改导出）——题目 = 嵌入单元（units.lectureId=本讲义、域内未软删、多者取 order 最前）的 live 题，建卷即冻结；事件：建卷（且仅建卷）经 event-service 新增 `recordAttemptStartEvent` 直记一条 attempt_start（与 hint_open 服务端直记同模式；幂等取回/已完成取回不重复记——测试钉死两卷各恰一条）。
- **投影组装 buildLessonStartData（start/restart 共用）**：blocks = `splitLessonBlocks(lectures.markdown)`（服务端切段，学生端永不见原文）；questions = 冻结行公开投影平铺（`publicOfSnapshot` + questionRevisionId = 行 id），快照缺失行跳过、**不按 blocks 过滤**（孤儿题平铺下发、前端页尾渲染，决策 2）；drafts/hintsOpened 与草稿视图同口径（本人答案、已解锁提示回显，`openedHintEcho` 同一实现）；released = submittedAt 非空的行 → `resultQuestionOf` + **stemMd 补经 studentStemMd 投影**（resultQuestionOf 返回原文题干，buildResultData 的 releaseAwareQuestion 同法；导出处注释明示该约定），teacherMark/teacherComment/finalCorrect 读当前行值（进行中卷教师已批即反映）；summary 读侧现算（见决策 2）。

### 2. student-course-service.ts：三分谓词抽出 + lesson 安全投影

- 原 getStudentLecture 内联的三分访问谓词整体抽为导出的 **`requireVisibleStudentLecture`**（不存在 404 / 指定 courseId 且存在但非成员 403 COURSE_ACCESS_DENIED / 缺省时任何课程不可见 404 / 条目隐藏 404 / 讲义行缺失 404），getStudentLecture 与 lesson-service 共用**同一实现**——两个入口访问口径永不漂移（任务硬性要求"复用同款三分谓词"落为代码共享而非复制）。讲义行 select 增 `kind` 列。
- **kind='lesson' 详情**：`markdown: null` + `blocks: splitLessonBlocks(markdown)` + `companionUnits: []`（跳过配套单元查询；契约 superRefine 锁定三不变式）+ enabledCapabilities 照旧；**kind='lecture' 行为零变化**（student-lectures.test.ts / student-courses.test.ts 既有用例全绿即对照）。

### 3. attempt-service.ts：最小扩展（全部为 lesson 数据流必需）

### 4. routes/student.ts：两条新路由

- `POST /lectures/:id/lesson/start`（200；幂等取回与建卷同码，对齐 assignment 来源 startAttempt 先例）与 `POST /lectures/:id/lesson/restart`（201 恒建新卷，对齐 wrong-practice 先例），挂现有 requireStudent 组守卫。
- **courseId 经 query 参数**（`?courseId=`，复用 studentLectureDetailQuerySchema）：契约**未定义** start 请求体 schema（任务口径"以契约为准"），query 形态与 GET 详情同款且 POST + query 在本路由组有先例（annotation base 的 ?phase=）——不新增契约面。restart 无参数。

### 5. 测试（routes/student-lesson.test.ts，13 用例）——泄露矩阵为主

- **开卷投影**：blocks 五段交替（md/题槽逐一对位）、questions 平铺（options 纯文本/hintCount/questionRevisionId 非空）、attempt 归属（sourceType=lesson、lectureId、unitId=嵌入单元、courseId、assignmentId=null、attemptNo=1）、lecture 上下文（title/topic=嵌入单元 topic/courseName）；**三层泄露断言**：assertNoLeak（键名级）+ assertNoStemLeak（题干内容级）+ 题块原文字符串级（`::::question`/`:::solution`/`:::hint`/`[[错误]]`/`- [x]`/未解锁提示文本/详解文本七个片段绝不出现在整个响应 JSON）。
- **幂等**：重复 start 同 attemptId（带/不带 courseId 各一次）；attempt_start 事件恰一条。
- **草稿/提示回显**：PUT 答案进 drafts、POST hints 解锁的进 hintsOpened、未解锁的提示文本字符串级断言绝不出现；**讲练卷流经的通用接口（GET /attempts/:id 草稿视图、GET /attempts/:id/paper）同样零题块原文**（钉"任何学生端响应"口径——讲义 markdown 从不进入这些路径）。
- **released 白名单**：fabricate 一行已提交 + 教师已批（submittedAt/autoCorrect/finalCorrect/teacherMark），start 响应 released 恰含该题（teacherMark 读当前行值）、未提交题的公开投影单独过 assertNoLeak、allow 放行后整壳无其余泄露键。
- **lesson 详情**：markdown===null、blocks、companionUnits==[]、契约 schema parse、无题块原文。
- **冻结语义**：开卷后教师直改题库行，再次 start 题干不变（快照冻结）。
- **访问控制**：非成员带 courseId 403 / 非成员无 courseId 404（不暴露存在性）/ 讲义不存在 404 / 条目隐藏 404 / 纯讲义（kind=lecture）404 / 未登录 401 / courseId 非 UUID 400。
- **restart**：无作答 409、进行中 409、已完成 201 新卷 attemptNo+1 空白卷、start 幂等取回新 draft、两卷各一条 attempt_start。
- **零题讲练页**（LESSON_WITHOUT_QUESTION 文档）：开卷合法——questions 空、blocks 纯 md、unitId 非空占位（见决策 1）。

## 决策与偏差说明

1. **零题讲练页的 unitId 落讲义 id 占位**：契约 attemptSummarySchema 锁定 lesson 来源 unitId 必须非空（"嵌入单元的快照值"），而零题讲练页解析**不产出单元**（03 单：无单元）——两要求在该形态冲突。取讲义 id 作非空稳定占位：全局唯一（不会与真实单元 id 碰撞）、该卷无题目行（unitId 无任何功能消费方：域内题按 unitId 查询自然为空、分组无行可分组）。已加代码注释与测试断言（非空）。若后续要改语义（如契约放行 null），只动这一处。
2. **summary 进行中也现算（非 null）**：任务指令"进行中读侧现算（仅按已提交行）"与契约字段注释"进行中为 null"字面冲突，但 schema superRefine 只锁"非 draft 时必须非空"（draft + 非空合法）。取指令口径：已提交题计入 correct/wrong/pending、未提交题计入 unanswered（与契约 lessonQuestionSubmitDataSchema 注释的提交响应口径**完全一致**——避免"提交瞬间看到部分汇总、刷新 start 又变 null"的 UX 断层）。answered 按契约字段定义数"已提交且 answer 非 null"；pendingCount 按 D4 的 finalCorrect 口径只数已提交行（教师课中批完即归零）。attempt 级 scoreAuto/scoreFinal 只在离开 draft 时写（本单不写，留下一单）。
3. **courseId 走 query 而非请求体**：契约无 start 请求体 schema（见 §4）；任务指令"以契约为准"优先于"请求体可带"字面。
4. **纯讲义（kind=lecture）POST lesson/start → 404 NOT_FOUND**：讲练开卷入口对纯讲义不存在，D22 不暴露形态差异口径（与条目隐藏同码同文案）。
5. TDD 中途修正两处**测试侧**预期：① released 用例的 summary——fabricated 行未存过草稿答案，按契约 answer 口径 answered=0/unanswered=2（非提交语义的想定值）；② restart 非成员——restart 无 courseId 参数，非成员在任何课程都看不到该讲练页 → 404（403 只在显式 courseId 时可达，start 用例已覆盖）。
6. **attempt_start 服务端直记**：任务改动点 5 字面"建卷发 attempt_start（复用现有埋点口径）"。现有口径是前端 use-attempt-events 页面进入时上报；讲练页（第 8 步）是全新页面，服务端建卷直记保证事件必有（与 hint_open「只要下发就必有事件」同模式）。已注释：clientTs 用服务端时钟（§2.6-3 不同源注记；attempt_start 不参与 focus/blur 区间计时，active-time 明确排除）；前端若另报一条，events 追加语义可容忍（不进任何区间/判分计算）。
7. **resultQuestionOf 导出后 stemMd 原文风险**：该函数返回的 snapshot.stemMd 是作答时原文（含 [[答案]]），原仅 buildResultData 内部消费（其内经 releaseAwareQuestion 统一投影）。导出处在注释加粗明示"消费方下发前必须自行经 studentStemMd"，lesson-service 的 released 条目即照做并有测试钉死（released[q].snapshot.stemMd 不含 `[[`）。

## 已知边界（不在本单、记录给后续）

1. **嵌套题块不切段**：题目容器嵌在其他容器内（如 :::fold 里套 ::::question）时 lint 记 warning「question 只能作为文档顶层容器」（DIRECTIVE_NOT_ALLOWED_HERE，不阻断导入）——解析层与 splitLessonBlocks 都只扫顶层，嵌套块不会被抽题、其文本按讲义正文段下发。该块不是题库题目（无冻结行），语义上等同纯讲义的 :::solution 讲解内容（学生端应见），非题库数据泄露；md-dsl 属本单红线不动，若要封死需在 lint 升 error（留待编排者决策）。
2. 单题提交（QUESTION_REVISION_STALE / QUESTION_ALREADY_SUBMITTED / 自动收尾）、整卷收尾 lesson 语义、待批谓词扩 submitted_at、记录聚合收录 lesson——全部在下一单（提交序列第 7 步）。
3. `studentLectureDetailQuerySchema` 被 POST start 复用为 query schema：若契约后续补 start 请求体定义，切换时注意前端调用面同步（第 8 步前端尚未接入，当前零迁移成本）。
