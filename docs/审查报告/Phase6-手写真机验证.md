## 1. 桌面自动化测量结果

### 1.1 测量环境

- Windows 11 Pro（10.0.26200），Claude 桌面内嵌浏览器（Chromium 内核，
  UA 含 `Chrome/152.0.7977.130 Electron/44.4.3`；UA 仅作环境记录，能力判断
  一律来自运行时探测，见 §2）
- `http://127.0.0.1:5301`（vite dev；127.0.0.1 属安全上下文）
- 实验室书写台画布约 317×718 CSS px（浏览器窗格较窄；引擎 devicePixelRatio
  内部上限 2，见 atrament-adapter MAX_DPR）
- 合成笔迹默认参数：种子 20261005、每笔点数 40、纸高 800（预算试验用 3000）

### 1.2 注入方案取舍（任务要求说明）

实验室提供两个注入按钮，**主方案＝驱动 pointer 事件序列**：在引擎真实画布上
逐点派发 `pointerdown/pointermove/pointerup`（pointerType=pen、带压感），
事件同步进入适配器真实输入热路径（clientX→逻辑坐标换算、atrament.draw、
livePoints 收集、收笔 commitAdd、InkPad onDocChange 通知与自动加高检查），
因此「事件处理耗时」就是真实输入路径的耗时。「对照：load 注入」只走确定性
重放重绘（T6R.6 渲染器同款原语），测不到输入热路径，仅作重绘对照。

**已知限制**：合成 PointerEvent 的 `getCoalescedEvents()` 返回空数组 → 走单点
回退路径；合并采样批次的真实批次耗时与高频事件下的 p95 只能真机测。
真实设备上 coalesced 批内多点的处理成本会高于这里的单点路径，本文数字是该
路径的**下界参考**。

### 1.3 合成书写注入（驱动指针事件）

| 档位 | 事件处理 pointermove | 收笔 max | 全量重绘 | 内存 Δ |
| --- | --- | --- | --- | --- |
| 100 笔 / 3500 点 | p50 0.00｜p95 0.10｜max 0.30 ms | 1.80 ms | 11.3 ms | +3.7 MiB |
| 400 笔 / 20128 点（长密集档） | p50 0.00｜p95 0.10｜max 1.10 ms | 12.8 ms | 65.9 ms | +25.2 MiB |

- 注入完整性复验：100/100 笔、3500/3500 点全部提交；合成笔画与引擎入库笔画
  逐笔 tool 一致，坐标经 CSS 像素往返的量化差 ≤0.58 逻辑单位（317px 窄画布
  下的换算精度，画布越宽量化差越小）。
- 收笔耗时随文档增长（1.8→12.8 ms）：包含 commitAdd 的历史副本与 InkPad
  通知链；60Hz 帧预算 16.7 ms 内仍富余，但**这是桌面数字**，真机事件率与
  CPU 不同，不外推。
- 对照 load 注入（400 笔 / 20128 点）：全量重绘 83.1 ms；JSON 原始 827.9 KiB、
  gzip 212.7 KiB（压缩 37.4 ms）；内存 Δ +7.3 MiB。
- 排障记录（对实现有价值的副产物）：注入最初用陈旧 rect 计算 clientY，进度
  行渲染把画布下推约 28px，导致坐标整体上移约 88 逻辑单位、首行 7 笔被
  pointerdown 边界校验整笔拒绝。修复为每笔取新 rect。这佐证了方案 §4.1
  「布局调整在收笔后执行、一笔不得混用两个坐标变换」的必要性——真实书写中
  旋转/加高同样会造成这类坐标基准变化（T6R.7 输入状态机的测试点）。

## 4. 暂定值建议（全部为暂定，真机定标后修订）

1. **正文 gzip ≤2MiB、解压 ≤32MiB**：维持方案 §7 起点。桌面实测要到
   6400 笔/21 万点（gzip）与 25600 笔/85 万点（解压）才触线，对单题笔量
   极宽松；但合成样本 40 点/笔偏疏，真机高采样密度下手感正常的稿子点数
   可能数倍于此，仍以真机实测为准再定契约数值（T6R.2 写入）。
2. **每分析图 ≤2MiB**：桌面整幅（不切片）在 1600 笔/5.3 万点即超线——
   长稿**几乎必然需要按记录范围切片**（方案 §7 已预留该路径与 40 逻辑单位
   重叠）。建议切片为默认策略而非兜底；切片后单片是否守住 2MiB 待真机。
3. **分析图逻辑宽 1000px**：维持试验值；桌面重绘与编码耗时见表（3200 笔
   整幅 413.7 ms 重绘 + 324 ms PNG 编码，一次性行为不在输入热路径）。
   真机若小字不可读再升 1500 并重测。
4. **每笔/总点数上限**：桌面单事件 p95 0.10 ms、收笔 max 12.8 ms（2 万点
   文档）不足以定上限；建议按真机 60Hz 帧预算与 20 题连写表现定标。
5. **预测层（T6R.22 触发条件）**：桌面数据不构成触发证据；按方案 §4.2，
   仅当真机实测输入手感不达标且瓶颈定位在采样/绘制时才立项。

**口径变更注记（2026-10-06 两轮闸门后）**：

影响单事件计时区间（sampler 只包 dispatchEvent）。
