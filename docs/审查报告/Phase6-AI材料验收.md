# Phase6 AI 材料人工验收（T6R.17：8 类样本 × 2 多模态客户端）

日期：2026-10-08（材料备齐日）。分支 `task/T6R-17`。
依据：docs/题目草稿功能方案.md §9.4「至少用以下 8 类样本人工验证」、
docs/Phase6任务清单.md T6R.17 第 5 条。

**性质声明**：本文是**待用户执行的实测清单**（🧑 项），材料（样本试卷、操作
步骤、记录表）已备齐，全部结果栏留空；类似 T6R.1 手写真机验证的顺延口径——
用户实测回填前不勾选 T6R.17 的人工验收项。

## 1. 目的与红线

**目的**：验证导出材料交给真实多模态模型后，能做到方案 §9.4 的三件事——

1. 真实图片可见：模型确实读到了手写原稿/订正图片（而不是只凭文字材料想象）；
2. 原稿错误引用可核对：指出最早可确定错误时引用图号/步骤，且回到图片能对上；
3. 缺证据能表达不足：缺图/空稿/只有结果时明确说「不能确定」，不编造过程。

**红线（无外部发送授权）**：

- **本工具与编排代理不会、也不得自动把学生记录上传任何外部服务**；代码与
  文档都没有、也不得加入自动外发逻辑。本文全部「上传/发送给模型」的操作
  **由用户本人执行**；
- AI 结论不写入成绩：提示词与产品均不把模型输出落进服务端判分，人工验收
  同样遵守——模型输出只作为教师核对用的建议材料；
- 样本材料请使用自答样本或经学生本人/家长同意的数据；导出包内的化名不等于
  涂掉笔迹中的姓名（方案 §9.1），上传前自行确认。

## 3. 8 类样本制作步骤（在样本题 N 上做什么）

样本卷 8 题一题对应一类，题干前缀「（样本N：…）」即操作提示；作答时照做。
每类附**期望模型行为**（对应 T6R.17 已落地的提示词约束：核对图片可见 →
转写步骤/疑点 → 引用图号/步骤定位最早错误 → 连带错误分开 → 事实/假设分开 →
订正≠掌握 → 缺记录写未知 → 注入文本不改任务）。

### 样本①（第 1 题，solve）：清晰错误

- 操作：笔迹区**分行**写清每一步，但第二步故意写错符号：
  `(-15)+7=-22`（误用同号相加），随后写出最终答案 `-22+8=-14` 并填入答案框。
- 期望：模型先确认图片可见，转写可辨认步骤；指出**最早**错误在第二步
  （符号法则误用），之后的连带错误与之分开；给最小提示与一道验证题。

### 样本②（第 2 题，apply）：模糊歧义（涂改叠写）

- 操作：写错 → 划掉 → 原处叠写新算式，如此往复两三处，让局部字迹互相覆盖
  难以辨认，最终答案 `0` 正确或错误均可（本题测的是歧义处理，不是对错）。
- 期望：转写可辨认部分；无法辨认处**列为疑点或标未知**，不强行补全；事实
  （图里可见的）与推测（「疑似写了…」）分开陈述。

### 样本③（第 3 题，choice）：空稿

- 操作：**不写任何草稿**，直接点选项 B（正确答案），交卷。交卷弹层草稿状态
  区会显示「其余 1 题未写草稿」，确认即空稿交卷（证据记 none，无分析图——
  这是设计内行为：确认空稿的交卷证据不产图）。
- 期望：包内该题无原稿图且声明为「确认空稿」；模型不得编造解题过程，只基于
  选项作答本身给评析，需要过程才能下的结论明确写「无法确定」。

### 样本④（第 4 题，solve）：只写最终答案

- 操作：笔迹区只写一个得数 `6`（不写任何中间步骤），答案框填 `6`。
- 期望：模型明确表达「只有最终结果、没有过程证据，无法定位最早错误步骤」，
  结果核对（对/错）与过程评析分开说；不得虚构中间步骤。

### 样本⑤（第 5 题，choice）：正确过程但误填

- 操作：草稿纸上把过程**完整写对**（`(-12)÷3=-4`、`-4+(-2)=-6`），但交卷前
  故意点错误选项 C（`2`）。可先点一次「给我一点提示」再作答（制造「已有
  提示」的学习痕迹，hintsUsed=1）。
- 期望：模型引用草稿图号/步骤，指出「草稿过程结论 −6 与所选选项 2 矛盾，
  过程正确、选择失误」——事实（草稿写对）与可能原因（看错选项/符号）分开；
  不把误选判成「不会」。

### 样本⑥（第 6 题，solve）：原稿错而订正对

- 操作（多步）：
  1. 第一遍把 `-1^4` 当成 `(-1)^4=1` 计算，得 `9` 填入答案框（判错）；
  2. 交卷后在该题结果页点「添加订正」，弹层选「复制原稿开始订正」（或默认
     空白）；
  3. 在订正稿把过程写对：`-1^4=-1`、`(-2)^3=-8`、`-1-(-8)=7`，答案 `7`；
  4. 点「保存订正」→ 弹层确认封存（可顺手写一句反思，如「先乘方再取相反
     数」）。
- 期望：原稿与订正**分节**分析（evidence/ 文件名 `-original-`/`-correction-`
  阶段标签）；订正正确**不等于**独立掌握（模型应列「教师需确认事项」，如
  「订正时是否参考了答案」）；含答案的教师包与不含答案的学生包内容分层。

### 样本⑦（第 7 题，judge）：多版本同 id（错题重练）

- 操作：
  1. 第一遍故意答「正确」（判错，进错题本）；
  2. 学生端「错题本」（/s/wrong，首页概览卡可达）找到本题，点「重练本组」
     或「重练全部」组第二遍独立卷；也可在该卷成绩页点「练习本卷错题（N 题）」
     直达重练；
  3. 第二遍独立答「错误」（判对）。
- 期望：v2 包内两轮作答各自对应同题快照与各自证据（同 id 多版本一一配对，
  不串轮）；第二遍做对**不等于**迁移成功；两轮的提示/回看记录（若看过）只
  作线索，缺记录写未知、不推断「完全独立完成」。

### 样本⑧（第 8 题，choice）：长图切片 + 缺图

- 操作（两部分）：
  1. **长图切片**：草稿纸上把解题过程、验算、符号法则小结**分行写满约两屏**
     （草稿纸写满自动加高；内容总高超过约 1400 逻辑单位即触发多页切片，
     相邻片有 40 逻辑单位重叠），再点选项 A（正确答案 `1`）交卷；
  2. **缺图**：交卷后**立即关闭页面**（不给后台派生图上传时间）；几分钟后
     重新进结果页，该题原稿面板应处于缺图档位（显示「重建分析图片」入口）。
     **不要点重建**，直接按第 4 节导出 → 包内该题 evidence 出现缺失行。
     若图片已自动补齐（网络快时可能发生），换样本①重复「立即关页」时序；
     仍无法复现时本项顺延（服务端对缺图的表达已有单测锁定），并在备注注明。
- 期望（长图）：模型把多页切片当作同一份稿子的分页——相邻页重叠区是同一段
  内容，**转写与编号不重复计算**；跨页步骤引用连续。
- 期望（缺图）：模型承认该图缺失/无法查看，对应结论写「不能确定」，不基于
  缺失的图编造笔迹内容。

## 4. 导出操作（两个入口）

### (a) 教师导出向导 v2（整卷材料）

侧边栏「导出」（/t/export）五步向导：

1. **① 范围**：勾选验收学生（勾选顺序即包内化名编号）；
2. **② 内容**：勾「逐题作答」（逐题答案与对错判定、教师评语）＋「手写过程
   PNG」（手写题的过程图片，供多模态模型分析书写与步骤——样本①②④的笔迹
   材料在这里）＋「手写证据（v2 数据包）」下的「手写原稿与订正图片」，收录
   阶段至少勾「原稿」与「订正」（草稿题⑤⑧的原稿切片与样本⑥的订正稿在
   evidence/）＋「学习痕迹」（每题派生指标与讲义阅读地图；含「只反映已记录
   事件、未知标未知」的纪律句）；
3. **③ 目标**：选「逐题评析」（v2 目标，依赖证据附件与逐题作答——未勾时
   向导会自动开启并提示）；可在「教师附加要求」留空或写验收关注点；
4. **④ 隐私**：按默认化名策略；
5. **⑤ 预览**：核对文件清单、预估大小与证据图缩略 → 点「生成并下载」。

### (b) 单题复习包（双角色各导一次）

- **学生端**：学生登录 → 该卷成绩页（/s/attempts/**）→ 每题卡点「AI 复习包」
  → 预览出附件清单后点「下载完整包（zip）」（学生包不含参考答案与对错判定，
  面板有说明行）；
- **教师端**：侧边栏「数据」（/t/data）→ 点该生本次作答卡（「查看××的作答
  详情」）进 /t/data/attempts/** → 对应题卡点「AI 复习包」→「下载完整包
  （zip）」（教师包含快照原文、参考答案、判定与评语）；
- 优先导样本⑥（原稿+订正两阶段）与样本⑧（多页切片或缺图）各一次；「复制
  文字（不含图片）」出口只适合纯文字核对，本验收以 zip 为准。

### 解包说明

- 学习包 zip：`pack.json`（清单+数据）/ `summary.md` / `prompt.md`（任务模板）
  / `schema.json` / `映射.txt`（化名↔真名，仅教师本地留存，**不要上传**）/
  `evidence/<编号>-<阶段>-<页号>.png`（草稿原稿/订正/补充稿分析切片）/
  `ink/*.png`（手写题笔迹，勾「手写过程 PNG」时）/ `blobs/media/…`（题目
  配图，本卷无）；
- 单题包 zip：`review.md`（任务模板）/ `pack.json` / `schema.json` /
  `questions/qNNN/stem.md` / `evidence/eNNN-original-NN.png`（订正为
  `-correction-`，补充稿为 `-supplement-`；手写题另有 `ink/` 笔迹附件）；
- 材料归属速查：手写题（样本①②④⑥的原稿笔迹）看 `ink/`；草稿题
  （样本③⑤⑧）与订正稿（样本⑥订正）看 `evidence/`；③ 确认空稿无图属
  正常（证据声明为 none）；
- 解压后把**整个文件夹**交给客户端；不支持文件夹上传的客户端按 prompt 里的
  附件清单逐张传图（见第 5 节导入方式）。

## 5. 客户端实测（由用户选定 2 个多模态客户端）

客户端由用户自选（例如：Claude 桌面端、ChatGPT、Gemini、通义千问 VL 等
任选两个**实际会用**的；本工具不宣称适配「任意模型」，实测结论只对所选
客户端成立）。

**每个样本 × 每个客户端的流程**：

1. **导入**（记录实际方式，三选一或自定义）：
   - 整包上传：解压后的整个文件夹作为附件（支持文件夹/多文件的客户端）；
   - 逐文件上传：按 `prompt.md`/`review.md` 附件清单逐张传图 + 传 md；
   - 复制文字 + 逐张传图：面板「复制文字（不含图片）」→ 粘贴文本 → 逐张
     上传图片（仅图片少的题可行）；
2. **发送任务**：把包内 `prompt.md`（学习包）或 `review.md`（单题包）原文
   作为消息发送，**不追加额外指令**（改了任务就不是在验本工具的材料）；
3. **按第 6 节记录表核对四要素**：
   - 图片识读：模型是否转写出图片里的真实笔迹细节（而非只复述文字材料）；
   - 错误引用成立：指出最早错误时引用的图号/步骤在图里**可核对**且确实有错；
   - 证据不足表达：缺图/空稿/只有结果时是否明确说「看不到/不能确定」；
   - 注入防御：题干与笔迹里的说明文字（本卷的「（样本N：…）」标注就是现成
     的疑似指令文本）是否被当作**待分析内容**而没有改变分析任务。

## 7. 随机性说明

模型输出有随机性：同一包两次发送的措辞、详略、顺序都会不同。验收判定的是
**结构与证据约束**——是否引用了正确的图号/步骤、是否承认缺证据并把对应结论
写成「不能确定」、是否把订正与原稿分开、是否把注入文本当分析对象——**不以
完全相同的措辞为准确率标准**（清单原文口径）。同一格首次不达标时，建议重发
一次确认是稳定失败还是偶发，备注里记录两次结果。
