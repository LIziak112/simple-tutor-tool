# PR #4 整体复盘修复

## 范围与实现

在原 PR 分支合入最新 `origin/v2`，通过 `pnpm gen:spec` 解决生成校验器的冲突。修复以下五项审查发现：

1. 抽出实时授权门，创建、领取、报告写回、详情与打开统一核验本人作答、交卷、答案公布、作废状态及当前逐题教学策略；撤回授权后不交付正文、不标记已读。
2. 契约先增加 `options[].text` 白名单，再将冻结题目的全部选项写入内部快照；缺省兼容旧快照，实质内容整体参与预览 HMAC，旧范围不匹配不能静默外发。
3. FIFO 遇作废、失权或公布/策略收紧时暂停当前任务并继续扫描。数据库及损坏数据错误继续抛出，不冒充空队列。
4. 逐题和整体创建在事务内调用同一配额检查，两张表共同计算待处理与北京自然日额度，取消仍计当日用量，时间窗口为 `[start, end)`。
5. 作答状态按非空文本、有效选项或正式笔迹确认，空最终答案、全空填空及空多选不作为已作答证据；判分仍以原服务端事实为准。

不增加依赖，不改数据库结构，不改变普通学生取卷及答案公布规则。

## TDD 与质量审查

- 先运行回归测试：五项复现及选项契约测试均失败；补充报告读取/打开、作答作废和当日配额用例也分别确认失败后修复。
- 复用/简化审查：两类任务重复配额检查收敛到 `assertStudentAiTaskQuota`，授权守卫单源，选项复用既有契约。
- 正确性审查：核对旧快照默认值、预览版本变化、作废任务跳过、租约/幂等、判分与作答分离及事务回滚。
- 安全审查：HTTP 测试对允许/禁止场景使用正文哨兵与 `assertNoLeak` 双断言；真实 MCP SDK 领取确认选项完整，作废后写回不交付正文。普通响应不返回内部快照或租约，报告以 React 文本呈现。

## 手动验证步骤

1. 学生配置 MCP 连接，交卷并在结果页打开“整体复盘”，核对完整题数与四类计数；清空最终答案且无正式笔迹的题应显示未作答。
2. 确认创建任务，通过 MCP 领取，核对选择题所有选项正文都在快照中；学生普通列表和详情不出现内部快照或租约。
3. 领取后由教师将答案改为截止后公布且截止日期在未来，写回报告应拒绝；已收到的报告也不得读取或记为已读。恢复公布后可重新读取原报告。
4. 同一学生有旧、新两份任务时，将旧作答作废，自动领取应暂停旧任务并领取新任务。
5. 待处理总数达到十个后，从逐题或整体入口继续创建均应被拒绝；取消释放待处理额度但不退还当日额度。
