## 交付与根因

1. `compatibleSurfaceEvidence` 改为保存基准的 left/top/right/bottom 最大绝对差 ≤10 逻辑 CSS px。位移与尺寸不能各放宽 10 导致右边累计超限；块数、tag、已保存 node 和顺序保持严格。字体字符串不独立阻断。文本碎片仅在同结构块内、连续且竖向重叠的行中合并；不按最近距离匹配语义区域，也不合并无结构块归属的片段。
2. `questionSurfaceMatchesLayout` 的 >1px 宽高早退改为 10px；新增 schema 防御。发现旧 1/64px 测量取整会把块偏移 10.001 变成 10，已先 red 后修复：有兼容证据的准入读取精确逻辑几何，历史签名和底图生成默认测量仍保留旧取整，未改旧 hash 算法或原始基准。实测 2px 填空夹具已由现状拒绝转为批准行为放行。
3. 契约先增加 layout v4：`renderVersion=4`、`renderProfile=whole-question-v1`、必填 `compatibility`；不含 `controls`。v2/v3 schema 原义不变。预览、API 解析、IDB schema reader 和同步复用既有契约；正文坐标域与 PNG ready 身份继续精确检查。
4. PUT 的 `protocolVersion` 接受已知 3/4；服务端按底图保存版本精确核对（v3 要 3，v4 要 4），未知底图/损坏布局拒写。同步按所选底图声明能力，升级拒绝仍保留 PNG、pending、mutationId。表结构没变，不需要 DDL。
5. 新 `resolveQuestionSurface` 把来源/正文域判断从图片解码中拆出。它没有图片 URL、下载或解码状态参数，不授予墨层/写权；外层只读仍核验当前冻结 revision。pending/conflict/retained 使用本机基准，不能拿另一个云端布局配本机正文。`base.stale` 反映活题库变化，不替代冻结 revision 身份，不据此误拒旧卷历史。
6. 恢复 `prepareQuestionAnnotationContinuation`，仅供显式开笔补充旧稿证据。原签名未命中不发请求，账号/题目/基准变化拒绝；在途封存时 `applyAnnotationBaseCompatibility` 拒绝补写。被动读取/导出不调用它。补证据不改 PNG、核心 layout、points、pending、正文版本或活动时间。

## 下一单 API

```ts
resolveQuestionSurface(record, questionRevisionId, externalReadOnly = false)
// status: none | metadata-ready | legacy-evidence-required | blocked
// source: null | { kind: local | cloud, baseId: string | null,
//                 layout, pixelWidth, pixelHeight }
// readOnly: boolean; geometry: unverified; reason: string | null

await questionSurfaceMatchesLayout(question, surface, source.layout)

await prepareQuestionAnnotationContinuation(
  session, scope, question, surface, localBase, signal?,
)
// 返回已保留/已补证据的 localBase；不是几何准入或写权判定。
```

- `record` 必须来自当前账号/作答/题目/阶段的严格 store/session 读取；resolver 不在孤立记录里反推账号，不跨键取稿。只读入口也须传当前冻结 `questionRevisionId`。
- `metadata-ready` 仅代表来源与正文像素域可用，`geometry` 恒为 `unverified`。调用方必须等字体/图片/公式与真实题面就绪，再 await `questionSurfaceMatchesLayout`，随后复核当前会话、封存和本机持久化条件，才能显示同框墨层/显式开笔。不能把 metadata-ready 当成浏览器几何已通过。
- `legacy-evidence-required` 覆盖缺 compatibility 的 v2 与 v3。源设备原签名匹配后，显式开笔调用补证据函数；目标设备仍对照最初证据做 10px 判定。补证据网络失败可返回原 localBase，仍须原签名核验，不能伪造 compatibility 或目标设备新基准。
- 新常量为 `ANNOTATION_WHOLE_QUESTION_RENDER_VERSION=4`、`ANNOTATION_WHOLE_QUESTION_RENDER_PROFILE="whole-question-v1"`；兼容模块导出 `ANNOTATION_SURFACE_TOLERANCE_CSS_PX=10`。`measureQuestionSurface(surface, { precise: true })` 可获取无历史量化的逻辑框。
- 后续 UI 单负责开始生成 v4、删除 captureFrozenControls/FrozenFillControls/图片主视图和双视图。当前生成仍为 v2/v3，旧 `resolveFrozenQuestionSurface` 故意保留以确保现有 UI 可用；它的 ready 仍只代表旧图片路线，不能替代新几何判定。
