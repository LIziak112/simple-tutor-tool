# v2.3.0：练习反馈升级——逐题反馈、单题专注与做题方式

第四个正式版本（待发布：本说明随 v2 线验收通过后发布 main）。v2.2 让学生在作答中能按教学策略向 AI 求助；v2.3 解决「反馈的时机与形式」：什么时候看到对错、以什么节奏看解析、用什么布局做题——由教师授权、学生选择、单元推荐三层共同决定，且历史作业与进行中作答的行为完全不变。

- 用户验收清单（真机与人工项，未执行项如实标注）：`docs/releases/验收清单-v2.3.0.md`

## 一句话说明每个学生可感知的变化

- **每题提交后立刻知道对错**：新开的自由练习（课程单元、错题重练）默认逐题反馈——提交一题，当题立刻给判定、参考答案与详解；已提交的题锁定防误改；最后一题提交后整卷自动收尾。
- **作业听老师的**：教师布置作业时可显式开启「逐题反馈」；未开启的作业维持「交卷后统一公布」的旧节奏。教师还能在设置里收紧默认策略，收紧立即对进行中的作答生效。
- **单题专注布局**：做题方式可选「列表作答」（默认，同旧版）或「单题专注」（一次只看一题，配键盘操作：Enter 主动作、←→ 切题、1-9 选选项）。两种布局随时切换，答案与笔迹不丢。
- **做题方式偏好**：学生在 `/s/settings` 保存默认布局与反馈节奏（含「跟随单元推荐」三选）；单元落地页可临时预选；作答中还能换反馈节奏（与服务端 CAS 同步，他端改动会提示刷新）。
- **单元推荐（DSL）**：练习文档 frontmatter 新增 `practice:` 命名空间，作者可推荐布局与节奏；推荐只做标注与预选，不越权——教师限制仍是最终裁决。

## 首发能力边界（不泛称全支持，逐项列实际范围）

| 维度 | 实际支持 | 明确不支持 / 未验证 |
| --- | --- | --- |
| 反馈节奏 | 两档：`per_question`（每题提交后查看）/ `after_attempt`（交卷后查看）；裁决链：续作 attempt 事实 > 学生显式选择 > 单元推荐 > 缺省（新自由练习逐题、作业按教师授权） | 无第三档节奏；教师收紧后学生不可越权选择（服务端收敛到允许项） |
| 逐题反馈内容 | 已提交的当题：判定（对/错/待批）、参考答案、详解；四态裁决（未提交/待批/受限/已释放）——受限态零题目内容 | 未提交题目（含邻题）的答案/详解在任何普通学生接口不可达（键名级+内容级泄露测试族钉住） |
| 布局 | 列表/单题两布局，覆盖七题型；布局是纯呈现维度（客户端 transient），不是权限 | 布局选择不经服务端；硬刷新后回落本机保存的偏好 |
| 键盘 | 单题专注：Enter 主动作（提交/下一题）、←→ 切题、1-9 选中选项；输入焦点在文本框/MathLive 时不劫持按键；repeat 与合成事件保护 | 列表布局不响应这些按键；真实外接键盘与 MathLive 让位待真机抽验（验收清单 A） |
| 偏好存储 | localStorage 仅存版本号+枚举（布局/节奏/快捷键开关），按部署来源+角色+账号 id 隔离；「未设置」是显式状态（跟随单元推荐） | 不存默认反馈节奏之外的内容；无凭据、无答案、无跨设备同步（每设备各自保存） |
| DSL 推荐 | frontmatter `practice: {layout, feedback}` 两键均可选、未知键拒绝；导入、建卷（课程/作业/错题三入口）、落地页、导出往返全链路 | 推荐不进资源库单元列表展示（只在落地页标注）；mixed 文档各单元可各自推荐 |
| 历史兼容 | 迁移前作业、进行中作答、已完成卷、旧 lesson 逐题行为全部维持旧语义；旧客户端（无 workflowVersion）不能无版本覆盖已设节奏的卷 | 旧进行中卷不会「升级」成逐题模式；旧客户端在新卷上按旧协议建卷（缺省节奏） |
| AI 联动 | 「本题完成」（逐题卷=该题已提交；其余来源=整卷已提交）后 AI 按复盘尺度（open_study）回答；任务出站前按当前模式与完成态实时重校验 | 教师刚改设置立即生效；「仅启发」是提示词约束不是保密模式，需要作答期不接触答案须选 post_submit_only |
| 统计口径 | 题级进度（已提交 x/N）与整卷次数分开；待批提前收录，整卷汇总收尾纳入；错题本、课程进度、学情矩阵口径不变 | 教师批改页节奏摘要行为 P1 候选未做（验收清单 C） |
| 性能 | 目标：提交到当题反馈可见 p95 ≤ 700ms（本地部署、无材料上传）；e2e 记录实测值见验收清单 | 未在低配远程真机测速；带材料上传的提交不在此预算内 |

## 数据与运维

- **迁移 `0038`**（drizzle-kit 生成）：`teachers.practice_feedback_policy`（可空）、`assignments.allow_per_question_feedback`（默认 0）、`attempts.practice_workflow_version/feedback_mode/workflow_revision`（默认 0/NULL/0）、`responses.practice_mutation_id/practice_request_digest`。全部默认值 = 旧行为，升级即兼容，无回填。
- **迁移 `0039`**：`units.practice_defaults_json`（可空；坏 JSON/契约不过时读取侧归一 null 并告警，原文绝不透传到学生端）。
- 备份恢复往返已纳入测试（新列不放宽、不丢失）；`secret.key` 与既有备份语义不变。
- 服务端新增缓存纪律：逐题提交回执与题级反馈读取端点带 `private, no-store`。

## 升级与回退

1. **升级**：沿用 `docs/部署.md` 的 tar-over 流程。停服 → 覆盖 → 启动时自动跑迁移 0038/0039（纯加列，秒级）→ 冒烟（教师登录、学生开一份新自由练习、旧作业打开各一次）。**部署前先在本机跑全量测试**（低配机器先停服再构建）。
2. **行为开关即回退面**：不需要二进制回退时，把教师设置里的默认策略收紧、新作业不勾「逐题反馈」，即回到「交卷后公布」为主的旧行为；已经开始的逐题卷可安全续作或自然完成，不会变成打不开的半卷。
3. **二进制回退**：已产生逐题作答事实（responses 行级 submittedAt、工作流列）的数据库**不要**交回不认识这些列的旧版本服务。需要回退二进制时，先用升级前备份在隔离环境演练（备份-恢复链已测试），确认数据影响后再操作；绝不自动回滚线上库、不删除已提交事实。旧版本服务读到新列会忽略（SELECT 按列名取），但不要让它写。
