# v2.2.0：学生端 AI 伴学——三通道求助、教学模式与督学留痕

第三个正式版本。v2.0 解决「讲练批」，v2.1 解决「过程证据」，v2.2 补上「按教学策略受控地把当前题交给 AI」：学生可在作答中向自己选定的外部 AI 求助，教师用三种教学模式控制可用性与回答尺度，平台如实留痕。

## 数据与运维

- 新增 9 张 `ai_*` 表（迁移 `0036`）+ `ai_tasks.archived_at`（迁移 `0037`），全部新表零改既有列；材料文件落 `DATA_DIR/blobs/ai-materials/<sha256>.png`（内容寻址不可变），已纳入备份引用保留清单（`BLOB_BACKUP_REF_COLUMNS`）。
- **发布步骤**（增量迁移，随启动自动执行、幂等）：升级前在教师端「设置 → 备份与恢复」下载完整备份 → 替换构建产物（或 `docker compose up -d --build`）→ 重启 → 观察迁移日志。**禁止对线上库手改 schema 或反向删列**；回退 = `git checkout` 旧版本重建 + 从备份 zip 恢复（应用内恢复带密码确认与恢复前保险快照）。
- **恢复备份的代价**：数据库回到备份时点——备份窗口内的作答、AI 任务、票据、凭证轮换全部失效（迟到回执只留审计事实不写正文，演练实证）；登录会话以恢复库为准，需重新登录。恢复不设额外代价：AI 任务状态持久化于库，created/claimed 照常续跑，dispatching 超时收敛 uncertain。
- **回退路径注意**：0036/0037 只增不改，旧版本代码可读新库结构（多出的表/列不影响旧逻辑），但**不得反向删列**；数据回退走备份恢复，不走迁移反转。
- **降级行为**（演练实证）：AI 全关（post_submit_only/无连接/密钥丢失/材料缺失）时普通作答、交卷、判分、结果查看全部照常；AI 材料孤儿 GC 未接自动调度（与既有 blobs 口径一致），需回收时运维显式调用，被行或备份引用的文件绝不删。
- GC/备份/部署细节见 `docs/部署.md`；本版无新增外部依赖（fetch 直调零新包）。
