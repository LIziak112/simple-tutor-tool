# B19 真机核对清单（SAI-34）

本清单把批次文档《B19-真机与真实客户端.md》的真机 6 步与三通道真实验证逐条
转成**三元组**：人工操作步骤（用户做）＋平台侧可核对的数据点（部署本机能
看到什么）＋自动核对脚本（怎么核对）。供用户拿真实设备/账号执行时照单操作、
照单留证。

## 0. 使用总则（先读）

1. **环境**：用已通过 B18 总验收的 HEAD 构建做隔离部署（独立 DATA_DIR，
   不复用演示站正式数据；演示站抓取项除外）。材料一律合成/匿名。
2. **密钥纪律**：外部 AI 的 API Key、学生 MCP Token、票据明文 token 只在
   界面/环境变量出现，**不写进本仓库任何文件**；本清单与验收记录只记指纹
   掩码与现象。
3. **真实费用调用须用户明确授权**：页内通道对着真实外部 AI 出站会产生真实
   费用。编排者/执行者不得擅自发起；用户授权后按 §2.1 执行，并把「授权范围
   （哪个连接、几次调用）」记入验收记录。
4. **待人工不冒充**：凡需要真机/真实客户端/真实账号的项，一律由用户执行并
   记录；脚本与自动化只证明平台侧证据链，不伪造真机结果（批次文档硬性要求）。
5. **脚本本身已自证**：`apps/server/src/test/b19-verify-scripts.test.ts`
   27 例在合成世界证明四个脚本的断言正确（含逐项破坏检出与 CLI 退出码），
   并随 `pnpm test` 回归。先跑 `seed-demo-world.ts` 试手感再碰真实 DATA_DIR。
6. **只读纪律**：materials-check / trace-audit 只读打开 `DATA_DIR/tutor.db`
   与 blobs，绝不写用户数据目录；mcp-smoke 只做只读调用（不领取不写回）；
   link-check 默认 GET 会计一次 link_viewed（与外部抓取同链路，对账时计入），
   `--head` 预检不记。

## 1. 工具箱（apps/server/scripts/b19-verify/，均不进 CI）

| 脚本 | 一句话用途 | 用法（apps/server 目录下） |
| --- | --- | --- |
| `seed-demo-world.ts` | 临时目录生成合成世界（真实服务写出），先试跑再碰真实部署 | `node node_modules/tsx/dist/cli.mjs scripts/b19-verify/seed-demo-world.ts`，输出 DATA_DIR 后用下面的脚本核对，用完删目录 |
| `materials-check.ts` | 核对服务端实际收到的笔迹材料：页数/尺寸/字节/sha-256 内容寻址/PNG 完整性/页序连续/纸面二选一 | `…tsx scripts/b19-verify/materials-check.ts --data-dir <DATA_DIR> [--task <任务id>…/--latest N]`（默认最近 5 个带材料的任务；`--task` 指定但无材料行的任务显式输出「无材料行」，断网失败核对中无行即预期） |
| `trace-audit.ts` | 平台留痕审计：任务状态/代际/消息/事实序列/票据读取计数 + 七条列⟷事实成对不变量 | `…tsx scripts/b19-verify/trace-audit.ts --data-dir <DATA_DIR> [--task <id>…/--student <id>/--attempt <id>/--latest N]`（默认最近 10 个任务） |
| `mcp-smoke.ts` | 第二协议客户端只读冒烟：匿名 401 / initialize / tools/list 恰四工具 / list_my_ai_tasks | 设 `B19_MCP_BASE_URL`（部署根地址）与 `B19_MCP_TOKEN`（一次性下发明文）两个环境变量后 `…tsx scripts/b19-verify/mcp-smoke.ts` |
| `link-check.ts` | 票据快照核对：七处区块标记（标题+六区块）/no-store/UUID 哨兵/自定义 must 与 must-not 哨兵/材料拉取（按 anchor 真实页号）/过期-撤销-快照变更-缺失拒绝形态 | 设 `B19_LINK_URL=<票据URL>`（推荐，明文 token 不进命令行）后 `…tsx scripts/b19-verify/link-check.ts --expect ok\|expired\|revoked\|stale\|missing [--must-contain 哨兵]… [--must-not-contain 哨兵]… [--head] [--fetch-materials]`（`--url` 参数仍可用于本地试跑） |

任务 id 的来源：学生网页队列「更多 → 练习信息」或任务详情 URL；教师端
/t/data/attempts/:id 督学记录；或直接用 `--latest` 看最近任务。

## 2. 三通道真实验证（批次文档「三通道」节）

### 2.1 页内通道（inapp）

| 项 | 内容 |
| --- | --- |
| 人工操作 | ①（需授权·真实费用）学生连接页配置真实外部 AI（OpenAI 兼容 baseUrl+Key+模型），用合成题**一次纯文字**求助；②再次求助**带多图材料**（圈画+草稿或正式手写多页）；③配置错误 Key 与额度不足 Key 各试一次 |
| 平台侧数据点 | 任务行 status=created→dispatching→replied、generation≥1、`dispatched`/`reply_received` 事实；多图任务的 ai_task_materials 行与 blobs PNG；错误 Key/额度不足收敛 failed+errorText、网页反馈文案 |
| 自动核对 | `trace-audit.ts --data-dir …`（事实序列与状态；failed 时失败摘要）；`materials-check.ts --data-dir … --task <多图任务id>`（页数/尺寸/配对/完整性） |
| 需要什么 | 真实外部 AI 账号与 Key；**用户对真实费用调用的明确授权**（次数与连接记入验收记录） |
| 状态 | 脚本已备（27 例自证）；真实调用待人工+需授权 |

「实际目的地/模型」核对：dispatched 事实 detail 与任务行不存完整出站载荷
（防泄露设计），目的地/模型以学生连接页配置 + 外部 AI 服务商控制台的调用
记录互证，两处记录入验收记录。最后一笔笔迹完整性：materials-check 过后，
人工打开材料 PNG 目视最后一笔在图内完整（脚本验字节不验内容）。

### 2.2 MCP 通道（真实外部客户端）

| 项 | 内容 |
| --- | --- |
| 人工操作 | 学生连接页生成 MCP 端点+Token（一次性下发，记录即失效语义）→ 在外部客户端（Claude Code / Cursor 等，**记录名称与版本**）配置 Streamable HTTP + Bearer → 两道合成题攒队列 → 客户端 tools/list → 逐题领取（核对图像能力检查与附图 base64）→ 逐题写回 → 网页侧查看回信 → 重置 Token 后旧客户端再试（应 401） |
| 平台侧数据点 | 四工具清单；任务 claimed→replied 状态迁移与 `reply_received` 事实；领取附图任务的材料行；重置 Token 后旧 Token 全 401；B17 矩阵未覆盖的真实客户端未知项（非标字段、重试/超时策略、truncated 声明与领取附图超限 413 的实际处理）逐一记录 |
| 自动核对 | 配对后本机跑 `mcp-smoke.ts`（应四步全过：匿名 401/initialize/四工具/只读列表，列表应与网页队列一致）；用户客户端操作完跑 `trace-audit.ts --student <学生id>`（状态与事实和客户端实际行为对账）；重置 Token 后用**旧 Token** 再跑 mcp-smoke 应在 initialize 步 FAIL（401） |
| 需要什么 | 真实外部客户端与其账号；学生测试账号；部署对客户端网络可达 |
| 状态 | 脚本已备（假端点 4 例自证）；真实客户端联调待人工（B14/B17 同项遗留） |

### 2.3 链接通道（上下文链接）

| 项 | 内容 |
| --- | --- |
| 人工操作 | 学生对合成题生成 link 通道任务与票据 URL → 用目标 AI（或抓取工具）读取链接正文与材料 PNG，核对公式/长稿呈现 → 同一链接再次读取（旧链接缓存识别）→ 等过期/撤销后同链接再读 → 复制失败场景核对降级（手动复制/材料下载）；无法确认外部抓取来源时如实记 unknown |
| 平台侧数据点 | 票据行 viewCount/lastViewedAt 与 `link_generated`/`link_viewed(source=unknown)` 事实；过期/撤销后的 403；快照变更后旧票据拒绝（状态码以实测记录） |
| 自动核对 | 用户读取前后各跑一次 `trace-audit.ts --task <任务id>`（link_viewed ×N 与票据读取计数合计应与实际读取次数一致；重新生成链接后按各票合计对账）；`link-check.ts --expect ok --must-not-contain <教师私注片段>/<他题题干片段> --fetch-materials`（授权投影完整+无禁止哨兵+附件可拉取）；过期/撤销/快照变更后 `--expect expired`/`--expect revoked`/`--expect stale` |
| 需要什么 | 真实外部 AI 或抓取工具；合成题里预埋的独特哨兵文本（供 must/must-not） |
| 状态 | 脚本已备（假端点 6 例自证）；真实抓取呈现待人工（B15 遗留同项） |

### 2.4 仅启发模式（guided_only）真实回复检查

| 项 | 内容 |
| --- | --- |
