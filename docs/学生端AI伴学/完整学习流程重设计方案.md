# OwnClass AI 助教：从求助到继续作答的完整设计方案

2026-10-19 · 方案评审稿 · 运行走查于10月18日完成 · 基线 `v2@7dcedb10`

## 1. 本次结论与交付边界

上一轮解决的是容器和部分状态可靠性，没有完成学习流程设计。题下展示是基础布局，不能单独解决不会提问、不知道AI看到了什么、长回复难理解、读后不知道下一步、写了新稿又要重新组织求助这些问题。

本次推荐：**以题目为工作单位，建立“准备求助 → 等待时继续做 → 主动读反馈 → 回题尝试 → 必要时检查新步骤”的循环。** 同一题的历史任务作为材料轮次收在背后；学生主要操作自己的学习动作。

本稿给出可实施的交互、界面、权限与工程边界。配套示意可以切换求助、等待、回信、阅读、继续作答、检查新稿等状态，示例回答经过人工编写，不代表模型一定能生成这样的内容。本轮不修改生产代码、不新增任务、不向真实AI发送材料。

## 3. 信息架构：三个区域，各自只做一件事

1. **题目与纸面**：保留学生正在处理的题、圈画和草稿。助教开合不改变题卡宽度规则，不重挂题面/纸面控制器。
2. **本题AI工作区**：准备求助、看当前反馈、针对反馈继续问。默认位于完整题卡后，属于同一阅读流；显式宽屏对照只换呈现位置。
3. **求助记录入口**：显示新回复和需要处理的任务，点条目直接到对应题与对话。抽屉不再展开全文。默认本次练习，明确入口查看全部来源。

不增加第三条常驻导航轨道。现有答题定位已有空间成本；先把AI状态整合到题号/题旁入口和顶栏记录中。评审书的224px轨道只是候选，并不适合机械地放进1024px iPad。宽度满足时也优先给题面与纸面，轨道不是本次完成条件。

“老师的提示”和“AI助教”保持同组、明确命名：前者是现有老师预置内容，后者会对外求助。避免两个都叫“给我提示”而学生不知是否会发起AI请求。

## 4. 一次完整学习循环

### A. 卡住了：先能发起，再允许细化

- 点本题“AI助教”，打开简洁的准备区；不自动唤起软键盘。
- 默认意图“给个提示”，另外两项为“检查步骤”“解释概念”。学生自定义问法放在“更多问法”，不删除已有配置。
- 补充问题是可选项，示例“我不明白为什么要分两种情况”。默认意图本身构成合法诉求，不强制键入“帮我看看”。
- 选择问法只改变请求草稿，不发送、不覆盖学生已写的补充文字。底层将所选问法与补充文字组装为一个可预览请求，沿用既有question字符串接口。
- 材料条置于发送动作之前：“题目与当前作答 · 未附草稿 [附上草稿]”。只列本题实际可用材料；读取失败显示“材料未能核对”，不能显示“没有草稿”。
- 点“检查步骤”但没有选步骤材料时，就地说明“附上草稿，或把步骤写在下面”，提供两个直接动作。不能把没有材料的检查请求包装成“AI已看过”。
- 主按钮按当前意图和通道命名；页内如“请AI给个提示”。按钮附近显示所选连接名称和“只给提示/可完整讲解”的当前尺度，连接详情收进菜单。
- 默认材料遵循学生已保存的偏好；没有偏好时不暗中勾选手写。用户在发送前能看见、调整本次清单。只有按发送后才冻结并外发。

目标路径：已配好连接的普通提示为“打开 → 发送”两次动作；检查已有草稿最多增加一次明确附上。选择不同问法增加一次选择，不把它算作零操作。

### B. 等待：保留学习位置

- 发送成功后，不强制收起或把题目滚走。在同一个区域显示一行“已发出，可以继续做题”，提供“回题继续做”。
- 学生点返回才回到先前题干/纸面锚点。当前稿继续可写；没有纸面的选择题回原作答控件，不凭空新建草稿。
- 题旁入口保留真实状态。页内显示“AI正在回复”；MCP显示“等待外部AI领取”，并给“查看连接说明”；链接显示“已复制，去所选AI粘贴”，不伪造处理中进度。
- 回信到达只更新预留状态位与记录数。笔画、焦点、滚动和键盘状态不变，不自动增加长正文。
- 用户在等待期间输入的追问草稿可保留；不能发送的原因在按钮旁说明。没有真实服务端进度时，不做百分比动画。

### C. 读反馈：让学生迅速找到有用的一步

- 点“查看新回复”后直接打开对应正文，不再经历“打开面板 → 找任务 → 查看回信”。
- 顶部只保留“第5题 · AI助教”、回题入口、更多菜单。连接/材料详情可展开；发送链路、已查看、完整时间戳不占正文前几行。
- 当前问题压成一行可展开摘要，正文成为视觉主体。默认显示当前轮，其余轮次放“之前的交流（N）”，不按多个物流任务卡平铺。
- 首期按真实Markdown标题生成目录；没有标题时不编造“思路/结论”标签。短回答不加目录。
- 默认提示词建议输出“下一步尝试 → 为什么 → 如何自检”，先给一个能动手的动作。这里是生成质量目标，不是前端从任意长文凭空生成结论。老师自定义模板和外部AI不配合时，仍可安全读完整原回复。
- 核心动作：“回题试一试”；次动作：“这一步没懂”。后者展开唯一追问输入，首次预填“请换一种方式解释这一步”，并可附上学生明确选中的原文段落，选择本身不发送；已有自写追问不覆盖。每段有可触控的“问这段”入口；文本选择快捷操作只是增强，不能成为唯一入口。
- 不增加强制“我懂了”弹窗、不自动给掌握徽章。AI判断不进入可信判分。

### D. 继续写：保留一条回去看提示的路

- “回题试一试”恢复学生进入前的题目或纸面锚点，折叠为紧凑状态条：“上一条提示 [再看一眼]”。不跳到整题最上方让学生再找笔迹。
- 如明确选中某段，可选择“留着这条提示”；显示有长度预算的原文摘录和“看完整”，不把截断摘录冒充概括结论。默认不复制长回复占住草稿。
- 滚动题目不自动切换正在交流的题；答题定位可以反映可见题，但AI头始终写明绑定题号，二者含义不混用。
- 同卷点另一条求助记录，先完成既有收笔/本机落盘保护，再定位与打开目标任务。失败留原处，输入和纸面都在。

### E. 又写了一步：就地交给AI检查

- 只有可靠检测到所选材料版本已变化，才提示“你又写了新步骤”。不能用时间差猜测，也不在每笔落下时弹条。
- “检查新步骤”打开同一个输入区，意图切为检查，材料条明确“本次将发送当前草稿”。学生最后按“发送新步骤”才采集、发送。
- 底层继续创建新任务/新快照，不修改旧任务。界面表达为同题的“新材料一轮”；可见问题摘要标注本轮目标，历史保留原材料时间。
- 若需延续上一条指导，可将学生选中的短原文引用放入新请求预览。第一期不声称AI自动获得整个旧会话，也不声称已做新旧稿逐笔对比。
- “继续问上一条”只沿用旧快照，输入旁显示“这次不会附上新笔迹 [改为检查新步骤]”。这样保留正确语义，又减少“新建任务、重选材料”的认知成本。
- 刷新后无法可靠比较材料版本时显示“上次发送15:43，可发送现在的草稿”，不显示未经验证的“已更新/未更新”。

### F. 本题做完：继续学习，复盘可回找

- 回到现有作答/单题提交流程；AI面板不代填答案、不自动交卷、不因看过回复标掌握。
- 交卷后单题复盘复用同一工作区，正式原稿只读。若结果页当前无新材料采集能力，清楚显示“本次只发送文字与本题上下文”；补接已授权原稿需要独立验收，不能假装已附原稿。
- 整卷复盘表现为按题索引的复盘清单，各题结果仍独立；不把单题授权扩展为跨题全卷总结。

## 5. 面板本身的界面规范

### 5.1 准备求助态

```text
第5题 · AI助教                         [收起]
页内回答 · 当前可完整讲解                  [连接与设置]

希望怎么帮你？
[给个提示 ✓]  [检查步骤]  [解释概念]  [更多问法]

补充问题（可选）
┌ 我不明白为什么要分两种情况……                       ┐
└                                                   ┘

会发送：题目与当前作答 · 草稿2页          [查看/调整材料]
                                      [请AI给个提示]
```

### 5.2 阅读态

```text
第5题 · AI助教                    [回题试一试] [更多]
依据：15:43的草稿                        [查看材料]
你问：为什么要分两种情况？                 [展开]

下一步尝试
先在数轴上标出 −2，再分别向左、向右走5个单位。

为什么要这样做
距离不区分方向，因此两边都要检查。……

[回题试一试]  [这一步没懂]
之前的交流（2）                              [展开]
```

上下两个返回入口服务于长文不同位置；短文只呈现尾部主动作，顶部用低强调文字入口。当前回复引用不是老师的标准答案，应保持“AI回复”标识。不要把提示词生成的标题/重点渲染成已验证事实。

### 5.3 视觉与响应式

- 使用现有学生蓝色语义主题。一个工作区一层表面、一组主要动作；去掉“面板框 → 任务卡框 → 内容框”的重复装饰。保留必要输入边界和错误边界。
- 头部16px/600；正文16px/1.75；主操作14–16px；关键信息14px；次要时间13px。输入至少16px；所有触控命中区≥44×44px，实际量测确认。
- 正文最大约40em（以中文约30–40字/行起步实测），长公式和表格可以使用容器全部宽度。限宽只作用于AI正文，不能收窄作答题卡。
- 常规题下区随页面滚动，不新增固定高滚动盒。长文提供“专注阅读”，同一个正文控制器，仅一个活动编辑器；覆盖层保留底层作答挂载并使用成熟Dialog焦点/返回逻辑。
- 阅读层首期只看内容与追问，不叠加第二套浮动手写画布。需要写时一键回原纸面，避免一次引入两套写入与落盘关系。
- 宽屏“并排对照”是主动选项。按实际题列、纸面、导航和助教最小可用宽度判定，不以设备名称决定；不满足时回题下并保留阅读位置。现有1060px只是当前组合预算，不能把它当成所有纸面状态的通用保证。
- iPad1024横屏、768竖屏、分屏及手机默认都允许单列。较长题干打开AI时，给“前往本题提问区”就地提示，学生主动移动；不能自动越过正在写的长稿。
- 页面交卷底栏在AI输入时缩为次要入口或让出键盘可见区域，避免“发送”和“交卷”两个蓝色主按钮争夺注意；交卷依然可通过顶栏更多访问，实际键盘与安全区需真机验证。
- 不使用打字机、跳动未读点、自动滚到底等高频动画。状态保留文字；焦点和键盘可达性遵循W3C [On Input](https://www.w3.org/WAI/WCAG22/Understanding/on-input) 与 [Status Messages](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html)，不靠抢焦点通知新消息。

## 6. 异常与首次使用：始终能继续学

| 状态 | 就地内容与主动作 | 保留内容/禁止误导 |
| --- | --- | --- |
| 未配连接 | “还没连接AI，问题先留在这里”＋“连接AI” | 返回同题同输入；设置成功不自动发送 |
| 仅启发 | “当前只提供提示与思路” | 完整拆解不成为可用操作；不能承诺模型绝不泄露答案 |
| 完成后可用 | 按场景写“交卷后可用”或“提交本题后可用” | 不展示通用“不可用”；不提前加载隐藏正文 |
| 材料读取/本机保存失败 | 指明材料＋“重试保存/重新读取” | 不能默默丢附件；明确选择仅发文字才改变清单 |
| 模型不能识图 | “这个连接无法读取草稿”＋“更换连接/改发文字步骤” | 不自动换供应商，不假装带图 |
| 已创建任务但上传失败 | “草稿还没传完”＋“继续上传” | 沿用任务和幂等键，不重复新建 |
| 断网或发送状态不确定 | “暂时无法确认是否发出”＋“核对状态” | 不自动重发，不承诺重复调用绝不计费 |
| MCP未领取 | “等待外部AI领取”＋“查看操作说明” | 不用页内AI的“正在思考”制造假象 |
| 链接已复制 | “去所选AI粘贴；回复将在那里查看” | 平台无回信时不标已回复；复制失败可手动复制 |
| 正文读取失败 | “回复暂时没加载出来”＋“重新加载” | 保留未读、原问题与材料信息 |
| 内容过长/公式异常 | “部分内容暂不能排版”＋“查看安全纯文本” | 受字节/节点/公式预算限制；不能放开任意HTML或绕过sanitize |
| 教师临时改变策略 | 当前动作原因＋可用的返回动作 | 请求前重新校验；旧可读缓存不能成为绕过限制的途径 |
| 切题/转屏/关闭/换账号 | 保存保护、显式目标、按账号隔离 | 避免迟到回执覆盖新会话；重新进入按当前权限读取 |

## 7. 对评审建议书的取舍

| 建议 | 本方案处理 | 理由 |
| --- | --- | --- |
| 题下阅读 | 保留并补完整学习动作 | 上轮只实现容器，缺的是读后行动与材料更新 |
| 224px常驻轨道 | 不作为首期默认；复用已有定位和顶栏 | 1024横屏空间有限，增加一栏并不等于降低摩擦 |
| 全宽阅读态 | 纳入第二批完整交付 | 能解决长文；首期不加浮动草稿，缩小状态风险 |
| 材料快照说明 | 变成发送前清单、阅读时依据、更新时明确动作 | 时间戳不能独自解释AI看见了什么 |
| 模板不自动发送 | 严格保留；补充文字不被替换 | 探索问法无需担心误发或丢输入 |
| 收起/关闭同时展示 | 只保留学生能理解的“收起”；不自动重开 | 两个结果接近的按钮会增加判断成本；取消任务单独表达 |
| 自动离屏收起 | 曾按本行实现，2026-10-21 整体摘除：固定对照打开期间侧栏常驻，不再随题卡离屏隐藏 | 与答题卡折叠互相触发，先后引发面板闪动与「隐藏后答题卡不回弹」；滚动闸门/抑制窗补丁堵不住根因，删功能保稳定 |
| 结构化/分段回复 | 先真实标题导航与安全降级，再做可选结构化增强 | 不依赖所有模型遵守格式，不伪造AI提炼的重点 |

## 8. 工程上怎样落地

### 8.1 复用与状态归属

- 任务/消息/许可继续由既有服务端与TanStack Query提供；不另建并行聊天数据模型。
- 一个按账号＋attempt＋question隔离的本地学习工作区状态，保存activeTask、准备/阅读/回题视图、当前意图、补充文字、材料选择、引用段落、题面锚点、阅读锚点。任务级追问草稿仍按task隔离。
- 同卷定位优先调用既有jumpToQuestion和openForQuestion；补充openTask入口，必须先材料恢复和收笔落盘。跨页面导航携带经过校验的question/task定位字段，落地验证属于当前学生与当前attempt，成功或失败都显式消费，避免后台刷新反复抢定位。
- 阅读正文只保留一个活动实例；容器切换不清空上层状态。题卡与手写控制器稳定，重排前flush，失败保持原布局。
- 材料变化用已落盘文档版本/签名比较，不在pointermove中截图。当前采集层能暴露哪些可靠签名需在实施首个探针中确认；无法确认的状态采用“尚未核对”，不会成为实现阻塞或虚假提示。
- 默认问题、引用与补充文字组装后仍使用现有question字段。输入区显示会发送的内容，用户可编辑；引用只来自当前已授权并实际可见的回复。
- 新稿继续走现有新任务API，旧稿追问继续走followup；界面以同题历史组织，不假造两个任务属于同一个服务端会话。

### 8.2 明确需要契约的边界

第一批完整循环可不改服务端数据结构：意图与引用组合为请求文本、题内历史依现有任务列出、导航字段属于客户端路由。默认提示词文本变更虽不改schema，仍须同步契约包中的单源默认与相关测试。

以下能力不能用前端假装实现，若纳入后续必须先改Zod契约、再服务端、再泄露测试：可持久化的跨快照会话关系、跨设备新旧稿签名比较、AI结构化nextStep字段、精准笔迹区域引用、跨题总结。新增持久化字段才走drizzle-kit迁移。本方案不以这些能力为第一批完成前提。

## 9. 验收看学习任务，不只看组件测试

### 9.1 五条必须完整走通的学生任务

1. **不会提问**：没有输入任何文字，使用默认提示完成一次求助；能说出AI会收到哪些材料。
2. **边写边等**：发出后回原纸面继续写，回信到达不改变笔画、焦点、滚动；主动点一次查看即到正文。
3. **不懂某一步**：从具体段落进入追问，无需重打题号、复制长段；草稿和引用可撤销，只有发送才出站。
4. **改完再检查**：回原位置写一步，选择检查新步骤，确认新稿后发送；AI确实收到最新固定材料，旧记录仍对应旧稿。
5. **多题穿插**：第5题等待时做第6题，再从新回复定位回第5题；完成后能回第6题原位置，已有回答/纸面不丢。

增加复盘任务：已提交题的正式纸面保持只读，复盘意见不会自动进入答案或掌握度；批量复盘失败只处理失败项。

### 9.2 可量化的验收目标（不是已达成数据）

| 目标 | 判定方式 |
| --- | --- |
| 默认文字提示≤2次关键动作 | 从题旁打开，到最终发送；不要求额外空文本 |
| 从新回复提示到正文≤1次动作 | 打开目标任务即读，不再二次“查看” |
| 从读答到原书写位置≤1次动作 | 记录锚点与纸面实例；不是仅滚到题干顶部 |
| 更新已有选中草稿并送检≤2次动作 | “检查新步骤 → 发送”，缺图/失败不计正常路径但要可恢复 |
| AI异步到达不改变学习现场 | activeElement、scrollY和笔画文档版本在未操作时稳定 |
| 学生能辨认AI看到的是哪份稿 | 让学生用自己的话回答；不能由开发者代答 |
| 整个任务无需口头指导 | 先邀请3–5名目标学生完成上述任务；记录卡住点与错误判断，定性试用不包装成统计显著性 |

### 9.3 自动化与真机分开

- 自动化：状态转移、材料版本隔离、读取失败未读保持、权限改变、相同任务幂等、长公式/超限纯文本、同卷/跨卷定位；Chromium/WebKit隔离端口，覆盖14题真实长度与105题合成列表、多轮长回复。
- 回归闸门：相关与全量单测、类型检查、lint、构建；接口/契约改动才增加相应生成、迁移与泄露测试。UI任务不引入不必要的判分/解析器改动。
- 真机：iPad Safari横竖屏、分屏、Pencil、软键盘、200%文字放大、VoiceOver；这些结果必须独立记录。
- 体验闸门：上述五个学习任务有一条需要反复解释，或学生不能分清新旧材料，就继续修正设计。测试绿不是体验合格的替代品。
