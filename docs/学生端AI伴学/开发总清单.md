# 学生端 AI 伴学开发总清单

日期：2026-10-15。执行对象：GLM 5.3。范围为 36 项任务，划分 21 个推荐会话批次。任务均未实施，进度以[验收记录](验收记录.md)为准。

## 1. GLM 如何读取和执行

每个新会话读取：根 AGENTS.md、本文件、[需求规格](需求规格.md)的相关章节、当前一个批次文件、依赖验收记录、当前批次所需代码。不要一次载入全部批次原文。

同一批中的任务可以在同一会话顺序完成，但各任务分别保留计划、RED/GREEN、提交与验收结果。批次是控制会话范围的单位，不能把三个任务合成一个大补丁，也不能跳过中间的契约或迁移验证。

批次开始先列出**本批所有任务**的具体文件、实现步骤和测试，等用户或已获授权的审核编排者确认。确认覆盖的范围内可逐任务继续，不必为每个小步骤反复问同一问题。未批准新范围、规则变化或破坏性操作不因“批次确认”而自动获得授权。本文档编制本身不启动开发。

每批为一个阶段，使用独立分支 `codex/student-ai-bxx`，每任务保持可构建的小步提交。完成一批后停止，统一对完整批次 diff 跑 simplify、code-review、适用 security-review，修复并真实验证，再按项目流程合入 v2。下一批从已验收基线开始；main 按正式发布安排推进。

一个批次的推荐任务数不是时间或上下文保证。出现以下任一情况，应在当前任务的干净检查点交接到新会话，仍使用同一批次编号，不改产品范围：

- 反复查找或遗忘已确定契约、接口和失败原因，无法稳定解释当前改动。
- 当前任务尚有未解决失败；不能为了做完本批继续堆下一任务。
- 改动明显超出批准文件，或需要改变已确定产品行为。
- 需要真实账号、外部客户端或 iPad 而环境尚不具备。
- 自动压缩上下文后无法根据交接记录恢复准确状态。

提前换会话不必丢工作。提交仅包含已绿的阶段；未完成 RED/实现保留在明确的工作区，写明未提交文件、失败原因和下一步，禁止强行提交不通过代码或清理他人文件。

## 4. 所有任务共用的完成条件

批次文件中的逐项行为验收必须全部满足，并交付以下共用证据：

1. 对应需求章节和文件变化清楚；没有扩大到当天统计、课程提示词、Solo、改分、DSL 等范围外内容。
2. 先补与业务错误有关的失败断言，记录真实 RED 原因；模块不存在、类型错误或环境故障不能充当全部 TDD 证据。实现后 GREEN，已有普通学生载荷和历史样例回归继续通过。纯文档任务说明豁免。
3. 契约全部来自 packages/contract；新增字段可选/默认、结构迁移和生成产物遵守项目规则；不手改已有迁移。
4. 按代码任务执行定向测试以及 lint/typecheck/test/build，贴真实退出码与必要摘要。批次末审查的是本批所有提交的完整 diff，修复后重新验证。
5. 触及页面的任务补本任务相关组件/浏览器用例，不把所有联调推到最后；B18 再做完整 E2E，不是第一次验证界面。
6. 记录自动化、外部客户端、真机三类结果，人工未做标“待人工”，不得假称全通过。
7. 不提交密钥、真实学生材料、无关生成文件；不触碰用户正常作业端口和数据目录；不自动外发真实材料。
8. 更新验收记录，仅保留当前任务结论和可定位证据；历史提交通过 Git 保留，不复制多份现行规范。

确定性测试基础应在 B00/B01 计划中安排：双教师双学生、跨域相同 questionId、普通/讲练/错题/课程 attempt、冻结题、唯一答案/私注哨兵、固定时钟、fake provider、临时文件 DB/临时 DATA_DIR。测试夹具按需提炼，不为每任务复制一整套世界构造器。

## 5. 验证命令与审查纪律

以下命令在当前任务工作区执行，不使用生产 DATA_DIR。任务包中的测试文件名是本任务拟产出的目标，首次不存在时应先写测试；不可用 `--passWithNoTests` 的成功冒充该文件有测试。

```powershell
pnpm exec vitest run <本任务实际测试文件路径>
pnpm lint
pnpm typecheck
pnpm test
pnpm build
```

接口/页面任务使用实际存在的专项 spec；综合阶段至少：

```powershell
pnpm e2e e2e/student-ai.spec.ts --workers=2
pnpm e2e e2e/mcp-smoke.spec.ts --workers=2
```

E2E 沿用临时库与 8899/5199，不复用用户 5173。改数据库运行 `pnpm db:generate` 并测试升级；改契约运行 `pnpm schema:export` 和按项目要求的 `pnpm gen:spec`，提交产物后重新生成检查零漂移。生成器只能改预期文件，多余变化先定位，不能一股脑接受。

根 AGENTS.md 与用户最新需求共同适用；AI 出口的明确授权例外在 SAI-01 同步入规范。实施时读实际适用技能；本文件不允许伪造 `/simplify`、`/code-review` 或 `/security-review` 已执行。不存在可调用技能时按同等检查清单记录实际审查，报告局限。

## 6. GLM 每批派单模板

```text
本次只执行 docs/学生端AI伴学/批次/<批次文件>.md 中的任务。
读取根 AGENTS.md、需求规格相关章节、开发总清单、依赖验收结论及相关源码。
先确认工作区/分支/Base SHA/已有修改；不得清理他人文件。
为本批所有任务列出准确文件、步骤、测试与提交边界，等待确认。
确认后按任务顺序 TDD，任务自查通过并形成绿色检查点后可继续同批任务。
不得进入下一批，不得自动部署，不发送真实学生数据，不修改范围外功能。
每个任务分别记录 RED/GREEN、验收证据与已知问题。
批次结束停止，按验收记录模板提供当前 HEAD 和完整 diff 范围，等待审核。
若环境、契约或产品行为有实际冲突，写清冲突和可审核建议，不自行放宽。
```

审核者收到：批次号、工作区绝对路径、Base/Head SHA、验收记录与遗留事项。审核者读取实际 diff、复跑关键测试并给“通过/需修改/待人工/环境受阻”结论。实施者与审核者不要同时修改同一工作区。
