# B01 规范与共享契约

推荐一个 GLM 会话顺序执行：SAI-01 → SAI-02 → SAI-03。先读[开发总清单](../开发总清单.md)及[需求规格](../需求规格.md)，以[验收记录](../验收记录.md)确认跨批依赖。所有具体路径相对仓库根，拟新增文件名可按已确认技术方案映射。

本批先提交完整计划，经确认后逐任务执行，任务绿色检查点后才继续。本批结束停止，等待完整 diff 审核；不启动下一批。

## SAI-01

**同步规范与AI外发例外**。前置：00。

### 目标、输入与文件

让实施规则准确表达本次用户已明确授权的 AI 出口，而普通学生 API 继续受保护。输入是已确认的 B00 技术方案、需求规格 §2–3、根 AGENTS.md。

修改 `AGENTS.md`、`docs/技术架构与实施方案.md`、`docs/页面功能清单.md`；核对实际适用的 `.claude/skills/api-endpoint/SKILL.md` 等项目内说明是否存在冲突，只同步与本扩展直接相关的文字，不改与范围无关的技能或全局设置。

### 执行步骤

1. 搜索所有“学生永不返回答案”的现行规则及提示解锁例外，区分普通出口与受控 AI 出口。
2. 在权威规则写明：允许求助时可向选定 AI 发送本题已有答案解析；启发模式也携带；新建/领取/附件/回信交付必须按当前模式验证。
3. 明确三模式的完成定义和 AI 与普通答案公布独立；保留普通取卷/结果/非 AI 导出的规则。
4. 页面清单加入教师全局/学生/作业设置、学生右侧栏/队列/连接、教师事实记录，链接到本目录，不复制一份需求全文。
5. 对照各处枚举拼写、默认值和“无记录不能证明独立完成”的说明。
6. 运行文档格式/空白与链接检查，记录纯文档任务的 TDD 豁免。

### 验收与交接

- [ ] 后续实现者不再遇到同一出口既被授权又被禁止的互相冲突规则。
- [ ] 授权仅限当前题与有效通道，不包含教师私注、其他学生或整讲义。
- [ ] 不通过修改测试工具的全局禁止键规则掩盖泄露。
- [ ] 不改运行代码、schema、迁移或 UI。

交接：列出每处规范的准确位置、为何同步、验证输出；提交只含规范变更。

## SAI-02

**教学配置与预设契约**。前置：01。

### 目标、输入与文件

为教师模式、模板和学生按钮提供唯一共享定义。必读需求 §2–5 与 B00 模式/API 表，复用现有 settings/student/assignment 契约风格。

拟新增 `packages/contract/src/student-ai-policy.ts`、`student-ai-policy.test.ts`，修改 `index.ts` 和实际需要扩展的设置/学生/作业契约及测试。不开始数据库和前端实现。

### 实施步骤

1. 定义模式枚举、继承表示与明确配置表示；继承不能序列化为“开放”，否则无法区分默认和显式覆盖。
2. 定义有效裁决响应：可用性、回答尺度、来源和原因；这些是服务端输出，不是学生可提交的可信字段。
3. 定义教师三类模板与学生 preset：稳定 ID、label、prompt、排序、启用、独立附件偏好；缺省由一个 schema/常量来源提供。
4. 定义读取、暂存提交、版本冲突和恢复默认的请求/响应；恢复默认不能隐式覆盖未确认的个人修改。
5. 把长度、数量和非法字段处理按 B00 明确写进契约，采用推导类型，不在 UI 重抄接口。
6. 写失败测试后实现；生成并检查 JSON Schema/规范产物，确认不出现新 DSL 指令。

### 先写的断言

| 输入/行为 | 预期 |
| --- | --- |
| 新账号/无配置 | 默认开放，仍可区分继承 |
| 学生请求伪造 effectiveMode/teacherId | 不影响服务器权威，按契约拒绝越权字段 |
| 空白名称/空模板/超限内容 | 明确校验失败与中文信息 |
| presets 全部删除 | 合法，不强制恢复四个 |
| 同一 ID 重复/排序冲突 | 不能留下不确定列表 |
| 正式模板与学生 prompt | 分开字段，学生无法提交教师模板更新 |

### 完成条件

- [ ] 公共类型只从契约导出，strict 类型检查通过。
- [ ] 全局、学生、作业各自缺省/继承可往返。
- [ ] 默认 preset 的名称、提示词、附件选择有测试。
- [ ] 生成后没有无关规范变化。

交接：导出符号表、默认值来源、相关契约测试名和生成文件清单。

## SAI-03

**任务、材料与连接契约**。前置：02。

### 目标与文件

定义后续任务的上下文、材料、队列、连接器与事实边界。输入为 B00 已确认 API/状态表、SAI-02 契约。拟新增 `packages/contract/src/student-ai.ts`、`student-ai-api.ts` 及同名测试；修改 exports/生成产物。

### 实施步骤

1. 定义作答定位：本次 attempt 与 response/题目修订归属，不能只传 questionId。
2. 定义文字快照、材料清单与缺失状态：附件类别/页序/版本/尺寸/字节/缺失原因；标准答案解析是合法 AI 内容，教师私注不是。
3. 定义任务状态及允许动作、按题对话、未读/归档、幂等请求标识和上下文版本。处理状态与查看状态分开。
4. 分开内部执行载荷、Cookie 会话公开任务视图、MCP 领取视图、分享视图。Key、租约秘密、内部文件绝对路径不可共用一份公开 schema。
5. 定义连接元数据、首次创建凭证响应、撤销、默认通道、图像能力；明文凭证只在必要创建响应出现。
6. 定义成功/失败/部分成功/暂停与错误码，批量操作可逐项定位；限制全部采用 B00 的字节/数量定义。
7. 生成契约产物并运行所有受影响契约测试；未实现通道只定义已批准契约，不加虚构运行状态。

### 先写的断言

- 合法单题上下文可包含参考答案解析，缺任一者仍合法且有缺失说明。
- 无依据将状态由 pending 解释为已获帮助不属于契约语义；无反馈/无查看可表达。
- 序号、大小、页数、Markdown 与备注超限明确失败，分页游标不能接受任意查询结构。
- public connector/任务 schema 不能包含 secret、lease 或绝对路径；首次凭证响应是单独 schema。
- 同题追问可绑定父对话，不能把另一题 ID 合法拼入一个任务。
- 分享视图仅对应一个快照，不能含个人全量任务列表。

### 完成条件

- [ ] 状态、错误、限额没有分散重复定义。
- [ ] 公共与内部视图边界可用契约测试验证。
- [ ] B00 API 表与实际导出一致。
- [ ] 生成产物提交，下一会话可按符号表直接调用。

交接：接口与导出映射、各视图允许字段、测试输出；停止 B01 等审核。
