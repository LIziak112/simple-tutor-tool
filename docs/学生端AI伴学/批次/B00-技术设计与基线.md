# B00 技术设计与基线

推荐一个 GLM 会话顺序执行：SAI-00。先读[开发总清单](../开发总清单.md)及[需求规格](../需求规格.md)，以[验收记录](../验收记录.md)确认跨批依赖。所有具体路径相对仓库根，拟新增文件名可按已确认技术方案映射。

本批先提交完整计划，经确认后逐任务执行，任务绿色检查点后才继续。本批结束停止，等待完整 diff 审核；不启动下一批。

## SAI-00

**仓库基线与技术设计**。前置：—。

### 目标与入口

先把可实施的设计定下来，使后续会话能按固定契约开发。本任务只调查、运行基线检查和写设计，不建业务表、不发外部请求、不写功能实现。

必读：需求规格全文；根 AGENTS.md；架构文档的技术栈、作答快照、手写、鉴权、MCP、备份恢复章节；现有 `apps/server/src/{app,index}.ts`、`db/schema.ts`、`services/attempt-service.ts`、`mcp/{auth,mount,server}.ts`；前端题卡、设置页、workspace 与当前导出入口。

### 要交付的文件与内容

新增本文件夹的 `技术实施方案.md`；更新 `验收记录.md`。技术方案不是泛泛概述，必须包含：

1. 现有代码映射表：每项职责复用哪个实际符号/文件，哪些拟新增，哪些文件不能修改。
2. 三层策略的完整真值表，区分继承默认与明确关闭；普通作业、课程、错题、讲练逐题的阶段识别。
3. 三通道共同的单题上下文、材料快照、同题对话、任务状态转换、审计事实定义；客户端公开视图与内部视图边界。
4. 契约模块、API 方法/路径/请求/响应/错误码表；哪些操作有副作用、在哪一步校验最新权限。
5. Drizzle 表/列/唯一约束/索引/外键设计；快照写文件与数据库提交、孤儿回收和备份引用保护。
6. 队列领取/续租/幂等/取消/重试/恢复算法，用并发时序说明为什么迟到结果不能覆盖。
7. 首发 API 协议、Key 保存与解密方式、出站目标管理与实际连接防护、运行代际、恢复后凭证策略。
8. 页内/MCP/链接的能力差异、实际可验证的客户端认证范围；缺少能力时如何降级。
9. 具体可修改的限额表：文本字节、图像数量/总量、上下文/回复、任务频率/积压、并发/超时/重试、票据有效期和内容留存；明确单位、错误码、设置归属。
10. UI 接入表、布局收笔保护、输入按题隔离、查询键与缓存隔离；测试文件与夹具、需要人工/真实外部验证的列表。

### 操作步骤

1. 记录 `git status`、分支与 HEAD；识别用户已有未提交/未跟踪内容，不移动或清理它们。
2. 检查实际工具版本与工作区读写/测试能力。GLM 实际模型不能从“Sonnet”别名推定；若无法验证，只标“待验证”，不改用户全局模型配置。
3. 运行 lint/typecheck/test/build；逐条记真实结果，原有失败按可复现原因隔离，不用跳过测试来得到全绿。
4. 跟踪一次现有作答读/写、材料导出、MCP 调用与恢复重开数据库的代码路径，确认设计与仓库一致。
5. 用合成夹具设计具体验收场景。网络能力调查可用协议文档，不需要真实学生数据或真实收费请求。
6. 写出上面的十项设计，逐个标明后续任务归属；凡尚未确定的实现机制提出一个有理由的推荐值，不把关键空白推给每个后续会话。
7. 交接审核。方案没有确认前不启动 B01。

### 验收

- [ ] 文件清单与符号真实存在或明确标拟新增，模式矩阵与需求完全相符。
- [ ] 无“默认关闭”“只限已公布题”等额外产品限制。
- [ ] 每个 API/状态变更有归属、当前策略和幂等设计。
- [ ] B01–B20 所需实现机制有落点，不反复留空“自行决定”。
- [ ] 基线真实结果、环境问题与人工待验清楚分开。

禁止：安装/升级全局工具、改模型 Key、对真实数据库演练、自动改业务代码。交接时附设计路径、Base/Head、基线输出和需要审核者选择的具体技术项。
