# B14 学生MCP闭环

同一会话范围：SAI-25 → SAI-26 → SAI-27。先读[总清单](../开发总清单.md)、[需求规格](../需求规格.md)、技术实施方案和[依赖验收](../验收记录.md)，提交准确计划等确认。每个任务单独测试/提交，通道闭环后停止。真实客户端缺环境时保留待人工，不用mock冒充完成。

## SAI-25

**学生MCP鉴权**。前置：15、16。

### 输入与范围

读技术方案选定的MCP认证方式、SAI-16凭证服务、现有教师 `mcp/{auth,mount,server}.ts`。新增学生 auth/mount、工具实例构造入口与测试，`app.ts`在正确的SPA回退前挂载。

### 执行步骤

1. 建立专属学生MCP端点，外部身份绑定学生/范围/凭证，不接受调用参数自报studentId。
2. 按B00已确认认证方案验证每次请求；首发若仅支持自定义Bearer，明确兼容范围，不伪称已经实现OAuth发现。
3. 独立构建学生工具实例，不把教师server全部注册后仅在tools/list隐藏。
4. 凭证撤销、到期、归档、教师域可用性与当前对象访问实时核对。
5. 传输实例按现有SDK生命周期创建/关闭；错误/Origin/Content-Type/方法处理与协议一致，不套普通API响应壳破坏MCP。
6. 日志与错误不带Token/私密path；浏览器Cookie不能换作MCP凭证，外部凭证不能管理账号。

### 先测

- 无/错/过期/撤销token相同不可探测错误；账号归档立即失效。
- 教师Token到学生端点、学生Token到教师端点拒绝；学生Cookie不等同外部认证。
- tools/list不出现教师工具，直接伪造教师tools/call也无法调用。
- Origin不允许时拒绝，不能用全开放CORS修客户端连接。
- 多请求/异常结束均释放transport/server；教师原MCP冒烟不回归。

### 完成条件

- [ ] 使用真实SDK请求/响应测试，不只单测鉴权函数。
- [ ] 学生身份在所有工具闭包中固定且无教师提权路径。
交接实际端点、认证范围、失效策略与SDK生命周期测试。

## SAI-26

**MCP任务工具**。前置：25。

### 输入与文件

读SAI-12队列、SAI-09上下文、SAI-14事实、SAI-25鉴权。新增学生MCP工具实现与契约测试，工具名以B00表为准。

### 依次实现四类工具

1. 只读列表：仅本人任务元信息，游标分页，无领取/已读副作用。
2. 领取：带claim幂等键和上限，按任务逐条裁决当前模式并装配固定材料；返回当前lease/contextVersion与可用图像，不返回其他题/账号。
3. 续租：只对持有的有效lease，不能跨任务或无限续。
4. 回信：校验queueId/lease/contextVersion/feedbackId和正文上限，沿共享写回逻辑与事实服务，不直接更新数据库。

图片按SDK真实content结构提供；单任务多页与多任务边界清晰，Base64膨胀后的报文也受限。Prompt仅辅助用户操作，不是后台定时调度器。

### 必须先测

- 重放同claim返回同批次；两个客户端竞争只有有效持有者写回。
- 只读list不抢任务；工具副作用annotation真实。
- pending提交后领取采用复盘模式；老师关闭后领取/续取材料/交付一致受限。
- 旧lease/旧contextVersion/重复反馈冲突有稳定错误。
- 多图/长稿超限显式，不静默丢页；一个任务错误不会把另一个题的材料塞进回复。
- 假造未领取任务或其他学生queueId不能写回；MCP与页面接口执行同一规则。

### 完成条件

- [ ] 通过真实SDK调用完成claim→feedback→学生API可读，平台事实正确。
- [ ] 不增加summarize当日学情等范围外工具。
交接tool schema、示例调用、错误与幂等证据。

## SAI-27

**MCP配对与实测**。前置：18、23、26。

### 目标与文件

把学生MCP真正接入学生设置/队列，至少验证一种真实客户端。修改AI设置页与引导、通道选择，新增MCP专项E2E，记录本目录验收材料。

### 执行步骤

1. 显示端点/认证方式、生成命名凭证、一次明文复制、撤销与重连；普通查询只显示掩码。
2. “已配置”和“验证成功/最近使用”分开；没有可靠在线信号不标在线。
3. 向学生说明快捷按钮是入队，外部客户端需主动领取/执行，等待状态真实。
4. 提供按实际客户端版本验证过的配置与“读取求助队列并写回”操作引导；不把所有客户端列为已支持。
5. 用合成题在真实客户端完成领取、图片可见/不支持处理、写回和页面展示；费用和账号由用户掌握，真实操作需授权。
6. 自动化用协议客户端跑完整闭环；人工不可用则记录待验，不mock成真实已通过。

### 验收场景

- 复制成功/失败/不支持剪贴板；明文凭证不能通过普通刷新再取得。
- 撤销后旧客户端马上拒绝，历史反馈与新凭证分开。
- 两题入队可继续写，外部批量处理后各题收到对应回复，不自动切题。
- 客户端不能附Bearer或只支持OAuth时，显示当前不兼容及原因，不改用长效URL密钥绕过。
- 外部未写回时平台保持真实等待，不因工具被调用就显示“学生已看”。

### 完成条件

- [ ] 自动协议链路通过，真实客户端的名称/版本/认证/图片/回写范围有记录。
- [ ] 缺人工验证标待人工，本批不能伪报该通道真实可用。
交接操作步骤与兼容表，停止B14；B15代码实施可在已授权审核明确自动化基线足够时开始，人工缺口保持公开，整体完成仍需补齐。
