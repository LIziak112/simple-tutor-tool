本批先提交完整计划，经确认后逐任务执行，任务绿色检查点后才继续。本批结束停止，等待完整 diff 审核；不启动下一批。

## SAI-04

**统一教学策略裁决**。前置：02、03。

### 目标、入口与文件

实现唯一 AI 权限裁决，所有通道后续必须调用它。读需求 §2–3、SAI-02/03、`requireUsableAttempt`、讲练当题提交和教师域逻辑。

拟新增 `apps/server/src/services/student-ai-access.ts` 及测试；优先拆“查数据库/归属”和“纯配置裁决”两层，不另造作答鉴权体系。

### 实施步骤

1. 使用真实学生和本次 attempt 查归属/可用性，拒绝作废与越权；按 response 绑定冻结题。
2. 用服务端完成状态判断：普通交卷，讲练当前题 submittedAt；错题重练不继承以前完成。
3. 纯函数先判断学生/作业明确 post_submit_only 的关闭，再按作业→学生→教师默认确定尺度；完成后转开放复盘。
4. 产生来源原因，能同时解释多个关闭来源，供设置页和侧栏展示。
5. 参数化时钟和必需状态，以确定性测试验证；不要在纯函数读库/读全局时钟。
6. 暴露统一服务供创建、领取、回复交付、正文/附件/降级出口调用，不允许三个连接器各自抄判断。

### 失败测试矩阵

- 对教师 3 种默认、学生/作业各“继承+3模式”、完成/未完成参数化覆盖；明确关闭不可被另一开放覆盖。
- 全部继承时用教师默认；教师默认关闭但学生明确开放、作业继承时允许。
- 作业明确开放可覆盖学生仅启发，但不能覆盖学生明确完成后可用。
- 未交卷已过截止仍未完成；已交卷未到答案公布时间可复盘。
- 讲练仅已提交当题开放；邻题、重开后的新题不开放。
- 双教师同 questionId、跨学生 response、归档、课程失权、作废卷均拒绝。

### 完成条件

- [ ] 真值表全部有确定结果，无“默认看前端”分支。
- [ ] 业务错误沿用既有归属状态码口径并映射 B00 错误表。
- [ ] 原 answersReleased 和普通结果权限不被修改。
- [ ] 同一裁决可在多个出口重用。

交接：裁决 API、完整矩阵测试与来源字段例子，不开始通道代码。

## SAI-05

**数据库与生成迁移**。前置：03、04。

### 目标与文件

持久化配置、任务、材料、连接和事实。输入是已确认 B00 表设计和 SAI-02/03 契约，不临时自己简化出一张无归属的大 JSON 表。

修改 `apps/server/src/db/schema.ts`，运行 drizzle-kit 产生新迁移，补 schema/升级测试。已有迁移文件禁止修改。

### 实施步骤

1. 核对现有 teachers/students/assignments/responses 与快照外键和复合域，复用已有表关系。
2. 建立必要配置/模板/预设、任务/对话、材料引用、凭证、审计与分享存储；默认/继承可区别，文件只存相对路径和摘要。
3. 添加创建幂等、token hash 唯一与就绪/过期租约/本人游标/按题记录等实际查询索引。
4. 明确删除、软删、归档与留存：不能物理删题或已有作答，不能因取消回信删除正式证据。
5. 先补旧库升级夹具及空库/唯一约束断言；改 schema 后生成迁移并验证迁移内容。
6. 在临时数据目录执行完整升级及数据往返，检查旧作答、旧配置仍可读取。

### 失败测试与验收

- 无配置旧账号升级后默认开放，不统一写成显式开放导致继承消失。
- 同学生相同请求键唯一；不同学生不互相冲突。
- 无效引用不能写入；同 questionId 的跨教师记录仍分开。
- 临时文件 DB 与内存 DB 均能迁移；重复启动不重复建表/丢数据。
- 正式文件/备份引用不会因预设或连接删除级联丢失。

- [ ] 只新增生成迁移；schema、快照元数据与测试一致。
- [ ] 所有索引对应已确认的查询，无范围外预留。
- [ ] 不对用户 DATA_DIR 运行升级/清理实验。

交接：新表/列/索引一览、生成命令、空库/旧库测试证据和删除策略。

## SAI-06

**教学配置后端**。前置：04、05。

### 目标与文件

实现教师默认、学生覆盖、作业覆盖与模板管理的完整后端。拟新增 AI 配置 service/teacher routes，复用 `student-service.ts`、`assignment-service.ts` 和教师会话/域检查，挂载方式沿用现有 Hono 结构。

### 实施步骤

1. 按 B00 API 表提供 get/update/restore；查本人教师域后再查目标学生/作业，不能以传入 teacherId 决定域。
2. 返回原始配置（含继承）及有效裁决/来源，让 UI 不必自行运算一套规则。
3. 写入采用已确认版本并发语义；过期编辑返回明确冲突，不能静默最后写胜出覆盖其他教师操作。
4. 模板与模式保存保持一致；恢复默认只改指定范围，不能顺带重置学生按钮或其他作业。
5. 配置版本更新触发后续生命周期可感知变化，具体任务暂停接入留 SAI-15。
6. 与实际课程/讲练配置对象映射一致：没有作业对象就用学生/教师配置，不新增按课程模板系统。

### 先写的接口用例

| 场景 | 预期 |
| --- | --- |
| 未登录/学生 Cookie | 不允许修改教师策略 |
| 另一教师的学生/作业 | 沿用防探测错误口径，不读出配置 |
| 明确模式改继承 | 写入继承且返回实际有效来源 |
| 保存非法/空模板 | 不更新已生效配置 |
| 编辑版本过期 | 冲突且保留旧服务器值 |
| 恢复默认某模板 | 其他模板、学生偏好保持原值 |

### 完成条件

- [ ] app.request 路由测试覆盖鉴权、校验、正常与冲突路径。
- [ ] 实际调用唯一策略服务，不由路由拼业务逻辑。
- [ ] 教师全局配置不影响别的教师或账号。
- [ ] 返回结构从 contract 导入，统一壳/中文消息符合仓库约定。

交接：真实路由路径、service 符号、版本更新行为、接口测试列表；停止 B02 等审核。
