# B07 任务接口与生命周期

同一会话范围：SAI-13 → SAI-14 → SAI-15。必读[总清单](../开发总清单.md)、[需求规格](../需求规格.md)、B00 技术方案和[依赖验收](../验收记录.md)。先出本批准确文件/步骤/测试计划等确认；批内分别 TDD 与提交，结束停止审核。

## SAI-13

**学生任务API**。前置：09、12。

### 目标、入口与文件

提供学生任务入口，不让前端直接访问内部队列。拟新增 `apps/server/src/routes/student-ai.ts` 与路由测试，挂到实际学生会话子路由；`app.ts` 补正文限额。路径以 B00 API 表为准。

### 实施步骤

1. 为 create/list/detail/update-pending/cancel/retry/opened 等操作使用 contract 校验，路由只做鉴权→校验→service→响应壳。
2. 从学生会话取身份，忽略或拒绝客户端自报身份与 policy；每个任务 ID 查询后核验本人与当前题/作答访问。
3. 创建时固定选择、问题、preset 与材料版本，经统一裁决和上下文/材料服务入队；仅打开页面不创建。
4. pending 更新和重试必须显式动作，保持幂等；错误返回可恢复状态/中文操作指引，不回显参考/路径/密钥。
5. 查询根据当前策略决定可交付内容；禁用后不能靠 detail/list 的反馈正文绕过限制。
6. 列表游标/筛选字段白名单、最大页量与响应大小按契约；从 Hono 实际 AppType 导出前端类型。

### 最小接口测试表

| 操作 | 必测 |
| --- | --- |
| 每个受保护路由 | 无会话、教师 Cookie、参数错误、正常 schema |
| create | 默认已有参考在上下文；未完成禁用→拒绝且无任务/文件副作用 |
| list/detail | 跨账号拒绝；禁用不泄待交付回信 |
| update/retry | 已领取不能更新；同 requestId 不重复 |
| cancel/opened | 事实与处理状态分开；不能替别人取消/标已读 |
| 错误/附件 | 不带其他题、私注、真实路径或 secret |

### 完成条件

- [ ] 所有接口有 app.request 测试，未用前端隐藏代替权限。
- [ ] 原普通学生 assertNoLeak 用例不全局放宽。
- [ ] 接入点遵循现有 JSON/二进制响应模式与 body 预检。
交接实际方法/路径、错误表和单测命令，给 UI 足够稳定调用面。

## SAI-14

**求助事实记录**。前置：12、13。

### 目标与实现入口

独立记录平台实际发生的求助事实，不把一个 status 布尔值叫“辅助”。新增 `student-ai-audit.ts` 及测试，接入队列/出站/回复与后续通道的公共 hook；未实现通道只能预留明确函数，不能伪造访问。

### 实施步骤

1. 定义统一记录方法：request-created、dispatch-attempt/confirmed/unknown、claimed、feedback-received、opened、share-body-read、cancelled 等，以 B00 事实表为准。
2. 时间和阶段由服务端确认：普通卷提交时刻，讲练题行提交时刻；客户端时间只可作为非权威辅助。
3. 请求入队成功与创建事实原子一致，重复请求不写两次；操作失败不记成功。
4. 保存本次 mode/template/context 引用、通道和最小定位，正文材料由受控快照承载；原始学习事件 payload 不塞题文答案。
5. 对外给派生事实摘要：仅入队、已外发、已回信、有平台查看、外部未知；统计按 distinct 本题范围，不能重试一次就增加一题。
6. 归档/取消保留已发生事实；删除与留存按设计，不增加不可删除个人全部数据的隐藏承诺。

### 必须先测

- 打开 AI 栏无求助；请求失败无成功；只入队未外发不能说学生已获帮助。
- 供应商网络中断状态不明，不写“已回复”或“确定未收费”。
- 回信收到但未打开，与平台打开分开；重复打开不重复增题数。
- 链接 HEAD 不记正文访问，GET 读取只记来源未知，不是已读/AI 辅导。
- 提交前请求、提交后领取/打开按各自实际时点保留；迟到客户端不能改阶段。
- 跨账号与教师私注不进入摘要/日志。

### 完成条件

- [ ] 队列事实和处理状态可解释一致，但互不代替。
- [ ] 没有强行生成“独立正确/重度盲区”标签。
交接事件触发点、阶段判定及派生摘要示例，供教师 UI 和 MCP/分享使用。

## SAI-15

**提交与禁用生命周期**。前置：14。

### 输入与文件

读需求 §3.3、§8–10，实际 submitAttempt/submitLessonQuestion/restartLessonAttempt、账号守卫与 backup/DbHandle restart 路径。修改队列/权限/事实服务及必要生命周期 hook，避免在判分函数中塞模型调用。

### 实施步骤

1. 每次真正出站、领取、分享正文/附件、回信交付再做最新裁决，不只缓存创建时 mode。
2. 提交成功让尚未外发任务按完成后规则装配；保留原请求时间，不覆盖为提交后新请求。
3. 提交中途或失败不解锁，AI 未完成/失败不阻塞原有交卷与本机材料保存。
4. 教师关闭暂停未外发；在途回信收存但未完成题不继续交付；已经展示的内容保留事实、不假装撤回。
5. 重新开放要求学生主动继续，不能后台自动把所有积压发送。
6. 重开/作废卷与退出账号使旧操作失效；在途回执只能回到原任务，不能迁写新卷/新账号。
7. 恢复数据库前停执行并使旧运行代际失效，恢复后重新取配置；不能依赖备份内旧 generation 自己排除迟到结果。

### 必须先测的时序

- enqueue→submit→claim：请求为提交前，外发为提交后，使用复盘模式。
- claim→teacher-disable→feedback：存旧事实，不向未完成题新增交付。
- teacher-enable：任务可继续但未自动外发。
- submit 失败→claim：仍按未完成限制。
- lesson Q1 submit：Q1 解锁，Q2 未解；restart 后旧反馈不能进新 Q1。
- restore 期间 provider 晚到、卸载后换学生：均不串库/账号。
- AI 服务抛错不让既有 submit 回滚或漏存原稿。

### 完成条件

- [ ] 提交与领取/回信竞争有明确合法结果和确定测试。
- [ ] 原判分、封存及交卷保护不改语义。
- [ ] 旧分享附件和回信查询没有旁路。
交接生命周期时序图/测试名、暂停与继续动作；停止 B07 等审查。
