# AI 助教三种布局与阅读交互方案

2026-10-21 · 已确认实施方案 · 代码与验证见《三种布局实施与验收记录》

## 1. 目标与定案建议

保留题下阅读，新增统一的布局偏好：**题下阅读、侧边对照、独立弹窗**。学生在 `/s/settings` 的「AI 求助偏好」中选择。三种布局共用同一份任务、回复和输入状态，差别只在呈现位置与空间分配。

默认继续使用题下阅读，已有用户升级后不被突然迁移。独立弹窗是第三种正式布局，不再作为题下阅读之上的另一套对话系统。旧「专注阅读」改为同一工作区的临时放大能力。

本方案的重点同时包含容器和内容：修正「按段落阅读」实际跳转的问题，压缩正文前的管理信息，保证打开后能够立即看到解释，读完能准确回题。

建议布局偏好按当前部署、学生账号、浏览器保存，不跨设备同步。电脑和平板可以分别选择适合自己的方式；用户文案明确写「仅用于当前账号在此浏览器中的显示方式」。这是一项待整体方案确认的产品决策。

## 2. 已核对的现状与问题

核对范围：用户截图，以及 `StudentSettingsPage`、`AiCompanionDock`、`AiCompanionRail`、`ai-companion-layout`、`AiReadingWorkspace`、`AiConversationPanel`、`AiReplyMarkdown`、`use-ai-draft-map` 和现有需求文档。未对当前浏览器执行交互，也未完成新方案的真机验证。

| 当前实现 | 目标行为 | 原因 |
| --- | --- | --- |
| 题下是默认，侧边是临时固定，专注阅读又打开 Dialog | 三种正式布局共享一个工作区，默认由设置决定 | 明确选择与结果的对应关系 |
| 「按段落阅读」从 DOM 收集标题，点击执行瞬间 scrollIntoView | 标题就地展开内容 | 消除名称与实际行为的偏差 |
| 专注阅读复用同一套目录，目录仍排在正文前 | 放大后维持同一段落与阅读位置 | 增加空间的同时保持上下文 |
| 设置只有连接、手感和快捷按钮等入口 | 在 AI 求助偏好最前增加「助教显示方式」 | 布局是学习体验偏好，与连接凭据分开 |
| 固定对照的宽度预算与旧布局控制器存在多个阈值 | 一个测量入口和一套布局决策 | 避免多套逻辑互相切换 |

## 3. 学生设置

### 3.1 位置与文案

在 `/s/settings` 的「AI 求助偏好」下，先显示「助教显示方式」，后显示已有「自定义求助快捷按钮」。连接管理仍在 `/s/settings/ai`，不混入布局选项。

使用带简图的三个单选卡片：宽屏可横排，窄屏纵排。简图使用本地 SVG/CSS，仅表达题目与 AI 的位置；不得以截图文字代替可访问名称。

| 选项 | 说明文案 | 补充规则 |
| --- | --- | --- |
| 题下阅读 | 在当前题目下方展开，跟随页面阅读。 | 默认选中，保留现有使用习惯 |
| 侧边对照 | 在题目右侧查看回复，方便边看边写。 | 空间不足时暂用独立弹窗 |
| 独立弹窗 | 在独立窗口中阅读和追问，关闭后回到原题。 | 当前页面内的弹层，不开浏览器新窗口 |

卡片下显示作用域说明，以及「保存显示方式」和有改动时的「取消更改」。选择只修改草稿，保存成功后生效。成功反馈「显示方式已保存」；失败明确提示「未能保存显示方式，请重试」，保留选择，不虚报成功。

### 3.2 编辑与返回

- 支持键盘方向键选择、Tab 导航、明显焦点与选中标记，不仅依靠颜色。
- 设置后台更新不覆盖未保存编辑；存在外部更新时提示并提供载入已保存值。
- 有未保存更改时，普通页面导航提供放弃确认。布局区与快捷按钮区独立保存；一处保存不清除另一处的 dirty 状态。
- 工作区菜单提供「显示方式设置」，跳到 `/s/settings#ai-display`。来源信息复用已有受限站内返回机制，保留 attempt、question、task 和原位置；不接受任意外站 returnTo。
- 去设置前依既有规则收笔并确认本机落盘。读取或保存失败时保留现场，不跳走。AI 输入继续用学生角色内存缓存，不新建持久化副本。
- 返回后使用已保存布局；取消修改则沿用原布局。刷新页面后的阅读位置恢复不作额外承诺，账号布局偏好仍保留。

## 4. 三种布局的完整行为

### 4.1 题下阅读

- 保留在所属完整题卡之后、下一题之前的位置，不进入题面底图或采集副本。
- 与页面使用同一个纵向滚动，不新增固定高度滚动盒。打开不改变题卡外框宽度。
- 关闭完整工作区后保留紧凑入口和回复状态，不展示第二份正文。
- 用户主动打开且入口不可见时，才进行最小必要定位；收到回复、展开段落、后台更新不驱动整页跳转。
- 提供「放大阅读」，临时进入独立弹窗；退出返回题下原位置，不改设置。

### 4.2 侧边对照

- 固定放在右侧，保持与左侧题号导航的角色区分。本期不增加左右方向配置、自由拖拽或浮动窗口。
- 侧栏有独立正文滚动；主作答区可以继续操作。AI 绑定题号始终可见，主区滚动不自动换题。
- 初始设计预算为 AI 栏 416px、间距 16px、题列至少 560px，另计实际导航和容器内边距。这些是实现与验证起点，最终以题面、纸面布局和真实可用宽度决定，不能只用 viewport 或设备型号。
- 打开前先收笔落盘，按已有规则处理题面缩放与标画坐标。不得仅压缩笔迹或重排底图内容。侧栏开启不能改变题卡相对所属题列的填满策略。
- 可以按现有用户状态恢复规则暂收左侧导航；用户主动展开导航后优先尊重操作，空间不够则转独立弹窗。
- 空间不足时说明「当前空间不足，已用弹窗打开；你的侧边偏好仍保留」。无须每次弹 Toast，工作区轻量提示即可。
- 从侧栏退到弹窗后，本次打开期间不自动弹回侧栏；空间恢复后可主动「恢复侧边」，否则下次打开重新计算。避免旋转、软键盘和宽度临界值反复搬动正文。
- 侧栏关闭后仅恢复由系统临时改变且用户未再次操作的导航状态。

### 4.3 独立弹窗

- 宽屏居中展示大 Dialog，建议初始最大宽度 960px、高度不超过动态视口 90%；正文阅读列约 42rem，额外宽度用于合理留白，不强制拉长行宽。
- 窄屏为接近全屏或全屏 Dialog，包含安全区；同一组件响应布局，不在内部叠加第二层专注阅读。
- 顶部固定显示「第 N 题 · AI 助教」、材料入口、菜单和关闭。正文占主要空间，输入区位于底部且限制高度。
- 弹窗启用时背景不可操作，作业交卷栏不能盖在回复上；底层题卡和纸面保持挂载。
- 打开不自动聚焦输入触发软键盘，焦点先到工作区标题或适当容器；读屏获得题号与用途。
- Esc 和明确关闭按钮返回原入口与页面位置。为避免误触中断阅读，本期点击遮罩不关闭；正在输入时关闭保留草稿。
- 窄屏软键盘出现后输入仍可见，正文维持可滚动，顶部与底部固定区不得挤成零高度。实际验证后确定最小高度与输入最大行数。

### 4.4 偏好与临时呈现

| 保存偏好 | 打开条件 | 实际呈现 | 退出临时状态 |
| --- | --- | --- | --- |
| 题下 | 任意支持尺寸 | 题下 | 不适用 |
| 题下 | 主动放大阅读 | 独立弹窗 | 回题下原阅读处 |
| 侧边 | 空间与纸面适配条件满足 | 侧边 | 关闭回原作答处 |
| 侧边 | 空间不足 | 独立弹窗 | 关闭；下次重新计算 |
| 侧边 | 主动放大阅读 | 独立弹窗 | 条件允许回侧边，否则留弹窗并说明 |
| 弹窗 | 任意支持尺寸 | 大弹窗或窄屏全屏 | 关闭回原作答处 |

自动降级和临时放大都不写入保存偏好。菜单不再同时堆放「固定对照」「回到题下」「专注阅读」三个互相竞争的入口，使用「放大阅读／还原」与「显示方式设置」。

## 5. 回复阅读重设计

### 5.1 内容层次

工作区从上到下为：题号与控制 → 紧凑材料依据 → 当前回复 → 学习动作／追问。模式作为简短状态，连接配置收进设置入口；历史按需展开。首次求助显示编辑区，有回复后优先回复，不能重复展示输入框。

正文建议统一 16px、1.75 行高；标题层次清楚，段间距一致。长公式与宽表格局部横向滚动，不造成整页横向滚动。保留现有安全清洗和公式预算。

### 5.2 真正的按段展开

- 有两个及以上可分节标题时显示分节阅读，首节默认展开，后续节显示标题和展开图标。点击标题在当前位置展开，再点收起，可同时展开多节。
- 提供「展开全部／收起其余」；不再默认铺一份可跳转目录后又铺一份完整正文。少于两节时直接读全文。
- 标题前的引言保持可见，不为无标题回复编造总结或章节。只有总标题加多个子标题时，总标题作为回复标题，以子标题分节。嵌套小标题留在所属节内。
- 仅从当前活动 AI 回复的 Markdown 语法树确定分节，不混入用户提问、历史回复或隐藏正文标题。代码块中的 #、公式、引用里的标题不能被正则误切。
- 分节在完整文档解析后组织展示，保留跨节链接引用等文档语义；不将每节字符串独立解析而破坏引用定义。
- 段落有稳定标识，由任务、消息版本和语法节点位置确定；重复标题也能区分。
- 展开时保持标题可见位置，不调用全页 scrollIntoView。只在确实被面板固定栏遮挡时做局部最小修正，浏览器默认滚动锚定不得与手工补偿同时叠加。
- 恢复状态用「消息版本 + 节标识 + 节内偏移」，像素位置只作兜底。布局改变后文字换行，不能仅恢复旧 scrollTop。
- 收起包含当前焦点的内容前把焦点放回该节标题。所有展开按钮提供 aria-expanded 与 aria-controls。
- 不能可靠分节或渲染预算超限时使用既有安全纯文本阅读，不放宽 HTML、图片或链接规则；完整回复先做总预算检查，不能靠分节绕过限制。

### 5.3 追问与继续作答

- 「这一步没懂」可以引用当前节或选中文字，放入唯一输入框，允许编辑；不自动发送。
- 「回题继续写」关闭或收起工作区，恢复原题与书写位置；再次打开恢复本题阅读状态。
- 「带新稿另问」切到材料准备与编辑，保留旧任务。只有明确发送才重新采集和出站，旧稿追问不重采。
- 同题切历史任务保留各自输入与阅读状态，当前回复优先展示；历史记录入口只负责定位，不再建立并行全文阅读系统。
- 新回复以提示呈现，不替换当前正在读的版本，不自动滚到底部；学生主动查看后切换版本并初始化该版本的分节状态。

## 6. 状态、保存与技术方案

### 6.1 契约与持久化

先在 `packages/contract` 新增展示偏好 schema，建议字段为 `version: 1`、`layout: inline | side | dialog`；类型由 Zod 推导。没有配置时默认 inline，旧版本、损坏 JSON、未知布局安全回退且不影响取卷。

本期仅本地展示偏好，不增加学生 API 或数据库字段。持久化键复用项目部署命名空间，并按 student 角色和账号隔离；登录身份确认后读取，禁止旧身份迟到回调覆盖当前选择。若现有命名空间不区分同源不同部署，需要明确补齐来源，不自行创建含糊的全局键。

仅保存布局及存储版本；不保存题目、回复、输入、材料、Token、API Key 或阅读历史。退出清理内存，账号隔离的布局值可保留供本人下次登录使用。存储不可用时继续允许默认阅读；保存失败保留设置草稿并提示，不能显示已保存。

同浏览器多标签保存通过现有可订阅机制或 storage 事件同步。阅读中不强制切换容器，新的保存值下次打开生效；设置页无编辑时同步，有编辑时提示冲突而不覆盖。

### 6.2 控制器和视图边界

- 一个上层会话控制器持有绑定题、任务、材料轮次、输入和发送状态。
- 一个展示控制器管理保存偏好、实际布局、临时放大、打开原因、返回锚点和空间判断。
- 一个阅读状态层持有消息版本、展开节、阅读锚点及历史展开状态；存于学生角色内存，按 attempt/question/task/message 隔离。
- 题下、侧边、弹窗只负责壳、焦点与滚动宿主。切壳允许视图重挂，但控制器、草稿、任务不能重置；任何时刻只有一份活动正文和一个输入框。
- 将旧 `AiCompanionRail` 与 `AiCompanionDock` 的布局判断收敛到共同入口，先盘点真实调用方，再删无用路径；不要只新加第三套布尔状态。
- 复用现有 React、Radix Dialog、TanStack Query、Markdown/KaTeX 管线。不新增第三方依赖或 CDN。

### 6.3 手写和权限边界

布局变更先通过既有收笔／本机落盘入口；失败保留纸面、当前布局和输入，明确重试。旋转触发的浏览器自然缩放无法阻止，但组件不得在失败时卸载纸面或改写逻辑坐标，应保持稳定底图并允许必要的局部浏览。

布局选择不改变三教学模式、题级锁定、已提交材料封存、普通学生接口防泄露或受控 AI 出口。查看材料继续使用既有授权投影；新的分节渲染不得改变清洗边界。新增 API 若在实施中变得必要，必须先重新说明范围，并补新端点泄露测试。

## 8. 验收标准

### 8.1 自动化

1. 默认题下不变；三种选择保存后刷新可恢复，同浏览器另一账号互不串用。
2. 设置后台更新、跨标签更新和保存失败都不丢本地编辑；选择未保存不影响作答页。
3. 侧边不足时用弹窗，恢复空间不反复跳；持久化仍为 side。
4. 放大还原、关闭重开、设置往返、历史任务切换均保留应保留的草稿和阅读状态；退出换账号清理。
5. 点击节标题只展开该节，不大幅改变页面滚动。至少覆盖重复标题、总标题与子标题、无标题、引言、代码、长公式、引用链接。
6. 全局只有一份活动正文和输入，背景纸面节点保持；聚焦、Tab、Esc、屏幕阅读器标签正确。
7. 新回复、后台重取、状态变更不自动替换活动版本或滚动抢位。
