## 2. 三层策略真值表与阶段识别（十项之二 · SAI-04 实现裁决函数，SAI-05 落表，SAI-06/07/08 落配置 API/UI）

### 2.1 存储形态

- 教师默认：`ai_teacher_settings.defaultMode`（无行 = 未设置 = `open_study`）。
- 学生/作业覆盖：`ai_policy_overrides`（无行 = 继承；有行必为三显式值之一——**未配置与显式禁止天然可区分**，满足需求 §3.1）。
- 值域：`open_study`（默认）| `guided_only` | `post_submit_only`；无第四模式（需求 §2.3 明确不建"提交且到公布时间"模式）。

### 2.2 合并算法（两步，`resolveAiPolicy` 纯函数，27 组合的规范式）

输入：teacherDefault ∈ {open, guided, post}、studentMode ∈ {inherit, open, guided, post}、assignmentMode ∈ {inherit, open, guided, post}、本题是否完成。

- 课程练习/错题重练/讲练逐题：assignmentMode 恒按 inherit 处理（无作业配置，需求 §3.1）。
- **第一步（作答中可用性）**：`studentMode = post` **或** `assignmentMode = post` → 作答中不可用（明确关闭不可被绕过）；两者皆继承时 `teacherDefault = post` → 不可用（继承默认生效）；否则可用。
- **第二步（回答尺度，仅可用时）**：`assignmentMode`（显式非 inherit）> `studentMode`（显式）> `teacherDefault` > `open_study`。
- **完成后**：无论合并结果如何，本题完成后一律按 `open_study` 复盘尺度（需求 §2.1 表末行、§3.2 表末行）；作答中不可用的题在完成后自动开放复盘，无需重连。

关键真值行（与需求 §3.2 表逐行对应；完整 48 组合由 SAI-04 测试矩阵锁定）：

| # | 教师默认 | 学生 | 作业 | 作答中结果 | 来源标注 |
| --- | --- | --- | --- | --- | --- |
| 1 | open | inherit | inherit | open_study | 教师默认 |
| 2 | guided | inherit | inherit | guided_only | 教师默认 |
| 3 | post | inherit | inherit | 作答中不可用 | 教师默认 |
| 4 | open | guided | open | open_study | 作业覆盖学生 |
| 5 | open | post | open | 作答中不可用 | 学生明确关闭（作业开放不能绕过） |
| 6 | open | open | post | 作答中不可用 | 作业明确关闭 |
| 7 | post | open | inherit | open_study | 学生显式覆盖教师默认 |
| 8 | 任意 | 任意 | 任意 | 本题完成后 → open_study 复盘 | 完成态判定 |

继承语义辨析（实现要点）：**继承 ≠ 明确 open**。第 3 行教师默认 post、学生继承 → 不可用；第 7 行学生显式 open → 可用。两步算法里"继承"回退到上一层，"显式值"参与覆盖与关闭判定——`resolveAiPolicy` 返回 `{ usable, mode?, reason: 'teacher_default'|'student_override'|'assignment_override'|'student_closed'|'assignment_closed'|'teacher_default_closed'|'completed' }` 供配置页与学生端展示有效模式及原因（需求 §3.2）。

### 2.3 阶段识别（"本题完成"，`questionPhaseOf(db, attempt, questionId)`）

| 作答场景 | 完成判定（服务端唯一口径） | 备注 |
| --- | --- | --- |
| 普通作业（assignment） | `attempt.status ∈ {submitted, graded}` | 填完/交卷失败/收起纸面/到截止均不算 |
| 课程练习（course） | 同上（该次 attempt） | 重做 = 新 attempt 按新卷状态 |
| 错题重练（wrong） | 同上 | 每次 attemptNo 递增的新卷 |
| 讲练逐题（lesson） | 该题 `responses.submittedAt ≠ null`（题级，attempt-level answerRelease 不适用） | 邻题提交不解锁本题；整卷完成不回锁已提交题 |
| 任何来源 | `attempt.abandonedAt ≠ null` → 一切 AI 读写拒绝（`ATTEMPT_ABANDONED`） | 讲练重开：旧卷任务停为不可用、旧链接失效，新卷重新判模式（需求 §12） |

提交前/提交后归属（审计事实维度）：每个事实落库时由服务端按当时 `questionPhaseOf` 判定 `beforeSubmit` 布尔；客户端迟到上报不改写（§3.4）。

### 2.4 动态变更语义（SAI-04/12/15）

- 可用→禁用：未外发任务置 `paused`（保留问题与快照，不丢弃）；已外发不可追回；未展示的旧模式回信收存但本题完成前不交付（`replyDeliveredAt` 保持 null）；链接新读取与附件访问一致拒绝。
- 禁用→可用：`paused` 任务由学生显式「继续发送」恢复，不自动外发。

## 3. 单题上下文、材料快照、同题对话、任务状态、审计事实（十项之三 · SAI-09/11/12/13/14）

### 3.1 单题上下文（服务端装配，内部视图）

装配函数（拟）`buildAiContextBundle(db, { attemptId, questionId })`，输出固定快照：

- 题型、题干 Markdown（含选项列表，公式保留）、考点/难度（快照内字段）；
- 本人当前答案：`responses.answerJson` 反序列化为可读文本（fill 逐空、choice 选项文本、手写题标注"答案在笔迹材料中"）；
- 已有标准答案 `answers`、官方解析 `solutionMd`——三缺失态按需求 §4.1 显式标注（"暂无官方解析"/"无固定参考答案"/"缺少参考答案与解析"），不伪造；
- 学生问题 + 当时有效提示词快照（教师模板正文 + 模式硬约束句，模板删空时仅保留硬约束句——需求 §5.1）；
- 材料附件引用（§3.2）；
- 版本锚定：全部读 `questionSnapshotJson` 与该 responses 行，**不读当前题库**（教师改题不影响本任务；历史回信永指原材料）。

注入防御：学生备注/题面/笔迹文本作为待分析数据包裹（review-pack 注入防御句同款），不拼进 system 指令段。

### 3.2 材料快照

- 采集（客户端，SAI-10）：选定圈画/草稿/正式手写 → `AttemptEditorProvider` 收笔 → 本机落盘确认（draft-store/note-store strictRead + saved 态）→ `loadOngoingPaper` 语义取固定稿 → `renderNoteImages`/`renderInkSnapshot` 从固定矢量重绘（不截图活动画布、无预测点）→ 分页 PNG 上传。圈画材料 = 固定底图 + 笔迹重放合成（导出同款坐标配对，不混用草稿坐标域）。
- 服务端（SAI-11）：multipart 接收 → 字节限额校验 → 内容寻址/不可变路径落 `DATA_DIR/blobs/ai-materials/` → 行插 `ai_task_materials`（先写临时文件→事务插行→rename，同 note_versions 模式）；读取失败/缺件 → 任务创建被拒并指明失败项（不虚报已附图）。
- 服务端不实现笔迹渲染（现有渲染器全在浏览器侧；导出管线已验证）。**待拍板项 D3**。

### 3.3 同题对话

- `ai_messages`（role: `student` | `assistant`）：首条为任务问题，追问递增；同题对话 ≤ 20 轮（§9）。
- 追问上下文重建：system（当时提示词快照）+ 上下文快照（文字）+ 历史 messages + 新问题；**只引用本题当前对话**，不注入其他题、当日概况或其他题队列历史（需求 §4.3）。
- 新材料发送 = 新任务（新快照），旧任务继续显示"回复基于之前发送的材料"；同任务追问不自动重新采集笔迹（需求 §4.2/§7.4）。

### 3.4 任务状态机（SAI-12/13/15/17）

```
created ──dispatch(页内)──▶ dispatching ──成功──▶ replied ──学生打开──▶ (delivered)
   │                          ││
   │                          │└─HTTP 已发出但结果未知(崩溃/超时)─▶ uncertain
   │                          └─出站前校验失败/教师禁用──▶ paused ──学生继续──▶ created
   ├─MCP claim──▶ claimed(lease) ──写回──▶ replied
   │                 └─lease 过期──▶ created(可再领取；迟到写回仅记 late_reply 事实)
   ├─取消──▶ cancelled（claimed 后取消：阻止交付，回信仍入库为事实）
   └─失败──▶ failed（可显式重试，retryCount+1）
```

- 状态转换全部服务端事务内；`beforeSubmit` 在 created 与 replied 落库时各判一次（作答前入队、提交后才领取 → 发送时采用完成后复盘规则并显示阶段变化，任务不伪装成提交前已获帮助——需求 §8）。
- 提交作答不等待 AI 回信；交卷链路零改动（AI 队列故障不变成交卷失败）。

## 6. 队列算法（十项之六 · SAI-12 核心，SAI-13/15/17/26 消费）

better-sqlite3 单进程同步事务：同一进程内无真并发竞态；要防的是**多客户端并发领取、进程崩溃、迟到回执、备份恢复**。

- **创建**：事务 { requireUsableAttempt → resolveAiPolicy → 幂等键查重（命中且同参数 → 返回原任务，误触重复点击只产生一次）→ 限额检查 → 插行 created → fact task_created }。内容或材料变化 = 新任务（不同 mutationId）；待领取任务更新须学生显式操作（覆盖快照前确认），已领取任务输入不可替换（需求 §8）。
- **页内派发**：dispatch 事务 { 重校验策略/完成态（最新权限在出站前一步）→ 置 dispatching（generation+1，先落库）} → fetch 出站 → 成功：事务 { 写 ai_messages(reply) → replied → facts dispatched+reply_received }；失败：failed + retryCount。**迟到结果不覆盖**：回写按 `(taskId, generation)` CAS——dispatching 落库后任何人（暂停/取消/教师禁用）都无法改变"这一代已出站"的事实；回信到达时若任务已 paused/cancelled → 回信入库（审计保留）但 `replyDeliveredAt` 置 null 且本题完成前不交付（§2.4）。
- **崩溃窗口**：dispatching 且超过 60s 无回执 → 置 `uncertain`（状态待确认）：界面显示"发送结果待确认"，提供核对（查看是否已有回信）与显式重试（重试前明示可能重复计费），**绝不自动重发**（需求 §8）。
- **MCP 领取**：claim 单事务 { select status='created' AND channel='mcp'（含 resume 后）按 createdAt FIFO → 置 claimed + leaseToken + leaseUntil=now+10min → fact dispatched(claimed) }；写回 { leaseToken 匹配且未过期且 status 仍 claimed → 写回 replied }。租约过期由领取/查询路径惰性清理（claimed AND leaseUntil < now → 回 created 可再领取）。**迟到回执**：leaseToken 不匹配或已非 claimed → 拒绝写任务正文，仅记 `late_reply` fact——后领取者的结果不被先领取者的迟到结果覆盖（CAS 语义）。
- **取消**：created/paused → cancelled（事务+fact）；claimed → cancelRequestedAt 标记（回信到达仍入库为事实，不交付）；已出站不可拦截，事实保留。取消不撤回已外发信息、不保证退费（界面如实说明）。
- **恢复（重启/备份恢复）**：全部状态持久化于库 → 恢复后 created/claimed（租约按上述惰性回收）照常；dispatching 超时 → uncertain；票据 tokenHash 在库 → 恢复后继续有效；会话按恢复语义重新登录。
- **并发时序例**（为什么迟到结果不能覆盖）：
  ```
  T0 学生 A 创建任务 k(g=1) → T1 教师改 post_submit_only → T2 学生点发送：
    dispatch 事务重校验失败 → paused（未出站，无事实漂移）
  T0' 页内任务 k(g=1) 已 fetch 出站 → T1' 教师禁用 → T2' 回信到达：
    (k, g=1) CAS 匹配 → 回信入库为事实；任务态 paused → 不交付，完成前学生不可见

    leaseToken X≠Y → 拒绝写正文，仅记 late_reply —— 学生看到的是 Y 的有效回信
  ```

## 7. 首发 API 协议与凭证安全（十项之七 · SAI-16，SAI-17 执行）

- **协议**：OpenAI 兼容 `POST {baseUrl}/chat/completions`，`stream:false` 首发（是否流式由 SAI-17 实测后决定，协议字段预留）。选型理由：GLM/DeepSeek/Kimi/通义/OpenAI 兼容网关全覆盖；**fetch 直调零新依赖**（硬性规则 5）。Anthropic 原生协议不首发（待拍板 D4）。
- **Key 保存**：AES-256-GCM，根密钥自 `DATA_DIR/secret.key`（`loadOrCreateSecretKey` 既有）经 HKDF/sha256 派生 `ai-connection-key`；库只存 ciphertext+iv+tag+指纹（keyHash 前 8 hex）；明文只在写入请求出现一次，任何读接口/日志/链接不出现。secret.key 随备份打包 → 恢复后解密照常；**secret.key 丢失（异机迁移误操作）→ 解密失败 → 连接置 needs_rekey，学生重填，不静默失效**。
- **出站目标管理**：baseUrl 必须 http(s) + 带主机名；DNS 解析后拒绝私网/环回/链路本地段（10/8、172.16/12、192.168/16、127/8、169.254/16、::1、fc00::/7、0.0.0.0）——SSRF 防护；重定向不自动跟随（如跟随则逐跳同规则复核）；仅允许 443/8443 及显式声明端口？——不限制端口但保留私网拦截（自部署内网 GLM 网关是真实场景，**待拍板 D5**：默认拦私网 + 教师管理员级"内网 baseUrl 白名单"开关，或完全放开）。连接测试 10s 超时、真实调用 60s。
- **运行代际**：`ai_tasks.generation`——每次出站尝试自增并先落库；回执/写回全部带代际 CAS（§6）；进程重启不续发旧代际。
- **恢复后凭证策略**：见上（secret.key 随备份；丢失 needs_rekey；票据/任务行随恢复库继续）。
- 出站请求体不含：学生内部 UUID（材料图像无法避免笔迹中姓名，首次知情已声明）、教师私注、其他学生数据；User-Agent 固定标识 + 任务 id 便于网关侧对账。

### 7.1 个人用户 MCP 凭据查看（2026-10-17）

本人学生会话的连接列表、创建与更新响应可以返回完整 MCP Token，均为 `Cache-Control: no-store`。复用现有凭据密封能力，在 `configJson.tokenSealed` 可选字段保存密文，认证仍使用 `tokenHash`；不变更表结构。历史哈希无法还原，旧连接继续认证并提示手动重置一次后可持续查看；解密失败或密文与认证哈希不匹配时返回 null，不自动更换凭据。API Key 仍只写不读；任务、MCP 上下文、分享与日志不含连接凭据。

## 8. 三通道能力差异、认证范围与降级（十项之八 · SAI-16/25/28/30）

| 维度 | 页内 AI | 远程 MCP | 上下文链接 |
| --- | --- | --- | --- |
| 认证 | 学生 Cookie 会话（既有守卫） | Bearer 学生受限 token（`ai_connections` channel=mcp 的 tokenHash；明文在本人连接设置持续可见，库内保留密文与认证哈希） | 票据本身（无登录可读——外部 AI 无 Cookie，**待拍板 D8**） |
| 出站方向 | 服务端代发（凭证不出服务端） | 外部客户端主动拉取 + 写回 | 学生复制 URL 出去；读取即出站 |
| 能力上限 | 单题同步问答+追问 | 攒题批量、逐题写回、长时处理 | 只读；无写回（不冒充双向） |
| 平台可确认的事实 | dispatched/replied | claimed/replied | link_viewed（不能证明谁读、是否已辅导） |
| 回复位置 | 伴学栏内 | 伴学栏查看 | 默认在外部 AI；平台只有发送记录（"回复在外部，平台未取得"） |
| 失败形态 | 连接超时/Key 错/费用尽 → 明确错误码 | 无人领取 → "等待外部 AI 领取"（不显示"AI 正在思考"） | 抓取失败 → 复制文字/下载图降级 |

客户端认证范围实际可验证项：Cookie 会话有效期与续期（既有）、MCP token 撤销即时性、票据过期/撤销/禁用三态拒绝；不可验证项（如实声明）：外部 AI 是否真的读了链接、是否识图、是否常驻。缺能力降级：模型不支持图片 → 发送前说明并允许仅文字（材料选择处显式提示，不偷偷丢图）；剪贴板不可用（HTTP 部署 secure-context 坑，见记忆 http-deploy-secure-context）→ 复制降级为显示可手动复制内容；无 fetch 能力的外部 AI → 复制文字+下载材料（同遵守策略与留痕）。
