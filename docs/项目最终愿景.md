# 项目最终愿景（最终产品形态）

## 定位与主线

线上一对一辅导老师的**自部署、AI 原生**轻量教学工具。产品是一条可循环的主线：

**老师用 AI 等工具制作出符合规范的 MD → 导入平台，自动渲染成可互动的讲义与练习 → 学生线上答题 → 老师从后台获取做题痕迹与数据 → 数据可交回 AI 统计整理，服务于后续课程。**

这条主线里，本工具最核心的资产是**规定好的数据结构**：上游，符合结构的 MD 能被自动转成讲义和练习；下游，讲义和练习产生的作答数据是结构化的，能被 AI 轻松统计与整理。工具因此简单、轻量，但天然是 AI 原生的。

围绕主线，最终产品由三部分组成：内容流水线（核心引擎）、学生端、教师端；以及对未来的 AI 探索方向（第四部分）。

## 一、内容流水线（核心引擎）：MD 进，互动页面出

1. **导入即用**：老师用 AI 或其他工具制作出**符合格式规范**的 `.md` 文档（讲义、练习册或两者混合），在教师端选择或粘贴导入，系统自动识别类型、解析、上架——中间零手工整理。
2. **自动解析**：练习自动结构化为题库（单元、题号、题型、难度、考点、答案、详解）；讲义按"第 X 讲"自动切分成篇。
3. **自动渲染、可互动**：Markdown 与数学公式自动渲染为排版良好的页面。**页面不是静态文档，而是互动的**：讲解默认折叠、学生点击才展开；答案与详解在交卷后才出现。既避免一眼望到底，也把"想一想再对答案"变成产品行为。
4. **可管理**：老师对习题和讲义有完整管理能力——列表查看、预览、编辑、删除、调整顺序与组织归类。内容是可维护的资产，不是一次性的导入物。

## 二、学生端：看讲义、做题、看自己的记录

页面结构：**输入姓名进入 → 讲义 / 练习 / 我的记录** 三个区域。

1. **零门槛进入**：浏览器打开链接，输入姓名即用；免安装、免注册。
2. **看讲义（互动）**：讲义列表 → 阅读页，公式排版正确、自动目录、例题解析折叠点击展开。
3. **线上答题**：判断/选择/填空点选即答，交卷自动判分；计算/应用等过程题在网页手写作答（保留笔迹原图）。交卷即见对错、参考答案与详解（此时才展开）。
4. **做题记录**：学生能看到自己的历史做题记录——每次练习的时间、得分、逐题对错；错题可回看题目、自己的答案、手写原图与详解。做题不是交完卷就散了，记录沉淀在学生名下，可随时翻阅。

## 三、教师端：管理内容、获取数据

页面结构：**内容管理 / 作答数据 / 导出** 三个区域。

1. **内容管理**：习题与讲义的导入、预览、编辑、删除与组织；题库可备份与恢复。
2. **作答数据**：按学生查看每次提交——逐题答案、自动判分结果、手写原图、每题用时；**做题痕迹与花费时间等数据**都可从后台查看；主观题一键批注正确/错误并写评语。
3. **总结性学情**：不只是逐份记录，还要能一眼看到总结性的信息——哪个学生做了/没做，错了哪些题，错在哪类考点，历次趋势——为下一节课讲什么提供直接依据。
4. **导出**：提交记录可导出 CSV 归档。

## 四、对未来的探索：AI 原生的教学工具

本工具虽轻，但**定位是 AI 原生**——真正嵌入老师的教学过程，减轻备课与备考压力。方式不是内置一个大模型，而是**守住数据结构契约，让 AI 在闭环的两端随时接入**：

1. **制作端（AI 产内容）**：格式规范本身是对 AI 友好的契约——把规范和样例交给任何 AI，它产出的 MD 即可直接导入为讲义与练习。老师的工作从"写材料"变成"审材料"，讲义与练习的设计过程被大幅简化。
2. **数据端（AI 读数据）**：作答数据是结构化 JSON（谁、哪题、对错、用时、笔迹、批注），可以整包交给 AI 做统计整理——错误分布、薄弱考点、下次课的讲解建议——产出老师直接可读的学情总结。
3. **闭环转动（远期探索）**：AI 根据学情数据自动生成下一份针对性练习（错题变式、薄弱考点加练），再回到制作端导入——"测 → 析 → 练"循环转动，工具成为老师教学过程的一部分而不只是布置作业的入口。

对应的产品化方向（均为探索项）：教师端一键导出"AI 可直接分析的学情数据包"（结构化数据 + 预置提示词）；AI 学情报告页；基于错题的变式练习生成。

## 五、产品形态约束

- **自部署**：老师在自己电脑或云服务器上跑一个进程（零第三方依赖），两端由同一服务提供；
- **数据自持**：题库与作答记录都是老师机器上的文件，不经任何第三方平台；
- **轻而 AI 原生**：保持简单轻量，但数据结构两端开放，AI 可随时接入任何一环；
- **学生零负担**：一个链接 + 姓名，免打印、免拍照上传、免装 App。

| 互动讲义（讲解折叠点击展开、答案交卷后才出现） | ✅ 部分实现（例题解析已折叠；答案仍在学生端数据中，可被提前看到） |
| 学生线上答题（客观题自动判分 + 手写笔迹 + 交卷反馈） | ✅ 已实现 |
| 教师查看作答数据（逐题、手写原图、用时、批注） | ✅ 已实现 |
| CSV 导出 | ✅ 已实现 |
| **学生端做题记录**（历史成绩、错题回看） | ⬜ 未实现（交卷后记录只在教师端可见） |
| **教师管理习题与讲义**（单条编辑/删除/组织） | ⬜ 未实现（当前仅导入与整库覆盖，无单条管理） |
| **总结性学情**（按学生聚合的错题/薄弱考点/趋势） | ⬜ 未实现（当前只有逐次提交的原始记录） |
| **AI 学情数据包 / AI 学情报告** | ⬜ 未实现（数据本身已结构化，具备前提） |

| 作答草稿防丢（刷新/锁屏后恢复） | ⬜ 未实现 |

即：主线"导入 → 渲染 → 互动答题 → 数据回收"已经跑通，且数据两端对 AI 友好；最终产品还差四块——**学生端做题记录、教师端内容管理、总结性学情、AI 学情数据包**——它们共同把工具从"答题回收页"变成嵌进教学过程的 AI 原生工具。
