```

3. 逐条对照该任务的「验收」自查，说明每条如何验证。
```

### 0.2 规则

- 严格按编号顺序执行；「依赖」未完成不得开始。每个任务一个分支 `task/T4.x`，验收通过后合并到 `v2`。
- **每个任务结束时应用必须完整可用**：`pnpm e2e` 必须保持全绿（若任务改变了 E2E 覆盖的流程，在本任务内同步更新用例）。
- **契约优先**（硬性规则 1）：涉及数据结构的改动先改 `packages/contract` 的 Zod schema 再实现，完成后运行 `pnpm schema:export` 并提交。
- **学生端任何新增/修改接口都必须接入 `assertNoLeak` 泄露测试**（硬性规则 3）。
- **域隔离红线（沿用 T2B 口径）**：教师端每一个按 id 取数的新接口，都必须有「教师乙访问教师甲资源 → 404」的服务测试。
- **事件语义只增不改**（T4.0）：既有 11 种事件的语义、payload 结构与 `activeSec` 计算口径不得改变（与 DSL 兼容规则同精神）；新事件进契约枚举后，服务端对旧客户端（不产生新事件）零影响。
- 数据库结构变更走 drizzle 迁移；存量数据回填放 migrate.ts 流程内执行、带完成标记幂等（T2A.1 模式）。
- 带 🧑 的验收项需要用户本人手动检查。完成后在 `docs/进度表.md` 打勾。

### 0.3 本阶段明确不做

- 内置 AI（BYO-Key、一键报告、变式生成、预批改——全部属 Phase 5）。
- 实时看板/推送（学情为查询式页面，不主动推送）。
- 原始事件流的管理界面（教师端只看派生指标，events 表不提供浏览/导出原始行的界面）。
- 学生端学情页（学生只保留 Phase 3 的「我的记录」与错题本）。
- 修改 DSL 语法、`pnpm gen:spec` 产物、判分规则。

## 2. 设计决策（已定，实施时不得更改）

> 标注「用户定」为 2026-09-28/29 用户拍板或确认推荐；标注「T2A/T2B」为改进清单既有修订；标注「默认」为按 Phase 3 判分链推演的既定口径，如需推翻请在对应任务下达前提出。

### 学情指标（T4.1/T4.2）

- **D1 统计口径总则（T2A.9）**：全部指标以 `finalCorrect` 为准；**作业取全部作答；课程练习默认取首次作答（attemptNo=1）**，重做次数作为独立指标单独展示（历次明细可展开，见 Phase 3 T3.1 详情页）。
- **D2 完成矩阵范围（用户定，按推荐）**：学生 × **作业 + 可见课程单元**（列 = 未开始/进行中/已交/已批；课程单元列含做过的次数与首次得分），与 T2A.6 课程进度矩阵呼应，总览一眼看全。
- **D3 课程维度（用户定，按推荐）**：不单做「课程学情页」；学情总览页顶部提供**按课程筛选**（含「全部」），指标口径不变。
- **D4 待批题口径（用户定，按推荐）**：`finalCorrect = null` 的题**不计入正确率分母**，单独显示待批数（正确率 = 判对 ÷ 已判定题数；与 Phase 3 D2 的 scoreFinal 分母=全部题是两个并列口径——scoreFinal 是「这份卷子的得分」，正确率是「已判定题的对率」）。
- **D5 时间口径（用户定，按推荐）**：周趋势按自然周（北京时间、周一起算、取 `submittedAt`）；「下节课重点」周期默认 **14 天**、页面可调；学情页时间范围默认**最近 30 天**，快捷项 7 / 30 / 90 天 / 全部。
- **D6 用时异常题（沿用架构 §5.8）**：> 该题用时中位数 2 倍**或**提示数 ≥2；中位数按**本教师域内该题全部已交作答**计算。
- **D7 教师域（T2B）**：全部学情查询按会话教师隔离；MCP/导出同口径。

### 学习痕迹采集（T4.0）

- **D8 events 表补 `studentId` 列**：新增列 NOT NULL；存量回填——有 `attemptId` 的事件按 attempt → student 回填，无 attempt 的存量讲义事件（存量极少）回填不了的历史行允许 NULL 并在代码层兼容（只读聚合按非空过滤）；此后所有落库事件（含无 attempt 的讲义事件）必须携带。出处：T2.10 验收记录已预告「events 表无学生列，T4.x 学情统计需『谁读了讲义』时再立项加列」。
- **D9 讲义阅读会话（补齐最大缺口）**：讲义端点契约从只收 `lecture_expand` 扩展为接收讲义域事件组（进入/离开讲义页 = lecture scope 注入 `page_visible`/`page_hidden` 的讲义版本，`visibilitychange` + `pagehide` 双兜底，与 attempt scope 同款机制），使「哪名学生、哪篇讲义、读了多久」可计算。
- **D10 离线语义（用户关注点，先澄清再落地）**：离线期间**事件不会丢**——T2.10 队列离线时写 IndexedDB、恢复后自动补发（`apps/web/src/lib/event-queue.ts` 已实现）。缺口在于**没有「网络状态」这个上下文标记**：分析侧无法识别「这段作答是在离线状态下完成的」。落地：新增 `net_offline` / `net_online` 标记事件（window online/offline 驱动，attempt 与 lecture scope 均注入），并由服务端聚合成「离线作答时长占比」派生指标。
- **D11 事件增强清单（全面完善，P0 必做 / P1 重要 / P2 可选）**：见 §4 T4.0 的清单表——题目操作（手写橡皮/撤销重做/全屏进出）、提示使用深化、讲义滚动深度与目录跳转、网络状态标记。**全部为新增事件类型，不改既有 11 种事件的语义与 activeSec 口径**。
- **D12 事件量与 payload 纪律**：高频信号（滚动、笔画）必须**节流/阈值化后才上报**（滚动按 25/50/75/100% 阈值各至多 1 条；手写交互按操作批次聚合）；payload **不存题目内容**（learning-event.ts 既有注释原则），只存 id、序号、计数与时间戳；`clientTs` 毫秒约定不变。
- **D13 聚合而非透传**：原始 events 不进学情页、不进 AI 数据包（D18/D22 之外无任何原始事件出口）；一律由服务端聚合成派生指标（activeSec/hintsUsed/changeCount 模式的延伸：讲义阅读时长、离线作答占比等），聚合在 SQL/服务层按需计算，**不建新表回写**。

### AI 学情数据包（T4.3/T4.4）

- **D14 模块化定向导出（用户定，核心重构）**：不做「一键全量 zip」。导出中心五步向导——① 范围（学生多选 / 按课程 / 按作业 / 时间范围，交叉）② 内容模块（分组多选，清单见下）③ 任务目标（决定 prompt.md）④ 隐私选项 ⑤ 预览（包内文件清单 + 预估大小）→ 生成 zip。内容模块清单：

| 分组 | 模块（独立勾选） | 数据来源 |
| --- | --- | --- |
| 教学内容 | 讲义：仅大纲 / 大纲 + 勾选小节全文 | `lectures`（H2/H3 目录既有） |
| | 题目：仅题干 / +参考答案 / +解析 | 题目快照 |
| 学生作答 | 逐题答案与对错判定、教师评语 | `responses` |
| | 作答汇总（得分、状态、历次） | `attempts` |
| | 手写过程 PNG（默认关，体积大） | `ink` |
| 学习痕迹 | 每题派生指标（有效用时、提示数、改答次数、离线占比） | `responses` + T4.0 聚合 |
| 历次口径 | 全部历次（带 attemptNo 与首次标记） | — |

- **D15 历次口径（用户定，按推荐）**：数据包收录**全部历次作答**（带 attemptNo 与「首次」标记）——AI 能看到重做进步曲线；T4.1 指标层默认首次的口径（D1）不适用于数据包。
- **D16 化名与隐私（用户定 B）**：**默认化名**（学生A/学生B…，按导出名单顺序编号）；zip 内附独立的 `映射.txt`（化名 ↔ 真名，仅教师本地保存，**不进 pack.json**）；「包含真实姓名」为需二次确认的开关。pack.json 的学生字段在化名模式下只有化名与 id 无关标识。
- **D17 prompt.md 任务目标模板（用户定，四种 + 自定义）**：诊断薄弱点 / 备下节课讲解建议 / 生成变式练习（输出 DSL v2）/ 阶段总结（可用于家长沟通）；模板按勾选的内容模块自动拼装（如未勾选手写过程，提示词中不提笔迹）；支持自定义提示词附加段。
- **D18 大小与体积（用户定，按推荐）**：手写 PNG 默认不包含；数据包总大小上限 **50 MB**，超限在预览步骤提示精简（减学生/减 ink/缩时间范围）。zip 用 archiver（技术栈清单内）。
- **D19 LearningPack schema 模块化**：按勾选模块分 section 定义（content/attempts/traces/summary），未勾选的 section 不出现在 pack.json；`summary.md` 只统计勾选模块；schema 进 `packages/contract` 并 `pnpm schema:export`。

### 备份与恢复（T4.5）

- **D20 备份范围（用户定，按推荐）**：**全量 DATA_DIR**——db 快照（VACUUM INTO）+ `blobs/`（笔迹）+ `shared/`（共享发布，T2B 新增）+ `secret.key`（Phase 5 加密密钥），排除 `backups/` 自身；下载 zip 同口径。架构 §5.10「db + blobs」的旧口径在 T4.7 收尾时更新。
- **D21 恢复安全（用户定，按推荐）**：恢复弹层需**输入登录密码**确认；执行前自动再做一次快照（回滚保险）；恢复 = 校验 zip → 替换 DATA_DIR 内容 → 重启数据连接；恢复后以恢复库中的会话为准（当前登录会话可能失效，属预期，页面提示重新登录）。

### MCP（T4.6/T4.7）

- **D22 apiToken（用户定 + T2B.8）**：每位教师独立 token（`teachers.apiToken` 列，T4.6 起**启用并加唯一索引**）；设置页**可随时查看**（不做「只显示一次」）、可重置；重置后旧 token 立即失效；格式 randomBytes(32) base64url。MCP 全部操作按 token 绑定教师隔离域。
- **D23 工具清单定稿（架构 §5.9 表 + T2A.9/T2B.8 增补 + 用户确认）**：`get_dsl_spec`、`lint_markdown`、`import_markdown`（默认 dry-run，`confirm:true` 才写入，导入到 token 教师的资源库）、`list_students`、`list_assignments`、`list_courses`（新增：AI 需要课程上下文）、`get_lecture` / `get_unit`（按资源库 id 读 Markdown，T2A.9 增补）、`get_student_learning_pack`（复用 T4.3 打包服务，参数对齐 D14 模块）、`get_question_stats`、`save_report`。**不提供任何删除类工具**。
- **D24 reports 表（用户确认最小集）**：`id / teacherId / studentId / title / markdown / source('mcp'|'manual') / createdAt`；教师端在学生画像页查看（Markdown 渲染）、可删除，不做编辑。学生端不展示报告。

### 页面（T4.2/T4.7）

- **D25 考点正确率图型（用户定，按推荐）**：条形图（按正确率升序 top N，薄弱考点在上），不用雷达图；ECharts 按需加载（技术栈清单内）。
- **D26 AI 连接说明页（用户确认）**：通用 MCP 配置 JSON 片段 + Claude Desktop 专属示例，均一键复制；显示 token 与服务器 `/mcp` 地址（按 PUBLIC_URL 生成）。

## 4. 任务

### T4.0 学习痕迹采集增强（前置，本阶段地基）
- 依赖：Phase 3 完成（T3.6）；无数据库外的其他前置
- **详细方案独立成文**：[`docs/T4.0学习痕迹采集增强方案.md`](T4.0学习痕迹采集增强方案.md)——含现状盘点（全部代码/文档引用）、缺口分析、新事件清单（P0/P1/P2）、服务端聚合指标、前端接入点、实施产出与验收、供外部 AI 复核的重点清单。**T4.0 的执行细节以该方案文件为准**（该文件经外部 AI 复核后定稿）；下达 T4.0 时，§0.1 提示词的阅读清单追加该文件。
- 要点摘要：
  - `events` 表 + `studentId`（drizzle 迁移 + migrate.ts 幂等回填；服务端从会话写入，前端不传——T2.10 验收记录预告过的「谁读了讲义」缺口）。
  - 讲义阅读会话事件（`lecture_visible`/`lecture_hidden`）：补齐「哪名学生读了哪篇讲义多久」这一最大缺口（现状：lecture scope 不注入 page 事件、讲义端点只收 lecture_expand）。
  - `net_offline`/`net_online` 离线标记。**澄清**：离线期间事件本就不丢（T2.10 队列写 IndexedDB、恢复后补发），缺的是「这段作答发生在离线状态」的上下文标记。
  - P1 事件：讲义滚动深度（25/50/75/100% 阈值化）与目录跳转、手写橡皮/撤销重做（防抖聚合计数）/全屏进出；P2（hint_close、math_keyboard_toggle）经用户确认取舍。
  - 服务端派生指标（纯函数 + 测试）：讲义阅读时长、阅读深度、离线作答时长占比、手写反复度——供 T4.1/T4.3 消费；原始 events 不出库。
