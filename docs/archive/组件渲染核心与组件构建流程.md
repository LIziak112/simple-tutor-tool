# 组件渲染核心与组件构建流程

> 用途：定位组件渲染核心、指导新增组件、作为审核时的对照清单。
> 依据 2026-10-06 代码快照整理，文中行号会随代码演进漂移，定位以**文件 + 函数/符号名**为准。
> 2026-10-06 评审补充：本文描述当前实现与既有流程，不代表全部约束已经落实。已确认缺陷、待验证风险、改进建议与验收标准见 [渲染核心评审与改进建议](组件渲染核心评审与改进建议.md)。本次仅整理文档，未修复业务代码。

## 一、总览：三层架构

组件（指令）体系分三层。**新增纯展示指令通常不需要修改底层语法解析器**；涉及题目结构、答案、公开投影、媒体或学情统计的能力，还必须检查对应的语义处理和服务端链路。

| 层 | 位置 | 职责 |
| --- | --- | --- |
| ① 数据契约（注册表） | [packages/contract/src/directives.ts](../packages/contract/src/directives.ts) | 声明每个组件：语法类型、位置语境、属性 schema、文档 |
| ② 语法树 → 宿主标签 | [apps/web/src/features/markdown/remark/](../apps/web/src/features/markdown/remark/) | remark 插件把指令节点转成 `directive-container/leaf/text` 三个宿主标签 |
| ③ 宿主标签 → React | [apps/web/src/features/markdown/directives/index.tsx](../apps/web/src/features/markdown/directives/index.tsx) | `directiveComponents` 查表渲染，未知指令优雅降级 |

数据流（DSL 原文 → 页面）：

```
导入时（服务端）：
  md 原文 ── lintDocument（解析 + 规则校验）──► issues 阻断/提示
        ── parseDocument ──► Question/Unit/Lecture 结构化入库
                              （sourceMd 原文 + stemMd/答案等派生字段，不存渲染 HTML）

展示时（浏览器）：
  获准展示的 Markdown 片段 ─► remarkParse/frontmatter/math/gfm/directive
          ─► remarkBlank（[[…]] → blank 行内指令）
          ─► remarkDirectiveHost（指令 → directive-* 宿主标签 + 语义编号）
          ─► rehypeKatex ─► rehypeSanitize（白名单）
          ─► react-markdown components 接管 directive-*
          ─► getDirective 别名归一 ─► directiveComponents 查表 ─► React 组件
```

两端使用相同种类的 remark 前置插件（frontmatter/math/gfm/directive），但插件链分别维护。语法基础相同不等于题干扫描、脱敏、目录、编号等语义自动一致，仍须共同规则和跨端测试保证：
- web 端插件链见 `RichMarkdown.tsx` 的 `remarkPlugins`
- md-dsl 端 processor 见 [packages/md-dsl/src/v2/shared.ts](../packages/md-dsl/src/v2/shared.ts) 的 `processor`

服务端负责最终校验、结构化入库、重解析、判分与学生载荷投影；教师编辑器也会在浏览器调用 `lintDocument` 做预检。客户端预检不替代服务端校验。学生题干必须来自服务端公开投影，不能把教师域 `sourceMd` 直接交给渲染器。当前投影边界仍有已确认问题，见评审报告 R01–R03。

## 二、渲染核心

### 2.1 单一入口：RichMarkdown

文件：[apps/web/src/features/markdown/RichMarkdown.tsx](../apps/web/src/features/markdown/RichMarkdown.tsx)

- 组件 `RichMarkdown`：外层 `DirectiveTelemetryContext.Provider` + `ReactMarkdown`
- remark 链：`remarkFrontmatter(["yaml"]) → remarkMath → remarkGfm → remarkDirective → remarkBlank → remarkDirectiveHost`
- rehype 链：`rehypeKatex → rehypeSanitize(richMarkdownSanitizeSchema)`
- components 映射：`directive-container / directive-leaf / directive-text` → 三个宿主组件

已核对的主要页面展示入口包括：教师导入预览（`pages/teacher/BatchImportPreview.tsx`）、开发调试页（`pages/dev/RenderDevPage.tsx`）、题干/详解（`features/teacher-attempts/AttemptDetailQuestionCard.tsx`）、讲义学生端（`pages/student/StudentLectureViewPage.tsx`，挂 `onDirectiveTelemetry` 上报 `directive_interact`）及学情中的 Markdown 内容。服务端导出原文或结构化数据不等同于调用 React 渲染入口；新增打印、导出视图需单独声明展示策略。

### 2.2 自定义 remark 插件

| 文件 | 关键符号 | 作用 |
| --- | --- | --- |
| [remark/remark-directive-host.ts](../apps/web/src/features/markdown/remark/remark-directive-host.ts) | `remarkDirectiveHost()`、`HOST_TAG_BY_TYPE`、`annotate()`、`walk()` | 指令节点经 `data.hName/hProperties` 变宿主标签；指令名放 `directive` 属性（避开 sanitize 的 name clobber），`.样式类` 放 `dclass`，语义编号放 `index`（第 N 题/提示 N/步 N/空 N），文档全局序号放 `dindex`（遥测定位） |
| [remark/remark-blank.ts](../apps/web/src/features/markdown/remark/remark-blank.ts) | `remarkBlank()`、`BLANK_PATTERN`、`replaceBlanks()` | 题干 `[[…]]` 填空标记 → 名为 `blank` 的 textDirective；跳过 math/inlineMath（公式内的 `[[…]]` 是记号，不识别） |
| [remark/mdast-interop.ts](../apps/web/src/features/markdown/remark/mdast-interop.ts) | `MdNode`、`DIRECTIVE_TYPES`、`isDirectiveNode()` | 本地最小 mdast 类型（web 端不引 @types/mdast） |

### 2.3 sanitize 白名单

文件：[apps/web/src/features/markdown/sanitize.ts](../apps/web/src/features/markdown/sanitize.ts)

`richMarkdownSanitizeSchema` 在 defaultSchema 基础上放行三个指令宿主标签（`DIRECTIVE_HOST_TAGS`）及列举的 KaTeX MathML/SVG 标签和属性；现有测试覆盖部分公式保真及 script / 事件属性 / `javascript:` 清除。它不是完整安全证明：清洗发生在组件执行之前，组件生成的 URL、样式和第三方图表输出仍须按使用位置验证。新增指令属性还需检查手写的 `DIRECTIVE_HOST_ATTRS`，目前不会随注册表自动同步。

### 2.4 指令 → React 组件映射层

文件：[apps/web/src/features/markdown/directives/index.tsx](../apps/web/src/features/markdown/directives/index.tsx)

- `directiveComponents`：注册名 → 组件 的映射表（当前 17 项）
- `readDirective()`：从 hast properties 还原 name/attrs/index/docIndex
- `createDirectiveHost()`：宿主工厂；别名经 `getDirective()` 归一到主名 → 查表；查不到渲染 `UnknownDirective`
- 导出 `DirectiveContainerHost`（`:::`）、`DirectiveLeafHost`（`::`）、`DirectiveTextHost`（`:`）
- 统一 props：[directives/types.ts](../apps/web/src/features/markdown/directives/types.ts) 的 `DirectiveProps`（name/attrs/directiveClass/index/docIndex/children）

当前限制：组件拿到的是字符串属性表，宿主未消费 Zod 属性解析结果；未知名称查表存在继承属性问题；别名归一晚于编号生成。这些属于待改进事项，不应把“查表 + 统一 props”理解为完整的契约闭环，详见评审报告 R04、R07、R09。

### 2.5 边界：哪些不属于这套体系

- `apps/web/src/components/ui/`：仅 5 个 shadcn/ui 基础件（button/dialog/dropdown-menu/input/sheet），业务 UI 全在各 `features/` 内
- `apps/web/src/features/ink/`：独立的手写答题引擎（`engine/index.ts` 的 `create({engine: "atrament"|"excalidraw"})`、`InkPad.tsx`、`replay/InkReplay.tsx`），不走 Markdown/指令管线

## 三、组件构建过程

### 3.1 注册表：组件的出生地

文件：[packages/contract/src/directives.ts](../packages/contract/src/directives.ts)

- 语法外壳固定三种（`directiveKindSchema`）：container `:::名称{属性}…:::` / leaf `::名称[文字]{属性}` / text `:名称[文字]{属性}`；唯一例外 blank 语法糖 `[[答案]]`
- 位置语境：document / lecture / question / steps / columns（供 linter `allowedIn` 校验）
- 单条定义 `DirectiveDefinition`：`name / kind / since / allowedIn / attrs(zod strict) / attrDocs / description / example / aliases / syntax`
- 注册函数 `defineDirective`：注册期 fail-fast 校验（元 schema、example 与 kind 自洽、attrDocs ⊆ attrs、主名/别名全局唯一）
- 查询：`getDirective`（别名→主名）、`listDirectives`（按注册顺序）
- 属性底座 `directiveAttrs`：`z.strictObject({id, class, …业务属性})`——strict 拒未知属性名，拼写错误在 lint 期暴露
- **`description` + `example` 是 gen:spec 文档的数据源，质量直接决定 AI 写对的概率**

### 3.2 解析与校验：@tutor/md-dsl

包入口：[packages/md-dsl/src/index.ts](../packages/md-dsl/src/index.ts)

- `parseDocument`（[v2/parse.ts](../packages/md-dsl/src/v2/parse.ts)，纯函数不抛异常）：frontmatter 提取 → 按 kind 分派 practice/lecture/mixed → `extractQuestions` + `splitLectures` → 输出经 `parsedDocumentSchema` 契约兜底校验。**原文是真相**：题干/提示/详解按行号切原文、不重新序列化
- 题干变换：`studentStemMd` / `displayStemMd` / `stemMdLeaksAnswers`（[v2/public-stem.ts](../packages/md-dsl/src/v2/public-stem.ts)，学生载荷脱敏 + 泄露检测）
- 讲义结构：`analyzeLectureStructure`（[v2/lecture-structure.ts](../packages/md-dsl/src/v2/lecture-structure.ts)）
- lint：`lintDocument` = 解析透传 issues + 规则层（[lint/lint.ts](../packages/md-dsl/src/lint/lint.ts) 的 `runRules`，依次调 fences/directives/questions/math/math-text/tables/blank-marker/raw-html 等规则）
  - [lint/directives.ts](../packages/md-dsl/src/lint/directives.ts)：注册表驱动——是否注册、属性 schema、`allowedIn` 语境链；未知指令 warning + 近似名建议（[similarity.ts](../packages/md-dsl/src/lint/similarity.ts)）
  - [lint/rules.ts](../packages/md-dsl/src/lint/rules.ts) 的 `LINT_RULES`：全部错误码的单一权威登记处（约 40 条）；`rules.test.ts` 扫描源码中的 UPPER_SNAKE 字面量防漏登记
- CLI：`runTutorLint`（[cli/run.ts](../packages/md-dsl/src/cli/run.ts)）；仓库入口 `pnpm tutor-lint` 与独立脚本 [scripts/tutor-lint-standalone.ts](../packages/md-dsl/scripts/tutor-lint-standalone.ts)（esbuild 打包为 `dsl-kit/tutor-lint.mjs`）共用同一模块

### 3.3 服务端接入点

- 导入：`apps/server/src/services/content-service.ts` 的 `analyzeImport`（直通 lintDocument）→ `previewImport` → `commitImport`
- 编辑：同文件单题/讲义编辑重解析
- 重抽取：`reparse-service.ts` 用 `parseDocument` 全量重跑
- 脱敏：`attempt-service.ts` / `assignment-service.ts` 用 `studentStemMd` 生成学生载荷；泄露检测 `test/assert-no-stem-leak.ts`

### 3.4 dsl-kit/：自动生成的对外镜像

`dsl-kit/` 同时包含生成/复制产物与手写文件。应按来源维护，不能把整个目录都视为禁止编辑的生成物。CI 的生成一致性检查用于发现受生成链管理的文件漂移。

- 生成链：[scripts/gen-spec.ts](../packages/md-dsl/scripts/gen-spec.ts) 生成规范和提示词等文档，并按其 `kitCopies` 清单同步到 [dsl-kit/](../dsl-kit/)，不能假定所有 docs/dsl 文件都会复制。
- [dsl-kit/schema/content.json](../dsl-kit/schema/content.json)：先由 `pnpm schema:export` 从内容契约导出，再复制到分发目录。它描述 Question/Unit/Lecture 等结构化数据，当前不是完整的指令属性 schema 清单；新增纯展示指令不保证使此文件变化。
- `dsl-kit/README.md`、`dsl-kit/SKILL.md` 手写维护。
- `dsl-kit/完整样例.md` 从 [docs/dsl/完整样例.md](dsl/完整样例.md) 复制；应修改 docs 下的手写源，再运行生成命令同步。

## 五、新增组件标准流程（四步）

既有流程出处：[.claude/skills/add-directive/SKILL.md](../.claude/skills/add-directive/SKILL.md)（AGENTS.md 明确"不得绕过注册表"）。四步是交付项顺序；实施时仍按 AGENTS.md 先计划确认、先写失败测试再实现，不能等组件写完才补测试。下列评审补充不表示对应缺陷已经修复。

1. **注册**：[packages/contract/src/directives.ts](../packages/contract/src/directives.ts) 加一条 `defineDirective({name, kind, since, allowedIn, attrs, description, example})`
   - 已发布指令的新增属性必须可选且有默认行为；现有 `question.type`、`image.src`、`graph.fn` 首发即必填，见注册表说明。部分既有默认行为在组件内实现，后续需统一，不能据此随意改变旧语义
   - description / example 认真写——会自动生成进给 AI 的规范文档
2. **组件**：在 [apps/web/src/features/markdown/directives/](../apps/web/src/features/markdown/directives/) 写 React 组件
   - props 用 `DirectiveProps`，遥测走 `useDirectiveTelemetry`
   - 在 [directives/index.tsx](../apps/web/src/features/markdown/directives/index.tsx) 的 `directiveComponents` 表加一行
   - 检查属性是否完整经过 sanitize，是否影响私密内容、编号、父子结构与遥测；不能只增加映射表项
3. **样例 + 测试**：[samples/](../samples/) 加用到该指令的样例。合法历史样例须保持解析和渲染语义；`samples/lint/` 反例须保持预期诊断，不能要求它们全部 lint 零错误。测试应随 TDD 实施，参考 `directives/telemetry.test.tsx`、`RichMarkdown.test.tsx`
4. **生成规范**：跑 `pnpm gen:spec`，确认 [docs/dsl/规范.md](dsl/规范.md)、提示词模板包含该指令，内容契约 JSON Schema 与独立 linter 按真实改动同步。生成变化应与已提交产物一致，不能要求每个文件每次都必须变化

常用命令：

```bash
pnpm tutor-lint samples/v2   # 校验合法样例；lint 反例由测试断言预期诊断
pnpm gen:spec     # 重新生成规范文档 + schema + 独立 linter
```

## 六、审核清单（Review Checklist）

### 6.1 核心完整性检查（审查渲染核心是否被破坏）

- [ ] 所有展示场景仍走单一入口 `RichMarkdown`（无旁路渲染 markdown 的自定义实现）
- [ ] remark 插件链顺序未变：`frontmatter → math → gfm → directive → blank → directiveHost`（顺序错会导致解析口径不一致）
- [ ] md-dsl 的 `processor`（[v2/shared.ts](../packages/md-dsl/src/v2/shared.ts)）与 web 端 remark 前置插件保持一致
- [ ] sanitize 白名单未放行危险标签/属性；新增标签必须走 `sanitize.ts` 的 schema
- [ ] `directiveComponents` 主名键集合与 contract 注册主名集合一致（仅数量相等不够）；`UnknownDirective` 包括特殊名称在内的降级路径可用
- [ ] 遥测编号（`index` 语义编号 / `dindex` 文档全局序号）有跨端一致性测试；若修改语义，已说明版本和历史事件处理策略
- [ ] 学生公开载荷不含嵌套私密容器或编码形式的答案；渲染隐藏不替代脱敏

### 6.2 新增组件审核（对照第五节四步）

- [ ] `defineDirective` 定义齐全：kind / since / allowedIn / attrs（strict）/ description / example
- [ ] 已发布指令的新增属性可选且有默认行为；既有必填属性不被误改；无破坏性改动（**已发布指令只增不改**）
- [ ] 改名已登记 `aliases`（渲染端 `getDirective` 自动归一）
- [ ] React 组件使用统一 `DirectiveProps`；折叠类复用 `LabeledFold`；交互上报 `useDirectiveTelemetry`
- [ ] 已在 `directiveComponents` 注册，含别名场景
- [ ] `samples/` 新增样例；合法历史样例解析/渲染语义不变，非法反例诊断符合预期；新文件已被回归测试发现
- [ ] 渲染测试已补（对照 `telemetry.test.tsx` / `RichMarkdown.test.tsx`）
- [ ] `pnpm gen:spec` 后 `git diff` 仅含预期新增（规范.md / 提示词模板 / content.json / tutor-lint.mjs 同步更新）
- [ ] dsl-kit/ 的生成/复制文件未直接手改；README.md、SKILL.md 按用途维护；完整样例修改的是 docs/dsl 下的源文件

### 6.3 兼容性硬规则（违反即打回）

1. 已发布指令只增不改（不改 kind、不删属性、不改默认值语义）
2. 新属性必须可选、带默认值
3. 指令改名必须登记 `aliases`
4. 未知指令必须优雅降级（渲染 `UnknownDirective` + linter warning + 近似名建议）
5. sourceMd 保留原始内容，是重解析依据；stemMd、答案等为派生字段，不用重新序列化的 Markdown 或渲染 HTML 替代教师域原文
