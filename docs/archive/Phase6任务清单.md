## 0. 执行纪律与完成标准

每项任务先给出具体文件清单、契约变更、实施步骤与失败测试，依 AGENTS 流程确认后执行。本文提供阶段级完整任务分解，不替代具体任务的计划确认。

所有开发任务遵循：计划 → 失败测试 → 实现 → 完整 diff 的 simplify → code-review → 涉及学生载荷时 security-review → 真实命令验证 → 合并。确认问题当场修复，未修问题逐条说明。仓库引用的 task-workflow 等技能应在执行环境核实可用性；本次未调用也未声称完成这些技能审查。

默认按编号推进，任务依赖不得跳过。每项独立分支 `task/T6R-N`（T6R.0 决策：沿用项目既有 `task/Txx` 命名），小步提交保持可构建。通过后先合并 v2，再按发布闸门发 main。不能在真机项未完成时打勾或发布相应能力。

公共验证集（以下简称 G）：

```powershell
pnpm lint
pnpm typecheck
pnpm test
pnpm build
```

每个实现任务还须运行对应定向测试；改变答题／导出流程时运行相关 Playwright 用例。各发布闸门运行全量 `pnpm e2e`，覆盖 Chromium＋WebKit。WebKit 自动化不等于 iPad 真机。根 package.json 已定义真实 Playwright 命令。

契约变更后运行 `pnpm schema:export`、`pnpm gen:spec` 并提交所有产物；之后再跑一次生成并确认无新增 diff。迁移只用 `pnpm db:generate`，不手改生成文件。涉及解析器／判分时先有失败测试，保留所有 samples 历史兼容；不能用更新快照掩盖渲染回归。

每个任务 PR 写明：问题与行为变化、定向测试和 G 的实际输出、人工复核路径、兼容／迁移影响、未完成事项。新增依赖写理由与替代方案。纯文档 T6R.0 可豁免 TDD，改查链接与决策一致性；实验 T6R.1 如有代码，仍走对应测试。
