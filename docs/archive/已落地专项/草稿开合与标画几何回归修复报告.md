# 草稿开合与标画几何回归修复

日期：2026-10-13。分支：codex/annotation-paper-geometry。

## 根因与修复

上一轮将草稿与圈画状态分开，但题卡最大宽度及题干分栏仍以 noteOpen 为条件。草稿打开时外框变宽，或题干从整宽转成分栏，导致重新换行；标画层又以 inset-0 覆盖整个父框，实际题面却有 720px 的宽度上限，画布和底图尺寸出现偏差。

修复将布局偏好与可用空间作为唯一几何依据，草稿开合只控制纸面可见性。右侧模式收起草稿时保留题干列位。原位标画覆盖层采用保存的 CSS 宽高，题面在空间足够时保留保存的宽度并居中，使覆盖层、文字和选项共享同一坐标域。新增的位置检查还复现了固定尺寸后的 55px 横向跳动，已通过保留居中对齐修复。

不改写已有笔迹、底图、API 或数据结构。真正切换布局或缩小视口且不再容纳旧题面时，继续保留原底图入口；不向新题面强行套圈。

## 测试与审查

- 先失败再实现：题卡在草稿未打开时的布局断言、覆盖层固定尺寸断言，以及自动／右侧的圈画后开稿 E2E 都先失败；下方布局作为对照通过。
- 三种布局使用长题干与补充材料，在标画激活和退出状态下反复展开、收起草稿。比较题面及画布宽高、相对位置、位图哈希、有效像素数、笔数和模式状态；不会因开合出现「查看原标画」降级。
- 模拟原来的窄题卡，圈画后恢复新外框宽度，检查既有题面及画布的屏幕位置、尺寸和位图哈希不变。
- 原位标画全链回归增加进入模式前后横纵位置断言，继续验证导出、离线保存、窄屏原底图、菜单和题目唯一输入。
- 先做简化／复用检查，再做正确性审查：保留现有布局偏好、组件身份、兼容性核对与存储路径；确认的横向跳动已修复，没有遗留确认发现。未新增依赖，也未修改其他任务的橡皮引擎逻辑。

## 手动验证

1. 在学生作业上先圈画题干或选项，再反复展开、收起草稿；确认框范围、文字换行、圈的位置和大小不变。
2. 自动、右侧、下方三种布局各检查一次，再退出圈画后重复开合。
3. 查看已有标画，确认题卡扩宽时仍在原题面坐标上；真正改布局或旋转使题面不兼容时，检查原底图仍可查看。
4. 对照长题干、四个长选项及数学公式；检查标画区域不包含草稿、题头或状态提示。
