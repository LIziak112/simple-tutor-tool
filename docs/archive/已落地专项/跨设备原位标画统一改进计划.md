# 跨设备原位标画统一改进计划

日期：2026-10-15。状态：用户已确认实施；分支 codex/annotation-fixed-surface。采用保存时蓝框区域的固定排版整体缩放；实施与验证结果见同目录《跨设备原位标画实施记录》。

## 目标与决策

题卡始终只呈现一份题面。已有笔迹自动恢复并覆盖题面；切换设备不要求再次点击圈画才能看见。点击顶栏「圈画」进入原位编辑，再点退出，收笔并确认本机落盘后恢复普通作答；退出保留笔迹，只隐藏工具栏。需要隐藏笔迹时继续用更多菜单「隐藏标画／显示标画」。删除「编辑原标画／收起原标画」这套第二入口。

采用保存时的题面排版作为逻辑画面，公开题面 DOM 与透明矢量层共用一个等比变换。先保证整体缩放正确，再评估另立项目实现段落、公式、图片级锚定；本次不承诺任意重排或改题后旧笔迹自动正确迁移。

## 已确认根因

1. `question-base-image.tsx` 的 `questionSurfaceMatchesLayout` 要求宽高差不超过 1 CSS 像素，且公开内容、几何、字体签名一致，未区分整体缩放与文字重排。
2. `QuestionAnnotationOverlay.tsx` 不匹配时设置独立的 `original` 状态，并在真实题面下方增加 PNG 工作区，产生重复题面。
3. `AttemptQuestionCard.tsx` 顶栏主要依据编辑器的 `drawing` 状态切换；下方工作区由 `original` 状态控制。显示原图时可以没有活跃编辑者，顶栏与下方按钮因此不能统一开合。
4. `annotation-surface.ts` 已经保存矢量，具有屏幕指针与底图坐标转换；缺口主要是题面几何复现、变换校验与交互状态统一，并非完全缺少缩放能力。
5. 现有布局只记录尺寸和签名，不能保证未来字体、样式或动态资源变化后仍能复现原排版。不能仅放宽签名检查就宣称修好。

## 交互与几何方案

- 已有标画的题面按保存的逻辑宽度排版，外层按可用宽度计算统一缩放比例；题面、笔迹、裁剪边界与占位高度同步更新。新增笔画反向映射回同一逻辑坐标域，旋转和缩放不反复改写原始点集。
- 复现校验在未缩放的逻辑坐标下进行，保留版本、公开内容、字体、关键元素几何检查；不能将非等比拉伸视为兼容。
- 窄屏默认适配宽度；缩小导致难读时，提供同一题面区域的放大与平移。真实输入框保持可填写、可聚焦；工具栏与触控目标不随题面缩小。移动键盘、浏览器缩放及 Pencil 必须实测。
- 新版布局契约按需要增加可选的复现信息（有默认语义），先在 contract 定义，再接实现；不能只存签名而缺少复现依据。公开资源校验不得携带答案、教师节或完整快照散列。
- 普通恢复、预览与编辑共用一个状态控制器。顶栏、退出、切题、隐藏、草稿开合使用同一收笔和保存入口；保存失败保留当前画面与编辑状态。
- 同题圈画与草稿继续允许同时展开；布局切换不重挂控制器，不重置答案、撤销历史或未传稿。

## 历史数据与教师场景

- v2 历史记录：先用原宽复现真实题面，验证通过后自动原位显示、继续编辑；不重新生成并替换已有持久底图。
- 无法复现或缺少布局信息的旧记录：在同一题面区域自动显示原始题面与矢量层，明确标记历史题面，提供同一顶栏编辑入口，不在下方再复制一份。需要交互作答的旧 PNG 须提供独立、无损的答案控件，不能用图片遮住唯一作答入口，也不能凭猜测重建空位坐标。
- 字体或图片加载失败先提供重试；不得直接认定无稿。异常时保留当前可用内容，不闪现空白覆盖原稿。
- 当前作答读取建卷冻结快照，教师修改题库不应改变这份作答的题面；需要补回归验证。新题目版本不自动继承旧圈画。
- 教师批改／学生结果回看自动展示授权范围内的原题与封存笔迹，复用只读呈现入口；教师评语、评分和订正不写入学生封存原稿。
- 继续保留 CAS、幂等、账号隔离、离线恢复和提交封存；显示缩放不触发迁移上传，不重写历史证据。

## 实施顺序、文件与测试

### 第一阶段：先补复现测试，统一控制入口

文件：`QuestionAnnotationOverlay.tsx`、`AttemptQuestionCard.tsx`、相关组件单测及 `e2e/question-inline-annotation.spec.ts`。

先写失败测试：已有不匹配布局时点击顶栏直接编辑；再次点击退出；保存失败不关闭；退出保留笔迹；隐藏与显示一致；没有第二份题面和第二套收起按钮。统一控制器后适配普通与历史工作区。

### 第二阶段：实现逻辑画面与缩放

文件：`QuestionSurface.tsx`、`question-base-image.tsx`、`QuestionAnnotationOverlay.tsx`、`annotation-surface.ts`，按需要新增独立几何变换模块；相应单测、浏览器测试。

先测不同容器宽度下的单一比例、占位高度、指针往返、笔宽、橡皮命中、缩放中收笔和恢复追加，再实现逻辑画面。校验失败走同区域历史呈现。测试多行文本、公式、表格、图片、选项和填空，不能仅用纯图片验证。

### 第三阶段：契约、旧稿与各消费入口

文件：`packages/contract/src/annotation.ts`、`question-annotation-base.ts`、`annotation-store.ts`、`annotation-sync.ts`、`annotation-service.ts`、`AnnotationView.tsx`、`AnnotationLayer.tsx`、`AnnotationWorkspace.tsx` 及实际调用它们的回看／教师入口、导出模块。

先补旧 v1、现有 v2、新布局兼容与泄露用例，再改实现。扩展结构时契约优先；数据库如需变更，仅通过 drizzle-kit 生成迁移。导出与封存继续使用固定矢量和对应题面，不能截图当前可缩放界面。

### 第四阶段：质量闸门、验证与合并

对完整 diff 依次执行 simplify、code-review；触及学生载荷或答案数据加 security-review，发现逐条修复或说明。同步 `AGENTS.md` 原布局不匹配规则、技术架构、页面功能清单及相关标画方案，明确以新决策替代原来的下方原图入口。

独立阶段分支，小步提交。执行相关单测、`pnpm test`、`pnpm typecheck`、`pnpm lint`、`pnpm build`，以及隔离环境的相关 `pnpm e2e`（Chromium/WebKit）；修改契约／规范时执行 `pnpm schema:export`、`pnpm gen:spec` 并检查生成产物。确认现存 samples 兼容。记录真实命令输出；全绿后按项目流程先合入 v2，再发布 main。

## 验收矩阵

1. 桌面写入，平板／手机重开：笔迹自动出现，题面仅一份；覆盖 320、768、1024、1440 宽度及横竖屏。
2. 圈选公式、图片局部和填空，变换前后逐点按理论比例核对，几何测试误差不超过 1 CSS 像素；跨浏览器视觉检查单独记录，不能仅凭截图近似判断。
3. 换设备继续写、擦除、撤销、保存，再回原设备：没有累计漂移，无重复迁移、覆盖或丢稿。
4. 顶栏进入／退出控制统一；退出后第一击能正常填写答案；草稿同时展开不影响标画。
5. 刷新、离线、恢复失败、字体延迟、旧布局、账号切换、跨端冲突和本机保存失败均不静默丢稿。
6. 教师改题库后旧作答仍对应冻结题面；教师回看自动显示原稿；新卷不错误复用旧稿。
7. 导出、交卷封存、结果回看与屏幕上的题面笔迹对应，原始证据不可改写。
8. iPad Safari／Pencil 真机验证书写、手指滚动、放大、输入框与键盘；自动化通过不能替代真机结论。

## 范围与当前验证状态

本轮根因来自本地代码，与截图现象相符；尚未连接现场浏览器复现，不能确定线上部署与本地提交完全一致。本次未修改线上部署；本地已用脱敏公开题面的隔离浏览器回归验证，部署版本与真机体验仍须上线前独立核对。

本计划的核心取舍是：已有笔迹时优先保持排版与笔迹对应，窄屏通过整体缩放和放大浏览保证可用。任意重排、教师改题后自动迁移笔迹，需要独立语义锚定设计与迁移验收，不包含在本次承诺内。
