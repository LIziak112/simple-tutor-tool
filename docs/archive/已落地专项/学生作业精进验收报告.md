## 3. 性能方法与结果

环境为本机Windows上的Playwright Chromium（本机Edge）和WebKit，iPad浏览器配置/DPR2；API为隔离本机服务、无网络节流。130题，进入前0个标画画布，只显式准备第130题。最终耗时从页面事件触发到canvas可输入且实际blur监听已绑定，并持续两个动画帧，以requestAnimationFrame和performance.now测量，不包含Playwright点击等待。首开含底图生成及本机保存，缓存进入重复5次。两个稳定帧计入耗时，比原MutationObserver单次属性出现测量更保守，避免把布局核对时的瞬时状态当作可输入。

性能测试先失败：Chromium缓存进入231–355ms，WebKit205–311ms。根因是全局编辑Context变更导致整卷题卡与Markdown重新渲染。改为稳定操作接口、按题useSyncExternalStore订阅；底栏仍订阅全局模式，题卡事件通过稳定getActive读取跨题模式，不牺牲收笔与落盘语义。130题单测证明只有原题与新题更新。

第二轮在后台上传时仍出现320/494ms尖峰，确认是顶栏保存状态推动整卷题卡重渲染。新增memo题行，按题绑定稳定事件/答案操作，稳定埋点操作对象与空提示数组，避免ref重新注册和无关Markdown重跑；答案、提示、待检查或正式笔迹变化仍正确更新。没有将150ms断言放宽。

连续绘制用60个合成PointerEvent并观察其他129题DOM更新，记录requestAnimationFrame间隔P95；这不是Pencil真实笔尖延迟，也不是硬件掉帧验收。最终整卷回归数据如下；后台同步与其他回归并行运行，Chromium帧间隔P95高于独立专项的7.1ms，保留实际结果，不宣称恒定60fps。

## 4. 质量闸门

按顺序人工复核完整功能diff的简化/复用、正确性与安全；当前环境无可执行的simplify/code-review/security-review斜杠技能，不能声称调用过这些工具。

- 简化：复用QuestionSurface、既有CAS上传队列和各域持久仓；工具呈现复用而控制器分域；编辑状态优化没有新增另一份笔迹模型。保存详情仅打开时消费标量，不序列化整卷笔迹/PNG。
- 正确性：检查同实例全屏、迟到准备取消、指针释放、对象URL清理、清空待传稿、异常持久化保留、跨题收笔、聚焦和重排回退。发现并修复保存详情重开被旧重试错误污染，以及预取空草稿壳被误记为“已保存稿件”；均先补失败测试。
- 安全：布局预算与实际PNG尺寸校验、ready不可覆盖、身份/版本绑定、CAS冲突、跨学生权限和封存门槛保持；学生题面投影无未授权答案、详解、提示或秘密hash。新导出仅公开题面/中性选项与当前授权笔迹，不包含个人答案；KaTeX trust=false及sanitize保持。接口泄露单测与浏览器监视保留。
- 全量回归发现旧测试把答题卡标题混入单元标题计数，改为现有attempt-unit-heading定位，仍断言单元数量、顺序及后续作答/判分/泄露链路，不降低业务要求。
- WebKit学情链路还揭示了真实快速交卷竞态：trace中submit在327469.294ms，而填空PUT在327535.962ms（迟66.668ms），答案因已交卷返回409。新增答案flush，确认时先等待既有后台同步、清理600ms防抖、等待在途答案并上传本机最新值，失败阻断并允许重试；旧回执只改指纹，不覆写新输入。补了5项失败单测及双浏览器延迟/503故障注入。未修改服务端判分或提交契约。
- 新故障夹具首轮找了不存在的“重试”按钮，已改用实际“确认交卷”重试入口。性能夹具也修正了瞬时属性先出现、监听器稍后重绑的测量竞态，要求持续两帧同时就绪；真实功能断言与阈值保持。
- 纯样式题卡8px圆角调整豁免行为TDD；通过响应式几何与截图验证，不扩展成全站主题重构。

## 5. 手动验证

1. 登录学生，分别从作业入口和课程练习入口打开未交卷页面。检查题号、完整度、答题卡、顶栏保存状态与最后一题不被底栏遮挡。
2. 填空只填一部分，从交卷检查定位遗漏；判断选“错”应计作已填写。草稿或标画不能代替答案。
3. 题头画笔进入，在文字/公式上圈画，点“作答”后第一击能选答案，笔迹保留。切题时只有一个活动输入；改变宽度后不能错贴旧圈，使用查看原标画。
4. 打开草稿或正式手写，3笔后撤销，进全屏重做再加1笔，退出再撤销，验证同稿4→3笔；空开关不改变填写状态。
5. 题头更多导出题目与标画，核对实际PNG与预览同内容、没有个人填答或参考答案。复制失败仍可下载。查看保存详情按题定位与重试。
6. 断网写稿后尝试交卷，必须明确确认仅交答案或返回重试；仅交答案不会删除本机待传稿，也不会把它假冒成交卷原稿。正式手写flush失败仍阻断。
7. 交卷后沿原学生结果页/教师回看与数据包导出检查原稿；历史第8题的冻结源不变，新修正内容由教师正常修订并重新发布。

日常服务器保持运行：[现有学生作业](http://localhost:5173/s/assignments/b5b5e176-99c6-496a-985c-4804d1200fc8)。旧作业若已有v1底图会保留兼容入口，不强制覆盖成新布局。
