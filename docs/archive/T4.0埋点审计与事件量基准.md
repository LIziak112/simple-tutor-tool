## 一、埋点审计表

### 1. 队列层（`apps/web/src/lib/event-queue.ts`，T4.0a 已落地）

| 事件 | 来源 | 说明 |
| --- | --- | --- |
| `page_hidden` / `page_visible` | 既有（T2.10） | 仅 attempt scope 自动注入，语义零变化 |
| `lecture_visible` / `lecture_hidden` | T4.0a | lecture scope 注入（viewId 配对；双兜底允许双发，聚合按重复 hidden 忽略） |
| `net_offline` / `net_online` | T4.0a | 两 scope 注入；创建时离线主动补发 |
| `idle_start` / `idle_end` | T4.0a | 两 scope 注入；阈值 attempt 90s / lecture 300s，惰性判定 |

**明确不采**：
- 逐帧滚动位置（被 `lecture_section_focus` 替代——折叠架构下百分比会倒退，方案 §6）；
- 心跳/在线探针（iOS 后台 timer 挂起，靠心跳必错，§5.0-A2）；
- 服务器可达性探测（`navigator.onLine` 口径只反映网络接口连接，这是有意选择，§5.0-A3）。

### 2. 答题页（AnswerView / AttemptQuestionCard）

| 事件 | 来源 | 触发点 |
| --- | --- | --- |
| `attempt_start` / `question_view` / `question_focus` / `question_blur` / `answer_change` / `ink_stroke_batch` / `submit` | 既有（T2.10） | 语义与 payload 零变化 |
| `hint_open` | 既有（T2.11，服务端直记） | 解锁接口内直记（不经前端队列；clientTs 为服务端时钟，不参与区间运算） |
| `directive_interact`{host=question} | **本次新增** | HintPanel 解锁**成功**回调（`unlockHint`）；index 与 hint_open 直记同口径（解锁接口返回的 0 起序号），失败重试不发 |
| `ink_edit_batch` | **本次新增** | 手写橡皮/撤销/重做/清空（reason 分型），2 秒防抖窗口聚合计数；交卷/卸载冲出 |
| `ink_fullscreen` | **本次新增** | HandwrittenControls 的 fullscreen state 翻转（on 布尔，不拆 enter/exit） |

**明确不采**：
- 提示面板内滚动/长时间停留细粒度行为——面板平铺常驻，无开合交互；停留由 hintDwellSec（open→blur/隐藏边界）代理；
- 数学键盘切换（`math_keyboard_toggle` 已砍，无指标消费，方案 §6）；
- 手写工具栏的笔色/粗细/工具切换——无 T4.1/T4.3 指标消费（若将来「只用橡皮不改错」之类的信号需要，再立项）；
- 手写区的展开/收起（「展开手写区」按钮）——与 fullscreen 语义重叠且无指标消费；
- 最终答案输入框的逐键击——已有 answer_change 按保存节奏聚合，逐键属于过度采集。

### 3. 结果视图（AttemptResultView，交卷后回看）

| 事件 | 来源 | 触发点 |
| --- | --- | --- |
| `directive_interact`{host=result} | **本次新增** | SolutionFold「查看详解」开合；payload 带 attemptId+questionId+name=solution+index（该题全卷 0 起序号）；结果页自建 attempt scope 队列（同一 attemptId，离开 dispose，§5.0-C12） |

**明确不采**：
- 结果页滚动深度/停留——无对应指标，且与 attempt 域 activeSec 口径有交叠风险；
- 笔迹缩略图的查看——图片加载无交互语义；
- 老师批改块的展开细读——展示型内容，无折叠交互。

### 4. 学生讲义阅读页（StudentLectureViewPage）

| 事件 | 来源 | 触发点 |
| --- | --- | --- |
| `lecture_expand` | 既有（T2.10） | **新客户端不再产生**（方案 §6 决策 1）；服务端继续接收（旧前端 SW 缓存兼容），读侧归一为 directive_interact{action:open} 计入 name 计数 |
| `directive_interact`{host=lecture} | **本次新增** | 折叠开/合（open/close）与 steps「显示下一步」（reveal：容器 docIndex + step 两套编号）；带 lectureUpdatedAt 版本定位 |
| `lecture_section_focus` | **本次新增** | 「当前阅读节」切换（IntersectionObserver 占比最大 + 0.1 余量或 1s 稳定迟滞，§5.0-C13）；页面加载即报起始节 |
| `lecture_toc_jump` | **本次新增** | 目录点击；headingIndex 与自动目录下标同源 |

**明确不采**：
- 逐像素滚动深度（`lecture_scroll_depth` 已被 section_focus 替代，方案 §6）；
- 目录面板自身的展开/收起（「收起目录」按钮）——纯版式操作，与阅读内容无关；
- 正文内文本选择/复制——隐私敏感且无指标消费；
- companionUnits（配套练习入口）的点击——点击后进入单元落地页会另起 attempt 域采集，双计无益。

### 5. 指令组件层（RichMarkdown + DirectiveTelemetryContext）

| 组件 | 上报 | 说明 |
| --- | --- | --- |
| LabeledFold（fold/hint/solution） | open / close 双向 | 组件只报 {name, docIndex, action}，归属由页面层决定 |
| StepsDirective | reveal（step 序号） | index=容器文档全局序号（docIndex），与展示编号两套口径 |
| answer | **不上报** | 机密内容学生端不下发，无交互可采 |
| example / tip / warning / box / columns / mark / image / graph | **不上报** | 非折叠组件，无交互语义（example 内嵌的 solution 走 LabeledFold 通道正常上报） |

**教师端预览 / 导入预览 / 错题本**：不提供遥测回调（Context 为 null，组件行为零变化）——错题本的 SolutionFold 复用组件但无 attemptId 复盘语义（其卡片聚合自多次作答，不属于某次 attempt 的复盘口径）。

### 6. 其余学生页面

| 页面 | 事件 | 原因 |
| --- | --- | --- |
| 首页 / 讲义列表 / 课程目录 / 单元落地页 / 我的记录 / 错题本 | 无 | 导航型页面，无学习行为语义；进入讲义/答题页即有各自的会话事件（lecture_visible / attempt_start）作为「到达」标记 |

### 7. 已知限制（采集口径，非缺陷）

1. **`lecture_section_focus` 不带 viewId**（契约 payload 只有 lectureId+headingIndex）：双标签页同读一篇讲义时两页的 focus 事件在流内交错，逐节 focus 区间会互相截断（时长不虚高、但归属偏保守）。visible 区间不受影响（带 viewId）。如需精确分账需契约加可选 viewId（待裁决）。
2. **存量 `lecture_expand` 行的旧 index 口径**（按语义计数、折叠类恒 0）与 docIndex 不兼容：读侧归一后**只计入** summary 的 hintOpenCount/solutionOpenCount 与总时长，不定位到具体折叠块行（地图分母仍为当前结构解析值）。
3. **lecture 域 idle/net 事件无归属列**（T4.0a 环境族 payload 无 lectureId，落库 NULL）：地图扣 idle 用「学生级 idle」近似——idle 语义是「该生在任一队列域内无输入」，与「没在读讲义」一致（单设备使用是常态）。attempt 域不受影响（attemptId 列恒写）。
4. iOS 无 Background Sync / Safari ITP 7 天清存储等平台限制见方案 §5.0-A6（说明性，不写码）。

## 二、事件量基准（实测）

场景：**20 题作业（含 5 道手写题、10 道带提示题）+ 2 篇讲义完整阅读**的单次会话。
数据来自确定性测试 `apps/web/src/lib/event-volume-benchmark.test.ts`（事件间距 1.5 秒的保守密集模拟；含长文本 answer_change 字节压力样本、双会话讲义、双发 hidden、回滚重读）。

### 三项指标

| 指标 | 实测 | 方案估算 | 结论 |
| --- | --- | --- | --- |
| 会话事件总数 | **262**（构造 259 + 队列注入环境事件 3） | ~300（attempt ~200 + 每讲义 ~45） | 量级一致（实测略低——估算偏保守），节流有效 |
| 单批最大字节数 | **18,462 B**（4 批） | ≤32KiB（sendBeacon 64KiB 队列的一半余量） | 远低于上限，字节双限切批有效 |
| 批次数 | 4（attempt 1 + 讲义各 1~2） | — | 5 秒周期下单会话仅数批，服务端压力可忽略 |

### 分类型计数（实测）

| 事件类型 | 条数 | 说明 |
| --- | --- | --- |
| `answer_change` | 40 | 20 题 × 2 次修改（与草稿保存同节奏聚合，非逐键） |
| `directive_interact` | 38 | 讲义折叠开合 20 + steps 揭晓 8 + 答题页提示解锁 10 |
| `ink_stroke_batch` | 30 | 5 手写题 × 6 笔（每笔一条，T2.10 既有口径） |
| `question_focus` / `question_blur` | 25 / 24 | 25 次聚焦切换（含隐式结算） |
| `lecture_section_focus` | 24 | 2 讲义 ×（10 标题 + 2 次回滚）——事件量=标题数级，天然节流 |
| `question_view` | 20 | 每题首次进视口 |
| `ink_edit_batch` | 10 | 5 手写题 × 2 防抖窗口（四计数合并，非逐操作） |
| `ink_fullscreen` | 10 | 5 手写题 × 进出各一 |
| `lecture_toc_jump` | 8 | 2 讲义 × 4 次目录跳转 |
| `lecture_visible` / `lecture_hidden` | 4 / 6 | 2 讲义 × 2 会话；hidden 含双兜底双发（聚合按重复忽略） |
| `page_hidden` / `page_visible` | 3 / 3 | 3 次切后台 |
| `net_offline` / `net_online` | 3 / 3 | 含队列注入 |
| `idle_start` / `idle_end` | 3 / 3 | 每空闲期一对 |
| `attempt_start` / `submit` | 1 / 1 | 会话首尾 |

（`hint_open` 服务端直记不经队列，不在上表；其条数等于提示解锁数 10。）

### 对照结论

- **估算 ~300 条/会话成立**：实测 262 条在同一量级（方案估算偏保守方向）。
- **节流有效**：section_focus 事件量 = 标题数（≤2×标题数含回滚）；ink 编辑按防抖窗口合并四计数；idle 每空闲期恰一对；无逐帧/逐键/逐操作上报。
- **字节切批有效**：最大批 18.5KiB（含 60 字长答案样本），远低于 32KiB 切批线与 sendBeacon 64KiB 硬限。
