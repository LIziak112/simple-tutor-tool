## 问题与观察清单（只记录，不修复）

### #1 [建议] 「已批改」状态徽章与「待公布」得分并列展示
- **现象**：《随堂小测》（after_due，截止前已交卷、全部自动判完）在 /s/records 中状态徽章为「已批改」，得分位置却是「待公布」。
- **复现**：布置 after_due 作业 → 学生截止前交卷（无待批）→ 教师开 /s/records 看该条目。
- **影响**：口径上「已批改」= 全部题有最终判定，「待公布」= 答案未到公布时机，二者并不矛盾，但并列阅读略矛盾（已批改却看不到分数）。纯文案/UX 层面。
- **严重度**：建议（可在 D10 展示层把未公布条目的状态徽章降级为「已交卷」或加「未公布」说明）。

### #2 [建议] CSV 手写笔迹链接依赖 PUBLIC_URL 与访问主机一致
- **现象**：CSV 中笔迹列为绝对 URL（`http://127.0.0.1:5299/api/teacher/ink/...png`）。教师会话若从与 `PUBLIC_URL` 不同的主机名访问（实测：会话 Cookie 在 `localhost`，链接指向 `127.0.0.1`），直接点开链接会 401（Cookie 不随跨主机发送）。
- **复现**：以 `http://localhost:5299` 登录教师 → 导出 CSV → 新标签打开链接（127.0.0.1）→ 401。
- **影响**：部署时 `PUBLIC_URL` 必须与教师实际访问_origin 一致，否则 CSV 内笔迹链接需重登录/手动换域名。同源 fetch 场景（导出本身）不受影响。
- **严重度**：建议（部署文档已要求设置 PUBLIC_URL；建议在部署文档显著位置强调「必须与访问域名一致」）。

### #3 [记录→确认设计] 截止时间后仍可交卷，交后立即公布
- **现象**：《单元过关测》截止 03:59:00，学生 03:59:11 交卷被接受，且结果立即公布答案与得分（after_due 已过截止）。
- **影响**：作业截止不做硬拦截（迟交允许）。与「截止后公布」的语义自洽，但教师侧可能期望「截止后禁止交卷」。请产品确认这是预期行为；若需拦截，属新需求。
- **严重度**：记录（设计确认项，非缺陷）。

### #4 [建议] 笔迹回放时长无下限，短笔画回放过快
- **现象**：回放总时长 = 笔迹点时间戳跨度。快速书写的两笔总时长仅 0.3 秒，回放一闪而过（截图 16/17）；进度条拖动正常。
- **影响**：真实 Apple Pencil 书写跨度通常以秒计，影响有限；但极短笔迹（如点划）回放可读性差。
- **严重度**：建议（可对总时长做下限归一，如最短 2s，等比缩放时间轴）。

### #5 [次要] 学生结果页对「无笔迹」的手写题仍发起笔迹请求，服务端 404 业务错误
- **现象**：第 4 次练习中手写题只填了最终答案未写笔迹，学生结果页仍 GET `/api/student/attempts/:id/ink/...` → 服务端记 `INK_NOT_FOUND` 404（UI 正常降级不展示笔迹区，无用户可见影响）；服务端日志出现对应业务错误记录。
- **复现**：手写题只填最终答案不画 → 交卷 → 打开学生结果视图 → 看 server 日志。
- **影响**：无用户可见影响，仅日志噪声与一次无效往返。
- **严重度**：次要（建议前端根据 attempt 数据判断有无笔迹再请求）。

### #6 [记录] 其他验证通过但值得留档的行为
- 待批队列「清除判定（0）」对仍待批的题：提交 mark:null 且**卡片保留在队列**（按钮文案已提示），进度不变——与 D3/D4 语义一致。
- 错题本「最近一次做对即已攻克」：教师对**较早一次**作答改判「判错」，若该题**最近一次**作答做对，则错题主列表不出现、已攻克列表出现（有理数乘法运算实测）。与页面文案口径一致，但教师改判时可能预期错题本立即出现该题——建议产品知晓该口径。
- 详情页对含待批题的 attempt 导出 CSV/顶部得分均按「未批」口径展示，一致。
- 手写缩略图 `loading="lazy"` 在页面不可见/后台节流环境下不加载（本实测环境复现过一次）；正常前台浏览加载无问题。
