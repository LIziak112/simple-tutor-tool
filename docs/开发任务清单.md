# 开发任务清单（v2）

> 配套文档：`docs/技术架构与实施方案.md`（下称"架构文档"，引用写作 §x.x）。本文只写**做什么、按什么顺序、怎么验收**，设计细节以架构文档为准，不重复。
> 执行对象：GLM 5.3。每次只下达**一个任务（Txx）**。

## 0. 使用方法

### 0.1 每个任务的下达提示词

```
阅读 AGENTS.md、docs/技术架构与实施方案.md、docs/开发任务清单.md。
执行任务 <Txx>，只做该任务范围内的事。
1. 先列出：要新建/修改的文件、实现步骤、要写的测试。等我回复"确认"。
2. 确认后实施。完成后运行 pnpm lint && pnpm typecheck && pnpm test（涉及 E2E 时加 pnpm e2e），贴出结果。
3. 逐条对照该任务的「验收」自查，说明每条如何验证。
4. 文档未覆盖的设计决策，停下来问我，不要自行假设。
```

### 0.2 规则

- 严格按编号顺序执行；「依赖」未完成不得开始。
- 每个任务一个 git 分支 `task/Txx`，验收通过后合并到 `v2` 分支。
- 带 🧑 标记的验收项需要**你本人**手动检查（尤其是 iPad 真机），通过后才算完成。
- 任务完成后在本文 §7 进度表打勾。

### 0.3 全局固定约定（所有任务通用，不再重复）

| 项 | 约定 |
| --- | --- |
| API 前缀 | `/api/public/*`（无需登录）、`/api/teacher/*`（教师会话）、`/api/student/*`（学生会话）、`/mcp` |
| 响应格式 | 成功 `{ ok: true, data }`；失败 `{ ok: false, error: "UPPER_SNAKE_CODE", message: "中文说明" }` |
| 主键 | 实体 id 用 `crypto.randomUUID()`；题目/单元 id 来自 DSL（字符串） |
| 时间 | 数据库存 UTC ISO 字符串；界面显示 Asia/Shanghai |
| 配置（环境变量） | `PORT`(默认 8787) `DATA_DIR`(默认 ./data) `PUBLIC_URL`(默认 http://localhost:8787)；会话密钥首次启动自动生成到 `DATA_DIR/secret.key` |
| 数据目录 | `DATA_DIR/tutor.db`、`DATA_DIR/blobs/`、`DATA_DIR/backups/` |
| 测试位置 | 包内 `src/**/*.test.ts`；E2E 在 `e2e/` |

### T1.3 v2 解析：练习题
- 依赖：T1.2
- 产出：`packages/md-dsl/src/v2/`：unified + remark-parse + remark-gfm + remark-math + remark-directive + remark-frontmatter；解析 frontmatter、`::::question` 及其子指令 `hint/answer/solution`、填空 `[[a|b]]`、任务列表选项；输出 `ParsedDocument`，每题保存 `sourceMd`（该题原文片段）。
