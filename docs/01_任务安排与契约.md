## 1. content.json（题库 + 讲义存储格式）

`data/content.json`，不存在时 `GET /api/content` 返回 404。

```json
{
  "version": 1,
  "lectures": [
    { "id": "lec-1", "title": "第 4 讲 加法——方向参与的合并", "markdown": "…原始讲义 MD 全文…" }
  ],
  "units": [
    {
      "id": "练习四",
      "unit": "练习四",
      "lecture": "第4讲",
      "topic": "有理数加法",
      "questions": [
        {
          "id": "练习四-1",
          "number": 1,
          "difficulty": 2,
          "type": "计算",
          "knowledge": "有理数减法-双负号",
          "stem": "计算：$5-(-3)=$ ____。",
          "options": [],
          "answers": ["8"],
          "solutionMd": "【思路】…\n\n【过程】…\n\n【易错】…"
        }
      ]
    }
  ]
}
```

字段规定：

- `units[].id`：单元名（来自 UNIT 注释第一段），全库唯一；重名导入时**整体替换**旧单元；
- `questions[].id`：`{单元id}-{number}`，必须唯一（重复时追加 `-2` 后缀）；
- `difficulty`：★ 个数（1~3），缺失为 0；
- `type`：`判断|填空|选择|计算|应用|找错` 六选一；
- `options`：仅选择题有，`[{"key":"A","text":"…"}]`；判断题选项为空（前端固定给"正确/错误"两个按钮）；
- `answers`：字符串数组；多空/多问按 `;;` 拆分后的顺序，与题干中 `____` 顺序一一对应；
- `stem`/`solutionMd`：保留原始 markdown（含 `$...$` LaTeX），前端负责渲染；
- `lectures[].id`：`lec-<序号>`；同 title 再导入时替换。

## 2. 提交记录（submission record，学生端 POST 的 body）

存为 `data/submissions/<学生名净化>-<yyyymmdd-HHMMSS>-<4位随机>.json`：

```json
{
  "version": 1,
  "student": "小马虎",
  "unitId": "练习四",
  "unitName": "有理数加法",
  "submittedAt": "2026-09-24T12:00:00.000Z",
  "durationSec": 600,
  "device": "ipad",
  "questions": [
    {
      "id": "练习四-1",
      "number": 1,
      "type": "计算",
      "textAnswer": "8",
      "correct": true,
      "autoGraded": true,
      "strokesPng": null,
      "timeSec": 45,
      "teacherMark": null,
      "teacherComment": null
    }
  ]
}
```

- `textAnswer`：多空用 `;;` 连接；手写题允许为空串；
- `strokesPng`：`data:image/png;base64,…` 或 null；
- `correct`：客观题=自动判分结果；手写题提交时为 null，等教师批注；
- `autoGraded`：true=机器判的，false/null=待教师批注；
- `teacherMark`：null | `正确` | `错误`；`teacherComment` 可选字符串；
- `device`：`ipad|pc|other`（前端按 UA 粗判）。

## 3. HTTP API 契约（除静态文件外全部 JSON；请求/响应均 UTF-8）

| 方法 | 路径 | 请求 body | 成功响应 | 失败 |
|---|---|---|---|---|
| GET | `/api/health` | - | `{"ok":true,"time":"<ISO>"}` | - |
| GET | `/api/content` | - | 200 + content.json 全文 | 404 `{"ok":false,"error":"CONTENT_NOT_FOUND"}` |
| POST | `/api/content` | content.json 全文 | `{"ok":true}` | 400 |
| POST | `/api/import` | 见下 | `{"ok":true,"content":<全文>}` | 400 `{"ok":false,"error":"<原因>"}` |
| POST | `/api/submit` | submission record | `{"ok":true,"file":"<文件名>"}` | 400 |
| GET | `/api/submissions` | - | `{"ok":true,"submissions":[{"file":"…","record":{…}},…]}`（按 submittedAt 倒序） | - |
| POST | `/api/grade` | `{"file":"…","questionId":"…","teacherMark":"正确","teacherComment":"…"}` | `{"ok":true}` | 400/404 |

`/api/import` body（三选一，按 `kind` 区分）：

```json
{"kind":"practice","filename":"有理数配套练习.md","markdown":"…练习册MD全文…"}
{"kind":"lecture","title":"第 4 讲 加法——方向参与的合并","markdown":"…讲义MD全文…"}
{"kind":"content","content":{…content.json 全文，整库替换…}}
```

- `kind=practice`：服务端调 `parser.parse(markdown, filename)` 得到 `units`，逐个按 `id` 合并进 content.json（同 id 替换）；
- `kind=lecture`：追加/替换（同 title）一条 lecture，`id` 自动编 `lec-<n>`。**智能切分**：markdown 含 ≥2 个"第 X 讲"标题（H2/H3 均匹配）时按讲拆成多条（前言单独成讲、标题取 H1；每讲首行规范为 H2；同题替换），单一标题时按整篇处理；
- `kind=content`：整库替换。
- 响应一律带最新 content 全文，便于前端刷新。

其他服务端规定：

- 端口默认 **8787**，监听 `0.0.0.0`，可用 `--port`/`--host` 覆盖；数据目录可用 `--data` 覆盖（默认 `./data`，测试必须用它指向临时目录）；
- JSON body 上限 25 MB（手写 PNG base64 较大）；超限返回 413；
- 文件名净化：`[\\/:*?"<>|]` 及空白替换为 `_`；
- 静态文件只准 GET，根路径默认 `index.html`，拒绝路径穿越（`..`），无目录列表；mime 表至少含 html/js/css/png/svg/json/ico；
- 未知 `/api/*` 返回 404 JSON；所有响应头 `Content-Type: application/json; charset=utf-8`；
- `server.py` 必须暴露 `make_server(host, port, data_dir) -> http.server.ThreadingHTTPServer` 供测试导入，`if __name__ == "__main__"` 才进入 CLI；
- CLI 下 `python server.py` 启动后在控制台打印本机各局域网 IP 与访问地址，Ctrl+C 退出。

## 4. parser.py 契约（T1）

解析目标格式 = 《有理数打磨/01_线上格式规范.md》第 3 节。**写代码前必须先读该文件。**

- 接口：`parse(markdown: str, source: str = "") -> dict`，返回 `{"version":1, "source":source, "units":[…如第 1 节 schema…]}`（无 lectures 字段）；
- 单元切分：`## ` 二级标题开启新单元，取其后前 3 行内的 `<!-- UNIT: 名称|讲次|主题 -->`；缺失时从 H2 文本推断（`lecture=""`、`topic=H2去编号标题`）；全文无 H2 但有题时归入单个"未命名单元"；
- 题目切分：`#### 题 N（★★）`，N 取整数，难度=★ 个数；
- `【题型】`、`【考点】` 各占一行紧跟题号行；题型不在六值内时原样保留但转小写？——**不转**，原样保留，前端按未知类型归入手写题处理；
- 题干：考点行之后到 `<!-- ANSWER:` 行之前的所有行；其中以 `A. `~`D. ` 开头的行抽为 `options`，其余拼回 `stem`；
- 答案：正则 `<!--\s*ANSWER:\s*(.*?)\s*-->`，按 `;;` 拆分并 trim；
- 详解：`<details>`…`</details>` 之间内容，剔除 `<summary>…</summary>` 行，剩余文本存 `solutionMd`；无详解则为空串；
- 兼容 CRLF、UTF-8 BOM；容忍题内空行；输入含 emoji/HTML 时**不清洗不报错**，原样保留；
- CLI：`python parser.py <md文件>` 输出解析结果 JSON 到 stdout（UTF-8，`sys.stdout.reconfigure(encoding="utf-8")` 防 Windows 控制台 GBK 报错）；
- 测试 `tests/test_parser.py`（unittest）：至少覆盖——单元切分与 UNIT 注释、六种题型各一、多空 `;;` 答案、选择题选项抽取、难度星解析、详解提取与 summary 剔除、无 UNIT 回退、CRLF+BOM 输入、重复题号 id 去重后缀。测试数据可内嵌字符串，不依赖 samples 文件。

## 5. 判分规范化（T3a 在前端实现，规则如下）

`normalize(s)`：NFKC 规格化 → 去掉全部空白 → `﹣－–—−` 统一映射为半角 `-` → 去掉 `$` 与 `\left` `\right` → 首尾 trim。

- 判断题：`{正确,对,√,✔,T,TRUE,是}`→正确；`{错误,错,×,✘,F,FALSE,否}`→错误；
- 选择题：学生所选字母与答案字母大写比较；
- 填空/计算/找错/应用的文本填法：逐空 normalize 后全等；**全部空对**才算 correct=true；
- 手写题不自动判分（correct=null）。

## 6. 手写组件契约（T3a，`public/js/handwrite.js`）

- 暴露全局 `Handwrite.create(container, opts)` → 返回 `{getPNG(), isEmpty(), clear(), undo(), redo(), destroy()}`；
- Pointer Events + `touch-action:none`；"仅笔"模式只接受 `pointerType==='pen'`（防手掌误触）；学生端按设备智能默认（平板仅笔、电脑可写，以 UA+maxTouchPoints 判定，勿信 maxTouchPoints 单一信号）；工具栏开关"仅笔/笔·手指·鼠标"同页跨题记忆；仅笔模式下被拒输入在画布内弹提示条并支持一键切换；状态行实时显示最近输入的 pointerType 与 pressure（便于 iPad 实测）；
- perfect-freehand CDN `getStroke` 平滑 + 压感变宽；CDN 加载失败自动降级为普通折线（不许报错）；
- Canvas 按 devicePixelRatio 缩放；创建 2D 上下文时尝试 `desynchronized:true`（特性检测）；
- 笔迹以 CSS 像素坐标存储，resize/旋转后按新尺寸重绘不丢失；
- `getPNG()`：合成白底 + 传入的题目文字（opts.caption）导出 data URL；
- 大按钮（≥44px）：撤销/重做/清空；黑色笔迹。

## 7. 页面行为规定

**学生端 index.html（T3a）**：

1. 首屏输入姓名（localStorage 记住，历史姓名下拉可选），进入后顶栏显示姓名与"离线/已连接"状态；
2. 两个 Tab：讲义 / 练习。讲义列表→阅读页（marked+KaTeX 渲染 `lectures[].markdown`）。讲义渲染管线（2026-09-24 #4 修复后）：`$..$`/`$$..$$` 先抽占位符再过 marked 后还原（防 Markdown 语法破坏公式）；行内公式含 `\begin{}` 或为长链式等式（≥3 段且去空白 ≥18 字符）自动转 `aligned` 多行展示；`**【解】**` 段落自动折叠为 `<details class="lec-sol">`；页面顶部由 H2/H3 自动生成"本讲目录"锚点导航。练习列表（units）→答题页；
3. 答题页按题渲染：判断→两按钮；选择→选项按钮（单选）；填空→按 `answers.length` 给 N 个输入框；计算/应用/找错→手写板（可折叠）+ 可选"最终答案"输入框；
4. 题卡顶部：题号、题型徽章、难度★、考点；底部固定"交卷"按钮；进页开始计时（durationSec）；
5. 交卷=组 submission record → POST /api/submit；成功后每题显示 ✓/✗（客观题）并展开详解 `<details>` 样式折叠块（渲染 solutionMd）；失败则提示并允许重试；
6. CDN 不可用时：KaTeX/marked 降级为转义后纯文本展示，页面功能不得崩溃；
7. 每题有独立用时统计（该题首次可见→交卷，P2 可简化为粗略值）。

**教师端 teacher.html（T3b）**：

1. 三个 Tab：内容管理 / 提交记录 / 导出；
2. 内容管理：选择本地 .md 文件（或粘贴文本）→"导入为练习"/"导入为讲义"→ POST /api/import → 显示导入结果（单元数、题数、题型分布）；另有 content.json 下载与整库 JSON 导入（kind=content）；
3. 提交记录：按学生分组倒序列出提交；点开详情→逐题表：题号/题型/学生答案/自动判分✓✗/手写图缩略（点击放大）/【正确】【错误】批注按钮（POST /api/grade）；
4. 导出：当前筛选下全部提交 → CSV（带 `\ufeff` BOM 防 Excel 乱码；手写图不在 CSV 内，列名含"手写:有/无"）；
5. 风格与学生端一致：浅色、中文、触控友好。
