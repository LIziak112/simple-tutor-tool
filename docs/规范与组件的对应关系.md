## 规范与组件的对应关系

`规范.md` 文件头写明它由 `pnpm gen:spec` 从两个数据源生成：指令清单来自 `packages/contract/src/directives.ts`(指令注册表)，lint 错误码来自 `packages/md-dsl/src/lint/rules.ts`。前端渲染层不直接消费规范文档，而是**与它共享同一个注册表**——规范描述的每种指令(16 个:question、hint、answer、solution、blank、example、steps、step、fold、tip、warning、box、columns、col、mark、image、graph)在 `apps/web/src/features/markdown/directives/` 下各有一个 React 组件。

## 渲染实现：四层结构

**第 1 层：统一入口 [RichMarkdown.tsx](C:\Users\HUAYU\Documents\github\simple-tutor-tool\apps\web\src\features\markdown\RichMarkdown.tsx)**

所有 Markdown/DSL 内容都通过这一个组件渲染，内部是 react-markdown 的插件管线(与 `packages/md-dsl` 服务端解析器用同一套 remark 插件，保证解析口径一致)：

```
remarkParse → frontmatter → math → gfm → directive(三种指令语法解析)
  → remarkBlank([[…]] → blank 指令)
  → remarkDirectiveHost(指令节点 → 宿主标签)
rehype → katex(公式) → sanitize(白名单清洗)
```

**第 2 层：两个自研 remark 插件(remark/ 目录)**

- [remark-blank.ts](C:\Users\HUAYU\Documents\github\simple-tutor-tool\apps\web\src\features\markdown\remark\remark-blank.ts):把题干中的 `[[答案]]` 填空语法糖切分成名为 `blank` 的行内指令节点；数学环境(`$…$`)内的 `[[…]]` 整棵子树跳过。**答案内容在这一步就被丢弃**，只留下空填空框——这是防泄露的第一道关卡。
- [remark-directive-host.ts](C:\Users\HUAYU\Documents\github\simple-tutor-tool\apps\web\src\features\markdown\remark\remark-directive-host.ts):利用 remark-rehype 官方的 `data.hName`/`data.hProperties` 机制，把三种指令写法映射为三个自定义宿主标签——容器 `:::name` → `directive-container`、块 `::name` → `directive-leaf`、行内 `:name` → `directive-text`。它还在深度优先遍历时维护计数器，给 question/hint/step/blank 注入文档顺序编号(`index`,即“第 N 题”“提示 N”),组件无需跨组件通信就能显示序号。

**第 3 层：指令 → 组件映射层 [directives/index.tsx](C:\Users\HUAYU\Documents\github\simple-tutor-tool\apps\web\src\features\markdown\directives\index.tsx)**

一个工厂函数 `createDirectiveHost` 生成三个宿主组件，注册到 react-markdown 的 `components` 接管那三个宿主标签。宿主组件从 hast properties 还原出 `{name, attrs, directiveClass, index}`,先经 `getDirective()`(contract 注册表)把**别名归一到主名**，再查 `directiveComponents` 映射表(16 个指令各一行)渲染对应组件；查不到就渲染 `<UnknownDirective>`——灰色虚线框 + 保留内部文字 + 标注“未支持指令：xxx”,页面不报错不崩溃，对应 AGENTS.md 第 11 条的优雅降级。

**第 4 层：具体指令组件(directives/ 下 6 组文件)**

每个组件只接收统一的 `DirectiveProps`(name/attrs/directiveClass/index/children,见 [types.ts](C:\Users\HUAYU\Documents\github\simple-tutor-tool\apps\web\src\features\markdown\directives\types.ts)),不接触 hast 细节。例如 [Callout.tsx](C:\Users\HUAYU\Documents\github\simple-tutor-tool\apps\web\src\features\markdown\directives\Callout.tsx) 中 tip/warning/box 三个指令共用一个 `Callout` 骨架，只差配色与默认标题；box 还按 `{.样式类}` 简写切换 warning/info/success/neutral 四种变体。children 已是 react-markdown 渲染好的 React 子树，组件只负责外壳样式与交互(如 steps 逐步揭晓、hint 折叠)。

## 两个横切设计

**安全([sanitize.ts](C:\Users\HUAYU\Documents\github\simple-tutor-tool\apps\web\src\features\markdown\sanitize.ts))**:rehype-sanitize 白名单在 defaultSchema 之上放行了三类东西——指令宿主标签及其属性(指令名刻意放在 `directive` 属性而非 `name`,避开 sanitize 会强制加前缀的 clobber 属性)、KaTeX 的 MathML/SVG 输出(否则公式被静默剥坏)、GFM 复选框；`src` 只允许 http/https 协议，`javascript:` 被拦截。原始 HTML 因未开 `allowDangerousHtml` 在上游已丢弃，sanitize 是第二层纵深防御。

**答题交互**：填空在答题页不是静态下划线——`BlankAnswersContext` 按注入的 blank 编号把空框渲染为可输入控件，收集学生答案。

## 调用方

`RichMarkdown` 被教师端(导入预览、内容编辑)、学生端(讲义阅读页 `StudentLectureViewPage`、答题卡 `AttemptQuestionCard`、结果页)共用，还有一个开发调试页 `pages/dev/RenderDevPage.tsx`。

总结成一句话：**规范.md 是注册表的投影，渲染端以“三个宿主标签 + 一张映射表”承接全部指令——新增一个指令只需注册表加定义、映射表加一行、写一个组件(即 add-directive 技能的四步流程)，解析器底层永不改动**。
