# 资源库文件夹栏与侧栏优化方案（A + C）

> 状态：**已实施**（方案成文于 2026-09-30；2026-10-01 于 task/ui-library-sidebar 分支实施，见文末「7. 实施记录」）
> 适用页面：`/t/library`（资源库，讲义库 / 题库 / 回收站三页签）
> 结论先行：**A 治「丑」**——把每个文件夹下常驻的 4 个操作图标收进「⋯」菜单；**C 治「怪」**——侧栏面板化、滚动钉住、放宽容器、细节对齐。两者相互独立，可分别实施、分别提交。

---

## 0. 背景与问题诊断

### 现象 1（丑）：文件夹操作按钮常驻，侧栏被图标撑爆

每个文件夹渲染成**两行**（见 `FolderSidebar.tsx` 头注释）：

- 第一行 = 拖拽把手 + 文件夹名（超长截断、title 悬停看全名）+ 计数；
- 第二行 = **常驻** 4 个 44×44px 图标按钮：重命名 ✏️ / 上移 ↑ / 下移 ↓ / 删除 🗑，`pl-12` 与名称起点对齐。

代码注释写明了这是当时的设计取舍：无障碍规范 §4-9 要求触控目标 ≥44px 且拖拽必须有按钮兜底，「单行会把名称挤到不可读」，于是做成两行常驻。代价是：文件夹一多，侧栏被成片的图标占满，视觉噪音大、高度翻倍。

### 现象 2（怪）：侧栏缺整体感，滚动即失联

- 文件夹文字与图标浮在白色页面背景上，与右侧列表无视觉分界，看起来是散落元素而非「导航面板」；
- 列表一长，向下滚动时文件夹栏跟着滚出屏幕，切文件夹必须先滚回顶部；
- 页面容器 `max-w-6xl`（1152px）居中，宽屏（尤其 5173 开发模式无全局导航时）两侧大量留白；
- 计数数字宽度不一（「1」与「11」），右对齐后参差。

## 2. 方案 A：文件夹单行 + 「⋯」下拉菜单

### 2.1 目标效果

```
现在（每夹两行）                 改后（每夹一行）
┌──────────────────────┐      ┌──────────────────────┐
│ ⠿ 📁 第二章节        1 │      │ ⠿ 📁 第二章节    1  ⋯ │ ← ⋯ 悬停/聚焦时浮现
│    ✏  ↑  ↓  🗑       │      │ ⠿ 📁 1           8  ⋯ │
│ ⠿ 📁 1               8 │      └──────────────────────┘
│    ✏  ↑  ↓  🗑       │        点 ⋯ 弹出菜单：
└──────────────────────┘        ┌──────────────┐
                                │ ✏ 重命名     │
                                │ ↑ 上移       │（首项时禁用）
                                │ ↓ 下移       │（末项时禁用）
                                ├──────────────┤
                                │ 🗑 删除（红） │
                                └──────────────┘
```

行高约从 100px 降到 44px，图标噪音归零；四个操作一个不少。

### 2.2 交互设计

1. **行结构**：`DragHandle`｜`📁 名称（截断 + title）`｜计数｜`⋯` 按钮（`size-11`，ghost）。名称占 `flex-1`，较现状更宽。
2. **⋯ 的显示时机**（关键，三者并用）：
   - 桌面：`opacity-0 group-hover/item:opacity-100`（行 hover 浮现，`transition-opacity`）；
   - 键盘：`group-focus-within/item:opacity-100`——Tab 到行内任意元素时 ⋯ 必须可见，不能只靠 hover；
   - 触屏：`pointer-coarse:opacity-100` 常显（Tailwind 4.3 内置变体；触屏无 hover，不常显则功能不可发现）。
   - 行容器加 `group/item`。
3. **菜单内容**：重命名 / 上移 / 下移 / 分隔线 / 删除（删除项红色 destructive）。菜单项沿用现有 aria-label 文案（`重命名文件夹 X`、`上移文件夹 X`、`下移文件夹 X`、`删除文件夹 X`），**保持与现单测的选择器兼容**（只需先开菜单）。
4. **边界禁用**：第一个文件夹的上移、最后一个的下移置 `disabled`，与现状 `canMoveUp/canMoveDown` 一致。
5. **重命名**：主路径 = 菜单 → 重命名（`setRenaming(true)`，现有整行改名表单原样保留）；增强 = **双击名称**直接进入改名（`onDoubleClick`，与菜单同入口）。Esc 失焦取消、Enter 提交，沿用现有 form 逻辑。
6. **删除**：菜单 → 删除 → 现有 `DeleteFolderDialog` 二次确认，不动。

### 2.3 无障碍（§4-9）合规说明

- `⋯` 触发按钮 `size-11`（44px）✔；
- 菜单项设 `min-h-11`（radix DropdownMenuItem 可带 className）✔；
- 拖拽把手不动；「按钮兜底」从行内常驻改为菜单可达，功能仍全部有非拖拽路径 ✔（实施后人工过一遍纯键盘路径：Tab → ⋯ 可见 → Enter 开菜单 → 方向键选 → Enter 执行）；
- 触发按钮加 `aria-haspopup="menu"`、`aria-label="文件夹「X」的更多操作"`；菜单可访问名实施时由 radix 自动经 `aria-labelledby` 取触发器文案（「文件夹「X」的更多操作」），比原计划的裸文件夹名更具辨识度，Content 上不再另设 `aria-label`（设了也会被 labelledby 覆盖）。

### 2.4 改动点清单（文件级）

1. **新增 `apps/web/src/components/ui/dropdown-menu.tsx`**：按项目现有 shadcn 模式（参考 `dialog.tsx` 的写法）从 `radix-ui` 引 `DropdownMenu` 命名空间，只封装本页用到的子集：`Root / Trigger / Content / Item / Separator`，Content 走 portal、`min-w-40`、`min-h-11` 于 Item。项目无现成参照的动画可用 `tw-animate-css` 已有类（`data-[state=open]:animate-in` 等，dialog.tsx 里应有同类写法可抄）。
2. **改造 `FolderSidebar.tsx` 的 `SortableFolderRow`（304-458）**：
   - 删除第二行操作区（407-451）；
   - 第一行末尾加 `⋯` 按钮 + `DropdownMenu`；四个菜单项 onClick 分别接现有 `setRenaming(true)` / `onMove(-1)` / `onMove(1)` / `onDelete`，逻辑零改动；
   - 行容器（`SortableItem` 渲染的 `li`）加 `group/item`；`⋯` 按钮按 2.2-2 加显隐类；
   - 名称按钮加 `onDoubleClick` 进改名。
3. **`FolderSidebar.tsx` 其余部分、`LibraryPage.tsx` 逻辑**：不动。
4. **同步改 2 个单测**（`LibraryPage.test.tsx:394-441`）：在点「重命名/上移」前先 `fireEvent.click(await screen.findByRole("button", { name: "文件夹「有理数」的更多操作" }))`（radix 菜单在 jsdom 下默认同步挂载 Content，开菜单后 `findByRole("menuitem", ...)` 即可）。测试头注释「两行布局回归」相应更新为「⋯ 菜单回归」。

### 2.5 风险与注意事项

- **dnd-kit 冲突**：`⋯` 按钮与菜单都在 `SortableItem` 内，但未挂 `handleListeners`，不会触发拖拽；DropdownMenu Content 走 portal 渲染在 body，与 DndContext 无层级冲突（低风险，实施时验证一次「菜单打开状态附近拖拽另一文件夹」即可）。
- **触屏可发现性**：靠 `pointer-coarse:opacity-100` 常显兜底；验收时用 DevTools 模拟触屏确认。
- **jsdom 菜单渲染**：若单测里 radix 菜单 Content 因动画/portal 不挂载，退路是在测试里用 `pointerEvents: "none"` 兼容或直接断言 `onMove` 回调（实施时定，工作量不变）。

## 3. 方案 C：侧栏整体打磨（四个子项，全部只改类名/容器，零逻辑）

### C-1 面板底：给文件夹栏一块「底盘」

- **现状**：文字与图标直接浮在页面白底上，只有选中项有胶囊底，侧栏与列表无分界。
- **做法**：`FolderSidebar.tsx:141` 的 `<aside>` 类名追加 `rounded-xl border bg-muted/30 p-2`（或 `p-3`）；标题行与空态提示（241-243「还没有自定义文件夹」）的左右 padding 相应微调，保持文字与列表左缘对齐。
- **效果**：侧栏成为一块浅灰圆角面板，与右侧白色列表自然分区，与左侧全局导航的分组感呼应。

### C-2 粘性定位：滚动时侧栏钉住

- **现状**：`aside` 随页面流滚动，列表一长文件夹导航即不可见。
- **做法**：`aside` 追加 `md:sticky md:top-6 md:max-h-[calc(100vh-3rem)] md:overflow-y-auto`。仅在 md+（双列布局）生效；`max-h + overflow` 保证文件夹很多时面板内部自己滚，钉住部分永远完整可见。
- **前提已核实**：父容器 `LibraryPage.tsx:525` 的 flex 链上无 `overflow-hidden`，sticky 可正常工作；移动端单列不受影响。

### C-3 放宽容器：宽屏少留白

- **现状**：`LibraryPage.tsx:404` 容器 `max-w-6xl`（1152px）。8787 生产布局左侧已有全局导航，1500px 屏下每侧仅约 60px 留白，收益中等；**5173 开发模式（无全局导航）或 ≥1600px 屏幕收益明显**。
- **做法**：`max-w-6xl` → `xl:max-w-7xl`（1280px，仅 ≥1280px 视口放宽；该类名只影响本页，不动其他页面）。
- **代价**：列表行变长，标题截断裕度更大；搜索框、BatchBar 同步变宽，无需其他调整。

### C-4 细节两枚

1. **计数等宽对齐**：`FolderSidebar.tsx` 两处计数 `<span>`（298、402）加 `tabular-nums`，多位数右对齐不再参差。
2. **选中项左侧竖条**：给选中态（`FolderItemButton` 292 与 `SortableFolderRow` 选中按钮 394 的 active 分支）加非位移实现——**不要用 `border-l-2`**（会挤入 2px 引起文字跳动），用 `shadow-[inset_2px_0_0_var(--color-primary)]` 或 `before:` 伪元素。与现有 `bg-primary/10 text-primary` 胶囊叠加即可。
