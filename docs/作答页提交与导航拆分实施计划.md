## 职责与写集

- `AttemptSession.tsx`：保留草稿恢复、答案/过程采集、题卡注册与虚拟挂载、AI dock、材料与题卡 JSX 装配。共享的滚动当前题仍在容器；不改变题卡树位、key、正式手写与圈画生命周期。
- `use-attempt-question-location.ts`：拥有布局初值/显式切换、账号首次绑定补齐、单题当前题优先级、URL q 与单题容器焦点。读取位置仍复用现有 `useReadingPosition`。
- `use-attempt-question-navigation.ts`：拥有答题卡开合/返回焦点、显式跳题信号、懒挂载后对齐、单题本机落盘与 AI 收起保护及重试；同文件的键盘 hook 只路由既有命令、保留同步锁与守门链。这些逻辑随“怎样安全地切题”共同变化。
- `use-attempt-practice-submission.ts`：协调既有逐题提交结果、缺稿弹层、选中即提交偏好与串行队列；复用 `usePracticeQuestionSubmit`，不复制 CAS/证据/反馈缓存。
- `use-attempt-submit-confirmation.ts`：协调整卷证据题集与 revisions、既有整卷 flow 与确认状态机、取消/重开中止标记；不再包装网络层。
- `AttemptSessionActions.tsx`：呈现列表/单题的底栏与主操作；`AttemptSessionDialogs.tsx` 呈现答题卡与两种提交确认弹层。按操作条和弹层的共同变化拆分，均不创建题卡、移动题面或接管草稿状态。
- 必要文档与 `scripts/file-size-baseline.json`：只下调原容器基线，补最小模块索引与真实验证记录。原容器如仍超 1000 行，继续使用下降后的历史基线；新模块均低于 1000 行。禁止 part2、等价转发链、删空行或压句凑数。

## 依赖有向图

```text
草稿/材料/题卡注册 -> 阅读位置 -> question-location
question-location -> usePracticeQuestionSubmit
usePracticeQuestionSubmit -> submit-confirmation / practice-submission
AI dock + question-location + 逐题 busy -> question-navigation
question-navigation + 两种提交入口 -> 键盘动作
上述状态/动作 -> Controls 与原题卡装配
```

AI 旧任务定位仍通过原有 `goToQuestionRef` 晚绑定导航入口，这是原代码已存在的唯一回调反向边；不新增 callback ref 桥或万能 session context。所有 hook 均无条件调用，逐项核对 effect/callback 的依赖闭包、取消与代次保护，不能用抑制 lint 换绿。

### 等价性与审查边界

- 简化自查：复用原有 `usePracticeQuestionSubmit`、`useAttemptSubmitFlow`、`useSubmitEvidenceConfirm` 和 `useReadingPosition`，未引入通用会话 context、额外 callback ref 桥、依赖或请求；操作条/弹层拥有实际呈现和裁决职责。
- 正确性自查：所有 hook 无条件调用，状态在同一 AnswerView 生命周期中稳定；移动的 effect 体和依赖保持一致。URL 同步 effect 随题位迁入 hook，仍 replace 并保留其他参数，不以提交 overlay 推动自动切题；底层提交 effect 不读 URL。编辑器 → 本机落盘 → AI 收起 → 题位/跳题的保护次序、键盘同步锁、取消/重开中止标记和队列暂停条件保持原样。传入 recorder ref 后仅补其稳定身份为 callback 依赖，仍在提交回执后读取 current 校验 attempt。AST 检查对位置/注释/格式忽略，仅规范化局部别名和该 ref 依赖。
- 学生载荷安全自查：适用。无新增出口，提交 revisions/证据题集与 UI 的反馈可读门保持原 AST；普通投影、AI 授权、服务端判分与 CAS 实现未变。没有扩大答案/解析或其他学生数据可见性。独立审查由主会话另行安排，本记录只代表实现者自查。
