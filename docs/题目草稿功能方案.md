## 1. 目标与非目标

**目标**:每道题可展开一块**独立草稿区**(Apple Pencil 手写演算),笔迹持久保存;回看做题记录时看到自己的演算过程;草稿与题目强关联,可连同题干/作答/解析一起**导出给 AI 评析**(单题即时、整套批量)或导出为图片。

**非目标**(本期明确不做):

- 不做"笔迹叠在题干文字上"的覆盖式标注(评估过,指针穿透、重排错位、z-index 三类复杂度收益比差,已否);
- 不做草稿回放、草稿判分、草稿进作答上传链路;
- 不做整卷一张长草稿纸(无法按题归因,已否);
- 学生端学情/AI 直连(Phase 5 范畴)、锚定内容的相对坐标对齐(远期)。

## 3. 设计决策(D6.x)

- **D6.1 独立草稿区,归属 `(studentId, questionId)` 全局单份**(用户定,2026-10-04)。草稿是学生对"这道题"的演算层,跨 attempt 持续(错题重练、二次作答、回看都可见),交卷不清除。不按 attempt 冻结快照——评析包带草稿 `updatedAt` 标注新鲜度即可,不为快照翻倍存储。questionId 非全局唯一(§2 复合主键):笔记语义上归属"学生所属教师域内的这道题",服务端一律按 `(student.teacherId, questionId)` 查题目;UNIQUE(studentId, questionId) 仍成立(学生归属唯一教师)。
- **D6.2 草稿不校验 attempt 状态**:交卷后仍可写(个人学习层,非作答)。与作答 ink 的 `ALREADY_SUBMITTED` 409 口径(`ink-service.ts:192`)刻意分离。题目归属简化为"**学生所属教师域内**存在且未软删"即可读写(按 `(student.teacherId, questionId)` 复合查询,**绝不按全局 questionId 查**——跨教师同 id 合法共存,见 §2)——草稿内容为学生自产、无泄露面,不做课程/作业可见性判定(避免 D7 失权链复杂度;失权后笔记保留,重新可见)。不设每学生总量配额(自部署一对一场景,单条 ≤2MB 且域内题目数有限)。
- **D6.3 手写题(solve/apply/find-error)P1 不显示草稿按钮**:它们已有答题区,同卡双画布徒增困惑。是否放开留待 P2 复议。
- **D6.4 布局三态 + 注册表 + 设备级偏好**(用户定,2026-10-05)。配置分两层:**影响呈现保真的进 noteDoc(随笔记走、跨设备一致:padHeightLogical、bgStyle);只影响本机编辑体验的进 localStorage(随设备走:布局)**。布局注册表 `NOTE_LAYOUTS = { auto / side / below }`,`resolve(viewportWidth)` 纯函数归一;`side` 在 <1024px(对齐 Tailwind lg,常量单点)静默回退 `below`(物理约束)。未来"全屏草稿/浮窗"= 注册表加项,消费方零改动。不做服务端偏好系统。
- **D6.5 高度:自动加高(复用 72px/+240px 语义)+ 底部拖拽把手,上限 3000 逻辑单位**;高度与背景样式持久化在 noteDoc。侧栏模式下高度 = max(自动加高状态, 兄弟列高度(grid 拉伸))。
- **D6.6 双存储镜像 ink 表**:`strokesPath`(.json.gz)+ `pngPath`,`(studentId, questionId)` 唯一 upsert;合计 ≤2MB 复用现有 413 预检/解压炸弹防护。PNG 必须存:AI 评析、教师端、回看缩略都吃图,不依赖客户端现场渲染。
- **D6.7 防丢独立成仓**:IDB `tutor-notes` 仓、key `note:<studentId>:<questionId>`(含 studentId,防共用 iPad 多账号串写——draft 先例靠 attemptId 天然隔离,note 没有),与 `tutor-drafts` 物理分开——**交卷 `clearDraft` 永不触碰草稿**(`tutor-drafts` 是单 store,clearDraft 删整条记录,inks 随之清;进结果页另有兜底清除)。同步机制照抄现状两层的组合:控制器层 = `use-ink-upload` 的 2s 防抖 PUT + dirty 标志去重(笔迹上传现状并无 digest 去重,那是答案链路;PNG 每次上传现导,与 ink 现状一致);事件层 = `use-draft-sync` 的 visibilitychange(hidden→PUT)+ pagehide(只落 IDB 不 PUT,服务端靠下次按 updatedAt 合并兜底)。加载时本地/服务端按 `updatedAt`(UTC 毫秒)新者胜。
- **D6.8 回看 = PNG 直出**(本人 `note.png` 接口,同作答 ink 的 `InkThumbnail` 模式,懒加载 + onError 隐藏);错题重练渲染快照时草稿按 questionId 全局带出。教师端可见性 P2(批改填空/选择时看演算,诊断价值高)。
- **D6.9 AI 评析导出 = 扩展现有 LearningPack,不另建管线**(2026-10-05 定)。①教师整套:D14 模块表新增「草稿 PNG(`question_notes`,默认关)」一行,D17 prompt 模板四→五(新增「逐题评析(含草稿)」:逐题对照题干/学生作答/判定/行为数据/草稿,指出错误步骤与知识点)——`/t/export` 向导与 MCP `get_student_learning_pack` 自动受益。②单题即时(学生结果页/教师详情页):客户端轻量组合「复制评析文本 + 下载/复制笔迹图」,复用同一纯函数(两个上下文:学生版**不含行为数据段**——activeSec/changeCount/hintsUsed 只在教师端契约,学生端结果契约没有,待 P3 学生端契约扩展后再加;学生版"正确答案/判定/解析"三段均按 `answersReleased` 门控,未公布时服务端已把这些字段置 null,前端字段缺省即整段不渲染;教师版恒含解析、评语、最终判定与行为数据)。文本为主、笔迹为图:题干/解析用快照 Markdown 原文(`$...$` LaTeX 原样保留),手写草稿/作答以 PNG 给出(教师版草稿图待 T6.10,见 §7.1)。
- **D6.10 人看合成图导出用 html-to-image**(MIT,~10KB,唯一新依赖,PR 说明理由与替代方案:html2canvas 字体痛点排除、snapdom 生态新、自研 foreignObject 不值、服务端 Puppeteer 资源错配)。KaTeX 字体:全量 `getFontEmbedCSS()` + `preferredFontFormat: 'woff2'`,会话级缓存——**不做过滤**:已核实 apps/web 无其他 @font-face,唯一字体来源即 katex.min.css(getFontEmbedCSS 无 filter 参数;KaTeX 字体实际为 `/assets/KaTeX_*-<hash>.woff2`,不存在 `/katex-fonts/` 路径段,**勿为此新造字体路径稳定化 vite 插件**);canvas 内联若 iPad Safari 异常,兜底为捕获前把 canvas 替换为 `exportPng()` dataURL `<img>`;`pixelRatio: 2` 自适应降级防 iOS 16.7M 像素上限。

## 4. 交互设计

### 4.1 布局(横屏分栏 / 竖屏下方,同一 DOM 媒体查询切换)

```
横屏(≥1024px,side)                      竖屏(<1024px,below)
┌─ 题卡 article ───────────────────┐   ┌─ 题卡 article ─────┐
│ 题号 · 题型 · [✏️草稿]            │   │ 题号 · 题型 · [✏️] │
│ ┌──────────────┬──────────────┐ │   │ 题干 / 选项 / 控件 │
│ │ 题干          │ 草稿区        │ │   │ ┌────────────────┐ │
│ │ 选项/作答控件 │ [笔|萤|橡|↶↷] │ │   │ │ 草稿区(280 起)  │ │
│ │              │ ~~~~~~~~~~~   │ │   │ │ ▁▁▁▁拖高▁▁▁    │ │
│ │              │ ▁▁▁▁拖高▁▁    │ │   │ └────────────────┘ │
│ └──────────────┴──────────────┘ │   └────────────────────┘
└──────────────────────────────────┘
```

- 题卡内 CSS grid(约 55/45),右列 = 草稿区,**grid 默认拉伸使右列与左列等高**,题干长则草稿区跟长;
- 开启/收起:题头 ✏️「草稿」按钮(44px);默认收起,收起不清笔迹、按钮带墨点标记,有笔迹的题下次自动展开;
- 布局切换入口在草稿工具条(布局图标 → 自动/右侧/下方),即时生效、写 localStorage(本设备全局,不按题记忆)。

### 4.2 手势矩阵(全部复用 atrament 适配器既有行为,零新开发)

| 输入 | 行为 |
| --- | --- |
| Apple Pencil 写草稿区 | 落墨;手掌搭屏不误触(见过笔后手指永不落墨;笔尖触屏期间 iPadOS 整体抑制手指事件) |
| 手指划草稿区 | 页面滚动(touch-action: pan-y),不落墨 |
| 笔悬停 | 预览圈不落墨 |
| 无笔设备 | 手指直接写 + 工具条「滚动/书写」开关(既有回退) |

选项与草稿天然无冲突:草稿区是独立 DOM 块,选项在题卡内容区,互不覆盖。

### 4.3 高度与背景

- 自动加高:距底 72px → +240px(与 InkPad 同参),上限 3000 逻辑单位(约 5 次扩展余量,一张卡最宽 ~700px × DPR2 远低于 iOS canvas 上限);
- 底部拖拽把手(仅把手 touch-action: none)手动调高;
- 背景三选一:空白/淡格线/横线(CSS 背景,画布透明在上),数学演算推荐格线;选择存 noteDoc,回看与导出同背景。

```ts
noteDocSchema = z.object({
```

### 5.2 表(`apps/server/src/db/schema.ts`,drizzle-kit 迁移,编号顺延)

```
question_notes:
  id uuid pk · studentId(→students) · teacherId(→teachers)   -- teacherId 冗余:写时取 student.teacherId 快照,导出/教师接口 join 免经 students
  questionId text    -- 学生所属教师域内的题目 id(复合主键 (teacherId,id) 的 id 分量;DSL id 可含中文/点/斜杠,落盘前经 safeInkFileName 同款处理)
  strokesPath text   -- blobs/notes/<studentId>/<安全名>.json.gz(.tmp 后 rename 原子替换)
  pngPath text       -- blobs/notes/<studentId>/<安全名>.png
  padHeightLogical int · bgStyle text · strokeCount int · updatedAt int(UTC 毫秒)
  UNIQUE(studentId, questionId)   -- upsert 幂等、id 稳定(同 ink 表先例);teacherId 随行写入不参与键
```

无软删列:清空 = 上传空 strokes 文档(前端以 strokeCount=0 视为"无草稿",墨点标记与自动展开据此判定)。题目软删后接口一律 404(同 D6.2 域内"未软删"校验),**行保留不删**,题目恢复即自动回读(孤儿无害)。

### 5.3 API

| 接口 | 说明 |
| --- | --- |
| `GET /api/student/questions/:questionId/note` | 本人草稿矢量文档;无 → 404 NOTE_NOT_FOUND |
| `PUT /api/student/questions/:questionId/note` | multipart `strokes`(gzip,载荷 = 整个 noteDoc,魔数判别同 ink)+ `snapshot`(png);合计 ≤2MB 走现有 413 预检与解压炸弹防护;不校验 attempt 状态(D6.2);**题目按 `(student.teacherId, questionId)` 域内查询,须存在未软删**;传输用原生 fetch + FormData(同 putAttemptInkApi 先例,hc 推断不出 form 入参);**必须接 `assertNoLeak`** |

```ts
// §6.1 note-layout.ts(示意)
export type NoteLayoutKind = "auto" | "side" | "below";
export type NoteLayoutResolved = "side" | "below";
export interface NoteLayoutDef {
  label: string;                                   // 自动 / 右侧 / 下方
  resolve: (viewportWidth: number) => NoteLayoutResolved;
}
export const NOTE_LAYOUTS: Record<NoteLayoutKind, NoteLayoutDef> = {
  auto:  { label: "自动", resolve: (w) => (w >= NOTE_LAYOUT_MIN_WIDTH ? "side" : "below") },
  side:  { label: "右侧", resolve: (w) => (w >= NOTE_LAYOUT_MIN_WIDTH ? "side" : "below") }, // 窄屏回退
  below: { label: "下方", resolve: () => "below" },
};
export const NOTE_LAYOUT_MIN_WIDTH = 1024;
```

状态全部 hooks 局部 state,不引 Zustand(与现状一致)。

## 7. AI 评析导出(D6.9)

### 7.1 单题即时(学生结果页 / 教师详情页,轻量客户端组合)

纯函数 `buildQuestionReviewMarkdown(ctx)` 产出(学生/教师两上下文复用):

````markdown
# 请分析这位学生的答题过程
你是数学辅导老师。请根据题目、学生作答、判定与学生草稿,指出错误步骤与知识点,给出讲解建议。

## 题目(第 3 题 · 单选 · 考点:一元二次方程)
(题干快照 Markdown 原文,$...$ LaTeX 原样)
## 学生作答
选择:A(正确答案:B)· 判定:错误
## 学生草稿(手写)
[scratch-q3.png · 更新于 2026-10-05 14:32]
## 解析
(快照原文;学生版未公布不含本节)
````

## 8. 人看合成图导出(D6.10,html-to-image)

- 场景:学生/教师把「题目 + 草稿」存图或分享(草稿工具条「导出图片」、结果页同入口);
- `toPng(题卡 article, { pixelRatio: 2, fontEmbedCSS, backgroundColor: "#fff" })`——题干 DOM(KaTeX/DSL 组件)与草稿画布一次成像;横屏导出即左右分栏构图,竖屏即上下;
- KaTeX 字体:会话级 `getFontEmbedCSS()` **全量内联,不做过滤**——已核实 apps/web 无其他 @font-face,唯一字体来源即 katex.min.css(getFontEmbedCSS 无 filter 参数;KaTeX 字体实际为 `/assets/KaTeX_*-<hash>.woff2`,不存在 `/katex-fonts/` 路径段,**勿为此新造字体路径稳定化 vite 插件**)+ `preferredFontFormat: "woff2"`;
- 兜底:canvas 内联异常时捕获前替换为 `<img>`(dataURL);超高卡自适应降 pixelRatio;
- 新依赖 PR 理由模板:对比 html2canvas/snapdom/自研 foreignObject/服务端 Puppeteer(§3 D6.10)。

## 10. 实施红线与坑位清单(执行时逐条对照)

1. **IDB 必须独立仓**(`tutor-notes`,key `note:<studentId>:<questionId>`):草稿仓 `tutor-drafts` 是单 store,交卷 `clearDraft`(及进结果页的兜底清除)删整条记录、inks 随之清——草稿绝不能混入;key 含 studentId 防共用设备两账号串写(§2);
2. **不复用 `responses.inkId` 死列语义**;草稿关联键只有 (studentId, questionId),**题目校验/查询一律走 `(student.teacherId, questionId)` 域内复合条件**(questionId 跨教师同 id 合法共存,绝不按全局 id 查);
3. **2MB 口径 = gzip 后 strokes + PNG 合计**,入口 content-length 预检 + 解压 32MB 上限,全部照抄 ink-service,勿另写一套;
4. multipart 字段名沿用 `strokes` + `snapshot`(与 ink 一致,hc 客户端推断友好);
5. **学生端评析组合的"正确答案/判定/解析"三段均受 `answersReleased` 门控**(服务端未公布时已把这些字段置 null,前端字段缺省即整段不渲染;组合函数不得从其他途径拼出这些内容);
6. `ResultQuestionCard` 已有 `overflow-hidden` + before 伪元素色条:草稿块放卡内正常文档流,不 absolute 溢出;
7. 事件埋点(若加 `note_edit_batch`)遵守 D12/D13:批次聚合、payload 只存计数不存内容;P2 再做;
8. LearningPack 扩展走 D19 模块化 schema(新 section 可选、未勾选不出现),prompt 模板进 contract 单一源并同步 `gen:spec` 产物(学情分析提示词.md 增补);`schema:export` 必跑;
9. html-to-image 为**唯一新依赖**,PR 描述写理由与替代方案(硬性规则 5);不引入 zip 客户端库(单题走剪贴板/下载,整套走既有服务端 archiver);
10. 布局常量 `NOTE_LAYOUT_MIN_WIDTH=1024` 单点定义,不散落 Tailwind 断点字面量;
11. 引擎升级(如 perfect-freehand 回迁)与本功能正交:一切经 InkSurface,换引擎零影响。
