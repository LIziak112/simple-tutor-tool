## 1. 我的判断

**Web 独立草稿区可行，现有 InkSurface 可以继续用；原方案不能直接按清单实施。** 最重要的修改不是换手写库，而是把“输入可靠、数据保存、按次留证、可用导出”四条链路闭合。

独立评审的核心判断正确：全局可修改草稿不能充当历史原稿，时间戳解决不了证据被覆盖；PNG 不能成为矢量保存的前置条件；实时题干覆盖层的“环境匹配”没有可靠的几何保证。但是，评审还是建议集合，缺少可直接执行的提交协议、迁移口径、状态模型和发布闸门。本稿补齐这些部分，并控制首版复杂度。

最终用户体验：

```text
做第一遍 → 本次草稿 → 交卷固定原稿 → 老师看原稿／导出本题
                                ↓
                           添加订正（独立记录）
                                ↓
重练同题 → 新空白草稿 → 再次交卷 → 按轮次对照

题目笔记本 = 汇总以上记录；不再是一份会覆盖历史的全局画布。
```

原稿指“交卷时保留下来的演算”，不等于全部思考过程。擦除和撤销的内容不永久留存；不新增事件溯源、笔迹录像或草稿自动判分。

## 4. 手写输入与纸张：具体解决办法

### 4.1 输入策略先明确，再谈低延迟

新草稿默认“笔写／手指滚动”，工具菜单提供“手指书写”；鼠标仍可写。纯触屏无笔用户主动切换书写，模式保存在设备偏好中。首次手掌触屏不应先落墨再期待 Apple Pencil 帮它擦掉。旧作答组件通过可选配置接入，新参数缺省保留兼容行为，单独验收后再推广。

在当前会话统一维护输入偏好，多个画布共享，避免每道题重新探测。设备偏好不是身份数据；笔迹与上传任务仍严格按账号隔离。不以 UA 字符串推断是否有笔。

笔输入、手指页面滚动和操作选项的区域分开。不能把“pointerdown 后修改 touch-action”当万能修复：手势开始后的更改不能可靠改变本次浏览器行为，参见 [W3C Pointer Events §8](https://www.w3.org/TR/pointerevents3/#the-touch-action-css-property)。现有 stylus touch 阻止默认行为须在真机保留验证；遍历触点并核对对应输入，不默认 `touches[0]` 总是笔。

输入状态机显式处理第二指针、pointercancel、lostpointercapture、窗口失焦、布局变化和卸载。只接受当前活动指针；取消时只保存已收到的真实采样，不补造终点。布局调整在收笔后执行；系统强制旋转时先结束当前真实笔段，再建立新变换，不允许一笔混用两个坐标变换。

### 4.2 低延迟的次序

1. 先量实际采样、事件处理耗时、重绘耗时及卡顿；不以“浏览器支持 API”代替手感验收。
2. 输入热路径只收点与轻量绘制；JSON 序列化、压缩、PNG 编码不在每个 pointermove 中执行。React 不接管每个采样点。
3. 能用合并采样则用，缺失或返回空数组时回退普通事件。Safari 18.2 增加相关 API 有官方记录，但 HTTP 与 HTTPS 必须分别能力探测。[WebKit 18.2](https://webkit.org/blog/16301/webkit-features-in-safari-18-2/)
4. 仅当实测不达标时加入临时笔迹层／帧调度；预测点只显示、下一批真实点到来即替换，绝不进入矢量、撤销历史或 PNG。双层也有内存成本，不能无条件增加大画布。
5. 不依赖 pointerrawupdate、Ink API、desynchronized 来满足首版目标；不对“Safari 27/TP”或固定支持上限作未经核实的断言。

### 4.3 逻辑坐标与高度

草稿纸宽固定为 1000 逻辑单位，高度首版默认 800、上限 3000；默认值为待真机确认的配置。显示比例 `scale = paperCssWidth / 1000`，CSS 纸高为 `paperHeightLogical * scale`。屏幕、PNG、历史回看使用同一坐标和背景间距。

自动加高可沿用距离底部 72 CSS px 的触发体验，但增加高度前换算成逻辑单位；拖高也同样换算。缩小时不得低于所有笔画包围盒（含线宽）加留白。首次默认高度不随每次横竖屏反复重写。

题干很长时外框可以等高，纸张不因此无限拉长。优先单一页面滚动，“回到题干”按钮解决长稿定位；达到上限显示剩余空间与导出入口。多页纸属于后续扩展，不以无限增长硬撑内存。

分栏初值 55/45，最终阈值由两列最低可用宽度与 gap 决定，1024 viewport 不作为硬约束。折叠题目仅显示缩略图／有笔迹标记，默认只挂载正在编辑的画布。工具条常驻笔、橡皮、撤销、更多，触控目标保持 44px。

## 5. 数据模型：身份、正文、图片分开

下列是待实现的契约与数据库概念，不是要求直接手写迁移。所有跨端类型先进入 `packages/contract`，再由 Zod 推导。

### 5.1 题目版本

新建 attempt 时，服务端冻结本次题目集合、顺序与完整题目快照；答题显示、提示读取、答案校验、判分、结果和导出使用这份快照。题库修改只影响之后新建的练习。可复用 `responses.questionSnapshotJson`，但必须系统调整现有“草稿行快照为空”的假设；不要同时维护第二套内容真相。

冻结内容不冻结权限：作业到期、课程撤权、学生停用仍按既有策略决定能否继续答题。已交卷历史按既有历史权限回看，不能因为 questions 当前软删而丢失原稿。

学生只拿到白名单公开投影与不透明 `questionRevisionId`；完整教师快照及其摘要不发学生。若有公开内容 hash，也只能计算公开投影。该引用只能定位授权记录，不能当访问凭证。已打开旧标签页提交时需验证题目版本，避免旧页面静默配上新快照。

升级前已交卷数据直接使用既有快照；快照缺失列“历史题目缺失”，不拿当前题库伪装。升级前进行中 attempt 在首次恢复时冻结当前可取得版本并提示重新载入；保存已有答案和本地笔迹，标记 `legacy_unverified`，不能宣称它就是学生更早看见的内容。新增题目的冻结策略不是对历史事实的补造。

### 5.2 笔记模型

| 概念 | 最小字段／约束 |
| --- | --- |
| NoteDoc v1 | `version`、`ink`（现有 atrament data）、`paperHeightLogical`、`background`；高度／背景有默认值，不修改已发布 InkDoc 必填形状 |
| NoteRecord | 服务端 id、attemptId、questionId、questionRevisionId、phase、当前 revision；归属从 attempt→student→teacher 推导 |
| NoteVersion | noteId、revision、正文文件路径、服务端正文 hash、尺寸／笔画计数、serverSavedAt、renderVersion；正文不可变 |
| NoteImage | noteVersionId、渲染规格、页号、逻辑裁剪区、像素宽高、文件 hash/path、状态；同版本可有缩略图和分析切片 |
| SubmissionEvidence | attemptId＋questionId 唯一，指向确定 NoteVersion 或显式 none/missing；提交事务写入后不能换原稿 |
| Correction | 指向来源 attempt/题目版本；保存独立 NoteRecord，点击“保存订正”固定检查点，再编辑另起一次 |

首版 phase 为 scratch；第二批新增 correction 与 supplement（交卷后找回、不能证明交卷前已固定的补充材料）。original 是 SubmissionEvidence 的角色，不是客户端随意上传的标签。学生不能自行指定 teacherId、studentId、serverSavedAt 或把订正冒充原稿。

按题笔记本通过查询聚合得到，首版无需另建全局可编辑记录。每笔只更新本地最新工作稿；每次成功同步可产生不可变版本，非检查点中间版本在安全窗口后回收，不承诺永久保存每笔历史。

### 5.3 状态必须正交

不要用一个 `saved` 同时表示本机、服务端、图片和交卷。至少区分：

| 维度 | 状态 |
| --- | --- |
| 本地正文 | saving / saved / failed |
| 服务端正文 | dirty / uploading / synced / conflict / denied |
| 派生图片 | pending / ready / failed / missing |
| 提交证据 | none（确实空稿）/ frozen（确定版本）/ missing（未能固定）/ legacy_unverified |

“图片待生成”不等于“原稿未保存”；“服务端已保存”不保证本机事务成功。错误页、教师端与 manifest 都保留区别。关闭草稿区不会变成清空操作；显式清空作为新正文版本保存，仍不能清除已冻结原稿。

## 6. 同步、存储与交卷协议

### 6.1 本地队列

使用独立 IDB 库 `tutor-notes`；键至少包含部署实例标识、studentId、attemptId、questionId、noteId/phase。同源恢复备份导致数据集变化时更新部署数据代际，旧本地队列不能自动重放到恢复后的新数据。

每笔结束、撤销、重做、清空、背景或纸高变化均进入串行持久化队列。事务完成才显示“已存本机”。加载恢复不算编辑。队列和上传调度位于会话服务，React 组件仅订阅，收起／路由切换后仍能完成当前账号的已授权工作。

原文与待传版本描述同一 IDB 事务写入。不要无限追加全量副本；首版保留当前正文、在途版本和必要冲突／提交记录，按单文档串行合并尚未执行的本地写入，已经开始的事务不乱序覆盖。长文档每笔序列化成本纳入真机测量。

登出或切账号立即使旧会话任务失效，中止／忽略旧回执，新账号不读取、不展示、不续传旧数据。未同步内容不静默删除，旧账号重新登录才可恢复。

### 6.2 服务端并发

每个上传带 `baseRevision` 与 `mutationId`，正文 schema 校验后在事务中 CAS 更新头指针。初版 revision=0；成功返回 revision、versionId、服务端 hash、savedAt。hash 基于服务端校验并按固定字段顺序序列化的正文，不基于 gzip 字节或客户端墙上时钟；相同内容的幂等判断使用相同规范化规则。

同一 mutationId＋同一正文重试返回原回执；同一 id＋不同正文拒绝；校验幂等记录应先于“旧 baseRevision”冲突判断，避免已成功但丢回执的请求被误判。revision 不一致返回 409 与当前版本摘要，保留本地副本，让用户选择保留云端或将本地作为另一份恢复稿。禁止自动按时间覆盖或拼接笔画。

同一文档一个请求在途；上传固定的不可变正文副本。A 上传期间写出 B，A 的回执只确认 A，B 仍 dirty。网络调度采用 2s 停笔防抖、建议初值 10s 最大等待；受网络／服务端耗时影响，它们不是最大丢失窗口。重试退避，恢复在线／可见时主动补传；403/404 停止自动重试但保留本地恢复入口。

退出事件只触发尽力刷新。浏览器存储也可能被清理，不能把 IDB 当长期唯一存档。[WebKit 存储策略](https://webkit.org/blog/14403/updates-to-storage-policy/)

### 6.3 文件与数据库

正文先写唯一临时文件，再 rename 到不可变版本路径，最后事务切换头指针。图片也采用不可变文件，不覆盖原路径；文件名用服务端生成 id，不能把任意 DSL questionId 直接拼路径。路径包含关系使用目录边界校验，不仅是字符串 startsWith。

失败可以留下未引用文件，不能留下指向未完成文件的已确认记录。并发请求各有唯一临时路径。垃圾回收须避开提交原稿、订正检查点、有效工作头、正在生成图片的版本、导出／备份持有的引用；只清超过安全窗口的无引用版本。未成为检查点的旧工作版本被新版本取代后，可取消其尚未开始的图片任务；失败任务不能永久锁住全部中间版本。保留中的数据库备份引用也要纳入保留集合，不能只保护当前库。

继续复用既有 gzip／原始 JSON 兼容、解压上限与上传预检原则，抽取局部存储原语即可，不照抄整份 service。新增坐标、点数、每笔点数、线宽、颜色、纸张尺寸、图片尺寸及累计字节边界；既有合法 InkDoc 的读取兼容不能被新笔记限制破坏。

完整备份包含 DB 与 blobs；打包持有相关版本直至归档完成，GC 不得删除它们。恢复后做引用完整性检查，缺文件显式列出。只备数据库的日常快照仍需对应 blobs 才能完整恢复：为备份建立引用保留清单，备份过期才释放；首版若尚未实现这项保留机制，则关闭相关版本的自动 GC，不以节省空间破坏可恢复性。

### 6.4 首版交卷：固定矢量，图片不阻塞

这是本稿对独立评审的进一步简化：**首版不提供“交卷后补传一份尚未固定的矢量，再自动当原稿”的协议。** 它需要额外承诺与校验，而且纯 HTTP 下不应新增对 Web Crypto 的隐性依赖。

1. 用户确认交卷时冻结编辑界面，结束当前真实笔段；等待本地持久化完成。
2. 对有改动的草稿上传矢量并等待确定回执；不等待 PNG。已在途上传必须等待并追平最终版本，不能仅调用一次 flush 就当完成。
3. 交卷请求带每题明确的 `none` 或 `versionId` 及预期当前 revision，并沿用既有答案／手写作答提交步骤。服务端逐项检查归属、题目版本及并发状态；事务内写 SubmissionEvidence 与成绩／状态。判分仍只由 packages/grading 执行。
4. 若其他标签页已改出新 head，拒绝这次冻结并提示处理；不静默冻结不一致旧版本。若网络回执丢失，按提交请求标识／查询 attempt 结果确认，绝不自动重交并产生不同引用。
5. 矢量失败默认保留答题状态供重试。用户可明确选择“提交答案，草稿未保存完整”，服务端记录 missing；本地稿继续保留。之后找回只作为 supplement，不冒称原稿。IDB 失败也须明确提示，并可在服务端正文成功确认后继续。
6. PNG 可由客户端后台或教师查看时，读取这个已固定的矢量重建后补传。补图只能挂该 versionId；不得更新正文或提交引用。

草稿与答案仍分通道传输，只在交卷边界协调版本；不改变“草稿不参与判分”。无网络时保持既有不能交卷的行为。旧客户端缺少证据字段时，不能把已有草稿记 none：检测到笔记则要求刷新新版；确无笔记允许按兼容规则交卷并记录未采集。

已有手写作答 ink 首批沿用其强制上传成功才交卷的约定；不借草稿改造放宽答案保存要求。装配统一后暴露其原有图片失败，不承诺此次已重写两种作答引擎。

## 7. PNG、预算与恢复

从不可变 NoteDoc 生成背景＋笔迹图，复用 atrament 重绘原语；不截图正在编辑的 canvas，不混入当前未结束笔画。确定性指相同文档／规格／渲染版本下内容与坐标一致，不承诺不同平台 PNG 字节完全一致。

图片派生队列最多同时编码一份，允许题卡已卸载。教师端可按授权取得学生自产矢量，浏览器重建并补齐图片；服务端校验附件归属、versionId、规格及大小。正文 hash 由服务端计算，客户端不必须调用只在安全上下文可用的 API。

PNG 是客户端产生的教学附件，版本绑定可以防程序串图，不能证明恶意客户端图片一定等于矢量；UI 与导出以受控渲染路径生成，异常时从矢量重建。此功能不提供考试防篡改证明。

预算建议起点（T6R.1 测完才能定稿）：正文压缩后 ≤2MiB、解压 ≤32MiB；每分析图片 ≤2MiB；每版本派生图合计 ≤8MiB；整包沿用既有 50MB 口径。与旧 ink 合计 2MiB 是不同契约，必须独立命名和文案，不悄悄改旧常量。点数／坐标等渲染复杂度限额也必须在技术验证中给出数值并写入契约，不只限字节。

分析图先以逻辑宽约 1000 像素试验；需要更清楚时提高至约 1500，并按高度切片。每片长边与总像素同时限制，不能宣称某个 iOS 像素总数在所有设备通用。切片记录顺序、原坐标范围与重叠区（建议初值 40 逻辑单位），模型不得把重叠当重复演算。缩略图单独低分辨率。

宽 2000、高 6000 的单 RGBA 位图约 45.8MiB，尚未计编码和第二份画布；不能用 PNG 文件大小估算内存。超限先减少空白、切片或按可读性调整尺寸，不要求学生擦掉步骤。矢量超限时保留本机并明确指出未同步，不能静默截断点或声称保存完成。

## 8. 接口与权限边界

以下为目标路由形态，正式实现时与 Hono 现有路由组织对齐；所有输入输出定义 Zod，二进制接口元数据也有契约。

| 接口 | 用途／授权 |
| --- | --- |
| `GET/PUT /api/student/attempts/:id/notes/:qid` | 本次工作稿与 CAS 更新；本人且 attempt 可继续作答，题目属于冻结集合 |
| `GET /api/student/attempts/:id/evidence/:qid` | 本次只读证据与图片状态；本人历史权限，不查询当前题存活性 |
| `GET /api/student/note-versions/:id/document`、`.../images/:imageId` | 仅可读取经上述归属链授权的内容，不暴露磁盘路径 |
| `POST /api/student/note-versions/:id/images` | 为自己的已固定版本补派生图；尺寸／规格／版本必须匹配，不能改正文 |
| `GET /api/teacher/attempts/:id/evidence/:qid` | 教师域内只读证据；域外统一 404 |
| 教师版本 document/image 与补图接口 | 按同一 attempt→student→teacher 授权，用于恢复派生图；不是教师编辑学生正文 |
| `POST /api/student/attempts/:id/questions/:qid/review-pack` | 本题包；从学生公开投影构建，公布策略在服务端执行 |
| 教师单题包与现有 learning-pack 接口 | 复用证据装配与模块配置；教师域过滤 |
| 第二批 correction 创建／更新／固定接口 | 来源已交卷且本人；不绕过当前答案公布策略；使用相同 revision 协议 |

新草稿、证据、图片、导出接口全部写权限测试。PNG/ZIP 也可能包含秘密，assertNoLeak 不能只检查 JSON 字段名：要使用答案哨兵、解包检查、渲染输入白名单与截图验收组合。

学生的已开放历史解法可能包含正确答案。保留既有合法历史访问，但不在当前重练自动展示；主动查看记录为已知辅助信息。不能声称隐藏按钮即可撤回学生早已获得的信息，也不新增用 questionId 越过 attempt 门控的统一答案入口。

历史读取不意味着允许继续新写：课程撤权后的进行中稿保持既有拒写策略；已交卷本人原稿按历史权限可读，是否允许订正遵从同一历史访问策略。学生停用／会话失效始终拒绝。所有角色判断在服务端执行。GET notes 工作稿头在交卷后与 evidence 同为**读投影放行**（不触发写门槛；正文写入仍被 ALREADY_SUBMITTED 拦截），补图作为恢复通道同样放行（T6R.5 落地口径）。

## 9. 导出与 AI 诊断

### 9.1 一个装配服务、三种用户入口

学生单题、教师单题、教师批量调用相同“取对应快照→角色投影→证据选择→附件清单”逻辑。学生不能调用教师装配后仅在前端隐藏字段；授权必须先于敏感素材读取与渲染。

首批提供完整单题 ZIP，同时提供可选择的 Markdown 文本与逐张图片下载。明确提示需要把真实图片作为附件上传；不能承诺所有 AI 客户端都能视觉读取 ZIP。普通 HTTP 的复制按钮采用能力检测，失败展示可手工选择的文字并保留下载。[WebKit 剪贴板要求](https://webkit.org/blog/10855/async-clipboard-api/)

```text
review.md                      # 已按角色过滤的文字和证据提示词
pack.json                      # LearningPack 正式机器清单，不另造竞争格式
schema.json
questions/q001/stem.md          # 原 LaTeX＋完整选项，DSL 可另附
questions/q001/figure-01.png    # 几何图／图表／媒体，按需
evidence/e001-original-01.png
evidence/e002-correction-01.png # 第二批
```

`pack.json` 承担评审建议的 manifest 职责：每条 response 引用准确 questionRevisionRef、evidenceRef；证据携带 phase、作答批次、保存时间、图片尺寸／裁剪范围、缺失原因。对外使用包内编号，文件名不含真实学生 id；沿用已选隐私策略并预览图片，化名不等于涂掉笔迹中的姓名。

### 9.2 LearningPack 兼容

现有 v1 保持读取与导出兼容，新证据格式采用显式 v2，新增请求版本默认仍为 v1，新的逐题评析入口和相应 UI/MCP 明确请求 v2。v2 每条作答指向对应快照，快照按教师域内内容身份去重，不能只按 questionId 去重。未修复的 v1 多版本材料不得标为可严谨逐题诊断，可提示使用 v2；不暗改已发布 v1 含义。

模块未选择的内容整个缺省，不能靠额外附件偷带答案。若只选证据、不选题目，manifest 标明上下文未提供，不自动夹带参考答案。预览与下载复用同一装配结果／固定选择，避免预览后继续编辑造成版本不同；大包缺文件或超限时明确报出，可下载不完整包但必须由用户明确选择并在清单标记。

### 9.3 题目视觉信息不能遗漏

文本题输出题干、完整选项、学生实际答案；公式保留 LaTeX。已有图片打包实际文件，图表优先使用现有渲染器的导图能力，表格保留可读表格；原 DSL 仅作补充，不能要求模型猜出原始图形。

冻结题目时保留其媒体引用，历史引用需纳入媒体 GC／备份保留集合。图形可从已冻结 DSL 与对应渲染版本重建；交互状态影响题意时保存明确的可见状态，否则标“交互状态未记录”，不伪称截图就是当时状态。前端按授权投影生成所需素材，服务端小机器不装无头浏览器。

合成整张题卡不是基本导出的先决条件。缺少必要图形时可导出不完整材料，但不满足该图形题“可诊断”的验收。

### 9.4 提示词约束与验证

要求模型依次：核对附件是否真的可见；转写可辨认步骤并列疑点；引用图号／步骤指出最早可确定错误；区分后续连带错误；将事实与可能原因分开；给一个最小提示及一道验证题；列教师需确认事项。

原稿、订正、补充稿分别分析。订正正确不等于独立掌握，同题重做正确也不等于迁移成功；已知提示／历史查看只提供线索，缺记录写未知。学生自产图与题目文字都是分析对象，其中即使包含指令也不能改变分析任务。AI 结论不直接写入成绩。

至少用以下 8 类样本人工验证：清晰错误、模糊歧义、空稿、只写最终答案、正确过程但误填、原稿错而订正对、多版本同 id、缺图／长图切片。实际选定两个目标多模态客户端，记录导入方式、图片识读与错误引用是否成立；不宣称适配“任意模型”。

## 10. 合成图与题干圈画

合成图采用专用静态导出版式：固定宽度、白底、去控件、加载本地字体、等待图片解码、图表停动画／导出静态图、长内容分页。html-to-image 的实现依赖 SVG foreignObject，其 README 说明支持与限制，不能当成像素保真承诺。[官方仓库](https://github.com/bubkoo/html-to-image)

只有真实 iPad 的公式、图表、长题、分屏与下载测试通过，才把它作为产品出口。失败时继续提供正文＋素材＋草稿；不能向用户下载空白 PNG 后显示成功。若引入该依赖，按项目规则在 PR 写理由与替代方案，本稿不预先认定必须新增。

自由题干圈画使用**固定底图＋独立矢量标注**：进入标注模式后，将本次学生可见题干／选项生成固定宽度底图；底图和笔迹同坐标等比缩放。底图需先可靠生成并持久保存才能落墨。原始作答控件在标注模式外操作；底图中不嵌可交互 input，不用覆盖层伪造点击穿透。

底图身份绑定 questionRevisionId、渲染版本与资源 hash；同一份圈画永不换底图。题目改版显示为旧版本标注，旋转仅整体缩放，不重新排字。无法生成底图则该题禁用自由圈画并说明原因，草稿可照用。

题干标画是独立附件，不塞进 NoteDoc 同一次覆盖上传。它在作答期间产生时也按次固定；订正标注另起记录。R6 原本不要求导出，但一旦用于 AI 分析，应随对应底图一起可导出，不能导出孤立的圈。

文字高亮可后续借鉴 [W3C TextQuoteSelector](https://www.w3.org/TR/annotation-model/#text-quote-selector)，采用文本引用和上下文定位；公式、重复文本、图表不强行走同一逻辑。它不能替代任意自由手绘，本期不同时开发两套标注。

## 11. 分期与发布判据

| 批次 | 范围 | 发布必须证明 |
| --- | --- | --- |
| A 核心闭环 | 输入修正、版本冻结、草稿保存、提交原稿、双方查看、完整单题包 | 第一遍原稿不会被重练覆盖；断网／冲突可解释；老师拿到正确题目＋正确原稿 |
| B 学习闭环 | 订正／补充、历史对照、批量 v2、MCP、提示词与实测 | 原稿与订正不混淆；多轮多版本配对；模型确实收到图片 |
| C 体验出口 | 合成图片；条件成立后固定底图圈画 | 真机可读、下载可用、重排不漂；不影响 A/B 数据正确性 |
| 条件增强 | 专注／多页、预测或双层渲染 | 由空间不足或性能测量触发，单独批准计划，不作为 A/B 阻塞项 |

不能将 A 批次称为 R1–R6 全部完成：合成图片属于 R4 的增强出口，R6 只有 C 真机通过后才算交付。性能优化未必需要全部实现，但输入正确性、原稿固定和不丢已确认数据是强制闸门。

方案仍有两项依赖现场证据：实际 iPad/Pencil/浏览器版本上的手感与资源预算，以及选定 AI 客户端真实图片导入行为。技术方案可以收敛，真机结论不可由静态审查代替。

## 12. 本轮核查限度

本轮完成文档阅读、关键源码静态复核、官方资料查证和任务分解；没有运行应用、性能测量或模型识图实验。此处引用的代码事实是当前工作区状态，不代表已经复现每一项用户可见故障。

没有改动判分、DSL、数据库或前端代码，因此不声称 lint/typecheck/test/E2E 已验证功能通过。真正实施的测试、质量审查、迁移生成、文档同步与 v2→main 合并要求全部列入配套任务清单。
