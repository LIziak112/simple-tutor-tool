# 默认判分策略兜底验证（第 2 步）

> 任务 b7df16f6。对应台账「已定口径」第 2 条：栗子🌰定的是补一套内核默认判分策略，卷子的策略为空、缺字段或取值非法时一律回落到它；兜不住就不上。本文先写死「兜得住」的标准，再报验证结果和旧样例的差异清单，请栗子🌰看清单决定上不上。

## 结论

- **兜得住**：15 种声明（空、缺字段、全缺、类型错、未知取值、夹带未知字段、合法）全部回落成完整策略，没有一次抛错。每种声明的分流结果编译成发布声明后，混合卷经真实确认和评估，每道题要么判出对错、要么进待批，只有带私有键、能自动判的题调用了评估器。
- **行为有变化**：旧产品两份策略为空的样例卷按默认策略重跑，客观题结果与旧版完全一致。有参考答案的主观题全部从旧语义（填空进教师待批，解答、应用、找错按最终答案自动判）改成学生自评待批，共 8 处，明细见下文。
- **还没接进运行时**：策略和分流函数在内核里（`src/kernel/grading-policy.ts`），但还没从 `src/server.ts` 导出，也没写进发布流程。栗子🌰看过差异清单、决定上之后再接线。接线时有一条硬条件：「能自动判」要由内核从冻结的私有键和已登记的评估器推导，或在发布时与它们核对一致，不能只靠宿主自报；否则宿主把有键客观题错报成不能自动判，题就会被错送进待批。接线后再更新《工程接入说明》。

## 策略长什么样

```ts
type GradingPolicy = { version: 1; withReference: "selfReview" | "teacherReview" };
const defaultGradingPolicy = { version: 1, withReference: "selfReview" };
```

每道题按两个事实分流。本轮这两个事实由调用方按题提供（接线时的要求见上文「还没接进运行时」）：

| 能自动判（有评估器且有私有键） | 有参考答案 | 分流结果 |
| --- | --- | --- |
| 是 | 任意 | 交评估器（自动判） |
| 否 | 是 | 按策略 `withReference`：学生自评，或教师评阅 |
| 否 | 否 | 教师评阅 |

- 默认值对应旧产品新开卷的冻结规则：客观题 auto，有参考的主观题 reference_self，无参考的 manual_only。教师关闭自评，就是把 `withReference` 设成 `teacherReview`。
- 策略只决定「有参考的题归谁判」。它没法把一道不能自动判的题变成自动判，所以策略声明写错了也只会让题进待批，不会被静默判错。
- 回落规则：不是对象（未声明、null、字符串、数组）就整份回落；`version` 存在但不认识（类型错或未知版本）也整份回落，不把未来版本的字段按 v1 去读；`version` 缺失按 v1 读，只回落缺失或非法的那个字段。声明里夹带的未知字段不参与判分，另记在 `ignored` 里备查。
- 只有一种取值的项（能自动判的题恒交评估器、无参考的题恒交教师）不做成字段，避免出现看着能配、其实不能改的开关。

## 「兜得住」的标准（动手前写死）

1. 每份声明都能回落成完整策略：结果能通过严格 schema，合法字段原样保留，回落了哪些字段逐一记账（`fallbacks`），忽略了哪些未知字段也记账（`ignored`）。
2. 判分不抛错：解析、分流、发布、确认、评估全程不抛错。
3. 每道题要么判出对错、要么进待批，没有静默判错：只有带私有键、能自动判的题调用评估器，其余题一律待批。

## 喂了哪些输入

按王玄策给的口径，不做 2 的 n 次方组合，只喂下面这些（`tests/contracts/grading-policy-fallback.test.ts`）：

| 类别 | 用例 | 回落字段 |
| --- | --- | --- |
| 空策略 | 未声明；null | version、withReference |
| 全缺 | 空对象；只有未知字段 | version、withReference |
| 每次只缺一个字段 | 只缺 version；只缺 withReference | 缺的那一个 |
| 字段值非法：整份 | 整份是字符串（旧档名 `reference_self`）；整份是数组 | version、withReference |
| 字段值非法：类型错 | version 为字符串 `"1"`（整份回落）；withReference 为布尔 | version 错则全部，否则错的那一个 |
| 字段值非法：未知取值 | version 为 2（整份回落）；withReference 用旧产品档名 `manual_only` | 同上 |
| 夹带未知字段 | 合法策略里多一个旧字段 `gradingPolicy` | 无（记入 ignored） |
| 合法 | 默认策略；教师关闭自评 | 无 |

另有一条用例守住矩阵本身：每个字段都必须同时有「只缺它」「它类型错」「它取值未知」三种用例，并且该字段确实出现在回落记账里；按名目删掉其中任何一种就会变红。

结果：标准 1、2 在 15 种声明上全部成立。标准 3：每种声明先分流，核对分流结果（默认策略下有参考解答题归自评，关闭自评时归教师），再把分流结果编译成发布声明，跑一份混合卷（有键判断题、无键判断题、有参考解答题、无参考作文题）。4 道题里只有有键判断题进了评估器，其余 3 道进待批。内核暂无自评入口，自评题和教师题编译后都落在教师评阅位，所以运行期这一层验证的是「编译后的声明能发布、确认、评估且不误判」；策略带来的差别只体现在分流结果里，这一层已单独断言。

### 这些变化意味着什么

- 客观题（judge、choice、multi）在两份样例里都和旧版一致。
- 填空：旧草稿卷里本来等老师批，回落后改成学生自评。这就是例外清单 X1 说的「学生做到一半规则变了」。
- 解答、应用、找错：旧草稿卷按最终答案自动判，回落后不再自动判，等学生自评。样例二里这三题旧版都判对、整卷交卷即已判，回落后整卷会停在待批。
- 如果希望旧草稿卷不出现上面的变化，就要在迁移时给旧行显式写入策略，或者另外保留旧语义，但这正是第 2 条决定不做的。所以请栗子🌰看着这张表定：**上**（接受这 8 处变化）或者**不上**。
