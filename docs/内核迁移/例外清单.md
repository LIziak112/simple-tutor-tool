# OwnClass 旧产品按题型特判的例外清单（第 1 步，只读）

> 任务 f9439bfd 产物，第 0 步入仓。旧产品基线：LIziak112/simple-tutor-tool `49a3fb07`（固定 v2）。行号都在这个提交上用 `grep -n` 实测过。全程只读，没有改任何仓。

## 结论

例外 4 条，共需额外补 **11 条用例**：服务端 1 条（历史数据兼容），前端 3 条（交互和展示）。服务端的作业/课程/讲练/错题重练、整卷/逐题、反馈/再练这几条路径里，**没有一处是场景按题型名特判的**。题型差异都通过两个口子进场景：一是开卷时冻结到每一行的 `gradingPolicy`，二是题型表加判分分派。这两处在任何场景下都走同一个函数，所以属于题型契约，不算例外。

这说明「题型契约 + 模块契约」的拆法在服务端成立。例外只要单独补用例，不用回到全排列。

## 认定口径

按已定口径执行：只认旧代码里**对题型有显式分支**、而且**对外可观察结果确实不同**的地方。下面两类不算例外：

- 题型契约内：差异就是题型自己的判分、空答、改判语义，任何场景都一样，只是代码写在场景文件里。
- 非例外：写法不同但结果一样，或者场景差异对所有题型一视同仁。

显式分支有两种形式，都算：

- 字面写题型名，例如 `case "judge"`、`HANDWRITTEN_TYPES.has(type)`；
- 用按题型取值不同的能力位分流，例如 `placement === "options-radio"`、`gradingPolicy`。

## 例外

### X1　旧 NULL 判分策略行按题型走旧语义（服务端，历史数据）

- **位置**
  - `apps/server/src/services/attempt-freeze.ts:158`：懒冻结给升级遗留的草稿卷补行时不传 `gradingPolicy`，落成 NULL。
  - `attempt-freeze.ts:229`：只有 wrong 来源跳过补行。
  - `packages/contract/src/self-review.ts:244`：`resolveRowGradingSemantics` 在 NULL 时按题型 `switch`。
  - 对照：新开卷 `attempt-freeze.ts:123` 和错题重练 `wrong-practice.ts:199` 都显式冻结 `frozenGradingPolicyOf(...)`。
- **涉及题型**：fill、solve、apply、find-error。
- **差异**
  - NULL 行：fill 恒为 null，进教师待批；solve/apply/find-error 按最终答案等价比较自动判对错，有 `autoCorrect`，没有自评入口。
  - 同一道题进了新开卷或错题重练后变成 `reference_self`：`autoCorrect` 为 null，出现自评入口，不进教师待批。
  - judge/choice/multi 两边都是 auto，没有差异。
- **为什么算例外**：差异轴是「历史卷还是新卷」，不是题型评估器本身的语义。新内核必须显式定规则：迁移时回填策略，还是保留一个旧语义的评估器版本。
- **额外用例（4 条）**：fill、solve、apply、find-error 各一条，用真实 v2 留存卷升级后读回，断言判定与旧侧一致。
- **状态（2026-11-24）：已验收（关闭）**。栗子🌰选 A：不保留旧语义，空策略一律回落内核默认判分策略，接受旧卷重新判分。内核兜底随 learning-kernel PR #7 合入 v2 `caf40a54`（`tests/contracts/grading-policy-fallback.test.ts`、`grading-policy-legacy-sample.test.ts`）；产品 PR #195 合入 v5 `de980b15`，回填存量空策略行并重算已收尾卷（`apps/server/src/db/backfill-default-grading-policy.test.ts`、`packages/grading/src/grade-row.test.ts`、`packages/contract/src/self-review.test.ts`）。上面「断言判定与旧侧一致」按定案改为「断言回落默认策略、旧自动判定作废、教师判定保留、卷级重算」；用例名与固定提交的链接见[台账.md](台账.md)表 4 X1 行。

### X2　单选「选中即提交」（前端，逐题交付）

- **位置**
  - `apps/web/src/features/attempt/AttemptSession.tsx:1075-1078`（逐题列表）和 `:664-667`（单题模式）：`canAutoSubmitChoice && questionBindings[type].placement === "options-radio"`。
  - 开关在 `use-attempt-practice-submission.ts:44-45`，只在 `practiceWorkflow.canSubmitQuestion === true` 时生效。
- **涉及题型**：只有 choice。judge 也是单选形态，但它的 placement 不是 `options-radio`，不触发；multi 也不触发。
- **涉及场景**：新版逐题交付（作业、课程、错题都可能）。讲练恒走旧协议，没有这个功能。
- **差异**
  - 学生打开开关后，单选题一点选项就直接逐题提交，提交按钮隐藏，失败时才出现「重试提交」。单题模式下按 Enter 只切到下一题。
  - 其他题型照常要点「提交」。
- **额外用例（2 条）**：choice 选中即提交；judge/multi 在同一开关下不自动提交。

### X3　手写题逐题已提交或时间到后，卡片上看不到本人答案（前端，逐题交付）

- **位置**
  - `apps/web/src/features/attempt/AttemptQuestionCard.tsx:289-291`：`HANDWRITTEN_TYPES.has(type) && (!readOnly || inkSyncWhileReadOnly)` 才挂 `HandwrittenControls`。
  - `AttemptSession.tsx:1134-1138`：已提交或时间到即只读，`inkSyncWhileReadOnly = timeUp && !practiceSubmitted`。
- **涉及题型**：solve、apply、find-error 的最终答案和笔迹都不显示；response 正文以禁用态显示，但笔迹不显示。
- **涉及场景**：逐题交付已提交后的只读态，以及时间到后的只读态。讲练提交后整张卡换成结果态，不受影响。
- **差异**：客观题、matching、ordering 提交后，选择仍冻结显示在卡片上；手写题卡片上没有本人答案。如果反馈节奏是「交卷后查看」，学生在这道题上完全看不到自己写了什么。
- **额外用例（2 条）**：逐题提交后的只读态；时间到但未提交时的只读态（笔迹继续同步）。

### X4　结果页复盘模板按题型组成自动选择（前端，整卷结果）

- **位置**：`apps/web/src/features/attempt/ReviewTemplateFrame.tsx:61` 把全卷题型列表传给 `packages/contract/src/review-template.ts:177-185`。后者写死主观题集合 {response, solve, apply, find-error}，判成 subjective / mixed / objective 三档。
- **涉及场景**：整卷结果页，四种来源都会走到。
- **差异**：全主观、混合、全客观三种卷子默认用的模板不同，展示的分区也不同。
- **建议**：新内核里改由评估器能力（是否自动判分）推导，不再写死题型名。
- **额外用例（3 条）**：三档各一条。

| 内容 | 位置 |
