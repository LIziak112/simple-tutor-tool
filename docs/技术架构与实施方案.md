## 1. 为什么这么选（架构决策记录）

### 1.1 放弃"Python 标准库 + 原生 ES5 JS 零依赖"

旧约束的真实目的只有两个：**部署简单**、**数据在自己手里**。v2 用"单容器 / 单进程 + SQLite 文件"同样满足这两点。

而愿景里剩下的功能——内容单条管理与编辑器、学生做题记录、学情聚合看板、学习痕迹采集、草稿防丢、鉴权、服务端判分、AI 接入——会让原生 JS 手写 DOM 的复杂度指数上升，也让执行模型更容易写出 bug。成熟框架 + 类型系统是这个量级项目的正确投资。

### 1.2 选 TypeScript 全栈，而不是 Python 后端 + React 前端

决定性理由是 **"数据结构契约是核心资产"**：

1. **契约只写一份**：Zod schema 放在 `packages/contract`，前后端共用，编译期就能发现契约不一致；还能直接导出 JSON Schema 交给 AI。Python + TS 需要两份模型定义并靠代码生成同步。
2. **Markdown 解析与渲染同一生态**：导入时服务端用 remark 解析成 AST，前端用同一套 remark/rehype 插件渲染，同一个 AST 规则，不会出现"解析器认为是 A、渲染器认为是 B"。
3. **判分逻辑共享**：判分函数写在共享包里，服务端权威执行；前端只用来做"未提交前的输入格式提示"。
4. **AI 生态**：Vercel AI SDK、MCP 官方 SDK 在 TS 侧最成熟。
5. **对执行模型友好**：React + TS + Hono + Drizzle 是训练语料最丰富的组合之一，生成代码质量稳定。

### 1.3 明确不采用的方案

| 方案 | 不采用的原因 |
| --- | --- |
| Next.js + Supabase + Vercel（gemini 提案） | 数据托管在第三方云，违背"数据自持"；多一个外部服务要维护；SSR 对这个"登录后使用的工具"没有收益 |
| PostgreSQL | 单老师、几十个学生的量级，SQLite 性能绰绰有余；SQLite 是一个文件，备份 = 复制文件，符合"数据就是老师机器上的文件" |
| tldraw 做手写 | 生产使用需商业授权（约 6000 美元/年），免费版限非商业且带水印（Excalidraw 已采用，见 §5.4） |
| MathJax | KaTeX 更快、同步渲染、体积小，足够覆盖中小学/大学数理公式（化学可加 mhchem） |
| 微前端/微服务/消息队列 | 过度设计 |

## 5. 关键子系统设计

### 5.1 内容 DSL v2（AI 友好的核心契约）

设计原则：**标准 Markdown + 少量显式指令**；结构靠语法而不是靠猜；AI 容易写对，写错时 linter 能精确指出行号并给出修正建议。

语法基础：YAML frontmatter + `remark-directive` 容器指令（`:::名称{属性}` … `:::`）。嵌套时外层多用一个冒号（`::::`）。

**练习示例：**

````markdown
---
kind: practice            # practice | lecture | mixed
unit: 练习四               # 可选；缺省取文件名（去扩展名）
lecture: 第4讲             # 可选；配套讲义的名字（挂到同文件夹同名讲义）
topic: 有理数加减混合
---

::::question{type=fill difficulty=2 knowledge="有理数加法"}
计算：$(-3)+7=$ [[4]]；$(-2)+(-5)=$ [[-7]]。

:::hint
同号相加取相同符号；异号相加取绝对值较大的符号。
:::

:::solution
$(-3)+7=4$；$(-2)+(-5)=-7$。
:::
::::

::::question{type=choice difficulty=1 knowledge="相反数"}
$-5$ 的相反数是（ ）

- [ ] $-5$
- [x] $5$
- [ ] $\frac{1}{5}$
- [ ] $-\frac{1}{5}$
::::

::::question{type=judge difficulty=1}
$0$ 既不是正数也不是负数。 [[正确]]
::::

::::question{type=solve difficulty=3 knowledge="有理数混合运算" id=p4-q7}
计算 $-2^2 + (-3)\times\left(-\frac{1}{3}\right)$，写出过程。

:::answer
-3
:::

:::solution
…
:::
::::
````

规则要点：

| 元素 | 规则 |
| --- | --- |
| 题型 `type` | `judge` 判断 / `choice` 单选 / `multi` 多选 / `fill` 填空 / `solve` 计算 / `apply` 应用 / `find-error` 找错；未知值 lint 报错 |
| 填空 | 题干中 `[[答案]]` 即一个空；等价答案 `[[0.5\|1/2]]`；空数由标记自动得出，答案与空天然对齐 |
| 选择 | GFM 任务列表，`[x]` 为正确项，选项字母按顺序自动编为 A/B/C/D |
| 手写题 | `solve/apply/find-error` 默认带手写区；可选 `:::answer` 给出"最终答案"用于自动判分 |
| `:::hint` | 可有多个，学生逐个点开，每次点开都记录事件 |
| `:::solution` | 交卷后才下发 |
| `id` | 可选；缺省为 `单元slug-序号`。**编辑内容时保持 id 不变**，学情统计才能跨版本延续 |
| 讲义 | `kind: lecture`；`# 第X讲 …`（H1）切分多篇（单讲义文件可用 `title:` 指定讲义名，缺省取第一个 H1；多讲义逐篇按各自 H1，声明的 `title:` 被忽略并告警）；讲义内可用 `:::example`、`:::hint`、`:::solution`、`:::steps` + `:::step{title}`（逐步揭晓）、`:::fold{title}`（通用折叠） |
| 混合文档 | `kind: mixed`，讲义段落与 `::::question` 可以交替出现，导入后自动拆成讲义 + 练习单元并建立关联 |

**命名与身份规则**（2026-09-29 内容模型与导入规范化落地，详见 `docs/内容模型与导入规范化方案.md`）：题目 / 单元 / 讲义统一为「**文档声明的名字 = 身份；没声明 = 缺省派生；身份决定重导时更新还是新建**」——

| 实体 | 身份（导入键）来源 | 缺省派生 | 再次导入 |
| --- | --- | --- | --- |
| 题目 | 容器 `id` 属性 | `单元名-序号` | 同 id → 更新（version+1） |
| 单元 | frontmatter `unit:` | 文件名去扩展名 | 同名 → 合并题目 |
| 讲义 | frontmatter `title:`（可选） | 第一个 H1 | 同文件夹同名 → 覆盖正文 |

匹配范围：题目全局按 id（文件中缺失的已有题保留）；单元全局按 unit 名（命中保留原文件夹）；讲义同文件夹按讲义名（其他文件夹已有同名 → warning）。`lecture:` 是**配套讲义指针**（按讲义名在同文件夹匹配），匹配不到 → 导入 warning（LECTURE_LINK_UNRESOLVED），不再静默不关联。

**linter（`packages/md-dsl`）输出：**

```ts
type LintIssue = { level: 'error' | 'warning'; line: number; column: number; code: string; message: string; fix?: string };
```

- 教师端导入前先 dry-run 预览，错误在编辑器对应行标红；
- 提供"复制错误给 AI"按钮：把错误列表格式化为一段提示词，老师直接粘回 AI 让它修正——这就是 AI 原生的"制作端闭环"；
- 同一个 linter 以 CLI 形式提供：`pnpm tutor-lint 练习.md`，并通过 MCP 暴露给 AI。

#### 5.1.1 可扩展性设计：新前端功能如何不破坏旧内容

目标：V2 上线后，前端每新增一种展示或互动能力，老师只需在 MD 里**多写一行"指令"语法**就能用上；已经导入的旧文档不用修改，照常正确显示。

**（1）固定不变的"语法外壳"：三种指令写法**

DSL 只使用 `remark-directive` 定义的三种通用写法。以后所有新功能都复用这三种写法，**永远不再发明新的符号**，因此解析器的底层不必改动，AI 也只需要学一次：

| 写法 | 形式 | 适用场景 | 示例 |
| --- | --- | --- | --- |
| 容器指令 | `:::名称{属性}` … `:::` | 包住一段内容 | `:::tip` 小贴士 `:::` |
| 块指令（单行） | `::名称[文字]{属性}` | 独立一行的组件 | `::graph{fn="x^2" range="-3,3"}` |
| 行内指令 | `:名称[文字]{属性}` | 句子中间的标记 | `这是:mark[重点]{color=red}内容` |

属性写法统一为 `{#id .样式类 键=值 键="带空格的值"}`，例如 `:::box{.warning title="易错点"}`。

**（2）指令注册表：新功能 = 注册一个新名字**

`packages/contract/src/directives.ts` 中维护一张注册表，每个指令一条记录：

```ts
defineDirective({
  name: 'tip',                       // 指令名
  kind: 'container',                 // container | leaf | text
  since: '2.0',                      // 从哪个版本开始支持
  allowedIn: ['lecture', 'question'],// 可出现的位置
  attrs: z.object({ title: z.string().optional() }), // 属性 schema，全部可选且有默认值
  description: '提示框，用于补充说明',  // 自动写进给 AI 的规范文档
  example: ':::tip{title="小技巧"}\n先通分再计算。\n:::',
});
```

前端 `features/markdown/directives/` 中为每个注册名提供一个 React 组件。**新增一个前端功能的标准流程只有四步**：

1. 在注册表加一条定义（名字、属性、说明、样例）；
2. 写对应的 React 组件；
3. 在 `samples/` 加一个样例并补一个渲染测试；
4. 运行 `pnpm gen:spec`：`docs/dsl/规范.md` 的指令清单、JSON Schema、给 AI 的提示词模板都由注册表**自动生成**，AI 立刻就会用这个新功能。

**（3）兼容规则（写进 AGENTS.md，执行模型必须遵守）**

1. **只增不改**：已发布指令的名字和含义永不改变；属性只能新增，且新增属性必须可选、带默认值。
2. **改名用别名**：确需改名时，在注册表登记 `aliases: ['旧名']`，旧写法继续有效，linter 仅提示"建议改用新名"。
3. **未知指令优雅降级**：遇到尚未支持的指令（如用新版格式的文档导入到旧版系统，或手误写错名字），渲染时显示其内部文字内容（外加一个不显眼的灰色边框），页面不报错、不崩溃；linter 给出**警告**而不是错误，并提示"你是不是想用 `:::tip`？"。
4. **文档声明版本**：frontmatter 中 `dsl: 2`（缺省即 2）。解析器按版本选择规则，旧版本文档永远按旧规则解析。

**（4）原文是真相，渲染时再解析**

- 每道题、每篇讲义都保存**原始 Markdown**。导入时只抽取"判分与统计必需"的结构化字段（题型、答案、考点、难度）入库；
- **展示内容在前端渲染时才解析**。因此前端升级、新增指令组件后，旧内容里如果本来就写了该指令（此前处于降级显示），会自动以新样式呈现，无需重新导入；
- 若升级涉及结构化字段（例如新增一种题型），提供 `pnpm reparse` 命令，用新解析器从原文重新抽取全部内容的结构化字段，题目 id 不变，历史作答不受影响。

**（5）V2 首发即内置的一批指令**（后续按需扩充）

| 类别 | 指令 |
| --- | --- |
| 题目结构 | `question` `hint` `answer` `solution` `blank`（即 `[[…]]`） |
| 讲义互动 | `example` `steps`/`step` `fold` |
| 版式与强调 | `tip` `warning` `box`（`.样式类` 可选）`columns`/`col` 分栏、`:mark[…]` 重点标记 |
| 媒体 | `::image{src width}`（图片存 blobs）`::graph{fn range}`（函数图像，function-plot 库，按需加载） |

"以后可能加"的例子：`::video`、`:::tabs`、`::geometry`（几何画板）、`::audio`（英语听力）——都只是往注册表里加一条。

**v1 兼容：** `md-dsl` 内保留 v1 解析器（`#### 题 N（★★）`、`【题型】`、`<!-- ANSWER -->` 格式），导入时自动识别版本；另提供 `v1 → v2` 转换函数，教师端可一键升级旧文档。

**规范文档化：** `docs/dsl/规范.md` + `docs/dsl/完整样例.md` + `docs/dsl/提示词模板.md`，服务端在 `/spec` 提供，教师端"复制给 AI"一键复制规范 + 样例 + 模板。JSON Schema 由 `packages/contract` 导出并随 `/spec` 提供。

关键设计：

- **多教师归属与四层域隔离（Phase 2B）**：业务根表带 `teacherId`（students、courses、library_folders、lectures、units、questions、imports、assignments）；**列在 DB 层声明可空、代码层恒写非空**（SQLite 给已有数据的表加 NOT NULL 列需重建，回填又按 T2A 先例放在迁移之后以代码执行），读侧视为必有。派生表不加列、经 join 推导归属：`course_items`/`course_students` → course，`assignment_units`/`assignment_students` → assignment，`attempts`/`responses`/`ink`/`events` → attempt → student。教师访问非本人资源一律 404（不暴露存在性），资源库、课程作业、学生作答、学生侧内部四层全部按教师域过滤；学生端对外行为零变化。
- **复合主键与外键去除（Phase 2B）**：`units`/`questions` 主键 `(teacherId, id)`、`question_knowledge` 主键 `(teacherId, questionId, knowledgePointId)`——DSL id 只在域内要求唯一，两位教师各持同 id 单元/题目合法。SQLite 外键必须引用完整唯一键组，故指向 `units(id)` / `questions(id)` 的外键全部去除（questions.unitId、assignment_units.unitId、attempts.unitId、question_knowledge.questionId、responses.questionId、ink.questionId 等，子表表重建、**引用列值不变**），域一致性由服务层保证：**任何按 id 查 units/questions 的查询必须同时携带 teacherId**（教师侧取会话教师，学生侧从 attempt → student 推导），否则两位教师持同 id 时会取到任意一行——取卷、判分、提示、课程目录都会串域。
- **考点公共共享**：`knowledge_points`（name 全局唯一）不加 teacherId——考点是通用学科概念，不同教师导入同一份材料自动合并到同一条，不泄露内容；导入匹配范围＝「各教师自己的资源库 + 公共考点库」内（单元/题目/讲义按 `(teacherId, …)` 域内匹配）。
- **共享目录（Phase 2B，非数据库）**：`DATA_DIR/shared/` 存发布快照与本地放入的 `.md`，伴生 `<同名>.meta.json`（teacherId/loginName/publishedAt，发布者显示与删除权限依据）；详见 §5.7 与 `docs/部署.md`。
- **引用而非复制**：课程目录条目只保存资源 refId，资源库改动全课程即时生效；已交卷作答经快照不受影响。
- **软删除 + 回收站**（Phase 2A 扩展到讲义与单元）：`deletedAt` 置值进回收站，可恢复；彻底删除仅当无作答记录与作业引用。题目沿用软删。被软删资源在课程中对学生自动不可见，作业不受影响。
- **学生可见性唯一判定**：成员（未归档）∧ 课程未归档 ∧ 条目可见（`visible` 且 `publishAt` 到点）∧ 资源未软删（单元还需有未删题）——所有学生端接口复用同一判定函数；非成员/归档 403，隐藏条目 404（不暴露存在性）。
- **课程练习可重做**：同一 (学生, 课程, 单元) 同时至多一份未交卷作答（服务层事务保证）；已交卷可再做一次（`attemptNo` 递增，从空白开始），历次记录全部保留。
- **题目快照**：`responses.questionSnapshotJson` 保存作答时的题目版本。老师后来编辑或删除题目，历史记录依然完整、可回看。
- **笔迹不进数据库、不用 base64**：以文件形式存到 `data/blobs/ink/<attemptId>/<questionId>.json.gz` 与 `.png`，multipart 上传；数据库只存路径。
- 时间统一存 UTC ISO 字符串。

**批注、得分与状态机（Phase 3 定稿，设计依据 `docs/Phase3任务清单.md` §2 D1–D4）**：

- **待批口径（D1/D4，全站唯一）**：`autoCorrect = null` 只剩三种且全部进待批——手写题未能自动判（整题未作答 / 只写笔迹未填最终答案 / 最终答案为空）、题目无标准答案（该判定优先级最高，先于未作答判定）、判断题学生写法无法归一化；其余未作答客观题（judge/choice/multi/fill 的 `answerJson` 缺省，或多选空选 `indexes = []`）判 `false` 不进待批（详见 §5.6）。**待批题 ≡ 已交卷 attempt 中 `finalCorrect IS NULL` 的题**——共享谓词落在 `apps/server/src/services/pending-mark.ts`，数据页卡片、待批队列、课程进度矩阵、学生单元卡片的待批数全部复用；**不得叠加 `answerJson 非空` 条件**（只写笔迹、未填最终答案的手写题 answerJson 为 null，却正是最需要批改的）。在该口径下「待批数 = 0 ⇔ status = graded」严格成立。
- **得分与状态机（D2）**：`scoreFinal = finalCorrect 为 true 的题数 ÷ 该 attempt 全部题数 × 100`（四舍五入，**分母 = 全部题**，不是可自动判分的题）；`status = graded` 当且仅当该 attempt 全部 responses 的 `finalCorrect` 均非 null，否则 `submitted`。清除批注使题目回落 null 时，status 回 `submitted`、`scoreFinal` 置 null。所有界面「得分」展示一律 **`scoreFinal ?? scoreAuto`**（作业卡片、课程进度矩阵、单元卡片、我的记录、CSV）。
- **批注（D3）**：`POST /api/teacher/responses/:id/mark` 请求 `{ mark: 'correct' | 'wrong' | null, comment: string | null }`，两字段一次提交。持久化口径 `finalCorrect = teacherMark ?? autoCorrect`：交卷时同时写 `finalCorrect = autoCorrect`（此后待批判定以 finalCorrect 为准）；批注在事务内逐题改写并用交卷链路同一实现 `finalScoreOf`（`attempt-service.ts`）重算整卷 `scoreFinal / status`——公式不复制。`mark = null` 清除判定（finalCorrect 回落 autoCorrect，手写题回落 null 重新待批）；`comment` trim 后空串按 null，上限 2000 字（契约校验，超出 400）；**允许对任何已交卷的题批注/改判**（含自动判过的题，入口在数据页详情）；对 draft attempt 批注 → 409 `NOT_SUBMITTED`；非本人教师 → 404（域口径）。
- **存量回填**：判分口径修订（T3.2a）上线前已交卷的 attempt，经 `data_migrations` 键 `t32a_grading_semantics_backfill`（`apps/server/src/db/backfill.ts`，幂等、事务内）按新口径重算 autoCorrect / finalCorrect / scoreAuto / scoreFinal / status——数据回填，非结构变更，无 drizzle 迁移。

### 5.3 渲染与互动

- 服务端导入时解析出结构化数据入库，**不存 HTML**；前端用统一的 `<RichMarkdown>` 组件渲染 Markdown 片段，指令映射为 React 组件（`<Hint>`、`<Solution>`、`<Steps>`、`<Blank>`…），经 rehype-sanitize 防 XSS。
- 讲义：自动目录（H2/H3）、例题解析默认折叠、`:::steps` 逐步揭晓；每次展开都上报事件（`lecture_expand`），老师能看到学生读讲义时看了哪些解析。
- 练习：学生端只拿到"公开题目"（无答案、无详解、无提示内容）；提示通过 `POST /api/student/attempts/:id/hints` 按需获取并同时记录；交卷后接口返回判分结果 + 答案 + 详解。

### 5.4 iPad 手写（体验重点）

#### 5.4.0 选型结论：用现成库，不自研绘制引擎

| 候选 | 许可 | 评估 | 结论 |
| --- | --- | --- | --- |
| **Excalidraw**（`@excalidraw/excalidraw`） | MIT，可商用、无水印 | 成熟的 React 组件：压感自由笔（内部即 perfect-freehand）、笔模式（检测到 Apple Pencil 后自动屏蔽手指绘制）、橡皮、撤销重做、套索移动、直线/图形（几何题有用）、中文界面、导出 PNG/SVG、JSON 矢量场景。缺点：体积大（需懒加载）；社区反馈掌托防误触和平滑度不如 GoodNotes；是无限画布，不适合嵌在滚动页面里 | **首选：用于"全屏作答"** |
| **Atrament** | MIT | 约 3 KB 的画布绘制库：压感、平滑、橡皮、**笔画录制与回放**（`recordStrokes` / `strokerecorded`），可嵌在页面里。缺点：工具栏、撤销需自己写几十行 | **备选：用于"页内小答题区"** |
| tldraw | 源码可见，生产需许可证 | 书写手感最好；但商用许可约 6000 美元/年，免费 hobby 许可仅限非商业且必须显示水印 | 不采用 |
| signature_pad | MIT | 非常稳定，但只按速度变粗细、不支持压感，定位是签名 | 不采用 |
| 原生 App 套壳（Capacitor + Apple PencilKit） | — | 手感等同备忘录；但需要装 App、苹果开发者账号（99 美元/年），违背"免装 App" | 远期备用方案，不在 v2 范围 |

**落地形态：两种作答区 + 一个统一适配层**

1. **页内答题区（默认）**：每道手写题下方一块答题区，写几步简单过程用。用 Atrament 实现，只做笔、橡皮、撤销、清空。
2. **全屏作答（大题）**：点"全屏作答"→ 顶部固定题干，下方是 Excalidraw 画布，UI 精简为笔/橡皮/套索/撤销/清空（通过 `UIOptions` 隐藏其余功能，`langCode="zh-CN"`）。适合长过程、需要画图的题。
3. **统一适配层 `InkSurface` 接口**：答题页、草稿、上传、老师查看都只依赖这个接口，不直接依赖任何库。以后换库（包括将来换成原生 PencilKit）只需重写一个适配器：

```ts
interface InkSurface {
  mount(el: HTMLElement, initial?: InkDoc): void;
  getDoc(): InkDoc;                 // { engine: 'atrament' | 'excalidraw', version, data, updatedAt }
  exportPng(): Promise<Blob>;       // 白底 PNG，供老师和 AI 查看
  undo(): void; redo(): void; clear(): void;
  onChange(cb: (doc: InkDoc) => void): () => void;  // 每一笔结束触发，用于草稿保存
  destroy(): void;
}
```

- 数据库和文件只存 `InkDoc`（库自己的 JSON 格式，外加 `engine` 字段）+ PNG 快照；老师端按 `engine` 选择对应的查看器。
- 回放：Atrament 录制的笔画带时间戳，可按真实节奏回放；Excalidraw 按笔画顺序逐笔回放。

**需要注意的库配置**

- Excalidraw 默认从 CDN 加载字体和资源，必须配置 `window.EXCALIDRAW_ASSET_PATH` 指向本站静态目录（遵守"不用 CDN"规则），并且只在打开全屏作答时动态 `import()`。
- 执行模型只需"安装库 + 按接口写适配器 + 加下面的 iPad 处理"，不需要写绘制算法。

**Phase 2 第一步先做真机试验（1–2 天）**：做一个独立演示页 `/dev/ink-lab`，把 Atrament 页内版和 Excalidraw 全屏版并排放上，你拿 iPad + Apple Pencil 按 §7.1 清单试写。三种可能的结果：
- 两者都满意：按上面的两种作答区落地；
- 只满意 Excalidraw：所有手写题都用全屏作答；
- 都不满意：退回自研，即下文 5.4.1 的完整方案（由 `InkSurface` 隔离，不影响其他代码）。

#### 5.4.1 iPad 专项处理与自研参考方案

> 不管用哪个库，下面的"输入层"和"数据层"要求都适用（库只替代"绘制层"）。只有真机试验选择自研时，才需要实现全部内容。

组件拆为两层：`features/ink/engine`（纯 TS，无 React，便于测试与性能控制）+ React 外壳（工具栏、弹层）。

**输入层**

1. Pointer Events 统一处理笔/手指/鼠标；`pointerType === 'pen'` 识别 Apple Pencil，读取 `pressure`。
2. 支持时使用 `getCoalescedEvents()` 获取高频采样点（笔迹更顺滑），`getPredictedEvents()` 绘制预测段降低视觉延迟；不支持时自动回退。
3. **"笔写字、手指滚动"**（iPad 上最重要的体验）：Canvas 监听 `touchstart`（`passive:false`），若 `touch.touchType === 'stylus'` 则 `preventDefault()` 进入书写；手指触摸不拦截，页面照常原生滚动。这样学生不用在"书写模式/滚动模式"之间来回切换。
   - 非 iPad 设备（无笔）回退为：手指/鼠标直接书写 + 工具栏"滚动模式"开关。
4. 防误触：仅笔模式下忽略手指绘制；CSS `-webkit-user-select:none; -webkit-touch-callout:none`，拦截 `selectstart`/`contextmenu`，防止长按弹出放大镜和菜单；页面 `touch-action: manipulation` 防双击缩放。
5. Apple Pencil 悬停（支持的机型）：`pointermove` 且 `buttons === 0` 时显示笔尖预览圈，不落墨。

**绘制层**

1. 双层 Canvas：底层为已完成笔画（位图缓存），顶层只绘制正在书写的一笔，结束后合入底层——长答题区也不卡。
2. perfect-freehand 生成压感轮廓；`requestAnimationFrame` 合批；按 `devicePixelRatio` 缩放（上限 2，控制内存）。
3. 工具：笔（2–3 种粗细、黑/蓝/红）、荧光笔、**整笔橡皮擦**（碰到即删整笔，比像素橡皮更适合答题且可撤销）、撤销/重做、清空（二次确认）。
4. 答题区**向下无限延伸**（写到底部自动加高）；提供"全屏作答"模式：题干固定在顶部，下方整屏书写区，适合大题。

**数据层**

1. **矢量存储**（自研时的格式；用库时存库自己的 JSON，见 5.4.0）：`{ v:1, width:1000, strokes:[{ tool, color, size, points:[[x,y,pressure,t],…] }] }`，坐标归一化到逻辑宽度 1000——横竖屏旋转、换设备都能无损重绘。
2. 由矢量数据派生：交卷时导出 PNG 快照（老师缩略图 / 给 AI 视觉模型看）；老师端**笔迹回放**（按时间戳重演书写过程，这就是愿景里的"做题痕迹"，成本极低、价值很高）。
3. 草稿防丢：每一笔结束即写入 IndexedDB；每 10 秒或切后台（`visibilitychange`）时把增量同步到服务端草稿接口。刷新、锁屏、Safari 被系统杀掉都能恢复。
4. 上传：`CompressionStream('gzip')` 压缩后 multipart 上传。

**最终答案输入**：手写题下方的"最终答案"普通输入框在 iPad 上天然支持 **随手写（Scribble）** 手写转文字，零成本；需要输入复杂公式的题目可开启 MathLive 数学键盘。

**验收**：必须在真实 iPad + Apple Pencil 上按 §7 的手写检查清单逐项通过，不能只以模拟器为准。

### 5.5 学习痕迹采集

事件类型（`packages/contract` 中定义枚举，T4.0 增强后共 **22 种**；既有 11 种语义零变化，新事件按"环境 / 位置 / 交互"三族扩展）：

- **作答域（既有 11 种，Phase 2 起冻结）**：`attempt_start` · `question_view`（进入视口）· `question_focus` / `question_blur` · `answer_change`（前后值）· `hint_open`（第几条）· `ink_stroke_batch`（笔画数）· `page_hidden` / `page_visible` · `submit` · `lecture_expand`
- **环境族（T4.0）**：`lecture_visible` / `lecture_hidden`（讲义阅读会话，viewId 配对双标签页）· `net_offline` / `net_online`（离线上下文标记——离线期间事件本就不丢，缺的是"这段作答在离线状态完成"的标记）· `idle_start` / `idle_end`（分域阈值挂机判定）
- **位置族（T4.0）**：`lecture_section_focus`（讲义分节聚焦，**替代滚动深度设计**——折叠架构下滚动百分比会倒退、语义失真）· `lecture_toc_jump`（目录跳转）
- **交互族（T4.0）**：`directive_interact`（统一交互事件：折叠开/合、steps 揭晓、结果页看解析、提示解锁，按 host 判别）· `ink_edit_batch`（手写橡皮/撤销/重做按操作批次聚合计数）· `ink_fullscreen`

采集与上报原则（T4.0 定稿的纪律，D12/D13）：

- 前端内存队列，每 5 秒批量发送；页面隐藏时用 `navigator.sendBeacon` 兜底；离线时存 IndexedDB，恢复后补发。批次按**条数与字节（≤32KiB）双限切**（sendBeacon 队列上限 64KiB）；高频信号（滚动、笔画）必须节流/阈值化后才上报。
- **每题有效用时**由服务端根据 focus/blur/hidden 事件计算（不信任客户端的汇总值），同时回写到 `responses.activeSec`。
- "当前聚焦题" = 最近交互的题，若无交互则取视口中占比最大的题。
- `events` 表带 `studentId` / `lectureId`（服务端从会话/payload 写入，前端不传），"哪名学生、哪篇讲义、读了多久"可计算。
- **payload 不存题目内容**（只存 id、序号、计数与时间戳）；原始 events 不出库、不进学情页与 AI 数据包（D18/D22 之外无任何原始事件出口），一律由服务端聚合成派生指标（讲义阅读地图、离线作答占比、手写反复度等），聚合按需计算、不建新表回写。

### 5.6 判分

- `packages/grading` 纯函数，服务端交卷时执行，结果入库。沿用旧版已验证的归一化规则（NFKC、去空白、负号统一、去 `$` 与 `\left`/`\right`），并增加：
  - 数值等价：`0.5` = `1/2` = `\frac{1}{2}`（简单有理数解析）；
  - 等价答案列表（`[[0.5|1/2]]`）；
  - 多选题全对才判对（可配置部分得分）。
- **未作答客观题判错（Phase 3 定稿，D1）**：判断/单选/多选/填空完全未作答（`answerJson` 缺省）或多选空选（`indexes = []`，学生选后又全部取消即落此态）→ `autoCorrect = false`，不进待批。填空**部分空有答案**不属于未作答，按既有规则正常判定。`scoreAuto` 公式不变（答对 ÷ 可自动判分题数），但未作答客观题从此计入分母，数值更真实。
- `autoCorrect = null` 只剩三种，全部进入老师待批队列：①题目无标准答案（`answers` 缺省——判定优先级最高，先于未作答判定）；②手写题未能自动判（整题未作答 / 只写笔迹未填最终答案 / 最终答案为空）；③判断题学生写法无法归一化（教师裁定）。
- `finalCorrect = teacherMark ?? autoCorrect`，交卷时即持久化（= autoCorrect），批注/清除时事务内改写并重算整卷得分与状态（见 §5.2「批注、得分与状态机」）；待批口径全站唯一（`finalCorrect IS NULL`，共享谓词 `services/pending-mark.ts`）。所有统计都以 `finalCorrect` 为准，`scoreFinal` 分母 = 该 attempt 全部题数。
- **修订（2026-10-02）：填空题改为全人工批改。** `gradeFill` 恒返回 `null`——fill 一律不自动判（原「normalize + 有理数等价 + 等价答案列表」的自动判分逻辑废止），与手写题同流程进待批队列由老师批改；原因：数学答案等价形式长尾（±、√、π、区间、单位等）自动判分误判风险高。上文 D1 对 fill 的「未作答判错」口径同步废止：未作答 fill 亦进待批，由老师裁量。`scoreAuto` 分母无需改代码——该口径本就只计 `autoCorrect` 非 null 的题，fill 从此自然不计入。normalize/rational 保留不动，仍服务手写题 final 答案判分；待批队列、attempt 状态机本就支持 null（判不出）路径，服务端无其他改动。

### 5.7 身份与安全

- **教师（多教师 + 管理员，Phase 2B）**：登录名 + 密码登录（同一登录页同一接口，管理员与普通教师不区分入口）。登录名全局唯一，字符集中文/字母/数字/下划线/连字符、长度 2–32（禁止空白与文件路径非法字符——登录名会进入共享文件名与各处展示位）；不引入姓名字段，身份显示一律用登录名。密码 scrypt 哈希；登录后 httpOnly + Secure + SameSite=Lax 会话 Cookie；`apiToken` 列给 MCP/脚本预留（Phase 4 起启用，届时每教师独立、可重置）。
  - **首位教师**：全新部署由首启设置向导创建（登录名 + 密码两字段，必然 isAdmin=true）；存量单教师部署升级时唯一教师行**自动升级为管理员**（loginName='teacher'、isAdmin=true、密码不变，部署者无感）。
  - **第二位及以后的教师，两个来源**：自助注册 `POST /api/public/teacher/register`（表单同为登录名 + 密码，成功自动登录，isAdmin=false），受**注册开关**控制——开关存 `app_settings` 表 `allowRegistration` 键（默认开），管理员经管理端读写，关闭时注册接口 403、登录页不显示注册入口；无教师行时注册不可用（第一位只能走首启 setup）。管理员创建（管理端，登录名 + 初始密码，不受开关影响）。
- **管理员**：`teachers.isAdmin` 的教师（单表多角色，不建独立管理员表），兼任全部教师功能，另可进管理端 `/a`（`/api/admin/*` 整组 requireAdmin）。管理动作只有账号与系统集：教师账号（创建/改登录名/重置密码/禁用启用/授予撤销 isAdmin）、注册开关、共享文件管理（列表/删除）；**看不到任何教师的业务数据**（题库、课程、学生、作答）。硬约束：不能禁用自己；不能禁用或撤销最后一位未禁用管理员（否则系统失去管理入口，409 LAST_ADMIN）。
- **禁用（可逆的人事动作，不是数据删除）**：`disabledAt` 置值即禁用——该教师当前全部会话**立即失效**（守卫按教师行校验，禁用动作成功那一刻起旧 Cookie 全部 401）；**其学生不受影响**（照常登录、作答、查看记录）；其资源/课程/作业全部保留；重新启用完全恢复原状。
- **错误码与防枚举**：登录名不存在 / 密码错误统一 401 `INVALID_CREDENTIALS`（不区分暴露账号是否存在）；身份验证通过但被禁用 → 403 `ACCOUNT_DISABLED`（明示「账号已被停用」，本人有权知道原因）；非管理员访问管理接口 → 403 `ADMIN_ONLY`；教师访问非本人资源 → 404 `NOT_FOUND`（不暴露存在性，四层域隔离同口径，见 §5.2）。
- **学生**：老师在名单中添加学生（显示名 + 登录名 + 初始密码），系统同时提供两种登录方式，登录后都写入同一种会话 Cookie（有效期 90 天）：
  1. **专属链接**：`https://域名/s/<随机令牌>`，微信发给学生，点开即进入；令牌可一键重置（链接泄露时）。
  2. **姓名 + 密码**：登录页输入登录名和密码（适合换设备、链接找不到时）。登录名默认等于姓名，重名时老师改成"张三2"之类即可，全局唯一（多教师后依然全局唯一：不同教师各自创建「张三」时登录名必须不同，冲突自动建议后缀名）。密码 scrypt 哈希存储；学生登录后可自行修改；老师可重置。
  - 老师可对单个学生分别开关两种方式（例如只给链接、不设密码）。
  - 同名学生问题、看到别人记录的问题一并解决。学生归属创建教师（`students.teacherId` 终身不变）；学生端不知道也不需要知道教师是谁，接口行为零变化。
- **会话时长与续期**：Cookie 设 Max-Age 与服务端会话有效期对齐（老师 7 天、学生 90 天），是持久化 Cookie——关闭浏览器（含 iPad 上 Safari 被系统回收）不丢登录态；守卫校验通过即滑动续期（DB 会话与 Cookie 一起重置为满额时长），只要两次使用的间隔不超过有效期就无需重新登录；连续不用超过有效期、登出、学生被归档、或教师被禁用才会要求重新登录。
- **限流**（复用 `login_failures` 表，按 key 独立计数）：登录 `name:<登录名>` 与 `ip:<IP>` 双 key，任一 key 连续失败 5 次锁定 10 分钟（教师 key 用真实登录名，多教师各自计数互不影响；学生 key 加 `student:` 前缀隔离命名空间）；注册按 IP 单独限流 `reg:ip:<IP>`，1 小时内最多 5 次（含成功尝试，防滥用上限）→ 429 `LOCKED`。所有输入走 Zod 校验；上传大小限制（单题笔迹 ≤ 2 MB）。
- **共享目录 `DATA_DIR/shared/`（Phase 2B）**：教师间内容流转的唯一通道是「发布 → 文件 → 他人导入」——发布把单元/讲义按导出格式写成独立快照 `.md`（文件名 `<标题>-<发布者登录名>-<时间戳>.md`，经 safeFilename 防路径注入）+ 伴生 `<同名>.meta.json`（teacherId/loginName/publishedAt）；也可以直接把 `.md` 放进服务器该目录（U 盘/网盘/scp，与在线发布同源并列，无 meta 显示「本地文件」、仅管理员可删）。共享页 `/t/shared` 浏览（含「预览」渲染查看——preview 响应携带 markdown 原文，前端 RichMarkdown 只读渲染）与导入（导入进**导入者自己的域**，与发布者无后续关联）；发布者删自己的、管理员删任意；资源库列表勾选后可在批量操作栏「发布到共享」（batch action=publish，逐项生成快照、单条失败不中断，成功项返回实际文件名）。目录只列前 200 个文件、单文件 > 1 MB 不列出（规模防线）。

### 5.8 学情分析（教师端"学情"页，Phase 4 已交付）

> 侧边栏「学情」自 T4.2 起实装，三视图：总览 `/t/insights`（含时间范围快捷项 7/30/90 天/全部，默认 30，与按课程筛选——不单做「课程学情页」）、学生画像 `/t/insights/students/:id`、题目视角 `/t/insights/questions`；「导出」（`/t/export`，§5.9 第二层）与「连接 AI」（`/t/connect`，§5.9 第三层）入口在其附近。全部查询教师域隔离（会话教师，MCP/导出同口径）。

以 SQL 聚合 + 少量 TS 计算实现，不引入分析引擎。指标口径（Phase 4 §2 D1–D7，契约 `analytics-api.ts` 注释为权威）：

1. **统计口径总则（D1）**：全部指标以 `finalCorrect` 为准；**作业取全部作答，课程练习默认取首次作答（attemptNo=1）**，重做次数作为独立指标单独展示。
2. **完成矩阵（D2）**：学生 × 作业 + 可见课程单元，状态 = 未开始 / 进行中 / 已交 / 已批 / 未指派；课程单元列含做过次数与首次得分；矩阵是当下状态一览，不受时间范围影响。
3. **正确率与待批（D4）**：`finalCorrect = null` 的题不计入正确率分母、单独显示待批数（正确率 = 判对 ÷ 已判定题数，与 scoreFinal 的"分母=全部题"是并列口径）。
4. **时间口径（D5）**：周趋势按自然周（北京时间、周一起算、取 submittedAt）；「下节课重点」周期默认 14 天可调（错误最多 3 考点 + 代表错题）。
5. **用时异常题（D6）**：> 该题用时中位数 2 倍**或**提示数 ≥2；中位数按本教师域内该题全部已交作答计算。
6. **学生画像页**：正确率周趋势（折线）、考点正确率**条形图**（正确率升序 top N，薄弱在上，ECharts 按需加载独立 chunk；不用雷达图）、错题列表（点击跳作答详情）、异常题卡片、重做概览、离线作答占比（T4.0 离线标记聚合）、**讲义阅读地图**（目录树逐项"时间代理的行为推断"状态：节三态/折叠两态/steps 进度，含挂机时长；显著标注"非注意力测量"）、AI 报告列表（§5.9 save_report 写入，可查看/删除）。
7. **题目视角**：每道题的正确率、平均/中位用时、高频错误答案分布（fill/choice/multi 聚合）、异常计数；行展开题干全文。

### 5.9 AI 原生接入（三层）

**第一层：制作端契约**（Phase 1 就有）
DSL 规范、样例、提示词模板、JSON Schema、linter + "复制错误给 AI"。

**第二层：AI 学情数据包**（Phase 4 已交付，导出中心 `/t/export` 五步向导）
模块化定向导出（不做一键全量 zip）：① 范围（学生多选〔勾选顺序 = 化名编号顺序〕/ 按课程 / 按作业 / 时间范围，交叉）② 内容模块（分组勾选：讲义大纲或勾选小节全文 / 题目三层递进 / 逐题作答与评语 / 作答汇总 / 手写 PNG 默认关 / 学习痕迹派生指标）③ 任务目标（四模板决定 prompt.md：诊断薄弱点 / 备下节课讲解建议 / 生成变式练习〔输出 DSL v2〕/ 阶段总结，另有自定义附加段）④ 隐私（**默认化名**：学生A/学生B…，`映射.txt` 仅存教师本地不进 pack.json；「包含真实姓名」需二次确认）⑤ 预览（文件清单 + 预估大小）→ 下载 zip：

```
learning-pack/
  pack.json          # 符合 LearningPack JSON Schema（模块化 section，未勾选的不出现）；历次口径：全部历次作答带 attemptNo 与首次标记
  summary.md         # 人类可读的统计摘要（AI 读 Markdown 表格效果很好）
  ink/*.png          # 可选：手写图，供多模态模型读过程（默认不包含）
  prompt.md          # 按勾选模块与任务目标拼装的提示词
  schema.json
  映射.txt            # 化名对照（仅教师本地保存，不交给 AI）
```

包上限 50 MB（预览步骤超限提示精简）。老师把整包拖进任何 AI 对话即可得到愿景里描述的那种诊断报告；AI 生成的变式练习因为遵守 DSL，可直接回到导入流程——"测 → 析 → 练"闭环不依赖任何内置模型也能转起来。

**第三层：MCP Server**（Phase 4 已交付）
在 `/mcp` 暴露（Streamable HTTP，stateless + JSON 响应），鉴权用 **apiToken（每位教师独立一份**，`teachers.apiToken` 列，base64url；设置页可随时查看、可重置，重置即覆盖旧值立即失效；禁用教师其 token 同 requireTeacher 口径立即 401）。MCP 全部操作按 token 绑定教师隔离域；无/错 token 同一文案 401（防探测）。`/t/connect`「连接 AI」页（D26）展示 MCP 地址（PUBLIC_URL + /mcp）、token 与通用 mcpServers 配置 JSON + Claude Desktop 专属示例，均一键复制。11 个工具：

| Tool | 作用 |
| --- | --- |
| `get_dsl_spec` | 获取内容规范与样例 |
| `lint_markdown` | 校验 AI 生成的 MD，返回错误 |
| `import_markdown` | 导入（默认 dry-run，需参数确认才真正写入；写入 token 教师的资源库） |
| `list_students` / `list_assignments` / `list_courses` | 基本信息（`list_courses` 为 AI 提供课程上下文） |
| `get_lecture` / `get_unit` | 按资源库 id 读讲义 / 单元 Markdown（域隔离 404） |
| `get_student_learning_pack` | 获取某学生某时间段的学情数据（复用第二层打包服务，参数对齐模块勾选） |
| `get_question_stats` | 题目/考点维度统计（复用学情聚合） |
| `save_report` | 把 AI 写的学情报告存回系统（reports 表），教师端画像页可查看、可删除 |

老师可以直接对 AI 说："看看小明这两周的作业，总结薄弱点，出 8 道针对性练习并导入成新作业"——这是愿景第四部分的完整形态，且系统本身仍然不内置模型。

**可选：内置 AI（Phase 5，BYO-Key）**
设置页填入 OpenAI 兼容接口（可接 GLM、DeepSeek、通义、Kimi 等）或 Anthropic Key；通过 Vercel AI SDK 提供"一键生成学情报告"、"根据错题生成变式练习（输出 DSL → linter → 老师审核 → 导入）"、"手写过程题 AI 预批改建议（老师确认后生效）"。不配置 Key 时这些按钮隐藏，其余功能不受影响。

### 5.10 部署、备份与运维

- `docker compose up -d`：`app`（Node）+ `caddy`（HTTPS）；数据卷挂载 `./data`。
- 首次启动自动建库、跑迁移、进入设置向导；`/api/health` 健康检查。
- 自动备份（Phase 4 已交付，**备份范围 = 全量 DATA_DIR**）：启动时 + 每 24 小时 `VACUUM INTO data/backups/tutor-YYYYMMDD-HHMMSS.db`，保留最近 14 份（日常快照只做 db，大文件目录实时读档）；教师端"下载完整备份（zip）"在下载前**恒先拍一份当前时刻快照**再打包 `db 快照 + blobs/ + shared/ + secret.key`（不存在的目录跳过；排除 backups 自身——备份不进备份）；"从备份恢复"上传 zip → 结构校验 → **恢复前自动再拍一次快照（回滚保险）** → 临时目录整体替换 DATA_DIR（原子性，失败回滚）→ 热重启数据连接，请求需带登录密码确认；恢复后以恢复库中的会话为准（当前登录可能失效，页面提示重新登录）。运维细节见 `docs/部署.md` §1.4/§4.2。
- **HTTPS 与备案（已决定：去备案）**：
  - 现状是公网 IP + HTTP。系统必须**在纯 HTTP 下也能完整使用核心功能**（答题、手写、IndexedDB 草稿、交卷都不依赖 HTTPS）；只有 PWA 安装/离线缓存、Secure Cookie 需要 HTTPS。服务端通过配置 `PUBLIC_URL` 自动判断：`http://` 时关闭 Secure Cookie 与 Service Worker 注册，`https://` 时全部开启。
  - **建议现在就开始备案，与 Phase 0–2 开发并行**（备案一般需要 1–3 周）：在阿里云购买域名并实名 → ECS 实例需满足备案要求（包年包月、剩余时长足够）→ 阿里云备案系统提交 ICP 备案 → 通过后 30 天内在全国互联网安全管理服务平台完成公安备案 → 域名解析到 ECS → Caddy 自动申请证书。
  - 备案完成前的临时方案：继续用 `http://公网IP:端口` 测试和使用（功能完整、无 PWA）。
- 本地开发：`pnpm dev`（Vite 开发服务器 `--host` 暴露到局域网，iPad 同一 Wi-Fi 直接访问测试）。

## 8. 给执行模型的工作约定（写入仓库根目录 `AGENTS.md`）

```markdown
# AGENTS.md

## 项目
simple-tutor-tool v2：一对一辅导老师的自部署、AI 原生讲练工具。架构权威文档：docs/技术架构与实施方案.md。

## 硬性规则
1. 契约优先：任何数据结构改动先改 packages/contract 的 Zod schema，再改实现；禁止在前后端各自手写同一个类型。
2. TypeScript strict，禁止 any、禁止 @ts-ignore（确有必要用 @ts-expect-error 并写原因）。
3. 学生端 API 永远不返回未交卷题目的答案、详解、提示内容；新增学生端接口必须加泄露测试。
4. 判分只在服务端执行（packages/grading），客户端结果不可信。
5. 不新增技术栈清单以外的依赖；确需新增时在 PR 描述写明理由与替代方案。
6. 不使用 CDN，所有前端资源随构建打包。
7. UI 文案与代码注释使用中文；标识符使用英文。
8. 每个阶段在独立分支完成；小步提交；每个提交保持可构建、测试通过。
9. 修改解析器或判分逻辑必须先补测试用例，再改实现。
10. 数据库结构变更必须通过 drizzle-kit 生成迁移文件，禁止手改线上库。
11. DSL 兼容：已发布指令只增不改；新属性必须可选且有默认值；改名用 aliases；未知指令必须优雅降级。新增指令走"注册表 → 组件 → 样例测试 → pnpm gen:spec"四步，不得绕过注册表。
12. 所有 samples/ 下的历史样例文档是兼容性回归测试，任何改动后都必须仍能解析、渲染一致。

## 常用命令
pnpm dev / pnpm test / pnpm e2e / pnpm lint / pnpm typecheck / pnpm build / pnpm tutor-lint <file.md>

## 完成一个任务的定义
代码 + 测试 + 类型检查通过 + 相关文档（docs/dsl 或本文件）已同步更新 + 在 PR 描述中列出如何手动验证。
```
