## 1. 背景与目标

Phase 4 的两个消费方对学习痕迹提出了超出 T2.10 现状的要求：

- **T4.1 学情聚合**：「下节课重点」、异常题诊断需要可信的行为信号；讲义阅读行为目前基本不可用。
- **T4.3 AI 学情数据包**：定向导出中的「学习痕迹模块」（每题有效用时、提示数、改答次数、离线占比、讲义阅读情况）是 AI 诊断「学生怎么学的」的核心输入——只有对错数据 AI 只能判「会不会」，加上痕迹才能判「熟练度、专注度、做题习惯」。

用户对采集的要求（2026-09-29 原话归纳）：**全面完善**——页面停留时间、上下滚动、对题目的操作、看提示的行为等都要能采；组件（讲义/练习的 DSL 指令组件）应承担「信息提供」职能——折叠块、选择类交互在什么时间点被点击要能记录；指标要清晰不混乱，便于整体分析。且要求本方案信息自包含，供外部 AI 复核后完善。

**先澄清一个容易误解的点（离线）**：离线期间**事件不会中断或丢失**——T2.10 的队列在离线时把事件写入 IndexedDB，网络恢复后自动补发（`apps/web/src/lib/event-queue.ts` 已实现并有 14 项亲验）。真正的缺口是**没有「网络状态」这个上下文标记事件**：事后分析无法区分「这段作答是在断网状态下完成的」。本方案用 `net_offline`/`net_online` 标记补上（§4.3.1）。

## 2. 现状盘点（T2.10 已落地的，全部引用可查）

### 2.1 事件类型（11 种，契约权威定义）

`packages/contract/src/learning-event.ts`：

| 事件 | 语义 | payload |
| --- | --- | --- |
| `attempt_start` | 进入答题页/开始一次作答会话（每次进入一条） | — |
| `question_view` | 题目进入视口（**每题首次**报一次） | questionId |
| `question_focus` / `question_blur` | 题目获得/失去焦点（有效用时的计算基础） | questionId |
| `answer_change` | 答案变化（前后值） | questionId, 前后值摘要 |
| `hint_open` | 解锁第 n 条提示（服务端直记） | questionId, index |
| `ink_stroke_batch` | 手写笔画批次（防抖窗口聚合） | questionId, 笔画数 |
| `page_hidden` / `page_visible` | 页面隐藏/可见（切后台停表；**仅 attempt scope 自动注入**） | — |
| `submit` | 交卷 | — |
| `lecture_expand` | 讲义指令折叠展开（**唯一无 attempt 上下文的事件**） | lectureId, 指令名, 序号 |

契约既定纪律：payload **不存题目内容**（只存 id/序号/计数）；`clientTs` 毫秒整数（对 §0.3 ISO 约定的已注释例外）；单批 ≤200 条。

### 2.2 前端队列（`apps/web/src/lib/event-queue.ts`，可靠性完备，本任务不动它的机制）

- attempt / lecture 两种 scope；内存队列 + **每 5 秒批量 POST**；页面隐藏 `navigator.sendBeacon` 兜底；**离线写 IndexedDB、online 补发**；IndexedDB 不可用退化为内存。
- attempt scope 自动注入 `page_hidden`/`page_visible`；**lecture scope 不注入，且讲义端点（`POST /api/student/events`）契约只收 `lecture_expand`**（文件注释原文：这是讲义停留时长缺失的直接原因，本方案 §4.3.1 修正）。
- 403/404 终态停止（T2A.6 D7：课程练习失去访问权后丢弃待发并静默，不当网络失败重试）。

### 2.3 埋点链路（讲义侧）

`apps/web/src/features/markdown/RichMarkdown.tsx` 的 `onDirectiveExpand` 回调 → `directives/expand-context.ts`（Context 下发）→ 各指令组件（Steps / LabeledFold 等），**仅学生讲义阅读页提供回调**，教师端预览为 no-op。这是「渲染组件不改结构、页面层决定是否采集」的既有模式，本方案的新讲义事件沿用该模式。

### 2.4 服务端

- `apps/server/src/services/event-service.ts`：批量落库（≤200 条校验）、`hint_open` 直记、已交后宽松接收（迟到 flush 不影响已算结果）。
- `apps/server/src/services/active-time.ts`：**每题有效用时由服务端按原始事件序列计算**（focus/blur 精确扣除 page_hidden 区间；26 条时间规则用例锁定），回写 `responses.activeSec` 与 `changeCount`。「当前聚焦题」= 最近交互题优先 + 视口占比兜底。

### 2.5 已知缺口（T2.10 验收记录实现备注原文，出处 `docs/进度表.md`）

> 「lecture_expand 的 attemptId/questionId 为 NULL、归属在 payload（**events 表无学生列**，T4.x 学情统计需要『谁读了讲义』时再立项加列）」

### 2.6 复核期代码核查结论（2026-09-29，§4 设计的依据）

1. `onDirectiveExpand` **已覆盖 hint / solution / fold / steps 全部四种**：消费方集中在 `directives/Steps.tsx`（hint→HintDirective、solution→SolutionDirective、fold→FoldDirective、steps 容器「显示下一步」报 `step`+步序号；Example 内嵌的 solution 走同一组件映射，同样覆盖）；底层统一走 `LabeledFold.onExpand`，仅收起→展开方向触发一次；`answer` 不上报（机密内容学生端不下发）。上报 name 为注册表主名（别名已归一），index 为全文档顺序编号。
2. `question_view` 确用 IntersectionObserver 实现（`use-attempt-events.ts`）：threshold `[0, 0.1, 0.25, 0.5, 1]`，`intersectionRatio > 0` 且每题首次（Set 去重）。同一 observer 耦合了答题页「聚焦兜底」（占比 <10% 切最大占比题）——讲义复用该模式时需去掉此耦合。
3. `hint_open` 服务端直记的 clientTs 填的是**服务端处理请求时的 `Date.now()`**（`event-service.ts` 的 `recordHintOpenEvent`），与学生真实点击时刻差一个请求往返，与其他前端队列事件的 clientTs（真客户端时钟）**不同源**。
4. `InkSurface` 只有一个 `onChange(doc)` 回调：一笔结束、整笔橡皮、撤销/重做、清空、load 全触发同一回调，只带最新 doc、不带变化类型（消费方只能前后 diff，`HandwrittenControls.onInkStroke` 即如此）。Excalidraw 适配器**能识别 undo/redo**：无命令式 undo API，适配器自维护快照栈（undoStack/redoStack，`canUndo/canRedo` 已实现）——变化类型在适配层内部可感知，只是接口未向外暴露。
5. 结果视图：详解**折叠**（`AttemptResultView.tsx` 的 `SolutionFold`，自有组件、不走 LabeledFold/onDirectiveExpand 通道——**结果页目前零埋点**）；已解锁提示**平铺**（HintEntryList，无折叠交互）。

## 3. 缺口分析

| # | 缺口 | 后果 | 严重度 |
| --- | --- | --- | --- |
| 1 | `events` 表无 `studentId` 列 | 讲义事件（无 attemptId）无法归属到学生；一切讲义侧学情不可算 | 高（结构性） |
| 2 | 讲义页停留时长完全未采集（lecture scope 不注入 page 事件 + 端点只收 lecture_expand） | 「读了哪篇、读了多久」不存在 | 高 |
| 3 | 无网络状态标记 | 离线作答（行为模式往往不同：外部帮助、搜答案）无法识别 | 中 |
| 4 | 手写橡皮/撤销重做/全屏进出、讲义滚动深度/目录跳转、提示面板停留等细粒度交互未采集 | 「犹豫、反复、跳读」等过程信号缺失，AI 诊断与异常题判定变弱 | 中（按 P1/P2 分级补） |
| 5 | 结果视图（交卷后回看）零事件 | 「做错后有没有看解析/订正」这一高诊断价值行为完全不可知（复核新增，§4.3.3 directive_interact host=result 补齐） | 中 |

## 4. 设计方案（复核定稿）

### 4.0 复核总结论

现有设计能承接 T4.0 的全部 P0/P1 事件，且**不需要改渲染架构**。分层恰好把采集所需的信号切在三个互不干扰的层上：

| 信号来源层 | 已有机制 | T4.0 新事件落点 |
| --- | --- | --- |
| 队列层 `event-queue.ts` | attempt scope 自动注入 page_hidden/visible；离线 IndexedDB；sendBeacon | net_offline/online、lecture_visible/hidden、idle_start/end（P0 全部在这层） |
| 页面层（讲义阅读页/答题页/结果页） | 页面提供回调、组件不改结构（expand-context 模式） | lecture_section_focus、lecture_toc_jump、ink_edit_batch、ink_fullscreen |
| 组件层 `directives/*` | onDirectiveExpand → Context → Steps/LabeledFold；remark-directive-host 注入的文档序号 index | directive_interact 统一事件——已有 lecture_expand 覆盖 hint/example-solution/steps/fold 四类交互，序号由第 2 层注入、天然不含内容 |

新事件里**没有一个需要碰 remark 插件、宿主标签映射或指令组件结构**，符合 AGENTS.md 第 11 条与 §4.1「语义只增不改」。

### 4.1 设计原则（原五条 + 复核新增两条）

1. **语义只增不改**：既有 11 种事件的结构与语义、`activeSec`/`changeCount` 计算口径**零变化**（26 条时间规则用例是回归底线）；新事件进契约枚举，旧客户端不产生新事件也完全兼容。
2. **payload 不含题目内容**：只存 id、序号、计数、阈值、时间戳（`learning-event.ts` 头注释既有原则，新事件逐一对照）。
3. **节流后才上报**：高频信号（滚动、笔画）必须阈值化/聚合，杜绝逐帧逐笔上报（§4.3 各事件标注节流规则）。
4. **聚合而非透传**：原始 events 不进学情页、不进 AI 数据包、不提供管理界面；一律由服务端聚合成派生指标（`activeSec` 模式的延伸），聚合按需 SQL 计算、不建新表回写。
5. **复用既有队列**：新事件全部走 `event-queue.ts` 既有链路（5 秒批量 / sendBeacon / 离线补发 / 终态停止），采集可靠性零新增代码。
6. **指令组件即传感器，只报「什么」与「何时」，不管「是否」与「归属」**：组件通过 Context 拿上报回调，报 `{name, index, action}`；clientTs 由队列统一打；页面层决定要不要提供回调（教师端预览、导入预览不提供 → 组件行为零变化）以及事件归属哪个 scope/宿主。这是现有 `onDirectiveExpand → DirectiveExpandContext → LabeledFold.onExpand` 模式的推广：从「只报展开」推广为「报全部交互（开/合/揭晓）」，从讲义页推广到答题页与结果页。组件永远不知道 attempt/lecture/API 的存在。
7. **一个交互一个事件，指标在服务端拼**：不为每种组件造一个事件名（hint_close、solution_open、step_reveal……会越积越乱），一个 `directive_interact` 事件承载全部指令交互；name 用注册表主名（别名已归一）、index 用 remark-directive-host 注入的全文档序号。**新增指令自动获得采集能力，不需要再动契约**。

### 4.2 数据模型与契约

- `events` 表加两列（同一次迁移，均为服务端落库时从 payload/会话提取，防伪造）：
  - `studentId`（text，**DDL 可空、代码恒写非空**——与 T2B D9 teacherId 同口径。复审修订：原稿「回填后 NOT NULL」与「存量 NULL 行读侧兼容」自相矛盾，且 SQLite `ALTER TABLE ADD COLUMN` 无法直接加无默认值的 NOT NULL 列、真要 NOT NULL 须整表重建，收益为零；读侧聚合一律按 `studentId IS NOT NULL` 过滤即可）；
  - `lectureId`（text，可空；讲义域事件落库时从 payload 提取，**复用 questionIdOf 的既有模式**。复审新增：地图查询按「学生 × 讲义」聚合，若 lectureId 只在 payloadJson 里则无法走索引、只能全扫该生事件逐行 JSON.parse）。
- 索引：**`(studentId, lectureId, clientTs)`**（讲义地图常驻查询的定位索引）+ 既有 `(attemptId, clientTs)` 不动。原拟 `(studentId, type, clientTs)` 改为上述更贴合查询形状的组合（type 过滤在少量行上做即可）。
- 回填（backfill.ts 的 data_migrations 完成标记模式，单事务幂等）：有 `attemptId` 的行按 attempt → `attempts.studentId` 回填、同批回填 lectureId（存量 `lecture_expand` 的 payload 里取）；无 attemptId 的存量讲义事件（上线以来数量极少）无法可靠归属，保留 NULL 并接受读侧过滤。
- 落库统一改由服务端从**会话**写 `studentId`（前端不传，防伪造）。
- 契约变更：
  - 8 个新事件枚举 + 各自 payload schema（§4.3）；`directive_interact` 的 action / host 用 Zod enum 锁死。
  - 讲义端点（`POST /api/student/events`）接收范围从「只收 lecture_expand」扩为「环境族 + 位置族 + 交互族（host=lecture）」；attempt 端点增收交互族（host=question/result）、`ink_edit_batch`、`ink_fullscreen`、idle、net。
- 前端 Context：`DirectiveExpandContext` 扩展为 `DirectiveTelemetryContext`，回调签名 `(e: {name, index, action}) => void`；`onDirectiveExpand` 保留为兼容别名（内部映射为 action=open）。
- 注册表描述文案「展开即上报」改为「展开/收起均上报」→ 重跑 `pnpm gen:spec` 并提交（硬性规则 11 的文档同步）。

### 4.3 事件体系（按域分三族；既有 11 种零变化，新增 8 种）

#### 4.3.1 环境族（两个 scope 通用，队列层注入）

| 事件 | 新/旧 | payload | 说明 |
| --- | --- | --- | --- |
| `page_hidden` / `page_visible` | 旧 | — | attempt scope，不动 |
| `lecture_visible` / `lecture_hidden` | 新 | lectureId, viewId | lecture scope 同款（visibilitychange + pagehide 双兜底）。viewId = 每次页面加载生成的随机串（不含内容），解决双标签页同开、iPad Safari 被系统回收重开导致的序列交错——聚合按 viewId 配对、再对同一学生×讲义的区间求并集 |
| `net_offline` / `net_online` | 新 | — | 两 scope 均注入；scope 启动时若 `navigator.onLine === false` 主动补一条 net_offline（window 事件只在翻转时触发，离线打开 PWA 壳没有翻转事件可听）；信号源与 T2.12 `useOnlineStatus`/顶栏三态**同源**，保证「离线占比」与学生所见状态口径一致 |
| `idle_start` / `idle_end` | 新 | — | 两 scope 均注入；无输入超过阈值发 idle_start，再有输入发 idle_end，每个空闲期只一对。**阈值分域（复审修订，原稿统一 90s）**：attempt 90s / **lecture 300s**——阅读的正常状态就是零交互（读一段长推导两三分钟不碰屏幕很常见），统一 90s 会系统性低估阅读时长、把细读判成掠过（方向性错误）；同类系统（GA4 engaged session、阅读类应用）对阅读场景均用分钟级。活动源：pointerdown/keydown/**scroll 必算**（iPad 阅读滚动是主要交互）、pointermove 加位移阈值（防手搭平板微抖）；判定用「上次活动时间戳差值」，不依赖 interval 心跳（iOS 后台 timer 被限 1Hz/挂起，靠心跳必错——现有事件锚点模式的正确延伸）。只供新指标扣减，**不进 activeSec 计算**（红线）。附带收益：idle_start 是未闭合讲义会话的天然截断点（§4.4.2 前提 4） |

#### 4.3.2 位置族（页面层）

| 事件 | 新/旧 | payload | 说明 |
| --- | --- | --- | --- |
| `question_view` / `question_focus` / `question_blur` | 旧 | questionId | 不动 |
| `lecture_section_focus` | 新 | lectureId, headingIndex | 「当前阅读节」切换时一条，口径与「当前聚焦题 = 视口占比最大」完全对称。**替代原方案的 lecture_scroll_depth**——讲义里 solution/fold/steps 默认折叠，展开任何一块都改变页面总高度，百分比会倒退、阈值语义失真，且百分比回答不了老师真正关心的「读到哪一节」；headingIndex 直接对应自动目录，事件量 = 标题数，节流天然满足。实现：新建独立 hook，复制 `use-attempt-events.ts` 的 IntersectionObserver 模式（threshold `[0, 0.1, 0.25, 0.5, 1]`，占比最大者变化时上报、由 threshold 0 / ratio 归 0 推断离开），**去掉答题页的聚焦兜底耦合** |
| `lecture_toc_jump` | 新 | lectureId, headingIndex | 目录点击；headingIndex 来自自动目录（H2/H3），序号不含内容 |

#### 4.3.3 交互族（组件层 → 页面层入队）

| 事件 | 新/旧 | payload | 说明 |
| --- | --- | --- | --- |
| `lecture_expand` | 旧 | lectureId, name, index | 语义/结构不动；新客户端不再产生（§6 决策 1），读侧归一为 `directive_interact{action:"open"}`；存量行读侧过滤 |
| `directive_interact` | 新 | host: `"lecture"｜"question"｜"result"`；hostId（lectureId / questionId / attemptId+questionId）；name；index；action: `"open"｜"close"｜"reveal"`；reveal 时额外带 `step`（步序号） | open=收起→展开、close=展开→收起、reveal=steps「显示下一步」。**复审修订：reveal 的 payload 必须同时带容器身份与步序号**——`{name:"steps", index: 容器的文档序号, step: 容器内步序号, action:"reveal"}`；原稿只有步序号，而一份讲义可有多个 steps 容器（samples/讲义样例.md 就有两个），§4.4.2(c) 的地图按容器分行时无法归属。注意两套编号的区别：`DirectiveProps.index` 是**文档全局指令序号**（step 指令也有自己的全局 index），`revealed+1` 是**容器内步序号**，契约注释必须写清，聚合只用容器 index + step。覆盖：hint / solution / fold / step（现有 LabeledFold 通道加 close 方向即可，`StepsDirective` 解构出自己的 `index` 一并上报）+ **结果页 SolutionFold**（自有组件，同一回调接入，host=result——补齐 §3 缺口 5「错后有没有看解析」）+ **答题页提示解锁点击**（host=question；复审澄清：§2.6-5 已确认提示面板是平铺常驻、不存在「面板开合」交互，此处的正确落点是 HintPanel 解锁**成功回调**时发一条 `{name:"hint", action:"open", index}`，与 hint_open 服务端直记一一配对——失败重试不发，避免同一次解锁双报）。`hint_open`（服务端直记）仍是「解锁事实」的权威记录；directive_interact 提供真实客户端时钟——已核查直记 clientTs 用的是服务端时钟（§2.6-3），配对算停留必须用客户端这条，**任何区间运算不得把 hint_open 的 clientTs 与客户端事件混排** |
| `ink_edit_batch` | 新 | questionId, erase, undo, redo, clear | 四个计数一条事件，与 ink_stroke_batch **同一防抖窗口**聚合。实现：`surface.ts` 的 `onChange(doc)` 扩展为 `onChange(doc, reason?)`（reason 缺省 `"stroke"`，老调用方零影响）；atrament 与 Excalidraw 适配器各自在历史栈操作处填 reason（Excalidraw 快照栈内部可感知 undo/redo/erase/clear，§2.6-4） |
| `ink_fullscreen` | 新 | questionId, on | 一个事件带布尔，不拆 enter/exit |
| `hint_open` / `answer_change` / `ink_stroke_batch` / `submit` / `attempt_start` | 旧 | — | 不动 |

**砍掉（复核结论，§6 末列）**：`math_keyboard_toggle`（T4.1/T4.3 无任何指标消费）、独立 `hint_close`（并入 directive_interact close）、`lecture_scroll_depth`（被 section_focus 替代，百分比在折叠架构下不可靠）、`ink_erase`/`ink_undo`/`ink_redo` 三个（并入 ink_edit_batch，减少枚举）。

**隐私对照**：新增 payload 字段全部是 id / 序号 / 计数 / 布尔 / 枚举，无一含内容。headingIndex 与 index 可还原文档结构但不含文字，可接受（同原 §6.5 结论）。

### 4.4 指标字典（服务端纯函数，T4.1 / T4.3 唯一消费口；原始 events 不出库）

每个指标有唯一名称、公式、来源事件、消费方；判定阈值集中在一个可调配置常量（§4.4.2 前提 3），不散落各处。

#### 4.4.1 学生 × 题（attempt 域）

| 指标 | 公式 | 来源 | 消费 |
| --- | --- | --- | --- |
| activeSec / changeCount / hintsUsed | 既有，不动 | — | 既有 |
| timeToFirstHintSec | 首次 directive_interact{hint, open} − 首次 question_focus；未用提示为 null | 交互族 | 「先想没想」——秒开提示与思考 3 分钟后再开是完全不同的学习状态 |
| hintDwellSec | 每条提示 open→close（或→blur/隐藏）累加 | 交互族 | 是否真读了提示 |
| inkEditCount | Σ erase+undo+redo+clear | ink_edit_batch | 手写反复度（犹豫、订正），与对错、用时并列的过程信号 |
| fullscreenUsed | 存在 ink_fullscreen{on:true} | ink_fullscreen | 大题作答认真度旁证 |
| offlineShare | net_offline 区间 ∩ focus 区间 ÷ activeSec | 环境族 | 异常题与 AI 数据包参考，不下结论 |
| reviewedSolution | 交卷后存在 directive_interact{host:result, solution, open} | 交互族 | 「错了之后有没有看解析」——一对一辅导最高价值的新增信号（§3 缺口 5） |

#### 4.4.2 学生 × 讲义（lecture 域）：讲义阅读地图（逐项判定，汇总从地图求和）

服务端聚合产出一张**地图**：讲义每个 H2/H3 标题、每个可折叠指令、每个 steps 容器各一行。粒度天然存在（section_focus 带 headingIndex、directive_interact 带 name+index），本方案把「逐项判定」定义为一等指标——**汇总率全部从这张地图求和得出，不再单独定义**。

**(a) 每个子标题（section）**

| 字段 | 来源 | 说明 |
| --- | --- | --- |
| reached | 是否出现过该 headingIndex 的 section_focus | 到没到过 |
| dwellSec | 该节 focus 区间 ∩ visible ∩ ¬idle | 停留多久 |
| expectedSec | 服务端按该节 markdown 字数估算（中文约 300 字/分钟，公式段落打折） | 「读完要多久」的基线 |
| status | 未到达 / 掠过（reached 且 dwell < 20%·expected）/ 已读（≥ 50%）/ 细读（≥ 100%） | 判定结论，阈值可调（集中配置） |

**(b) 每个可折叠指令（hint / solution / fold / example 内 solution）**

| 字段 | 来源 | 说明 |
| --- | --- | --- |
| hostHeadingIndex | 服务端解析讲义时定位该指令所属的节 | 老师能看到「第 3 节的例题解析没点开」 |
| opened / openCount | directive_interact open 计数 | 用没用 |
| firstOpenOffsetSec | 首次 open 距该节 focus 开始的秒数 | 先读正文再点，还是一进来就点 |
| dwellSec | open→close（或→节切换/hidden）累加 | 点开后有没有看 |
| expectedSec | 该指令内部文本字数估算 | 同上 |
| status | 未打开 / 打开未读（dwell < 20%·expected）/ 已读 | 判定结论 |

**(c) 每个 steps 容器**

| 字段 | 说明 |
| --- | --- |
| revealedCount / total | 推进到第几步 / 共几步（total 来自服务端解析） |
| paceSec[] | 相邻 reveal 的间隔 |
| status | 未开始 / 连点跳过（中位间隔 < 2s）/ 逐步阅读 / 未走完 |

**(d) 汇总指标**（从地图求和）：readSec（Σ 各节 dwellSec，扣 idle、按 viewId 配对后区间求并集）、sectionCoverage（reached 节数 ÷ 总节数）、foldOpenRate（opened 指令数 ÷ 服务端解析的可折叠指令总数）、hintOpenCount / solutionOpenCount（按 name 计数）、stepsPaceSec（连点判定汇总）。

**逐项判定的前提（缺一个就判不准；4、5 为复审新增）**：

1. **条目身份要稳定**：headingIndex 与 (name, index) 都是文档顺序编号，讲义一改就错位。lecture 域事件 payload 带 `lectureUpdatedAt`；聚合时只对版本一致的事件做逐项定位，版本不一致的历史事件按「计入总时长、不定位到具体指令」降级处理。
2. **分母来自服务端解析**：expectedSec、每节字数、指令属于哪一节、steps 总步数，由服务端用 md-dsl 解析 `lectures.markdown` 得到（按 updatedAt 缓存一次；服务端解析基础已存在——`reparse-service.ts` 已在用 `@tutor/md-dsl` 的 `parseDocument` 解析讲义）。这是「组件当传感器、服务端当尺子」的分工——组件只报动作，判定标准不在前端。
3. **判定是代理，不是眼动**：「已读」的含义是「停留时间足够读完」，不是「真读了」。T4.2 页面与 T4.3 数据包须明确标注为**行为推断**；阈值（20% / 50% / 2s / idle 90s｜300s）集中放在一份可调配置常量里，不散在各处。
4. **区间必须能收尾（iPad 是常态不是异常）**：iOS 杀进程/断电时可能 visibilitychange 与 pagehide 都不发，「无结束事件的会话」必须由服务端收尾——口径：每个 viewId 的 visible 开区间在遇到 `min(下一事件, idle_start, 硬上限 30 分钟)` 处截断（Caliper TimedOut 与 MOOC gap-cap 的通行做法）；visibilitychange 与 pagehide 双兜底可能双发 `lecture_hidden`，聚合按「重复 hidden 忽略」处理（与 active-time 规则 3 同构）；最后一节的 dwell 以会话收尾点为终点，**不得**依赖「下一个事件时刻差」（GA4 的经典教训：最后一页永远 0 秒）。地图同时输出 `rawDwellSec`（visible∩focus）与扣 idle 后的 `dwellSec`，教师端可见「含挂机 X 分钟」。
5. **headingIndex 的三个口径必须锁死一致**：前端目录 `extractOutline` 是**对 markdown 原文的行扫描**（不跳过容器指令内部），而 `LabeledFold` 收起时 children **不渲染**（DOM 里没有该标题）——若折叠块内出现 H2/H3，目录序号、DOM 序号、服务端 AST 序号三者错位（`scrollToHeading` 今天就潜在错位，section_focus 会放大成地图错行，且不报错、只是数字错）。落地两件事：① 新增 lint 规则**禁止容器指令内使用 H2/H3**（语义上折叠块内的小节标题本就破坏目录语义）；② 契约测试：samples/ 全量断言 `extractOutline(markdown)` 序列 == 服务端 `parseDocument` 标题序列 == 渲染 DOM 的 h2/h3 序（渲染侧用测试环境挂载取 `querySelectorAll(".rich-markdown h2, .rich-markdown h3")`）。

#### 4.4.3 学生总体（T4.1 直接引用）

- `studySec` = Σ readSec + Σ activeSec（总投入）。
- `seriousnessFlags`：连点步骤、秒开提示、零复盘、高离线占比——**只标记不下结论**，供「异常题」与 AI 数据包引用。

#### 4.4.4 消费方影响

- **T4.2 学生画像页**：新增「讲义阅读地图」视图——讲义目录树，每个标题与折叠块旁打状态标记（未到达/掠过/已读；未打开/打开未读/已读；连点跳过）。老师一眼看到「第 3 节例题解析没点开、第 4 节推导 3 秒连点完」，比一个 63% 的覆盖率有用得多。
- **T4.3 数据包 traces 模块**：逐项地图直接进 pack.json（教师域数据，可含标题文字），AI 据此判「哪个知识点没认真学」。

## 5. 实施任务定义（拆两单：T4.0a 地基 / T4.0b 传感器与指标）

### 5.0 实现红线与坑位清单（2026-09-30 可行性复审产出；执行时逐条对照，标注〔a〕/〔b〕归属任务）

**结论**：方案可行。分层与现有代码咬合良好，核验过的现状断言无一失实；下列条目是「照做能避开」的坑，不是方案障碍。同类系统的前车之鉴（xAPI/edX 的时间双轨、GA4 最后一页零时长、Caliper TimedOut 收尾、Meta/GA4 的事件去重、Safari PWA 生命周期实测）已折算进各条。

**A. 队列层（event-queue.ts，〔a〕）**

1. **先修一个现存 bug：IDB 持久键跨实例冲突**。lecture scope 的持久键是全局 `"events:lecture"`（attempt 键同理按 attemptId），`persist()` 是替换式写——两个标签页（iPad Safari 多标签、投屏演示）同时离线会互相覆盖、丢先写一方的事件。现状事件量小无感，本任务把讲义事件放大一个量级后必炸。修法：持久键加每队列实例的随机后缀（`events:lecture:<rand>`）；`flushNow` 时不只读自己的键，而是**遍历前缀下全部键**合并发送、成功后逐键删除（遗留键=上次页面被杀的积压，顺带修了「换讲义/刷新后旧键被覆盖」的次生问题）。
2. **idle 判定不得依赖 interval 心跳**：iOS 后台 JS 全挂起、timer 被限 1Hz，心跳式必错。用「上次活动时间戳」惰性判定：活动事件只更新 `lastActiveAt`（时间戳比较，不在高频回调里做重活；pointermove 加位移阈值、scroll 用 rAF/节流），一个低频 interval 只负责「检查是否已越过阈值该发 idle_start」、visible 恢复时补检查。监听在 `dispose()` 全部移除。
3. **net 事件注入顺序**：scope 创建时若 `navigator.onLine === false` 先补一条 `net_offline`（离线打开无翻转事件可听）；此后 online/offline 翻转各发一条。口径写进契约注释：**navigator.onLine 只反映网络接口连接（连上路由器即 online，不代表服务器可达）**，offlineShare 语义=「设备联网状态」，与学生顶栏三态所见一致——这是有意选择，不是缺陷；服务不可达的时段不标 offline。
4. **lecture_visible/hidden 双兜底允许双发**：`visibilitychange→hidden` 与 `pagehide` 都注入 `lecture_hidden`（先到的先入队）；服务端聚合按「重复 hidden 忽略」容错（与 active-time 规则 3 同构），不为去重在前端做防重锁。
5. **beacon 批次要按字节切**：sendBeacon 队列上限 64KiB（Chrome 上与 `fetch(keepalive:true)` 共享、超限静默 stall——OpenTelemetry JS 真实翻过车）。`answer_change` 的 from/to 是学生原文，可能很长；现有「按 200 条切」改为「按条数与字节（≤32KiB 留余量）双限切」。同源 beacon 无 CORS content-type 问题（现状 `Blob application/json` 同源可用），端点已被 5 秒周期预热、冷连接证书坑不适用——此两条写注释即可。
6. **iOS 已知限制（写进任务报告，不写代码）**：iOS 无 Background Sync——离线积压要等学生下次打开页面才补发；Safari 标签页 7 天不用会被 ITP 清空全部脚本可写存储（含 IndexedDB 与 SW 缓存），**主屏 PWA 豁免**——学生加主屏是队列存续前提，验收文案照此解释数据缺口。卸载竞态（dispose 时 in-flight 批次可能丢）接受为已知极限场景，与 T2.10 口径一致。

**B. 契约与库（〔a〕）**

7. `studentId`/`lectureId` 均服务端写入：路由层 `c.var.student.id` 现成可用（`appendLectureEvents` 的 `_studentId` 参数启用即得）；`lectureId` 复用 `questionIdOf` 的提取模式。`recordHintOpenEvent` 直记路径也要带 `studentId`（attempt 行可查）。
8. `directive_interact` 用 Zod discriminatedUnion 按 host 分支（hostId 形状随 host 变化：lecture→lectureId、question→questionId、result→attemptId+questionId；reveal 仅 host=lecture 且带 step 字段）；契约注释写明两套编号（§4.3.3）。
9. 端点扩容的兼容顺序：先部署服务端（多收新事件）、前端随后（PWA 的 SW 缓存可能让旧前端多活几天——旧前端只发旧事件，安全）；反向（新前端打旧服务端）只在降级部署出现，契约 400 会被队列当普通失败重试（403/404 才终态），可接受、注释说明。
10. **泄露测试与域口径**：讲义/attempt 端点扩展后 `assertNoLeak` 泄露测试必须补（硬性规则 3，payload 虽不含内容、测试防回归）；讲义事件端点的讲义可见性校验对齐学生端 GET 讲义的现状口径（存在 + 未软删），不单独发明规则。

**C. 组件与页面层（〔b〕）**

11. `LabeledFold` 加 close 方向：`onExpand` 之外加 `onToggle(action)`（或改签名、旧 prop 保留兼容），改动集中在 Steps.tsx 的四个指令组件 + 结果页接入；`StepsDirective` 记得解构出自己的 `index` 上报（§4.3.3 修订）。
12. 结果页（host=result）事件走 attempt 端点：`requireUsableAttempt` 的宽松口径（draft/submitted 均收）已支持交卷后上报，无需改服务端校验——但结果页要自建队列实例（attempt scope、同一 attemptId），离开结果页 dispose。
13. **section_focus hook 的 IntersectionObserver 细节**：讲义页滚动在文档层（正文非内部 overflow 容器），root 用默认视口即可，但 hook 里要写死「取 `.rich-markdown h2, .rich-markdown h3`」与 `scrollToHeading` 同一选择器（同源）；判定用「视口占比最大者」时——高于视口的节 ratio 永远到不了 1（W3C 已知语义，threshold 1 永不触发），比较 `intersectionRatio` 大小可行、判定「在视口内」必须显式 `ratio > 0`（`ratio===0 && isIntersecting===true` 是合法状态）；不要用 `rootMargin` 百分比做中线法——**百分比按 root 宽度解析**，iPad 横竖屏切换会改变判定带。**加迟滞**：折叠块展开/steps 揭晓会改变布局（旧 entry 异步才更新），「当前节」切换要求新节占比超过当前节一定余量（如 0.1）或稳定 ≥1s 再上报，防止展开一个折叠块产生一串 section_focus 抖动。复制 use-attempt-events 模式时**去掉聚焦兜底耦合**（§2.6-2）。
14. 手写 reason：`surface.ts` 的 `onChange(cb: (doc, reason?) => void)`，reason 缺省 `"stroke"`；两个适配器在 undo/redo/clear/erase 处填值，`load` 也填（**消费方把 load 排除在 inkEditCount 外**——注意全屏进出会把笔迹在页内/全屏两个引擎间移交、触发 load，不得计成 erase/clear）。全屏事件挂 `HandwrittenControls` 现成的 `fullscreen` state 变更处。

**D. 聚合层（〔b〕，纯函数，先写用例再实现）**

15. 区间运算统一规则（写成一个工具函数 + 用例锁定）：按 viewId 分流→区间求并集（双标签页/双设备并行不叠计）→未闭合开区间按 §4.4.2 前提 4 截断→负时长 clamp 0（客户端时钟回拨防御）→`hint_open` 的 clientTs 不参与任何区间运算（服务端时钟，§2.6-3）。
16. 排序确定性：同 `clientTs` 的事件排序要给确定的 type 优先级（events.id 是 randomUUID，作 tie-break 是随机的）；测试数据避免同刻事件但实现要容忍。
17. 幂等/容重复：同一事件重复落库（fetch 响应丢失重试）时指标不翻倍——区间配对天然容重复，计数类指标若要硬保证可加可选 `eventId`（客户端入队时生成 UUID、服务端唯一索引 INSERT OR IGNORE）列为 **P2 可选加固**，不阻塞验收。
