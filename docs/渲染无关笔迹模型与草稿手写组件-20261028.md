## 1. 渲染无关模型是什么

一句话：**笔迹以矢量文档存储，坐标与线宽归一化到「逻辑宽 1000」，与任何具体屏幕/画布/设备解耦；渲染时按当前容器宽度等比反算，同一份数据在任何尺寸、任何 DPR、任何渲染器下还原一致。**

覆盖范围：**草稿纸（NoteDoc）与正式手写作答（InkDoc）两条链路是渲染无关的**；题干圈画（AnnotationDoc）是**刻意渲染锁定**的对照设计（见 §2.4）。

### 1.1 数据形状（单一事实来源：packages/contract/src/ink.ts）

一笔笔画（`inkStrokeSchema`）：

| 字段 | 含义 |
| --- | --- |
| tool | `pen` \| `highlighter`（整笔橡皮不产生笔画，见 §1.3） |
| color | CSS 颜色串（荧光笔带 alpha） |
| weight | 归一化线宽（逻辑宽 1000 基准） |
| points | 点数组，每点 `{x, y, p, t}`：坐标 + 压力 0–1（无压感恒 0.5）+ 相对本笔起点毫秒 |
| rendering（可选） | 内嵌渲染参数 InkRendering：renderer/smoothing/thinning/streamline/sizeScale/simulatePressure |
| id / startedAt / pointer（可选，LR-1） | 客户端铸造的稳定笔画 id（8–40 位，撤销/擦除/重投影都不改）、落笔绝对时刻、输入来源 pen/touch/mouse |

外层文档（`inkDocSchema`，按 `engine` 判别联合）：

- `engine: "atrament"`（页内默认）：`data = { width: 1000（字面量锁定）, strokes[], deleted[]? }` + `updatedAt` + `serverRevision?`
- `engine: "excalidraw"`（全屏作答历史形态）：`data.scene.elements` 存库原生 JSON，契约不解释内部结构
- 墓碑（LR-2，`inkDeletedStrokeSchema`）：被删笔画的完整几何 + `deletedAt` + `deletedBy`（eraser/clear/undo），放**兄弟数组 `deleted`** 而非在笔画上打标记——回放/合成/快照/命中/历史栈等既有消费方只读 `strokes` 即保持正确；最终态 = 过滤墓碑后的投影

### 1.2 坐标归一化（渲染无关的核心机制）

- 常量 `INK_LOGICAL_WIDTH = 1000`（contract/ink.ts；引擎层 apps/web/src/features/ink/engine/types.ts re-export）
- 换算：apps/web/src/features/ink/engine/normalize.ts 的 `toLogical` / `fromLogical`——按容器宽度**等比**缩放（y 用同一比例，横竖屏旋转/换设备无损重绘）；存储值保留 2 位小数（1000 宽下约 0.1px 精度），反算不取整，normalize→denormalize→normalize 严格可逆（有单测）
- DB 层锚：note_versions 表 `paper_width` 列带 CHECK `= 1000`（apps/server/src/db/schema.ts）

### 1.3 确定性渲染（存储态 → PNG 的权威口径）

- 契约常量 `NOTE_RENDER_VERSION = 3`（packages/contract/src/note.ts）：服务端把它铸在 note_versions 行的 `render_version` 列；**同一文档 + 同一规格 + 同一 renderVersion ⇒ 输出内容与坐标一致**（不承诺跨浏览器 PNG 字节一致——抗锯齿差异）
- 确定性渲染器：apps/web/src/features/notes/render-note.ts——只消费已提交的 NoteDoc.strokes（不截图活 canvas、不混入未收笔笔画），复用 atrament 官方程序化绘制原语 `replayAtramentStroke`（与实时书写/全量重绘/回放同一绘制路径），每页独立离屏 canvas
- **递增纪律**：改任何影响 PNG 像素输出的值（背景画法/颜色、切片几何、绘制原语版本、分析图/缩略图像素宽）必须递增 NOTE_RENDER_VERSION；纯重构不改像素输出不递增。递增后旧版本派生图不自动重生成，补图链路按需重建
- 正式手写快照复用同一管线：apps/web/src/features/ink/render-ink-snapshot.ts（按内容包围盒裁剪出快照 PNG）

### 1.4 边界：哪些刻意「不是渲染无关」

- **题干圈画是渲染锁定设计**（packages/contract/src/annotation.ts）：坐标域 = 底图**像素坐标**（0≤x≤baseWidth），与笔记逻辑坐标（0..1000）是两个坐标系，契约级隔离、互不混用；底图身份三要素 questionRevisionId + snapshotHash + baseRenderVersion（`ANNOTATION_BASE_RENDER_VERSION = 1`，**不得复用** note_versions.render_version），底图 ready 后永不重生成——原位编辑靠「底图身份 + 实时 DOM 文本行 ≤0.75px 对齐 + 字体签名」兼容检查。生产环境 4 种底图像素宽并存就是这个设计的代价
- **消费侧只见最终态**：AI 复核包与教师/学生 MCP 拿到的都是最终态栅格图（手写快照 PNG、圈画合成图），无矢量/时序接口；矢量与节奏只在学生端编辑器与教师端回放组件内消费

### 1.5 回放时间轴（渲染无关模型的已知近似）

apps/web/src/features/ink/replay/model.ts：点内时间戳精确（t 相对本笔起点），**笔间真实停顿未记录**——回放按「上一笔结束 + 固定 160ms 间隙」近似（`REPLAY_INTER_STROKE_GAP_MS`），真实长停顿压缩到 5s 上限并打「停顿 N 秒」标记；旧数据缺时间戳退化为每点 12ms 匀速；总时长不足 2s 等比拉伸保证可读。这是「手写体验迭代」最直接的候选改进点（记录笔间停顿）。

## 3. 草稿里面的手写组件（详解）

### 3.1 组件树与数据流

```
题卡（答题页）
└─ NoteLayer（题卡级草稿纸，features/notes/NoteLayer.tsx）
   ├─ NoteToolbar（精简工具条：笔/橡皮/撤销/手指书写/更多——SessionPrefToggleButton 共用）
   ├─ InkPad（showToolbar=false 形态，inputMode="session"）
   │  └─ engine/atrament-adapter（InkSurface 实现：指针状态机 + InkStore + 归一化）
   ├─ NoteStatusArea（四维状态区：本地/服务端/派生图/提交证据）
   └─ useNoteEditor + useNoteHead + useNoteSyncActions（编辑器核心与接线）
        ├─ note-store（IndexedDB tutor-notes 串行持久化队列）
        ├─ note-sync（PUT gzip NoteDoc + baseRevision + mutationId → 服务端 note-service）
        └─ render-note（head 版本 → 缩略图/分析图 PNG → image-sync 补传 note_images 槽位）
```

手写题不走 NoteLayer（继续走 HandwrittenControls 作答 ink，两条链不混）；订正工作台 CorrectionWorkspace **复用同一套** NoteLayer/编辑器（phase="correction"，正文走 correction 行、图片维度关闭）。

### 3.2 关键行为与文件

- **收起/保活**：收起只显示「草稿纸 · N 笔」标记按钮；引擎保活 45s（NOTE_ENGINE_KEEPALIVE_MS，NoteLayer.tsx；use-retained-paper.ts）——「先做选项再回草稿」往返零重建，超时才卸载释放画布内存
- **纸高与自动加高**：逻辑高持久化在 NoteDoc.paperHeightLogical；CSS 高 = paperCssHeight() 每次换算（notes/paper-geometry.ts）；自动加高统一走逻辑口径（触发 72 / 步长 240，常量在 engine/paper-style.ts，新草稿换算成逻辑单位落库）；InkPad 以 paperHeight prop 受控（禁内部 CSS 直增）。旧作答链（HandwrittenControls）保持内部 CSS px 直增语义不变
- **纸张背景**：white/grid/line 存进 NoteDoc（默认 grid）；屏幕端 CSS 渐变与 PNG 描边用 paper-style.ts 同源常量（格距 40 逻辑、#cbd5e1、1px），**派生图是权威口径**（屏幕 CSS 仅为编辑时视觉对齐，允许 ≤1px 栅格相位差）
- **本地持久化**：note-store.ts——独立 IndexedDB 库 `tutor-notes`（与 tutor-drafts/tutor-events 互不触碰，交卷清理不删笔记）；键 = 「note + origin + 学生 + attempt + 题 + phase」五元；正文与待传版本描述同一 IDB 事务写入；每笔/撤销/重做/清空/纸高变化统一进**串行持久化队列，无防抖**（事务完成才显示「已存本机」）；服务端数据回退（备份恢复代际）检测到 head 比本地已知回执旧时置 conflict 停自动上传，绝不静默覆盖
- **服务端同步**：note-sync.ts 带 baseRevision + mutationId；冲突走 use-note-sync-actions 的用户裁决接线；四态（dirty/uploading/synced/conflict/denied）由 deriveServerState 派生而非存储
- **派生图**：head 版本由 render-note.ts 确定性产出缩略图（480 像素宽）与分析图（1000 像素宽、片高 1400 逻辑、重叠 40 逻辑、裁剪留白 48——全部暂定值，真机定标后修订）；note_images 槽位 upsert + 新文件新路径（不可变，不覆盖）；失败/缺失走 image-sync.ts 补图
- **多题隔离**：正文键含 questionId；布局切换（auto/side/below，note-layout.ts 持久化偏好）只改外框宽度，逻辑坐标笔画恒在纸内，不新建笔记不换正文身份
- **坏文档防线**：note-doc-repair.ts 加载端修复；契约 superRefine 拒 NaN/越界/超限

### 3.3 与作答页「手写草稿防丢」（T2.9）的区别

NoteLayer 草稿纸（note 链，可回看版本、可交卷固定证据）≠ HandwrittenControls 的草稿防丢仓（attempt/draft-store.ts，把答案+笔迹整体存 tutor-drafts，只做恢复与去重同步，交卷即清）。两条链复用同一引擎与 InkDoc 形状，但存储、生命周期、消费方式完全独立，迭代时不要互相牵改。

## 4. 手写体验迭代指引（改哪里）

1. **笔手感**（最常见诉求）：renderer（atrament ⇄ freehand）、smoothing/thinning/streamline/sizeScale/simulatePressure 全在契约 ink-profile.ts + 引擎 freehand-paint.ts / atrament-adapter.ts；每学生档案走 ink_profiles（服务端 routes/ink-profiles.ts，前端 ink-profile-store.ts）；调参实验用 features/ink/lab/ 脚手架 + pages/InkFeelPage.tsx。注意：**预测（prediction）只用于输入层，不进入笔迹/证据**
2. **改影响 PNG 输出的任何常量/画法** → 递增 packages/contract/src/note.ts 的 NOTE_RENDER_VERSION（当前 3）；圈画侧是 ANNOTATION_BASE_RENDER_VERSION（当前 1），两者**不得互相复用**
3. **扩展笔画字段**（如笔间停顿、笔迹事件）：走契约可选字段（LR-1/LR-2 先例：旧客户端不发、旧文件不含、消费方降级），新消费方才读新字段；墓碑兄弟数组模式是范本。笔间停顿目前**未记录**（回放 160ms 近似），是现成的立项候选
