## 实际接入与隐私边界

- 公共 Hono RPC 客户端随同源业务请求携带本机随机 UUID 和设备元信息；有效会话守卫据此登记当前本人设备，不增加前置网络等待。跨源请求保持原 fetch，不附加设备头，不改变 credentials。
- 设备元信息只包含粗粒度设备类型、系统名、浏览器名、主屏幕应用标志与使用时间；不保存原始 UA、硬件型号、序列号、画布/字体指纹或学生内容。不把设备 id 当权限凭据。
- 普通事件、回执事件和 beacon 同时支持设备引用；服务层先验证本人作答，再将事件及 attempts.device 同事务写入。没有事件的刚打开作答保留空设备；后续首批事件覆盖所有作答来源。
- 浏览器清空数据、不同浏览器/主屏幕应用可能得到不同 ID；保留合并别名。用户改名优先于自动名称。历史会话只允许本人清理，默认不推测设备。
- Agent 连接名到设备的映射留在二期 MCP 接入，当前 MCP 入参和行为保持兼容。未执行真实 iPad、线上部署或真实线上快照演练。

## 元数据总量补审修复

- 唯一限额来源为 `packages/contract/src/memo-api.ts`：`MEMO_METADATA_MAX_BYTES`（64 KiB）和由它、`MEMO_TEXT_MAX * 6`、固定 1 KiB 信封余量派生的 `MEMO_JSON_BODY_MAX_BYTES`。
- `memoMetadataByteLength` 按规范 JSON 的 UTF-8 字节计量 anchor、context、tags、device、deviceId、recordedAt，包含空字段默认值；正文仍独立遵守原 5000 字符语义。保留完整 ID/标题，不恢复 80/160 字符截断。
- 文字请求复用 `guardBodyLimit` 同时做 Content-Length 预检和实际流计数，信封预算也覆盖未知字段与 JSON 转义。离线补传使用同一入口，不绕限额。
- 媒体文件仍沿用原 20/10 MiB 限额；非文件字段（包含重复、未知字段）单独受信封预算限制，解析后的来源元数据与文字/MCP共用同一 64 KiB 预算。
- 共享写服务先检查输入，再检查服务端真实来源展开后的完整元数据；包括设备引用和标题快照。超量由服务抛出 `413 MEMO_METADATA_TOO_LARGE`（HTTP 返回 413，MCP 沿用工具错误壳返回同码），不截断、不静默丢合法来源、不新增条目或消耗序号；媒体也在检查成功后才写 blob。
- 读侧既有历史记录及历史回填保持兼容，不按新预算截断原始来源。新请求若合法来源整体超预算，会明确拒绝，调用方可不带来源另记，不篡改已有条目。
