# 学生端 UI 与学习流程精进实施计划

日期：2026-10-05。状态：已完成线上检查与源码定位，待用户确认后实施。

## 目标与范围

优先让学生在 iPad 横竖屏及电脑上顺畅完成「继续学习 → 阅读/作答 → 交卷 → 看反馈 → 复习」。手机保证可读、可点击、无遮挡。交付包括代码、测试、审查与验证记录，以及与实际组件一致的 `docs/学生端组件与UI设计规范.md`。

沿用 React、Tailwind、Radix/shadcn、lucide、现有 Markdown 与数学公式渲染器。视觉方向：安静、清晰的学习工作区，白色内容面板、浅中性背景、克制的蓝色强调、充足的阅读空间；减少装饰渐变、重复状态和没有下一步的统计数字。

本轮以现有接口为基础，不增加学习推荐算法、跨设备掌握状态同步或新判分机制。若发现必须调整载荷，先修订 contract，再实现并补泄露测试。现有答案公布与提示解锁边界保持有效。

## 已核实的问题

浏览器检查覆盖电脑 1366×900、iPad 竖屏 768×1024、横屏 1024×768、手机 390×844。已查看首页、错题本、课程列表、课程目录、单元入口及已有未交卷练习；没有填写答案或交卷。以下区分实测与源码发现。

| 改前（证据） | 改后（拟实现） | 原因 |
| --- | --- | --- |
| 首页主区是三份已完成作业；课程目录另有两份进行中练习，首页没有继续入口（线上） | 首屏单一主任务优先「继续上次练习」；随后待办、短复习、课程，已完成作业收纳 | 找回进度、明确下一步 |
| 错题默认主操作为重练全部 39 题（线上） | 默认「先练 5 题」，可选 10 题或全部，明确当前课程/分区范围 | 降低开始复习的负担 |
| iPad 错题筛选设置占较多首屏；手机题干几乎消失（线上） | 题干两行/块级摘要，次行显示统计和时间；高级设置按需展开 | 题目内容比辅助信息优先 |
| 摘要出现 LaTeX 命令和 Markdown 表格符号；正则还会剥掉代码中的运算符（线上及 `stemSummaryOf`） | 使用安全的结构化摘要/现有富文本渲染能力，保留数学和代码含义 | 避免摘要改变题意；不靠追加替换正则修补 |
| 390px 导航中「我的记录」与「退出」重叠（线上） | 电脑/iPad 稳定顶部导航，窄屏底部四入口，账号菜单容纳退出 | 保证触控目标和内容宽度 |
| 答题页连续长列表，横屏一张题卡接近满屏，无题号导航（线上及源码） | 电脑侧边题号导航，iPad 可展开题号面板；标出已答/未答、跳至未答题 | 长练习更易定位、检查和继续 |
| 吸底栏固定定位，正文只预留固定 `pb-24`（源码） | 按实际操作栏空间预留正文，协调安全区与窄屏导航；多行错误不遮挡最后一题 | 覆盖离线、上传失败等状态 |
| 单元页固定显示首次/最近/最高三个数字；再做一次使用手写模态层（源码） | 仅一次成绩时简化展示，多次才比较；复用 Radix Dialog 管理焦点/关闭/返回 | 避免重复信息并完善键盘操作 |

## 实施顺序与文件清单

### 1. 隔离工作与补回归测试

- 当前主工作区存在其他任务的未提交内容，而且检查期间分支和文件发生了变化。实施前再次检查 Git 状态，从确认后的 `v2` 创建独立工作树与 `codex/student-ui-refinement` 分支；不挪动、不提交其他任务的文件。
- 先补能失败的行为测试：最近草稿入口、短复习范围、题号跳转、结果筛选、模态框焦点、窄屏布局。
- 纯色彩、间距、圆角等样式调整按 AGENTS 豁免单元 TDD，通过浏览器截图及真实布局断言验证；不写只检查 className 的测试。

### 2. 统一学生端设计基础和导航

- 修改 `apps/web/src/index.css` 中学生主题作用域，统一颜色、状态、字阶、间距、内容宽度、焦点、动效与安全区约定。
- 修改 `apps/web/src/pages/student/StudentLayout.tsx`、`StudentScreen.tsx`，统一导航与页面状态。
- 整理 `apps/web/src/features/student/student-ui.tsx`，抽出确实被多页复用的页头、状态标签、卡片、空态和分区结构；需要时按职责拆分。
- 学生端控件触控区至少 44×44px；输入文字至少 16px；保留缩放。悬停仅用于具备悬停能力的设备，减少动态效果时关闭位移动画。
- 全局基础组件如有修改，必须检查教师端回归；优先采用学生端作用域。

### 3. 首页与课程学习入口

- 修改 `StudentHomePage.tsx`，复用 `student-records-queries.ts` 的草稿记录查询，把最近未交卷练习放在第一主行动；覆盖作业、课程、错题重练来源。
- 有草稿则继续；无草稿则显示待完成作业；都没有时提供短复习/课程入口。局部查询失败不把整个首页变成错误页，也不伪造已完成状态。
- 已完成作业采用紧凑收纳，保留回看入口；课程进度明确为练习完成进度，不暗示知识掌握。
- 修改 `StudentCoursesPage.tsx`、`StudentCourseDetailPage.tsx`、`StudentCourseUnitPage.tsx`，统一目录层级、返回入口、长标题、主按钮、成绩与历史布局。
- 单元「再做一次」复用项目 Dialog。

### 4. 错题与记录体验

- 修改 `StudentWrongQuestionsPage.tsx`、`features/student/wrong-questions-ui.tsx`，增加 5/10/全部的复习批量选择，按当前筛选范围和既有排序取题，点击后才创建重练；不声称是间隔记忆算法。
- 分组重练与全范围重练的题数/范围明确；提交时防重复，失败可重试；不满 5 题按实际题数。
- 摘要复用富文本管线或基于现有 AST 构造受限展示，覆盖公式、代码运算符、表格、长标题和未知 DSL 的降级；正文、答案和详解不混入摘要。
- 默认展示常用筛选，高级掌握设置展开查看；保留旧 URL 筛选兼容。文案说明「已达本设备复习标准」，不把做对一两次等同永久掌握。
- 修改 `StudentRecordsPage.tsx`、`features/student/records-filters.tsx`、`records-views.tsx`，统一筛选、时间、状态和继续入口，保留分页与返回筛选状态。

### 5. 答题、讲义和结果工作区

- 修改 `features/attempt/AttemptSession.tsx`，新增 `AttemptQuestionNavigator.tsx`（必要时独立测试），采用现有已答判断口径；导航仅表示是否作答，交卷前不呈现正确性。
- 修改 `AttemptBottomBar.tsx`、`AttemptQuestionCard.tsx`、`SubmitConfirmDialog.tsx`，统一正文密度、选项反馈、保存状态、交卷确认和未答定位；保持题卡稳定挂载，避免题号切换丢手写/输入状态。
- 修改 `AttemptResultView.tsx`，统一待公布、待批、最终结果的文案层级，提供全部/错题/待批筛选，保持老师评语和重练入口可发现；答案未公布时不泄露结果筛选计数或内容。
- 修改 `StudentLectureViewPage.tsx`、`StudentLecturesPage.tsx`，规范阅读宽度、目录折叠、锚点与返回位置；减少动态效果时不强制平滑滚动。
- 登录页面沿用同一视觉规范并检查错误、失效链接和输入状态。
- 不改手写引擎和草稿同步协议；如涉及画布外层尺寸，额外执行现有手写回归并列出真机验收项。

### 6. 规范、质量闸门、验证与合并

- 新增 `docs/学生端组件与UI设计规范.md`：语义色与状态映射、中文字体栈/字号/行高、间距/圆角/阴影、布局宽度与断点、导航与操作条、组件变体、加载/空/错误/禁用状态、公式与长文本、触摸与键盘、动效/性能、答案展示边界、验收清单，并关联实际组件文件。
- 在 `AGENTS.md` 或项目 UI 约定中添加规范入口，避免后续实现另起一套。记录设计取舍及手动验证步骤。
- 对完整 diff 先简化审查再正确性审查，涉及学生答案/结果展示时补安全审查；发现当场修复或逐条记录理由。使用可用的项目 `code-review` 与相应安全指南；补齐其他工作流技能位置后遵循其纪律，不把未运行的检查记为通过。
- 运行真实命令，保存关键输出；小步提交，分支全绿后按仓库顺序合并 `v2` 再发 `main`。处理当时新增的并行改动，合并后重验必要检查。部署状态单独确认和报告，不能将本地完成等同线上已更新。

## 测试与验收

| 范围 | 必须验证的行为 |
| --- | --- |
| 首页 | 草稿优先与来源正确、继续时不创建新作答、无任务/无错题、局部失败、已完成作业回看、长名字 |
| 复习 | 0/1/5/10/39 题边界，课程/分组/tab 范围，不重复创建，失败重试，返回保留筛选 |
| 摘要 | 数学公式、代码运算符、表格、超长标题、未知指令，不泄露答案，不出现嵌套交互控件 |
| 答题 | 题号跳转/未答跳转、草稿恢复、题型输入和手写不丢失、离线/无权限/上传失败、交卷中防重复 |
| 结果 | 未公布不显示答案/对错计数、待批与最终判定清楚、错题/待批筛选、批改信息与重练入口 |
| 模态框 | 初始焦点、Tab 限制、Escape 关闭、关闭后焦点回到触发点、忙碌态 |
| 响应式 | 1366×900、1024×768、768×1024、iPad 分屏 640×900、390×844；主页面无横向溢出，导航不重叠，底栏不挡内容 |
| 阅读 | 表格/代码/长公式仅内容区域滚动，讲义锚点可见，放大文字及减少动态效果可用 |

## 确认点

确认按上述范围实施：优先继续学习、短批量复习、专注作答工作区和整套学生 UI 一致性；交付正式设计规范。该确认来自仓库 AGENTS 的要求：多步任务必须先出计划、待用户确认再实现。
