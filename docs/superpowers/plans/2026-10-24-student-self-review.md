## 行为与边界

1. 对照自评用于填空、解答、应用、找错等需要本人对照参考解答的题。判断/选择保留服务端自动判定；不把学生自评冒充自动成绩。
2. 必须本人、已提交、教师实际提供参考答案且已按当前规则公布。用户追加决定优先：仅有提示或解析、空白参考答案都不开放自评或逐题提交，该题随整卷交卷。普通逐题卷和 lesson 的已提交单题可以先自评，不要求整卷交卷；统一反馈须等整卷提交，截止公布须到截止。仅 AI 上下文带答案不构成自评授权。
3. 反馈/结果中提供「对了」「错了」「暂不判断」，明确「自评正确/自评错误/待自评」，允许修改。自评生效不等教师确认；自评本身不触发交卷、不解锁题目正文修改、不改原稿。
4. 建议有效判断顺序：教师判定 > 学生自评 > 既有自动判定；自评入口按服务端资格裁决，不允许通过自评改写客观题自动结果。教师判定存在时禁用自评写入；教师清除判定后回落自评，再回落历史自动判定。本人清除自评后恢复未判断或已有自动判定。
5. 交卷完成与是否已评独立。自评题未评记「待自评」，不加入教师必批队列；没有参考材料等必须教师处理的情况保留教师待处理，教师始终可主动改判。
6. 自评错误进入当前错题集合；修正为正确后更新当前错题状态，其他历史错误记录保留。未判断不算错；新自评不能重算或删除历史自动/教师事实。
7. 版本兼容策略已定：新协议普通卷与讲练的新冻结行使用 `self_review`，主观题停止字符串自动匹配；无工作流版本的旧客户端、历史冻结行使用 `legacy`，既有判定不重算。现有待评且已公布的主观题可补自评，不覆盖原自动判定事实。

## 文件范围与实现顺序

### 1. 契约、存储和判定单源

- `packages/contract/src/attempt.ts`、`grading.ts` 与现有 API 契约入口：先定义最小自评请求/响应、可自评资格、判断来源、待自评状态及版本/幂等字段；派生类型，不在前后端复制。
- `apps/server/src/db/schema.ts`：增加与冻结作答行关联的自评值、版本、时间与必要兼容标识，学生自评不写 teacherMark；通过 drizzle-kit 生成迁移。
- `packages/grading/src/grade.ts`、`validator-registry.ts` 与契约能力元数据：按版本策略处理新主观题不匹配，先补失败测试。判断、选择保持现有服务端自动判定。
- 提取有效判定与整卷汇总的公共服务，供交卷、单题提交、教师判定、自评共用；历史行按旧来源事实读取。

### 2. 自评服务与全站消费

- 新增学生 self-review 服务/路由与 API 客户端方法。服务端事务内重查归属、题目、提交事实、当前公布权限、参考可用性与教师判定，做版本 CAS 和 mutationId 幂等，再更新自评、finalCorrect 与必要汇总；迟到写入不能覆盖教师或其他设备。
- `attempt-service.ts`、逐题反馈和 lesson 投影：沿用现有释放裁决，只在授权响应中提供自评能力及来源；自评请求不能提前读答案。
- `pending-mark.ts`、`mark-response.ts`：分开待学生自评与教师待处理；教师清除后按统一优先级回落。进行中卷自评不能提前写整卷终态，交卷不覆盖已提交行自评。
- `wrong-questions.ts`、`wrong-practice.ts` 及历史/记录/统计消费者：共享有效判定与公布口径。纳入已经提交且允许读取的题级记录，不能简单删除 draft 条件而泄露未提交题。排序使用当题提交事实，重练快照引用保持原题原稿；核对来源结果跳转与归属校验。
- 新字段纳入备份恢复与历史升级测试；普通导出、统计与教师视图能区分判断来源。

### 3. 页面与交互

- 共享自评组件接入 `QuestionFeedback.tsx`、整卷结果和 lesson 反馈，只有一套提交逻辑。
- 展示参考解答和本人作答后提供对错选择；无参考材料明确说明，未评不阻塞继续下一题或离开。
- 保存成功更新当题反馈、结果汇总、错题与教师待处理缓存；保存失败保留操作现场，旧响应不得改写新题或新账号。
- 教师详情和错题本展示自评来源，不能把自评正确解释为客观能力或独立完成证明。

## 测试与验收

- 契约先行；服务与 UI 均先补失败测试，再实现。
- 服务测试：未登录、他人作答、未提交、未公布、参考缺失拒绝；普通逐题/lesson/统一反馈/截止公布；重复请求幂等、版本冲突、教师与自评竞争、教师清除回落、历史不重判。
- 普通学生响应与新增自评接口加 assertNoLeak：不能通过自评获取邻题答案、教师私注或内部凭据。AI 已拿答案不能绕过自评公布规则。
- 全流程：填空/手写题提交后已公布→对照自评错→不经教师确认入错题→改为对→当前错题集合更新；整卷草稿期间同样成立，剩余题无泄露。
- 验证单题自评后整卷交卷不覆盖判断或封存证据，最后一题仍可自动收尾，尚未自评不阻塞作答完成。
- 相关单测、类型检查、lint、构建、现存样例兼容；Chromium/WebKit E2E。按顺序做简化、正确性和安全审查；契约生成物与文档同步。
