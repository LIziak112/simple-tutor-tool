# 讲练一体（kind: lesson）与逐题即时反馈

> **状态（2026-10-13）：已实施完成并合入 v2。** 实施偏差与闸门结论见 `docs/审查报告/讲练一体/16-收尾与验收.md`；安全修复新增 error 码 `QUESTION_NESTED_IN_LESSON`。以下为实施时的原计划文本（决策依据留存）。

> 依据：docs/技术架构与实施方案.md §5.2/§5.3、docs/组件渲染核心精进方案.md:139（"即时反馈补端点"预留）、AGENTS.md 硬性规则。
> 固定边界：**只增不改**——practice/lecture/mixed 三种既有 kind 与既有作答链路行为零变化；讲练作答复用 attempt/responses 全套模型（冻结快照/草稿/提示/笔迹/笔记证据/订正/错题本/待批/记录），不新建作答表；判分只在服务端（规则 4），学生端未提交题的答案/详解/提示内容永不下发（规则 3，新端点全部配泄露测试）。
> 背景结论（2026-10-12 调查）：现 mixed = "讲练同源拆分"（导入时题块从讲义剔除、位置信息落库即丢），学生端只有整卷一次交卷；本方案新增第四种文档形态 `kind: lesson`（讲练页），题目原位保留、单题提交、当题即时释放对错与详解，服务课堂"讲一段练一题"场景。

## 范围枚举

- DSL：frontmatter `kind` 增 `lesson`（讲练页）；题目容器在 lesson 文档合法且**保留在讲义 markdown 原位**（开围栏注入最终题目 id）；规范三件套与 dsl-kit 同步重生成。
- 数据库：`lectures.kind`、`attempts.lecture_id`（+索引）、`responses.submitted_at` 三列，drizzle-kit 迁移。
- 服务端：讲练开卷（幂等 create-or-return）+ 单题提交判分 + 整卷收尾复用；学生讲义接口对 lesson 改安全投影（markdown 原文不再下发）；待批谓词、我的记录、教师批改队列收录 lesson 来源。
- 前端：学生讲练页（讲义段落 + 可作答题卡 + 提交后原地展开对错/参考答案/详解）；讲义/课程/资源库列表「讲练」徽标；教师编辑与预览的题块占位卡。
- 嵌入单元仍是一个普通练习单元：可在资源库查看、照常单独布置为作业（与 mixed 产物同权限）——教师可"课上讲练 + 课后整卷"两用，不额外设开关。
- 不做（v1 明确出范围）：授课投影/白板模式、教师端实时进度推送（学生端手动刷新即可）、讲练页限时、mixed 语义变更、存量 mixed 数据迁移（持原 md 重导为 lesson 即可，`imports.rawMd` 亦留档可追溯）。

## 关键设计（决策记录）

1. **学生端永远拿不到含题块的 markdown 原文**：题块内含 `- [x]` 正确标记、`:::solution`、`:::hint`，lesson 讲义的原文（教师域）与学生投影（blocks 切段 + 冻结题公开投影）物理分离，`splitLessonBlocks` 在服务端执行——这是本方案防泄露的根基，泄露矩阵测试钉死两类面（lesson 讲义详情 markdown 恒 null；start/submit 响应逐题白名单）。
2. **位置即 markdown（原文是真相的延伸）**：题目位置不建锚点表，讲义 markdown 原位保留题块 + 注入 id，渲染时切段对位；重导/reparse 天然幂等（id 已显式化）。教师重导后进行中卷的孤儿冻结题（不在当前 markdown）渲染于页尾「本次练习其余题目」区，不丢失。
3. **单题提交 = 既有交卷管线的单题化**：判分复用 grade 纯函数（精进方案:139 预留兑现），questionRevisionId CAS、笔记证据 CAS、hints/ink/events 全按 attemptId+questionId 复用；当题释放 = lesson 恒 on_submit 的题级粒度（attempt 级 answerRelease 不适用于 lesson 来源，契约注释明示）。
4. **不可自动判题（fill/solve 无标准答案）**：提交即释放解析（学生已锁定答案，看解析不影响判定），对错显示「待老师批改」，教师批改后 teacherMark/finalCorrect 随 released 下发——课堂节奏由"学生刷新"承载，v1 不做推送。
5. **整卷收尾与单题提交正交**："完成练习"= 对未提交题走既有 submit（未答判 false），已提交行不重判不重冻结；最后一题单题提交的事务内自动收尾，两路殊途同归到同一状态机（draft → submitted/graded）。
6. **待批谓词扩展而非新队列**：`submitted_at IS NOT NULL` 的行（仅 lesson 会产生）视同"已交"，pending-mark/mark-response 两处同改——教师批改界面零新增，lesson 卷自然进队。
7. **start 永不误开新卷**：幂等 create-or-return；restart 是显式独立动作（仅完成后）——刷新已完成讲练页不会消耗 attemptNo（对照 course 来源"再点开新卷"的行为差异在契约注释里写明）。
8. **id 注入只动存储形态不动原文语义**：注入发生在 parse 产物（讲义 markdown 与题目 sourceMd），`imports.rawMd` 留档仍为教师原稿；导出带 id，再导入稳定——是"只增"（新增属性、默认合法），符合规则 11。
