# 作答题卡与本题导出精进计划

状态：用户已确认并授权在独立分支实施，完成后合并到 v2；本轮不发布 main。

## 目标与范围

围绕学生作答中的题卡完成三项精进：题目资料与题号共用题头；更多菜单统一图标、布局与动作文案；导出本题时始终包含题面，并按实际内容加入标画、草稿或正式手写作答，方便把完整上下文交给 AI。

覆盖共用 AttemptQuestionCard 的作业、练习及讲练作答态；结果页 AI 复习包作为兼容性回归范围。交卷、订正封存、答案释放规则保持原有语义。

## 交互方案

### 1. 紧凑题头

- 题号、题型、作答状态、待检查标记和展开的难度/考点共用一条元信息流；右侧圈画、草稿/手写与更多入口保持稳定。
- 宽度足够时资料与题号同排，不再建立独立资料行；窄屏或长考点允许在同一元信息区域自然换行，避免强行挤压、截断或横向溢出。
- 保留默认收起资料的行为，菜单使用“显示题目资料 / 隐藏题目资料”；资料开合不能重挂题面或改变已有标画的坐标尺寸。

### 2. 更多菜单

建议顺序：

1. `ImageDown` 导出本题。
2. 分隔线。
3. `EyeOff / Eye` 隐藏标画 / 显示标画，仅在有笔迹时出现；没有笔迹时通过圈画入口开始绘制。
4. `Info` 显示题目资料 / 隐藏题目资料。
5. 分隔线。
6. `Flag / FlagOff` 标记待检查 / 取消待检查。

统一使用已有 Lucide 图标、Radix 菜单和语义颜色。每项保留至少 44px 触摸高度，图标固定 16px，文字左对齐；菜单宽度适应文案与视口。动作式文案配合正确菜单语义，避免只修改 role 模拟复选框。支持键盘方向键、Enter、Escape 与焦点返回。减弱运动偏好下不播放缩放动效；优先在本菜单局部处理，避免无关全站改动。

### 3. 作答中的“导出本题”

| 本题已有材料 | 导出内容 |
| --- | --- |
| 无笔迹 | 题面 |
| 只有标画 | 题面与标画 |
| 只有草稿 | 题面与草稿 |
| 标画与草稿 | 题面与标画、草稿 |
| 正式手写作答 | 题面、已有标画及正式手写作答 |

- 导出图按“题面（叠加已有标画）→ 草稿 / 手写作答”纵向排列；添加作业名、题号与材料区分，布局不受当前草稿左右/上下排列影响。
- 隐藏标画或收起草稿只改变屏幕显示，导出仍包含已有内容；草稿为空时不生成空白草稿区。
- 导出前沿用编辑协调器收笔并确认本机落盘，再固定矢量快照。读取失败与无稿必须分开；落盘失败、材料加载失败或快照不一致时明确报错并允许重试，不能默默遗漏草稿。
- 题面沿用公开底图与标画合成能力；草稿复用 render-note，正式手写复用 render-ink-snapshot。禁止截取活画布，预测点不进入导出。
- 纯题面导出也应可用，但要检查现有 prepareQuestionAnnotationBase 的写入行为，避免导出无标画题时意外建立或覆盖标画绑定。
- 旧底图使用其保存尺寸；不为了导出自动覆盖已有、绑定或封存底图。字体读取沿用已挂载导出副本的逻辑，失败显式提示。
- 普通题生成一张 PNG，下载与复制使用同一产物。长草稿触及安全画布预算时分页，每页携带题目上下文，并提供全部下载、逐页预览与逐页复制，不能只复制第一张却提示全部复制成功。
- 预览显示实际包含的材料；会话切换、退出页面、重试或迟到回执不得发布上一次的图片。

## 与 AI 复习包的边界

- 作答中的入口叫“导出本题”，用途是带题面和当前个人笔迹去询问 AI，不引入订正包、复习提示词或 ZIP 协议。
- 结果页保留“AI 复习包”及现有 ZIP、文字、附件与合成图出口，继续使用服务端授权投影与证据封存规则。
- 复用绘制、字体、PNG 校验、剪贴板和安全预算等底层能力，不把作答数据伪装成 ReviewPackPreviewData，不调用结果页接口绕过作答态权限。
- 作答导出不得加入未授权参考答案、详解或提示内容。题面使用公开投影，不复制包含提示或交互控件的整张题卡 DOM。

## 实施顺序与测试点

1. 用户确认后创建独立 `codex/` 分支；保留工作区现有未跟踪文件，避免带入无关内容。
2. 先补失败测试：资料同排、可见性反向文案、菜单图标一致、无标画仍可导出，以及上述材料组合。
3. 完成题头和菜单；视觉样式可豁免 TDD，行为变化必须先测。
4. 先写导出失败与材料完整性测试，再实现快照和合成：关闭/卸载的草稿、未上传本机稿、长稿分页、保存/读取失败、冲突提示、换账号中断、复制失败回落下载。冲突只能导出明确标示的当前本机版本，不能假称已解决跨设备冲突。
5. 增加安全回归：未交卷答案/详解/未授权提示不进入导出；既有 AI 复习包、结果页合成图与封存标画回归通过。
6. 浏览器验收宽屏、截图同宽、320px、200% 缩放，检查长考点、菜单键盘访问、隐藏标画后导出及真实 PNG 内容。Playwright 使用独立 8899/5199 与临时数据库，不复用用户 5173 作业。
7. 对完整 diff 依次执行简化、正确性审查与必要的安全审查，修复确认问题。
8. 执行相关单测、`pnpm test`、`pnpm typecheck`、`pnpm lint`、`pnpm build` 和相关 Chromium/WebKit E2E，记录真实输出。触及契约或 DSL 工具时运行要求的 schema/gen:spec 与样例回归。
9. 文档与手动验证步骤同步；小步提交且提交可构建、测试通过；分支全绿后按项目流程先合并 v2，再发 main。

## 验收标准

题目资料在空间足够时与题号同排；更多菜单每项都有一致图标且文案准确描述下一步动作；题面始终在导出中，已有标画、草稿或正式手写不因隐藏/收起而遗漏；导出失败可重试，复制与下载内容一致；既有 AI 复习包权限、封存与产物语义无回归。
