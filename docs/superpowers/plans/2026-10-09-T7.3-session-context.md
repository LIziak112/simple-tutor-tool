## 二、设计

### 新文件 `directives/session-context.tsx`（单一会话上下文，canonical）

- 类型迁入（canonical）：`DirectiveFillState`（原 `BlankAnswersState` 形状不变：values/onChange/disabled）、`DirectiveTelemetryAction`、`DirectiveTelemetryInfo`（名字不变零churn）。
- `DirectiveSessionState = { readonly fill: DirectiveFillState | null; readonly telemetry: ((event: DirectiveTelemetryInfo) => void) | null }`。
- `DirectiveSessionContext`：`createContext<DirectiveSessionState>` 默认值 `{ fill: null, telemetry: null }`（模块级常量）——无 Provider：fill null（空框下划线）、telemetry null（调用方空值保护=静默 no-op）。Context 对象**不导出**（避免再造裸 Context 镜像）。
- `DirectiveSessionProvider({ fill?, telemetry?, children })`：`useContext` 读外层，`fill !== undefined ? fill : outer.fill`（telemetry 同理）——**继承外层、仅覆盖显式提供的字段**；显式传 null 视为显式覆盖（保持 RichMarkdown 现行"内层恒定遮蔽外层遥测"语义）。
- Hooks（canonical）：`useDirectiveSession()`、`useDirectiveFill(): DirectiveFillState | null`、`useDirectiveTelemetry(): ((event) => void) | null`（返回形态与旧 hook 完全一致）。

### 兼容适配（旧导入路径保留）

- `BlankAnswersContext.tsx` → 纯适配：`export type BlankAnswersState = DirectiveFillState` + `BlankAnswersProvider` 内部委托 `<DirectiveSessionProvider fill={state}>`。**删除 `blankAnswersContext` 裸导出**（唯一消费方 Inline.tsx 迁新 hook；清单明文"不能把值形状不同的 Context 直接 re-export 为同一个对象"，无消费者即无必要适配）。
- `expand-context.ts` → 纯 shim：re-export `DirectiveTelemetryAction`/`DirectiveTelemetryInfo`/`useDirectiveTelemetry`（自 session-context）；保留 `DirectiveExpandInfo` + `useDirectiveExpand`（T2.10 兼容别名，读 canonical hook）。**删除 `DirectiveTelemetryContext` 裸导出**（唯一使用方 RichMarkdown 迁新 Provider）。
- **零改动文件（兼容承诺的活证据）**：`AttemptQuestionCard.tsx`（继续用 BlankAnswersProvider）、`Steps.tsx`（继续 import ./expand-context 的 useDirectiveTelemetry）、`StudentLectureViewPage.tsx`（类型经 shim re-export）、`telemetry.test.tsx`（经 RichMarkdown props，整文件不动即回归）。

### 迁移点

- `Inline.tsx`：`useContext(blankAnswersContext)` → `useDirectiveFill()`（清单"原始 useContext 调用点更新为新 hook"）。
- `RichMarkdown.tsx`：`DirectiveTelemetryContext.Provider value={telemetry}` → `<DirectiveSessionProvider telemetry={telemetry}>`（内层只覆盖 telemetry，fill 继承题卡外层）；onDirectiveExpand 兼容映射逻辑不动。

### 不预造（清单红线）

不新增 reportEvidence、提示请求、步骤答案、手写上传接口；不改事件字段（{name,index,action,step?} 原样）；不改判分/投影/学生端载荷。
