# T7.6 能力清单生成与分发实施计划（2026-10-09）

清单条目：docs/Phase7任务清单.md T7.6（依赖 T7.4 ✅、T7.5 ✅）；方案 §4.4「capabilities.json 与 gen:spec」。
目标：capabilities.json 从契约元数据生成，经 gen:spec / HTTP / MCP / dsl-kit 四路分发；只读契约，不导入服务端 grading 函数。

## 调查结论

- gen 链：根 `pnpm gen:spec` = contract export-schema（content/learning-pack/review-pack JSON Schema）→ md-dsl gen-spec（规范.md/提示词模板.md/学情分析提示词.md + dsl-kit 同步四件）→ bundle-standalone（tutor-lint.mjs 重打包）。
- gen.ts 属性表内省（unwrapAttr/typeName/formatLiteral/businessShape 过滤 id/class 通用底座）可复用为 JSON 数据源；AttrRow 现为直接拼字符串，需抽数据层。
- 分发面现状：契约 spec.ts 枚举四文件（rules/example/prompt/schema.json）→ 服务器 spec-files.ts 物理映射 + mtime 缓存 → 公开路由枚举校验；copy-spec.mjs 整目录拷 docs/dsl→dist/spec（完整性守卫列了四文件，可加）；MCP 13 工具（get_dsl_spec 复用 readSpecFile）。
- 测试挂点：md-dsl gen.test.ts 有「磁盘一致（CI diff 进程内预演）」与「dsl-kit 同步件逐字节一致」两 describe 可直接扩；server spec.test.ts 有五文件/404/SPEC_UNAVAILABLE 用例组；mcp.test.ts tools/list 13 个断言。
- directiveKindSchema 在 directives.ts（capability.ts 引用会成环：directives.ts 已依赖 capability.ts）——需把 kind schema 搬到 capability.ts 再由 directives.ts 引用/re-export（单一来源不重复定义）。
- JSON 落盘格式先例：`${JSON.stringify(x, null, 2)}\n`（content.json 尾换行实证）。

## 设计

1. **contract/src/capability.ts 增清单 schema**（方案 §4.4 形态，strict）：
   - `directiveKindSchema` 自 directives.ts 迁入（directives.ts 改为 import + re-export，既有导入零改动；避免反向依赖）；
   - `capabilityAttrSchema`（name/type/required/default?/description——与规范.md 属性表同列，数据同源自不必重复内省）；default 为原始值（string|number|boolean），非展示串；
   - `directiveCapabilityEntrySchema`（name/kind/attrs/capability——capability 可 null=未声明）；
   - `capabilitiesManifestSchema`（formatVersion: z.literal(1)、directives: min(1)、questionTypes: **复用 questionCapabilityBindingsSchema**）。
2. **md-dsl gen.ts 增 `renderCapabilitiesManifest(directives): string`**：formatVersion=1 + 全量指令（attrs 复用内省抽出的数据层、capability ?? null）+ questionTypes=questionCapabilityBindings（值导入 @tutor/contract，不导入 grading）；输出 2 空格 JSON + 尾换行。同步改 renderSpecMarkdown §七/头注配套文件清单，提及 schema/capabilities.json 与 capabilities 分发。
3. **gen-spec.ts**：outputs 增 docs/dsl/schema/capabilities.json；kitCopies 增 dsl-kit/capabilities.json（清单要求 kit 根路径，非 schema/ 子目录）。
4. **分发面一体改动**（同提交保证可构建——SpecFileName 枚举扩会破 Record 完备性）：
   - contract spec.ts：specFileNames + "capabilities.json"（application/json；注释四→五文件）；
   - server spec-files.ts：SPEC_PHYSICAL_PATHS + "capabilities.json" → "schema/capabilities.json"；
   - copy-spec.mjs：完整性守卫 + schema/capabilities.json（整目录拷贝天然带上新文件）；
   - MCP server.ts 增第 14 工具 `describe_capabilities`（readOnlyHint、inputSchema {}、复用 readSpecFile 原文返回）；description 写明「snapshot 描述既有采集形式、partial 仅词表保留未实现」防错误能力承诺。
5. **不做**：manifest 不加 notes/说明字段（方案 §4.4 枚举三字段为准，说明文案进 MCP 工具 description 与规范.md）；不给学生端新增消费面；不导出 manifest 进 schema:export（content/learning-pack/review-pack 覆盖面不变）。

## 测试点（先写失败测试再实现）
