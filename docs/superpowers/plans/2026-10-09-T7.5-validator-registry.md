# T7.5 服务端校验器注册表实施计划（2026-10-09）

清单条目：docs/Phase7任务清单.md T7.5（依赖 T7.4 ✅）；方案 §4.3「题型与校验器的桥接」。
目标：判分经契约题型表路由，**外部签名与输出零变化**（等价性以既有测试全量锁定）。

## 调查结论

- grade.ts 现状：两道闸（`answers === undefined` → null **优先级最高**；`answer === undefined` → unansweredCorrect 按型分派）+ 按型 switch 七函数；gradeFill 恒 null（2026-10-02 全人工）；gradeHandwritten 三型共享；纯函数无异常出口。
- 契约侧 `questionCapabilityBindings`（T7.4）：七型 validatorId 同名；fill=rubric，其余六型 exact。
- grade() 消费方只有两处（attempt-service.submitAttempt 交卷权威判分、db/backfill）——外部签名 `(question, answer?) => boolean | null` 不变即零改动。
- 交卷集成测试：student-attempts.test.ts「POST /api/student/attempts/:id/submit：判分与快照」describe 已覆盖全对即 graded、部分错/未答、scoreAuto 口径、finalCorrect 同步、空选 false、fill 恒 null、手写待批——路由改造后原样重跑即「自动判定与人工待批仍走原流程」的回归证明。
- grading 包 exports `"." → src/index.ts`，新文件自动纳入；dependencies 已含 @tutor/contract（本任务新增**值**导入 questionCapabilityBindings，不新增依赖）。
- vitest 按测试文件隔离模块图：validator-registry.test.ts 内自登记 t-test-* 前缀指令不污染其他文件（directives.registry.test.ts 同款前提）。
- 服务器 index.ts 首行装 installCrashHandlers（uncaughtException → stderr 横幅 + exit 1），其后抛错即得「启动期报开发错误」的友好崩溃路径；测试不导入 index.ts。

## 设计

1. **packages/grading/src/validator-registry.ts（新建）**
   - `GradeValidator = (question: Question, answer?: StudentAnswer) => boolean | null`（清单口径：接受 Question 与**可缺省** StudentAnswer）。
   - 机制：`registerValidator`（重复 validatorId 抛错）/ `getValidator` / `listValidatorIds`。
   - `assertValidatorCoverage()`：契约题型表全部 validatorId 必须有实现，缺失即 throw（开发错误；启动/测试期调用）。
   - **七个内置校验器 = grade.ts 既有各题型函数迁入**，签名扩展为可缺省 answer：judge/choice/multi 未作答 → false（D1 吸收进校验器，unansweredCorrect 删除）；handwritten 未作答 → null；fill 恒 null。判分算法一行不动（清单：三手写题型共享既有函数，不复制算法）。
   - 内置登记在**模块加载期**完成（与 contract/directives.ts 注册表同款模式）；函数与登记同文件自包含——单独导入本文件即得完备注册表，避免「grade.ts ↔ registry」循环导入。
2. **grade.ts（重写为三行路由）**
   - `answers === undefined` → null（无标准答案优先，保持第一闸）；
   - 题型表 `validation.shape !== "exact"`（rubric/unverifiable）→ null 恒人工；
   - 按 `validatorId` 查注册表执行；查不到兜底 null——正常路径**无异常**（完备性由启动/测试期检查保证，兜底不换判分、落人工待批）。
3. **grading/src/index.ts（桶）**：+ `assertValidatorCoverage` 导出（服务器启动用）；registerValidator 等机制 API 留文件内，测试直连路径导入。头注「只依赖 contract 的类型」更新为含 questionCapabilityBindings 值。
4. **apps/server/src/index.ts**：installCrashHandlers 之后调 `assertValidatorCoverage()`——注册遗漏即启动失败（stderr 横幅 + exit 1，不能静默换判分）。
5. **不做**（清单边界）：reason 载荷、部分得分、自动步骤判分、题目级策略、学生校验 API。

## 范围决策（可推翻）

- fill 校验器照常登记（七个内置登记项要求）但经 grade **不可达**（rubric 形态先行短路 null）——两路同 null；登记服务于「契约表引用全部有服务端实现」的一致性检查。
- 内置登记用字面 validatorId（非 `bindings.judge.validatorId` 取值）：可 grep、可读；与契约漂移由集合相等测试拦截（两种写法都不防语义交叉配错，字面量不更差）。
