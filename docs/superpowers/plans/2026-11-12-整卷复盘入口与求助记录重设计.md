# 整卷复盘入口、报告阅读与「求助记录」任务展示重设计

> 日期：2026-11-12 · 分支 `feat/v2-review-report-entry-ux` · 基点 `origin/v2` @ `8f375d31` · PR #121
> 权威行为回写：[需求规格 §8](../../学生端AI伴学/需求规格.md)、[技术实施方案 §4.4](../../学生端AI伴学/技术实施方案.md)、[约定/学生AI伴学](../../约定/学生AI伴学.md)。本文是本轮的设计与实施计划，落地后留作溯源。

## 1. 要解决的三个问题与根因

| 问题 | 现状根因（基点代码） |
| --- | --- |
| 发起入口难找 | 顶栏三入口同排（`AttemptResultView.tsx:646-673`）；「整体复盘」「批量复盘」用同一个 `ListChecks` 图标，文字在窄屏 `hidden sm:inline`（`AiAttemptReviewPanel.tsx:383-384`、`AiBatchReviewPanel.tsx:486-487`），手机上是两个一样的图标 |
| 报告出来后难找 | 只有汇总卡下的提示条，按钮固定写「查看」（`AiAttemptReviewHint.tsx:100`）；报告挤在 `max-w-lg` 的发起面板里与表单、任务行混排（`AiAttemptReviewPanel.tsx:254-311`）；面板一打开就取详情并记已读（`:158-191`），「查看进度」也会把报告记成已读 |
| 求助记录像「整卷复盘发了六次」 | 列表只读逐题任务表（`ai-queue-queries.ts:67-79` → `student-ai-queue.ts:903-909`），整卷任务不在列表里，但顶栏计数把两类任务加在一起（`student-ai-queue.ts:1162-1171`）；同一批逐题任务没有批次呈现，六行问题文本相同 |

线上案例对应：01:09:19 的一次「批量复盘」= 六条逐题任务（`ai_tasks`），01:11:55 的整卷任务 = 一条 `ai_attempt_review_tasks`。两者是两张表、两条创建路径，数据上本来就没有混装；混淆只发生在展示层。

## 2. 术语（学生界面统一）

| 名称 | 含义 | 任务数 |
| --- | --- | --- |
| 整卷复盘 | 对一次作答的全部题目做一次整体分析，产出一份报告 | 1 条整卷任务，0 条逐题任务 |
| 批量复盘（错题） | 学生另行勾选若干题，一次确认，每题一条独立任务 | 选中几题就几条逐题任务，归为一批 |
| 单题求助 | 在某道题旁发起的求助 | 1 条逐题任务 |

学生界面原「整体复盘」统一改称「整卷复盘」（与产品口径一致，并与「批量」拉开字面距离）。服务端错误文案、MCP 工具名与工具描述本轮不改（见 §9 未做项）。

## 3. 结果页顶栏：整卷复盘入口

一个有状态的主按钮（`AttemptReviewTopBarEntry`），**任何宽度都带文字**。状态由服务端事实单源派生（`attemptReviewEntryStateOf`），顶栏按钮与汇总卡下的提示条共用同一份状态与文案。

| 状态 | 判定（服务端事实） | 顶栏主按钮 | 样式 | 点击后 |
| --- | --- | --- | --- | --- |
| 不可用 | 未公布 / 预览被服务端拒绝 / 加载中 | 不显示 | — | — |
| 首次发起 | 无有效任务且预览放行 | 「整卷复盘」 | 实心主色 | 打开发起面板（预览 → 确认） |
| 等待领取 | 最新任务 `created` | 「整卷复盘 · 等待领取」 | 描边 | 打开进度面板（只读，可取消） |
| 处理中 | 最新任务 `claimed` | 「整卷复盘 · 处理中」 | 描边 | 同上 |
| 报告已出（未读） | `replied` 且 `openedAt` 为空 | 「查看整卷复盘报告」+「新」标 | 实心主色 | 打开报告阅读器 |
| 已读后再回来 | `replied` 且 `openedAt` 非空 | 「查看整卷复盘报告」 | 描边，常驻不消失 | 打开同一份报告 |
| 需处理 | `paused` / `failed` | 「整卷复盘 · 需处理」 | 描边 + 警示图标 | 打开进度面板（重试 / 取消） |

任务选取沿用既有规则 `pickAttemptReviewTask`：活动任务优先，其余取最近更新的一次；已取消 / 已归档不参与。

### 桌面（≥ 1024px）

顶栏一行：返回 · 卷名 · **整卷复盘主按钮** · 批量复盘 · 求助记录 · 随手记。主按钮排在动作组最前，是这一排里唯一的实心 / 描边文字按钮，其余保持幽灵按钮。

### 手机与窄屏（< 1024px）

顶栏两行：第一行不变（返回 · 卷名 · 图标组），**第二行整行就是整卷复盘主按钮**（< 640px 占满整行，640–1023px 靠右）。手机上最醒目的就是这一个带文字的整行按钮：首次发起与报告未读时是实心主色，其余状态是描边。不可用状态没有第二行，顶栏高度不变。顶栏高度由 `AttemptWorkspace` 实测写入 `--attempt-header-height`，题目定位偏移自动跟随。

「批量复盘」图标改为 `ListPlus`（加入队列），与「求助记录」的 `ListTodo` 不再两两相似；名称与行为不变。

### 讲练完成页

讲练完成页顶栏在「查看结果」旁增加同一个有状态入口（链接形态）：直接进入该次作答的结果页并打开对应的发起面板或报告，不必先点「查看结果」再找入口。

## 4. 报告阅读器

独立的阅读界面（`AttemptReviewReportReader`），不再与发起表单混排。

- 桌面：居中大弹窗（最大宽 768px，正文限 42rem 行宽）。
- 手机：全屏；顶部固定「整卷复盘报告 + 关闭」，中间唯一滚动区，底部固定「关闭，回到结果页」。正文 16px / 1.75。
- 头部身份行（确认作答轮次）：卷名 · 来源与第几次 · 交卷时间 · 覆盖题数 · 报告生成时间。
- 正文顺序：概览 → 计数 → 知识点发现 → 错误模式 → 表现说明 → 训练建议 → 局限说明。每条发现带「事实 / 假设」「置信度」标签；**证据题号是可点的题号片**，点了关闭阅读器并定位到结果页该题，顶栏按钮随时可再回到报告。
- 报告文本按纯文本渲染（外部 AI 产出按不可信输入处理，沿用现状）。

### 已读口径

只有阅读器在「详情接口成功返回（服务端已过当前交卷 / 公布 / 逐题教学授权门）+ 报告属于当前作答 + 正文已渲染」之后，才调用一次 `open` 动作。以下情况都不记已读：浏览求助记录、打开进度面板、详情被拒（撤回公布 / 授权变化 / 不存在）、报告与当前作答不符、报告尚未生成、重取失败但缓存里留有旧正文（按本轮结果判断，不显示旧正文）。`open` 失败不影响阅读，未读保持，下次打开再记。

## 5. 同一份报告：地址驱动

结果页地址参数 `aiReview`：

- `aiReview=<整卷任务 id>`：打开该任务的报告阅读器；
- `aiReview=panel`：打开发起 / 进度面板。

顶栏按钮、提示条、求助记录、讲练完成页都只做一件事——把地址设成上面两种之一；结果页只挂一个承载组件（`AttemptReviewHost`）按地址渲染。所以无论从哪进，打开的是同一个组件、同一个任务 id、同一次详情请求。

| 入口 | 行为 |
| --- | --- |
| 结果页顶栏 / 提示条 | 当前地址加 `aiReview`（replace，不堆历史） |
| 求助记录 · 本次练习的整卷任务（在结果页内） | 关抽屉，当前地址加 `aiReview` |
| 求助记录 · 其他练习的整卷任务，或当前页不是结果页 | 跳 `/s/attempts/<任务所属 attemptId>?aiReview=<id>&aiFrom=<来源位置>` |
| 讲练完成页 | 跳 `/s/attempts/<attemptId>?aiReview=…` |

### 确认作答轮次

1. 导航只用任务自己的 `attemptId`（attempt 级定位，不按题目或卷名反查，旧轮次不会跳到新轮次）。
2. 求助记录的整卷任务卡显示「卷名 · 来源 · 第 N 次 · 覆盖 N 题」（服务端来源摘要）。
3. 阅读器取到详情后核对 `task.attemptId` 与当前结果页 attempt 一致；不一致不显示正文、不记已读，给出「打开它所属的那次作答」的链接。
4. 阅读器头部身份行显示当前结果页的卷名、轮次与交卷时间。

从「我的记录」「历次记录」进入某次作答的结果页时，顶栏状态只查这个 attemptId 的整卷任务，不会串到别的轮次。

### 关闭后回哪里

关闭阅读器 = 去掉 `aiReview`，留在该次作答的结果页原滚动位置，焦点回到顶栏整卷复盘按钮。页面自己的返回键不变：从求助记录跨页进入的回 `aiFrom`（「返回原页面」），从「我的记录」进入的回 `returnTo`（「返回我的记录」），其余按来源回落地页。

## 6. 求助记录

面板分两段，类型标签用「图标 + 文字」，颜色只作辅助：

1. **整卷复盘**段：每条整卷任务一张卡——状态、发起时间、「卷名 · 来源 · 第 N 次 · 覆盖 N 题」；主操作按状态为「查看整卷复盘报告 / 查看进度 / 查看并处理」；取消、重试、归档按服务端 `allowedActions`。
2. **逐题求助**段：
   - **批量复盘错题**：同一次批量确认创建的逐题任务合成一张批次卡——标题「批量复盘错题 · 6 题」、发起时间、卷名与轮次、一句来源说明「同一次批量复盘创建，每题一条独立任务，不是整卷复盘」、进度汇总「待领取 6 · 处理中 0 · 已回复 0 …」、逐题状态片（第 1 题 待领取…）。展开后是逐题行，保留「回到本题 / 查看回复 / 取消 / 重试 / 归档」。批次有成员不在当前列表（已归档或未加载）时如实写「另有 N 题不在当前列表」。
   - **单题求助**：沿用现有单行卡，加「单题求助」类型标签。

线上案例在新界面里是：整卷复盘段 1 张卡（覆盖 27 题，报告已出）+ 逐题求助段 1 张批次卡（6 题，待领取 6）。顶栏「待处理」数字不变（仍是任务条数），但点开后能看到它由哪次操作产生。

浏览列表、展开批次、看进度都是只读，不调用任何详情或已读接口。

## 7. 数据与契约（契约优先，最小化）

### 7.1 批次来源：由既有幂等键派生，不加列不迁移

批量创建时每题任务的幂等键恒为 `<批次键>:<attemptId>:<questionId>`（`student-ai-batch.ts:132`）。据此：

- 服务端把「派生」与「反解」收敛到一处（`student-ai-shared.ts`：`batchItemMutationIdOf` / `batchKeyOfTask`），创建与列表共用；
- 逐题任务来源摘要新增 `batch: { id, taskCount, createdAt } | null`：`id` 是批次键的哈希（不回传幂等键原文），`taskCount` 是该批次任务总数（含已归档），`createdAt` 是批次内最早任务的创建时刻；单题求助为 `null`；
- 历史数据（含线上那六条）无需回填即可按批次呈现。

依据与边界：单题求助的幂等键是客户端随机 UUID，不会以 `:<attemptId>:<questionId>` 结尾；即便学生伪造幂等键，也只影响本人列表的分组显示。「仅重试失败项」换新批次键（`AiBatchReviewPanel.tsx:188`），重试的题自成一批。

### 7.2 整卷任务进列表

`GET /api/student/ai/attempt-reviews`：

- 查询新增 `archived=exclude|only`（与逐题列表同义；缺省 = 全部，既有调用不变）；
- 响应新增可选 `origins`（按任务 id 索引的作答级来源摘要：来源、第几次、标题、导航键、作答阶段），只在不带 `attemptId` 的账号范围列表返回。

作答级来源摘要抽成一个 schema（`aiAttemptOriginSummarySchema`），逐题来源摘要在其上扩展 `questionNo` 与 `batch`，两类列表共用同一套标题 / 轮次装配。

### 7.3 不变量

- 学生确认整卷复盘只写 `ai_attempt_review_tasks` 一行，不写 `ai_tasks`；批量复盘只写 `ai_tasks`。本轮补测试把这条钉住。
- 新增字段都是展示与定位元数据，不含题面、答案、解析、作答内容；两条列表路由补 `assertNoLeak` 与哨兵内容断言。
- 公布状态、教学授权、可用动作一律以服务端为准：入口显隐看预览接口，按钮看 `allowedActions`，报告正文看详情接口。

## 8. 交互流程

发起：结果页（或讲练完成页）点「整卷复盘」→ 面板显示范围与四类计数、发送字段说明，并写明「确认后只创建 1 条整卷任务，不会为每道题另建任务」→ 确认 → 顶栏变「整卷复盘 · 等待领取」，求助记录的整卷复盘段多一张卡。

等待：停留结果页时每 15 秒核对一次状态（沿用既有轮询，页面隐藏暂停）；点顶栏只看进度，可取消。

报告已出：顶栏变实心「查看整卷复盘报告」带「新」标 → 点开阅读器 → 详情通过校验并渲染正文后记已读 → 「新」标消失，按钮变描边并常驻。

回来再看：从顶栏、提示条、求助记录任一处点「查看整卷复盘报告」，都是同一地址同一份报告。

批量复盘：另一个入口，学生勾题后确认，按选中的题建任务；求助记录里显示为一张批次卡。

## 9. 未做项

- 服务端错误文案、MCP 工具名与描述里的「整体复盘」未改名（涉及外部 Agent 可见文本与既有断言，另行处理）。
- 「我的记录」「历次记录」列表行不显示整卷复盘状态（需要记录列表接口加字段）。
- 报告文本仍按纯文本显示，公式不渲染。
- 顶栏「待处理 / 新回复」数字不拆分整卷与逐题。
- 批次不物化为数据库列；若以后要跨作答批次或服务端批次级状态再做迁移。

## 10. 实施步骤

1. 契约：作答级来源摘要、批次来源、整卷列表 `archived` / `origins`（先测）。
2. 服务端：来源摘要抽出独立模块并加批次；整卷列表查询抽出并加归档过滤与来源；路由透传；泄露测试与任务条数不变量测试。
3. 前端状态与地址：入口状态模型、`aiReview` 承载组件、报告阅读器、发起 / 进度面板瘦身、提示条改用共享状态。
4. 前端顶栏：`ResultWorkspace` 主动作位、结果页 AI 动作组抽出（`AttemptResultView.tsx` 降到 1000 行以下并移出基线）。
5. 前端求助记录：分组模型、批次卡、整卷复盘段。
6. 讲练完成页入口；文档回写；验证与自审。
