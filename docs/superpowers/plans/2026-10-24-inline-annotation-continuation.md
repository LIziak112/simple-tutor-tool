# 更正圈画交付目标：跨设备原位呈现与继续编辑

## 用户纠正与验收目标

上一批将跨设备读取交付为只读弹窗，未恢复用户原有的连续编辑体验。用户明确要求：圈画直接呈现在原题卡上，换设备后继续增加笔迹、擦除、撤销并同步，不能以只读弹窗作为正常工作流。

本文件合并第二批「增强续写」与更正后的原位编辑目标。用户已确认合并推进；在 `codex/annotation-inline-continuation` 分支实施，沿用此前授权的验证后合并 v2、推送与云部署流程。

## 合并后的交付范围

- 正常路径：已有笔迹自动在原题卡出现，点击唯一圈画入口继续增写、擦除、撤销；保存、刷新和换设备后仍可续写。
- 新稿：增加有版本、有数量上限的公开几何与文本行框证据；字体语义等价、半像素内核基线差异可兼容，真实换行和偏移继续保护。
- 旧稿：保留原三项签名和底图身份；按原签名验证历史字体序列化。只有哈希且无法复现的记录，需由原设备核对后补齐证据，不能在接收设备直接猜测原布局。
- 恢复流程：保留保存时的逻辑宽度；重试或字体加载完成后重新校验，不能因首次失败永久退出原排版。续写复用现有本机落盘、冲突裁决和提交封存规则。

## 必须验证的闭环

- WebKit 创建并上传原圈画 → Chromium 自动在原题卡显示旧笔迹 → 增加一笔、橡皮删除、撤销 → 刷新 → WebKit 读回同一份更新后的记录。
- 反向重复上述闭环，检查底图身份、旧笔迹、版本与最终正文，不以笔数增加作为唯一成功证据。
- 同题草稿开合、左右/上下布局、缩放与横竖屏变化后，题面、笔迹和实际输入位置仍一致；无重复作答控件。
- 真实换行、题目版本变化、底图缺失、断网、本机保存失败和跨设备冲突不会造成错位书写或覆盖旧稿。
- 重点验收用户已有的第 1 题 1 笔和第 2 题 6 笔记录，而非只验证新建夹具；真实记录的编辑验证须保留可恢复备份。
- 自动测试与电脑线上验证之外，真实 iPad/Pencil 的续写、擦除和回读体验仍须单独确认。

## 定位记录与实施决策

1. 两份真实旧稿保存宽度均为 822 CSS 像素，原内容哈希命中 HTTP 的 FNV 历史算法。第二题在 Chromium/WebKit 的块几何一致，字体引号序列化不同；第一题还存在无法用现有哈希解释的公式几何差异，不能宣称已在电脑直接恢复。
2. 已复现 Chromium 的 `19.36px / 23.232px` 与 WebKit 的 `19.360001px / 23.232002px` 等价表示，以及半像素文字基线差异。新稿保存逐块与逐文本行框，不用完整原始 CSS 字符串哈希作为唯一兼容依据；固定 FNV 算法供 HTTP/HTTPS 与服务端共同核验。
3. 真 WebKit 测试另复现 `UnknownError: Error preparing Blob/File data to be stored in object store`，网络 Blob 与重新创建的 Blob 都会失败。圈画专用 IDB 适配改为原子保存 Uint8Array 字节，读取恢复 PNG Blob；不更换 KV 通用协议或删除旧库。
4. 历史证据只能补充一次，经已有 `/annotation/base` 接口在服务端核对旧哈希与当前公开投影；提交或封存记录不能借此解锁。不新增数据库列、依赖或学生端答案出口。读取/查看/导出不触发云端补充，仅显式原位编辑触发。
5. 用户已确认原 iPad 仍在使用。上线后须在原 iPad 打开同卷并点击圈画完成旧稿核验，再在电脑核对自动显示和续写；原设备仍不能核验时继续保稿调查，不强制覆盖旧布局。

## 手动验收步骤

1. 在 iPad 打开原有练习，等待材料恢复与保存状态正常，点击已有圈画；不重开练习、不清除网站数据。核对旧笔迹位置，续写一笔、橡皮删除并撤销，退出圈画后等待保存成功。
2. 电脑打开同卷，旧笔迹应自动出现在原题卡，点击圈画进入原位编辑；核对没有弹出原稿查看、没有新增第二套答案控件。增加一笔并保存，刷新后检查。
3. 回 iPad 刷新并检查电脑新增笔迹；再切换横竖屏、放大题面、开合草稿与左右/上下布局，核对旧笔迹、题面和实际落笔位置。
4. 对确实改变排版、缺少历史布局或已提交/封存的材料，只能保留原稿查看，不应在另一排版上开放书写；断网及保存失败须保留现场和待传记录。

## 线上真实记录补充：非整数系统缩放
