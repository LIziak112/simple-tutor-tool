## 3. 实施与提交顺序

1. **基线**：确认运行环境，执行 lint/typecheck/test/build；区分既有问题与本任务问题。两份阶段文档纳入版本控制时检查本地引用，必要的归档依赖逐项处理，不带入研究材料或无关技能。
2. **TDD**：先写失败测试并记录红灯。集合正向测试可能已通过，但白名单纯函数及原型名称降级应能暴露当前缺口。红灯状态不提交。
3. **实现**：在 sanitize 内通过 ZodObject 的公开 shape 提取键，合并四个宿主语义属性并去重；类型引用 RegisteredDirective，不手写契约。组件映射只保留主名；宿主查注册表和自有键后渲染，失败走现有 UnknownDirective。
4. **回归**：新增用例转绿，既有 Markdown、遥测、样例与完整单测通过，类型与构建通过；测试和实现一起形成可构建提交。
5. **质量闸门**：对完整 diff 先做简化/复用审查，再做正确性审查，检查清洗安全边界；若实际改动触及学生载荷或答案，追加安全审查。确认的发现修复并重新验证受影响检查。
6. **收尾**：记录命令与验收证据，同步进度与方案状态，小步提交；分支和既有 CI 全绿后合并 v2。发 main 仍遵守现有发布闸门，不把创建分支当作发布许可。

不新增依赖、契约字段、指令、数据库迁移或通用注册框架。本任务正常不改变规范产物；若实施中确需修改契约/注册表，则先补对应契约测试并运行 schema:export/gen:spec。

## 4. 测试点

1. 主名集合与映射键集合相等；局部映射删一项或多一项时，复用同一个断言产生失败，最终测试以捕获该失败的方式通过。
2. 别名归一命中主名组件；当前生产注册表没有别名，使用局部 fixture 或模块 mock，不污染真实全局注册表。
3. 白名单等于全部 schema 属性键与四个宿主键的并集；构造纯函数输入新增/删除属性，结果相应变化，重复键仅出现一次。
4. constructor/toString/__proto__ 等未注册名称不能借原型链命中组件。对 remark 不识别为指令的名字，直接构造宿主输入测试，不把普通文本显示误当降级通过。
5. 三种宿主的未知名称均保留正文，合法既有指令仍正常渲染。
6. 现有 XSS、KaTeX、图片/图形、折叠/揭晓、填空、遥测与样例测试通过；不扩大白名单到普通 DOM 标签，不改变危险协议拦截。
