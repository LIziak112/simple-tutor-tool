# 一期 1.5：门户注册表、统一登录导航与个人端缺口

基点：`d02f90ab`（origin/v2），独立树 `simple-tutor-tool-wt-session-portals`，草稿 PR #161。依据原计划 §2.4、§3.1；D8 按建议执行，个人端不提供作业。

## 范围与职责

- 统一登记学生、教师、个人、管理员门户的登录与首页地址；管理员复用教师登录。
- 七个登录相关页面的正常、加载、失败与关闭注册状态均使用同一个登录壳，产品名回首页，底部切换门户。
- 首页始终可达，显示各端登录身份；布局提供不退出会话的「切换身份」。学生已登录访问密码登录页仍直接进入学习页。
- 共用守卫处理等待、网络错误、未登录与安全回跳地址；管理员权限检查保留。
- 单一能力表控制不同门户、账号类型的作业、成员、连接 AI 等入口。个人端课程创建自动添加本人，成员候选只显示名字，学习首页和课程页不显示作业。
- 不改作答生命周期、设备、随笔与学习上下文；不新增接口或数据库字段，不改变现有契约。门户表和能力表是前端静态配置。

## 实施与 TDD

1. 先增加门户/安全回跳、守卫、统一壳行为测试，运行并记录失败；增加个人课程创建失败测试。
2. 实现门户注册表、能力表、登录壳和统一守卫。复用现有会话缓存，不引入第三套身份。
3. 七页接壳，成功登录消费经校验的回跳地址；登录页之间跳转保留回跳。三个布局接守卫并提供切换身份。
4. 首页按注册表展示可进入身份（含管理员），个人端三处作业入口用能力表收口；成员窗口隐藏个人内部登录名；课程写入同步失效学习端课程缓存，保证视角切换后立即可见。
5. `content-service.ts` 已超过历史规模基线，先按课程写入职责把创建/更新/删除抽到独立 `course-write.ts`，旧导出保持兼容，再在课程创建事务里添加个人绑定学习者；基线只降不升。
6. 定点红绿测试后运行仓库选测、受影响类型检查、格式/规模检查、生成一致性（仅在触发规则时）。新增浏览器用例覆盖七页返回首页/切换、未登录回跳、学生首页三次点击到教师登录、切换身份保留会话、个人课程和作业缺口。

## 验收与限制

- 有效回跳限定对应门户的同源站内路径，拒绝外链、双斜线、反斜线和登录页循环（含大小写、编码变体）；不合法或跨门户地址回默认页。
- 成员自动添加与课程写入同事务；班级课程保持不自动加成员。
- 用 Playwright Chromium 实跑桌面及 iPad 模拟回归；模拟器不等于真实 iPad Safari 或主屏幕应用，真机留主会话验收。
- 独立审查由主会话执行，交接完整 SHA、写集、验证命令与结果、未覆盖项。子代理不 push、不 merge、不外发。
