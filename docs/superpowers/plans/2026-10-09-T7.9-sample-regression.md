## 3. 实施步骤与提交

1. 重读 AGENTS、方案和 T7.9 条目，确认 T7.1 已验收；检查干净任务分支与现存样例。
2. 先写失败测试：向临时样例目录新增讲义与纯练习文件应被自动发现；删除真实 step 节点但保留 steps 时精确覆盖应失败；代码块之外的说明文字不能填补覆盖。
3. 实现测试辅助函数，统一稳定排序与样例来源。辅助函数读取完整样例的 AST code 节点（lang=markdown），不把说明正文交给 DSL 解析；指令收集复用现有 processor/blank 转换与注册表别名归一。
4. 增加所有 `.md` 的 parseDocument 与契约回归。临时 fixture 使用独立临时目录，测试结束清理；不改历史样例语义。
5. 目录一致性测试改为共用自动发现；每篇已解析讲义仍经过真实 RichMarkdown DOM 和原有编号/结构对账。
6. 对每道练习/混合题，按既有公共契约构造 QuestionPublic，stemMd 使用 studentStemMd；渲染真实题卡，检查必要题面、公式、填空空位和选项。题面测试不启动笔迹上传/网络；手写题的笔迹全链沿用既有测试与 E2E。
7. 定向测试转绿，依次做 simplify/正确性审查，运行 lint/typecheck/test/build、既有双引擎 E2E 和 CI。无需修改完整样例；若覆盖确有遗漏才增补样例并运行 gen:spec，同步 dsl-kit 后复查无漂移。
8. 按文件范围小步提交，记录逐条验收，全部通过后合并 v2；main 遵守现有发布闸门。

## 4. 测试点

- 自动发现全部 `.md`，新增纯练习与讲义无需手改文件名；嵌套目录如存在同样发现，结果排序稳定，空目录与无 Markdown 样例块明确失败。
- 每份文档均解析，输出通过 ParsedDocument 契约且没有 error；现存样例维持既有零 issue 约定。
- 练习/讲义/混合三种 kind 均被实际覆盖，纯练习不能因 lectures 为空而跳过题目渲染。
- 完整样例主名集合覆盖 listDirectives 的完整主名集合，不永久写死数量。说明文字、代码块字符串和 step/steps、col/columns 的子串不能伪造覆盖；blank 语法糖必须转成 AST 指令后计入。
- 删掉 step 节点的局部 fixture 使同一个覆盖断言失败，最终测试捕获该失败并通过；不保留故意失败用例。
- 已有练习解析快照继续通过；目录、编号、正式空位和选项行为不变，投影后的题干不携带标准答案标记。不以全文 HTML 快照代替必要语义检查。

## 5. 验收

1. 全部样例文件以及完整样例的实际 Markdown 块进入解析/适用渲染，三种 kind 有证据；新文件自动纳入。
2. 精确指令覆盖与反向 fixture 通过；目录一致性继续通过。
3. lint/typecheck/test/build、本地 E2E 和既有 CI 全绿；需要生成的产物提交且二跑无漂移。
4. 不增加生产框架或依赖。无清单要求的用户人工验收项，报告提供可选教师预览走查方法。
