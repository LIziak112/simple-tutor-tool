## 恢复任务时先读

**目标**是让教师回到同一题的某个时刻，同时看到题干圈画、草稿、当时的作答状态和已呈现的提示。学生可以先圈画再写草稿，中途回题面继续圈画。所有动作按实际顺序进入**一个播放器、一条时间轴**。两个画布继续使用各自的坐标、底图和撤销栈。

**当前状态**为用户已授权实施。代码在独立工作区的分支 `codex/question-process-replay` 上，基线为 `v2` 的 `f4c1b7f6`。实现提交为 `5c78d1e9`（契约和服务端）及 `24de182f`（采集、播放器和浏览器测试）。继续完成下方验收，检查通过后再按 [AGENTS.md](../../../AGENTS.md) 的顺序合并。

**续做入口**是 A06 浏览器增强回归和 A07 iPad 真机。首轮 Chromium／WebKit 已跑通十种题型的圈画、作答变化及教师回放。增强回归加了逐题纸面操作、交卷后正式笔迹、提示前后及擦改画面断言，结果见下方。iPad Safari 已打开独立测试库的「iPad 回放验收 → 单题回放十题验收」，学生已登录并开启过程记录。

**首版范围**是普通练习的题干圈画、题目草稿、各题型的作答值和站内提示。建议先以 `course` 普通课程练习做试点，按现行 `questionTypeSchema` 逐题型验收。正式手写答案在本轮做兼容验收，逐笔过程采集留在后续批次。共享材料圈画、讲练、错题重练和订正也留在后续批次。新增过程数据的首版用途是教师复核。

必读 [手写与同步](../../约定/手写与同步.md)、[学生作答与讲练](../../约定/学生作答与讲练.md)、[圈画架构与维护指南](../../圈画架构与维护指南.md)、[题目模型与练习适配](../../题目模型与练习适配/)和[工程验证说明](../../约定/工程验证说明.md)。

## 实施清单

- [ ] **T01 · 契约与回放模型。** 在 `packages/contract/src/question-process.ts` 定义版本化 Zod 契约。每条事件绑定作答、冻结题目版本、采集段、段内序号和单调时间。圈画、草稿、作答值和提示共用同一题内排序。采集开始及刷新恢复时，保存实际恢复出的起始状态，含当前题可用的画布、圈画底图身份、当前作答值及已呈现的提示。旧笔迹标为「录制前已有」。先写回放纯函数的失败测试，锁定任一时刻的状态、同刻顺序及缺段降级。
- [x] **T02 · 手写操作采集。** 在两条手写链共用的实际提交位置接入录制器。复用现有笔画 ID、已采样点、笔内时间和输入来源。收笔记录起止时间和正常／取消／失焦等结束原因。每次有效擦除、清空、撤销和重做都追加记录，保留实际移除与恢复的笔画 ID 及恢复顺序。加载稿件只建立起始状态。回放应用记录的变更，不重新计算橡皮碰撞，也不靠最终删除记录倒推中间过程。[草稿画笔](../../../apps/web/src/features/ink/engine/atrament-adapter.ts) · [圈画表面](../../../apps/web/src/features/annotation/annotation-surface.ts) · [InkStore](../../../apps/web/src/features/ink/engine/history.ts)
- [ ] **T03 · 题目操作采集。** 在受控答案入口复用 `StudentAnswer`，记录各题型有效的作答变化及清空，选项、空位、配对和排序使用冻结题目的身份。文本记录已确认的编辑值，覆盖输入法提交与失焦，不采集按键或输入法中间状态。现有随保存触发的 `answer_change` 继续供学情使用。提示按请求 ID 关联请求、成功／失败及实际呈现，提示内容进入可见区域才记呈现。仅记录提示序号与版本引用，恢复时已存在的提示进入起始状态。提示呈现只能证明界面展示过。[会话入口](../../../apps/web/src/features/attempt/AttemptSession.tsx) · [答案入口](../../../apps/web/src/features/attempt/use-attempt-answers.ts) · [提示面板](../../../apps/web/src/features/attempt/HintPanel.tsx)
- [ ] **T04 · 过程落盘与续传。** 在作答会话接单题录制器，复用 IndexedDB 基础设施，过程批次独立落盘并等待服务端幂等确认。重发相同批次只确认一次，服务端按采集段和序号识别缺口。刷新后续传已落盘的旧段，再按实际恢复状态开新段。跨设备冲突沿用现有稿件裁决，无法确定先后的片段分别展示。过程保存失败与当前稿保存状态分开。先定稿账号切换、逐题或整卷提交时的收尾及迟到批次规则，任何过程写入均不得修改已封存稿。新增存储走 Drizzle 迁移。[草稿同步](../../../apps/web/src/features/notes/note-sync.ts) · [圈画同步](../../../apps/web/src/features/annotation/annotation-sync.ts) · [服务端表结构](../../../apps/server/src/db/schema.ts)
- [x] **T05 · 教师单题播放器。** 在教师卷详情的题卡加「过程回放」，按需加载。播放、拖动和事件跳转共用同一播放头，同时更新题面圈画、草稿、当时作答与提示。圈画用保存的底图和同域矢量，答案控件位置未验证时在题面旁显示只读的「当时作答」。没有底图时复用冻结题面的只读作答视图。只显示学生当时的作答值，参考答案和对错判定不进入回放视图。缺段、坏底图和旧卷无录制均明确标记。[教师卷详情](../../../apps/web/src/pages/teacher/AttemptDetailPage.tsx) · [现有整卷复现](../../../apps/web/src/features/teacher-attempts/AttemptReplay.tsx)
- [x] **T06 · 试点与数据生命周期。** 默认关闭，启用前告知学生擦掉的内容仍可能出现在回放里。试点保留期建议 30 天，作为上线前待确认项。学生写入验证本人、试点范围和冻结题目，教师读取沿用作答归属检查。提供删除过程记录的入口，覆盖新增过程及其快照并阻止迟到批次恢复已删除记录。界面分别说明清空画布、删除过程和已有作答证据的含义。新增过程数据在本批只走教师回放投影。

## 验收清单

- [ ] **A01 · 同题交替操作。** 圈画题干 → 选 B → 写草稿 → 回题面再圈一处 → 改选 C。逐个跳转节点，三个区域都反映同一时刻。补多选增删和清空。刷新恢复不产生新的选项变化。
- [ ] **A02 · 擦除与撤销。** 写 `2x−3=8` → 擦掉 → 撤销恢复 → 重做擦掉 → 写 `2x−6=8`。逐帧核对原笔画出现、消失、恢复、再消失。题干圈画也执行擦除和撤销，确认不改变草稿。再测清空后撤销、空撤销不产事件及异常收笔标记。
- [ ] **A03 · 断网恢复。** 完成初次恢复后断网，交替圈画、写草稿、擦除和改选。等待本机落盘后刷新，再联网。两张当前稿都能恢复，回放顺序正确，丢确认后的重传不产生重复。模拟批次缺失及本机写入失败，回放标出缺口，作答仍沿原保稿流程。
- [ ] **A04 · 提示前后。** 写错 → 请求提示 → 延迟响应 → 提示呈现 → 修改。在请求后、呈现前查看当时状态，随后跳到呈现和修改节点。补请求失败、响应前切题以及恢复时已有提示，确保没有虚假的呈现事件。
- [ ] **A05 · 权限与兼容。** 验证换账号、同题双设备冲突、提交后迟到批次、删除后重传、越权读取、旧卷、旧底图和坏底图。回放明确区分已记录和未知区间，原稿与封存证据按原规则处理。学生端及未授权出口不得获得题目答案、未公开提示或他人数据。
- [ ] **A06 · 浏览器全题型。** 用同一份普通课程练习夹具，在 Chromium 和 WebKit 逐项跑下表。覆盖学生端作答、保存和教师端拖动回放。执行受影响单测、类型检查、lint 和 E2E 选测，按脚本的升级规则执行。契约改动跑 `pnpm gen:spec`，数据库迁移用 `pnpm db:generate`。记录长卷首屏、录制开启后的书写表现与存储上限。
- [ ] **A07 · iPad Safari 真机全题型。** 实现完成后由用户连接并解锁 iPad，按调试指南确认能打开本次测试环境。用同一份夹具逐题操作，在 Safari 上用 Apple Pencil 实写、擦除、撤销，手指滚动和操作答案控件，再到教师端逐项核对回放。额外实测两张画布往返、横竖屏切换、提示出现前后、断网后刷新并联网补传。记录设备、iPadOS、浏览器、构建提交和每题结果，浏览器模拟结果与真机结果分别登记。专题行为落地后更新相关约定和项目进度表。[iPad 真机调试](../../iPad真机调试.md)

### 验收记录（2026-11-07）

- Chromium、WebKit 均通过十题主链和增强回归（各 1 条十题场景）。逐题使用可用纸面、修改作答，交卷后核对正式手写证据；判断题另验证原稿已同步后断网、擦除、撤销／重做、过程刷新补传和提示呈现前后。表中「通过」指这条浏览器主链，未覆盖各题型的所有清空、输入法等边界。
- 真机为已连接的 iPad，Safari 报告版本 17.8.1；验收分支 `codex/question-process-replay` 的本地开发版本。教师端已打开判断题真实记录，核对原题底图（2044 × 192）及相邻擦除节点：草稿 5 → 4 笔，题面保持 2 笔。服务端记录确认该题两层有 `pointer: pen`，另收到了多选的双层 Pencil 与作答变化、填空和配对的圈画与作答，以及排序变化。这些是分项证据，全题型尚未验收。
- 真机续测：逐题按矩阵补齐。在第 1 题选「错」，点「给我一点提示」并滚动到提示出现；用 Pencil 再写一笔、擦掉、撤销，回到题面改选「对」。教师依次点作答、请求提示、已呈现提示、草稿擦除、草稿撤销，核对两层画面和答题值。横竖屏各往返一次。断网测试等过程显示待同步后再回到练习，并在恢复网络后核对原稿与过程分别同步。不要用桌面 WebKit 的指针模拟替代真机结果。
- 当前 iPad 测试地址为局域网 HTTP，适合验证已打开页面的断网书写及恢复网络后补传。若要在仍离线时重新打开应用外壳，另用 iPad 已信任的 HTTPS/PWA 环境验收。
