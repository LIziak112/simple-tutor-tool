# 圈画统一整题缩放实施计划

日期：2026-11-05。状态：待用户审阅；本轮仅编制计划，不修改生产实现、不提交或合并代码。

方向已由用户明确：移除图片主视图、图片上的控件恢复以及「进入作答／返回原稿」，统一使用真实题面整题缩放。排版小差异接受 10px，本计划不再使用 0.75px 作为正常作答的准入标准。

依据：[固定逻辑题面跨设备实测](../../审查报告/固定逻辑题面跨设备实测-20261105.md)、当前圈画及作答代码、根 AGENTS.md 和相关专题约定。调研时工作目录已有其他任务的未提交修改；本轮仅新增本计划，不移动分支、不修改或收纳其他任务文件。实施前重新核实 v2 基线和届时实际 diff。

## 1. 交付行为与范围

同一道题只有一个真实、可操作的题面。圈画后冻结其逻辑排版，其他设备按同一逻辑宽高恢复；题面、选项、输入框和笔迹按相同比例显示。选择、填写、打开草稿、分栏、旋转和切题返回，不隐藏已有笔迹、不切换为另一份题面。输入框值、选中状态和答案保存只有一份。

所有正常入口均采用此规则：课程练习、作业、单题/列表、讲练嵌入题、订正工作台、学生结果回看、教师批改回看。纯资源预览沿用正常题面，但不得在带圈画历史入口中另走图片替换。

明确移除：

1. 保存 PNG 作为题卡背景或主视图、下载原图后替换真实题面的显示路线。
2. 按 PNG 槽位坐标再叠一套真实输入控件的生产路线，包括 FrozenFillControls 和相关能力分发。
3. answerMode、annotation-answer-view、「进入作答／返回原稿」以及同义改名的双视图流程。
4. 以图片解码成功作为真实题面可以显示或接受正常答案输入的条件。
5. 结果页/教师回看通过隐藏真实正文、显示 AnnotationOriginal 替代它的正常路线。

PNG 资产、既有布局、笔迹及封存证据继续保留。PNG 可用于存证、文件导出和旧稿恢复时的校对，不能再作为上述入口的图片主视图或隐蔽兜底。题目本身合法的图片、图表、公式照常展示，不属于本次移除对象。

## 2. 10px 容差的精确定义

### 2.1 来源与新口径

历史 0.75px 来自 2026-10-24 的兼容实现提交 c35fae6b，逐块、逐文本行比较及半像素差异处理是当时的工程策略；相关记录见旧原位续写计划。它不是本次用户要求的使用标准。本次以用户明确接受的 10px 为准。

10px 定义为保存题面在 100% 显示时的逻辑 CSS px，包含 10px 边界；先去掉显示缩放与设备像素比再比较。若 PNG 像素比为 2，对应 20 个底图像素；不直接比较截图物理像素，不把 px 固定换算成毫米。容差不做用户设置项。

- 同一公开冻结题目、同一排版基准下，匹配区域最大边界偏差 ≤10px，正常显示、续画和作答；不告警、不要求用户确认、不换视图。
- 使用边界 left/top/right/bottom 的最大绝对差，避免分别容许 x 和 width 各偏 10px 后，右边累计偏到 20px。
- 比较始终对照最初保存基准，不以上一次目标设备排版为新基准，防止多次跨端各漂移几像素后累积。
- 笔迹 points、笔宽和原始坐标域不因容差重算或覆盖。2px 测量差不触发重投影，也不产生数据迁移。
- 字体 CSS 字符串、Range 返回的碎片数量或序列化小数不同，不单独判失败；比较对应语义区域及可核对的行区间，不能把辅助测量碎片差异当成题目内容变化。
- 区域匹配依赖冻结题、选项/槽位 ID、顺序与节点证据；不能按最近距离把 A 项匹配到 B 项。文字像素一致不再是交付要求。

### 2.2 与容差分开的约束

题目/账号/作答/阶段身份、封存状态、文档协议、坐标域、PNG 资产身份和服务端权限仍按各自契约校验。不同题目恰好只差 2px 也不能叠画；AnnotationDoc 的 baseWidth/baseHeight 与所属存储基准仍须精确对应，不能将其改成 ±10px。

真实缺项、选项次序变化、资源未加载、损坏数据不属于显示误差。可匹配区域发生 >10px 偏差时，先检查排版版本、资源、断点和真实重排；既有成功显示的工作区保留原 DOM 与笔迹，不在一次晚到测量中拆掉它。首次恢复确实不能成立时就地报错保稿，不重冻、不清空、不自动回退图片。

10px 是允许的小幅显示差异，并不授权伪造缺失的历史排版证据。无法判断的旧稿按第 6 节处理。

### 2.3 必须先补的测试

0、0.75、2、9.999、10 均接受，10.001 拒绝；覆盖正负偏差、四边、不同显示比例与 DPR。再加同几何异题/异账号/异底图、区域顺序变化、缺项、未知协议、逐次漂移不累积等反例。将实测那份「字体元数据相同、文字框差 2px」做成永久回归夹具。

## 3. 统一工作区与渲染资源

### 3.1 共用真实题面框架

新增或抽取 QuestionAnnotationFrame，作答、订正和只读回看共用。职责限定为逻辑框尺寸、排版就绪、等比显示、容差测量及墨层定位，不管理判分、答案公布或另建答案状态。

结构沿用已经实测的旧 Overlay 方式：真实题面固定逻辑宽高并整体 transform；墨层作为同一显示框内的兄弟层，使用相同显示宽高和比例。现有 Atrament 换算依赖 offsetWidth，不能直接把 canvas 塞进 transform 后代造成二次缩放。保持原矢量坐标域，复用现有笔迹引擎、整笔橡皮和撤销历史。

无原稿时使用正常真实题面；首次显式圈画前完成字体/图片/公式就绪、公开导出副本和几何核对。建立基准后，逻辑宽高固定；窗口、分栏、AI 面板和草稿只改变显示比例。异步字体/图片不能在已落笔后悄悄把下方内容推移。

被动显示时墨层 pointer-events 为 none，原生选项和输入框正常接收事件。圈画态复用现有笔写/手指滚动偏好，不能让笔落到选项上时意外选答案。退出圈画只收笔并可靠落盘，笔迹和题面不卸载、不替换；工具栏用「完成标画」。点击控件、Tab/键盘接管、切题和纸面切换统一经过既有编辑器协调器，保存失败不能把事件放行成未保存就离开。

缩小时保留 1:1 放大和横向浏览，避免 44px 控件一起缩成过小触控目标。框内不按屏幕断点重排，题卡外部仍可响应式布局。上下/左右草稿、材料分栏、单题/列表保持现有偏好和阅读锚点。

### 3.2 排版版本与资源固定

保存/引用渲染配置版本，内容包括题面样式版本、字体与 KaTeX 资源版本、逻辑尺寸和会影响框内几何的公开交互状态。题面样式限定在工作区作用域，不通过全站 CSS 覆盖影响教师后台或无圈画页面。

现有 KaTeX 和 Geist 已本地打包，先固定其资源和排版规则；不重复打包、不引入 CDN，也不把全部字体字节塞进每一笔记录。明确中文存在系统字体回退，先用 10px 标准实测；不为已经可用的 2px 差异强行引入大字库。若回退确实导致 >10px 的差异，再评估有可自托管许可、分片体积可接受的中文字体，作为新渲染配置的一部分验证。不得给旧稿突然换字体。

历史 styleVersion=1 使用对应兼容样式；新样式版本独立。配对/排序中的 sm:flex-row 等视口规则改为源逻辑框决定的稳定布局。公开 fold/steps、宽表和图表等会改变几何的内容逐项登记：圈画时所用公开状态须可重现，不能把隐藏答案/提示展开进公开底图；作答反馈、解锁提示与参考答案放在冻结题面之外。

## 4. 十种题型的实施行为

| 题型 | 唯一真实控件与几何要求 | 专项验证 |
| --- | --- | --- |
| judge | 复用原生对/错控件，选择只改变状态 | false 是有效答案，选择后题面及笔迹保留 |
| choice | 复用原生 radio 和完整选项行，固定顺序和布局 | 长选项、公式、图片选项、键盘与触摸 |
| multi | 复用 checkbox，多选不排序答案数组 | 勾选/取消/全清，不改变选项行高 |
| fill | 复用真实 BlankDirective，不根据旧 PNG.controls 重新造控件 | 多空、长值、中文 IME、焦点、只读、缩放，不撑开冻结空位 |
| solve | 正常题面与既有正式手写/最终答案通道共存 | 草稿不是正式答案，纸面开合/全屏不丢稿 |
| apply | 同 solve | 中文/数学最终答案和正式笔迹的保存与锁定 |
| find-error | 同 solve | 原题圈画和正式作答证据分离 |
| response | 复用唯一正文框和既有正式手写能力；题干逻辑区稳定 | 长文、字数提示、旧 title/body、IME，不让答题提示撑动题干 |
| matching | 完整选项常驻，真实 select 按稳定 slotId 显示 | 窄视口仍保持源排列；重复约束与材料空号不变 |
| ordering | 原文条目常驻，不从原文池删除或移动；答案区操作稳定编号序列 | 固定项/空位/移除/换序/部分草稿；排序不得拖着可圈画正文重排 |

排序沿用原有 sequence 和 itemId 保存语义、上移/下移等控件能力，不新加拖拽库。呈现改为完整条目原文固定展示，答案区用编号及固定尺寸的位置控件表达顺序，不重复一份完整题面。为兼容旧空排序板几何，保留对应旧排版模板，避免把旧稿强套到新模板。该项是必要的交互调整，必须有前后截图和真实数据状态差分，不能仅断言旧 points 没变化就称笔迹仍对齐。

所有题型变化进入现有 answering 调度边界及视图，不在 Overlay/页面新增第二套按题型判断和答案更新逻辑。题组、材料子集、讲练嵌入题、错题重练均消费相同的冻结公开模型。

## 5. 协议与保存：保留基础，拆掉图片显示依赖

1. AnnotationDoc.version=1 及底图像素坐标继续使用；不转换历史点、不合并草稿/正式手写协议。
2. v2/v3 原始 layout、controls、PNG、ready 身份和封存证据可读且不改写。v3.controls 仅为历史数据，停止生产捕获和控件恢复；不能为清理代码顺便删字段、改旧 schema 或批量重存。
3. 新建稿使用显式的新布局协议版本（拟 v4），记录整题渲染配置和公开几何证据，不包含图片控件清单。先在 packages/contract/src/annotation.ts 定义 Zod，再实现服务端/API/IDB；复用现有 layout JSON 列，预计无数据库结构迁移，若确认需要 DDL 必须 drizzle-kit 生成。
4. 新版 PUT 协议能力声明、未知版本拒写与保稿行为一起更新。不能借新版本改变旧版本的含义；旧 v3 的能力拒旧守卫继续有效。
5. 原稿来源、正文、权限的判定从图片解码判定中拆出。已可靠读取的布局和正文不需要 img.onload 才能显示；进入圈画仍须满足真实本机持久化与稿件身份条件。缺失 PNG 或其下载失败按存证/导出/本机完整性问题处理，不能伪装成无稿另建，也不再因此把正常题面换成图片。
6. 首次基准 PNG 可继续生成用于证据及现有服务端 ready 协议；先基准资产、后正文的可靠落盘与同步顺序保留。优化 PNG 生成不是本次另起的重构任务。
7. 保留 CAS、mutationId、pending、retained、conflict、擦除墓碑、账号隔离、封存单调性、提交保护和 PWA 安全更新。正常恢复不得因测量或新样式自动写回服务端。补充渲染证据若需要持久化，另存有身份的展示记录，不改不可变原基准。

## 6. 旧稿兼容与恢复失败

| 旧稿类别 | 计划处理 | 验收门槛 |
| --- | --- | --- |
| v2，有公开区域证据 | 按原逻辑宽高、冻结题和旧样式恢复真实组件，按 10px 比较 | 不下载 PNG 来替换题面；旧 points/PNG/layout/ready 身份不变 |
| v3，有填空 controls | 与 v2 同路线，使用原生题内输入；controls 只读保留 | 真实输入每空只有一个，不使用 controls 的 x/y 生成控件 |
| v2，只有几何/字体哈希 | 用原渲染版本和固定框重建；旧哈希可证明相同，但失配不能反推出误差大小 | 先用完整旧格式夹具核实；必要时原 PNG 仅作离线校对证据，不能显示成题卡或推测控件 |
| v1，无 layout | 核对原固定宽栅格化管线、像素尺寸及冻结公开题面，建立对应旧 DOM 模板 | 不能把它当作普通 v2 强套；未补齐证据前保留只读/异常边界，不能宣称已全量支持 |
| 本机待传、保留本机、跨端冲突 | 沿用既有来源裁决，题面与笔迹绑定同一版本 | 不取云端基准去配本机未同步正文，不覆盖待传身份 |
| 已逐题提交/整卷交卷/订正封存 | 真实题面只读，原样显示本人答案与笔迹 | 不因允许 10px 误差恢复写入，不改封存证据 |
| 未知协议、缺正文、损坏资产、错题身份 | 报错保稿、可重试；有上一成功工作区就保留 | 不清库、不当空稿、不自动重冻、不静默隐藏笔迹当成功 |

其中「只有哈希」与「无 layout」不能靠调大阈值凭空补出历史位置。阶段 0 必须明确可恢复的旧模板与仍缺证据的类别；不能等大改完成才发现，也不能用图片主视图或图片控件适配绕过本次要求。首次恢复确实失败时显示明确的保稿错误并保留原资产的下载/导出能力，不把无笔迹的普通题面包装成恢复成功。

旧样式兼容有明确版本入口，不能复制整套旧应用。禁止自动重置真实用户稿或要求重新做题消除兼容问题。

## 7. 回看、材料、导出与 AI 影响

### 7.1 回看与订正

AnnotationView 改为数据读取与只读同框宿主，显式接收必要的冻结公开题面和本人答案；不再靠任意 children 隐藏后替换成图片。学生结果、教师详情、订正历史及相关 compact 入口逐一接入。学生参考答案/正确项/详解在已授权反馈区域呈现，不混入公共题面，不为了复现主视图扩大接口公开内容。

已提交态与未提交态保持同一稳定宿主；锁定不卸载题面或重建画布。教师拿到的完整快照只按公开题面字段交给共享框架，教师私注不进入底图或学生出口。订正仍按 correction 独立记录、封存与重试规则执行。

### 7.2 材料和草稿

材料不走 PNG 题面方案，但纳入「原位持续显示」回归。已有材料基准的真实阅读框在非圈画态也保持，分栏拖拽只改变比例，不再正常隐藏笔迹并要求切换排版查看。其 1000 归一笔迹坐标按已保存 CSS 宽高映射，不能套用题卡底图像素域。

旧材料只有宽高基准的证据局限如实保留；长材料、晚到图片、跨版本同材料和分栏滚动逐项测试。材料服务端同步不在本次新增，文档不能暗示它已获得题卡云同步。草稿和正式纸面的原保存、全屏、布局偏好与本机保稿保护保持。

### 7.3 导出与已有 AI 材料采集

区分两种既有证据用途：当前题面导出按统一逻辑渲染器生成公开题面，再叠同域笔迹及获准的本人答案/草稿/正式手写；原历史证据导出仍可读取已封存原 PNG 与对应文档，不改写旧证据。两者都不能把保存 PNG 再接回普通题卡主视图。

移除 FrozenFillControls 后，导出不得遗漏本人输入、选项状态或缺少 SVG/公式/图片。材料收起、题卡隐藏或画布释放时，从冻结模型、渲染配置和持久化稿件生成导出，不依赖活 DOM 或“当前恰好显示”。

exportQuestionAnnotationImage 同时被作答导出与 AI 材料采集消费，因此必须回归 ai-material-capture、review-pack 及已授权上下文附件。只改变呈现来源，不改变 AI 出站授权、普通学生防泄露、私注排除或封存时序。新增普通学生载荷如确实需要，必须复用 contract 公共模型并补泄露测试。

## 9. 实施阶段与每阶段闸门

### 阶段 0：固定需求、旧稿夹具与影响基线

- 记录用户这次三项移除和 10px 标准；逐一列出图片主视图、控件恢复和旧兼容门禁的生产调用方。
- 将实测数据转为可重复的测试夹具，补 v1、v2 有/无证据、v3、擦空稿、待传、冲突、封存与坏数据样例。
- 先核实第 6 节无完整证据旧稿的恢复范围；输出缺口，不能假定全支持。
- 闸门：无业务数据写入，已有图片方案不新增扩展；每个入口与旧稿类别有对应测试责任。

### 阶段 1：10px 判定与稳定渲染框架

- 先写失败测试，再实现第 2 节判定、共用逻辑框、兄弟墨层和作用域样式。
- 验证真实题面在不同视口/比例/DPR、草稿/AI 分栏下不因断点重排；已存坐标不改。
- 闸门：2px/10px 均正常通过，错题/错域不通过；旧原稿不因判定写回。代码保持可构建。

### 阶段 2：协议与生产保存/恢复接线

- 先改 Zod 并补正反例，增加最小 v4 渲染配置；更新 API/IDB/服务端 reader/writer 和能力拒旧。
- 把来源/正文/权限判定与 PNG 解码分开，保留真实落盘、ready、pending、冲突和封存链。
- 闸门：生产协议测试证明新稿完整可恢复；旧 v2/v3 字节和身份不变；图片下载失败不会把正常题面切走；读取失败不能造空稿。

### 阶段 3：作答、十题型与讲练统一接入

- 先补「标画可见时选/填/写」失败测试，再删除 answerMode 与图片控件适配。
- 真实题面接入统一框；修复 matching 断点和 ordering 主动移动正文，其他题型复用原控件。
- 闸门：十题型均可直接更新原答案状态；小误差不告警；无第二份完整题面或第二套真实输入；单题提交原位锁定。

### 阶段 4：回看、订正、材料与导出全链路

- 接入只读统一框，去掉 AnnotationView 图片替换；落实材料常显，回归草稿与全屏。
- 导出和 AI 采集使用对应冻结模型，不丢输入或笔迹；保留历史原证据文件导出。
- 闸门：学生/教师、作答/结果/订正/历史均无图片主视图；普通学生及 AI 各自授权回归通过。

### 阶段 5：生产协议跨端、真机与发布收口

- 这次必须经真实测试 API、独立本机存储与服务端同步完成电脑 → iPad → 电脑，不能沿用调试协议直接搬 JSON 来代替。
- 先自动化完整回归，再用独立测试账号、新旧格式题卡进行真实 Pencil、中文 IME、旋转/分栏、离线重开、冲突裁决、提交封存和 PWA 更新测试。
- 清理生产无用图片控件代码、测试断言和现行文档；保留历史报告事实并注明取代关系。
- 闸门：所有要求的入口、旧稿类别和异常场景逐项记录结果；未解决问题不得写成“全部兼容”后合并。CI 全绿后先合并 v2，main 发布遵守原流水线。

## 10. 验证矩阵与真实命令

单元测试至少覆盖：

- 容差边界与身份/损坏反例；历史哈希/缺证据不伪装成可量化误差。
- 首次创建、恢复、隐藏再出现、后台请求失败、晚到图片/权限、源身份变化和中途旋转收笔。
- 原生 radio/checkbox/输入/IME/final/response/select/ordering 的答案值、输入节点身份、焦点与只读；重复文本选项不串项。
- 固定点序列、擦除墓碑、撤销/重做；存储、绑定、pending/mutationId、冲突和封存在新旧协议下保持。
- 封存/未知协议/读失败时不写；账号切换后的迟到回执不能改新账号稿。
- 当前题面导出与历史证据导出分别正确，收起或未挂载不漏材料，普通学生载荷与授权 AI 材料均有对应泄露断言。

浏览器测试覆盖原 e2e/annotation-cross-device-view.spec.ts、annotation-native-surface.spec.ts、annotation-paper-interaction.spec.ts、question-inline-annotation.spec.ts、annotation-pixel-grid.spec.ts、question-base.spec.ts，以及讲练、单题反馈、材料分栏、导出、AI 上下文相关 spec。原来点击「进入作答」的用例改为真实题面直接操作并断言旧墨仍显示，不能仅删按钮断言。新增 spec 时更新选测登记，优先扩展已有范围。

跨端保留原 PNG/hash/layout/points 的前后证据，同时测对应 DOM 区域的逻辑位置和实际控件操作。只验 points 相等不足以证明正文没有移动。容差验证按原始基准，不只测一个像素比或仅整数宽高。

真实 iPad 和电脑矩阵：横/竖屏、不同源逻辑宽、窄题列/1:1、中文/英文/长公式/图片/表格、不同字体加载时序、无网络重开、新旧版本页面并存、单题与整卷封存。手工项逐项记录设备、源稿类别、操作和结果；没有执行的写未覆盖，不以 WebKit 模拟代替。

开发循环运行 pnpm test:quick、pnpm typecheck:affected、pnpm lint:changed；阶段验证运行 pnpm test:affected、pnpm e2e:affected。修改契约后运行 pnpm gen:spec 并提交全部生成产物，最终再次生成后 git diff 应为空。契约/迁移等升级全量时执行脚本决定，不绕过。PR CI 承担双浏览器完整回归和构建，不额外手动重复全量。

全 diff 依次做简化审查、正确性审查和学生数据/答案出口安全审查。仓库列出的 writing-plans、task-workflow、simplify、code-review、security-review 等专项技能当前未提供，按上述等效步骤执行并记录，不能写成已运行这些技能。
