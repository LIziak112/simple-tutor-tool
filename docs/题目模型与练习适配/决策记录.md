#### 5.1.1 cloze 定稿：组合结构

结论：**完形填空 = 共享材料（含 choice 槽位）+ 题组 + 若干 choice 子题**，不引入 cloze 答案 kind、不增加 cloze 题型枚举。理由：

1. 设计方案 §4.2 贯穿示例即此形态：「一份文章包含二十个稳定槽位，槽位映射二十道 choice；每道题的选项互相独立。若二十空共用一个词库，才改用 matching」——每空选项独立的完形不需要共享选项池，choice 逐题作答即足够。
2. 逐题保存、提交、行级锁定、题级释放、自评、错题重练、计数统计全部复用 choice 既有链路，TT-09/TT-10 零新增作答协议；若引入整体 slotId→optionId 映射，则完形成为「一道大题」，逐题提交与锁定协议须另建，违背「父组不创建作答行、子题是最小作答与判断单位」。
3. 总清单 §2 底线「不预设增加领域型枚举」——完形是呈现形态（材料+槽位+组的组合），不是新的答案数据结构。
4. 适配层方案 §11.4 推演表 cloze 行的四个属性全部由组合结构覆盖：槽位=材料/题干内 SlotKind="choice"（§8.2 预留位）；完整度=组内 choice 子题计数；对照=choice 逐题对照（复用既有对照，槽位-子题绑定提供「第 N 空」定位）；纸面角色=choice 子题的 scratch。推演表定稿列见 5.7.4。
5. 学生答案即普通 `{kind:"choice", index}`（index 语义、旧投影、旧对照零变化）；材料中的槽位标记只是渲染绑定，不进答案数据。
6. 「二十空重排不串答」由槽位 ID 稳定性保证（D5），与答案形态无关。

若未来出现「共享词库完形」（二十空共用一个大词库），按方案指示改用 matching 表达，仍不需要 cloze kind。语料 valid-03 按组合结构书写，即本结论的语法评审对象。

### 5.2 内容模型定稿：材料、题组、引用与稳定 ID

#### 5.2.1 物理布局：引用式（题块保持顶层）

依据设计方案 §9「题块继续保持顶层。组声明引用子题，不在 question 中直接嵌 question」与适配层现状（question.ts:67 只在顶层扫描、directives.ts:325 question allowedIn=["document"]），定稿**引用式布局**：

- 材料用容器指令 `::::material{id=… title=…}` 在文档顶层声明（与题块平级，须在首个 H1 之后，与题块同规则）；内容为材料 Markdown 原文（文字、表格、图片、公式、`:::seg` 片段、`{{slot}}` 槽位标记）。
- 题组用容器指令 `::::group{id=… title=… label=…}` 在文档顶层声明；内容为公共说明文字 + 引用指令：`::ref{material=…}`（材料引用，可多个）与 `::ref{question=…}`（子题引用，按序可多个）。
- **question 的 allowedIn 不改**：子题仍是文档顶层题块，question.ts 主谓词与 lesson 嵌套禁令（QUESTION_NESTED_IN_LESSON）零改动；组引用子题而非物理包含，组的「子题 ID 顺序」=组内 `::ref{question=…)` 的书写顺序。
- 题内（题干中）允许 `::ref{material=… segs=… slot=…/slots=…}` 引用材料/片段/槽位（见 5.2.2）；组内 `::ref{material=…}` 为全组共享展示。
- 不允许组引用组（首版仅一层）：`::ref{question=…}` 的目标必须是题块 id；组内出现指向组的引用报错（错误码见 5.4.3）。

理由：物理嵌套（group 物理包含 question）需要改 question 顶层谓词与 lesson 安全面，引用式把全部解析改动限制在新指令上（B2/B3 的 TT-06 风险面最小）；且「一个组完整出现一次、同一题在一个 attempt 只出现一次」由引用解析保证。代价是教师写作时组声明与题块分离，由 lint 兜底（组引用的子题不存在、重复引用、子题不在文档中）。

#### 5.2.2 引用、片段锚点与槽位

- **材料引用 `::ref`**（叶子指令，allowedIn: group/question）：属性 `material`（必填，材料 id）；`segs`（可选，片段选择：`seg-2` 单个 / `seg-1..seg-3` 区间 / `seg-1,seg-4` 列表；缺省=材料全文）；`slot`（可选，单个槽位 id——子题绑定该槽位作答）；`slots`（可选，槽位区间/列表——matching 类题目声明其槽位集合）。
- **片段锚点 `:::seg{id=…}`**（容器指令，allowedIn: material）：包裹被引用的块级片段（段/句群/表）；id 缺省 `seg-{n}`（n 按材料内出现顺序），导入回写。区间语义：`seg-1..seg-3` 指文档顺序上 seg-1 起至 seg-3 止的连续片段（含中间未列名片段）。
- **槽位标记 `{{slot-id}}`**（文本标记，非指令）：材料或题干正文中行内挖空标记，在文本节点识别、math/inlineMath/code/inlineCode 子树跳过（复用 `[[…]]` 的识别纪律，question.ts:291）；**不用 `[[…]]` 表达选择空位**（[[…]] 携带答案，属教师侧内容，混用会破坏学生端投影边界）。槽位身份 = `(scopeId, slotId)`（适配层方案 §8.2）：独立题 scopeId=题目 id，材料槽位 scopeId=材料 id。
- **子题-槽位绑定**：组内 choice 子题用题内 `::ref{material=mat-x slot=slot-3}` 显式绑定（第 n 个空 ↔ 第 n 道子题，由引用显式声明，不做隐式推断——适配层方案 §8.2「共享材料由宿主提供明确的槽位→所属子题绑定」）；matching 题用 `::ref{material=… slots=slot-1..slot-5}` 声明槽位集合。无绑定的材料槽位为错误（SLOT_UNBOUND，见 5.4.3）。
- 多材料引用：同一题/组内多个 `::ref{material=…}` 累加（材料 1、材料 2…），展示按引用顺序。

#### 5.2.3 稳定 ID 与显示编号

| 实体 | 显式来源 | 缺省生成规则 | 回写 |
| --- | --- | --- | --- |
| 材料 | `::::material{id=…}` | `mat-{unitId}-{n}`（n 按文档出现顺序 1 起） | 是 |
| 题组 | `::::group{id=…}` | `grp-{unitId}-{n}` | 是 |
| 片段 | `:::seg{id=…}` | `seg-{n}`（材料内顺序） | 是 |
| 槽位 | `{{slot-id}}` | `slot-{n}`（所在材料/题内顺序） | 是 |
| 配对选项 | `:::option{id=…}` | `opt-{questionId}-{n}` | 是 |
| 排序项 | `:::item{id=…}` | `item-{questionId}-{n}` | 是 |
| 题目 | 现状不变（question.ts:55 `单元id-序号`） | 不变 | 不变 |

- 前缀（mat-/grp-/seg-/slot-/opt-/item-）保证不同实体类型 id 不撞名空间，引用解析（`::ref` 的 material= 与 question= 属性）不歧义。
- **导入规范化时生成并回写源文**（把 id 写进指令属性/标记内），此后 id 显式存在；重排、reparse、编辑、导出重导**不重新生成**（设计方案 §4.3）。生成仅在「源文缺 id 且首次导入」时发生。
- 显示编号（「材料 2」「第 36 题」「（1）」）是展示派生，不进主键、不进 id：组 `label` 属性可选存组级显示题号说明（如「1～5」）；子题组内序号由组的子题引用顺序派生，开卷冻结时写入 attempt 上下文快照的公开投影字段 `groupOrdinal`（TT-05 契约草案，见 5.8.1）。
- 命名空间与归属：材料/组/槽位 id 仅在**教师域 + 单元内**保证可解析；materials/question_groups 表主键含 teacherId（沿用 questions (teacherId,id) 先例，schema.ts:526-542）；跨教师同 id 互不可见（引用校验含教师域，不按全局 id 裸查询——实施清单 §3.1）。

#### 5.2.4 单元顺序与组的关系

- units.questions 平铺数组**保持现状不变**（全部可答子题按文档顺序），组是叠加元数据：unit 增可选 `groups: [{ id, title, label?, materialRefs[], questionIds[] }]`（解析抽取结果；questionIds 必须是 questions 顺序的子序列，lint 校验）。
- 「父组不重复计题数」自动成立：组不产生题行、不出现在 questions 数组；资源库/课程/作业计数消费 questions 平铺口径，零改动兼容（QM-07 验收点）。
- 作答顺序 = questions 数组顺序（现状不变）；组渲染（共享材料、公共说明、组内编号）由 QM-08 宿主按 groups 元数据叠加，不改变保存/导航协议。

#### 5.2.5 源文保存与导出重建

1. 「原文是真相」三份源文：`material.sourceMd` = 材料容器原文（含 id/title 属性与内部 seg/slot）；`group.sourceMd` = 组容器原文（含 ref 引用行）；`question.sourceMd` 不变。单元结构源文=文档本身（units 不再复制正文）。
2. 导入、编辑、reparse 必须经同一组解析与写入函数（实施清单 §3.1）；结构化字段（anchors/slots/options/items/引用索引）只是抽取副本，不接受绕开源文的独立修改。
3. **导出重建 = 按源文原样导出**：导出的 MD 含材料/组/题块原文（含回写后的 id），重导经同一解析器还原同结构、同 id、同引用（round-trip 稳定）；不重新拼装、不丢格式。
4. 规范化回写只发生在导入时（生成缺省 id 写回源文）；编辑器/导出不追加改写。
5. 旧 practice 文档题块外曾被忽略的文本（B3 现状）不能凭空恢复为材料——迁移报告列为无法自动还原，需原始 Markdown 重导（设计方案 §5.2 第 5 条，不重开）。

### 5.3 答案与参考形态定稿（response / matching / ordering）

以下 schema 为设计定稿（Zod 生产实现在 TT-05）；对偶关系沿用 grading.ts 头注释「学生答案与 QuestionAnswers 按题型一一对应」的既有口径。

#### 5.3.1 学生答案（studentAnswerSchema 新增三分支）

| kind | schema 草案 | 草稿/未答表达 | 结构校验（inspectShape + 服务端保存校验，均不接触参考答案） |
| --- | --- | --- | --- |
| response | `{ kind: "response", title?: string, body: string }` | body 空串=未写正文（仅手写作答合法，grade 侧与完整度见 5.7.4） | 无未知键；title 可缺省（未填不携带）；不校验字数（word-min/max 仅提示，见 5.4.1） |
| matching | `{ kind: "matching", pairs: Record<slotId, optionId> }` | pairs 只含部分槽位=部分配对草稿，合法 | 键∈题目声明的槽位集合；值∈选项池 id；allowRepeat=false 时同一 optionId 不得被多槽占用（重复占用报 ShapeIssue） |
| ordering | `{ kind: "ordering", sequence: itemId[] }` | 部分序列=草稿，合法 | 每个 itemId∈题目声明项集合；无重复；固定项若出现必须在其声明位置；干扰项不得进入序列（进入报 ShapeIssue） |

- 三种新 kind 的**保存只校验结构/范围，永不比对参考答案**（QM-09 验收线）；提交也不强制排满/填满（「未填完整」与「未判断」是两个维度，QM-13）。
- isAnswered 纯行为口径：response = body 非空白；matching = pairs 非空对象；ordering = sequence 非空数组。完整度口径与之分离（I06 纪律）：response 完整度考虑正式笔迹（见 5.7.4）。

#### 5.3.2 参考答案（questionAnswersSchema 新增三分支）

| kind | schema 草案 | 缺省策略 |
| --- | --- | --- |
| response | `{ kind: "response", referenceMd: string(min 1), variantsMd?: string[] }` | **整个 answers 允许缺省**（无参考答案题：reference_self 不成立，行 gradingPolicy 落 manual_only，见 5.6） |
| matching | `{ kind: "matching", pairs: Record<slotId, optionId> }` | 同上可缺省；提供时**可发布校验要求覆盖全部槽位、值∈选项池**（部分映射不可发布） |
| ordering | `{ kind: "ordering", sequence: itemId[] }` | 同上可缺省；提供时可发布校验要求=全部非干扰项恰一次、固定项在位 |

- **主观参考答案支持 Markdown**：response 的 referenceMd 与 variantsMd 均为 Markdown 原文（KaTeX、分段、列表均合法），渲染走 RichMarkdown 管线；公布前不下发（三投影纪律，见 5.8.2）。
- **多种参考表达**：主参考=题内 `:::answer` 内容 → referenceMd；备选表达=题内若干 `:::variant` 容器 → variantsMd（有序数组，无 id）。翻译题的多个可接受译文、作文的多角度范文由此表达。
- matching/ordering 的参考是纯 ID 映射/序列（无 Markdown 需求）；其 DSL 书写形态见 5.4.2（answer 容器内行式书写，解析为结构化映射）。
- fill 的既有参考（blanks 等价答案列表）不变：有 blanks 即视为「有参考答案」（新行 gradingPolicy=reference_self），公布后逐空对照+自评，**不恢复自动匹配**（2026-10-02 决策不重开）。
- solve/apply/find-error 的既有 final 参考（:::answer 单行文本）不变；**新作答不再用它做等价比较**（5.6），它转为公布后的对照文本 + 自评依据。

#### 5.3.3 可发布校验（严格层）

两层校验沿用设计方案 §4.1「解析结果允许表达有问题的文档；进入持久化、发布和冻结前必须通过严格校验」：

- 解析/lint 层（宽松）：产出实体 + issues（错误码见 5.4.3），不阻止解析完成。
- 可发布校验（严格，导入提交/发布/开卷冻结前执行）：
  1. 类型-答案形态匹配（choice 有 options 且 index 界内、response 不带 ID 映射等）；
  2. 材料引用闭合：全部 `::ref` 的 material/segs/slot(s) 可解析且属本教师域；
  3. 组引用健康：子题存在、无重复成员、无组引用组；questionIds 是单元题序子序列；
  4. 槽位绑定健康：材料槽位全部被绑定（组内子题 slot= 或 matching slots=）；子题绑定的槽位存在；
  5. matching：选项池非空、选项 id 唯一；参考（若提供）全覆盖槽位、值合法、重复约束一致；
  6. ordering：项 id 唯一；参考（若提供）=非干扰项恰一次、固定项在位；
  7. 材料正文无答案型内容（[[…]]/:::answer/:::solution/hint）；
  8. 旧七型的既有校验规则全部继续成立。
- 校验失败的批次整批拒绝（事务不落库，QM-05「批次验证全部成功才事务提交」）。

### 5.4 DSL 指令草案与引用错误处理（TT-06 按此注册）

> 本节是新增指令语法的**唯一集中记录**；语料目录的文件按本草案书写，即语法定稿的评审对象。TT-06 按「注册表 → 组件 → 样例测试 → pnpm gen:spec」四步注册（AGENTS 规则 11），不得绕过注册表。全部新属性可选（有默认值），旧文档缺省行为不变；bool 属性以字符串 `true`/`false` 书写（mdast 指令属性恒为字符串，注册表 schema coerce——difficulty 数字属性同款先例）。

#### 5.4.1 新增指令清单

| 指令 | kind | allowedIn | 属性 | 缺省 id/值 |
| --- | --- | --- | --- | --- |
| `::::material{id= title=}` | container | document（顶层，H1 后） | id（可缺省，见 5.2.3）、title（可选显示标题） | mat-{unitId}-{n} |
| `::::group{id= title= label=}` | container | document（顶层，H1 后） | id、title（公共说明可写在容器正文）、label（可选组级显示编号说明） | grp-{unitId}-{n} |
| `:::seg{id=}` | container | material | id | seg-{n} |
| `::ref{material= segs= slot= slots=}` | leaf | group、question | material（必填）；segs/slot/slots 可选（5.2.2） | — |
| `::::options{allow-repeat=}` | container | question（matching） | allow-repeat（bool，缺省 false：同一选项不得被多槽占用） | — |
| `:::option{id=}` | container | options | id | opt-{questionId}-{n} |
| `:::item{id= fixed= distractor=}` | container | question（ordering） | id；fixed（bool 缺省 false，锁定显示位置）；distractor（bool 缺省 false，干扰项不属正确序列） | item-{questionId}-{n} |
| `:::variant` | container | question（response） | 无（内容=一条备选参考表达 Markdown） | —（有序数组） |
| `{{slot-id}}` | 文本标记（非指令） | material、question 正文文本节点 | — | slot-{n} |

- question 新增可选属性：`word-min` / `word-max`（正整数，response 类字数提示，**仅展示提示不硬校验不截断**——设计方案 §7.3）；旧属性（type/difficulty/knowledge/id/class）语义不变。
- `:::variant` 与既有 `:::answer`/`:::solution`/`:::hint` 同为 question 子指令（从题干行中排除收进对应字段，复用 question.ts:114 的子指令分区机制）。
- `::image` 的 allowedIn 增加 `material`（材料内图片与讲义/题干同规则：src 必须 blobs/media/ 内容寻址路径）；材料内其余既有展示指令（fold/tip/box 等）按需在 TT-06 注册时扩展 allowedIn，能力声明不新增输入面。
- matching/ordering 的**选项与项的容器内容保留在题干 sourceMd 中**（与 choice 任务列表同款：正文即题面，结构化字段是抽取副本）；`::::options`/`:::item` 在题干内的行不计入答案标记扫描。

#### 5.4.2 参考答案的 DSL 书写

| 题型 | 书写 | 解析产物 |
| --- | --- | --- |
| response | `:::answer`（Markdown 主参考）+ 若干 `:::variant` | `{kind:"response", referenceMd, variantsMd?}` |
| matching | `:::answer` 内行式：每行 `slotId = optionId`（空格可省；行序无关） | `{kind:"matching", pairs}` |
| ordering | `:::answer` 内行式：每行一个 itemId，**行序即正确顺序**（固定项也列出） | `{kind:"ordering", sequence}` |
| 旧七型 | 现状不变（[[…]]/任务列表/:::answer 单文本） | 不变 |

- 行式格式不符（未知 slot/option/item id、非 `a = b`/裸 id 行）记 `INVALID_REFERENCE_ANSWER_FORMAT`，该参考答案不落结构化字段（保留原文，发布校验拒绝）。
- 语料中的行式书写见 valid-04/valid-05；语法定稿评审以语料为准。

#### 5.4.3 引用与结构错误码清单（lint/导入/发布共用码表）

| 错误码 | 触发层 | 语义 |
| --- | --- | --- |
| `UNKNOWN_MATERIAL_REF` | lint | `::ref` 的 material= 在本文档不可解析（未声明且单元内无此材料） |
| `MATERIAL_REF_OUT_OF_DOMAIN` | 导入/发布 | 材料 id 可解析到库中但属**其他教师域**（静态 lint 不查库，跨域在导入服务按教师域校验——实施清单 §3.1「不按全局题目 ID 裸查询」同款纪律） |

| `GROUP_NESTED_OR_CYCLIC` | lint | 组引用组（首版仅一层，天然无环；嵌套/循环统一此码） |
| `GROUP_ORDER_INVALID` | lint | 组 questionIds 不是单元题序子序列 |
| `UNKNOWN_SLOT_REF` | lint | slot=/slots= 引用的槽位在目标材料/题干中不存在 |

- 既有 lint 码（UNKNOWN_DIRECTIVE、INVALID_DIRECTIVE_ATTRS、QUESTION_NESTED_IN_LESSON 等）对新指令继续生效：关闭开关的旧 tutor-lint 对新文档报 UNKNOWN_DIRECTIVE 即期望行为（老校验器拒绝新文档，不静默放行）。

#### 5.4.4 两遍解析与向后引用

沿用设计方案 §5.2 第 3 条：批量文档解析两遍——第一遍收集全部实体（材料、组、题块、锚点、槽位、选项/项），第二遍解析引用（组→子题/材料、题→材料/片段/槽位）；**向后引用合法**（组先声明、题块在后，或反之均可）；引用解析完成后整批校验，成功才事务提交。reparse（TT-06）从各实体 sourceMd 重抽取，题目 id 不变纪律沿用（AGENTS 常用命令节）。

### 5.5 自评与判定状态定稿

#### 5.5.1 自评请求/响应、来源枚举、版本与幂等

- **判断来源枚举**：`verdictSourceSchema = z.enum(["auto", "teacher", "self"])`（判定来源三值；AI 评判接入时另行扩展，本轮不预设——设计方案 §6.2）。
- **自评请求**（TT-09 落地，沿用本站 API 风格：409 附 `_current` 摘要、mutationId 幂等回执，见 routes/student.ts:167 笔记接口先例）：

```text
POST /api/student/attempts/:id/questions/:questionId/self-review
{ verdict: "correct" | "wrong" | "undecided",   # undecided = 撤回自评（回到暂不判断）
  baseRevision: number,                          # 自评记录基线（CAS；首次自评为 0）
  mutationId: string }                           # 幂等键（网络重试同键不重复写）
```

  - 校验链（服务端依次裁决）：登录本人 → 行属本 attempt → 行已提交（行级 submittedAt / attempt 已交）→ **公布 gate**（resolvePracticeQuestionFeedbackState = released，practice-workflow-service.ts:230 单一出处复用，不改口径）→ 教师未判（teacherMark=null，已判即 409）→ baseRevision CAS → 事务写入。
  - **教师已判后的自评请求拒绝**（409 SELF_REVIEW_TEACHER_MARKED）：迟到自评不能覆盖教师判断（设计方案 §6.2）；教师判定前已写入的自评记录保留展示，但有效判定=教师。
  - 响应：`{ selfReview: { verdict, at, revision }, effective: { source, value } | null, summary }`（本题有效判定 + 卷汇总刷新）；409 CAS 冲突附 `_current`（最新自评与 revision）。
  - 「暂不判断」不是一次写入：undecided = 清除自评记录（幂等写，revision 递增）；从未自评的行天然处于暂不判断。
- **自评不写 teacherMark、不写 finalCorrect**（D7）：自评是本人声明，不能伪装成教师或自动判定（设计方案 §6.3）。

#### 5.5.2 三源分立与有效判定

存储四元组各自独立，**禁止一个布尔兼任所有来源**（QM-01 条目原文）：

| 字段 | 写入方 | 语义 |
| --- | --- | --- |
| autoCorrect | 服务端判分（提交时） | 客观题自动判定；主观新行恒 null |
| teacherMark | 教师批改接口 | 教师对/错；可清除 |
| selfReview（新列/记录） | 学生自评接口 | { verdict, at, revision }；可撤回可修正 |
| finalCorrect | 提交/批改事务 | **持久语义冻结：teacherMark ?? autoCorrect**（D3 既有口径不变，教师权威判定线） |

- **学生侧有效判定投影 effectiveVerdict = teacherMark ?? selfReview ?? autoCorrect**（三层回落：教师 > 自评 > 自动）；结果页/记录/错题本消费投影并携带 source 徽章（auto/teacher/self），scoreFinal 等「教师权威口径」继续消费 finalCorrect，两条线不混用。
- graded 状态、教师批改队列消费 finalCorrect/教师待处理谓词（5.5.3/5.5.4），**不被自评推动**：自评完成不改变 graded 触发、不把自评当可信成绩（QM-12「不把自评当客观独立完成证据」）。

#### 5.5.3 教师待处理 vs 普通未判断；已提交/已公布/未判断三态推导

单题推导状态机（服务端 resolveSelfReviewState / pendingMark 谓词共用，TT-09 落地；完成态单源纪律同 phaseOfRows——不各写 sourceType 分支）：

| 前置 | 条件 | 状态 | 学生侧展示 | 教师侧 |
| --- | --- | --- | --- | --- |
| 行未提交 | submittedAt=null | not_submitted | 未作答/草稿 | — |
| 已提交 | 未公布（四态 pending_attempt/restricted） | pending_release | 已完成作答、等待公布；**不显示答案、无自评入口** | 可读原稿、可批改（入口照旧） |
| 已提交+已公布 | teacherMark≠null | teacher_judged | 教师判定（徽章来源） | 已判，可改判/清除 |
| 同上 | autoCorrect≠null | auto_judged | 自动判定（旧客观题，现状不变） | 现状不变 |
| 同上 | 有参考答案（reference_self）、自评=null | **self_pending（普通未判断）** | 待自评：展示参考+解析+对/错/暂不判断 | **不入必批队列**（教师可选批改，走全部已交列表） |
| 同上 | 有参考答案、自评≠null | self_reviewed | 自评正确/自评错误（可修正） | 同上 |
| 同上 | **无参考答案（manual_only）**、teacherMark=null | **teacher_pending（教师待处理）** | 「暂无参考答案·未判断」（不自动判错、不伪造答案） | **进必批队列**（唯一判定出口是教师） |
| 同上 | 无参考答案、teacherMark≠null | teacher_judged | 教师判定 | 已判 |

- **教师待处理 ≡ 已提交 + 无 autoCorrect + 无 teacherMark + 无自评 + 无参考答案**（判定来源枯竭：客观 auto、主观参考、学生自评、教师判定四路全断，唯余教师）；「无参考答案」判定依据=题目快照 answers 缺省（快照冻结时定，教师后续给库中题目补答案不影响已冻结行——快照纪律）。
- **批改状态不阻止提交完成**：self_pending/teacher_pending 都不阻塞交卷、不阻塞回看/订正/记录；「完成作答」与「已判断」独立（设计方案 §1）。
- 待学生自评与待教师处理分别计数展示（pendingMarkCount 谓词 TT-12 拆分；旧 `finalCorrect IS NULL` 快捷过滤全部审计改造，C3 风险项）。

#### 5.5.4 有效结果组合与教师清除后的回落表

组合全表（✱=教师清除动作后的状态）：

| autoCorrect | teacherMark | selfReview | finalCorrect（存储） | effectiveVerdict（学生侧） | 必批队列 |
| --- | --- | --- | --- | --- | --- |
| true/false | null | 任意 | autoCorrect | auto | 否 |
| 任意 | correct/wrong | 任意 | teacherMark | teacher | 否（已判） |
| null | null | correct/wrong | null | self | 否 |
| null | null | null/undecided | null | **未判断** | 有参考→否（self_pending）；**无参考→是（teacher_pending）** |
| null | ✱清除→null | correct/wrong | **null（回落 autoCorrect=null）** | **self（恢复生效）** | 有参考否；**无参考是** |
| null | ✱清除→null | null | null | 未判断 | 同第 4 行 |

- 教师清除 = 撤回 teacherMark：finalCorrect 按 D3 既有语义回落 autoCorrect（null 即 null）；学生侧有效判定回落下一层（自评存在则自评恢复生效；无则未判断）；无参考答案行回到必批队列。清除是显式动作，UI 提示回落后果（TT-12 文案）；清除与自评并发按 CAS+事务串行化，事务内刷新结果、错题集合与汇总（QM-12）。
- 自评修正（对↔错）与撤回（undecided）同链路：CAS+幂等；修正后错题集合即时刷新（自评错→入错题，改对→出集合，原作答与原稿保留——QM-12）。
- **历史行为不变**：旧行（gradingPolicy NULL）无自评接口入口（5.6 冻结解释）；旧 autoCorrect/teacherMark/finalCorrect 按原事实展示、不重算（总清单 §2）。

#### 5.5.5 graded 触发放宽（新行）

- 旧口径（D2/D3）：graded = 全部 finalCorrect 非 null。**历史卷不重算、不重解释**。
- 新行口径（TT-09 起）：graded = 全部行已提交 且 无「教师待处理」行（teacher_pending 谓词见 5.5.3）。推论：全客观卷交卷即 graded（不变）；**有参考答案的主观卷交卷即 graded**（自评与否不阻塞——「完成作答不以自评为前提」）；含无参考主观行的卷在教师判完前停留 submitted（学生侧任何完成口径不受阻塞，仅教师队列计数）。
- 「整卷无需批改」的批量跳过动作**不在本轮**（教师逐题用既有批改入口；如需批量动作 TT-12 再议，见 5.10 待确认 3）。
- scoreFinal 写入口径随 graded（教师权威线）；学生侧若需「含自评完成度」的汇总文案，QM-12 以 effectiveVerdict 单独统计并注明来源（不冒充自动测评事实，设计方案 §6.3）。

### 5.6 新作答策略冻结边界

**决策（D11）：判分策略按 response 行冻结，不全局改 grade()。**

- responses 增列 `gradingPolicy`（TEXT，可空）：`"auto" | "reference_self" | "manual_only"`（TT-05 迁移生成）。开卷冻结该 attempt 每一行时按**题目快照内容**写入：

| 题型（快照） | 有参考答案 | gradingPolicy |
| --- | --- | --- |
| judge / choice / multi（旧客观） | —（必有） | auto |
| fill（新行） | blanks 存在 | reference_self |
| fill（新行） | 无 | manual_only |
| solve / apply / find-error（新行） | :::answer 存在 | reference_self |
| solve / apply / find-error（新行） | 无 | manual_only |
| response / matching / ordering（新行） | 参考存在 | reference_self |
| 同上 | 无 | manual_only |

- **旧行 gradingPolicy=NULL 按题型能力表旧语义解释**（solve/apply/find-error 走 final 等价比较；fill 恒 null 进待批——即现状），历史判定不重算：**禁止全局改 grade 后意外重释历史**（QM-01 条目原文）。
- 三分支语义：
  - `auto`：走既有 validator（gradeJudge/gradeChoice/gradeMulti），交卷写 autoCorrect（现状链路）；
  - `reference_self`：grade 恒 null（不进 autoCorrect），公布后开放自评（5.5.3）；
  - `manual_only`：grade 恒 null，教师待处理（5.5.3）。
- **已交卷旧卷**：行策略=NULL，重读按旧解释原样展示（submitted/graded 状态、autoCorrect、待批谓词全部现状语义）。
- **升级时进行中的旧 draft attempt**：其行在开卷时冻结为 NULL，升级后继续作答/交卷仍按旧策略判定（冻结即真相；不做「升级后把进行中卷迁移到新策略」——那是重释历史）。新策略只对**升级后新开的卷**生效。
- 与 5.5 的衔接：gradingPolicy 决定「有参考答案」判定不必再查快照 answers（行上直接可判），pendingMark 谓词消费行级字段，避免每行反解快照（性能与单一出处双收益）。

### 5.7 能力表、validatorId 与跨端证据角色

#### 5.7.1 validatorId / 能力表人工分支兼容（D12/D13）
