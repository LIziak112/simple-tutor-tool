适用范围：本专题全部已合入变更（迁移 0038–0041、材料五表与冻结快照、行级判分
策略与学生自评、错题重练复制卷、新题型序列化单源、学情数据包 v2 材料节、学生端
AI 伴学三出口、媒体管线与 GC 依赖面、备份恢复全链）。权威依据：
[技术架构与实施方案](../技术架构与实施方案.md) §5.10、AGENTS.md 相关小节、
[决策记录](决策记录.md) §5/§22–§27。

## 1. 备份覆盖面（事实基线）

- 备份 = **全量 DATA_DIR**：`VACUUM INTO` 完整库（WAL 下安全）+ `blobs/`（笔迹/
  媒体/AI 材料图片）+ `shared/` + `secret.key`，排除 `backups/` 自身（D20）。本专题
  新增的全部表（材料五表、`attempt_context_snapshots`、AI 任务/材料表、`responses`
  新列）随库文件整体进入备份，无需逐表登记。
- 文件引用面（`BLOB_BACKUP_REF_COLUMNS`）是**单一清单**：备份收集、GC 保留、
  AI 材料清理三处同源消费——新增含 blob 文件引用的表时必须同步登记（当前含
  `ai_task_materials.png_path`）。
- 恢复后可续写、看旧卷、重练与导出的服务级回归：`backup-qm-restore.test.ts`
  （表内容与文件字节身份逐一相等 + 四链路）。

## 2. 部署顺序（先兼容读/服务端，再开放新导入）

1. **维护窗口停写**：停服（旧版服务端正常退出，WAL 落盘）。
2. **更新服务端与前端**：同版本发布。启动时 `runMigrations` 自动应用 0038–0041
   （只加表加列，不动存量行）：
   - 已交卷答案/判定**原样保留**（`grading_policy` NULL → 按题型能力表旧语义解释，
     历史不重算不重释，契约 `resolveRowGradingSemantics` 单一出处）；
   - 进行中草稿/笔迹不受迁移影响，升级后按版本协议继续续写。
3. **验证**：起服后抽查——学生端进入进行中练习（续写）、教师端回看已批卷、
   错题本与重练、导出一次学情包；核对 `backups/` 自动快照在生成。
4. **开放新导入**：确认新版稳定后再开 `NEW_CONTENT_ENABLED`（新题型导入与开卷
   判分策略写入的总开关）。开关关闭期间：旧题型工作流零变化、新题型文档被导入
   lint 阻断；开关开启后新开的卷才冻结 `grading_policy`（按部署当前开关在**开卷
   时点**裁决，见决策记录 tt-07a）。

## 3. 兼容边界（新旧数据双向）

| 方向 | 行为 | 依据 |
| --- | --- | --- |
| 旧库 → 新服务端 | 启动/恢复时自动迁移升级，存量行零改写、判定不重判 | `migrate-qm.test.ts` 四类边界（空库/旧库/草稿笔迹库/混合库，账本与快照身份幂等） |
| 旧备份 → 新服务端 | `restoreFromBackup` 后 onOpen 迁移钩子自动补表 | `backup-qm-restore.test.ts` 第二例（0040 前结构备份恢复后 QM 表齐备、已判行原样） |
| 新库 → 旧服务端 | **禁止**。旧迁移账本不回滚（新表/新列残留不损坏），但旧服务端读不到新实体（材料/自评/AI 面缺失），且旧版判分/导出不认识新列——只允许作为**回退窗口内的短暂过渡**（见 §4），不允许承载新创作后长期运行 | 迁移只前滚不回滚（drizzle 账本）；「生成新数据后不直接降级到无法读取的版本」 |
| 旧客户端 → 新服务端 | 答案保存走逐题 `baseRevision`/`mutationId`：已接管（`answerMutationId` 非空）的题拒绝无版本覆盖（409 `ANSWER_REVISION_CONFLICT`，回 `_current` 供裁决）；手写同先例（旧客户端只能首次创建，已有稿的无版本覆盖拒绝并提示刷新） | AGENTS「作答跨设备同步」「手写可靠性」；`student-attempts-response.test.ts` |

旧格式冻结快照（QM-13 前三结构键全缺）由 `effectiveStructureOfSnapshot` 从快照
自身 `sourceMd` 兜底重抽——只用于当次投影，**不回写库、不重判**（回归锁
`student-attempts-qm13.test.ts`「旧卷判定不重判、不漂移」）。

## 4. 回退预案

触发条件（任一）：新版服务端启动失败、核心路径（登录/开卷/交卷/批改）不可用且
短时无法修复、教师确认需要回到升级前状态。

1. **关闭新创建**（软回退，优先）：停新版 → 开关 `NEW_CONTENT_ENABLED=false` →
   起新版。已开的新题型卷按冻结快照继续作答完成（判分/回看/导出不受开关影响——
   开关只裁决新导入与新开卷的策略写入）；教师端旧题型工作流零变化。
2. **保留兼容读取**：新版对旧数据只读不改判（见 §3 第一行），回退窗口内已完成
   的新题型作答、自评、材料仍然可读、可批、可导出——回退不丢数据。
3. **成套恢复到升级前版本**（硬回退，维护窗口内）：
   1. 停服；定位**升级前时点**的备份（升级窗口前手工下载的完整 zip，或
      `backups/` 中早于升级时刻的自动快照）——回退目标必须是旧结构时点的备份；
   2. 当前数据另存一份完整 zip 留档（硬回退放弃的新数据仍可事后在隔离环境查看）；
   3. 在**隔离环境**先验证该备份可恢复、可开卷（`restoreFromBackup` 的原子性
      与回滚保险由服务自身保证：恢复前自动快照进 14 份轮转，任一步失败原数据
      无损复原）；
   4. 恢复 = DATA_DIR 整体替换（库 + blobs + shared + secret.key），回到备份时点；
      恢复后用**升级前版本**的服务端启动（旧结构备份 + 旧服务端 = 原工作组合）。
   - 注意：硬回退会丢掉备份时点之后的全部新数据（教师/学生侧均然）——执行前
     与教师确认时点；恢复后所有会话失效属预期（重新登录）。升级后时点的备份
     含新结构，不能作为「回到旧服务端」的回退目标（新库配旧服务端见 §3 红线）。
4. **明确红线：不在生产库演练破坏性恢复**。破坏性操作（手工 SQL、直接改库文件、
   删 `backups/`）只允许在隔离副本上做；生产库的一切变更走服务端自身入口
   （迁移、恢复接口、GC），本专题全部路径均有服务级测试覆盖。
