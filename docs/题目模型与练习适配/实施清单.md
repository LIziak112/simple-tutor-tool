## 2. 已确认范围与禁止扩展项

### 2.1 必须交付

- 共享材料：文章、统计表、图片、多份给定资料、稳定句段引用。
- 题组及独立子题：公共说明、显示编号、题序；父组和材料不额外算题数。
- 开放作答：简答、翻译、申论、作文、证明等，多行正文与正式手写共存。
- 完形槽位、配对和排序的作答数据、参考答案及渲染。
- 填空与开放/解答类的新作答停止自动答案匹配。
- 有参考答案时，提交且获准公布后默认对照自评：对了、错了、暂不判断。
- 教师沿用后台简单对错评选；AI 具体评判后续再做，但已有 AI 求助必须能读取新题型所需上下文。
- 课程练习、普通作业、讲练、错题重练、保存恢复、结果、历史、订正、导出、备份和相关统计完整适配。
- 历史题目、历史判定、旧样例和已有手写/标画可靠性继续成立。

### 2.2 明确不进入本轮

- 卷面分、步骤分、部分分、评分量表、新权重或通用评分引擎。
- 填空/主观题字符串、数学表达式或关键词自动匹配判对错。
- 配对/排序的新自动判分器；这里的“配对”仅指交互与答案结构。
- AI 自动评分队列、模型评分协议、自动采纳 AI 评分及精细教师批改工作流。
- 听力、录音面试、代码执行、自动几何判定、多试卷归属模型重构。
- 共享材料的独立圈画。本轮共享材料先只读，子题草稿/正式手写/题面标画照常支持；独立材料圈画单列后续范围，不复制材料或冒充题目绕过证据协议。

共享材料圈画的这一边界必须在界面、说明和验收记录中写清楚；长材料阅读、完整导出与已有子题书写功能均为本轮必需。

## 3. 必须统一遵守的数据与行为约定

### 3.1 内容身份与原文

- 继续使用 `packages/contract` 的 Zod 单一类型来源，TypeScript strict，禁止 any。
- 新材料/组/槽位/选项身份稳定，显示编号单独保存；重排不能串答。
- 旧 choice/multi 索引与旧 fill 数组含义保持，旧源文规则不改名、不重解释。
- question、material、group 各有权威源文；单元结构只列引用与顺序。所有抽取字段走同一解析链路。
- 首版只允许一层题组，同一题在一个 attempt 出现一次；引用校验含教师域，不按全局题目 ID 裸查询。
- 原文可含 Markdown、公式和本站图片，不执行任意 HTML、SVG、脚本或导入组件代码。

### 3.2 快照与保存

- 开卷在同一事务冻结题目、组、材料、锚点、参考答案解析和媒体引用；显示、回看、重练与导出读来源快照。
- 同一材料同版本可去重；同 ID 不同来源版本不能互相覆盖。
- 保留 responses 原行 ID、questionRevisionId 和已有答案 CAS；禁止整卷删除重插。
- 正式手写、草稿、标画仍走既有落盘/恢复/收笔/封存；读取失败不能当无稿。
- 新结构编辑只影响之后的新作答，不补造过去材料，不重判历史成绩。

### 3.3 评判最小语义

| 题目/情况 | 本轮默认 |
| --- | --- |
| 原判断、单选、多选 | 沿用已有服务端自动判定，不扩展计分规则 |
| fill、solve、apply、find-error、response、matching、ordering 的新作答 | 不做答案匹配；有参考答案时默认对照自评 |
| 已提交但未公布 | 完成作答，等待公布，不提前显示答案或开放对照自评 |
| 已公布、有参考答案、未判断 | 待自评；本人可选对、错或暂不判断 |
| 无参考答案 | 保留未判断；可由教师处理，不伪造答案、不自动判错 |
| 自评结果 | 标注来源，影响当前结果/错题集合；不是 teacherMark |
| 教师结果 | 标注来源，不能被迟到自评覆盖；清除教师判定后如何回落由 QM-01 定稿并覆盖测试 |
| 历史已判题 | 维持事实及来源，不清空、不批量重判 |

自评是本人判断声明，不是客户端计算出的可信成绩。服务端裁决归属、提交、公布、版本、写入和汇总。未判断不能当错误；提交完成不以自评完成为前提；待学生自评和待教师处理分开。

### 3.4 安全与兼容

- 普通学生载荷不提前返回答案、解析、提示、教师私注或原始题块。
- 自评也必须服从既有公布时机；教师 after_due 等约束不能被默认自评绕过。
- lesson 原位混排、当题提交/锁定、当题释放和最后一题收尾继续成立；用安全 blocks 适配材料/组，不放宽嵌套题禁令。
- 公共组解析若透露未提交兄弟题答案，延后释放或要求拆题级解析。不要给所有材料题默认增加组级提交系统。
- AI 原有三受控出口遵守当前教学策略，仅携带本题及必需材料；普通接口的公开投影不放宽。
- API、DSL、能力清单必须描述实际支持。中间批次未完成时可以关闭新内容入口；最终不能以“该入口暂不支持”抵消必需适配。

## 6. 每个任务的执行与记录格式

### 6.1 固定流程

1. 阅读根规则、相关架构、当前任务和依赖证据；核实代码实际变化。
2. 列具体文件（含测试）、提交步骤、失败测试点；遵守用户现有授权及仓库确认流程。
3. 在独立阶段分支小步实现；解析器/判分必须记录先红后绿。纯文档任务可说明免 TDD。
4. 完成完整 diff 质量闸门，再运行最终验证；发现修复后重跑受影响检查。
5. 逐条贴命令与真实输出，更新状态和依赖；必需人工验证没完成保持待验证。
6. 全绿后按 v2→main 流程集成。技能缺失/不可用须如实记录，不得声称已经调用或审查完成。

### 6.2 验收记录模板

每个任务在 `验收记录.md` 增加一节，包含：

## 8. 验证命令与证据要求

按依赖顺序逐条运行，保存退出码和输出。下面是可用命令模板，不表示已经执行：

```text
# 针对性 TDD：替换成当前任务真实测试文件
pnpm exec vitest run <当前任务测试文件>

# 契约/DSL/CLI 变更
pnpm gen:spec
pnpm tutor-lint <新增有效样例文件或目录>
# 再次 gen:spec，对比生成文件内容/哈希确认没有二次变化

# 质量闸门后最终验证
pnpm test
pnpm typecheck
pnpm lint
pnpm build

# 使用仓库隔离配置的真实浏览器测试
pnpm e2e <当前专题实际spec路径> --workers=2

# 数据库结构变更时生成，并验证全部迁移
pnpm db:generate
```

注意：故意错误的 lint 样例预期非零退出，需断言准确错误码。gen:spec 的首次预期改动应提交；第二次生成只比较生成产物，不能要求包含正常源代码修改的整个工作区无差异。DB 生成在对应实现任务进行，不在最后凭模板盲目补跑新迁移。
