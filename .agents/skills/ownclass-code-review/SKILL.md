# OwnClass 代码审查

以 [AGENTS.md](../../../AGENTS.md) 为准。[requesting-code-review](../requesting-code-review/SKILL.md) 提供独立审查的交接流程，[审查员模板](../requesting-code-review/code-reviewer.md) 提供需求对照、只读审查与发现分级。以下项目规则用于确定顺序、范围和结论。

## 固定审查范围

1. 记录独立工作树路径、任务起点提交和审查时的 HEAD。分阶段审查以任务起点为基线，合入 v2 前记录实际目标 v2 的 SHA，以该提交和 HEAD 的合并基点为基线，复核待合并的完整差异。当前工作树混有其他任务时，先隔离本次改动。同一个文件交叠且无法安全分离时，明确范围缺口。
2. 以下四项分别收集，保留各自的路径和内容。尖括号中的占位符须换成记录的完整 SHA。

```text
git diff --binary <BASE_SHA> <HEAD_SHA> --
git diff --cached --binary <HEAD_SHA> --
git diff --binary --
git ls-files --others --exclude-standard
```

3. 逐个读取本任务的未跟踪新增文件。以三段补丁和新增文件的路径并集核对清单，包含删除与重命名。把对应内容或只读快照交给审查员。审查期间若有写入或目标分支变动，重新固定范围，并对新增或变化的部分补审相关阶段。清单有缺口时不得判定完整审查通过。

## 质量闸门

按 [项目审查清单](references/checklist.md) 对同一范围依次执行。

1. **简化**。检查复用、重复逻辑、抽象层级和热路径成本。先处理确认的简化问题，再进入正确性审查。
2. **正确性**。对照已确认需求、调用链、边界和验证证据。需要独立验收时，用上游模板派给只读审查员，按下方交接内容替换模板里的提交范围说明。
3. **安全（按需）**。触及学生端载荷或答案数据时必做，并说明相关出口和证据。其他任务记录不适用及原因。

编排模式由独立验收者按顺序覆盖各适用阶段，编排者裁定发现。独立审查不可用时，如实注明，按授权做等效检查。有明确独立验收要求时保留缺口。确认问题应修复，未修逐项说明。对修复产生的差异补审受影响的阶段，并按 [工程验证说明](../../../docs/约定/工程验证说明.md) 补跑受影响的检查。

## 派单内容

- 需求或计划、实现摘要、当前审查阶段及相关约定。派单使用必要上下文。
- 工作树、目标分支、基线和 HEAD 的完整 SHA。提供四项范围内容及文件清单，未覆盖项单列。
- 相关验证的命令、基线、结果和未覆盖项。审查员只读检查和复用有效证据。
- 输出按严重程度列出文件行号、触发条件和实际影响，说明覆盖缺口及是否通过当前阶段。编排者按实际 diff 核实每项。
- 在 Codex 显式指定 `gpt-6.1-sol` 或 `gpt-6.1-terra`，并按复杂度选择 `medium` 或 `high`。执行环境不支持时如实说明。
